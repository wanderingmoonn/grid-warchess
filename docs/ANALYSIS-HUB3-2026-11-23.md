# 三件套：一座枢纽城同时决定"升哪座、从哪座出兵、谁给产兵格让位"（2026-11-23）

> 这一轮按你的方案做：**枢纽唯一一座**，然后三处一起（升级对象 / 出兵点 / 守军让位），
> 前线城的判据改成"**威胁度 + 守不守得住**"。三个开关都默认关，关着时逐局与基线一致。

## 一、做了什么

### 1. 枢纽城（唯一一座）

```
候选：不是废墟、不是要放弃的城、还有产兵格
     ！（守得住 或 敌人还没到跟前）
打分：-6 × (到"兵该去的地方"的行军回合) + min(12, 产兵格 × 3)
```

- **"守得住"**（新加的判据）：5 格内我方战斗单位的血量加权战力 ÷（我方 + 6 格内敌方战力），
  6 成权重；城墙剩余血量 4 成权重。0.5 = 五五开。
  合格线是 `守得住 ≥ 0.5` **或** `敌人威胁度 < 0.35`（还没到跟前）。
- 粘住：上一回合已经在攒这座城的升级费，就继续用它，避免枢纽在两座城之间抖
  （抖一次就把"攒了几天、还差多少"重置一次，这是攒钱目标永远差一口气的一半原因）。

**为什么不用"离敌人多远"当判据**：上一版（P1-3 第一版）就是用它，结果前线城必然离敌人近 →
永远当不上枢纽 → 永远追不上时代。你现在这条"威胁度 + 能不能撑住"正是对症的：
敌人近但打得过 → 继续投；敌人近又打不过 → 换城，把钱和兵都撤出来。

### 2. 升级对象 = 枢纽

三处一起换：攒时代的钱攒给枢纽、`+18` 的"集中升一座"判给枢纽、攒钱期只许升枢纽。
（关着时仍然是老口径"时代最高的那座"——这一点必须显式写，见下面第三节的坑。）

### 3. 出兵点 = 离枢纽几回合

每多一回合扣 3 分、封顶 12 分。12 分只够压过同分噪声（±2）和同档小差异，
不足以改写"买坦克还是买民兵"（那有 10~20 分）。

### 4. 守军让位

- 枢纽城至少留一格产兵（守军不超过城格数 − 1）；
- **守不住的城不派人进去**（守得住 < 0.45 就不进城），人留在外面打野战。
  以前是"最近敌兵 ≤ 9 格就往里塞 1~2 个"，于是常见"两个兵守一座必丢的城"。

## 三、两个必须记住的坑

### 1. "用开关包住一段逻辑"时，关着必须等于老行为，不能"整段跳过"

我给"攒钱期只许升枢纽"这段加了 `aiHub 打开才生效`，写法是给整个 `if` 加条件——
结果关着时这一整段被跳过（老行为是"只许升时代最高的那座"），
默认状态就漂了：同一颗种子 84 回合的败局变成 116 回合。

表现很隐蔽：`probe:collapse` 只看胜负和回合数，不看"为什么"。
抓到它的办法是**拿基线逐局对拍**（Q1|30|A 负 78 / Q3|31|A 负 84 / Q4|30|A 胜 101 三颗钉子）。

正确写法是保留这一段、只换条件里的判据：

```ts
const hub = aiHub && plan.hubCityId ? cityById(...) : null;
const top = hub ?? 时代最高的那座;   // 关着 → hub 是 null → 退回老判据
```

### 2. 单开任何一件都不行，这次有数据了

只开出兵点、只开升级，两组的配对方向**完全一样**（小图 1↑2↓、大图 0↑5↓），
等于把同一份"改变"从两个入口各做了一半。合在一起才在小图上转正。
这就是你说的"单独做任何一件都没法获益"——不是巧合，是机制：升级只决定"能不能造"，
出兵点只决定"在哪造"，守军让位只决定"造得出不出"，三样缺一样都会被另外一样抵消。

## 四、大图为什么变差（待验证的假设）

三件套在大图把 7 局拖进了 190+ 回合。两个可能，都值得单独验：

1. **枢纽选到了"安全的城"而不是"该出兵的城"**：`守得住 ≥ 0.5` 这条在 24×24 上很容易
   把前线城排除掉（对面兵多），于是枢纽退回后方，兵照旧从后方出发——等于只加了延迟。
   验法：`probe:city-role` 看"兵出在被威胁城的比例"，并打印每回合的枢纽是谁。
2. **守军让位副作用**：不进城就没有城墙护甲和回血，反而更守不住；
   而守着的那几局恰好是能赢的。验法：只关 `aiGarrison` 跑一组（`--city-site --hub`），
   这个格子现在还没测——这是最便宜的一次对照（24 局）。
