## 2. 敌人成长：三种方案，建议混合

### 2.1 你提的「每层全属性 +x%」有什么问题

方向是对的——敌人需要一个**可预测的统一成长轴**，否则每层都要重写一张战力表。但有三个坑：

**坑一：不能加「移速 / 射程 / 视野」。**
这三个是**战术常量**，不是数值。移速从 3 变成 4，所有「风筝 / 绕后 / 卡位」的判断全变；射程 4 变 5 会直接越过墙和河。属性成长只应该作用于 **攻 / 血 / 甲 / 魔抗** 四项，其余冻结。

**坑二：纯百分比会让后期手感变「海绵」。**
「敌人血 +60%」的结果不是「更危险」，而是「更耐打」——玩家要多打两回合，体感是拖，不是难。**难应该来自新的威胁，不是来自更长的血条。**

**坑三：百分比按「层」算，会惩罚慢速阵容。**
一个走「低代精兵」路线的玩家，到第 3 层还在用 e3 的兵（因为有词条），敌人却按层涨了 60%，直接碾压。而肉鸽的核心情感恰恰是「带着老兵往前走」。

### 2.2 建议：把成长拆成三份

| 份 | 占比 | 怎么实现 | 玩家的体感 |
|---|---|---|---|
| **数量** | 50% | 提高 k（敌方总造价），多来 1–2 个单位 | 「人变多了」 |
| **质量** | 30% | 每层 攻/血/甲 各 +8%（复利，L4 ≈ +36%），移/射/程/视野**不加** | 「兵变硬了」 |
| **性质** | 20% | 会战给每个敌势力一条**势力特性**（见下） | 「打法变了」 |

数值上，L4 的敌人：数量约 1.5×、质量约 1.36×、加一条性质 → 综合压力约 2.1×，与我方「代际 + 词条 + 藏品」的 2–3× 大致对齐，但**不会变成海绵**。

### 2.3 势力特性（这是「性质」那一份，成本最低）

| 势力 | 特性 | 逼玩家做什么 |
|---|---|---|
| 敌甲（重装） | 全军 +1 甲，城耐久 +30% | 必须带破甲或法术 |
| 敌乙（机动） | 全军 +1 移，每 3 回合召唤 1 个杂兵 | 必须堵路或速杀 |
| 敌丙（术法，L4） | 全军带 1 条固定词条（如「再生」） | 必须集火或断补给 |
| 敌丁（L4 第四家） | 全军射程 +1 | 必须近身或架炮 |

**关键**：特性是**写死的 3 条**，不随机、不叠加。它不增加内容量，只改变打法。

### 2.4 顺便修一个已有条款的错

§10.3.4 现在是：

> 代差修正：我方每有一个「低于本层时代 2 代以上」的单位，k **+0.05**

这条**方向反了**。它等于「你带老兵，敌人变强」——而带老兵是这个游戏的主题。建议改成：

> 我方平均时代低于本层上限 2 代以上时，敌方**质量成长减少一半**（即 +8%/层 → +4%/层）

也就是说：老兵不吃数量惩罚，只让敌人「不那么硬」。这样「带老兵」从被惩罚变成**被宽容**，而且不会让「压级」变成最优解（因为你放弃的是更高的基础属性）。

## 3. 元进度（科技树）与 N0–N10

### 3.1 先定一条铁律：局外收益不给战斗数值

如果科技树给「全军 +10% 攻」，那 N10 必须按满科技树来调，新玩家第一局直接死；反之若按零科技树调，老玩家满科技打 N0 就是割草。**这是所有 roguelike 元进度翻车的同一个原因。**

所以：

| 维度 | 给什么 | 不给什么 |
|---|---|---|
| **科技树（局外）** | 选择权：解锁方略、解锁兵种图纸、起始兵种、商店货位、重掷次数、事件可见性 | 攻 / 血 / 甲 / 金币产出 |
| **N 级（局内难度）** | 约束：更多敌人、更少节点、更贵商店、更狠修饰 | 不改我方数值 |

两者**不重叠**，平衡矩阵就从「科技树 × N」的二维降回「N」的一维——因为科技树不改变战力上限，只改变**你能玩什么**。

### 3.2 科技树结构（建议 3 线 × 7 节点 ≈ 21 节点）

| 线 | 节点举例 | 终点（传说节点） |
|---|---|---|
| **军械** | 解锁第 2/3/4 个方略、解锁某 DLC 兵种图纸、起始多 1 个兵 | 「时代残响」常驻：招募池含全时代 |
| **后勤** | 起始金币 +100、商店 +1 货位、休整可多用 1 次 | 「军械库」常驻：每层首次刷新免费 |
| **时运** | 战后三选一可重掷 1 次、事件多 1 个选项、Boss 掉落 +1 件 | 「黑匣」常驻：剧情事件标注后果 |

战功来源沿用 §10.4：通关层数 ×10 + Boss ×20，一局 3 层约 90–150 点。
**建议总成本约 1200 点**（21 节点），即 **10–15 局点满**——太慢会让元进度变成负担，太快会让它失去意义。

### 3.3 N0–N10 怎么拆（不要做成血包）

每一级一条**具体规则修正**，而不是「敌人 +10% 血」：

| 级 | 修正 |
|---|---|
| N1 | 商店价格 +15% |
| N2 | 每层少 1 个休整节点 |
| N3 | 精英战多 1 场（第 2 层起） |
| N4 | 敌方质量成长 +4%/层 |
| N5 | Boss 战第二幕的战场事件变成对玩家不利 |
| N6 | 战后回复 20% → 10% |
| N7 | 每层 1 个事件变成「无收益」的纯叙事 |
| N8 | 敌方数量 k +0.15 |
| N9 | 第 3 层 Boss 多一条势力特性 |
| N10 | 第 4 层取消，第 3 层 Boss 就是终局（**且 Boss 属性 +30%**） |

N10 的设计是「**收窄**」而不是「加厚」：它砍掉你最喜欢的第 4 层，把压力全压在第 3 层。这比「所有敌人 +50% 血」有意思得多。

**解锁方式**：通关 N 才解锁 N+1（StS 的 ascension 模式）。但 N0 必须从第一局就能打。

### 3.4 存档：三层方案，从便宜到贵

| 方案 | 存哪 | 成本 | 缺点 | 建议 |
|---|---|---|---|---|
| A | `localStorage` | 半天 | 换设备 / 清缓存就丢 | **必做**（自动存，玩家无感） |
| B | **导出/导入码**（JSON → base64，带版本号 + 校验和） | 1 天 | 玩家要手动复制 | **必做**：这是最符合这个项目性格的方案（纯前端、可分享） |
| C | 账号云存档 | 需要后端 | 与「纯静态部署」冲突 | 可选，等有账号体系再说 |

关键是 **B**：一个 `{"v":1,"medals":1200,...,"maxN":4}` 的短码，玩家可以粘到别处保存。它同时解决了「换设备」「多存档」「分享给朋友试我的科技树」三件事，而且不需要服务器。

格式上必须有 `version` 字段和迁移函数——你们以后会改科技树结构，没有版本号就是灾难。

### 3.5 局内进度与局外进度的边界

| | 局内（一局） | 局外（永久） |
|---|---|---|
| 金币 | 有 | 无 |
| 兵 / 词条 / 藏品 | 有 | 无 |
| 方略 / 策略点 | 有 | 无 |
| 科技树 / 战功 / 最高 N | 无 | 有 |

**一条铁律**：局内的东西一局结束全部清零，只有战功和「最高 N」留下。否则第 20 局会变成「数值继承」，肉鸽就变成了养成。

## 4. 建筑卡：把 19 个建造单位变成消耗品

你在讨论的方向（战前投放、一次性）我认为是对的，这里给一个可以直接试的模型：

### 4.1 规则

- **获得**：战斗掉落 / 商店购买 / 事件。卡面上写清建筑名与造价。
- **价格**：卡价 = 建筑造价的 **40%**（因为一次性、不可修、战后消失）。
- **部署**：战前有一个「布防阶段」，给 **2 个部署点**（Boss 战 4 个），每张卡占 1 点，只能放在自己的半场。
- **限制**：每场最多 **2 张**（Boss 4 张），同类不叠加。
- **战后**：全部消失。**不可修复、不可回收**。

### 4.2 为什么是「卡」而不是「现场建造」

现场建造会让每场战斗回到「20 回合运营局」，而我们要的是 1.5–3 分钟的突袭战。**布防阶段是 15 秒的决策，建造是 15 分钟的运营**——这是两者的根本区别。

### 4.3 风险与对策

| 风险 | 对策 |
|---|---|
| 建筑卡变成「必带」，挤掉买兵 | 与兵**共享同一份金币**；卡价 40% 但每场只能 2 张，收益上限被锁死 |
| 塔防化：玩家靠塔赢 | 塔的血/攻按**该层时代**打折（−30%），且不能升级 |
| 断档层的方略没有兵可买 | 建筑卡给「没有兵的方略」一条临时出路（施法方略可以放「法阵」） |

### 4.4 经济单位的用法（你已打算转告合作者，这里补两条）

- **军需官** = 商店老板，价格随「军需官是否活着/是否被抢」浮动。
- **矿队** = 「发现矿脉」事件，选「开采」得金币但暴露位置（下一场敌方 +10%），选「保密」得 1 件藏品。
- **物流集团** = 「护航」任务，护送到地图另一侧得 2 倍奖励。

零系统成本，全是文案 + 一次数值判定。

## 5. 会战不可撤 → 撤退与「怯战」要重做

你定了「Boss 战不许撤，死了就是输」。那现有的两处要改：

### 5.1 撤退阈值只管非 Boss 战

| 场景 | 能否撤 | 条件 |
|---|---|---|
| 突袭 / 据点 / 精英 | 能 | 存活 ≤3（怯战方略 ≤5） |
| **会战（Boss）** | **不能** | — |

这条其实让规则更简单：撤回原来那句「会战不适用」的补丁。

### 5.2 「怯战」方略改成「保活流」

原来「阈值 3→5」的收益在 Boss 不可撤之后几乎没用了（Boss 才是死人的地方）。改成一个**身份明确**的方略：

> **方略名：留得青山**
> - 非 Boss 战撤退**无惩罚**（不扣金币、不触发敌方加成）
> - 撤退阈值 3 → 5
> - 每层可免费治疗 1 次
> - **代价：不能拿「增强」类因果标记**（不能追上限），且 Boss 奖励 −20%

它的定位很干净：**用上限换容错**。适合新手、适合长线运营、也适合 N 高难度（因为你本来就不该贪）。

### 5.3 Boss 战的一次「押注」（补 R12）

Boss 不能撤，但允许在开战前做一次**押注**：

- 押 1 件藏品 或 30% 金币 → 若战败，全队以 50% 血复活一次（只一次）。
- 赢了，押注物归你；输了，押注物消失但你能继续打（不是终局）。

这样「不能撤」不会变成「一次失误就重开」，但也没有免费读档——**你要先付钱买保险**。

## 6. 方略被动：从「数值」改成「操作」

你的判断对，「+X% 伤害 / +X 甲」太粗暴。给一条可执行的准则：

### 6.1 三条准则

1. **每回合至少一次决策。** 如果被动在战斗开始的瞬间就结算完了（+2 甲），它就不是设计，是数值。
2. **强弱要能被「站位 / 顺序 / 时机」影响。** 玩家操作好，收益应该翻倍；操作差，收益归零。
3. **主被动必须是操作型，两条进阶可以是数值型。** 主被动决定「你在玩什么」，进阶决定「你后期多强」。

### 6.2 三个改法示例

| 方略 | 现在（数值） | 改成（操作） |
|---|---|---|
| **铁砧** | 相邻重装互 +1 甲（上限 +3） | **可以替相邻单位承受一次攻击**（每单位每场 1 次）——你要决定「谁替谁挡」 |
| **齐射** | 同一目标每多一个远程 +12% | 远程命中给目标叠「标记」，**近战打标记目标 +30%**——你要决定「先射谁、再冲谁」 |
| **制空** | 敌方无空军时 +25% | 每回合选择**升空 / 降落**：升空免疫地面近战但每回合 −5% 血；降落可占点但吃全部伤害 |

改完之后，同样一句话「你玩的是铁砧」，但玩家每回合都在做决定。

## 8. 最小可玩切片（建议的落地顺序）

不要一次做四层。先做一个**15 分钟的切片**，验证「这套东西好不好玩」：

| 步 | 内容 | 为什么先做它 |
|---|---|---|
| 1 | **单位个体化**（`UnitInstance`：uid + 词条槽 + 跨战斗血量） | 这是词条、升格、老兵情感的地基，没有它后面全是空中楼阁 |
| 2 | **L1 的 3 个节点**（1 突袭 + 1 抉择 + 1 小 Boss） | 验证「短战斗 + 事件 + Boss」的节奏是否成立 |
| 3 | **5 件藏品 + 10 条词条** | 验证「三选一」是否真的让玩家纠结 |
| 4 | **1 个方略**（铁砧，操作型版） | 验证「方略被动」是否每回合都有决策 |
| 5 | **L1 完整 8 节点** | 验证 15 分钟一层的手感 |

做完这 5 步，你会知道三件事：战斗该多长、藏品该多强、方略该多「操作」。**这三件事定不下来，后面写 100 个遭遇战都是白写。**
