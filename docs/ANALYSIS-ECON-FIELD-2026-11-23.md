# 经济单位「产出距离场」：设计、实测与回退（2026-11-23）

> ⚠️ 2026-11-23：本文的「待办 / 下一步 / 还没做」章节已并入 `docs/V3-BACKLOG.md`
> （v3 待办的唯一清单）。本文只作历史记录与设计依据，**不要再往这里加新条目**。


> 结论先写在最上面：**机制做了、单点验证有效，但 24 局跑批净负（21-3-0 → 19-3-2），
> 默认回退**。这篇留的是设计口径、三个踩过的坑、以及"什么情况下值得重做"。

## 一、为什么要做

经济单位的走位分只有一条：

```ts
gain = 产出(目标格) − 产出(当前格)
score = gain * 5 − 1.5 + 威胁项
```

`gain` **只比相邻一格**。站在平原（7 金）上、邻格还是平原（7 金）时 `gain = 0`，
分数恒为 −1.5；而 `aiNextAction` 在 `best.v <= 0` 就收手（`ai-v3.ts:10443`）。
于是"去 5 格外的丘陵"的**第一步永远迈不出去**——它看不到坡度。

实测口径（`probe:econ-idle`，Q3/24×24/era2/seed30/新版坐 A）：

```
经济单位-回合 1156 · 动了 36（3.1%）
应动 272 · 空转 251（21.7%）= 有威胁没跑 14 + 该找地没找 237
空转里"这回合我方一个经济单位动作都没有"的 222 次
```

同时排除了两个猜测：不是动作配额（每回合只走 7.7 步，`aiStepCap` 是 130+），
也不是路径被堵（判据用的是多回合 BFS，穿过己方单位）。

## 二、设计

### 场的定义

```
value(格) = 产出(格) + rearBonus(到最近敌城的切比雪夫距离)
field(p)  = max over q ( value(q) − λ × 步数(p,q) )
走位分 += (field[目标] − field[当前]) × K
```

`field` 是"从这一格出发能拿到的最好**净**收益"，**越大越好**，所以坡度取
`there − here`。它自带盈亏判断：

```
目标 +3 产出、走 6 步 → field(现在) = max(7, 10−3) = 7   （和原地一样，没有坡度）
目标 +8 产出、走 2 步 → field(现在) = max(0,  8−1) = 7   （坡度 +7，会走）
```

### 常量

| 常量 | 值 | 依据 |
|---|---|---|
| `ECON_FIELD_LAMBDA` | 0.5（试过 1.0） | 走一步的代价（金）。也是"多远算太远"的唯一判据 |
| `ECON_FIELD_K` | 10（试过 8） | 沿最优路径一步 = λ×K = 5 分。**必须压过 −1.5 的基准**，否则候选进不去 |
| `ECON_FIELD_R` | 8 | 传播半径（格）。λ=0.5 时 8 步能吃到 4 金产出差 |
| `ECON_REAR_MAX` | 0.8 | 后方加成上限（金当量）。**小于 1 = 最小产出差**（farmer 丘陵 4 / 森林 3） |
| `ECON_REAR_HALF` | 4 | 后方加成的半饱和距离 |
| `ECON_FIELD_DANGER` | 3 | 危险格扣分（后加的，见第四节） |

### 后方加成（用户 2026-11-23 的两条硬要求）

```
rearBonus(d) = 0.8 × d / (d + 4)
  0格=0.000  1格=0.160  2格=0.267  3格=0.343  4格=0.400
  6格=0.480  8格=0.533  12格=0.600  24格=0.686  → 上界 0.80
```

- **单调递增**：✓（上式对 d 求导恒正）
- **有最大值**：✓（上界 0.8，永远碰不到）
- **量级不超过经济产出本身**：✓ 0.8 < 1，而 1 金是 farmer「丘陵 4 / 森林 3」
  这一档最小产出差。所以后方偏好**永远翻不动 1 金的产出差距**，只在产出完全相同时起作用。

形状用双曲线 `d/(d+half)` 而不是线性截断：线性在截断点有折角，单位会在折角附近来回犹豫。

### 实现位置（已回退，留档备查）

- `Fields.econField: Map<string, Float32Array>`——按兵种各一张，**惰性**算（某兵种第一次被评分时才建）；
- `econFieldOf(s, me, typeId, all)`——两遍：算 `value`，再做 8 轮 max-plus 松弛（λ 是常数，不用 Dijkstra）；
- `tacticalMoveScore` 的 economy 分支加 `slope` 一项。

## 三、路上踩的三个坑

### 1. 坡度符号反了（最贵的一次）

第一版按"距离场"的直觉写成 `here − there`，但 `field` 是"可达到的最好收益"，
**越大越好**，应该是 `there − here`。

后果：单位专挑更差的地走。实测 herder 从 (20,21) 走到 (23,21)（产出 −7）却拿到
+15 坡度，Q3/seed30/A 从**胜 109 变成负 246**。

抓到的办法：看调试输出里 `gain` 是负的、`slope` 却是正的——自相矛盾。**读代码看不出来**。

### 2. 探针自己找了个不可达的目标

第一版探针只查目标格是陆地，没查**路径**。于是挑出"隔着一格水"的丘陵，
场只能把兵带到最近的河边平地，探针却报"离目标 3 格、产出差 6"，看起来像"场没生效"。

修法：加一次只走陆地的 BFS（`pathExists`）。

### 3. 单位赖在好地上不走（真实的副作用）

加了场之后，Q4/seed32/A 的「有威胁没跑」从基线的 **103 次**涨到 **443 次**——
场只认产出和后方，完全不知道敌人射程，单位在宝地上"沉没成本"式地不肯挪。

补了 `ECON_FIELD_DANGER = 3`（按敌人当前站位的射程铺一张危险格集合，不用
`tactical.exposure`——那是按单位算的，576 格一铺就爆）。443 → 327，但**那局仍然是平**。

## 四、实测

### 单点验证（`npm run probe:econ-field`）

局部最优场景（起点产出 4、周 3 格内没有更好的地、5 格外有 11 的丘陵）：

```
无距离场：8 个回合一直待在原地，产出 4.0
有距离场：2 个回合走到 (6,2) 丘陵，产出 4.0 → 11.0
```

**机制本身是有效的**，它确实打破了"一步看不到收益"的僵局。

### 整局经济产出（`probe:econ-idle` 新增的快照）

Q3/seed30/A，每 20 回合的**总产出**：

| 回合 | 基线 | 距离场 |
|---|---|---|
| T20 | 90.0 | 91.0 |
| T40 | 111.0 | 114.0 |
| T60 | **182.0** | **176.0** |
| 终局 | 胜 109 | 胜 191 |

**产出没有提高**。这是最关键的一条：在真实对局里，经济单位并没有"长期待在不该待的地方"。

### 跑批（对手 `baselines/ai-9efb961.ts`，24 局）

| 版本 | Q1/Q2 | Q3/Q4 | 合计 | 平局 | 配对 |
|---|---|---|---|---|---|
| 基线 cutfix | 10-2-0 | 11-1-0 | **21-3-0** | 0% | — |
| 距离场 λ=0.5 | 9-3-0 | 10-0-2 | 19-3-2 | 17% | **1↑2↓** |
| 距离场 λ=1.0 + 危险扣分 | 7-4-1 | — | — | — | 更差 |

λ=0.5 那版的三处变化：

```
Q1|32|B  胜→负  (88→123)
Q3|31|A  负→平  (84→261)   ← 唯一的改善
Q4|32|A  胜→平  (87→261)
```

λ=1.0 单独试时那两局都恢复了（Q1|32|B 胜 82、Q4|32|A 胜 175），但整体 Q1/Q2 掉到 7-4-1
——参数一动结果就大跳，说明**这个机制的收益落在噪声里**，没有稳定方向。

## 五、为什么没用（比"参数没调好"更根本）

1. **前提在 24 局里不成立**：`reachableTiles` 一回合就给 2~3 格（牧民 3），
   而地图上"更好但一回合够不到"的地块很少。场的边际价值只剩 4~8 格外那一段，
   实际触发次数极少（整局经济 MOVE 从 36 变 26，还少了）。
2. **成本和收益不成比例**：场让单位"为了好东西长途跋涉"，而真实地图上好东西
   往往就在 2 格内；多出来的只是"沉没成本式地守着宝地不躲威胁"。
3. **它治的不是真病**：21.7% 的空转里，多数是"已经在一回合够得到的最好地块上，
   但探针的判据认为还能更好"（判据换成多回合 BFS 后必然如此）。

## 六、什么情况下值得重做

- 地图**好地块稀薄**（大片平原、丘陵孤立），或者经济单位移动力被砍到 1；
- 出现"经济单位该长途迁移"的玩法（城市被毁、资源枯竭、需要跟随前线）。
- 重做时要一次带上的三件事：**符号自检**（`gain` 与 `slope` 必须同号才合理）、
  **危险格扣分**、**同格抢占**（现在所有单位共享一张场，会朝同一个最优点挤，
  这一版没做，也是它收益不稳定的原因之一）。

## 七、留下的工具

- `npm run probe:econ-idle`：经济空转率 + **每 20 回合的总产出快照**（后者才是客观口径）；
- `npm run probe:econ-field`：单点验证"会不会为了更好的地跋涉"，含后方加成的单调性/上界自检。
