也就是说：**"两人一队打 C"的素材全都有，缺的是"队"这个概念本身。**

---

## 二、缺什么（都查过代码）

### 1. 敌我判定是"除我之外所有人"

```ts
// src/core/ai.ts:381
function enemySeats(s: GameState, p: PlayerId): PlayerId[] {
  return seatsOf(s).filter((x) => x !== p);
}
```

AI 用它找目标、算威胁、算对方经济。没有"队友"这一档。

### 2. 攻击判定只认"同一主人"

- `rules.ts:5338` `if (defender.owner === attacker.owner) return '不能攻击友军'`
- `rules.ts:5696` `if (city.owner === attacker.owner) return '不能攻击自己的城市'`
- `rules.ts:3492` 溅射跳过同主单位

所以 A 能打 B、能打 B 的城——合作关一开局就能互相拆家。

### 3. 胜负是"只剩一家"

```ts
// src/core/rules.ts checkWinner
if (alive.length === 1) return alive[0]!;
```

A、B 打光 C 之后，`alive = [A, B]`，对局**不会结束**，两人还得互相打完。
（关卡 `goals` 可以提前判赢，但 `goals` 也是按单个席位写的。）

### 4. 三个连带问题

| 问题 | 位置 | 后果 |
|---|---|---|
| 视野不共享 | `fog.playerView(s, p)` 按席位算 | 两人各看各的，配合全靠喊 |
| 丢城撤兵 | `retireLostSeat`（3+ 家局） | 队友丢光城，它的兵被系统撤走 |
| 认输按人算 | `doSurrender` 3 人局分支 | 一人认输只退自己，队友还在打 |

## 三、改法（三档，按"不做就没法玩"排序）

### ✅ P0：让"队"成立（已完成 2026-11-16）

1. **数据**：`LevelSeats.teams?: PlayerId[][]`
   ```ts
   seats: { count: 3, ai: ['C'], teams: [['A', 'B'], ['C']] }
   ```
   - 不写 = 每家独立（现状完全不变）
   - 校验：每个坐人的席位**恰好**出现在一个队里；队内不能重复；队数 ≥ 2
2. **判据**：新增 `sameTeam(s, a, b)`（`a === b` 或同队），没有 `teams` 时退化成"只认自己"
3. **攻击**：上面三处 `owner ===` 改成 `sameTeam`
4. **胜负**：`checkWinner` 按队算存活：
   - `aliveTeams = teams.filter(队里至少一人活着)`
   - `aliveTeams.length === 1` → 该队赢，返回队内第一个还活着的席位（`winner` 仍是 `PlayerId`，
     界面层再翻译成"盟友胜利"）
5. **AI**：`enemySeats` 排除同队

这一档做完，合作关就能打、能收场。**已全部实现**（`sameTeam` + 四处判定 + 胜负按队 + AI）。

### ❌ P1：用户明确不做

6. ~~视野共享~~：**不做**。"共享了就变成一个人操作两条线，不如一个人玩两家。"
7. ~~丢城不撤兵~~：**不做**。队友丢光城被撤兵是正常的。
8. ~~认输按队~~：**不做**。一人认输只退自己，不需要处理"同时投降"。

### ✅ P2 里的第一项已做，其余未做

9. **友军穿行**（已做）：`enemyBlocks` 同队豁免 → 可以穿过；`blockedAnchor` 仍然拦终点
   → 不能停在别人身上。友军的城也不挡路（`blockedFor` 同队豁免）。
   实现上**没有**把 `sameLayerAt` 改成区分敌我——它同时被"能不能站"和"落点"用，
   改它会把"不能停在队友身上"一起放掉。只改寻路那一处才刚好是"能穿不能停"。
10. **结算/简报文案**：「你和 XX 是盟友」「盟友胜利」——未做（界面现在显示单个席位名）。
11. **席位面板加"同盟"开关**——未做，目前只能改 JSON。

## 五、关卡设计建议（真要做的第一张合作关）

- **C（强敌）**：3 座城、`cityEra: 5`（机械化，城血 80 / 甲 12，能造坦克）、
  开局 8~10 兵、`ai: { riskAversion: 0.2, appetite: 3 }`、第 6/12/18 次各刷一波
- **A、B（玩家）**：各 2 座城、`startEra: 2`、开局 4~5 兵，**从南北两侧分开进场**
  （逼他们分工，而不是挤在一处）
- **胜利**：`survive`（A 守到 30）或"打光 C 的三座城"
- **难点设计**：C 的兵力 ≈ 两个玩家之和 × 1.5；给 A、B 不同的资源/地形短板，
  让"合流"成为必须而不是可选

**一个必须提前想清楚的坑**：`cityEra` 决定**造兵时代**。C 用机械化会刷坦克，
玩家只有铁器兵——这正是"强敌"，但也很容易变成"一见面就崩"。
要么给玩家反装甲手段（弩兵/长弓的穿甲），要么把 C 的城压到火器（时代 3）。

## 七、风险

- **AI 不会配合**：A 或 B 交给电脑时，它不打队友了，但**也不会刻意掩护队友**。
  合作关默认两个真人；别指望 AI 队友。
- **联机观战**：观战端本来就不该看到双方的迷雾；视野共享后要确认观战视角没漏。
- **平衡很难**：2 打 1，要么一边倒要么打不动。第一版必须靠实机调，脚本测不出来。
- **热座交接**：两人轮流点同一个屏幕，回合切换提示要足够明显（现在有，但多席位时要再看）。
