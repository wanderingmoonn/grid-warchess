# 把一局棋拖回来

**v0.3.37（2026-11-05）** · 对局复盘

## 一句话

结算卡上「下载 .json」出来的那份数据，直接**拖进页面**就能逐帧回看那一局：
每一步谁走到哪、打了谁、什么时候掉的城，都能停在那一帧上看。

## 为什么现在做

11-04 那版已经在报告里记了**整个动作序列**，当时的用途是"开发这边重放"。
但那是命令行工具：要装 Node、要敲 `node scripts/rl/replay-cli.ts`。
而真正需要复盘的人不是开发者——是那个打完一局觉得"我第 12 回合就把三个兵送进
对面射程了"的玩家。他手里只有一份 json。

所以这一版把重放器搬进了游戏：**引擎是确定性的，种子 + 配置 + 动作序列 = 完整一局**，
这三样报告里都有，那就不该只在开发者机器上能跑。

## 怎么用

1. 打完一局，结算卡上点「下载 .json」（或者「复制报告」，粘成文件也行）；
2. 把文件**拖到页面上**——或者首页点「复盘」选文件；
3. 拖着进度条往回看。

控制条在顶栏下面：⏮ / 上一步 / 播放 / 下一步 / ⏭，右边三档倍速。
键盘也认：`←` `→` 步进、`空格` 播放暂停、`Home` `End` 跳两端、`Esc` 退出。
点棋盘上的兵可以看它当时的属性卡（光环、加成、剩余行动都在），但**不能走子**。

## 三件必须说清楚的事

**1. 复盘是只读的，而且碰不到你本机那局。**

复盘的做法是把当前局面换成"别人那一局"，退出时再还回去。这里有个很脏的坑：
主程序里有二十多个地方会顺手把当前局面写进存档——不拦住的话，**你看一次复盘，
自己没打完那局就被覆盖了**，而且没有任何提示（下次打开就是别人的棋）。
所以存档层加了一个总闸，复盘期间一律不写。这一条有专门的用例守着。

**2. 走不下去就停在那一刻，并且说明是第几步。**

规则改过之后，老数据里的某一步可能变得不合法。这时候**不会假装走过去了**：
播放停在能走到的最后一步，控制条下面挂一条橙色的说明，写着"第 37 步走不下去：
目标越界"。滑块的上限也跟着缩短，拖到头不会出现"后面全是重复的一帧"。

顺带把两种"这份数据不准"的情况也说出来了：老格式（没存开局参数）只能按种子**重建**，
控制条上会标「按种子重建」；日志超过上限被截断的，会说丢了多了步。

**3. 没勾「结束后上传详细数据」的对局，复盘不了。**

动作序列是那时候才开始记的，没有它就没有"每一帧"。程序会直接告诉你这一点，
并且指向那个开关——而不是让你盯着一份能打开却放不动的文件。

## 顺带的一处改动：报告里多了「开局参数」

报告现在会带上整份 `MatchConfig`（尺寸、时代、扩展开关、兵种名单）。

原来只有种子：种子能重建地图、城、开局兵，重建不了"这一局都能造什么"。
而复盘要把动作原样重放一遍，兵种表差一个 id，第 N 步的产兵就会被拒，后面全歪。
加一个字段就解决，代价是几 KB——一局两百多步的报告从 ~7KB 变成 ~11KB，
离数据库那条 256KB 的线上限还很远。

这一条不改报告版本号：老分析脚本按已知字段读，多一个键读不出错。
