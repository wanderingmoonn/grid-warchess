# 四组对比：econcap × 威胁感知采购（2026-11-22）

## 要回答的问题

`aiEconCap`（经济铺到地块容量）单独打开会让小图崩（Q1/Q2 5-6-1）。
用户 2026-11-22 提出：用**威胁感知采购**抵消它的副作用——

> 三种信号：① 视野内敌方 2 回合能摸到我家城；② 近几回合我家城被打过；
> ③ 敌城因地图刷新离我城过近。信号越多，经济分越低、兵分越高。

## 四组

| 组 | 参数 | 经济上限 | 威胁分 |
|---|---|---|---|
| base | 无 | 每城 2 个 / 最多 12 | 无 |
| cap | `--econ-cap` | 地块容量 | 无 |
| threat | `--threat` | 每城 2 个 / 最多 12 | 有 |
| both | `--econ-cap --threat` | 地块容量 | 有 |

## 实现

- `aiThreatScale`（默认关）：`threatScaleOf` 读三个信号，`min(1, 0.4+0.3+0.3)`；
- 采购：经济 `score *= 1 - 0.5×scale`；战斗 `score += 40×scale`；
- 城被打过的记录：`keep.cityHp` 逐城比较，掉血就记 `cityHitTurn`。

## 结果

### Q1/Q2（12×12 / 16×16）

| 组 | 战绩 | 均回合 |
|---|---|---|
| base | 10-2-0 | 58 |
| cap | **5-6-1** | 82 |
| threat | 10-2-0 | 58 |
| both | **10-2-0** | 58 |

**cap 的崩被威胁分完全抵消**（5-6-1 → 10-2-0），且 both 与 base 同战绩。

### Q3/Q4（24×24，两种时代）

| 组 | 战绩 | 均回合 |
|---|---|---|
| base | 8-1-3 | 153 |
| cap | 6-0-6 | 168 |
| threat | 8-1-3（与 base 逐局相同） | 153 |
| both | 6-0-6（与 cap 逐局相同） | 168 |

### 全量

| 组 | Q1+Q2 | Q3+Q4 | 合计 |
|---|---|---|---|
| base | 10-2-0 | 8-1-3 | **18-3-3** |
| cap | 5-6-1 | 6-0-6 | 11-6-7 |
| threat | 10-2-0 | 8-1-3 | 18-3-3 |
| both | 5-6-1 | 6-0-6 | **11-6-7**（= cap） |

## 结论：威胁分**生效但无效**

探针实测（12×12，`threatScale` 每 10 回合）：

```
T10 threat=0.70   T20 threat=1.00   T30 threat=0.40
```

信号确实触发了（敌城近 + 城被打），经济分被压、兵分被提。但：

**both = cap，逐局完全相同**（24 局）。

原因两条：

1. **时机太晚**：econ-cap 前 10 回合就把经济铺开了（22 个），威胁 T10 才到 0.7——
   压住的是"后续投资"，不是"已经铺出去的单位"；
2. **压经济 ≠ 多造兵**：省下的钱受产兵格限制，不一定变成兵（这也是"7.5 万金"的同一个病）。

所以用户的方案方向对（威胁 → 少经济），但**输入时机**和**转化链路**都不对。

## 下一步建议

1. **开局就评估威胁**：信号 c 改成"敌城到我家城的行军回合 ≤ 4"（不是等敌人走到城下），
   在开局就把"该不该铺满"定下来；
2. 或者**高威胁时回收经济**：威胁 > 0.7 时允许拆/卖部分经济单位换兵
   （比"少投"快，但会亏钱）；
3. 或者**cap 按地图分档**：小图不铺满、大图铺满（保留大图的收益，避开小图的崩）。

第 1 条最符合原意，也最容易验：把 `threatScale` 在回合 1 就算出来，看 Q1 是否回到 4-2。
