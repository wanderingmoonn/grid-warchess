# 无城对战（F1）· 引擎方案（2026-11-16）

> 讨论稿，**还没写代码**。目标是把"双方或一方没有城、靠初始兵打一场"做成引擎能表达的东西。
> 计划里的位置：`PLAN-LEVEL-EDITOR-2026-11-15.md` 第八节（单开的引擎批，不属 E0~E6）。

---

## 一、这块要做什么

三种形态，实现上应该是同一套东西：

| 形态 | 例子 |
|---|---|
| 双方都无城 | 决斗图：两边各 8 个兵，谁先打光谁输 |
| 一方无城 | 攻城图的另一面：守方有城会补兵，攻方只有一支队伍，打不下来就没了 |
| 多人混编 | 三家局：两家有城打消耗，第三家是一支孤军 |

一句话：**"没城"从"立刻出局"变成"一种合法的开局状态"，代价是没有产线。**

## 二、为什么现在做不到（都查过代码）

| # | 位置 | 现在是什么样 | 不管它会怎样 |
|---|---|---|---|
| 1 | `rules.ts` `isEliminated` | `citiesOf(s,p).length === 0` 就是出局 | 无城方开局第一帧就"死"，回合轮转直接跳过它 |
| 2 | `checkWinner` 的存活条件 | "有兵 **或** 买得起一个兵" | 光改 #1 不够：无城方会一直"买得起"，**这局永远收不了场** |
| 3 | `retireLostSeat` | 三家以上局：丢光城 → 撤兵 | 无城方天生 0 城，这条会把它整支军队撤走 |
| 4 | `validateFixedMap` | `citiesA` / `citiesB` 少于 1 座就报错 | 关卡数据这一层就过不去，根本进不到建局 |
| 5 | `ai.ts` `advanceDistance` | 推进分 = 到**敌城**的距离场；没有敌城就是 `Infinity` | 双方都无城时 AI 会觉得"哪儿都不值得去"，全军原地不动 |
| 6 | `config.cityVision = 1` | 城提供 1 格视野 | 无城方在迷雾局里少一圈视野（不致命，但是个真实差异） |

### 2.5 顺带的口径变更：**把底薪删掉**（2026-11-16 定）

用户的原话："这个底薪本来就是莫名其妙的设计，全部删掉，包括有城的模式；
没有城市就应该没有产出。"

改法：`incomeResOf` 不再从 `CONFIG.baseIncome` 起算；各时代 `cityIncome` **各自 +20**
（现在的 30/35/41/48/56/62/68/78 → 50/55/61/68/76/82/88/98）。`CONFIG.baseIncome` 这个字段删掉。

**后果必须先看清楚**（这不是"等价替换"）：

| 场景 | 旧（底薪 20 + 城） | 新（城 +20，无底薪） | 差 |
|---|---|---|---|
| 无城 | 20 | **0** | −20（这正是要的） |
| 1 城 · 青铜（30） | 50 | 50 | 0 |
| 2 城 · 青铜 | 80 | 100 | **+20（+25%）** |
| 1 城 · 信息（78） | 98 | 98 | 0 |
| 2 城 · 信息 | 176 | 196 | +20（+11%） |

也就是说：**单城局一分不变；双城局每回合多 20。** 时代越高，相对影响越小（基数大）。

三条要跟着走：
1. `scripts/test-rules.ts` 里那条"收入 = 底薪 + 城 + 经济单位"的断言要改口径；
2. `scripts/build-manual.ts` 里规则书有两处写着"基础 20 + 每城"，要改；
3. `docs/ANALYSIS-ECON-2026-11-01.md` 一类经济结论**全部作废**（它们的基准是含底薪的收入）。

> 双城局要不要单独校准（比如双城时每城 −10）？我倾向**不校准**：
> 双城本来就该更富——它要多守一座城。但这条要写进文档，别以后被当成 bug 修掉。

另外两个"不是 bug 但会被误用"的点：

- **`incomeResOf` 有底薪**（`CONFIG.baseIncome`）。无城方照样进账，但**没有产线花不出去**——
  界面上会显示一栏永远变多的金币，玩家会以为能造兵。
- **招募必须有产兵点**（城市格或产兵建筑）。所以"无城 = 不能造兵"是自然结果，
  不需要额外写规则，只需要在界面上说清楚。

## 三、三种做法

| 做法 | 怎么实现 | 代价 |
|---|---|---|
| **A. 席位标记（推荐）** | `LevelSeats.cityless: PlayerId[]`，改上面 6 处判断 | 要动"出局"这个地基，风险最高；但语义最准 |
| B. 幽灵城 | 给无城席位放一座 0 血/隐形的城 | 污染收入、UI、AI、结算；而且"隐形城"迟早被人看见。否决 |
| C. 全局开关 | `config.cityless: true`，双方都无城 | 简单一半，但表达不了"一方无城"，而后者恰恰是更有意思的那一半 |

选 A。C 可以顺带支持（写一个"双方都填"的关卡就是 C），不需要单独字段。

## 四、详细设计

### 4.1 数据与校验

- `LevelSeats.cityless?: PlayerId[]`。不写＝老行为，一个空数组都不产生。
- `validateLevel`：
  - `cityless` 里的席位必须是这一局坐人的席位（否则报错，同 `ai` / `hidden` 的口径）；
  - **和城位互斥**：标了无城的席位不能在 `map.citiesA/B` 或 `seats.cities` 里有城
    （两边都写是自相矛盾，静默取一个会让人查半天）。
- `validateFixedMap`：现在是"For A/B 各至少一座"。改为接受一个选项
  `{ allowEmpty?: PlayerId[] }`，由 `validateLevel` 把 `cityless` 传下去。
  **地图文件上传那条路不传**——一个只有一方城位的 .txt 对普通对局仍然是坏数据。
- `level-lint`：无城席位**必须写 `deploy`**。不写＝开局零兵＝第一帧就出局，
  这是"作者忘了"的典型形态，要在编辑器里当场拦。

### 4.2 建局

`createMatch` 给某席摆城的循环里跳过 `cityless` 的席位。
没有别的改动——`deploy` 本来就会在城之后摆兵，顺序不用调。

### 4.3 出局与收场（这一块是全部风险所在）

要改三处，缺一处就出问题：

| 处 | 改成 |
|---|---|
| `isEliminated` | 无城席位：**没有单位**才算出局（`godMode` / `hidden` 是已有的两个同类豁免，照它们的形状加第三个） |
| `checkWinner` 的 `alive` | 无城席位只看"有没有兵"，**不看买不买得起**（他们买得起但造不出，那条腿在这里是假信号） |
| `retireLostSeat` | 无城席位直接 return（他们本来就没城，不该被"丢城撤兵"波及） |

收场逻辑因此不需要新增 goal：兵打光 → 出局 → 只剩一家 → 正常判胜负。
**不新增 `annihilate` 目标类型**，因为它等于把同一件事在两条路上各写一遍。

> **一个必须提前说清的后果**：无城方"兵打光 = 立刻输"。
> 如果这一关给它安排了后面几波援军，而它在第 8 次行动就被清光，那这局就到此为止——
> 引擎不会去读"未来还有没有兵"。所以：
> 要么保证前面不会被清光，要么给它一座城。这条要写进关卡简报和 GUIDE。

### 4.4 经济与生产

- **底薪已删除**（见 2.5）：无城方收入恒为 0。界面上就是干干净净的 0，
  不再有"涨着但花不出去"的数字。
- 想花钱？这一版**不提供任何出口**：不能造兵、不能修城（没城）、不能升级时代。
  这就是"孤军"的设定。以后要加（比如"用金币补员"）是另一个机制，别混进 F1。
- 顺带一个好处：`checkWinner` 里"买得起"那条腿对无城方**自然变假**了。
  但**仍然要按 4.3 改**——开局带着上一关余钱、或者事件给过钱时，那条腿还会真。

### 4.5 AI（最花时间的一块）

现状：推进分来自"到我方到敌城的距离场"，没有敌城时是 `Infinity`，
再经过 `bipolar(14 - focusDist)` 变成强烈的负分——**全军不动**。

两个做法：

| 做法 | 内容 | 评价 |
|---|---|---|
| **B1 完整** | 把"目标"从"某座城"抽象成"一个点"：有敌城时用城的重心/残城，没敌城时用**敌军重心**（或最近敌军）。`advanceDistance` 的 `focusCityId` 换成 `focusPoint` | 语义干净，改动面中等（`focusCity` 在 ai.ts 里出现 35 次，多数是参数传递）；推荐 |
| B2 最小 | 没有敌城时把 `focusDist` 钉成一个中性值（比如 6），让推进分不为负，靠本来就有的"打最近敌人"逻辑自己找架打 | 改动极小，但"往哪推"没有方向，容易变成两边互相绕圈 |

**建议先做 B1**。理由：这一步不做，"AI 能不能打无城局"就永远只能靠人肉调参数，
而参数调不动"没有目标"这件事——那是结构问题，不是权重问题（和"AI 不渡河"同一类教训）。

验收不许看配置表：**AI 对 AI 跑 3 局，逐局看无城那一方有没有"全员连续 5 次行动没位移"**。

### 4.6 视野

城提供 1 格视野。无城方在迷雾局里会少一圈，这是真实的战术差异，不是 bug。

建议：**不补偿**，但写进关卡简报（"这一方没有城，也就没有城的视野"）。
真需要时，作者可以给无城方配一个"营地"单位（用 `units` 面板做，已经有这个能力）。

### 4.7 界面清单

| 位置 | 要改什么 |
|---|---|
| 选关卡 / 任务简报 | 写清"红方无城"；说明它没有产线、兵打光即输 |
| 顶栏（当前方） | 无城方不显示城血/收入；显示"无城" |
| 侧栏（兵力/经济） | 收入那一栏标"无产线" |
| 结算卡 | 无城方输的时候，别写成"城市全部失守"（它从来没有城） |
| 编辑器 | 席位面板加"这一家没有城"的勾；勾上之后画布不能再给它摆城 |

## 五、兼容与回归

- **老存档**：`cityless` 不存在 → 空 → 行为一个字不变（这是 `LevelDef` 加可选字段的既有规矩）。
- **普通对局**：`config.level` 为 null，走不到任何新分支。
- **复盘**：数据全在关卡快照里，重走时同一份 `cityless`，确定性不受影响。
- **多人局**：`retireLostSeat` 的改动只多一个 early return，其余不动。
- **必须跑的**：`npm run probe:level`（26 段）、新增的 F1 用例、三张内置关的 AI 对 AI 各 1 局
  （确认"有城的局"一点没变）。

## 六、验收（可执行）

1. 双方无城的决斗关：能开局、能打完、有明确赢家、**不出现"跑到 1200 次行动还不结束"**；
2. 一方无城的攻城关：无城方兵打光 → 判负；有城方城破 → 照旧判负；
3. **零兵的无城席位**：建局时就被拦（lint），不会静默变成"开局即输"；
4. AI 对 AI 3 局：无城方不出现"全员连续 5 次行动没位移"；
5. 三张内置关 + 老存档 + 老复盘：行为不变；
6. 迷雾局：无城方视野确实少一圈（这是预期，写进用例避免以后被当 bug 修掉）。

## 七、明确不做

| 不做 | 理由 |
|---|---|
| 无城方的产线（营地/传送门/空投） | 那是新机制。要补兵就用事件（`spawn` 已经能做，而且"从边缘进场"是作者该做的决定） |
| 无城方专属经济（修理费、招募点） | 金币先当死数字；真要做是另一个批次 |
| 新增 `annihilate` 目标类型 | 出局判定修好之后是重复表达 |
| 无城方的视野补偿 | 那是设计选择，交给作者用单位解决 |
| 把 `cityless` 做成全局 config | 席位级天然能表达"双方"，反过来不行 |

## 八、已定的四件事（2026-11-16）

1. **AI 走完整方案（B1）**：把"目标"从某座城抽象成一个点，没敌城时用敌军重心。
   结构问题不能用权重糊。
2. **底薪全部删除**，包括有城的模式；各时代城市收入各自 +20 补回来（见 2.5）。
   单城局一分不变，双城局每回合 +20。
3. **视野不补偿**，如实写进关卡简报。
4. **无城方兵打光就输**，接受。带后续波次的关卡要自己保证前期不会被清光
   （这条写进简报和 GUIDE，别让它变成隐藏失败点）。

**唯一还需要确认的**：双城局 +25%（青铜）这个变化接受吗？我的建议是接受、
不额外校准——双城本来就该更富。如果不想动，就得让"每城加成"随本方城数分摊
（每城 +20/N），那会让单座城的收入取决于你有几座城，反而更难解释。
