## 二、P0：当前真正卡胜负的

### P0-1 开局被速推 —— 三局负全在 78~84 回合

```
Q1|30|新A  负 78 回合     Q1|31|新B  负 79 回合     Q3|31|新A  负 84 回合
```

**现象**：不是拖到后期打不动，而是中期被一波打死。同一形状在
`AUDIT-SOLVERS` 里记过一次（"48 回合崩：敌人大军压境还在发展"）。

**机制上的猜测（未验证）**：威胁没有参与 `horizon` / `econUntil`。
现在是"先按固定窗口发展经济 → 威胁到了再转兵"，转的时候已经晚了。

**下一步（不改代码先量）**：把这三局的崩盘时间点拉出来——
第几回合开始丢城/丢兵、当时 `econUntil` 是多少、敌方兵力从第几回合超过我方。
如果确认是"经济窗口没随威胁收缩"，再动 `horizon`。

**注意**：`EXPERIMENT-4WAY` 试过"威胁 → 压经济"，**both = cap 逐局完全相同**，
原因是"econ-cap 前 10 回合就把经济铺开了，压住的是后续投资，不是已经铺出去的单位"。
所以这次要么在**开局**就算威胁，要么做**回收**（卖/拆经济换兵），不能重复那条路。

### P0-2 没有进攻配额（PLAN 39/40 节）

- **现状**：编队只看"有没有 free 单位"，有 9 支就开 9 支；没有"这一波总共投多少人"。
- **后果**：兵力被摊薄，每支都不够厚；也解释不了"什么时候该收手"。
- **要做的**：战略层给总配额（按目标守军 / 我方兵力），组建编队时消耗配额。
- **依赖**：与 `postureBudget` 的关系要先理清。

### P0-3 钱变不成兵（产兵格是瓶颈）

- **证据**：`aiEconCap` 能让经济单位铺到 40 个、终局剩 7.5 万金，**胜负不变**。
- **`aiEconPlan`（残值 R=4）**：9-3-0 vs 基线 10-2-0，差在 Q2；可试 R=3 或边际递减。
- **要做的**：查 `productionCapacity` 曲线、产兵建筑数量、产兵格被占比例；
  必要时让 AI 建军营/工厂，而不是只加钱。
- **`aiEconCap` 不要删**：它是"迟早要打开"的开关，小图崩的原因是配套没做
  （产兵格 / 工人 / 威胁响应），不是"经济不该做大"。

## 三、P1：结构缺口

### P1-1 进攻编队没有伤亡回收（零风险，建议先做）

- **现状**：`note:'attrition'`（`lost ≥ 2`）只用于**上报**，编队照样留着；
  成员死光了只要 `count > 0` 就继续挂着。
- **证据**：`Q4|31|A` 的 `atk-3-55`：兵 7→5、**停 63 回合**一直没解散；
  `atk-4-83` 停 48、`atk-8-149` 停 55，编队数从 1 涨到 8，全卡在离目标 5~12 格。
- **要做的（按保守到激进）**：
  1. 成员全死（`count === 0`）→ 立刻丢弃（纯正确性问题，零风险）；
  2. `count < 3` 且 `lost ≥ 2` → 丢弃重组；
  3. `stalled ≥ 20` → 丢弃并回冷却。
- **风险**：编队成型要 10 回合，淘汰太快会更弱。第 2、3 条各自跑批。

### P1-2 编队没有"撤退"指令（PLAN 39）

- 只有"全灭 / 伤亡过重"被动解散，被反推时不会主动脱离。
- 与"建造编队待机 3 回合解散"是同一类需求，可共用一个 `retreat` 出口。

### P1-3 升级选城没有画像

- **现状**：`upgradeCandidate` 只按 `spare` 比例、时代差、"是不是最高时代那座城"给分。
- **缺**：离前线多远、产兵格多少、会不会立刻被拆。
- **要做的**：给每座城算"升级收益"（产兵格数 × 安全度 × 前线距离）。

### P1-4 建造编队第 2/3 步

- **第 2 步（收拢与下单）**：`squadTick` 的 `free` 只算 combat，要把 builder 放进未编队池；
  组建时优先收拢附近散工，判据 `dist(工人, 渡口) < dist(工人, 最近自家城)`；
  收不到就报 `builderNeed`（第 1 步已经能变成采购请求）。
- **第 3 步（状态机）**：`AiSquad.state` 加 `building` / `holding`，
  并同步 `planSummary` / UI / `squads.jsonl`。
- **现状**：建造编队**只有 1 人**（第二个不硬挤）。

## 四、P2：地图与战术

### P2-1 渡口选点没有连续性（"8 座桥散在河湾"的根因）

- `crossingPointOf` 每次挑"离对岸最近的岸"，不要求沿**已铺的桥面**往下接
  （`buildSpots` 有 `bridgeChainOk`，选点上没有）。
- 实测 Q3/seed30：桥 8 座、**关键 0 座**、坐标 T120→T260 一字未变，全是碎片。
- 换渡口（`noLink ≥ 30` / `cut ≥ 2`）只缓解，不治本。
- **成本高**：要改选址逻辑，单独一批跑。

### P2-2 水军封锁（用户 2026-11-23 反馈）

- AI 没有"敌方控制水域"的概念：岸线被船罩住，陆军/经济只能挪一格躲，躲不出射程就卡住。
- **三层**：① 水域威胁图（复用 `tactical.exposure`）；② 陆军走位加"离敌方船射程 X 格"惩罚；
  ③ 反舰决策（造自己的船 / 岸基远程赶船）——第三层是全新的。
- 先做 ①②。

### P2-3 `commit` 门槛写死 8 个兵

对面 20 兵时，8 兵全军压城就是排队送。要跟对面兵力比。

### P2-4 绕路只在"换城"层

没有"同一座城换一条进攻路线"（比如从另一侧过河再打同一座城）。

### P2-5 走位不绕防御建筑火力圈

建筑现在是**集火目标**，但走位评分里没有"绕开它的火力圈"这一项。

## 五、P3：计划层与体验

### P3-1 `trade` / `turtle` 还在 `stance` 里（PLAN 27）

它们**不能只用权重表达**，要先补三个出口（一次加一个，各自可验）：

1. `PlanWeights.pullHome`（0~1）：离家惩罚强度，`turtle` 用；
2. `PlanFocus` 从 `{x,y}` 扩成 `{x?, y?, cityId?}`，`trade` 用它指定主攻方向；
3. `plan.switches: { commit?, guard? }`：布尔，最容易搅乱行为，最后加。

顺序：`pullHome` → 搬 `turtle` → `focus.cityId` → 搬 `trade`。

### P3-2 `readyTurns` 没有消费者

扫描算出了"第几回合该开战"，但没有执行机制（编队 deadline、按 deadline 攒兵）。

### P3-3 回放面板不显示建造编队

`aiFocus[me].squads` 里有数据，`planSummary` 只统计 attack/defend。
39.3 的"v3 在想什么"小窗口整体没做——**等战略层落地再做**，否则是个空壳。

### P3-4 采购是"每金战力"不是"每产兵位战力"

后者只在 `power-solver.pickUnit`（钱瓶颈/名额瓶颈切换），没进采购。
只有在"钱花不完、名额是瓶颈"时才有差别——和 P0-3 同源。
