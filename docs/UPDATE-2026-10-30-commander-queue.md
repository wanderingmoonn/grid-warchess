# 指挥官模式：产兵操作改成和常规模式同一套

日期：2026-10-30

## 以前什么样

同一个动作，两套操作。

常规模式：点棋盘上的城 → 右侧弹出城市面板 → 在「生产」列表里点兵种，当场扣钱出兵。

指挥官模式：右侧城市面板里的产兵按钮**全部消失**（`mine` 在指挥官模式下被当成假，
理由是"你又不亲自造"），排队只能去顶端「参谋部」用下拉框写：5 格 × 两个下拉
（造什么 / 由哪个产兵点造），共 10 个 `<select>`。外面还挂着一排 DLC chip 和一排时代 chip
当筛选器。

后果有三个，都是真实玩家报上来的：

1. **得先想"我现在是哪种模式"**。点开城，右侧空空如也，第一反应是"这座城不能造兵了"，
   而不是"要去上面写下拉框"。同一座城、同一个兵，两种模式下入口不在一处。
2. **看不见兵**。下拉里只有一行字（"长弓手 · 40 金"），射程几格、护甲多少、血多厚全都没有。
   想知道这个兵值不值，得先去翻规则书，回来再翻一遍下拉。
3. **筛选器是另一套记忆**。常规模式的产兵面板有搜索框、有职能分组、有扩展包徽标；
   参谋部这套 chip 是另外写的，两边的筛选语义还不完全一样。

## 现在什么样

**排队只有一条路：点自己的城（或军营）→ 在右侧面板点兵种。**

面板本身是同一个 `renderPanel` / `renderCity`，指挥官模式不再把它藏起来，
只是把按钮的落点从「生产」（`data-act="recruit"`）换成「＋队列」（`data-act="order-add"`）：

- 按钮右侧多一颗 `＋队列` 标签，一眼看得出这一下是排队、不是当场出兵
- **不看当下余额**：钱是 AI 执行那一回合才花的，用此刻的金币把按钮禁掉，
  等于逼玩家先攒够钱再来排计划
- 城市面板里那颗「升级到「X」时代」在指挥官模式下也是排进队列（`data-type="@upgrade"`），
  同样带 `＋队列`
- 排满 5 格之后，产兵按钮与升级按钮**一起置灰**（以前点下去只弹一句"队列满了"）

**顶端那条「参谋部」只剩展示**，一字排开 5 格：

```
参谋部   点自己的城市 → 在右侧点兵种，就排进这条队列          已排 2 / 5
① 长弓手 · 云中城   ≈ 120 金  ×   ② 升级时代 · 云中城   ≈ 90 金  ×   ③ 空 …
                                    跑完这批预计剩 ≈ 240 金   [清空] [执行 5 回合]
```

- 队首编号、兵种名、产兵点（城市名 / 军营兵种名，没指定就写「自动选址」）
- 每格后面是 `≈ N 金`——那一回合大概有多少钱可花；注定造不出来时，同一个位置直接写原因
  （时代不够、英雄已在场），并标红
- 每格一颗 `×`：**按位置删**，不是按兵种删。同一条队列里可以有两次同一个兵
  （两个回合各造一个），按兵种删会把两格一起抹掉，而玩家只点了其中一格
- 右侧「清空」一次清完；条尾那句「跑完这批预计剩 ≈ N 金」跟着队列实时变

## 交互流程（一条完整的路）

1. 开局选「你的角色 → 指挥官模式」
2. 点棋盘上自己的城（城牌本身 `pointer-events: none`，点下去命中的是城脚下那格 tile）
3. 右侧城市面板照常弹出：耐久、护甲、收入、驻军，下面是完整的产兵列表
4. 点「长弓手」那一行 → 顶端队列第 1 格亮起「① 长弓手 · 云中城 ≈ N 金」，地图不变、钱不扣
5. 再点一次「长弓手」→ 排进第 2 格（同一条队列允许重复，两个回合各造一个）
6. 排错了：点那一格的 `×` 只删那一格；点「清空」一次清完
7. 点「执行 5 回合」→ 参谋部换成进度条，AI 按队列一回合造一格；中途「中断」可停
8. 联机房里同一条队列，按钮写「执行本回合并提交」——一次打完你自己这一回合，然后把动作交给对面

## 顺带修掉的一个真问题

`smoke-dom` 里"点自己的城"那几条测试原来是把合成事件打在 `.city-block` 上。
城牌是 `pointer-events: none`，真实浏览器里手点下去命中的是城底下那格 `.tile`，
而 `.tile` 才带 `data-x/data-y`（`coordsFromEvent` 只认这个）。合成事件打在城牌上
拿不到坐标，点击被当成"点空白"。

测试改成按城坐标去点那一格 tile——和玩家的手走同一条路。顺手补一条断言：
点完城之后城本身要亮起选中态。

## 回滚

这批只改界面层，`src/core` 零改动，所以回滚不需要迁移存档：

```bash
git revert <本批 commit>
npm run build:static && node scripts/serve-static.mjs
```

旧存档里的 `orders` / `orderSites` 在新旧两版里含义完全相同，
回滚后队列内容仍然读得出来（只是编辑入口换回下拉框）。
