# 更新公告 · 2026-10-29 · 连击改成"多动式"：溢出的段可以打别人

> 一句话：**多段兵打一个人，前面几段把他打死了，剩下的段不再白扔**——
> 可以先把旁边的敌人排进队列，富余的段依次转过去。
> 不排队的话，和以前一模一样。

---

## 一、以前什么样

多段攻击（`burst`）是在**一次 ATTACK 动作内部**跑一个循环：

```ts
while (hits < burst && defender.hp > 0) {
  const one = computeDamage(s, attacker, defender);
  defender.hp -= one;
  ...
}
```

后果是：目标死了循环就停，**剩下的段直接蒸发**。机枪 3 段打一个只剩 1 血的民兵，
只有 1 段生效，另外 2 段的火力凭空消失。战场上这很常见——多段兵本来就是为了
"扫残血"存在，可它连"顺手扫掉第二个残血"都做不到。

## 二、现在什么样

每一段变成**一次独立结算**，按顺序执行，目标可以逐段变化：

1. 主目标还活着 → 所有段继续打它（和以前完全一致）；
2. 主目标倒下 → 剩下的段按玩家事先排好的**溢出队列**依次转过去；
3. 队列里每个目标会被连续打到倒下，才轮到下一个；
4. 队列空 / 目标都打不着 → 剩下的段作废（不会凭空打空气，也不会变成非法动作）。

界面上怎么排：选中多段兵 → **右键点射程内的敌人**排队（橙色虚线框）→ 左键点主目标开火。
右键再点同一个人就是取消。换选中单位、开完火，队列自动清空。

## 三、兼容性：不排队时逐点一致

| 环节 | 变化 |
|---|---|
| 每段伤害 | 不变：仍然每段单独调用 `computeDamage`，护甲/地形/属性每次都重算 |
| 打满段数 | 不变：主目标活着就一直打它，所以"3 段全打一个人"的总伤害与以前相同 |
| 提前停手 | 不变：目标死了、又没有溢出目标，剩下的段作废 |
| 反击 | 不变：仍然只在全部段结束后判定一次，且只属于**主目标**；溢出目标不还手 |
| 溅射 | 不变：仍然以主目标为中心结算一次 |
| 命中状态 / 吸血 / 击退 | 不变：一次攻击结算一次，挂在主目标与总伤害上 |
| 战报 | 不排队时逐字一致；排了队会多一段「溢出打 民兵 8、民兵 7」 |
| 行动次数 | 不变：整次连击仍然只消耗这一次 ATTACK（`acted`）|

新增的只有一条：溢出段击杀也会走完整的善后（战报 + 沉船 + 击杀钩子/经济奖励）。
唯一刻意不给的是"收割"（刺客大师击杀后返还移动）——那条能力写的是"亲手斩掉"，
指的是这一击的主目标。

## 五、影响范围

- **规则**：只在 `burst > 1` 的兵种上生效，且必须有人真的排了队。不排队的对局
  数值一条不动（352 项规则测试里原有 351 项全过）。
- **联机 / 存档**：`Action` 多一个可选字段。老客户端读到带 `spillTo` 的动作会忽略它，
  退化成"打主目标"；新客户端读到不带该字段的动作照旧。不涉及存档结构。
- **AI**：**这次没让它用**。AI 仍然只提 `{type:'ATTACK', unitId, targetId}`，
  所以它对局表现与以前完全一致。要不要让 AI 也会排溢出，是下一件事——它得先学会
  算"这个目标会被几段打死"，否则排了也是浪费。
- **预览**：`previewAttack` 仍只算主目标（它算的 `hits` 就是"打满还是提前停"）。
  排了溢出目标时，预览不会把溢出的伤害算进来——这一点写在界面上会更好，暂时没做。
