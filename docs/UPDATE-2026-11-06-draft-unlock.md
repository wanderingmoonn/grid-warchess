# 升级预览只列真能造的

**v0.3.39（2026-11-06）** · 选卡模式下的城市面板

## 一句话

选卡模式里点自己的城，「升级后可解锁」那一行原来会把**池子里没选到的卡**整批列出来；
现在它只列这一局真能造的兵，而经济单位、建造单位、生产性建筑与桥（本来就不用选）照旧列。

## 原来错在哪

`ui/panel.ts` 里那行提示的判据只有一句 `def.era > city.era`：
"城市升级之后，所有更高时代的兵种"。

在普通对局里这没毛病——兵种表就是全部兵种。但选卡模式把兵种表切成了"这一局能用的那批"，
而这条判据完全不看名单，于是：

> 升级后可解锁：圣剑勇者、九头蛇、天使……

升完级，这些一个都造不了。这句话比不写更糟：它把"你没选到"说成了"再等等就有"。

## 现在怎么判

判据收到 `core/draft.ts` 的 `upgradeUnlocks(state, side, era)`，和产兵表**共用 `canUseType`**：
没选到的卡不出现；`draftAlwaysAllowed` 的那几类（经济单位 / 建造单位 / 生产性建筑 / 桥）不受选卡影响，照旧出现。

两条例外是刻意保留的：

- **经济与建造单位**：伐木工（二级）、民夫（二级）、种植园主、工程师……这些本来就不进池子，
  升级解锁它们是**真事**，玩家升级前正想知道；
- **召唤物不算**：它们只能被召唤者带出来，谁也"解锁"不了。

顺带把"能造"的判据收成一份：面板里的 `buildable` 与 `upgradeUnlocks` 现在读同一个 `canUseType`，
以后再改"什么算可用"只改一处。

## 钉住的用例

`npm run test:ui` 里加了一条，直接摆一局选卡模式、把池子选满，再渲染 A 方城市面板，两个方向都断言：

1. 提示里每个名字，要么在这一局的 picks 里，要么属于 `draftAlwaysAllowed`；
2. 池子里**确实存在**没选到的高时代卡，且它们一个都没出现在提示里；
3. 反面：伐木工、民夫、石桥必须还在（这条正是"别一刀切"的守门）；
4. 面板列出的等于 `upgradeUnlocks()` 的结果——防止以后有人在面板里再写一份判据。

把面板还原成旧那一行，这条用例会红（183 通过 / 1 失败），验证过。
