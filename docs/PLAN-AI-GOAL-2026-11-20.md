# 产业链目标（AiGoal）——计划与待办

> 2026-11-20 开。目的：让随机对局里的 AI 能自己修炼（走完宗门 → 藏经阁 →
> 研发 → 研读 → 施法），顺便把"AI 做不了投资"这个老毛病从根上解决。
>
> 结构说明见 `src/core/ai-goal.ts` 的注释；这份文件只记**计划、进度、待办**。

## 一、要解决的问题

AI 的每一个动作都是当场比分数选出来的。这套打法做"买一个兵、走一步、打一下"
很好用，但做不了**投资**——投资的第一步（建宗门、建电站、建船坞）当下一定
不如"再买一个弓兵"。于是引擎里长出一堆手写补丁（`seaDemand`、
`armorSupportNudge`、采购里那条「工程机组 +45」），形状一样，各写一份。

实测过的两个后果：

| 现象 | 数 |
|---|---|
| 20×20 纵河图 4 局，AI 造桥 40 座，船坞 **0 座** | `diag-build` |
| 79 次交棒的对局里，宗门 / 藏经阁 / 研发 **全是 0** | 修真包全开 |

## 二、机制概要

```
目标（扩展声明）  = 价值 + 有序的几段
每一段            = 完成判据 + 「建什么」或「做什么动作」
承诺（存在局面里）= 我在追哪一条的哪一段
```

三条纪律：

1. **核心不认识任何扩展**。判据用数据（`buildOn` 有水），不用兵种 id。
2. **目标归扩展声明**（`Expansion.aiGoals`），核心自己的海军/装甲也走同一个
   注册口，不留特例。
3. **扩展写坏了是扩展的问题**：抛错按"没这个目标"处理，不打死整局。

## 三、承诺：进去容易、出来难

每回合重算价值（局势会变），但"要不要放弃"用**相对**判据：

- 立约时记下当时的价值 `valueAt`
- 掉到 `valueAt × 0.6` 以下才放弃（中间四成是死区，小扰动跨不过去）
- **`urgent` 直接打断**，不看分数（大军压境时一切投资让位）

## 四、验收（每一步都跑，两个口径）

**A. 胜率**（对外）：`scripts/ai-duel.ts`，新 AI 对冻结的旧 AI，
20 种子 / 40 局 / 每颗种子两边各执一次先手，约 3 分钟。

冻结基线：`scripts/baselines/ai-22702c6.ts`（产业链改造开始前的那一版）。

> 灵敏度已验：同一套工具跑「tactic vs basic」20 局 → 优势方 87.5% 胜率、
> z=2.68。所以"跑出 50%"是真的没差距，不是工具坏了。

**B. 机制计数**（对内）：证明"它真的在玩这个东西"，而不是"分数碰巧没变坏"。
`probe:ai-goal` 打印每局的建造/招兵分布；`diag-build --exp <包>` 打印建造明细。

## 六、待办（不许忘）

### T1. 威胁判据已拆出来（2026-11-20 第一版）

**已做**：`threatLevelOf` —— 只算"能攻城的战斗单位、下回合够得着、没放弃的城"，
按攻击力求和，`THREAT_ATK = 40` 就算"大军"。产业链的承诺改吃 `threat`，
不再吃 `urgent`（那条 `army < 3` 会让开局永远"吃紧"，承诺每回合被清）。

**顺带修掉一个死锁**：素体目标原本和电/坞并列（都值 1），而目标是按注册顺序
抢并列的 → 素体排在前面就一直"攒一台装不了炮的素体"，**40 回合一台电站都没建**。
现在素体的 `value` 要求"有电有坞"才成立（和采购里那两道门同判据）。

**装甲现状（28×28，两局跑到 200 回合）**：

| 种子 | 结果 |
|---|---|
| 8100 | 一局只打了 29 回合就分胜负，来不及 |
| 8191 | **首次素体 t26**；t150 时 5 台；终局素体 4/2、**装配件 3/2** |

所以答案是**来不及，不是不想买**：链能跑通（素体买得到、炮也装得上），
但起步要 26 回合左右，而高时代对局常常在那之前就结束了。

这条顺带说明 T9（验收窗口）不是可选项：**验收时长本身就是一个参数**。

**下一步的两个方向**（择一或都做）：
- 加长验收窗口 / 加厚高时代开局经济（先确认这是"来不及"而不是"不想买"）
- 让素体这一步也进攒钱表（已经有 `cost`，但要在坞完成之后才激活）

**T1 三条收尾（2026-11-20 全部做完）**：

1. **只算"守不住多少"**：从"有人靠近"改成"攻方战力 − 城附近我方战力"，
   逐城算、取差值最大的一座。守得住的城不再打断投资。
2. **谁在打**：改用规则层的 `isArmed`（`atk` 或 `magicAtk` 或挂的能力），
   不再用 `atk > 0`。这条对修真很关键——**只放法术的修士 `atk = 0`，
   以前完全不算威胁**。
3. **阈值标定**：`THREAT_ATK = 80`（净值）。20 / 40 / 80 各跑两局：

   | 阈值 | 8191 | 8272 |
   |---|---|---|
   | 20 | t26 · 0/0 · 0 装 | t56 · 4/0 · 3 装 |
   | 40 | t26 · 0/0 · 0 装 | t56 · 4/0 · 3 装 |
   | **80** | t26 · **4/0 · 3 装** | t56 · **6/0 · 6 装** |

   阈值低的时候一队小兵路过就把投资打断，链永远走不完。
   **缺口：只有两个种子，且没量胜率。**

**用法文档**：`docs/GUIDE-AI-GOAL-2026-11-20.md`（怎么加新目标、五个坑、八条自检）。

### T1-旧. 威胁打断要细化（原始笔记，保留）

现在的 `urgent`（和"攒钱"共用）：

```
urgent = (自己战斗单位 < 3 && 不是安全后方 && 没在弃城) || 有敌人摸到城下 3 格
```

**对"打断产业链"太敏感**：对面一个侦察兵跑到城边，攒到一半的组合当场作废。
计划改成"威胁值"：

- 只看**能攻城的战力**（围城单位 / 对城有伤害的单位），侦察兵不算
- 只看**受威胁的那座城**（弃城、后方城不算）
- 阈值要"真的像大军"，比现在的"有人靠近"高一档

落地位置：`isUrgentNow`（`ai.ts`），或者给 `AiGoalCtx.urgent` 换一个更细的字段
（`threat`），两者并存：`urgent` 继续管攒钱，`threat` 管产业链。

### T2. 机制计数要进常规验收

胜率之外必须同时报：船坞 / 电站 / 宗门 / 藏经阁 / 研发数 / 施法次数。
现在的做法是手工跑 `diag-build` 和 `probe:ai-goal`，**没有统一口径**，
以后要收成一个"每步都能跑、结果可对比"的脚本。

### T3. 雾中建造撞车（老 bug，2026-11-20 才发现）

AI 的建造候选在**雾图**上算（那格站着看不见的敌人），执行在真局上做（那格有人）
→ 被规则拒。实机从 2026-11-19 起会**顺延**（`rejected.add + continue`），
所以只白费一步；但跑批脚本一直是 `break`（已改成顺延）。

真正的修法有两条，任选：
- 给建造补"真局再核一次"（和当年走位落点那个修法同构，见
  `docs/UPDATE-2026-10-28-height-terrain.md`）；
- 或者接受"实机顺延就够了"，只在跑批里保持同样口径（已做）。

### T4. `aiIntent` 的合并

`aiIntent`（攒钱目标）本质是一个只有一段（"攒够钱"）的 AiGoal，而且它更特殊：
它同时是**闸门**（本轮别乱花）。第 2b 步没有合并它，只把承诺单独做成了
`aiCommit`。合并时要解决：一个目标如何同时"出候选"和"拉闸门"。

### T6. "造太多"：建造事件 ≠ 现存建筑（2026-11-20 量过）

用户提的："7 个船坞、34 座桥，人打的话不会造这么多，钱拿去造军队早赢了。"

量了一局（20×20 纵河、海军包、90 次交棒）：

| | 数 |
|---|---|
| 建造事件 | bridge2×12、factory×6、bridge×1、tower×1、camp×1、watermill×1 |
| A 现存建筑 | bridge2×6、factory×3、tower×1、camp×1、watermill×1 |
| 花钱结构 | 建造 2400 / **招兵 10900** / 升时代 2000 |

两条结论：
1. **"造太多"有一半是统计口径**：`diag-build` 数的是建造**事件**，桥被打掉再修、
   或升级替换都会再计一次。现存只有一半。
2. **钱的大头确实是军队**（73%），建造只占 16%。所以"钱没变成军队"不成立。
   但终局压着 785 金没花（编制满了花不出去），这是另一个老问题。

先不修，理由：不是本批改动引入的（改前 40 座桥，现在 34），而且现在停下来调
会把"承诺层"和"桥的分数"两个变量混在一起。**判据**：如果某个里程碑之后
建造占比超过 30%，就停下来查。

### T7. 半压制对"所有被目标认领的建造"生效了

2a 把"过河压制"对目标认领的建造减半（−20 → −10）是为了海军，但装甲迁进来之后
它也跟着吃这个减免（电站本来吃 −45，现在是 −10）。实测装机电站从 2 → 5 座。
这是**行为变化**，不是纯迁移——如果后面觉得装甲基建太多，先看这一条。

### T8. 装甲链断在第一环：AI 根本不买素体（2026-11-20 量出来的）

| 尺寸 | 电站 | 装配坞 | **现存素体** | 装了配件的 |
|---|---|---|---|---|
| 12×12 两局 | 4 | 0 | **0 / 0** | 0 |
| 16×16 两局 | 4 | 0 | — | — |
| 24×24 两局 | 4 | 2 | — | — |
| 28×28 两局 | 4 | 3 | **0 / 0** | 0 |

电站会盖（每局两座），坞在大图上也会盖，但**素体一台都没买过**——
所以整条链的后半段（装炮、打）根本没有发生。`armorFrameScore` 把素体估值
封顶在 34 分，采购里永远输给同代常规兵。

**这就意味着第 3 步的验收是假的**：迁了一段没人走的链路，测出来的 45%/50%
和装甲本身无关。

第 4 步做完之后的复查（2026-11-20 晚）：
- **受控局面**（4000 金 + 已有的电站和坞）→ AI 立刻买 `armor_anvil×2 + armor_hawk×1`，
  素体 3 台。说明"目标认领兵种"这条路是通的。
- **真实对局**（era7、28×28、90 次交棒）→ 素体仍然 0。采购追迹给出的拒因：
  `钱不够 ×578`、`没电 ×36`、`时代未解锁 ×65`，终局金币只剩 39。

所以装甲链真正的断点是**经济**，不是偏好：
高时代开局的钱撑不起"电站 620 + 坞 420 + 素体 420~820"这一串，
而 AI 每回合有三格采购名额，会不断拿去买便宜兵。
这一条要单独处理（要么让 `savingFor` 认素体、要么调开局经济），
在那之前**装甲的胜率验收没有意义**，只看机制计数。

### T9. 验收地图尺寸（2026-11-20 量出来的）

`DEFAULT_CONFIG.size = 12`，而 `ai-duel` 一直用它——**对第 5 代以上根本不适合**：
作战半径比地图还大，兵一回合就到对面城下，没有投资回报的空间。

但往大调也有代价（era7 + 装甲，8 种子 / 16 局）：

| 尺寸 | 战绩 | 未决 | 均回合 |
|---|---|---|---|
| 24×24 | 3 胜 5 负 **8 平** | 50% | 124 |

所以"高时代验收"缺的不是地图，是"能在有限回合内分出胜负"。

验 5 代以上先别把胜率当主要判据，**看机制计数**（素体数、配件数、电站数）。

### T10. 产业链进攒钱表（2026-11-20 已落）

`SaveGoal` / `AiIntent` 加了 `kind: 'goal'`，产业链的当前段可以直接进
"为它停手攒钱"那张表，和**兵 / 英雄 / 升时代 / 收废墟共用一把尺子**
（`saveScore` 由扩展给，默认 8）。另外两处配套：

- `AiGoalStep.cost`：这一步要多少金（不写就不进攒钱表）
- **建筑冻结豁免**：`buildAllowance` 的老口径是"余额 − 目标价"，
  攒钱期把建筑冻死。产业链自己那一步的建筑必须放行，否则"攒钱建宗门"
  里宗门永远建不了。**只放目标认领的那一种**，磨坊照旧冻结。

实测：装甲局里 AI 有 16 / 8 个回合处于"为产业链攒钱"状态（`aiIntent.goal==='goal'`），
机制是通的。

**但素体仍然是 0 台。** 卡在哪已经定位：`armor-frame` 的承诺在第 20 回合被清空，
因为 `urgent` 里有 `army < 3`——开局兵本来就不够三个，于是永远"吃紧"，
承诺每回合被清。见 T1。

### T11. 产业链的建造，工人不会"走过去" —— 已做（2026-11-20）

修真链接上之后卡在这里（2026-11-20 实测，24×24 / 160 回合 / seed 8191）：

```
城时代 5 · 金币 87 · 灵石 21 · 会盖藏经阁的执事 1 个
选址原因：这里已经有单位或建筑了×11 · 必须紧邻宗门大殿×5 · 越界×5
```

条件全齐、人也在，但**宗门旁边没有空位**，而工人不会为了"给藏经阁腾个位置"
而移动。通用建造只看**当前站位周围**的格子（`buildSpots`），移动评分里
没有任何一项在说"往那个能盖东西的位置走"。

这是产业链机制的一个缺口，不是修真特有的：**装甲的电站、海军的船坞都吃同一刀**
（只是它们对位置不挑，所以在空地上总能找到地方）。

**已做**：`goalApproachCandidate`——建造候选在"脚下没有合法位置"时，额外发一条
MOVE，走向"能盖这个建筑的地方"。核心仍然不认识任何具体建筑：

1. 扫自己城市/建筑周围 10 格；
2. 逐格问规则层 `buildSiteError`（**关键**：要把工人"假想站在这一格"传进去，
   否则永远得到"建造者离得太远（最多 2 格）"——这条坑了半小时）；
3. 逐格问目标 `buildScore`，挑最高分的那一格；
4. 从可达格里找"站上去就能盖"的位置，发 MOVE，分 = 那一格的分 × 0.7
   （比真盖上低一档：能盖的时候当然先盖）。

**验证**：手工局面（执事在宗门 5 格外、田和宗都齐）→ AI 第一步就是
`MOVE→15,22`，朝能盖藏经阁的位置走。机制通。

**但真实对局里藏经阁还是 0**，原因换了：seed 8191 终局**金币 87**（藏经阁要 120），
seed 8100 卡在灵田那一格（田只有 1 座）。所以剩下的阻塞是**经济**，不是站位。

### T12. 多资源（灵石）与攒钱表

攒钱表只认**金币**：`savingAllowance(gold, inc, targetCost)` 三个参数都是金币。
灵石没有"存起来"的语义——它是**灵田的每回合产出**（1/田/回合）。

所以修真链把"攒灵石"翻译成了**"先把灵田建够"**（第一段就是灵田 ×2），
而不是给核心加一套多资源存钱。实测这条翻译是通的：seed 8191 建了 4 座灵田，
灵石稳定在 21。

**还没解决的是"抢资源"**：招修士、建藏经阁、研发都要灵石，
现在没有任何机制保证"研发那 60 灵石不被招兵花掉"。
要做得加一个"资源预留"（某一步锁定 N 灵石，别处不许动）——这是 T12 的全部内容。

### T13. 地形产出：AI 本来就会算，别把它盖掉（2026-11-20）

`rawBuildScore` 的经济分支里有一个**探针单位**：

```ts
const probe = { ...def, x: spot.x, y: spot.y };
const inc = resourceValue(s, owner, unitYield(s, probe));   // 这一格真能产多少
if (inc <= 0) return -999;                                  // 产出为 0 的地不盖
return inc * 4 - 造价 * 0.03;
```

所以"森林多灵石、平原多金币""城郭与物料的各地形产出不同"**本来就被算了**，
而且经济单位的**移动**也算了（`tacticalMoveScore` 里比对 `unitYield` 换格前后）。

**我差点把它盖掉**：第一版让修真目标 `claimsBuild` 灵田，走我自己的
`buildScore`（46 − 危险×30 − 造价），两块地同分——地形判断就没了。
现在灵田**不认领**，只在 `done` 里数"有没有两座"，怎么盖、盖哪交给通用那条线。

**结论：以后凡是"经济建筑"，一律不要认领它的建造**，除非你有比
`unitYield` 更好的判据。

### T14. 建筑被拆是常态，链需要"重建耐心"（2026-11-20）

### T5. 组合的边际递增 vs 采购的边际递减

采购里有一条"同兵种越多越不值"（`sameType × -3`，封顶 -20），
而组合目标要的是**边际递增**（第 3 个骑士比第 1 个值钱）。同一兵种上会打架。
合并时必须指定谁说了算——建议"组合目标认领的兵种，递减让位"。
