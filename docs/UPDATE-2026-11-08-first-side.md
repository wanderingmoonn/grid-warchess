# 两人局可选择先手（2026-11-08）

## 之前是什么样

`createMatch` 里写死 `current: 'A'`。人类永远是红方、永远先动，热座和人机都改不了。
要做平衡实验只能改代码或跑批脚本。

## 现在

新对局面板「对手」下面多一行 **先手**：

- **两人局**（热座 / 人机 / 双 AI 观战）：红方先手 / 蓝方先手 / 随机；
- **三四人局**：按席位顺序 / 随机。不提供"手选某一方"——多人局的席位顺序还牵着
  出生点与城的排布（`generateMultiLayout` 按席位分城位），让下拉框决定谁先动
  等于让一张图的公平性看运气。随机是在**参赛席位上抽**（三家就在 A/B/C 里抽）。

| 选项 | 含义 |
|---|---|
| 红方先手（默认） | A 先动，和以前完全一样 |
| 蓝方先手 | B 先动。人机局里 AI 在蓝方，所以这是"AI 先动一步" |
| 随机 | 用这一局的种子抽，**抽完落成具体席位存进 config**，复盘不会变。两人局抽 A/B，三四人局在所有席位上抽 |

多人局的回合本来就是环形的（`nextSeat` 按席位列环转），所以"从谁开始"只影响起点：
C 先手就是 C→D→A→B，循环本身不变。

## 一件事决定三处（改的时候别只改一处）

「先手」不只是"谁先点结束回合"，它同时决定：

1. **谁先行动** —— `state.current = firstSeat`；
2. **选卡 BP 谁先禁/先选** —— `createDraft` 把席位从先手方开始轮转，
   蛇形不变：红方先手是 `A,B,B,A…`，蓝方先手是 `B,A,A,B…`。
   不跟着转的话会出现"我选后手却还先选卡"，等于把先后手的定义拆成两套；
3. **先后手补偿发给谁** —— 原来是 `seats.slice(1)`（等于写死发给 B），
   现在是"除先手之外的每一个人"。先手是 B 时，补偿发给 A。
   「先手第一回合不结算收入」那条开关（`noFirstIncome`）同样改成挂在先手方身上。

`grantOpeningIncome(state, first)` 现在收一个玩家参数：开局那笔收入发给先手，
日志也记在先手名下——以前它硬编码 `'A'`。

## 两个字段，别合成一个

| 字段 | 谁读 | 含义 |
|---|---|---|
| `firstSide` | 只有开局面板 | 玩家**选的档位**（`'A'` / `'B'` / `'random'`），是面板记忆 |
| `firstSeat` | 规则、读档、复盘 | 这一局**实际**谁先动（抽完落定的席位） |

合成一个字段会分不开"四家局随机抽到 B"和"两人局手选 B"——面板会把抽出来的结果
误当成玩家上次的选择。`firstSeat` 每次都写，哪怕就是 A：一开始想省掉这个键，
结果读的一方分不清"没写"和"写了 A"。

## 老存档

两个字段都是可选的：老存档没有它们，按"红方先手"处理，与当初的局面一致。

## 老存档

`firstSide` 是可选字段，缺省按 `'A'` 处理——所有老存档、老房间、分享链接读回来
都是"红方先手"，与它们当初的局面一致。
