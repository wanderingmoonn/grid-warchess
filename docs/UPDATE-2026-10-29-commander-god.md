# 2026-10-29 · 参谋部与沙盒技能

四项改动，横跨指挥官模式与上帝模式：按城市指定产兵、兵种检索与分类、英雄产出链路、
沙盒里放技能。

---

## 一、指挥官模式：按城市指定兵种生产

### 以前

生产序列一格只回答一个问题——**造什么**。"从哪座城造"由 AI 自己挑。

这在只有两座城、都在同一片平原上的时候没差；一旦摊子铺开就开始别扭：

- 想把兵出在前线的营，不想让主城少一个守军——表达不出来；
- 刚打下来的城兵出在门口就是给对面送——只能靠 AI 的"弃城期"逻辑间接影响；
- 两座城时代不同，同一个兵只有一座造得出来——点名了兵种，AI 可能去一座造不出来的城
  试一下，然后空过这一回合。

### 现在

每一格多一个下拉：**由哪个产兵点产出**。选项是自己的城市（带时代）和军营（带坐标），
外加「哪座都行」。数据上是一串与 `orders` 逐格对齐的 `orderSites`：

```ts
orders?:      Partial<Record<PlayerId, string[]>>;  // 造什么（原样）
orderSites?:  Partial<Record<PlayerId, string[]>>;  // 从哪造，'' = 哪座都行
```

为什么是并行两串而不是合成一个对象数组：`orders` 已经写进存档，改成
`{ type, site }[]` 等于所有老存档都读不出来（还得升一次版本号）。并行的代价是
"两串长度必须一致"，这条只由两处保证——`doSetOrders` 写入时对齐，回合末
`doEndTurn` 前移时**两串一起 shift**。只挪队列会让"造在哪座城"错位到下一格上，
那比不做还糟，所以专门有一条测试盯着。

执行侧：`AiBudget` 多了 `orderSite`，`aiNextAction` 在遍历城市 / 军营 / 升级目标时
直接跳过不匹配的那几个。指定了谁就只认谁：

| 情况 | 行为 |
|---|---|
| 那座城时代不够 | 这一格空转，不换一座城 |
| 那座城的出兵格站满了 | 这一格空转，不换一座城 |
| 指定的军营被拆了 | 这一格空转 |
| 队首是「升级时代」、指定了某座城 | 只升那一座（指定军营则空转） |

这和"钱不够就空过"是同一条哲学：**排了造不出来是后果，不是 bug**。界面负责提前说清楚——
金币预估那一格会直接写「产不了（时代不够）」「已在场」，并把数字标红。

## 二、指挥官模式：兵种检索与分类

五个下拉、每个下拉六七十项，翻起来是没法用的。参谋部多了一行：

- **搜索框**：认名字、单字图标、编号，也认分类名（敲「远程」「英雄」都筛得出来）；
- **分类 chip**：近战 / 远程 / 机动 / 飞行 / 水上 / 经济工程 / 英雄。只列这一局真有的
  那几类——没有船的地图不该留一颗永远点不出东西的按钮；
- 右边的计数写着「12 / 47 个兵种（已筛选）」，提醒你现在看的是不是全量。

分类是**按数值推出来的**（`classesOf`），不是给每个兵种手写标签：兵种表两百多条，
手写一列标签等于每加一个兵就要回来补一次，而"射程几格、跑多快、在哪一层"本来就是它的定义。
一个兵可以同时属于几类（快速远程车既是「远程」也是「机动」）。

搜索与筛选**只影响"看得见什么"**，不动已经排好的东西：

- 某一格已经选中的兵种，即使被筛掉也会留在**这一格**的下拉里（只给这一格补，
  否则"筛过了"就名不副实）；
- 不补的话浏览器会因为找不到当前值而跳回第一项，等于替玩家把计划改了。

输入法组字期间不重绘（和侧栏那个产兵搜索框同一套讲究），否则拼音会被重投一遍，
变成「chuanchuan船」。

## 三、英雄产出的缺陷

三处问题，一个共同点：**"这个英雄要多少钱、能不能再招一个"没有单一真相**。

### 3.1 价格口径不一致（主症状）

面板上写着「矮人王 · 360 金」，金币预估也照 360 算。但规则层第一次招英雄还要收
150 金解锁费，于是：

1. 玩家看着「≈ 540 金可用」把英雄排进第 4 格；
2. 轮到那一格时，实际要 510 金，不够；
3. AI 造不出来，这一格**静默空转**，序列照走，没有任何提示。

修法不是"在界面里再加 150"，而是把口径收成一份：

```ts
recruitPriceOf(s, player, def) // { price, unlockFee, total, gold }
```

规则层（`doRecruit` 扣钱）、界面（`slotCost` / `estimateGold`）、AI（`recruitCandidate`
判断买不买得起、`planOrders` 排产投影扣钱）全部改用它。AI 那边还补了一处：
`planOrders` 的投影以前只扣兵价、不记 `unlocked`，于是排完英雄之后的余额偏高，
后面几格排进去的兵到执行时其实买不起。

### 3.2 已经在场的英雄还能再排

规则层会拒（"英雄场上只能有一个"），但下拉里照样能选。结果同样是一格静默空转。
现在下拉里这类选项标「已在场」并置灰；旧存档里已经排进去的那一格留活口（否则会显示成
"不指定"，看着像自己跳掉了）。

### 3.3 蛋没孵出来就能再造一只

`doRecruit` 的唯一性检查只看 `s.units`。不死鸟倒下会留下一枚**待孵的蛋**，
那段时间场上确实没有不死鸟——于是能再买一只，最后站起来两只。

现在检查和 AI 采购共用 `heroBlocked()`：场上有、或者蛋在等，都算"已经有一个"。

## 四、上帝模式：技能放不出来

这个模式的侧栏整块让给了兵种货架，正常对局那张属性卡（含技能菜单）根本不渲染。
于是"选中英雄 → 按技能"这条路是断的：棋盘上连一个按钮都没有，而货架上
「投斧」两个字明明印在那儿。

操控档里选中一支部队，侧栏顶上现在多一块「手上这支兵」：

- 谁、几血、还能走/打（和正常对局同一套判断，含多段攻击）；
- **主动技能按钮**，复用 `data-act="hero-skill"` 那条派发路径；
- 冷却中 / 不是这一方 / 没轮到你，按钮一律灰掉并写清原因——沙盒里最容易让人
  以为"坏了"的，就是一个亮着的按钮点下去什么都不发生。

这块卡进了货架的重绘签名（id + 血量 + 行动力 + 技能冷却）：只认 id 的话，
开完技能按钮还亮着、挨了一刀血量还是旧的。

新增用例都是先确认"改之前是红的"：

  （含一条原有的"解锁费只收第一次"）；
- 把 `main.ts` + `god-panel.ts` 换回旧版 → 五条 DOM 用例 FAIL（产兵点下拉、搜索、
  分类、英雄标价与置灰、沙盒技能按钮）。

## 没做的事

- **产兵点没有"记住上次"**：每格都从「哪座都行」开始，切换兵种不会自动带上同一个城。
  想做的是"这一批都用主城"，但那是另一种交互（批量套用），留到有人真的嫌烦时再加。
- **分类没有"复合筛选"**：点「远程」之后再点「飞行」是切换而不是叠加。
  叠加需要多选状态，而 5 格宽的一条横带未必放得下。
- **搜索不认拼音**：只认中文名、单字图标和编号。加拼音要么带一张词表，要么引一个库，
  两者都比这个功能本身重。
- **AI 自己排的序列不指定产兵点**：`planOrders` 还是"哪座合适就用哪座"。
  给它加上"挑城"是另一个优化问题（要考虑前线距离、被偷袭风险），不该混在这批里。
