# RL v2：观测与动作空间重做，以及一次能测出来的进步

**2026-11-05** · 承 `docs/RL-PLAN-v2.md`（规格）、`docs/RL-PLAN.md`（v1 全部记录）

---

## 一句话

把观测从"只看金币、标度写死、没有意图"改成"资源按比值、带环境描述、带意图"，
并把动作空间从 6 类补到 12 类之后：**老师的决策覆盖率从 93.0% 提到 100%**；
行为克隆的起点在 0.75 档从 48.4% 提到 60.0%；
PPO 自博弈 34 轮之后，**对战完全不削弱的手写 AI 拿到 54.4%**
（160 局 83 胜 69 负 8 平，95% 区间 [46.6%, 61.9]）——
温度计在最后一档归零，也就是说"为了五五开，手写 AI 不需要再被削弱了"。
v1 十八轮停在 21.9%/14.7%。

代价：每步推理 0.55 → 0.70 ms，参数量 2.28 万 → 3.28 万。

## 一、改了什么

| 项 | v1 | v2 |
|---|---|---|
| 观测 | 148 = 全局 40 + 棋盘 108 | **221 = 全局 50 + 环境 27 + 棋盘 144** |
| 动作特征 | 56（类型 one-hot 7 格） | **62（类型 one-hot 13 格）** |
| 动作类型 | 6 类（MOVE/ATTACK/SIEGE/RECRUIT/UPGRADE/END_TURN） | **12 类**，补 BUILD / LOAD / UNLOAD / HERO_SKILL / DISBAND / PLACE_EGG |
| 权重版本 | 1 | **2**（旧权重直接拒读） |
| 参数量 | 22,786 | 32,798 |

观测里三处结构性修改：

1. **资源从"只有金币"变成 5+5 槽**。引擎的资源是动态表（`player.res[id]`），
   扩展可以随时加粮食/建材/灵石，而 v1 的观测里只有金币——"粮材怎么分配"策略完全看不见。
   现在按 `RESOURCES` 注册表的顺序填槽，语义是**"这种资源够花几个回合"**
   （`存量 / 每回合进账`），不是绝对值：整体调价时这个商不变。
2. **标度全换成活的参照物**。`gold / 150`、`value / 1200` 这类写死的常数一律改掉：
   兵价除以**收入**（"几回合的收入能买一个"）、距离除以**棋盘边长**、血量除以**自身满血**。
   这是 §2 那条"数值一变就整体失准"的正面修法。
3. **环境描述接进来了**。`env-desc.ts` 早就写好了（27 维：资源表 / 兵种池形状 /
   机制开关 / 棋盘开局），但一直没进 `encodeState`——这一版才真正接上。
   它描述的是**结构属性**而不是扩展 one-hot：新扩展进来向量会自己变，
   而不是变成一片零。

外加第 4 件事：**意图**（4 维 one-hot，rush / harass / boom / auto）进了全局块末尾。

## 二、四件只有动手才会知道的事

### 1. 老师的跳过率 7.0% → 0.0%，每一段都是我自己造的

补完六类动作之后探路：跳过率从 7.0% 掉到 4.0%，但缺口表显示 **98/99 都是 MOVE**——
不是缺类型，是**同一个类型被我自己过滤掉了**。

枚举里原本有一段 `blockedByAlly`：扫一遍"格子上有没有友军"。删掉它之后归零。原因：

`reachableTiles` 返回的**已经是**"能停下的格子"，它内部按 `blockedAnchor` 过滤过，
而那套判据细得多——不同飞行层不占位、自家的塔/军营/**桥**可以站、
墙连自己人也停不上去、敌方建筑要先打掉。自己再写一遍"有友军就挡"，
后果是**过度过滤**：老师把工兵挪到自家桥上，引擎允许，枚举把它踢了。

> 判据只能有一处。这一条已经在 `legal.ts` 里当注释写死了。

另外两处同类问题：UNLOAD 的"贴着船"必须按 `distance(ferry, 格) === 1` 判
（2×2 的大舰锚点在左上角，按锚点 ±1 扫出来的 3×3 有一半是斜角、够不着）；
BUILD 有三道关，其中"时代供货"要问**落点**（`supplyEraAt(s, seat, {x,y})`），不是工兵脚下那格。

还有第三处，是最后那 0.27% 才暴露出来的：**BUILD 的扫描半径读错了对象**。
桥要多往外两格（`bridgeChainOk` 允许 +2，三格宽的河心岸上够不到），
而代码读的是**工兵**的 `def.bridges`——那是"这个单位是不是桥"，永远是 false。
AI 那边的 `buildSpots(s, unit, buildDef)` 传的是建筑 def，我这边抄成了工兵。

修完之后：**7654 步 0 跳过**（100% 覆盖）。三处坑的形状是同一个——
**判据复制了一份，然后和源头的语义漂开**。都不是"逻辑写错"，是"多写了一遍"。

`verify-legal.ts` 全量校验 95,842 个枚举动作 + 12×12 抽样 33,162 个，**0 个被 `applyAction` 拒绝**。

### 2. 高级档 AI 根本没有战术层，所以"意图标签来自老师"这个前提不成立

`ai.ts` 里 `moodFor()` 写得很清楚：三套 doctrine 只在**中级档（tactic）**生效，
高级档会把三种权重压成均分、drive 清零、也从不弃城。

而 `imitate.ts` 用的老师是高级档（和 v1 同一个，为了可比性）。所以那里录出来的
`lead` 只是"证据指向哪一边"的**状态派生特征**，不是"老师按它下了这一步"。

处理：**按局交替**——偶数局贴派生标签，奇数局贴 `auto`。
两头都不能走极端：全贴 lead 会让 `auto` 一格在训练集里一次都不亮，
而推理默认就是 `auto`（等于往没训过的输入上喂 1）；全贴 auto 则四格全是死的。

（第一版录到一半才发现，600 局作废重录。代价 35 分钟，但不是白花的。）

### 3. 那 4 个意图格是活输入，不是装饰

见下面第四节。

### 4. 内存：候选特征 4.7GB，这台机器装不下

`bc.py` 原来把候选整份 `copy()` 出来。v2 的候选是 65 槽 × 62 维、
289,979 行就是 **4.68GB**，而这台机器总共 15.7GB、录完数据只剩 5.5GB 可用。
改成留 memmap 视图、按批取（4096 行 ≈ 66MB），8~20 轮训练下来只多花二十来秒。

### 3.4 意图是不是活的

同一批种子、**同一条随机流**（`mulberry32(seed ^ 0x5f5f)`，四个意图共用），
所以任何分歧都只可能来自策略自己的概率分布。测两遍：十二轮权重（8 个种子）、
二十轮权重（8 个种子）：

| 对照 | 前缀一致（12 轮权重） | 前缀一致（20 轮权重） | 逐位相同（20 轮） |
|---|---:|---:|---:|
| auto vs rush | 3.2 / 20 | 7.8 / 20 | 55.6% |
| auto vs harass | 1.0 / 20 | 3.1 / 20 | 33.1% |
| auto vs boom | 1.5 / 20 | 7.3 / 20 | 50.6% |
| rush vs harass | 1.2 / 20 | 3.3 / 20 | 38.1% |
| rush vs boom | 4.0 / 20 | 4.5 / 20 | 36.9% |
| harass vs boom | 0.8 / 20 | 2.3 / 20 | 26.3% |

**换意图，两手到八手之间就开始分叉**，20 手之后只剩 26~56% 的位置还是同一个动作。
那 4 格不是装饰。

括号里的第二个现象也值得记：训到二十轮之后，**一致前缀变长了**（0.8~4.0 → 2.3~7.8）。
策略变自信了，不同意图在前几手会走同一套开局，之后才分岔——
这正是一个"成熟棋手"该有的样子（先按定式开局，再按打法分化），
而不是"一句话就整个换个人"。

但要说清楚它是什么：**同一个局面下换口令，它会换打法**；这不等于"它懂 rush 是什么意思"。
这份标签在高级档下是"这个局面像速攻"的派生描述，不是老师真的按 rush 下过棋。
要教出"按口令下棋"，得用 `--ai-level tactic` 另录一批——那一档 doctrine 才真的驱动行为。

### 3.5 把"它凭什么赢"端出来：一局可以对局复盘的对局

胜率说不清"它靠什么赢"。所以 `scripts/rl/export-win.ts` 会把一局**它赢下来的对局**
导成报告文件（和"结束后上传"那份同一个格式），直接拖进游戏就能逐帧回看。

口径：对手不削弱、座位交替（和 eval 的配对一致，否则导出来的永远是"先手怎么赢"）、
攒三局胜局之后挑**步数最少**的那局——一百多回合的拉锯虽然也是赢，
但要拖两百下进度条才看见一次交手，复盘价值低。

导出的那一局：

| 项 | 值 |
|---|---|
| 种子 | 1000（就是定测那批的第一颗） |
| 座位 / 结果 | A 座，31 回合取胜 |
| 步数 | 459 |
| 文件 | `docs/replays/v2-win-2026-11-05-1000-a.json`（39 KB） |
| 线上 | `/replays/v2-win-2026-11-05-1000-a.json` |

回放核对：459/459 步全部被引擎接受、终局胜方一致、原样还原（`exact = true`）、**零警告**。

## 四、怎么复核

```bash
# 0) 把那一局胜局拖进游戏自己看（首页「复盘」或直接拖文件），
#    也可以先在这里过一遍：
node --experimental-strip-types scripts/rl/export-win.ts \
     --weights scripts/rl/weights/v2-specialist.json --wins 3

# 1) 合法性：枚举出来的每个动作，applyAction 都必须接受
node --experimental-strip-types scripts/rl/verify-legal.ts --size 8 --seeds 2 --cap 60 --full

# 2) 观测/动作维度自洽 + 意图只动 4 格 + 环境块真的接上了
npm run rl:test

# 3) TS 与 Python 的前向逐位一致（换维度之后必须重跑）
npm run rl:parity

# 4) 定测（160 局、同一批种子）
node --experimental-strip-types scripts/rl/eval.ts --mode policy \
     --weights scripts/rl/weights/v2-specialist.json --games 160 --ai-handicap 0

# 5) 意图探针（换口令会不会换打法）
node --experimental-strip-types scripts/rl/intent-probe.ts \
     --weights scripts/rl/weights/v2-specialist.json --seeds 8
```

最终权重已冻存为 `scripts/rl/weights/v2-specialist.json`（和 v1 的 `v1-specialist.json` 并列）。
v1 的权重是 `WEIGHTS_VERSION = 1`，现在**读不了**——这是有意的：形状对不上却硬读，
只会得到一串静默错位的数。要复现 v1 的数字得用 v1 那个提交。

前向一致性实测：logp 最大偏差 **2.6e-7**、value **8.4e-9**（要求分别 <1e-5 / <1e-6）。
