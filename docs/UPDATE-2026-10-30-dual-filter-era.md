# 2026-10-30 · 双筛选铺到所有模式；城市不再"造不了老装备"

两件事：

1. **「扩展包 + 时代」两维筛选**从指挥官模式（当年挂在参谋部横带上）抽成共用组件，
   铺到所有会列兵种的地方——城市产兵面板、军营产兵面板、上帝模式兵种货架；
2. **取消"低于城市两个时代就不能生产"的下限**，城市能造当前时代及更早的**全部**兵种，
   所有模式一个口径。

---

## 一、双筛选：从"不见了"到"到处都是"

### 以前

参谋部那版筛选是 **DLC + 时代**：两排 chip，可单独可叠用，空值＝不筛，再点一次回全部，
只有一包或只有一代时整行不出现（`docs/UPDATE-2026-10-29-damage-chat-heroes.md` 第六节）。

后来指挥官模式的产兵改成「点城 → 右侧点兵种 → 顶端队列」，和常规模式共用一套面板
（`docs/UPDATE-2026-10-30-commander-queue.md`）。重构把参谋部那批下拉整个删掉了，
**`eraChipRow` 与 `cmdPass` 跟着一起没了**——于是：

| 界面 | 改动前 | 问题 |
|---|---|---|
| 城市 / 军营产兵面板 | DLC 一排 chip + 搜索框 | 少了时代这一维，一屏四十多个兵种只能靠搜 |
| 上帝模式货架 | 只有 DLC 一排 | 按时代分组但筛不了，找"这一代有什么"仍要滚动 |
| 参谋部横带 | 什么都不剩 | 它现在只负责显示队列，本来就该如此 |

### 现在

筛选的两个维度收进 `src/ui/packs.ts`，和包筛选同一套规矩、同一个文件：

```ts
export const ERA_ALL = 0;                              // 0 = 全部时代
export function eraOk(def, era): boolean               // 单个兵种过不过这一关
export function eraChipRow(defs, current, act)         // 那一排 chip
```

三处接入，行为完全一致：

- **城市产兵面板**（`ui/panel.ts` 的 `cityPanel`）：`buildable` 不变（那是"能买什么"），
  再叠一层 `eraOk` 得到 `shown`（那是"看得到什么"）；
- **军营产兵面板**（同一文件的 `campPanel`）：同上，时代仍取"最近一座己方城市"；
- **上帝模式货架**（`ui/god-panel.ts`）：`packOk && eraOk` 一起过，穿过之后再按时代分组。

前两处覆盖了**单机 / 热座 / 联机 / 指挥官 / 选卡**——它们本来就是同一个面板，所以"移植"
实际是"补回一处、接通三处"，不存在几套各写一遍的分支。

规矩逐条对齐旧版：

| 规矩 | 实现 |
|---|---|
| 空值＝不筛 | `ERA_ALL = 0`，`eraOk` 直接放行 |
| 两维是"与" | `shown = buildable.filter(matchRecruit && packOk && eraOk)` |
| 再点一次＝回到全部 | 两个处理器同一句：`x = x === v ? 0 : v` |
| 只有一个包 / 一个时代时不出现 | `eraChipRow` 里 `if (levels.length < 2) return ''` |
| 没命中要说清是哪几个条件 | `emptyRecruitHint(q, pack, era, …)` 把生效的每一维写进括号 |
| 计数对得上 | 两行的"全部 N"用同一份分母；货架那两行用**封顶之后**的清单 |

最后两条是这次新补的边界：以前只写"这个包里没有"，现在两个维度都写
（「没有匹配「龙」的兵种（只看「奇想·荒兽」「古典时代」）」）；货架的 chip 计数以前拿全表算，
会把这一局摆不出来的六代兵也算进"全部"，现在先按 `eraCeilingOf` 封顶，数字和点得到的按钮一致。

**选卡池没有加筛选**：那个池子固定 20 张卡，而且"看不见的卡"在 BP 里最危险——
筛掉了会以为这张没进池子。它需要的是排序（已按时代为主、扩展为辅），不是过滤。

## 二、时代下限：升级不该让选项变少

### 以前

```ts
// core/draft.ts
if (def.era > era) return false;
if (state.draft && !state.draft.skipped) return true;   // 选卡模式特例
return def.era >= era - 1;                              // 只带当前 + 上一个时代
```

于是第五代的城市造不出民兵。这条规矩的**动机是对的**——不想让产兵面板里堆十个早该
淘汰的兵——但**执行的位置错了**：那是界面装不下，不是规则不允许。代价是"城市升级让
能造的东西变少"，玩家在三级城里想补两个便宜长枪兵看家时，得到的是一句"已经过时了"。

更别扭的是选卡模式为了绕开它，单独放开过一次下限——同一个局面在"开没开选卡"下给两个答案。

### 现在

```ts
export function eraWindowOk(_state, def, era): boolean {
  return def.era <= era;   // 只剩上界：未来的兵造不了
}
```

- 面板装不下的问题交给筛选（上面那一节就是解药）；
- 选卡模式那段特例一起删掉——口径只剩一个；
- `rules.doRecruit` 里原本三段重复的时代判断（"没到那个时代" / "城市不够新" / "过时了"）
  收成一条，报错文案只剩「X 需要「Y」时代」；
- AI 的采购闸门（`ai.ts` 的 `recruitChoices`）用的是同一个 `eraWindowOk`，跟着一起放开；
  评分里"越新越好"的权重没动，所以它不会突然开始屯民兵。

界面侧：`locked`（升级后可解锁）仍然按 `d.era > city.era` 算，提示不受影响；
低时代兵种现在会正常出现在列表里，也能点。想只看某一代就点时代那一排 chip。

## 三、顺手修掉两处失效断言

上一批把地形高差改成"只有高差这一条"之后（`docs/UPDATE-2026-10-30` 那批地形改动），
`scripts/test-ai-optimization.ts` 里两条断言还按旧的"制高点 +1 再叠高差 +1 = +2"在写，
于是 `npm run test:ai-optimization` 一直是红的（在改动前就是红的，不是这批引入的）：

- 「高地上的射击能打到基础射程之外」：弓箭手射程 3，台地打谷地现在只 +1（不是 +2），
  所以距离要取 4 而不是 5；
- 「攻城射程的选择与执行一致」：原来靠"谷地 −1"把距离 3 的目标推出去，但城墙高度是 0、
  谷地是 −1，高差只有 1，**够不到扣射程的波段（2）**。改成用距离 4/5 验高地的 +1，
  顺带把"选择"和"执行"两处都断言一遍。

红着的用例比没有用例更糟：它会让下一个人以为整套 AI 测试不可信。
