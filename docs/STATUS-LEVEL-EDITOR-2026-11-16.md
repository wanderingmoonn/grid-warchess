## 一句话现状

**E0~E6 全部落地。** 现在不写一行代码可以做出一张完整的关卡：
选关页 →「我的关卡」→ 新建 → 画地图 → 摆兵 → 席位 → 事件（含时间轴）→ 胜负 →
兵种 → 扩展与 AI → 试玩 / 自打 3 局 → 保存 →「管理」里改名、复制、导出、上传。

**所有 `LevelDef` 字段都有面板。** JSON 退成"高级改法"，不再是唯一入口。

**但有一件事没验过**：拿编辑器完整复刻一遍孤城（5 组事件、12 次刷兵）还没做过。
机制都测过了，缺的是"一个真人从头做一遍"的手感验证。

## 文件在哪

| 文件 | 干什么 | 注意 |
|---|---|---|
| `core/userLevels.ts` | 本机关卡库（localStorage）+ 草稿箱 | 保存先过 `validateLevel`；**拒占内置 id** |
| `core/level-io.ts` | .json 导出/导入 | 三种外壳都收；一条坏的不拖累其他条 |
| `core/level-lint.ts` | 第二层校验（引擎查不了的） | 能确定才报错，其余只警告 |
| `net/levels.ts` | 云端关卡库 | 表没开通时要说"没开通"，不是静默失败 |
| `ui/level-editor.ts` | 编辑器外壳（JSON + 问题列表 + 各面板入口） | 唯一的"保存"在这里 |
| `ui/level-grid.ts` | 网格底座（画布/摆兵/选区共用） | 正方形格子靠 `aspect-ratio` |
| `ui/level-canvas.ts` | 画地图 | 城按 2×2 画（城郭扩展实际是 3×3，只影响预览） |
| `ui/level-army.ts` | 摆兵 | 货架**全时代**，不按开局时代过滤 |
| `ui/level-seats.ts` | 几家 / 托管 / 中途登场 / 每家城的时代 | 加席位会自动塞一座城（否则死锁） |
| `ui/level-events.ts` | 事件卡片 + 时间轴 | 区域拖框、刷兵点地图 |
| `ui/level-goals.ts` | 胜负条件（顺序可调） | 先成立的赢 |
| `ui/level-units.ts` | 关卡独有兵种 | 复制出来默认 `summonedOnly` |
| `ui/level-rules.ts` | 扩展四档 + AI 三旋钮 | 三个都是 1 时不写 `ai` |
| `ui/level-manager.ts` | 关卡管理 + 导入导出 + 云端 | 改名不动 id |
| `ui/toast.ts` | 轻提示 | 从 main.ts 挪出来的，避免循环依赖 |

## 五条不变量（改的时候别破）

1. **面板只产出数据，保存只有一处。** 所有面板走 `onApply(level)`，由编辑器写回文本；
   编辑器里 `readyToPlay()` / `commit()` 是唯一的校验+保存入口。
2. **一格正方形。** 容器 `aspect-ratio: w/h` + 格子 `1fr`。任何"用一个边长表示棋盘"
   的写法都会把 12×10 拉成长方格（对局棋盘踩过一次）。
3. **玩家数据不进 `LEVELS`。** 用户关卡走 `registerLevelSource` 挂进来；
   往内置数组里 push 会让 `probe:level` 的 26 段不可重复。
4. **改名不改 id。** 存档快照、事件引用、云端回读都靠 id 对账。
5. **能用 ≠ 找得到。** 控件放在滚动区外、或者在一屏之外，等于没做
   （地图尺寸控件就因为这个被投诉过一次）。

## 已知的坑

1. **`validateLevel` 会静默忽略未知字段** → 界面状态（选中的格子、`spawn` 的
   "下一个点放什么兵"）**绝不能写进关卡对象**；`level-events.ts` 里那个 `lastType`
   在应用前会被剥掉，删掉那行它就会跟着 JSON 进存档。
2. **`turn` 是行动序号不是轮**。界面上每个数字旁边都写着"约第几轮"，别删。
3. **草稿只对"编辑已有的关"自动恢复。** 「新建」自动恢复草稿 = 第二次点新建拿到半成品。
   新建时给的是「接着改那份 / 丢掉」的按钮。
4. **加席位要自动塞城。** 否则数据过不了校验 → 打不开画布 → 而画布才是摆城的地方（死锁）。
5. **云端的 `id` 前缀是 `cloud:`，本机是 `user:`**。两者不能混成一个命名空间；
   云端关卡不会进 `allLevels()`，只能通过「下载到我的关卡」变成自己的。
6. **测试里多个弹窗会叠加。** 断言要么限定最上层（`[...querySelectorAll('.modal-mask')].pop()`），
   要么盯"点的那一个"（`layer.isConnected`）；用全局计数会误报。

## 云端要动的手

`sql/warchess_levels.sql`（建表 + 权限）和 `sql/warchess_levels_review.sql`（审核三步）
需要**手动在云数据库执行一次**。不执行不影响任何本机功能，上传会提示"关卡库还没开通"。

审核时别只看名字和尺寸：关卡带**事件**，要顺带看一眼能不能把地图切成两块、
刷兵是不是直接刷在出生点旁边、`expansions.require` 有没有点名一个冷门包。
