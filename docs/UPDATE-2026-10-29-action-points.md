# 2026-10-29 · 行动点：把五种行动算进一个池子

新扩展「行动点」（`action-points`）。目标是把**移动、攻击、驻扎、上下船、释放技能**统一成
"行动"这一件事，每次行动都从一个单位自己的**行动点（E）**里扣。

关键约束：**整条规则只写在 `src/core/action-points.ts` 一个文件里，`rules.ts` 一行没动**。
`expansions.ts` 只多了一行注册，`types.ts` 一个字段都没加。这既是要求，也是这套扩展系统
（`ExpansionHooks` + `Unit.custom`）目前能撑住的边界——下面第三节会写清哪里撑不住。

---

## 一、价目表

| 行动 | 引擎里对应的事 | E | 判据（引擎已经记下的事实） |
|---|---|---|---|
| 移动 | `MOVE` | 20（骑兵/车 **15**） | 站位和本回合"开账"时不一样 |
| 上下船 | `LOAD` / `UNLOAD` | 20（同上） | 同上：下船那一刻单位换了个位置 |
| 攻击 | `ATTACK` / `SIEGE` | 40（近战 **30**） | `attacksLeft` 比"本回合允许的次数"少了几次 |
| 驻扎 | —（这一回合什么都没干） | 20（与机动同价） | 以上都没有 |
| 技能 | `HERO_SKILL` | 60 | `skillTurn === 本回合` |

池子上限 **100 E**。这个数不是随手取的：移动 20 + 出手 40 + 技能 60 = 120 > 100，
**这三件事同一回合做不全**，规则才有牙齿。只移动不攻击、或者只攻击不放技能，都绰绰有余。

## 二、数据结构

### 2.1 为什么不是 `Unit.E = 100`

`types.ts` 属于核心引擎，加字段就是改内核。就算能加，**也没有地方去减它**：

- 引擎没有任何"某次行动发生的那一刻"的扩展钩子；
- `modify*` 系列（`modifyMove` / `modifyAttacks` / `modifyArmor`…）按契约必须是**纯函数**——
  界面预览、伤害预估、AI 试算都会反复调用它们，在里面扣钱等于"鼠标划过就扣点"；
- 能改状态的只有 `onMatchStart` / `onTurnStart` / `onTurnEnd` 三个时点，全在回合边界上。

所以 E 是**从引擎已经记下的事实里投影出来的**，而不是"每次行动扣一笔"记出来的。

### 2.2 存的是什么

每个单位只有一个"开账记录"，存在 `Unit.custom.ap` 里：

```ts
interface ApMark {
  turn: number;   // 这份账属于哪个回合（s.turn）。对不上＝还没开账
  x: number;      // 开账那一刻站在哪 —— 用来判断"这一回合走没走过"
  y: number;
  debt?: number;  // 本回合一开始就欠着的 E（上回合透支）
  over?: number;  // 本回合结算出的透支额，下回合开账时变成 debt
}
```

`custom` 是引擎明说的扩展沙盒（"核心永远不会读取或修改这里的任何字段，只是让扩展把
自定义属性安全地存进存档里"，`types.ts` 里就有这句话），所以这份记录会跟着
**存档 / 读档 / 联机快照 / AI 状态克隆**一起走，不需要另开一张表。

### 2.3 算出来的账本

```ts
interface ApLedger {
  active: boolean;    // 建筑不参与（见 5.5）
  settled: boolean;   // 这一回合开账了没有（刚招出来的单位还没开）
  max: number;        // 上限 100
  start: number;      // 本回合起点 = 上限 − 上回合透支
  debt: number;       // 上回合透支、这回合先扣掉的部分
  spent: number;      // 本回合已经花掉
  left: number;       // 还剩
  over: number;       // 超支（>0 就是透支了）
  items: ApSpend[];   // 明细：{ 行动, 名字, E }，界面直接拿来念
  attacksAllowed: number;  // 这一回合还能出手几次（modifyAttacks 用它）
  cost: Record<ApAction, number>;  // 这个单位各项单价（含减免）
  classes: ApClass[]; // 命中的类别，用来解释"为什么便宜"
}
```

`apLedger(state, unit)` 是**纯函数**，界面预览、`modifyMove`、`modifyArmor`
反复问它都安全。这也是它能同时被三个钩子复用、并且和界面数值永远一致的原因。

## 三、消耗计算逻辑

一次完整流程只有三步：**开账 → 投影 → 结算**。

### 3.1 开账（回合开始）

`onTurnStart`（外加 `onMatchStart`，见下）给轮到的那一方的每个单位重写一次 `custom.ap`：

```
turn = s.turn
x, y = 当前站位
debt = 上一本账的 over（只滚一回合）
over = 0
```

`onMatchStart` 里也要开一次，因为**先手的第一回合根本不走 `onTurnStart`**
（那是"结束回合"时才触发的）。漏了这一处，先手第一回合永远读不到"走没走过"。

### 3.2 投影（每次读账时现算）

```
moved  = (u.x, u.y) ≠ (ap.x, ap.y)          // ① 机动
skilled = u.skillTurn === 本回合             // ② 技能
budget = start − 机动 − 技能
allowed = floor(budget / 攻击单价)           // ③ 这一回合能打几下
total = min(引擎给的 burst, allowed)
used  = attacksLeft 有值 ? max(1, total − attacksLeft) : 0
spent = 机动 + 技能 + used × 攻击
if (spent === 0) spent += 驻扎              // ④ 什么都没干
over  = max(0, spent − start)
left  = max(0, start − spent)
```

几个刻意的选择：

- **"哪一回合"要按人算**：`s.turn` 是全局回合数（每方结束就 +1）。轮到我就是 `s.turn`；
  不是我（对面回合、或我在看对方的单位）就是他上一回合 `s.turn − 1`。引擎只重置
  "轮到的这一方"的 `moved / acted / attacksLeft`，所以对面单位的上一回合在别人回合里
  仍然读得出来——驻扎的护甲加成正是靠这一点撑满整个对面回合。
- **判定用站位，不用 `u.moved`**：出手也会把 `moved` 置真（"攻击结束移动"），
  用它分不清"走过去打"和"原地打"，会把这笔机动费记到站着不动的单位头上。
- **攻击次数先取整再反推**：`attacksLeft` 只在第一次攻击时被填成
  `max(1, attacksPerTurn())`，所以"有值"＝"至少打过一次"。`max(1, …)` 那一项是专门
  兜住引擎的保底首击（见 5.1）：允许 0 次时 `attacksLeft` 仍会被填成 1，
  于是这里记 1 次、并把差额算进透支。
- **驻扎和机动同价**：一个单位这一回合要么走过去、要么就地待着，占的是同一份预算。
  如果驻扎比移动便宜，"先待着、再走一步"会看到 E 先掉 20 再涨回 5——账越算越多，
  玩家只会以为算错了。所以 `hold` 用的是 `move` 那一档的减免（骑兵 15、步兵 20）。

### 3.3 结算（回合结束）

`onTurnEnd` 排在 `resetUnitsFor` **之前**，所以那时 `moved / acted / attacksLeft` 都还在，
可以把刚结束那一回合的账完整算一遍，把 `over` 钉进 `custom.ap.over`，并写一条战报：

```
民兵 透支行动 5 E，下回合从行动点里先扣
```

下一回合开账时，`over` 变成 `debt`，起点从 95 开始。**只滚一回合，不滚雪球**——
否则一次超支会让这支部队永远慢半拍，而玩家没有任何办法洗掉它。

## 四、修正值在哪配置

全部集中在 `src/core/action-points.ts` 的开头，改数值不用碰规则引擎：

```ts
export const AP_MAX = 100;
export const AP_COST = { move: 20, attack: 40, hold: 20, skill: 60 };

export const AP_CLASS_MOD = {
  mounted: { move: -5 },    // 骑兵类：机动 −5E
  vehicle: { move: -5 },    // 车类：机动 −5E
  melee:   { attack: -10 }, // 近战类：出手 −10E
};

export const MOUNTED_IDS = ['scout', 'knight', 'hussar', 'med_horsearcher', ...];
export const VEHICLE_IDS = ['mortar', 'artillery', 'armoredcar', 'tank', 'anc_ballista', ...];
```

- **骑兵 / 车 = 显式 id 名单**。兵种表里没有"骑"这个字段，`move / range / armor` 也推不
  出来（游骑和弓手一样是 range 2，坦克和火炮的 armor 又差一截），这类归属是**设计决定**。
  漏写的后果是安全的：那个兵按标准价付 E（多花 5 点），不会凭空变强。
  `test-rules` 里有一条用例核对名单里的 id **都真实存在**——写错字、改兵种 id 会当场变红。
- **近战 = 派生**：`射程 1 的战斗单位`。两百多个兵种手写一遍不现实，而"射程 1 就是贴上去打"
  本来就是它的定义。斥候、民兵、长枪兵、骑士都在里面。
- **类别可以叠加**：斥候既是骑兵（机动 15E）也是近战（出手 30E）；骑士同理。
  这正是"斥候同时出现在用户点名的两张清单里"的合理解释。

## 五、拦得住的和拦不住的

这是这套实现最需要说清的一段。引擎里给扩展留的"否决位"并不对称。

### 5.1 拦不住的：保底首击

`doAttack` 第一次攻击时写的是 `attacksLeft = Math.max(1, attacksPerTurn(s, attacker))`。
即使 `modifyAttacks` 返回 0，这一格也会被兜成 1，攻击照打。这是引擎自己的口径
（"一回合至少能打一下"），扩展改不了。

**处理方式不是假装拦住**（比如把这一下的伤害改成 0——那会变成"我明明打了却打空了"），
而是**记账**：超支的部分变成透支，下回合先扣。

### 5.2 拦不住的：技能

`doHeroSkill` 只看冷却 / 充能 / 每回合一次，不看任何扩展钩子。所以 E 见底时技能照样放得出来，
同样记成透支。

### 5.3 拦得住的：移动

`modifyMove` 返回 0 是引擎写明的口径（`movePower` 收尾那句注释："钩子返回 0 = 这一回合动不了
（封冻的海军）"），所以 `left < 机动单价` 时单位就是走不了。界面上写「走不动了」，
免得玩家点下去只看到「目标格不可达」。

### 5.4 拦得住的：额外攻击

`modifyAttacks` 决定这一回合能有几次攻击：`min(burst, floor(预算 / 攻击单价))`。
机枪队 burst 3、E 只买得起 2 次，那这一回合就是 2 次。

### 5.5 顺带的几条

- **建筑不参与**：城墙不会"走"也不会"驻扎"，把 20E 记在它头上纯属噪音。
  面板上也什么都不显示。
- **刚上场的单位按满池、不拦**：新招的兵当回合本来就 `acted`，没账可记。
- **反击次数会跟着 E 走**：引擎按 `attacksPerTurn` 填 `countersLeft`，所以池子空了的守方
  还不了手。这是同一套账的自然结果，不是额外规则。
- **技能统一 60E**：`skillTurn` 只记"哪一回合放的"，不记"放的是哪个"。要按技能分档定价，
  得让引擎在 `skillTurn` 旁边再记一个 id——那属于核心改动，这一批不做（见第八节）。

## 六、界面上写了什么

`getUnitPanelLines` 是扩展唯一能往兵种面板写字的钩子（引擎负责画，扩展只给字符串）。
选中单位时多两到三行：

```
行动点 80 / 100 E
本回合：驻扎 −20
机动 15E（骑兵） · 出手 30E（近战）
```

- 第一行是余额；超支时补「已超支 N」，欠着时补「（上回合透支 N）」；
- 第二行是明细，直接说这一回合花在哪；
- 第三行只在**有减免**时出现（没有减免时它和规则书的默认值一样，纯占地方），
  末尾再补「走不动了 / 不够再出手」——**让玩家在点下去之前就知道为什么点不动**。

新增的六条规则用例：单价表（含 id 存在性核对）、开账与三种记账、攻击按次扣 + 次数被压回、
E 不足走不动 + 透支滚到下回合、驻扎 +2 护甲、建筑不参与 / 未开账按满池。
界面一条：面板上的余额、明细、单价与"走不动了"提示。

变异验证（改完都还原了）：

- `modifyMove` 改成永远 `return move` → 「E 不够时走不动」FAIL；
- `modifyAttacks` 改成永远 `return attacks` → 「次数被 E 压回」FAIL；
- `hold` 不套用机动档（改成不吃减免）→ 「单价表」里的"驻扎与机动同价"FAIL。

## 八、没做的事

- **技能按个定价**：引擎只在 `unit.skillTurn` 记"哪一回合"，不记技能 id，
  所以现在所有主动技能统一 60E。要分档，得先在核心那一侧多记一个字段。
- **上下船单独定价**：现在和移动同档（都是"站位变了"这一件事），想拆开需要引擎
  在 `LOAD` / `UNLOAD` 时留下一个可读的标记。
- **E 影响产兵 / 建造 / 拆除**：这几件事不属于"单位行动"，暂时不进这个池子。
- **AI 为 E 排序**：AI 通过 `attacksPerTurn` / `movePower` 自动看到 E 的后果（能打几下、
  能不能走），但它不会为了"省着用"而调整出手顺序。那是一个新的打分维度。
- **E 条 / 血条式显示**：现在是文字（余额 + 明细）。要多一条横条得改 UI，
  而 `getUnitPanelLines` 只给纯文本——这是扩展区的边界，不是懒。
- **透支的更多代价**：现在只是下回合少 E。掉血、减速这类惩罚会更狠，但那是平衡决定，
  不该和"先把账算对"混在一批里。
