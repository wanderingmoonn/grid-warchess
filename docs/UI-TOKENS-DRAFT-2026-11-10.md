### 2.2 硬编码色的处理策略（193 → 约 8 个家族）

不逐个造 token。按**用途家族**归并：

| 家族 | 现有代表值 | 归到 |
|---|---|---|
| 成功/治疗 | `#3f8a72` `#7ec47e` `#3f7a54` | `--ok` / `--ok-soft` |
| 警告/金币 | `#e0a33c` `#d8892b` `#a8761a` `#e8c76b` | `--warn` / `--warn-soft` |
| 失败/受击 | `#d9483f` `#c0392b` `#e07b6b` | `--danger` / `--danger-soft` |
| 信息/链接 | `#3b82f6` `#2f6ea8` | `--info` / `--brand` |
| 面板底色 | `#eae6dd` `#f6e2df` `#eef2ea` | 回落到 `--surface-*` |
| 文本灰阶 | `#4a5a44` `#4a463d` `#454d5b` | `--ink-*` |
| 地形色（白名单） | 17 个 `--plain/--forest/…` | **保持独立，不并入语义色** |
| 一次性特例（其余约 140 种） | — | **保留原值**，只加注释说明"这是局部色" |

最后一条是刻意的：把 140 个一次性色硬塞进 token，只会造出一堆 `--misc-17`，
既不可读也不可维护。**先归并能归并的，剩下明说是局部色**，比假装统一更诚实。

## 三、字体与排版

现状 19 种字号，收敛到 7 档：

| 档 | 值 | 现有用法（声明数） |
|---|---|---|
| `--fs-display` | 17px | 标题 3 |
| `--fs-h1` | 16px | 4 |
| `--fs-h2` | 15px | 5 |
| `--fs-body` | 13px | 37（正文主力） |
| `--fs-sm` | 12px | 73（最密的一档，卡片次要信息） |
| `--fs-xs` | 11px | 29（徽标、角标） |
| `--fs-num` | 12px + `font-variant-numeric: tabular-nums` | 数值（护甲/伤害/血量/回合数） |

两点说明：
- `11.5px` / `12.5px` 这两种半像素字号**直接归到 12**——它们在 1x 屏上是模糊的，
  并没有"更精确"的好处；
- 数值列改成 `tabular-nums`（等宽数字）是**唯一必须真做**的排版改动：
  战棋里"17/175"这种数字每秒都在扫，等宽能让竖列对齐，成本几乎为零。

## 四、间距与圆角

- 间距：`4 / 8 / 12 / 16 / 24 / 32 / 48`（现有 22 种取值，先只收"组件内边距"和"卡片间距"，
  布局级留白最后动）；
- 圆角：`--r-sm 6` / `--r-md 10` / `--r-lg 14` / `--r-pill 999`（现有 12 种 → 4 种）；
- 阴影：`--shadow-1` 卡片、`--shadow-2` 弹层、`--shadow-3` 模态。

| 批 | 内容 | 回滚方式 |

## 六、明确不做（这一轮）

1. **不改地形色**。17 个色按浅底调，棋盘保持浅底——认得出地形比"整体统一"重要。
2. **动画不上 `.tile`**。棋盘每帧重建，逐格过渡是最容易闪退的做法（64×64 踩过）。
3. **不做两套 CSS 文件**。单文件 + `data-ui` 属性切换，成本接近零，也不用双测布局。
4. **不把 modern 设成默认**。等 M3 验收后再讨论。

### 7.2 字号：19 种 → 16 种

- 立了 6 档 `--fs-title/h1/h2/body/sm/xs`；
- `11.5px`（16 处）与 `12.5px`（11 处）并进 `--fs-sm`——半像素在 1x 屏上本来就模糊；
- `12px`（73 处）改成走 `--fs-sm`，以后调密集卡片只需改一处。

还剩 17/16/15/14/10 等分档没动：**先动最没争议的**，剩下的等看实际观感再收。

### 7.3 数值等宽（新增）

`.info-row b` / `.price` / `.unit-sub` / `.city-line` 加 `font-variant-numeric: tabular-nums`。
战棋里"17/175""护甲 4""剩 2 次"每秒都在扫，比例字体的 1 比 7 窄，两行数字对不齐；
等宽之后竖列能直接比大小。**成本为零**（只影响字形宽度）。

### 7.4 对比度闸门（新增 `npm run test:contrast`）

把 `style.css` 的两套 token 抓出来算 WCAG 比值，已并入 `npm test`。
它当场抓出**我自己写的 modern 主题两处不达标**：

```
--line  #2e343f 在 --panel 上 1.32:1（要 ≥1.5）   → 改 #3a4250（1.63）
--text-3 #737b8a 在 --panel-2 上 3.51:1（要 ≥4.5） → 改 #8b93a3（4.85）
```

顺带暴露出**旧版早就有**的问题（本次记录、不动，因为改它就是改版）：

```
legacy --text-3 #9a9287：2.68 / 3.07 / 2.90 : 1（bg / panel / panel-2）
legacy --line   #e2ddd3：1.35:1
```

`--text-3` 用在 11–12px 的次要文字上（规则说明、坐标、注释），按 WCAG 它属于正文，
不适用"大字 3:1"的例外。**这是既有可读性缺陷，不是这次重构引入的**——
要不要顺手修，单独决策，别混在主题里。
