### 2.2 硬编码色的处理策略（193 → 约 8 个家族）

不逐个造 token。按**用途家族**归并：

| 家族 | 现有代表值 | 归到 |
|---|---|---|
| 成功/治疗 | `#3f8a72` `#7ec47e` `#3f7a54` | `--ok` / `--ok-soft` |
| 警告/金币 | `#e0a33c` `#d8892b` `#a8761a` `#e8c76b` | `--warn` / `--warn-soft` |
| 失败/受击 | `#d9483f` `#c0392b` `#e07b6b` | `--danger` / `--danger-soft` |
| 信息/链接 | `#3b82f6` `#2f6ea8` | `--info` / `--brand` |
| 面板底色 | `#eae6dd` `#f6e2df` `#eef2ea` | 回落到 `--surface-*` |
| 文本灰阶 | `#4a5a44` `#4a463d` `#454d5b` | `--ink-*` |
| 地形色（白名单） | 17 个 `--plain/--forest/…` | **保持独立，不并入语义色** |
| 一次性特例（其余约 140 种） | — | **保留原值**，只加注释说明"这是局部色" |

最后一条是刻意的：把 140 个一次性色硬塞进 token，只会造出一堆 `--misc-17`，
既不可读也不可维护。**先归并能归并的，剩下明说是局部色**，比假装统一更诚实。

## 三、字体与排版

现状 19 种字号，收敛到 7 档：

| 档 | 值 | 现有用法（声明数） |
|---|---|---|
| `--fs-display` | 17px | 标题 3 |
| `--fs-h1` | 16px | 4 |
| `--fs-h2` | 15px | 5 |
| `--fs-body` | 13px | 37（正文主力） |
| `--fs-sm` | 12px | 73（最密的一档，卡片次要信息） |
| `--fs-xs` | 11px | 29（徽标、角标） |
| `--fs-num` | 12px + `font-variant-numeric: tabular-nums` | 数值（护甲/伤害/血量/回合数） |

两点说明：
- `11.5px` / `12.5px` 这两种半像素字号**直接归到 12**——它们在 1x 屏上是模糊的，
  并没有"更精确"的好处；
- 数值列改成 `tabular-nums`（等宽数字）是**唯一必须真做**的排版改动：
  战棋里"17/175"这种数字每秒都在扫，等宽能让竖列对齐，成本几乎为零。

## 六、明确不做（这一轮）

1. **不改地形色**。17 个色按浅底调，棋盘保持浅底——认得出地形比"整体统一"重要。
2. **动画不上 `.tile`**。棋盘每帧重建，逐格过渡是最容易闪退的做法（64×64 踩过）。
3. **不做两套 CSS 文件**。单文件 + `data-ui` 属性切换，成本接近零，也不用双测布局。
4. **不把 modern 设成默认**。等 M3 验收后再讨论。
