## 0. 一句话

**阶段二修的是"钱往哪投"，阶段三修的是"兵怎么一路一路送上去"。**

主语要换：v4 现在的主语是"**一支要活下来的队伍**"，人的主语是"**一条能反复用的通道**"。
主力部队是消耗品——沿一条线一波一波送上去；一条线受阻就减每波兵力、把钱转产能，
直到产能撑得起两条线。所以本阶段的核心不是"某一处投送不好"，是**v4 心里没有"线"和"波"这两个对象**。

**"波"的定义（2026-11-26 10:52 定稿，第二版）：一波 = 一批人。** 不是"一支队的一次行军"，
也不是"一段战斗"。同一条线上**允许多批同时在途**（前面在打、后面在造、中间在路上），
判据看**断档**（前线空了、路上也没人）而不是"一波花了多少手"。定义与理由见
`DESIGN-LANES-WAVES` §3；第一版理解错了，已重写，别按旧版实现。

### 1.1 W1.5 的读数：v4 现在"送"得有多差

口径 `scripts/lane-report.ts`（34 题 × 24 手，我方 v4、对手 auto）。**不看红绿，只看投送**。

| 看到的 | 数 | 意思 |
|---|---|---|
| 从没补过人 | **22 / 34 题**（≤1 批） | 一次进攻只编一批，打完就没了 |
| 开过 ≥2 批 | 12 题 | 但这 12 题里几乎全是"每回合造 1~3 个就算一批" |
| 成批的（≥4 人） | **10 / 78 批** | 78 批摊在 213 人上，平均一批 2.7 人——**是滴灌，不是波次** |
| 打光后补过 | **1 题**（`S-002`） | "前一波死了后一波接上"这件事，几乎没发生过 |
| 前线 0 人 | **78 手** | 线开着，但没人能打到城。⚠️ **这里含"正常行军"**（用户 2026-11-26 指出）：第一批在路上时当然打不到，所以它只能当**上界**看，不能直接叫"送不上去" |
| 断档（前线 0 且路上 0） | 17 手 / 2 题 | 少见——因为大部分时候**路上还堵着一堆人**，不是没货 |
| 交换（6 手窗口） | 赚 4507 / **亏 5610**，9 题净亏 | 送到了也换不到东西 |

三句话：
1. **v4 不会编"一波"**：它是每回合把新造的 1~3 个人塞进同一条线，78 批里只有 10 批够 4 个人。
2. **它从不补位**：一波打光之后就没了（34 题里只 1 题补过）——这正是 W2/W3 要改的。
3. **问题不在"没货"**：断档只有 17 手，而"前线 0 人"有 78 手。但 78 手里有相当一部分是
   **正常行军**（第一波还在路上），所以只能说"展不开的时间明显多于"没货的时间"，
   不能直接说"送不上去"——要分开量得再记一个"在途已经走了几手"。

用户的判断同时被数据支持：多数题只给开局一堆单位、没有经济地基，所以**造兵本来就少**——
这也意味着 W3 的"下一批"在大多数题上会算成"没有下一批"。这不是 bug，是题的形状；
真正需要它的是长局（`S-001`/`S-002`/`E-2-05` 这类），到 W3 立新题时再补。

W1 已经把"投送"第一次变成可看的数（`V4_LANE_LOG=1` 每手一行）：

```
[lane] T=11 front=6 接火=7 road=8 make=0 · 波 c2 出发T1 10人 · 到7/10 均1.4/手 本手+4 首次T3 · 交换(6手) 赚250 亏0
```

三件已经量出来的事（都在 `S-000 / S-001 / S-002` 上，**S 系列只作参考**）：

| 观察 | 数 | 含义 |
|---|---|---|
| 到货率 | 三道题都 **1.2~1.4 人/手** | 差别不在"通道快慢" |
| 展开程度 | S-000 到 7/10；S-002 到 **6/25** | **送进去的规模 ≠ 能展开的规模** |
| 交换账 | S-001 赚 720 / **亏 720**；S-002 赚 1000 / **亏 2600** | **送到了也换不到东西** |
| 产能 | `make` 几乎恒为 0 | 现在只维持得起一条线 |

**结论**：主要矛盾**不是**"窄道慢"，是"**派得多、展不开、换不到**"。
这条直接决定了 W2 该先换判据（看交换），而不是先修路况（W4）。

### W3 ✅ 一批多少人（2026-11-26 12:45，**1 题变绿，0 题变红**）

**做了什么**（决定层 + 约束层）：

1. **决定层给出"这一批几个人"**（`Decision.men`）。口径 = **6 手内能走到城下的人数**
   = **这条线自己**实测的到货率 × 期限；**还没有数据就不设上限（全送）**——
   每张图的到货速度都不一样，写死一个数会错（第一版写死 8，已删）。
   另加一个**下限**：至少凑得够打死一个守军，否则会掉进"越打不过 → 批越小"的死循环。
2. **约束层只派这一批**：按"离城近"取前 `men` 个，**余下的留在家当预备队**；
   前排死了，下一手它们自动被选中往前走——这就是"一波一波接上"，不需要另写一条发车时刻表。
3. **留多少人，看能补多少人**：`men = min(总兵, max(能展开的, 总兵 − 每回合能造几个 × 6))`。
   产能 0 → 一个不留（后面根本没人来，扣着兵只会让前线更薄）；产能 12 → 最多留 12 个。
4. **旧的 `want`（守军身价 ÷ 我方身价 × 1.5、12 手不缩）退场**：它算"该派几个"，
   而真正的限制是"一批能送到几个"。

**"开几条线"这一半没写**：判据是 `产能 × 期限 ≥ 两条线各一批的成本`，而实测 22/34 题
一手能造 0 个兵（钱被兵吃光）。写了也永远不触发，等于一段没人走的代码。等有经济的长局再补。

**结果（34 题，和 W2 的基线逐题比）**：

- **只有 S-013（多城分兵）红 → 绿**：一批被限住之后，另一座城留住了人（`我城 2/2`）。
- **其它 33 题红绿一个没变**（S-000 / S-001 仍然绿）。
- 投送读数（`lane-report`，34 题 × 24 手）：批数 78 → **70**，其中 ≥4 人的成批 10 → **18**
  （不再是一人一批的滴灌）；送到前线 87 → 85 人；交换 亏 5610 → **4450**。

**为什么改得这么少**：用户的判断是对的——多数题只给开局一堆兵，`make` 常年是 0。
产能为 0 时"留预备队"没有任何好处，所以 W3 只在**多线**（S-013）和**有钱造兵**的局上咬合。
这不是没做，是这组题本来就没有第二批可送。

**验收缺口**：`P-2-01`（两波题）**要重做**。用户 2026-11-26 的审阅意见：

- 6 个"经济单位"里有 4 个是**奴隶**（建造工人，不产金）→ 换真正产金的农民；
- **火炮带溅射**，顺带考了"散开前进"，v4 不会；
- 开局兵**射程远的在前、射程近的在后**，要先变阵才能前进，v4 也不会；
- 开局送的兵就够赢 → **考不到沿兵线补充**；
- 结论：太综合。重做时要：只看"投送"，把阵型、溅射、兵种搭配都拿掉。

### W3 原始计划（留档）

- **做什么**：决定层输出从"打哪座城"变成"**开几条线、每条线每批多少人**"：
  `lines: [{ targetCityId, men, stance: 'push' | 'hold' | 'build' }]`。
  `men` 是**一批**的人数，由"每波成本 × 产能 × 期限"推出来，**不再是"守军身价 ÷ 我方身价 ×1.5"**。
  一条线受阻（`stuck` / 交换亏）→ `men` 减半、钱转产能；产能撑得起两条线各一批 → 开第二条线。
- **同时要立的第二件事（第一版漏了）**：**下一批什么时候上路**。
  不等前面死光，而是"前线人数 ÷ 每回合消耗 < 下一批到城下的回合数 + 造一批要的回合数"
  → 现在就编。判据是**断档**（前线 0 人、路上也 0 人，连续几手）。口径见 `DESIGN-LANES-WAVES` §3.3。
  这条和"开几条线"是两件事，**不许合成一个判断**。
- **前置**：账按线分（W1.5 第 2 条）。没有它，两条线一开就砍错线。
