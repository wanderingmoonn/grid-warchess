## 0. 一句话

**阶段二修的是"钱往哪投"，阶段三修的是"兵怎么一路一路送上去"。**

主语要换：v4 现在的主语是"**一支要活下来的队伍**"，人的主语是"**一条能反复用的通道**"。
主力部队是消耗品——沿一条线一波一波送上去；一条线受阻就减每波兵力、把钱转产能，
直到产能撑得起两条线。所以本阶段的核心不是"某一处投送不好"，是**v4 心里没有"线"和"波"这两个对象**。

**"波"的定义（2026-11-26 10:52 定稿，第二版）：一波 = 一批人。** 不是"一支队的一次行军"，
也不是"一段战斗"。同一条线上**允许多批同时在途**（前面在打、后面在造、中间在路上），
判据看**断档**（前线空了、路上也没人）而不是"一波花了多少手"。定义与理由见
`DESIGN-LANES-WAVES` §3；第一版理解错了，已重写，别按旧版实现。

### 1.1 W1.5 的读数：v4 现在"送"得有多差

口径 `scripts/lane-report.ts`（34 题 × 24 手，我方 v4、对手 auto）。**不看红绿，只看投送**。

| 看到的 | 数 | 意思 |
|---|---|---|
| 从没补过人 | **22 / 34 题**（≤1 批） | 一次进攻只编一批，打完就没了 |
| 开过 ≥2 批 | 12 题 | 但这 12 题里几乎全是"每回合造 1~3 个就算一批" |
| 成批的（≥4 人） | **10 / 78 批** | 78 批摊在 213 人上，平均一批 2.7 人——**是滴灌，不是波次** |
| 打光后补过 | **1 题**（`S-002`） | "前一波死了后一波接上"这件事，几乎没发生过 |
| 前线 0 人 | **78 手** | 线开着，但没人能打到城。⚠️ **这里含"正常行军"**（用户 2026-11-26 指出）：第一批在路上时当然打不到，所以它只能当**上界**看，不能直接叫"送不上去" |
| 断档（前线 0 且路上 0） | 17 手 / 2 题 | 少见——因为大部分时候**路上还堵着一堆人**，不是没货 |
| 交换（6 手窗口） | 赚 4507 / **亏 5610**，9 题净亏 | 送到了也换不到东西 |

三句话：
1. **v4 不会编"一波"**：它是每回合把新造的 1~3 个人塞进同一条线，78 批里只有 10 批够 4 个人。
2. **它从不补位**：一波打光之后就没了（34 题里只 1 题补过）——这正是 W2/W3 要改的。
3. **问题不在"没货"**：断档只有 17 手，而"前线 0 人"有 78 手。但 78 手里有相当一部分是
   **正常行军**（第一波还在路上），所以只能说"展不开的时间明显多于"没货的时间"，
   不能直接说"送不上去"——要分开量得再记一个"在途已经走了几手"。

用户的判断同时被数据支持：多数题只给开局一堆单位、没有经济地基，所以**造兵本来就少**——
这也意味着 W3 的"下一批"在大多数题上会算成"没有下一批"。这不是 bug，是题的形状；
真正需要它的是长局（`S-001`/`S-002`/`E-2-05` 这类），到 W3 立新题时再补。

W1 已经把"投送"第一次变成可看的数（`V4_LANE_LOG=1` 每手一行）：

```
[lane] T=11 front=6 接火=7 road=8 make=0 · 波 c2 出发T1 10人 · 到7/10 均1.4/手 本手+4 首次T3 · 交换(6手) 赚250 亏0
```

三件已经量出来的事（都在 `S-000 / S-001 / S-002` 上，**S 系列只作参考**）：

| 观察 | 数 | 含义 |
|---|---|---|
| 到货率 | 三道题都 **1.2~1.4 人/手** | 差别不在"通道快慢" |
| 展开程度 | S-000 到 7/10；S-002 到 **6/25** | **送进去的规模 ≠ 能展开的规模** |
| 交换账 | S-001 赚 720 / **亏 720**；S-002 赚 1000 / **亏 2600** | **送到了也换不到东西** |
| 产能 | `make` 几乎恒为 0 | 现在只维持得起一条线 |

**结论**：主要矛盾**不是**"窄道慢"，是"**派得多、展不开、换不到**"。
这条直接决定了 W2 该先换判据（看交换），而不是先修路况（W4）。

### W3 ✅ 一批多少人（2026-11-26 12:45，**1 题变绿，0 题变红**）

**做了什么**（决定层 + 约束层）：

1. **决定层给出"这一批几个人"**（`Decision.men`）。口径 = **6 手内能走到城下的人数**
   = **这条线自己**实测的到货率 × 期限；**还没有数据就不设上限（全送）**——
   每张图的到货速度都不一样，写死一个数会错（第一版写死 8，已删）。
   另加一个**下限**：至少凑得够打死一个守军，否则会掉进"越打不过 → 批越小"的死循环。
2. **约束层只派这一批**：按"离城近"取前 `men` 个，**余下的留在家当预备队**；
   前排死了，下一手它们自动被选中往前走——这就是"一波一波接上"，不需要另写一条发车时刻表。
3. **留多少人，看能补多少人**：`men = min(总兵, max(能展开的, 总兵 − 每回合能造几个 × 6))`。
   产能 0 → 一个不留（后面根本没人来，扣着兵只会让前线更薄）；产能 12 → 最多留 12 个。
4. **旧的 `want`（守军身价 ÷ 我方身价 × 1.5、12 手不缩）退场**：它算"该派几个"，
   而真正的限制是"一批能送到几个"。

**"开几条线"这一半没写**：判据是 `产能 × 期限 ≥ 两条线各一批的成本`，而实测 22/34 题
一手能造 0 个兵（钱被兵吃光）。写了也永远不触发，等于一段没人走的代码。等有经济的长局再补。

**结果（34 题，和 W2 的基线逐题比）**：

- **只有 S-013（多城分兵）红 → 绿**：一批被限住之后，另一座城留住了人（`我城 2/2`）。
- **其它 33 题红绿一个没变**（S-000 / S-001 仍然绿）。
- 投送读数（`lane-report`，34 题 × 24 手）：批数 78 → **70**，其中 ≥4 人的成批 10 → **18**
  （不再是一人一批的滴灌）；送到前线 87 → 85 人；交换 亏 5610 → **4450**。

**为什么改得这么少**：用户的判断是对的——多数题只给开局一堆兵，`make` 常年是 0。
产能为 0 时"留预备队"没有任何好处，所以 W3 只在**多线**（S-013）和**有钱造兵**的局上咬合。
这不是没做，是这组题本来就没有第二批可送。

### W3 原始计划（留档）

### W3.6 编队生命周期归位（**已完成：第 1~6 步全部 ✅（2026-11-26 15:40）**）

#### 为什么插队

2026-11-26 看 P-2-01 的回放，出现三个现象：后面几支进攻编队全是 `blocked`（其实是在"组"）、
攻城之后编队全部消失、编队人数和名册对不上。排查下来是同一件事：

> **编队的"出生"在链上（约束层组队），"死亡"是隐式的，中间还有四条老机制在从名册里偷人。**

不先修这条，W4 的路况没有可挂的对象——路况量的是"一条线上的一支队伍的通过能力"，
而"队伍"本身还不成立。

#### 三个现象 → 代码位置

| 现象 | 直接原因 |
|---|---|
| 后面几队全 `blocked`（面板上的"组"） | `ready = 本队现有人数 >= decision.men 或 八成人 2 回合内能到`。`men` 是**新编队的目标人数**，而名册只减不增 → 掉一个人就永远 `< men`，永远回不到 march |
| 攻城后编队全部消失 | 城一没，决定变 `takeover`；接管分支不看编队，直接 `rest` 重建一支 `main: hold`；记忆里的 `bands` 成了孤儿，下次按 `cityId` 过滤时全被丢掉 |
| 名册人数对不上 / 新兵进不来 | `rest = 战斗兵 − held − 站在关键格上的`。新兵**出生在产兵格**（= 关键格）→ 一出生就进 `yield`；队里的人走到关键格 → 下一手被剔出 `rest` → 名册静默少人 |
| （背景）每城留 2 个守军 | `constrain` 的 `held`：9.7 只是把"无条件"收窄成"敌人下一手能摸到"，`slice(0,2)` 没删。它不认编队，却决定编队能拿到谁 |

#### v3 是怎么做的（可学的六条）

| # | v3 的做法 | 对 v4 的意义 |
|---|---|---|
| 1 | 编队是**有状态的对象**：`forming → marching`，状态写在记忆里，每回合由 `squadTick` **一个入口**更新 | v4 的编队没有状态，只能从 `order` 反推 |
| 2 | **凑不齐也会走**：`人数 ≥ want` 或 `turn − since ≥ 10`（`SQUAD_FORM_TIMEOUT`） | v4 没有超时，凑不齐就永远在集结点 |
| 3 | **撤编有明确条件**：全灭 / 存活 `< want×0.4`（`SQUAD_DISBAND_RATIO`）/ 没有敌城 | v4 是"人从 rest 里消失"，没人对它负责 |
| 4 | **只在收拢期吸收新兵**，出发后不再补 | v4 现在反了：每回合重建都在换人 |
| 5 | **缺口回传采购**：`squadNeed = Σ(want − 人数)` 进采购评分；每队还上报 `count/lead/stalled/lost` | v4 的采购完全不认编队，新兵不知道该进哪队 |
| 6 | `want` 不是拍的：`squadCap = 6 + 8×兵力比`，计划层再按意图申报（突破 12 / 屯兵 8） | v4 的 `men` 已经有自己的口径（到货率 × 期限），**不抄这个公式**，只抄"计划层可以申报规模"这条通道 |

#### 第 1 步 ✅ 编队状态与超时（2026-11-26 14:10）

- `Band` 加了 `state: 'forming' | 'marching'` 和 `want`（编制人数）。
- **收拢中的队伍继续吸收新兵**（只补到 `want`），凑够就走；
  **凑不够等满 10 手也走**（v3 的 `SQUAD_FORM_TIMEOUT`，有多少走多少）。
- `ready` 改成看编队自己的状态，**不再拿"新队的目标人数"去卡老兵**。
- 结果（35 题）：**`blocked` 消失**——P-2-01 的第一队从 T2 起一直是 `siege`，
  第二队在 T4 成军、边收人边走，T12 凑够 8 人转 `marching`。
  - S-001（地板）红 → 绿；S-013 红 → 绿；**S-005（过桥）绿 → 红**（区域里只到了 2 个）。
  - 非 S 一道没变；P-2-01 从"未分胜负"变成第 17 手获胜。

#### 第 2 步 ✅ 撤编显式化（2026-11-26 14:25）

- **名册只因为"人死了"缩小**，不再因为"站在关键格上 / 被留作守城"被静默剔除。
  以前是"名册 ∩ rest"，新兵出生在产兵格 → 一出生就被踢；队里的人走过关键格 → 静默少一个。
- **撤编只有三种**：全灭 / **已出发**且存活不到编制四成 / 没有敌城（决定层不会走到 press）。
  "四成"只对已出发的队生效——收拢中的队本来就小，按四成判会把刚成军的两三个人立刻判死，
  于是每手重建一支新队（ID 一直变）。
- 这一手能派出去的，只是名册里不在关键格 / 没被留作守城的人；**名册不变**，下一手还会回来。
  全队这一手都在让位时，这支队的 squad 先不生成（不撤编）。
- 结果（35 题）：**S-005（过桥）红 → 绿**；**S-001（地板）绿 → 红**。
  归因：T8 决定翻成 `expand`，编队被另一条分支的 `main: assemble` 顶掉——正是第 3 步要解决的问题。
  非 S 一道没变。

#### 第 3a 步 ✅ 打空之后整队转接管（2026-11-26 14:40，**35 题红绿零变化**）

**改了什么**：`takeover` 分支不再"从这一手能派的人重造一支 `main`"，而是**按记忆里的编队名册
原样生成队伍，只换任务名**：

| 阶段 | 任务 | 名册 |
|---|---|---|
| 清场（废墟边还有敌人） | `march`（照打，路上遇敌就打） | 不变 |
| 攒钱 / 入驻 | `hold`（守着） | 不变 |

- 目标城**没变**（还是那座城，只是从敌城变成废墟），所以站位不用重排——这是所有转换里最便宜的。
- 不在编队里的兵（刚造的、原本守城的）照旧编一支 `main`，否则接管期会有一批人站着不动。
- 证据（S-000 第 10 手起进入接管）：

```
改前  squads[main:march:15]                        ← 三支队被并成一支，名册成了孤儿
改后  squads[c2#1:march:10 c2#3:march:4 main:1]    ← 两支队原样保留，只换任务
```

- 结果：**35 题红绿一个没变**（31 绿不变），`npm test` 21/21。接管只发生在战斗尾声，
  红绿判据基本只看结局，所以这一层的收益要在回放里看（队伍不再"突然消失"）。

**顺手量到一件事（下一步要治）**：S-001 现在红的直接原因**不是接管**，是 `press → expand` 的切换：
第 8 / 10 / 18 手决定翻成"发展"，正在攻城的编队被兜底分支的 `main: assemble` 顶掉——

#### 第 3b 步 ✅ 外来压力下整队召回（2026-11-26 14:55，**35 题红绿零变化**）

**改了什么**：

1. 服务层新增 `world.defensible(城)`（**唯一一份"守得住吗"的算术**）：
   时间窗 = `cityStand` 给的"这座城还能撑几轮"；`守军` = 窗口内赶得到、且**没有被编队派去进攻别处**的人；
   `产能` = 一手能造几个 × 窗，被"钱总共买得起几个"卡住；`来犯` = 窗口内赶得到的敌人。
   判据：**守军身价 > 来犯身价 才算挡得住**（打平算挡不住——守方没有余量时该收队，不是继续在外面打）。
2. 决定层 `defend` 的触发从"**总身价**被压到 0.9"换成"**某座城挡不住**"，并排除已派去进攻的兵。
3. 约束层 `defend` 不再把所有人收成一支 `recall`：**按编队处理**，判据只有一条"回得去吗"——
   回得去 → 这支队任务改"守"、目标改自家城，名册不动；回不去 → 不切任务，继续打它原来的城。
   距离用 `world.marchTurns`（距离场），期限用"城还能撑几轮"，**没有"8 格"这种死数字**。

**踩到的两个坑**（都记在下面，别改回去）：

| 坑 | 症状 | 正解 |
|---|---|---|
| 把"已经被派去进攻的兵"算成守军 | D-1-01 开局 4 对 4，判"挡得住"→ 继续攻城 → 6 手丢城 | `defensible(城, skip)`：编队派出去的人不算守军 |
| 把"产能"算进"该不该转守" | P-1-01：300 金能造 3 个戟兵 → 判"挡得住" → 去发展造农民 → 被 2 个戟兵拆家 | 产能只回答"守不守得住"（差多少、补不补得上），**不进"该不该转守"的不等式**；否则钱多就永远不回头 |

**结果**：35 题 **红绿零变化**（31 绿不变，仍红 S-001 / S-002 / S-004 / S-011），`npm test` 21/21。
行为在回放里可见（D-1-01 第 12 手：两支队回城守，一支回不来的继续打）。
`defend` 现在只在"守军真的不占优"时才触发，比原来的"总身价 0.9"精确到城。

#### 第 5 步 ✅ 采购认编队（2026-11-26 15:40，**35 题逐字节零变化**）

三件事，一件落地、一件本来就有、一件试完否掉：

| 要做的 | 结果 |
|---|---|
| **缺口回传采购**（编制 − 现在几个人） | ✅ `Constraints.bandNeed = { keep, men }`（编制之和 + 一支预备队） |
| **新兵进预备池，够 `menMin` 才成军** | 本来就有：空闲兵就是池子，`free ≥ menMin` 才开新队（第 1/2 步） |
| **采购按编制封顶**（造到编制 + 一批就停） | ❌ **试了，不行**，见下 |

**封顶为什么不行**：E-2-03 是一道"把 4000 金变成战力"的题，场上只有两个 1 人小队、编制也是 1。
按"编制 + 一批"封顶只造 5 个就停，部队战力 **897 → 454**，直接翻红。
结论：**编制是"最少要几个"，不是"最多造几个"**——采购该按缺口补员、按产兵格刹车，
不该拿编制去封顶。

**落下的是"缺员优先补兵"**（`withSpend`）：发展期如果**已出发的编队**还有缺口，
钱先买战斗兵，不先铺经济。缺口是数出来的（编制 − 活着的人），没有系数。

**读数**：35 题**逐字节零变化**（32 绿不变）。这条规则确实会触发（S-001 第 8/10/18 手
发展期就是它把模式从"先经济"改成"先兵"），但这组题在那些回合**没有空的经济岗来抢这笔钱**，
所以动作一模一样。它的价值要等"有经济的长局"才看得见——和 W3 那个结论是同一件事。

**顺手把缺口写进了观测**：`[band] c2#1[march] 13/18(缺5) 掉5 到4 距6手`，
快照里也有 `bandNeed`（采购要造到多少人）。

#### 第 3c 步 ✅ 决定层改成"每队一条任务"（2026-11-26 15:10，**S-001 红→绿**）

**为什么做这一步**：这一步之前，决定层只有**一个全局类型**（打 / 守 / 接管 / 发展）。
于是"打 → 发展 → 打"每翻一次，约束层就要把所有人重建成一支队伍，正在攻城的编队被叫回家集合。
S-001 第 8/10/18 手就是这么来回走的——**40 手打不完不是打不动，是走掉了**。

**改了什么（数据契约，不是新算法）**：

1. `Decision.bandTasks: BandTask[]`——决定层对**每一支在编的编队**交一条任务
   （`bandId / order / cityId`）。这是"每队一条任务"的落点，为之后多线铺路。
2. 任务怎么来（`bandTasksOf`，四条规则，都是二值的）：
   - **守**：所有在打敌城的队，任务标成"守这座城"（走不回去的，计划层会退回进攻）；
   - **接管**：只有冲着这座废墟去的队改任务（清场照打、攒钱入驻守着）；
   - **打 / 发展**：目标还是敌城就继续打它自己的城——**发展只管钱和后方，不改前线任务**；
   - 目标已经不是敌城（打下 / 废墟 / 丢了）→ 这队没有任务，交给计划层收编。
3. 约束层四个分支都改成读任务，只保留"可行性"：能不能派（在不在关键格）、
   走不走得回去（距离场 ≤ 剩几轮）。打 / 接管 / 守三条分支的**行为逐字不变**，
   变的只有发展分支（不再召回）。

**结果**：**S-001 红 → 绿**（32/35 绿）；其余 34 题红绿零变化，非 S 一道没红。
`npm test` 21/21。回放：S-001 第 8/10 手决定仍是 `expand`，但两支编队在 `march`，不再回家。

**它顺带说明了"每队一条任务"不是抽象的**：D-1-01 第 12 手同时存在两种任务——
`hold-c1:hold:2`（回城守）+ `c2#5:march:1`（回不去，继续打）。

### 批大小的上限：四次都试砸了（2026-11-26 16:20）

用户要求："有下限却没有上限，大批军队一起出行也会被各种地形拦住，用数据算出一个上限，不要太多人。"

先把"上限"的数据算出来了：**`world.siegeSeats(城)` = 能同时打到这座城、又站得下人的格数**。
它是几何事实（到城步数 ≤ 我方射程、不占城格），随城升级变大：

| 城 | 站得开几格 |
|---|---|
| P-3-01 的 3 代城（2×2，射程 2） | **16** |
| P-3-01 的城升到 3×3 之后 | **33** |
| S-001 的城（隔一条河） | 22 |

然后拿它当上限，**四种口径全试了，全砸**：

| 口径 | 结果 |
|---|---|
| `到货率 × 6 手` | 一批人一起到齐时（长距离图很常见），率算成 12 人/手 → 上限 72，等于没封 |
| `手上剩多少 − 能补多少`（原来的写法） | 长局里编制涨到 **27~29**，收拢要 10 多手——v4 比 v1 慢 20 手就是这个 |
| `过去几批平均送到多少人` | **自激**：批越小 → 平均越小 → 下一批更小。S-001 直接翻红（和"越打不过率越低"同一个死循环） |
| `站得开几格`（几何上限） | 第一队也封 → S-001 / S-012 红；只封后续队 → 连 S-011 也红 |

**为什么几何上限也不行**：走廊地图（过桥、要道）上"站得开"只有个位数，
可攻方偏偏需要**不断轮换补人**——封住批大小等于不许轮换，于是打不动。
**拦人的是行军通道，不是目的地容量**，这是两件事。

**所以这一步只落了观测**：`[lane] ... · 站得开 16 格`。批大小仍然只有下限（打死一个守军），
上限留给 W4 去算——要算的是"**最窄处几格宽 × 队伍排多长**"，不是"城下能站几个"。

### W4 路况（含原 P4 剩余 + P7）——拆成四小步

| 架桥 | **完全没有**（`grep BUILD src/core/v4/` 为空） | 工兵、选址、值不值 |

  刻意放慢会有损视野）。

  要数它：**桥面连续 N 手被"能打到城但这一手没动"的远程占着，且后面排队 ≥2 人**。
  修的时候有两条路（都不在 W4 做）：远程让开桥面再打（要多一步），或者过桥前就分好
  "谁先过、过完站哪"，不许停在窄口。
- **4c 窄道 ✅（2026-11-26 16:55，**36 题 34 绿、S-001 红→绿**）**：两件事，一件成了、一件否了。

  **成了：桥上的人不再被"关键格驱离"赶下来**（用户的想法）。
  关键格驱离的本意是"别把产兵口/桥头堵死"，但它把**正在过桥的人**也赶了下来：
  踩上桥面 → 下一手被摘出队伍去"让开" → 走一步下桥 → 再从头排队。
  现在只驱离**不准备过桥的**（不在任何进攻编队名册里的），已经在编队里、目标还是敌城的人
  允许站在桥上继续走。**只对桥面放宽，城格不动**（堵产兵口是真的不出兵）。

#### 4d 方案：学 v3，但拆进 v4 的三层（2026-11-26 17:30）

**先把短板量出来**（把 `P-4-01` 的桥拆掉、其余不动，跑同一套判据）：

| | 城伤 | 城下我方战斗兵 |
|---|---|---|
| 有桥（`P-4-01`） | 81（v4 第 13 手赢） | 12 |
| **无桥（同图，河横断）** | **0** | **0** |

12 个兵全卡在河西岸。原因在代码里是一句话：距离场只走 `passable` 的地形，水面走不通
→ `marchTurns = Infinity` → `planMarch` 找不到任何落点 → 整队不动。**v4 现在对"过不去的河"没有任何处理。**

**v3 的做法（五条，都值得学）**

| # | v3 的做法 | 为什么（v3 自己的实测） |
|---|---|---|
| 1 | **判据只有一条**：`canReach` = 地形 BFS 走不到敌城。桥一通就收回，不再建 | **不认"造了几座桥"，认"走不走得通"**：认桥数时 8 座桥有 0 座真的接通（在湖里填、在河湾抄近路，数量越涨越像干活） |
| 2 | 架桥点是**渡口**：横向数水面宽度，选**最窄**的一段；要靠我方这岸、对岸离敌城近 | "最近的一格水面"会在湖心架桥，永远接不上岸 |
| 3 | **顺着上次的方向接着铺**（`chain`）：那一格必须正好挡在近岸和我之间 | 只认"挨着自己桥面"会横着铺成广场（实测真干过：先横三格再竖两格，河心停住） |
| 4 | **工兵单独一队**（`build-{turn}`，2 人），目标 = 渡口；桥通了不给点 → 待机 3 回合 → 解散 | 解散太早会"拆了又修、修了又拆" |
| 5 | **拥堵分流**（可选）：主渡口连续堵 3 回合 → 引一支队去第二渡口（离旧口 ≥6 格，锁 10 回合） | 1~2 回合可能只是路过 |

**落进 v4 三层**

| 层 | 做什么 | 具体 |
|---|---|---|
| 服务层 `world` | **回答三个事实** | ① `canReach(city)`：地形 BFS 能不能走到城下（`marchTurns === Infinity` 即不能）；② `crossing(city)`：渡口 = 最窄、能接通两岸的一段水面，给出"从哪格起、朝哪个方向、要几格"；③ `bridgeCost(city)`：几格 × 木桥单价（45 金 / 8 工时，随时代可换石桥/钢桥） |
| 决定层 `decide` | **一句话：走不到，就架桥** | 排在 `press` **之前**（走不到就没得打）。输出 `kind: 'bridge'`，带目标城 + 渡口 + 一句理由。**收回条件**：`canReach` 变真就立刻回 `press`，不等工兵走回来 |
| 计划层 `constrain` | **工兵编队 + 铺桥次序** | 工兵单独一队（1~2 人，`Band` 加 `role: 'build'`），目标 = 渡口；一次铺一格、铺在渡口下一格，铺完接着铺（`chain`）；桥通 → 待机 3 回合 → 解散 |
| 打分层 `tactics` | **只执行** | 工兵贴着渡口（岸上或已铺的桥头）→ `BUILD`；够不着 → 朝渡口走一格。**沿用现有规矩：不自己挑位置** |
| 入口 `ai-v4` | 把 `BUILD` 加进动作表 | 现在 v4 根本不发 `BUILD`（`grep BUILD src/core/v4` 为空） |

**"值不值"怎么变成可数的比较**（这是 4d 唯一的题面风险）

不拍系数，两边都用现成的步数：

- **绕路**：`marchTurns(我 → 敌城)`（有陆路时才有值）；
- **架桥**：`走到渡口的手数 + 铺 N 格 × 1 手 + 渡口到敌城的手数`。

两者都有值时取小的；陆路是 `Infinity` 时架桥是唯一解。这样"该不该花这笔钱"不是一个主观判断，
而是**两个手数比大小**——能被别人拿回放反驳。

**分三步做（每步单独跑 36 题 + 无桥对照）**

1. **4d-1 服务层三个数**（只观测，不改行为）：`canReach` / `crossing` / `bridgeCost`。
   验收：无桥对照能报"走不到 + 渡口在 (9,9) 方向朝东、要 3 格、135 金"；
   有桥的 `P-4-01` 报"走得到"；36 题**逐字节零变化**。
2. **4d-2 决定层 + 工兵编队**：`kind: 'bridge'` + `Band.role='build'`。
   验收：无桥对照的 12 个兵**不再堆在岸边**（工兵往渡口走、其余待命/守城），
   看 `[band]` 日志里出现 `build` 队。
3. **4d-3 打分层 BUILD**：真的把桥铺出来。
   验收：无桥对照从"城伤 0"变成"能过河、城伤 > 0"；`P-4-01` 不许变红（13 手）。

**新题**：`P-4-02`（无桥版）—— 就是 `P-4-01` 去掉桥、给 2~3 个工兵、给够桥钱。
它是 4d 的验收题，只在 4d 期间用，不进跑批（桥是慢变量，跑批里没意义）。

**验收口径**：一律"**单位时间通过量**"（终点到货率 + `stuck` + 4a 的三个数），不看红绿。
