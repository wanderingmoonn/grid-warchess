# 规则书：14 册并成 6 册，兵种表不再重复解释

> 起因：想知道"盾墙到底减多少"，得在五个奇想分册里翻；同一句"魔法攻击不吃护甲"
> 在每本兵种表后面各印一遍，五本加起来二十二遍。想比"骑士团的剑士和荒兽的狼骑士
> 哪个值"，得同时开两个标签页对眼。

---

## 一、一句话

规则书从 **14 册并成 6 册**：奇幻五包一本、时代兵备五包一本；兵种表里只留能扫的
数值，解释挪进**悬停浮层**与**词条表**（点一下跳过去）。规则一条没改，兵种一个没少。

## 二、先报数

| | 改之前 | 改之后 |
|---|---:|---:|
| 册数 | 14 | **6** |
| 全部规则书体积 | 302 726 字节 | **270 157 字节**（−11%） |
| 奇幻系列（5 册 → 1 册） | 91 640 字节 | **65 029 字节**（−29%） |
| 时代兵备（5 册 → 1 册） | 70 991 字节 | **44 240 字节**（−38%） |
| 奇幻册兵种表"特性"列的总字数 | 1 388 字 | **739 字**（−47%） |
| 「不吃护甲」这句解释在全册出现的次数 | 22 次 | **1 次** |
| 可悬停 / 可跳转的机制引用 | 0 | **292 处** |
| 扩展兵种入册覆盖 | — | **135 / 135** |

一处不讨好的数字放在这里：**核心册从 107 115 字节涨到 117 747（+10%）**。
它的正文一个字没删，多出来的是第 21 章那份词条索引和 292 颗链接的标签。
换句话说，这一册是"给正文加了一层说明书"，不是"变薄了"——如果你只看体积，
这一册确实变厚了；如果你看"读表格时眼睛要跳过多少注释"，它变薄了。

另外三册（小型合订本、城郭、季节）也各涨了 2~3 KB：涨的是词条样式，不是内容。
浮层脚本按需注入——一册里一颗机制引用都没有（季节、小型合订本）就不带它，
省下 2.5 KB 的死代码。

## 三、为什么按"系列"并，而不是按包

拆册的初衷是"没开的包别占版面"。但拆到一包一册之后，代价开始反过来：

1. **同一套机制要印五遍。** 五个奇想包共用同一套魔法 / 属性 / 状态 / 空中层规则，
   原来每本分册各带一份四十行的"新规则"——五本里四本的内容是一样的。
2. **跨包比较做不了。** 玩家真正会问的是"同一个时代、差不多的价钱，这五个包里
   哪个划算"。五张表各有各的表头，翻到第二张就忘了第一张的数。
3. **查一个词要开五本书。** "掠空和飞行差在哪"这种问题，答案在五本里都有一段。

所以现在按**玩法系列**归册：

| 册 | 收什么 | 为什么能合 |
|---|---|---|
| 核心规则书 | 与扩展无关的全部规则 + 49 个本体兵种 + 51 条能力 | 永远相关 |
| 扩展规则（小型） | 只改规则、不带兵种的那批开关 | 每条一两段，本来就是一批 |
| **奇幻扩展** | 奇想·法则 + 骑士团 / 荒兽 / 秘法 / 英雄 | 共用一套机制，四队兵是四种打法 |
| **时代兵备** | 古典 / 中世 / 火药 / 工业 / 现代 | 互不依赖，但放在一起才能横向比 |
| 城郭与物料 | 单包 | 它动的是骨架（资源、主城尺寸），不归任何系列 |
| 季节与气候 | 单包 | 同上 |

游戏里点「规则书」看到的书单也跟着变：这一局开两个奇想包，也只出现**一本**奇幻册，
书名下面写着"已启用：奇想·骑士团、奇想·英雄"。

## 四、悬停与跳转怎么用

兵种表和正文里，带**虚线下划线**的词都是机制：

- **鼠标停上去**：浮出一句说明（"本回合没有移动过时，受到的伤害 −2。站住才硬。"）
- **点一下**：跳到本册末尾的词条表，那一格会高亮
- **键盘 Tab** 也能触发，浮层会跟着焦点走
- **打印 / 禁用 JS**：浮层不出，但链接还在，点着照样能跳到词条——不会出现"点了没反应"

浮层的文字**不是写在链接上的**，而是运行时从词条表里读。这一点值得解释：
最初的做法是给每颗链接带一份 `data-tip="整句说明"`，结果"盾墙"在三十个兵后面
各存了一份同样的句子——正文看着短了，文件里的重复反而更多。现在事实只有一份，
改词条不用回头改三十处引用。

## 五、信息完整性怎么保证

合并最容易犯的错是"悄悄漏掉几个兵"，而漏掉的那几个不会自己喊。所以
`npm run manual` 现在带三道自检，任一不满足**直接失败**：

1. **兵种覆盖**：每行兵种带 `data-unit="<id>"`，生成后把六册的 id 收一遍，
   和配置里的扩展兵种对照。少一个就抛错，并列出是哪一包的哪个兵。
   —— 这次上线第一跑就抓到了两个（城郭与物料的粮仓、采石场），因为它们的表
   走的还是旧的那条渲染路径。
2. **锚点闭合**：每颗 `href="#t-…"` 必须在**同一册内**有落点。跨册锚点在单册
   分发、打印、另存为时都会断，所以每册带自己的词条表，宁可多印几行。
3. **词条不含全量**：合册的词条表只收"本册兵种真的用到"的那几条（时代册 13 条、
   奇幻册 73 条）。全量 51 条能力只在核心册第 13 章出现一次——
   不然合册会退化成第二本核心册。

另外，旧的 11 个分册文件（`manual-pack-fantasy-core.html` 这类）会在生成时
**自动删除**。留着比 404 更糟：玩家按旧书签打开，看到的是一份"少了四个包"的
过时规则书，而且它不会说自己过期了。

## 六、顺手修的三处

1. **第 04 章「完整数值见第 15 节」→ 第 14 节**。兵种全表一直是第 14 章，这个
   指针错位了很久，点了会跳到"引擎与兼容"。
2. **正文里的「破城」「先手」变成可悬停**。这两处以前只写能力名，读者得自己
   翻到第 13 章；现在停一下就有一句。
3. **词条里的数字从配置读**，不手写。溅射比例写成 `CONFIG.splashRatio`
   （现在是 50%），建造距离写成 `CONFIG.buildRange`——词条和代码漂移是这类
   "说明文字"最容易犯的错，能自动读的就别抄。

## 七、自测与闸门

```
tsc --noEmit        干净
test:rules          339 项全过
test:ui             125 项全过（书单用例重写：开两个奇想包只出一本）
build               ✓
manual              6 册 · 兵种 49 · 扩展兵种 135 个已全部入册 · 能力 51 · 扩展 26
```

另外单独跑了一遍"每一颗引用都能弹出说明"：六册共 292 颗，逐颗触发 `mouseover`，
**292 颗都有文字、0 个空浮层、0 个脚本错误**。这一步没写进 `npm test`——
它需要一个真 DOM（jsdom 能跑但没有布局，浮层位置只能验证"不报错"），
放在一次性脚本里跑完就删，不值得为它拖慢每次提交。

## 八、如果你只想记一件事

**规则没变，只是不再把同一句话说二十二遍。** 兵种表回到了它该有的样子：
一行一个兵，能扫、能比；想深究哪个词，停一下或者点一下。
