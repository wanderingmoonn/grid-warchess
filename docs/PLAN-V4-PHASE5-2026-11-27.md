## 2. 阶段 5 要做的事（按顺序）

### 2.1 记忆层：记住"见过的敌人"（最小版）

**要解决的问题**（`S-004`）：撤得太快 → 敌人出视野 → 判"没有敌人" → 转进攻 → 兵又送回去。

**已有的东西**：`V4Memory.unitSeen` 字段**已经存在**，记 `单位id → {type, owner, x, y}`。
但它是从**全图**记的、而且**没有任何读者**——纯影子。所以这不是从零做。

**最小版只改三件事**：

1. **只记视野内**的敌人（用引擎的 `canSeeTile`，和开火同一个判据）；
2. 每条记录加一个**最后看见的手数**；
3. **决定层读它**，但只读一个布尔：**"这块区域最近有没有敌人"**。

**这条红线必须写死**：

> **记忆只能回答"这里最近有没有人"，不能回答"人在哪一格"。**

理由：记忆里的坐标是**旧位置**。如果把它并进 `foeCombat`，`defensible` 会拿旧位置算距离——
敌人可能早走了，也可能换了方向，判断会比现在**更错**。

所以两档不混：
- **当前视野**：精确（位置、血量），用来打仗；
- **记忆**：只用于"警觉"（这块区域近 N 手有过敌人 → 别撤、别判没威胁），**不参与任何距离/血量计算**。

**"多久算过期"不能拍**：用现有数——从那个位置走回我城要几手（`marchTurns`），
走得到的时间内算"还有效"。

**验收**：`S-004` 回绿（8 个兵回到城下）；`S-002` 不出现新的红；39 题其余不动。

### 2.2 「看不见 ≠ 没威胁」：守军名额（`V-1-01` 的正解）

**要解决的问题**：`V-1-01` 里 v4 每手判 `press`，三个守军全出城，敌人来了一个都没打。

**注意这不是"留几个人"的问题**：v4 是**留了人的**（0 伤亡、城没丢），它的问题是
"**看不见敌人就当没威胁，于是守军被抽走**"。留人是结果，不是原因。

**难点：名额从哪来。** 历史上试过"每城固定留 2 个"，被撤掉了（`S-016` 空城里 8 个兵白扣 2 个、
接管题唯一的兵被扣走）。所以不能回到拍数字。

**可用的数（都是现成的，不许新拍）**：
- 城的价值：血 × 代（`upgradedCity` 已有）；
- 丢城的代价：这座城是不是唯一的城 / 是不是产兵主力；
- **不能用的**：当前视野里的敌人（这正是"看不见"时没有的）。

**要定的一件事**：**"没有情报"本身要不要成为一个理由**——即"我看不见，所以我保守一点"。
这句话听起来对，但它是一条**新的原则**，需要用户拍板（阶段 4 的纪律是"每一条判断都要能数"）。

**验收**：`V-1-01` 从红变绿（`foeLost ≥ 1`）；`S-016`（空城）不翻红；`T-1-*`（接管）不翻红。

### 2.3 斥候与关口：预警（**大工程，最后做**）

**人类的做法**：斥候站住地形关口，看到大部队就回来报信，然后提前筹备兵力。

**v4 的现状**：`scout` 这个兵种在 v4 代码里**完全没有出现过**（`grep scout src/core/v4` 零命中）。
它只是个"便宜的战斗兵"（50 金 / 视野 4 / 移动 4 / 攻 14 / 血 26）。

**要拆成四件事，每一件都不小**：

| # | 要做什么 | 现在有什么 | 缺什么 | 难度 |
|---|---|---|---|---|
| ① | **知道去哪看**（关口） | 距离场（`marchTurns`） | "哪些格能看住来路"的可数定义 | 中（要为很多格各算一次视野覆盖，算力是问题） |
| ② | **派谁去** | 采购按每金币战力选 | 一个"侦察"任务类型 | 中（会同时碰采购、编队、让位：斥候站关口会被赶吗） |
| ③ | **看到就报信** | 当前视野里的敌人 | **记忆层（§2.1）** | 低，但依赖 2.1 |
| ④ | **提前筹备** | 决定层能判"守不守得住" | 把记忆里的敌情喂给它 | 中 |

**依赖**：③ 依赖 §2.1，④ 依赖 §2.2。所以**必须排在 2.1 / 2.2 之后**——
在没有记忆、也没有"没情报时别全撤"的情况下先派斥候，只会多送一个兵。

### 2.4 让位第 2、3 步（**低优先，可能永远不做**）

- **第 2 步（入口逐格化）**：把"有人要过"从全局布尔改成逐格的"这一手谁要进这一格"。
- **第 3 步（落点算法）**：让开的人落点 = 自由格 + 真实步数 + **一人一格全局配对**（抄经济配岗），
  "洞"的概念退役。

**这条判据已经失效**——现在全册被拒只剩 80，而且全是废墟重建（属于 §1.3 ①），和让位无关。
剩下的空间：让位 99 人次／232 手，其中空转 73、无目标 72。

**结论**：收益最低，等 §2.3 做完再回头看要不要动。

## 5. 出题的坑（阶段 4 踩的，直接照做）

1. **考"编队行为"的手摆局面，必须在快照里预置编制**：

```json
"aiFocus": { "A": { "v4": { "bands": [
  { "id": "c2#1", "cityId": "c2", "unitIds": ["u3","u4","u5","u6"], "state": "marching", "want": 4 },
  { "id": "c1#1", "cityId": "c1", "unitIds": ["u1","u2"],           "state": "marching", "want": 2 }
] } } }
```

不预置的话，所有兵会被重新编成**一支队**，"逐队判断"就失去意义（`R-1-01` 第一版就是这样）。

2. **判据要能被"什么都不做"证伪**：加一条"至少要打死一个"或"必须打下城"，
   否则空壳也是绿的（`V-1-01` 的 `foeLost ≥ 1` 就是这个作用）。

3. **判据线要先用四颗种子校准**：`V-1-01` 的 `lostUnits` 从 0 调到 2 才让参照稳定
   （v1 有一颗种子会死 2 个）。

## 6. 纪律（承阶段 4，不许松）

1. 任何决策和动作不许游离在三层之外（`V4-CODE-MAP` §0）。
2. 搬位置要 **40 题逐字节一致**；换判据要**逐题归因**。
3. 判据必须能数，**不许打分**。
4. 空壳必须红、参照必须绿；一道题**四颗种子同结论**才算立住。
5. 过程指标不能替代价值判断（空转到 0 但 `S-002` 掉火力，就是反例）。
6. 红了**先归因**：是这次改的那一层，还是别处在迁就旧版本。
7. 打补丁前**先搜计划层/约束层是不是已经做了**（`skip` 那次教训）。
