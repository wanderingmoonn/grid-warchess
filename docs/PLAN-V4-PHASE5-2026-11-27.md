## 2. 阶段 5 要做的事（按顺序）

### 2.1 记忆层：记住"见过的敌人"（最小版）

**要解决的问题**（`S-004`）：撤得太快 → 敌人出视野 → 判"没有敌人" → 转进攻 → 兵又送回去。

**已有的东西**：`V4Memory.unitSeen` 字段**已经存在**，记 `单位id → {type, owner, x, y}`。
但它是从**全图**记的、而且**没有任何读者**——纯影子。所以这不是从零做。

**最小版只改三件事**：

1. **只记视野内**的敌人（用引擎的 `canSeeTile`，和开火同一个判据）；
2. 每条记录加一个**最后看见的手数**；
3. **决定层读它**，但只读一个布尔：**"这块区域最近有没有敌人"**。

**这条红线必须写死**：

> **记忆只能回答"这里最近有没有人"，不能回答"人在哪一格"。**

理由：记忆里的坐标是**旧位置**。如果把它并进 `foeCombat`，`defensible` 会拿旧位置算距离——
敌人可能早走了，也可能换了方向，判断会比现在**更错**。

所以两档不混：
- **当前视野**：精确（位置、血量），用来打仗；
- **记忆**：只用于"警觉"（这块区域近 N 手有过敌人 → 别撤、别判没威胁），**不参与任何距离/血量计算**。

**"多久算过期"不能拍**：用现有数——从那个位置走回我城要几手（`marchTurns`），
走得到的时间内算"还有效"。

**验收**：`S-004` 回绿（8 个兵回到城下）；`S-002` 不出现新的红；39 题其余不动。

**拆成三步做（2026-11-27 20:10 定）**：`2.1a` 只写不读 → `2.1b` 接读者 → `2.1c` 撤 `unitSeen`。
前两步之间必过一道"40 题逐行为一致"，第三步才允许行为变。

### 2.1b 的归因：`S-004` 剩下的红**不是记忆问题**

`S-004` 判据是"10 手内 8 个战斗兵回到城 4 格内 + 伤亡 ≤6"。现在的读数：**6 个 · 伤亡 12**。

- **掉头那一段已经修好**：敌人只是退到"城还能撑几轮"的窗口外一手，守势就多续了两手。
- **剩下的是伤亡**：v4 确实把兵撤回城下了（T8 城 4 格内 10 个），但它**在城下继续对射**，
  对面 20 个四代步枪兵，12 个兵一个不剩（每手死 2~3 个、又补 2 个）。
  人手答案（纯后撤）只损 4 —— 差别不在"撤不撤"，在**回到城下之后还打不打**。
- 所以这条要修的是**守的时候怎么打**（打分层／城防换血），不是信息层。
  阶段 5 不追它；它现在的作用是"守势续期的回归题"。

#### 2.1c ✅ 撤掉全图记录（2026-11-27 21:40 落地）

**为什么迟早要撤**：它是 v4 唯一一处"雾里也知道全图伤亡"的地方 ——
记全图、不带时间，喂给交换账（`exchange` / `exchangeByCity`），
而交换账**被决定层读**（`decide.ts` 的 `lineLedger` 判"卡住才停、亏不停"）。
也就是说：**雾里对面死了一个兵，v4 是知道的**。这正好是阶段 5 要清的东西。

> ⚠️ 文档早先写"`unitSeen` 没有任何读者、纯影子"，**不准确**：
> 它的读者是交换账，交换账的读者是决定层。撤它是行为改动，不是清理死代码。

**落地方式：没有"删掉一个字段"那么干净，是把它拆成三件事**：

| # | 改了什么 | 一句话理由 |
|---|---|---|
| 1 | `unitSeen` 改成**只记我看得见的**（我的人全记、敌人只记视野内），并带"第几手看见的" | 原来 `s.units` 全抄 = 用引擎的全图算账 |
| 2 | "看不见了"的敌人记 `gone: true`（**挂账**） | 它可能只是走出视野；挂账只给预警用，**账上一分不结** |
| 3 | `foeSight`（2.1a 那本）**并回 `unitSeen`** —— 两本是同一件事，不再各记一份 | 一处口径 |

**"看得见"用的还是那一套**（不另发明）：开雾 → `canSeeTile`；没雾/玩家开着全图 → 和玩家一样看得见全图。
这就是阶段 4 定的"**看见什么跟 `s.fog`，能打什么跟 `canSeeTile`**"。

**三个坑（都踩了，都量过）**：

1. **删死记录不能关在"一手只差分一次"那道门后面**。一手里最后一下打死的人，
   是在这次写账**之后**才消失的；门一关，这笔记录要拖到下一手才删 →
   **每一手都挂着一个 1 手前的幽灵** → 判据以为"城门口还有人" → `R-1-01` 翻红。
   **记账要门，改事实不要门。**
2. **"看不见了"不能等它将来看得见再结算**。试过，结果没打仗的那些手也跳出收益
   （对面只是走开了、后来又路过被看见），账本还在替 v4 算它没看见的死亡。所以挂账**永不结算**。
3. **"死"和"走开"没有精确解**，两个极端都量了：
   · "最后一格还看得见"就算死（**现在这条**）：`S-004` 开雾会有幽灵收益（约 45 金/手），误差方向是**高估**；
   · "它这一步能去的格子全在我视野里"才敢算死（严格证明版）：`S-002` 开雾量出 **2000 金**真实击杀、
     账本记 **0 金** —— 太严，等于雾里永远没收益，那条线会被判成"一直亏"，v4 就再也不进攻了。
   取前者，理由：玩家能分清是因为他看着棋子一格一格在动，AI 只有每手快照；只剩一个方向已知的小偏差。

### 2.2 「看不见 ≠ 没威胁」→ **预警线（等时线 × 走廊）**

> **⚠️ 口径定稿（用户 2026-11-27 21:45，两次修正后）**
>
> 1. **不做"每城留 N 个"**。名额是拍数字，答案是**预警半径**：
>    我组织一支守军要几手，敌人这几手能推进多远 —— 那个距离才是我要看住的地方。
> 2. **不用"主力离家几手"当需求**（这是我 21:30 提的，被否掉）：主力越远越要警戒，
>    方向不对——主力位置每手都在变，预警点会跟着乱跳；而且主力远的时候，真正的底牌
>    是**现场组织守军**，不是把它叫回来。
> 3. **预警要作为"编队"存在**（哪怕只有 1 个人），走现有的编队/让位/采购通道。

**整体方案（一句话）**：把"守不守得住"从**名额问题**换成**时间问题** ——
先算我"组织守军要几手"（`T_def`），再画"敌人这几手能推到哪"的等时线，
等时线与"敌城→我城"最短路相交的那一格就是**必须派人盯住的地方**；
盯住它（1 个便宜兵），我就在 `T_def` 手之前知道敌人来了；
盯不住（敌城太近 / 没钱），才退回"就地堆兵"，堆多少也有算式。
**没有一个数字是拍的：全部来自产能、身价、移动力、视野、距离场。**

#### 2.2.1 预警线怎么算（**口径已定，2026-11-27 22:50**）

全部用几何 + 现成的数，不拍系数：

| 量 | 怎么算 | 从哪来 |
|---|---|---|
| **等时线** | `{ p : 敌人从 p 走回我的城 ≤ T_def 手 }` 的边界（**按敌方移动力**算距离场） | 新增一张"从我的城出发、按敌速摊开"的回合场；现有 `turnsFrom` 用的是我方速度 |
| **T_def**（我组织守军要几手） | `(需要的守军身价 − 已在家的守军身价) ÷ (每手产能 × 守军单兵身价)`，向上取整，最小 0 | `makeAt(城)` 已有；身价用 `unitWorth` / `unitWorthOfType` |
| **需要的守军身价** | **镜像估**：对面一只队伍 ≈ 我现在战斗兵的身价合计（"没情报就按对手和我一样快"） | `strength(s, myCombat)` |
| **走廊** | 敌城 → 我城的**最短路**（距离场沿梯度下降取出的那条格链） | `stepsFrom` |
| **预警点** | 走廊上**从敌城往我城走、第一个 `T_def` 手内到城的格**（叫它"交点" `E`），再从 `E` 沿走廊朝敌城方向回退到"`E` 刚好落在视野边缘"的那一格 | 视野半径 `visionOf` |

**三条已定的口径**（2026-11-27 22:50 拍板）：

1. **`T_def` 里算上"已在家的守军"**：人在家就不怕偷袭，`T_def ≈ 0` → 不派眼睛（省兵）。
   只有"家里空着、又补不上人"的时候才需要往远处看。
2. **敌队规模按镜像估**（= 我现在战斗兵的身价合计）。
3. **验收读数 = "敌人第一次进入我视野时，它离我的城还有几手"**，要求 ≥ `T_def`。
   它比"城里站着几个人"更本质，而且现在就能量出起点。

三条推论（方案的价值所在）：

1. **预警可行** → 派 1 个便宜兵站预警点（`scout` 编队，`want: 1`）。敌人进视野就后撤一步
   （不接战），退一步仍能看到来路。
2. **预警不可行**（走廊比 `T_def` 手还短，`E` 落到敌城外面；或者没钱、每手产能 0）→
   **这才是"必须就地堆兵"的唯一正当场合**，堆多少也有数：
   敌人在路上要走的这几手里，我造得出的守军身价 vs 敌队身价。
   → **"留人"不再是一条规则，而是"预警救不了"这个结论的结果。**
3. **多座敌城** → 每条走廊一个预警点，按"缺口手数"排队补兵。

#### 2.2.2.0 c 步的**三档顺序**（用户 2026-11-28 08:20 定，**先攻击，再收缩**）

原计划（我写的）是"预警不可行 → 直接缩减出征规模"，方向是反的。用户的口径：

> **没办法预警，就该尽快进攻**（趁现在能打，把仗打完，别留兵干等）；
> **只有"还是没法快速组建部队进攻"时，才会选择缩减出征规模。**

所以当 `预警不可行`（敌城太近 / 组织不出守军）成立时，按这个顺序问：

| 档 | 问题 | 成立时做什么 | 手上的数（都是现成的） |
|---|---|---|---|
| **① 尽快进攻** | 现在这支部队**打不打得动**？ | 催它出发、催它打（出征规模**不缩**） | `batchMen` 的下限 `killOneNeed`（打死一个守军要几个人）；接火账 `lineLedger` |
| **② 提前拉人** | 家里来不及组织，那**能不能早点开始组织**？ | 提前下单/提前升级（把 `T_def` 压下去），而不是等敌人来了才造 | `makeAt` / `incomeOf` / `eraLadder` |
| **③ 缩减出征规模** | 既打不动、又来不及 | **这时才缩**：出征兵数上限 = 现有战斗兵 − "`T_def` 手内造不出来的那部分" | 上面前两个的差 |

**影子读数（已加，`V4_ALERT_LOG`，只打不判）**：
`收缩[决定] 攻 N / 留 M / 需 K 手`

- `攻 N` = 这一手进攻会派出去的人数（一手内回不了城的战斗兵）；
- `留 M` = 派完之后家里还剩几个；
- `需 K` = 家里组织守军还要几手（`alertNeed`）。

**读法**：`需 K` 大 + `留 M` 接近 0 的手，才是"要收缩"的候选；
但现在还**先看①**——那些手是不是其实打得很顺（`攻 N` 大、账在赚）。先量，不改。

### 2.6 **姿态与目标拆开：行军途中遇到敌人就转身野战**（2026-11-28 11:40 定，讨论完的方案）

#### 2.6.1 问题抽象：一次只有一个 enum，编码了两件事

现在 `SquadOrder` 是 `assemble / march / siege / hold / yield / build / scout`，
**互斥的七个值**。它同时回答两个本来正交的问题：

- **姿态**：现在该干什么（行军 / 交战 / 撤离 / 站岗 / 攻城）
- **目标**：冲谁去（一座城 / 一个具体敌人 / 一格地点 / 没有）

因为塞在同一个值里，**换姿态就必须整个重算任务**；而重算任务的理由只来自战略层
（"打哪座城"），不看路上（"眼前这个敌人要不要现在处理"）。于是出现两个后果：

1. **进攻部队在路上只会攻城**——`march` 姿态下，走到能打城了就去打城，
   路上撞见敌方**进攻部队**时（这在实战里比守城更常见）没有"转身打"这个姿态。
   用户 2026-11-28 原话："更多时候是进攻队伍在路上遇到敌方进攻队伍，开始野战，现在貌似只会攻城。"
2. `V-1-01` 的 0 杀也是这一条的直接后果（长枪射程 1，走过去时敌人总在射程外一格，
   它只会"朝目标走一步"，永远走不进射程）。

#### 2.6.2 拆成两个正交的东西

```
姿态（stance） = march | engage | withdraw | hold | siege | scout
目标（target） = city | unit | cell | none
```

**分工**（承"选择在决定层、可行性在计划层"）：

- **目标**只由**计划层**给（要算钱、算编队缺口、算进度）；
- **姿态**由计划层给初始值，**战术层可以在这一手内临时改一次**
  （因为有视线的只有它：敌人走一步，视野就变）。

姿态不写进 `V4Memory`（不跨手），**一手内一次**——写进记忆就会变成"上一手的姿态"，
而不是"这一手的姿态"，那是 v3 的老病（每个动作重新评估、行为在手与手之间抖）。

#### 2.6.3 遭遇即交战的判据（**用户 2026-11-28 定稿**）

> **行军途中遇到敌人就迎上去打，除非敌人真的非常多。**

所以 **不要**"伤害 ≥ 目标半血"那个门槛——用户明确否掉：
"很可能遇到小兵是主力的一角，如果不打就会把敌方主力放过去坏事情。"
**放过一个探路的小兵，等于放整支主力过关。** 这一条要写进代码注释，防止以后有人"优化"回来。

三条二值条件（都不打分）：

1. **够得着**：这一手存在一格，站上去就进射程（用现成的 `approachStep`，
   它只回答"有没有这一格"，不比较哪一格更好）；
2. **不散队**：偏出去的一步落点，仍在"这支队原本的路线带"上（离最短路 ≤1 格）。
   不加这条，每个兵会朝不同敌人各偏一步，队形散掉、到货变慢（`S-002` 那类长线会吃亏）；
3. **不是送死**：**敌人"真的非常多"**——用户留了这个例外，但没给数字。
   **这条不许拍系数**，用现成的数：
   `world.defensible(我的城)` 那套口径搬过来（守军身价 + 产能 vs 来犯身价），
   或者更直接：**敌方在场身价 > 我方这支队身价 × 2**（`strength()` 已有）。
   具体取哪个在 2.6-0 里量，**先只打日志**，看实战里这道门会不会真的触发。

#### 2.6.4 三个必须保住的反例（踩过的，别踩回去）

#### 2.6.4e 排查：`V-1-01` 为什么打了也不赢（2026-11-28 14:00）

**先说结论**：这题的红**不是"城被打、进攻队不回"**——那个假设不成立（v4 的兵本来就往城里走）。

**① v1/v3 是怎么过的（用户要求对照）**：

**③ 一个真回归，也只能记成已知问题（`S-002`）**：

试过两条门，都撤回（都没有救回 `V-1-01`，却都让 `S-002` 继续掉）：

- "离城 >1 手才允许偏步"；

**为什么退回原判据**：`V-1-01` 的兵站在城圈上，条件 2（不踩必须空的格）本来就该拦住它——

属于决定层）。所以 b 步维持原判据，`S-002` 的红**登记为已知回归**，先不动。

**下一步（写给下一个人）**：`S-002` 和 `V-1-01` 指向同一个东西——

3. **但 v4 终局兵力是 168 : 2** —— 它不是"打不过"，是**"靠造兵把人堆死"**：
   80 手造了 147 个兵。这更像是"经济 + 数量"赢的，不是"战术"赢的。

##### 合起来看：三个读数推翻了我上一条的结论

我上一条说"问题在三层之间的带宽"。读数 2 说带宽不窄（57% 的手有 3 种任务），
读数 1 说决定层基本没错。真正的形状是：

> **v4 的信息不缺、决定也不全错；它缺的是"打完这一拳之后怎么办"。**
> 攻击占 7% 而动作数最多 —— 它把绝大多数动作花在**走位、让位、排队**上，
> 而真正改变胜负的那几下（打死人、打下城）很少。
> 于是它只能用"造更多的兵"来弥补（147 个），一旦地图大到产能撑不起（24×24/3 代），
> 这套就崩了 —— 那正是"实战低"的来源。

**下一步建议（待用户拍板）**：先量 24×24 / 3 代 上的三个读数（尤其是"攻击占比"），
确认崩的是不是"造兵补战术"这条路。如果是，接下来该动的是**进攻效率**
（为什么到位了打不出、展开不了），而不是信息层。

#### 2.6.5 施工计划（四步，每步都能单独验收）

| 步 | 做什么 | 改哪里 | 验收 |
|---|---|---|---|
| **0** 读数 | 先量"现在路上遇到敌人，有几手是**进了射程却没打**"——没有这个数，改完无法判断好坏 | `V4_ALERT_LOG` 加一行 `遭遇[姿态] 够得着 N / 打了 M / 放过 K`（只打日志） | 40 题矩阵逐行不变；快检档 12×12 / 20 局能打出分布 |
| **a** 姿态拆出来 | 把 `order` 的"姿态"那一半独立出来，**行为一字不变** | `types.ts`：`Squad.stance`（默认由 `order` 推出来）；`tactics.ts`：分支改读 `stance`，`order` 只在"目标是谁"的地方还用 | **逐题一致**（这是纯搬家）；40 题 + 12 局逐手相同 |
| **b** 遭遇即交战 | 补上"转身打"这个姿态 | `tactics.ts`：`stance==='march'` 且满足 2.6.3 三条 → 这一手按 `approachStep` 偏一步去打；打完下一手自动回 `march`（姿态不跨手，天然"短暂"） | `V-1-01` 的 `foeLost ≥ 1` **第一次变绿**；`S-004` / `X-1-01` / `S-017` / `R-1-01` 一律不许掉 |
| **c** 敌人非常多 | 那条例外真的生效 | `tactics.ts` 或 `constrain.ts`：2.6.3 第 3 条（数值在 0 步量出来之后定） | 快检档不出现"以卵击石"（我方整队被吃掉的局数不上升）；`S-004` 不掉 |

#### 2.6.6 验收与风险

**验收**（每步都要过）：`tsc` 干净；40 题矩阵除预期变化外逐行一致；
`S-004`（撤退）、`X-1-01`（合击）、`S-017`（清场）、`R-1-01`（撤攻）**一次都不许掉**；
快检档 20 局（12×12 / 1 代 / 160 手，约 7 分钟）。

**风险**：

- **偏一步会拖慢到货**（`S-002` 那类长线）→ 靠"路线带 ≤1 格"压住，读数上看 `S-001/S-002` 的手数有没有变长；
- **`engage` 被当成"永远开着的战术模式"**（v1/v3 的死法）→ 姿态只在**这一手**有效，不写记忆；
- **第 3 条门槛被拍成数字**（"敌人 > 8 个就不打"）→ 红线：只许用 `strength()` / `defensible()` 这类现成口径。

**两条红线**：
1. 姿态**不许**写进 `V4Memory`（写进去就变成"上一手的姿态"，会抖）；
2. **不许**回到"每步打分挑落点"（那是 v3 的死法）。偏步只有"有/没有"两档。

## 5. 出题的坑（阶段 4 踩的，直接照做）

1. **考"编队行为"的手摆局面，必须在快照里预置编制**：

```json
"aiFocus": { "A": { "v4": { "bands": [
  { "id": "c2#1", "cityId": "c2", "unitIds": ["u3","u4","u5","u6"], "state": "marching", "want": 4 },
  { "id": "c1#1", "cityId": "c1", "unitIds": ["u1","u2"],           "state": "marching", "want": 2 }
] } } }
```

不预置的话，所有兵会被重新编成**一支队**，"逐队判断"就失去意义（`R-1-01` 第一版就是这样）。

2. **判据要能被"什么都不做"证伪**：加一条"至少要打死一个"或"必须打下城"，
   否则空壳也是绿的（`V-1-01` 的 `foeLost ≥ 1` 就是这个作用）。

3. **判据线要先用四颗种子校准**：`V-1-01` 的 `lostUnits` 从 0 调到 2 才让参照稳定
   （v1 有一颗种子会死 2 个）。

## 6. 纪律（承阶段 4，不许松）

1. 任何决策和动作不许游离在三层之外（`V4-CODE-MAP` §0）。
2. 搬位置要 **40 题逐字节一致**；换判据要**逐题归因**。
3. 判据必须能数，**不许打分**。
4. 空壳必须红、参照必须绿；一道题**四颗种子同结论**才算立住。
5. 过程指标不能替代价值判断（空转到 0 但 `S-002` 掉火力，就是反例）。
6. 红了**先归因**：是这次改的那一层，还是别处在迁就旧版本。
7. 打补丁前**先搜计划层/约束层是不是已经做了**（`skip` 那次教训）。
