# v4 代码地图：每个文件管什么

> 这份是"读代码前先看"的地图。结构不对的时候，先回来对一遍这里说的是不是还是那样。
> 计划本身见 `PLAN-V4-2026-11-23.md`；这里只讲**代码分成哪几块、每块为什么存在**。

```
src/core/v4/
├── world.ts      服务层：算一次，全上层读（阶段 1a）
├── types.ts      三层的"数据契约"：每层准输出什么
├── decide.ts     决定层：做什么 + 期限 + 理由
├── constrain.ts  约束层：哪几格必须空、谁归哪队、打哪座城
├── tactics.ts    打分层：产出一个引擎认的动作
└── ai-v4.ts      入口：把三层接起来，对外的签名和 v1/v3 一样
```

调用顺序是单向的，没有回调、没有共享可变状态：

```
GameState ──► buildWorld ──► decide ──► constrain ──► actFor ──► Action
              (数)          (决定)      (约束)        (动作)
```

## 1. `world.ts` —— 服务层（这一层最先做，也最好验收）

**它回答的全是"数"，不做选择。**

| 它提供 | 为什么必须只在这里算 |
|---|---|
| `marchTurns(a, b)` | 从 A 到 B 要几**回合**（不是几格：森林两回合、平原一回合）。v3 每个模块自己算一张距离图，结果同一格在不同模块里能算出不同的回合数 |
| `roleOf(city)` | 城的角色（home / threatened / front / safe）。v3 有**三个口径**，谁也说不清"前线"到底指哪座城 |
| `keepClear` | 产兵格。造兵要落在这儿，所以它们必须空着——这是约束层的原料 |
| `affordableCombat(city, gold)` | 这城现在买得起什么兵 |

**为什么单独成关**：它输出的是数，能和引擎真值对拍；上层输出的是选择，只能看结果。
先把最容易验收的一层打牢，前两周才不会陷入"感觉变好了但说不清"。

**已知取舍**：`marchTurns` 用的是"层数 BFS ÷ 移动力"，把森林的额外消耗拍平了。
真值要按地形代价算 Dijkstra——等它开始出错再换，现在不值得。

## 2. `types.ts` —— 数据契约（这个文件没有算法）

v3 的病根是"三层都能往同一张分数表里加一项"。所以 v4 干脆把**每层准交什么**写成类型：

| 层 | 只能交 | 交不了的东西 |
|---|---|---|
| 决定层 | `Decision`（做什么 / 管到第几手 / 为什么） | 交不出"进攻意愿 +40" |
| 约束层 | `Constraints`（keepClear / squads / forbid） | 交不出"让位意愿 +50" |
| 打分层 | `Action`（引擎认的那一个动作） | 交不出"这个兵值 12 金"以外的价值判断 |

`Decision.untilTurn` 是硬要求：**没有期限的决定会悄悄变成常数**，然后没人记得它是谁写的。

---

## 3. `decide.ts` —— 决定层

三条规则，很粗，故意的：

1. 自家城被压着、兵力不占优 → **守**（把外面的兵收回城下）
2. 我明显更强 → **推**最近的敌城
3. 其它 → **发展**

"更强"用的是**身价**（atk + hp + 射程×4，按血量比例打折），不是个数——一个四代兵不等于一个民兵。

**为什么只有三条**：细则要靠题库一题一题长。v3 那六千行系数不抄，那些系数正是"改一处不知动到哪"的来源。

---

## 4. `constrain.ts` —— 约束层（v4 的关键投资）

把"要做什么"翻译成"哪几格必须空、谁归哪队、打哪座城"。

三条铁律：

- **不把自己人排到 `keepClear` 上**（那是"必须空"的格子，排上去自相矛盾）；
- **每个兵最多属于一支队**（v3 的一兵多队让两套指令互相覆盖）；
- **守城的兵不出去**（`hold` 是约束，不是倾向）。

**为什么这层排在打分层之前**：直觉是"打分才是现成资产，先做它"。但 v3 每次翻车都在
**分数表达不了的约束**上——桥头要让开、产兵格要让开。这些"必须"塞进分数里，
就会和"别送死"互相打折，最后谁也不让。

`keepClear` 就是这条思想的实体：打分层发现自家单位站在上面，**第一件事就是挪开，不许权衡**。

## 4.5 关键格与让位搬迁（阶段 2 的核心）

### 什么算"关键格"

判据是**功能**，不是几何：**占住它会让某个动作发生不了**。三类：

| 类 | 条件 | 占了会怎样 | 来源 |
|---|---|---|---|
| `spawn` | 产兵格被自家单位占住 | 这座城**造不出兵** | v3 的 `buildSlotPlan` |
| `exit` | 城格全被战斗单位占、外圈又被经济兵占满 | 军队**出不了城** | v3（`probe:combat-trap` 逼出来的） |
| 桥头 | 邻格有 ≥2 片水的桥面格 | 过河的唯一通道被堵死 | v4 新加（S-005） |

**"桥点周围 2 格"那种软区域不进硬约束**——v3 自己也标了它是"最好别站"，
按计划 4.3，软的东西不许伪装成硬约束。

### 让位为什么要"计划"而不是"判断"

关键格后面常常排着一串自己人。让一个人走开没用，整条链要一起挪一格：

```
关键格  自己人 自己人 自己人  →  空格（洞）
```

v3 用 `buildYieldPlan` 解决：**多源 BFS**，种子是"所有空格"，得到每格到最近洞的距离，
再沿 `prev` 指针把链上的人逐个朝洞挪。**一回合能清多格**（单链版只能清一格）。

v4 抄思路、不抄代码：

- 结果放进**约束层**（`Constraints.yieldMoves`），打分层只执行——v3 把它和 `yieldPlan`
  的分数混在一起，于是"让开"和"别送死"互相打折，最后谁也不让；
- **推进/攻城的兵不算挡路**：它们正在过桥，有理由待在那儿；把让位也对它们生效，
  过桥的兵会被自己的规则赶回去，在桥上来回横跳。

### 一个反直觉的坑

关键格的语义是**"不许停"，不是"不许过"**。
早期把 `keepClear` 当墙（`stepToward` 跳过这些格），结果桥头一进 `keepClear`，
**全军过不了河**（S-005 从过河 3 个掉到 0）。现在允许踩，"别停"由搬迁计划负责。

## 5. `tactics.ts` —— 打分层（第一版故意笨）

一个单位一步，优先级是**硬的**，不是分数：

| 顺序 | 条件 | 动作 |
|---|---|---|
| ① | 站在"必须空"的格子上 | 让开 |
| ② | 任务叫我去打城，且引擎说够得着 | `SIEGE` |
| ③ | 引擎说能打到某个敌人 | `ATTACK` |
| ④ | 有任务、没到目标 | `MOVE` |
| ⑤ | 没任务 | 什么都不做（交 null） |

### 两个坑（都写在代码注释里了）

**坑一：② 必须排在 ③ 前面。**
一开始"能打就打"排在前面，结果 S-000 上 30 手打掉 **0 城血**——敌人一直站在城格上，
永远有目标可打，永远轮不到攻城。**约束优先于战术自保**：约束层说了去打这座城，到了就打城。

**坑二：能打谁、能不能攻城，一律问引擎。**
我自己按切比雪夫距离判射程，而引擎按 `strikeDistance`（含高度差、空中 +1）算，
于是每回合都提一个必被拒的攻击（"目标超出射程"），30 手一次没打出去。
现在改成 `attackableTargets()` / `siegeTargets()`——**一份真相，别自己再算一遍**。

## 6. `ai-v4.ts` —— 入口

对外的签名和 v1/v3 完全一样（`aiNextAction(s, budget, rejected)`），所以游戏、判分器、
跑批脚本都能直接换，不用改调用方。

它只干一件额外的事：**按回合缓存**。

`aiNextAction` 是**一个动作**调一次。如果每调一次都重建 World、重做决定，那就是 v3 的老毛病
（每步都在重新评估，行为在动作之间抖动）。所以按"回合"缓存，只有局面真变了
（回合号 / 单位数 / 金币 / 城数）才重建。

### 第三个坑：造兵必须有上限

不设上限时，200 金会被一口气换成 8 个民兵，而动作数是有预算的——钱花完了这一步也走不动了，
最后 0 城伤、一兵未动。上限语义是"这回合补两个人"，不是"这回合把钱花光"。

### 第四个坑：新兵会堵住产兵格

新兵出生就在产兵格上，而且它的行动已经用掉了。① 那一步如果只看"站在 keepClear 上"，
就会一直给它派"让开"，然后被引擎反复拒（实测每回合空烧十几次）。
**跳过本回合已经动过的单位**，并且**城格不算 keepClear**（新兵本来就生在城里）。

## 7. 在游戏里看它想什么（右下角面板）

`src/ui/v4-hud.ts` + `main.ts` 的两个 URL 开关：

| 地址 | 效果 |
|---|---|
| `?ai=v4` | 这一局的 AI 换成 v4（压过"高级 = v3"的档位映射） |
| `?debug=v4` | 右下角出面板（不影响用哪个内核） |
| 两个一起 | 边打边看 v4 的三层输出 |

面板里有三块：

1. **决定**：做什么（推/守/发展）、管到第几手、理由原文；
2. **队伍**：每支队的任务和人数（`main 推进 10`）；
3. **迷你地图**：一格一方块。我方战斗青、我方经济琥珀、敌方红、敌城深红、
   **"必须空"的格子橙色空心框**（这是最该被看见的——约束在哪）。

面板是**只读**的：关掉它行为必须一模一样。它出错的代价只是"看不见"，所以面板内部
`try/catch`，出错就在面板上写一行字，不往对局里抛。

按回合缓存：`buildWorld + decide + constrain` 不便宜，而 render 每帧都跑，
所以只有「回合号 / 当前方 / 单位数 / 金币」变了才重建。

## 8.5 试过但失败的：编队级"算账"（2026-11-24，已回滚）

想给编队加一条"这仗值不值得打"。三次写法，三次把绿的题弄红：

| 写法 | 结果 | 死因 |
|---|---|---|
| 预计损失 = 能开火的敌人 × 攻击 × 还要走几回合；`剩余血量 ≥ 守军血量` 才打 | S-000 / S-005 / S-011 **一起变红** | 把损失估高一个量级：假设敌人每回合都开火、且不会被打死 → 结论永远是"打不了" |
| 同上，但只数"同时能打到前沿的敌人" | 仍然全红 | 换了个口径，还是同一个假设 |
| 卡住 3 手就收拢重整 | 锁死在退守 | **没有出口**：退回去 → 离城更远 → 更算"没推进" → 继续退 |

**根因不是实现细节，是缺一样东西：目标价值。**

人的判断是"城伤 45 值得折 20 条命"——人手上有这条判据。
AI 不知道"45"，所以任何"损失 vs 收益"的规则，其中"收益"那一侧只能拍一个数，
而这个数会变成下一个要调的旋钮（v3 的老路）。

**结论：先把"牙齿"装上（打分层能打穿），再回来算账。**
现在的 v4 打不动，任何成本收益分析都会得出"别打"——那不是判断力，是没能力。

## 8.6 试过但失败的：集火按"威胁"排序（2026-11-24，已回滚）

现在的集火口径是"能打死的挑血最少的，打不死的挑伤害/血量最高的"。
试过换成"按威胁排"（威胁 = 它的攻击 × 它能打到我几个），两种写法都失败：

| 写法 | 结果 |
|---|---|
| `威胁 × min(1, 伤害/血量)` 一个连乘式 | **S-001 四种子全红**，S-002 纹丝不动 |
| 分两档：能打死的按威胁挑，打不死的按"削得最狠"挑 | 仍全红 |

**S-001（该赢必赢）是最灵的探针**：任何让"打谁"变聪明的改动，只要把兵引向
一个够不着的目标，这题立刻红。

**教训**：两个量乘起来看着漂亮，实际把"先打死"和"先打疼"两个意图搅在一起。
现在的"挑血最少的"虽然笨，但它有个好性质——**目标和当下能打到的位置一致**。

## 8.7 S-002 的"压不到城下"：两次尝试都失败（2026-11-24）

先量清楚：拿人手答案（55 城伤 / 22 损失）和 v4 逐手对照。

| 手 | 人（最近距离 / 城血） | v4（最近 / 城血 / 能打到的单位数） |
|---|---|---|
| 1 | 6 / 99 | 4 / 99 / 0 |
| 2 | **3** / 99 | 4 / 99 / 0 |
| 3 | **2** / 99 | 4 / 99 / 1 |
| 6 | 2 / **62** | 5 / 99 / 0 |
| 7 | **1** / **1** | 6 / 99 / 2 |

**不是"打不过"，是"挤不进去"**：30 个兵排成一列纵队，前排被敌人挡住、后排被自己人挡住，
火枪永远停在 8 格外——每回合只有 1~2 个兵够得着，人的同一项是 5+。

两次尝试，都失败：

| 写法 | 结果 |
|---|---|
| **队形闸门**：比队伍中位距离领先 >1 格就等 | 自我强化——后排远 → 中位远 → 前排等 → 没人靠近。中位距离连续 7 手停在 8~9，比改之前更差 |
| **横向绕行**：距离不变但欧氏更近的格也允许走 | S-002 只从"打 3 次"变"打 4 次"，而 **S-005 过河 4→0 变红**，净负 |

**结论**：单列队形的微调救不了。要的是**分路**——把 30 人拆成 2~3 支，各走一条走廊。
那是约束层的事（谁走哪条路 = 约束），不是打分层能解决的。

## 8.8 分路与占用声明：也失败了（2026-11-24，已回滚）

按"人下意识会分左中右三路"的直觉做了两件事：

| 机制 | 做法 | 结果 |
|---|---|---|
| **分路** | 沿"队伍质心→城"的法向把成员排序、均分三组，各给一个城边引导点 | S-002 仍是 0 城伤；且 S-000 / S-005 / S-011 **三题一起红** |
| **占用声明** | 每回合记下"这格已经有人要去了"，后来的兵不许抢 | 修掉了"两个兵提同一个目标格"（实测 u1、u2 都提 (2,5)），但成绩无变化 |

**为什么失败**：两者都在改**局部走位**，而 S-002 的差距是**整体的**——
30 个兵的中位距离连续 6 手停在 8~9 格，根本没在推进，分不分路都一样。
人从第 1 手就是整体压上，第 2 手到 3 格、第 3 手到 2 格。

**下一步该看的不是"路怎么走"，而是"为什么整队不往前"**：
每回合能打到敌人的单位是 0~2 个，而人有 5+。要么是射程内没人（位置问题），
要么是**动作预算被别的事吃掉了**（造兵、经济兵、让位）。这个还没量。

## 8.9 S-002 到底卡在哪：量出来的结论（2026-11-24）

三次猜测（预算、采购、队形）都被数据否掉，最后量到了真东西。

| 假设 | 量法 | 结果 |
|---|---|---|
| **动作预算不够** | 每回合用了几步 / 上限多少 | 用 **22~28 步**，上限 50；`aiStepCap`（30 兵）= **206**。AI 自己收手 → **不是配额** |
| **兵没在动** | 每回合逐单位位移 | 21~24 个兵每回合确实挪 **1~2 格** → **动了** |
| **造兵稀释队伍** | 每回合 RECRUIT 数 | v4 **2 个/回合**（7 手 14 个），人 **0 个**。关掉造兵后：S-002 不变、**S-005 变红** → 不是根因 |
| **队形/路线** | 分路、横向绕行、队形闸门、占用声明 | 四种全失败（见 8.7 / 8.8） |

**真正的数据**：3 手之后，大部分单位还在西南角（(1,8)、(3,9)、(4,10)），
只有 3 个兵（u20/u21/u23）摸到中部，能打到 1~2 个目标。

**结论：拥堵，而且"每回合挪 1~2 格"是互挤/横移，不是推进。**
前排被 12 个步枪兵挡住（进不去），后排被自己人挡住（过不去），
净位移接近 0。人的解法是**第 1 手就横向展开**——但从正面看，那只是"往两边散"，
在桥/窄道上做同样的事会掉进水里（我之前试过，S-005 就是这么红的）。

**下一步的方向：横向展开要看地形宽度。**
开阔地才展开，窄道保持单列。这需要先算"这一格朝目标方向的走廊有多宽"——
一条几何查询，属于服务层（`world`），不属于打分层。

## 8.10 展开宽度（地形约束）已实现，但真凶是"人墙"（2026-11-24）

按用户意见把展开宽度做成**约束**（不是打分）：

- `world.corridorWidth(p, toward)`：横向能并排站几格（桥=1，开阔地 8~9）；
- `planLanes`：宽 ≥5 三路、≥3 两路、**窄道退回单列**；引导点是滚动航点（前沿+3格）。
- 结果：**没有回退**（S-005 仍是 4、S-000/S-011 都绿），但 S-002 仍然 0 城伤。

**然后量到了最后一个数**：从开局到第 5 手，单个兵只前进了 **3~4 格**——

```

u16 (1,10) → (4,8)   5 手 3 格
u20 (5,10) → (7,7)   5 手 3 格
```

火枪移动力是 **2**，也就是每手该走 2 格。实际只有 **0.6 格/手**。

30 个兵挤成一坨，前排挡的不只是敌人，还有后排的路。

**下一步的方向**：分排行动——前排先走开（走满 2 格），后排再补位。

而后排的 `stepToward` 需要知道"这一手哪些格会被前面的人腾出来"。

## 8.11 人墙破了：同距离选"更正对目标"的格（2026-11-24）

## 8.13 距离口径：曼哈顿 / 欧氏 / 按格 BFS（2026-11-24）

三层口径，现在各归各位：

| 用途 | 口径 | 在哪 |
|---|---|---|
| 规则判定（`distToCity` 等） | **曼哈顿** | 引擎 |
| 视野 | **欧氏**（历史 bug，不改） | 引擎 |

## 8.18 经济链路：位置先于兵种（2026-11-24）

v4 原来只有一个采购入口 `affordableCombat`——**它根本不造经济兵**。补了三段：

| 层 | 做了什么 |
|---|---|
| 服务层 | `world.econPost()`：把所有"可造经济兵 × 我方城附近空闲格"算一遍产出，返回 `(类型, 格子, 产值)` |
| 约束层 | 没有经济编制，用 econPost 的地形事实代替（"先有位置再造人"） |
| 打分层 | `recruitEcon()`：听 econPost 的；`expand` 或看不见敌人时先造经济，其余先造战力 |

**为什么"位置先于兵种"**：经济兵的价值全在脚下那一格。所以选型不是比单价，

而 `keepClear` 里混着**城格**——于是城边那一圈永远不许站。
S-015 那 2 格森林正好贴城，经济兵走不上去（三个伐木工站平原产 3）。
现在"四周不许站"只对**桥**成立。

**还没好**：S-015 只到 19。实测经济兵从城里出来往**北**走（平原 3），
不去**西**边一格的森林（12）。原因未定位（怀疑与城格的出城规则有关），留待下一步。

## 8.20 经济岗位进约束层（2026-11-24）

用户问："两个约束撞车谁赢？让伐木工去森林是约束层还是打分层？"

**答案（改之前）**：`actFor` 是**固定优先级短路**，没有协商——`① 让位` 排在 `①.2 经济兵` 前面，
**让位赢**。而"去森林"是 `bestYieldStep` **每步重算的打分层结果**，不是约束层指令。
所以：让位把兵推走 → 落点是多源 BFS 的任意空格（北边先扫到就往北）→
下一手它在北边平原上重新贪心 → **再也想不起森林**。

**改法**：给经济兵一个**岗位**（`Constraints.econPosts`）：

| 层 | 职责 |
|---|---|
| 约束层 | 每手分配岗位：已在自己高产格上的不动（迟滞）；其余的**按这个兵种在这格的产出**认领 |
| 打分层 | 只负责"朝岗位走"；让位时也**朝岗位绕**，而不是随机撤 |

**顺带查清一条硬约束**：`keepClear` 是"城 2×2 + 外一圈"，外圈**是军队出城的通道**。
试过只保城格（好让经济兵吃掉城边地形）——S-001（必赢题）当场从"胜"变"未分胜负"，
兵挤在城墙外主力出不来。**所以城边的高产地吃不到，要吃得改地图，不是改 keepClear。**

**效果**：S-006 经济 94 → **100**；S-015 19 → **25**（判据 44，仍红）。
S-015 的森林原来 2 格全在城圈内，已补 2 格到圈外（人类答案那 2 格没动，成绩仍 52）。

## 8.21 认领表：S-015 转绿，代价是五个坑（2026-11-24）

**改法**（和 8.20 的"岗位"是同一件事做到位）：

| 层 | 交什么 |
|---|---|
| 服务层 | `world.econSpots()`：城附近所有能站的格，一格一条 `{兵种, 产出, 走过去几回合, 造价}`。**兵种是格子的属性**（森林→伐木工、丘陵→牧民、平原→农民），所以"5 个伐木工抢 2 格森林"根本表达不出来 |
| 约束层 | `planEconPosts()`：一人一格，**按出生序配**——先出生的走远岗、后出生的拿近岗（见下面"配岗"一节）；再交出 `Constraints.econNext` = 下一个该造谁 |
| 打分层 | 只照做。`recruitEcon` 不再比价/比产出；`bestYieldStep` 只朝岗位走，**本地贪心整段删除** |

**配岗：老的挑远的，新的拿近的**（用户 2026-11-24 看回放时纠正，第一版是错的）

第一版写成"谁现在产得少谁先挑最好的岗"，结果就是用户说的那个必须避免的行为：
**新兵出生在城里，近岗永远离它最近 → 近处被新兵拿走，老兵被挤去远岗**（或者新兵自己走远路）。

人手答案的走法在 `exams/S-015/action.json` 里能直接看出来：

```
第 3 手  u4→(5,7)  u2→(5,6)  u3→(9,6)
第 5 手  u3→(9,7)  u5→(8,6)
第 7 手  u3→(9,8)  u5→(9,7)  u7→(9,6)  u6→(8,6)
```

u3 是第 1 手造的，它一路往东挪（9,6 → 9,7 → 9,8 → 9,9），**每一步都在把自己刚站的那格
让给后来的人**。所以规则是：

- 同兵种的岗先取**最近的 N 个**（N = 这个兵种的人数）——同产出的岗没有理由走远路；
- 这 N 个里**最远的给最老的**（出生序在 `V4Memory.econSince` 里，引擎不记这个）；
- 下一个没分出去的（也就是最近的那个）留给新兵 → `econNext`。

为什么目标不是"当前产出最大"：同产出的岗互换是等价的（总产不变），
但如果让新兵走远路，它剩余回合少，走到一半就到期了，这一手纯亏；
老兵剩余回合多，走远路"摊得开"。所以配对要摊平的是**到岗回合**，不是产出。

只取最近的 N 个这一步很关键：只有一个牧民时，不截断它会拿到全图最远的丘陵
（实测：一个人走 6 手，产量 0）。

**结果**：S-015 经济 25 → **52**（= 人手答案，线 44）。全套 8 绿 2 红（S-012/S-013），
S-000/S-001/S-002/S-005/S-009/S-011 都没动。S-006 100 → 90（仍绿）。
长局（20×20、120 手、seed 1401）：**经济 8 → 77**（对手 51），第 21 手就反超了。

**五个坑（都是这次实测出来的，改之前都没料到）**：

1. **`actFor` 的让位分支排在走位前面**：经济兵站在城圈（也是关键格）上时被判"该让开"，
   落点是多源 BFS 的随机空格 → 被甩到东边，整局回不来。**经济兵走位必须排第一。**
2. **"不许踩关键格"把兵卡死**：城圈全是关键格，经济兵从城里出来一步都迈不出去
   （6 个兵全冻在城墙边）。8.4 早就写过一遍：关键格是"不许停"，不是"不许过"。
3. **岗位不分兵种 → 牧民抢森林**：分配时用"这一格最好的兵种产出"（森林 12 是伐木工的数），
   牧民就搬进森林、伐木工被挤到平原。**岗位必须带兵种，同名才许认领。**
4. **"走过去几回合"按城算，不按人算**：S-006 六个兵都远离城，拿城当起点把近在眼前的岗算成 5~6 手
   → 净收益全负 → 一个都不挪（总产 27）。改成按"他现在在哪"跑一次走步表。
5. **认领表把"自家经济兵站着的格"也排掉了**：兵一站上自己的岗，那格就从表里消失 →
   配对整体错位 → 两个伐木工在 (4,6)/(4,7) 之间每手互换，总产卡在 39。
   现在只排除敌人、以及自家**战斗兵**占的格。

**还踩了一脚"改一处动两题"**：为了让岗表不塌，一开始把 `decide` 的 `untilTurn` 改成
"沿用即续期"，结果 S-000 从"19 手赢"变"未分胜负"（战斗节奏被改了）。
最后改成**只导出一个 `DECIDE_HORIZON` 常数**给岗表用，不碰决定层的行为。

**还没好**：S-006 从 100 掉到 89。疑似因为经济兵不再"见敌就跑"（本地贪心整段删掉了，
包括逃跑）。但 8.14 量过：逃跑的三种写法都不如不跑，所以先记账，不动。

## 8.22 走位三个坑：驱赶、顺序、直线距离（2026-11-24 晚）

用户看回放/实局截图提了三件事，都成立：

**① 驱赶要"按需"，不能"按位置"。** 原来只要站在城圈（城格 + 外圈）上就赶，
于是经济兵本来正往岗位走（方向就是出城），也被甩向"最近的空格"——大概率反方向。
一步能办两件事，被拆成两步、而且第二步是错的（伐木工进林又被甩出来）。

现在判据是"**这一手真有人要用这格**"：

| 需求 | 赶哪些格 | 什么时候算有需求 |
|---|---|---|
| 产兵口 | **只有城格**（引擎的产兵落点就是 `cityTiles`，外圈不是） | 有城买得起至少一个兵（战斗或经济） |
| 出门通道 | 外圈 + 桥头 | 有队伍**有兵**且任务是收拢/推进/攻城 |

S-015 这种"一条人烟"的题里没有队伍，于是外圈一律不赶——牧民在城边站着也不会被赶。

**② 行动顺序要"前面的先走"。** 排成一列时，只有前面的人先挪开，后面的人才看得到"更近的格"。
原来按单位建立顺序走（老兵先动），排的是"谁老"不是"谁在前面"，前排不动后排整手卡死。
现在每调一次动作都按**当下**位置重排：离自己岗位最近的先走。

**③ 直线距离会把兵锁死，绕路的那一步必须允许。** 实测长局 u11 在地图角落 (19,0)，
去西边岗位必须先往南绕一格——那一步"离目标更远"，规则不许走，它 9 个回合一动不动。
改成用**从岗位出发的真实步数图**挑下一步（`world.stepsFrom(post)`）；
绕路的那一步在图上也是"更近"。这一条同时解决了用户截图里"最后一个牧民死活进不去"。

**④ 配岗要按"最近的城"分组。** 只按兵种分会把 A 城的岗派给 B 城出生的兵——
实测长局两个牧民的岗在 **30 格外**，走一辈子到不了。现在分组键 = 最近城 + 兵种。

**结果**：S-015 仍 **52**（= 人手答案）；S-006 90 → **86**（仍绿）；S-000 仍 19 手赢；
长局 20×20 跑 49 手，**未到位的经济兵从 7 个降到 1 个**，没有"连着 5 手以上不动"的兵。
S-012 敌损 2 → 1（本来就红，记一笔）。

### 9.1 S-013 分兵太晚（队列第 2）

**实测（判分器，15 手）**：`noCityLost = 1/2`，但 `foeLost 0` / `lostUnits 0`——
**全程没有一次交战**，丢城是"没人守"而不是"打输了"。探针第 1 手：

```
决定：expand（身价 600 : 750）
队伍：main assemble 8 人 @(3,4)
城角色：c1 safe（离敌城 9 回合）· c2 safe（离敌城 10 回合）
```

**根因（两份口径，v3 的老病）**：

- `world.roleOf` 只看 `distToFoeCity`（敌**城**的距离），**完全不看敌军在哪** →
  两座城都是 `safe` → 不派守军、不触发 `planMains`；
- 约束层另有一份 `cheb(foe, city) <= 8`，要等敌人走到 8 格内才分兵（实测第 7 手）→ 太晚。

**改法方向**：服务层补 `CityInfo.turnsToFoe`（从城做一次 BFS，读各敌军位置的层数取 min，
和现有 `flipFromFoeCity` 同形状）；`roleOf` 改读它；分兵触发条件换成
"`foeEta ≤ 我最快增援的回合`"（两条腿比较，不是新阈值）。

**卡在一个契约问题**：`Decision.cityId` 是单值，而"两座城各守一边"是一个决定。
建议不加新 `kind`，把 `defend` 的语义扩成"守住所有来不及的城"（`cityId` 可选 + `cityIds?`），
分几个人仍归约束层 `planMains`。**要拍板后才能动。**

**验收**：`exams-all --diff` 里 S-013 由红转绿（`noCityLost = 2`），
且 S-000 / S-001 / S-004 不变——`defend` 语义一放宽，最容易被拉回来的是"该推的局"。

### 9.2 S-012 采购 + 收尾（队列第 3）

**实测（判分器，12 手）**：`foeLost 1`（要 3）、`lostUnits 1`、剩 **606 金**。
逐手看是两个独立的病：

1. **采购门槛用"人数"当开关**（`outnumbered = 我兵数 ≤ 敌兵数`）。一旦翻成"我更多"，
   `need` 变 `undefined` → 退回"买最便宜的" → 整局在刷 `RECRUIT:militia`（装甲车 atk 22，

2. **残血没人追**：第 16 手敌城还站着一个 **血 1** 的单位，我 19 个兵最近 4 格，
   而 `focusId` 只在"这一手够得到"的范围里挑，`④` 只会朝城走。

**改法方向**：门槛的开关换成规则事实——"对面存在一台我方最强单发三发都打不穿的";
收尾不动 `SquadOrder`，只允许 `focusId` 指向"够不到但残血"的敌人，并在
"这一手没有任何可打目标"时朝它走一步。**分两次改、两次跑批**（先采购，再收尾），
否则红了不知道是谁。S-001 是这条的灵敏度探针（8.6 的教训）。

**"买最便宜的"清查（2026-11-24 17:00）**：`8.19` 撤掉的是**"有钱就造兵"**（造不造），
"买最便宜的"是另一件事（**造什么**），还在，一共三处：

| 位置 | 现状 | 处置 |
|---|---|---|
| `tactics.ts` `recruitAction` 的三分支 | `need` 为空时直接用 `opts`（按价钱升序） | **待删**，但删了 S-002 由绿变红（8.15 实测）——要跟这条一起做 |

| `types.ts` 的 `need` 注释 | 写"挑最便宜的"，与代码不符（代码先挑射程） | **已改正**（纯注释） |

根因：`outnumbered`（人数占优才讲质量）本身就是一个人为开关。8.15 试过无条件讲质量，
