## 一、「老兵不死」：己方城市地块上每回合回血

**规则口径**（这四条是规则本身，不是实现细节）：

| 项 | 结论 | 为什么 |
|---|---|---|
| 触发时机 | **自己的回合开始时**，每回合一次 | 回合开始回血，这一回合的行动能围绕"我刚补了多少"规划；挂回合末的话回到血的那一下已经没有行动可用了 |
| 回复量 | **8% 最大生命**（四舍五入，至少 1 点） | 工业时代一轮集火打掉 30%~40%，8%/回合意味着站城休整三四回合才补得回来：它是"阵地守得住"，不是"打不死" |
| 生效范围 | 站在 `tile.cityId` 非空、且**该城属于自己**、且**未被摧毁**的地块上 | 敌城进不去（`blockedFor` 挡着）；废墟虽然能站，但把烧平的城当补给点等于鼓励"先拆了再蹲进去" |
| 是否叠加 | **不叠加**：按单位结算，一回合只回一次 | 站在 2×2 城的交界上不会回两倍 |
| 是否有上限 | **有**：不超过最大生命（含圣剑觉醒那类 `maxHpBonus`） | 满血不会被"回"出溢出值 |
| 是否复活 | **不**：只处理 `hp > 0` 的活人 | 死在城里的不会因此站起来 |

**实现**：`src/core/expansions.ts` 的 `veterans.hooks.onTurnStart`，比例常量 `VETERAN_CITY_HEAL = 0.08`
（和 `LAST_STAND_BONUS` 放在一起，方便平衡时一眼看到）。战报会写一句
「老兵不死：N 支部队在城下休整，回复 8% 生命」。

**影响范围**：只在开启「老兵不死」的对局里生效；不影响城市自身的回血、驻军、
也不影响其它扩展的回合开始钩子（大家在同一个循环里各写各的）。

## 二、血条 bug：打一个兵，旁边老伤号跟着演一次

**根因**：残留条（橙条）原来是在**渲染时**自己推断的——节点上记着上次的血量比例，
这一帧比它低就演一次。问题在于"渲染"不是"动作"的可靠镜像：

- AI 连走时多步共用一个渲染（中间那几下根本没画）；
- 悔棋、换局、联机拉取会重放状态；
- 顶栏/横幅/缩放触发的普通重绘也会走到同一段代码。

只要有一帧被跳过或重放，某个**早就受过伤**的单位就会被当成"这一帧刚掉血"，
于是它也跟着演一遍——看起来就是"我打了一个兵，旁边几个老伤号一起掉血"。

**修法**：把"谁掉了血"从渲染层的**启发式推断**改成动作层的**前后对账**。

1. `src/main.ts`：`dispatch()` 和 AI 落地动作的地方，在 `applyAction` 前后各取一份状态，
   由 `noteHpDrops(before, after)` 只挑出"这一次真的少血"的单位，写进 `pendingDrops`；
   绘制时**取走并清空**（一次性消费）。三条保守约定：换型的（晋升/孵卵/聚合）不算，
   只见于一边的（出生/阵亡）不算，比例差 < 0.1% 的忽略。
2. `src/ui/board.ts`：`BoardUi` 新增 `hpDrops`（id → 掉血前的比例），`UnitItem` 用
   `chipFrom` 代替原来从 `dataset.hpRatio` 猜的旧值；没有 `chipFrom` 就**不演**残留。
3. 抖动（`impacts`）复用同一份 `hpDrops`，不再维护第二套 `hpSeen` 血量快照。

**验证方式**：
- 新增 UI 用例「受击：只有这一次真掉血的那个兵演残留，老伤号不许跟着演」：
  先让两个单位都带伤并画一帧（都不该演）→ 只改其中一个的血并给出 `hpDrops` →
  断言**只有它**挂 `chipped`，另一个一动不动 → 再普通重绘一次（强制重建节点）断言不重播 →
  回血不给 `hpDrops` 时也不演 → 最后确认打击记账仍然只在给定 id 上发生。
- 全量：`npm run test:ui` 153 项、`npm run test:rules` 444 项全绿。

## 三、深水图标：它以前根本没有样式

**根因**：`src/ui/board.ts` 的地形→class 表里**漏了 `deep`**，于是
`TERRAIN_CLASS[terrain] ?? 't-plain'` 把外海兜底成了平原色——地图上"过不去的深水"
和"随便走的草地"长得一模一样。

**修法**（两处）：

1. `TERRAIN_CLASS` 补 `deep: 't-deep'`；
2. `src/style.css` 新增 `--deep: #4a7fa6` 与 `.tile.t-deep`：深蓝底 + 稀疏波纹（9px 一道，
   比浅流的 6px 更疏）+ 内阴影，并保持 `cursor: not-allowed`。

三个手段一起用，是因为只改颜色在 20px 缩略图上会被抗锯齿抹平——得靠"有没有纹路"来分辨：
深水（看不到底）纹路疏、浅流（能踩过去）纹路密。

**影响范围**：只影响 `deep` 这一种地形的绘制。水域、浅流、平原的样式一行未动；
深水本来就是不可通行地形，规则层没有变化。

**验证**：新增 UI 用例「地形底色：深水有自己的样式，不再被兜底成平原」——
把一格改成 `deep` 后断言它挂 `t-deep` 且**不挂** `t-plain`，同时用一格平原做对照。
