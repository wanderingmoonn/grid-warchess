# P0（能不能走过去按代价判）+ P4（平局形状标注）实测（2026-11-23）

## 一、P4 已落地：跑批现在会标"平局的形状"

`bench:ai` 每局结束会记：还剩几座废墟、我方/对手各剩几座完好城，并写进 JSON。
逐局输出也带标记，汇总末尾多一段：

```
**平局的形状**：3 局平局里，**1 局还剩废墟没被占**、0 局有一方已被打到 0 城。
（对手 v1 没有收废墟逻辑，这类"平"可能是败局）
平局明细：Q3|32|B 废墟0 我城2 敌城2；Q4|30|A 废墟0 我城2 敌城2；Q4|32|A 废墟1 我城1 敌城2
```

**这批队列里，"v1 收不了废墟"不是主因**——3 局平局里 2 局双方都还有 2 座完好城，
是实打实的僵持，只有 1 局还剩废墟。你观察到的那个现象是真的，但它不在这 24 局里，
以后看平局先看这一行就够了。

## 二、P0 实测：净负，默认关

开关 `aiReachCost`（默认关）。两种实现都跑了：

| 实现 | 说明 |
|---|---|
| v1 | 用 `advance` 场（水按 14 计价、**可以过**）+ 比值上限 |
| v2 | **水仍然是墙**，只把"绝对步数上限"换成"代价 ÷ 直线 ≤ 3" |

两版结果一样：

| 组 | Q1/Q2 | Q3/Q4 | 配对 |
|---|---|---|---|
| 基线 | 10-2-0 | 11-1-0 | — |
| **P0（`--reach-cost`）** | 10-2-0 | **8-1-3** | Q12 **0↑0↓** / Q34 **0↑3↓** |

三局胜变平：`Q3|32|B`（172→261）、`Q4|30|A`（101→261）、`Q4|32|A`（87→261）。

**v1 里还有一个真错**（已改掉）：把水当"贵但能过"，于是"中间隔一格水、两岸都通"的地图
被判成"走得过去"→ 桥不修了 → 陆军开到岸边停住（`blockedFor` 根本不让人进水）。

## 三、为什么净负：24 步上限在编码一个真实偏好

看 `Q4|30|A` 开 P0 之后的终局：

```
T261  我兵 126（！）  金 4848  桥 10 座  陆路最小步数 16（已连通）
```

不是"过不去"，是**根本没打算过去**：判"走得过去"之后，它不往渡口堆桥，
也不急着推——兵一路涨到 126 个，钱压着 4848，261 回合没打完。

所以那道 `min(w,h)` 的绝对步数上限，**本身就是一句话**：
"绕 24 步以上才到，不如修桥。"把这句话换成"绕到直线的 3 倍"，
等于告诉它"绕 60 步也行"——于是它真的去绕、去种田、去攒兵。

## 四、那"宽浅流被当渡口"还要不要治

要，但它**不能用这 24 局验**：

- 这四条队列里没有"很宽的浅流"的地图，改判据只会改动别的图的行为；
- 净负就是"在无关的图上改了行为"的代价。

正确做法是先**造一张代表性的图**（比如 24×24，中间一条 8~10 格宽的浅流，
两岸是我方/敌方），然后只在这张图上比较三种判据：
① 现状（等步数 + 24 步上限）；② 代价 + 绝对上限（`min(w,h)` 个"平地当量"）；
③ 代价 + 相对上限。看"会不会修桥""多久过河""能不能赢"。

## 五、结论与下一步

1. **P4 保留**（零风险，已经能回答问题）。
2. **P0 默认关**，代码和开关留着。它证明的是"绝对步数上限在做有用的事"。
3. **浅流**：先造图，再动判据；不要拿标准队列当试验田。
4. 真正还没解的还是"兵到 126 个也打不完"——那是收尾（P0-2 / P2-3），
   不是"能不能过去"。这一轮把"过不去"这条嫌疑排掉了：**开着 P0 它连通了，照样平**。
