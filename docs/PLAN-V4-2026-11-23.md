## 一、一句话

**v4 只重做"大脑"，不重做游戏。** 判断对错的尺子从"胜率"换成"考卷"，
因为 v3 的实测已经证明：24 局胜率的噪声（换种子 ±30 个百分点）比任何一次改动的信号（±10 个点）都大。

三条硬底线，写在最前面：

1. **没有考卷就不许改代码。** 一道题必须能说清"什么叫做对"。
2. **新题必须先红。** 一上来就绿的题没在考任何东西。
3. **胜率不是日常刻度。** 只在里程碑跑一次，用来看"有没有崩"，不用来比大小。

## 二、为什么从零，而不是在 v3 上改

不是"改不动"，是**改一处的代价不可估**。v3 的收尾文档把三条原因钉死了：

1. **三层名存实亡**：战略 / 计划 / 战术最后都往同一张分数表里加一项，
   加完就分不出是谁的功劳。所以"改一处"实际上是"改一个全局最大值的取法"。
2. **同一个概念有好几份实现**："该守哪座城 / 该打哪座城 / 兵回哪座城"三个口径并存，
   想统一到一处，发现要同时改四个地方。
3. **一句判据被三处共享**：`canReachEnemyByLand` 同时喂给修桥计划、海军需求、决战判决。
   按代价改写它是那次实测翻车的直接原因（0↑3↓）。

还有一条不在文档里、但从数字上读出来的：**v3 的真实水平是 44%，不是 88%。**
换到没碰过的种子，30 个百分点就没了。说明后期相当一部分"进步"是对三颗种子的记忆。
这两条加在一起，意味着 v3 不是一个"再努力一点就行"的位置。

## 三、界线：什么是"引擎"，什么是要重写的"大脑"

### 3.1 引擎只做三件事

| 它做 | 在哪 |
|---|---|
| 记着现在这盘棋长什么样（谁在哪、多少血、多少金、城归谁） | `src/core/types.ts` 的 `GameState` |
| 列出现在能做什么（走 / 打 / 攻城 / 造兵 / 盖房 / 装配…） | `src/core/types.ts` 的 `Action`（第 2930 行起） |
| 拿一个动作按规则算出新局面，或者判定不合法 | `src/core/rules.ts` 的 `applyAction`（第 5497 行） |

**它不判断该做什么。** 像棋盘和"马走日"：棋盘不替你选棋，只保证每一步要么合法要么被拦。

### 3.2 三张表

| 不动（资产） | 可以加（只读） | 要重写（v4 的主体） |
|---|---|---|
| `rules.ts` 规则结算 | 从某格到某格要几回合 | `ai-v3.ts`（约 1 万行） |
| `types.ts` 数据结构 | 某座城现在该算什么角色 | `ai-goal.ts` 目标状态机 |
| `board.ts` / `fog.ts` / `config.ts` | 某支部队归谁 | `ai-plan.ts` 计划层 |
| 地图生成、扩展包 | 当前这条路通不通 | `ai-strategist.ts` 战略层 |
| 存档 / 快照 / 回放 | — | `ai-tactics.ts` 战术估计 |
| 跑批脚本、探针 | — | `ai-strength.ts` / `ai-meta.ts` |

这三张表的位置写在这里，是为了让以后每一次"我想改 `rules.ts`"都能被拿出来对一遍。

### 3.3 唯一允许的引擎改动

**加只读查询：允许。** 它不改变任何结算，只是让上层少算一张图（这条本身就是 v4 的核心设计，见 4.2）。

**改结算规则：不许顺手做。** 必须单独立一批，且先证明"这是规则 bug"，不是"AI 想要一个更顺手的规则"。
否则"从零做大脑"会悄悄变成"重写游戏"，而 v3 的引擎已经被 1005 项规则测试和几十万局对局验过。

## 四、架构：三层各准输出什么

v3 的三层**名字**是对的，错在每层都能往同一张分数表里加一项。v4 沿用分层，但把
"每层允许输出什么"定死。

### 4.1 职责

| 层 | 只准输出 | 举例（对 / 错） |
|---|---|---|
| **决定层**（战略） | **决定**：做什么 + 期限 + 承诺 | ✅「这三回合先发展，第 20 回合前不开战」<br>❌「进攻意愿 +40 分」 |
| **约束层**（计划） | **约束与目标**：哪几格必须空、哪些兵归哪队、打哪座城 | ✅「(5,4) 必须空出来」「这 6 个兵归突袭队」<br>❌「让位意愿 +50 分」 |
| **打分层**（战术） | **分数**，且只有一把尺子（金 / 每回合金） | ✅「这一步净赚 12 金、少挨 9 点伤害」<br>❌「踩废墟 +220」（它凭什么值 220？） |

### 4.2 两条护栏

**护栏一：一层服务，一份真相。**
地形可达、行军回合、城的角色（前线 / 后方 / 受威胁 / 该弃）、部队归属——
**算一次，缓存在一处，所有上层都读同一份**。任何人想再算一张距离图，都算 bug。

v3 的三个病（三个城口径、`canReach` 被三处共享、各处自算距离场）全在这一层。
这一层还特别好验收——它输出的是**数**，不是**选择**，可以直接和引擎真值对拍。

**护栏二：排除和排序是两种工具，不许混用。**
分数只能排先后，不能表达"这个不许做"。v3 的让位折腾三轮，根因是拿分数去表达"必须"。
v4 里凡是"必须"，都进约束层，不进分数。

### 4.3 三条明确禁止的形状（都是 v3 真踩过的）

1. **一条判断没有执行者**：`targetCityId` 只写不读，计划立了没人动。
   → v4 要求：写进局面的每个决定字段，必须有一个读取者；没有就报错。
2. **同一概念多份实现**：城的三个口径。
   → v4 要求：这类东西只存在于服务层，别处不许再算。
3. **靠加权调和矛盾**：两个需求打架时加一项分数去"平衡"。
   → v4 要求：打架就说明约束层没排好序，回去排，不要加系数。

## 五、考卷：v4 的地基

### 5.1 为什么不用胜率起步

三个理由，都有实测：

- **噪声大于信号**：换种子 ±30 个百分点，任何一次改动 ±10 个点。等于对着噪声调参。
- **早期必然低**：v4 头两周一定比 v1 还弱。看胜率只能得出"更差了"，得不出"哪里差"。
- **胜率能被畸形打法刷高**：v2 的教训是 83% 弓手、0 建筑、0 升级，一路绿灯（`RL-AI-POSTMORTEM` D1）。
  没人看行为，就没人知道它已经废了。

### 5.2 一个"答题者"的接口

题库不认识 AI，只认这个格式。谁能吐出这个格式，谁就能答题：

```
输入：局面快照 + 我是哪一方 + 这一回合最多几步
输出：动作列表（每步一个合法动作）
      + 每步一句理由（为什么这么做）
      + 一句总述（这一步想达成什么）
```

判分器检查四件事：**动作合法**（`applyAction` 不拒）、**步数不超**、**判据通过**、
**没有踩红线**（见 5.5 的"没破坏什么"）。

### 5.3 一道题的卡片格式

局面**不靠字符表格**，走游戏自带的渲染：导出快照 → 测试员在「导入对局」里粘进去，
看到的就是真实棋盘。出题时必须把席位标成人类（`state.aiControl = {A:false,B:false}`），
否则导入后 AI 会当场自己走（`kickAiIfNeeded`）。完整流程见
`docs/GUIDE-V4-EXAM-2026-11-23.md`。

```markdown
## Y-012 桥头被自己人堵住

### 局面
快照：`exams/snap/Y-012.json`
12×12 / 时代 2 / 第 34 回合 / 我方 A 席 / 金 420 / 兵 6

我方（可读面板，出题工具打印）：
  w1  工人  (3,4)  40/40   正在产金
  s1  剑士  (5,5)  60/80   ← 站在桥点上
  s2  剑士  (7,5)  80/80
敌方已知：桥对岸 3 个兵，最近 4 格

### 问题
这一回合你会做什么？（最多 3 步）

### 标准答案（人写的，可有多解）
1. s1 → (5,3)   理由：让开桥点，敌人下回合就要过桥
2. s2 → (5,6)   理由：换到能堵桥的一侧，但不占格
3. w1 → (2,6)   理由：离开产金格，让后面的兵能站

### 判据（机器判，这是硬标准）
- 3 回合内 (5,4) 必须空出来；
- 期间我方跨过该桥的单位 ≥ 1；
- 我方在桥对岸 3 格内的单位伤亡 ≤ 1。
- 判据只看结果，不要求动作与标准答案一致。

### 为什么这题值得出
v3 在这里会站着不动（`probe:bridge-block` 复现过 10 回合零让位）。
根因是"必须空出来"是硬约束，而 v3 只有分数。

### 红线（这几种做法算错，哪怕判据通过）
- 为了腾格把兵送进敌人 3 格内；
- 拆掉唯一的桥。
```

注意卡片里两个东西是**分开**的：**标准答案**是"人怎么解"，可以有多解；
**判据**是"什么叫对"，机器判。判据通常两段——**做到了什么 + 没破坏什么**。
只有"做到了"的判据会被奇怪的方式刷过，所以第二段不能省。

### 5.4 四级题型

| 级 | 考什么 | 规模 | 例子 |
|---|---|---|---|
| **单机制题** | 一件事，错就一定错在这 | 几回合、几行判据 | 桥头让位、产兵格让位、死水不造船 |
| **判断题** | 时机与取舍，答"该 / 不该" | 一步 | 这波该打还是该继续发展 |
| **小局题** | 十回合内必须出结果 | 10 回合 | 我 30 兵打敌 1 城 5 兵，必须拿下 |
| **整局** | 看过程指标，不看胜率 | 一局 | 兵到城下几回合、僵持几回合 |

四级缺一不可：只有单机制题会重演"机制都会但赢不了"；只有整局题则什么都归因不了。

**小局题是 v4 最重要的新增**，因为 v3 最大的洞正是"兵堆到 100+ 也收不了尾"。
那个洞用单机制题测不出来，用整局题又归因不了。

### 5.5 十一条硬规矩

1. **先红后绿**：新题第一次跑必须显示"现在做错了"。一上来就绿的题作废。
2. **每题配两个笨基线**：一个"永远这么做"、一个"永远不这么做"。打不赢它们说明题坏了。
3. **答案由人写**：和其他测试员讨论后写进题库。AI 不许自己出题自己判。
4. **判据与答案分离**：判据看结果，答案只是示范。否则会把 AI 训成"模仿人的动作"，
   而不是"达到人的目的"。
5. **种子卫生**：出题用一段种子，最终体检用另一段，**体检种子写完就锁起来不许看**。
   v3 的 88% 就是"练习卷即考卷"的产物。**30/31/32 三颗种子已被污染，v4 不许再用它们做题。**
6. **局面要"人会走到"**（2026-11-23 由 `Y-001` 补）：局面真实 ≠ 合理。回放里每一格都真发生过，
   但只有一部分是人也会走到的。测试员的原话是"他不论如何都不会打出这种局面"——
   那种题问的是人从没遇到过的问题，答案没有参考价值。
7. **判据要先被跑绿**（2026-11-23 由 `Y-002` 补）：一条判据在被某个执行者（最好是人）跑绿之前，
   只是没人验证过的一段文字。三桩全红看起来像"题很难"，其实是"题不可能"。
8. **结论要在几颗种子上一致**（2026-11-23 由 `S-002` 补）：AI 的并列取舍由 `s.seed` 抽签，
   同一局面换种子会翻盘（实测 8 个守军时种子 1 绿、种子 12 红）。一道题必须三颗种子同结论，
   否则它考的是运气。`exam-grade --seed N` 就是干这个的。
9. **判据优先量"进度"，不量"胜负"**（2026-11-23 由 `S-002` 补）：胜负会在种子之间翻盘
   （同一局面 v3 有时 25 手赢、有时 40 手赢不了），而城伤、推进格数这类**累加量**单调且稳定。
   `S-002` 的判据从"30 手内赢"改成"15 手内城伤 ≥45"之后，空壳/v1/v3/人 才第一次分出红绿。
10. **防过拟合靠"影响面"，不靠"题够多"**（2026-11-24 补）。
   v3 真正的问题不是"在实战里发现问题"，而是**每次都用加一项分数来修**。
   考题只换了"问题从哪来"，没换"怎么修"——照样能过拟合。
   可操作的判据是**这次改动动了几道题**（`npm run exams:all -- --diff`）：
   动 0 道 = 没生效；动 1 道 = 高度怀疑补丁；动多道且方向一致 = 机制。
   **改机制会泛化，改数字只会拟合那道题。**
11. **题面只有一份正本**（2026-11-23 由 `S-002` 补）：测试员在游戏里打的那局，必须和判分器跑的
   那局是同一份。做法是"关卡为正本、快照由 `level-to-exam.ts` 从关卡生成"——
   别一边用 scene 手算、一边让测试员打开关卡（雾、开局金、逐席时代都会不一样）。

### 5.6 阶段 0 谁答题：四个桩

**阶段 0 不需要 v4 存在。** 题库只认 5.2 那个格式，所以：

| 答题桩 | 要求 | 作用 |
|---|---|---|
| 人写的标准答案 | 全绿 | 证明题目与判分器是通的 |
| v3 现状（`ai-v3.ts` 还能跑） | 至少 10/15 红 | 证明这题在考 v3 真会犯的错 |
| 空壳（什么都不做） | 全红 | 证明题不会因待机白送 |
| v1（`ai.ts`） | 只记录 | 下限参照 |

**阶段 0 的验收就是这两句话：标准答案全绿、v3 至少十道红。** 两条同时成立，题库才可信；
做不到，说明题写坏了——而这时候发现，代价几乎为零。

### 5.7 题目从哪来

不是凭空想的，从 v3 的失败局里挖：

1. 用现有工具导出失败局（`scripts/export-bench-replay.ts`，种子不在默认列表时加 `--allow-any-seed`）。
   已导出三局，回放都在 `results/replays/v4src-*.json`，重放终局与记录一致：
   `Q1|30|A 负 78`、`Q3|31|A 负 84`、`Q3|49|A 平 261`（100 兵打不动 1 城，收尾病的活样本）。
2. 用 `scripts/make-exam.ts --replay … --turn N` 切出"该方还没动手"的那一格，
   自动拆成 `snap.json / card.md / answer.md / author.md` 四份（见 `exams/README.md`）。
3. 看 `author.md` 里"v3 这一回合实际做了什么"，判断人会不会做得不一样；
   一样就说明这题不红，换一格。

**第一批目标 15 道**，但成分要按实测调整（2026-11-23 两条发现，详见 `exams/README.md` 第四节）：

| 类型 | 数量 | 判据 |
|---|---|---|
| 真实局面（综合判断） | 3~5 | 松，先验流程 |
| **手工小局（单机制）** | **10+** | 硬，能机器判 |

原因是：从失败局直接切出来多是"整体判断错"的局面，答案有分歧、判据写不硬；
而 24×24 的真实局面到中后期有 30~64 个单位，按手册第八节已经算坏题。
所以"真实回放"提供**证据**，"手工小局"提供**能判的题**。
造局面的工具已经做了：`scripts/make-scene.ts` + `scenes/*.json`（一张 ASCII 地图 + 城 + 兵），
第一道手摆题 `S-001` 已立住（空壳红、v1 红、v3 绿）。

覆盖方向不变：让位类 4、经济类 3、投送类 3、**收尾类 3**、时机类 2。
收尾类必须先做——那是 v3 唯一的"兵多也赢不了"的洞。

**前两道题已经证明这条路有多难，两道的下场都记在各自的 `review.md` 里**：
`Y-001` 废在"人不这么走"（第 6 条硬规矩），`Y-002` 废在"判据没人做到过"（第 7 条）。
所以下一步不是接着切真实局面，而是先把**造小局面的工具**做出来。

## 六、指标

### 6.1 主指标（日常就看这两个）

**M1 经济兵每回合实产（金 / 经济兵 · 回合）**
- 分子：本回合所有经济单位产出之和；分母：本回合活着的经济单位数。
- 报**中位数**和**最低 20% 分位**，不报平均值（少数好位会把它拉高）。
- 同时报**站位效率**：实产 ÷ 该兵种在脚下地形能达到的最大产出。
  只看绝对数会被地图骗——`ANALYSIS-CITY-PROFILE` 量过：60% 的经济兵-回合站错格子，平均少产 6.35 金。

**M2 升级时代时间（回合）**
- 定义：我方**第一座**城达到时代 N 的回合数（N = 2 / 3 / 4）。
- 必须同图同种子比，或报"相对 v1 的比值"，跨地图的绝对数没有意义。

### 6.2 每个指标必须配对的反指标

这是防止"从另一头刷"的护栏。两个主指标各配一个：

| 主指标 | 反指标 | 防什么 |
|---|---|---|
| M1 实产 ↑ | **战斗单位占比** | 经济铺满、一个兵不造 |
| M2 升级时间 ↓ | **同回合兵力值** | 早早升代、城里空着（虚胖） |

### 6.3 备选观察项（先记录，不判定）

兵到敌城下的回合数 / 僵持回合数（双方都不掉血）/ 单位空转率（一回合无动作的单位占比）。
这三个都能从现有探针读（`probe:econ-idle`、`probe:city-role`、`probe:collapse`），
等主指标稳定了再升格。

### 6.4 胜负平怎么用

**只在里程碑跑一次**，看两件事：有没有出现 0 胜（能力崩了）、平局率有没有超过 50%（收不了尾）。
不做精细比较。对手固定 `--old ./baselines/ai-9efb961.ts`，并记住它**不收废墟**——
平局要先看形状，别把它的缺陷当成自己的成绩。

## 七、阶段与验收

| 阶段 | 做什么 | 验收（硬标准） | 需要 v4 吗 |
|---|---|---|---|
| **0** | 题库与判分：快照 → 题卡格式、出题工具、判分器、答题桩 | 15 道题跑通；**空壳全红、v3 ≥10 红、且每道题都有人（最好是人的答案）跑绿过**；导入游戏后静止显示 | 不需要 |
| **1a** | 服务层：地形/距离/可达/城的角色/部队归属，算一次、全上层读 | 与引擎真值对拍 90% 一致；与 v3 现有口径不一致的每一条都能解释 | 不需要 |
| **1b** | 空骨架：三层接口 + 结构化日志 + 退化探测器 | 全流程跑得通、题库仍全红、**不崩不卡死** | 需要 |
| **2** | 点亮约束层：让位、编队指派、产兵格、关键格 | 让位类题目全绿；判据不许靠"多做几步"混过 | 需要 |
| **3** | 点亮决定层与打分层，交替推进 | 单机制题 ≥70% 绿 → 小局题 ≥50% 绿 | 需要 |
| **4** | 小局题 → 整局过程指标 → 胜利体检 | M1/M2 优于 v1 且反指标不恶化；胜负平只做体检 | 需要 |

几点补充：

- **1a 单独成关**：它输出的是数不是选择，最好验收，而且 v3 三个病都在这一层。
  先用最容易验收的一层打地基，前两周就不会陷入"感觉变好了但说不清"。
- **阶段 1b 的"题库仍全红"是验收项**：骨架不许偷偷解决问题。空壳必须真是空壳。
- **阶段 2 放在决定层之前**，和直觉相反（打分才是现成资产）。理由是 v3 所有翻车都在
  "分数表达不了的约束"上，先把这个工具做对，后面才有地方放"必须"。
- **打分层第一版故意写笨**：只做"能走、能打、能造"三件事，几十行，靠题库一题一题长。
  v3 那六千行不许抄——那些系数正是耦合的来源，抄过来第一周就回到"改一处不知动到哪"。
  代价是头两周它看起来比 v1 还蠢，这个要事先接受。

## 八、不做什么

| 不做 | 为什么 |
|---|---|
| 不在 v3 上叠补丁 | 已冻结；`V3-BACKLOG` 第六节是负结论登记簿 |
| 不重写引擎、规则、地图、雾、回放、跑批 | 这些是被 1005 项测试和几十万局验过的资产（`RL-AI-POSTMORTEM` 第十一节） |
| 不抄 v3 的战术打分 | 耦合的来源，见 7 的补充 |
| 不追胜率 | 噪声大于信号，见 5.1 |
| 不做 RL | v2 复盘的结论：规则写得出来时 RL 边际价值小，且推理在玩家浏览器里，规模被卡死。<br>但**题库正好是以后 RL 的评估集**，这份投资不会白费 |
| 不做平衡调整 | 全项目既有决定：数值留到内容补齐后统一调 |
| 不给 AI 戴编制帽子 | `V3-INVARIANTS` 第一、二、三条：24 兵上限 / 每城 2 个经济 / 编队数量上限都是 v1 自戴的 |
| 不用 30/31/32 三颗种子做题 | 已被调参污染，见 5.5 第 5 条 |

## 九、风险与预案

| 风险 | 预案 |
|---|---|
| 题库写太少，判不出好坏 | 先 15 道，宁可粗；每阶段末回头补题，别一开始就追求覆盖 |
| 题目能过但人觉得蠢（判据太松） | 每道题的判据必须两段：做到了什么 + 没破坏什么；再加红线清单 |
| 人写的答案自己也错 | 答案必须带理由，理由要能被别人反驳；一人写、另一人复核（测试员互查） |
| 阶段 1~2 太慢，看不到进展 | 每阶段都有可看的数字（红/绿题数），不给"感觉变好了"留位置 |
| 服务层无限膨胀，什么都往里塞 | 只放"算一次、多个读者"的东西；只有一个读者的不许进 |
| 半路忍不住去抄 v3 的战术层 | 写进文档：抄了就等于把 v4 变成 v3.1，前两周的笨是预算内的 |
| 又滑回"看胜率调参" | 胜率的唯一合法用途是里程碑体检，且要带平局形状 |
