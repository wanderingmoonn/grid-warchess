## 三、逐步回答"AI 为什么不这么做"

### ① 人类第 40 回合之后几乎不再造兵，把钱攒到 4,671——AI 为什么不攒？

AI 的金币整局平均 **180**，最高 548。代码上它并非"不会攒"，而是**攒钱的松紧度是分档的**：

```ts
// savingAllowance(): 目标价 + 4 回合收入以内 → 一分不花；
// 否则偶数回合仍然放开 floor(收入 / 产兵城数)
if ((targetCost - gold) / inc <= SAVE_TIGHT_TURNS) return 0;
if (phase !== 0) return 0;
return Math.floor(inc / sites);
```

也就是说：**只要"离目标还有 5 个回合以上"，它每回合照样花掉一部分**。
人类的做法是不分档的——"这一段我不花钱"。AI 从来没有"这一段"的概念，
它的额度是每回合按当下差额重新算的。

> 上一轮加的 `aiIntent`（跨回合记忆）补的是"**忘**"，补不了"**每回合都给自己留余地**"。

### ② 为什么买均价 100 的兵，而不是 176 的？

```ts
// recruitCandidate(): 价格是线性扣分项
const perGold = plan.stance === 'elite' ? 0.012 : aiLevelOf(s) !== 'basic' ? 0.035 : 0.05;
score -= price * (d.era >= 4 ? perGold * 0.6 : perGold);
```

而 `elite` 档的开关是：

```ts
const quality = savingFor !== null || gold >= inc * 1.2 || army >= CONFIG.maxUnits - 6;
```

这局 AI 的金币长期 ~180（低于 1.2 回合收入），兵数到第 55 回合才 18，
兵力也常年达不到门槛 → **大部分回合按 0.035 线性压价**：
300 金的兵被扣 10.5 分，100 金的只扣 3.5 分。价格差 200 金换来 7 分劣势，
只要贵兵不是强出太多，就永远排在后面。

### ③ 为什么整局只升级 2 次？

```ts
function upgradeCandidate(...) {
  const cost = upgradeCostOf(s, city);
  if (cost === null) return null;
  if (gold < cost) return null;   // ← 当下就得掏得出来
```

它的现金流是"每回合花到 180"，而第 4 代以后一级要 540~780。
**它永远差一口气**，而人类靠"停手两个回合"就攒出来了。

后果是复利的：人类四座城升到 5/4/3/3，终局每回合收入约 300 金；
AI 停在 1 代，全程约 150。同一份收入差距在 85 个回合里滚成了 3.4 倍的战损比。

### ④ 为什么"打不过还一直打"？

AI 只有两种相关姿态，中间是一大片空白：

| 姿态 | 触发条件 | 效果 |
|---|---|---|
| `turtle`（缩守） | `myVal < foeVal * 0.75` **且** 敌人压到我家城下 5 格内 | 不往外推 |
| `commit`（全军压城） | `myVal >= foeVal * 1.3` | 关掉"追路过敌军"，全军砸城 |

这局的 `vb/va`：第 45 回合 **0.87**、第 55 回合 0.60。**第 45 回合它落在那段空白里**——
不够强去总攻，又没弱到要缩守，于是"看到谁打谁"：
`scoreAttack` 只要目标在射程内就有 +14 的保底分，没有任何"我方战力是否劣势"的闸门。
人类那一侧的数字正是反面：他全程不超过 14 个兵，但**从不主动接战**，等 AI 撞上来。

### ⑤ 为什么 223 次移动只打出 10 次攻击？

人类 65 走 / 68 打，接近 1:1；AI 是 223 走 / 10 打。方向每回合重算：

```ts
const mood = aiActiveMood(view, traits);          // 三种打法，权重每回合重算
fields.focusCityId = mood.focusCityId;            // 主攻城每回合可能变
fields.lineRef = frontLineRef(...);               // 战线参考也每回合重算
```

队伍一直在"重新对齐到新的主攻方向"，而不是"沿一个方向推到底"。
人类的 4 座城是 5/4/3/3 且只剩 1 座时仍在往同一个方向压——**方向是他的计划，不是他每回合的输出**。

## 四、这局不是"人类比 AI 强"造成的个例

用**同一颗种子**（914654067）、同一套配置，让当前 AI 双方各打一遍（`scripts/repro-seed.ts`）：

| | A（AI） | B（AI） |
|---|---:|---:|
| 结果 | 67 回合胜 | 负 |
| 出兵 / 战斗兵均价 | 18 / 162 | 22 / 129 |
| 阵亡 | 12 | **29** |
| 行动 | 攻 48 / 走 234 | 攻 28 / 走 145 |

**同一个结构又出现了一遍**：落后的一方（B）兵造得更多、均价更低、死得更多。
所以这不是"人类用某种 AI 没有的技巧"，而是**这套 AI 在落后时没有"停手"这个动作**——
它对"我现在打不过"的反应只有一个：再造一个便宜兵送上去。

## 五、由这局直接指出的三个可测改动

都不是"加算法"，是把上面那几处阈值和闸门调对。**先说清楚：这是假设，没测过。**

1. **`turtle` 阈值 0.75 → 0.90**。理由：本局它整场卡在 0.87~0.95 这段空白里送兵。
   改完应当显著减少"劣势接战"，可以先用 `npm run duel` 验证。
2. **`perGold` 在有钱时降到 0.012**（现在只有 `elite` 档才降）。
   理由：均价 100 vs 176 的差别直接来自这条线性罚。可测口径：同一批种子下
   "战斗兵平均单价"和"交换比"两个数。
3. **升级允许"借一个回合"**：`gold + inc >= cost` 就允许攒（现在要求 `gold >= cost`
   才发出 `UPGRADE` 动作，之前那一步还得靠 `savingFor` 把额度压到 0）。
   理由：它的现金流永远差一口气，而升级是这局输掉的根本原因（8 次 vs 2 次）。

第 2、3 条都能用**这局的数据直接对账**（均价、升级次数），不需要等胜负分出来。
