## 一、浓雾蔽野：对面的钱袋变成「?」

**问题**：这个扩展把地图遮了、把敌人藏了，可 HUD 上那行 `金币 456` 还在——等于免费告诉你
"他还能不能再买一队兵"。雾做得再厚，看一眼数字就知道对面是不是已经空了。

**改法**：`resLine(p)` 里判断三种情况：

- 这一局开了 `blackout`；
- 这一行不是我自己（`p !== me`）；
- 不是观战位（观战位本来顶栏就写着"全图视角"，遮一半自相矛盾）。

三条同时成立就把数字换成 `<span title="…">金币 ?</span>`。**不整行删掉**是刻意的：
一个字段凭空消失，玩家会以为是渲染坏了；给个 `?` 是明确说"有这东西，但你不知道"。

没开这个扩展的对局一个像素都没变（有专门用例守着）。

**落点**：`src/ui/panel.ts` `panelHtml()` 里的 `blackout` / `hideEnemyGold()` / `resLine()`；
扩展自己的 `summary` 补了一句，规则书第二册补了一条说明。

## 二、敌方的桥：点了就走上去

### 2.1 规则层本来就是通的

先把话说清：`reachableTiles()` 里"敌方单位挡路"那条过滤器对桥是**放行**的
（`if (utype(s,u.type).bridges) return false`），`MOVE` 也接受把兵放到敌桥那一格上。
新加的用例「敌方造的桥，谁都能站上去」就是钉这条的：B 架桥 → A 的兵进 reach → 走上桥 → 地形仍是桥面。

### 2.2 坏在点击的**顺序**上

`onBoardClick` 的判断顺序是"先看这一格是不是我的攻击目标，再看是不是桥面"。而桥在数据上
是一枚**建筑棋子**（`bridges` 标记 + 把水格改成桥面），所以点到敌桥那一格时：

1. `clickedUnitId` 是桥的 id；
2. `targets` 里有它（相邻一格本来就能打，射程放开之后更是几乎总有）；
3. 于是走"开火"分支 —— 桥修好了，你只能隔河干看，永远站不上去。

### 2.3 现在的做法：可达的桥面，走上去优先

新增 1.2 段，排在开火之前：**桥面可达、且没按强制攻击键** → 直接 `MOVE`。三条理由：

1. 桥没有自己的操作面板（塔和军营才有），"选中它"从来不是玩家想要的；
2. 过河是这个格子上唯一常用的动作，攻击可以换一种点法；
3. 不改的话，射程放开之后敌桥几乎永远在 `targets` 里，等于把"站上敌桥"这个玩法关掉。

想拆桥：**按住 Shift 点**（强制攻击），或者先走到射程内再用强制攻击模式。
走上一座**敌桥**时会提示一句"想拆这座桥：按住 Shift 点它"——两种点法差一个 Shift，
不说一句玩家会以为"打不了"。

原来的 1.9 段（同样的逻辑，位置在开火之后）删掉，避免两处各写一遍。

## 三、AI：拆桥要看态势

### 3.1 老账：桥在"击杀"那套账里是白捡的 125 分

`scoreAttack` 的底分是 `击杀 ? 120 + 造价 × 0.12 : 掉血比例 × 60`。木桥只有
`UNIT_TYPES.bridge.maxHp` 点耐久、造价 45 ——**一发两发就塌**，于是"打死一支骑士"和
"拆掉一座木桥"在 AI 眼里分数只差几点。

表现出来就是：部队走到河边先拿一轮齐射把桥拆了，然后自己过河还得重新架。
桥是双向的，拆对面的桥往往等于拆自己未来的路。

### 3.2 现在：桥单独算一本账

`scoreAttack` 里 `if (targetDef.bridges) return scoreBridgeAttack(...)`，只认两种情况：

| 情况 | 判据 | 分数 |
|---|---|---|
| **死守** | 桥离我的城 ≤ 3 格，且比离对面的城更近 | `30 − 距离×4`，正在收缩固守再 +14（城门下的桥 40 分） |
| **进攻** | 桥在对面那一侧（离敌城更近），我又没在 hold / 攒钱 / 弃城 | 20 分 |
| 其余 | 攒钱、收缩、已放弃进攻、桥就在我过河的路上 | **0** |

0 分就是"别想"：候选分数 ≤ 0 的动作 `aiNextAction` 根本不会选，也不会像负数那样
把"往桥上靠"的走位分算歪（`tacticalMoveScore` 里 `nextAttack` 取的是 max，0 是中性值）。

**落点**：`src/core/ai.ts` `nearestCityGap()` / `scoreBridgeAttack()`（新增），
`scoreAttack()` 签名从 `mood: AiMood` 改成 `all: Fields`（要读 `hold` / `guardCityId`），
三处调用点跟着改。

**用例**：「AI 拆桥看态势」——同一座桥放两个位置对撞：顶到自家城门口时必须拆（`ATTACK` 那座桥），
搬到地图正中（离两边一样远、谁都不从这里过）时必须不碰（这时它宁可什么都不做）。

## 四、远程拆桥：准许打，但打折

### 4.1 原来的"必须贴到桥头"

`canStrike()` 里曾有一条 `if (utype(s,target.type).bridges && d > 1) return false`。
它治的是"两边各架七八座、隔着河互相对射桥头，打满 200 回合谁也过不去"，
但一刀切也治出了新毛病：远程连"顺手拆一座没人守的桥"都做不到，而近战要贴到桥头
才能动手，实际打起来又常常够不着。

### 4.2 现在：射程够就能开火，隔一格以上半伤

- `canStrike()`：删掉那条特例，只判射程（**落点**：`src/core/rules.ts`）；
- `computeDamage()` 收尾：`if (dt.bridges && ctx.distance > 1) × CONFIG.bridgeRangedDamageRatio`
  —— 放在最末，是因为它说的是"这一发落在桥上的效果"，属性倍率、护壁、反击折减都算完再对折，
  才不会被别的倍率抵消掉；
- 系数落在 `src/core/config.ts` 的 `bridgeRangedDamageRatio: 0.5`，和 `canStrike` 是一对：
  那边放开了射程判定，这边负责让放开之后的代价落在伤害上。

数字（长弓手 14 攻，木桥 0 甲、40 血）：

| 打点 | 一发 | 拆掉一座木桥 |
|---|---|---|
| 贴着桥头（1 格） | 14 | 3 下 |
| 隔着河（≥2 格） | 7 | 6 下 |

`doAttack` 里那条过期文案（"拆桥要贴到桥头（隔河打不塌一座桥）"）改成
"射程不够，还够不着这座桥"——现在只有射程真的不够才会走到那一句。

**用例**：「隔河拆桥：远程能放箭，但一发只算一半」——同一支长弓，隔两格打 7、
贴桥头打 14，并断言 40 血的木桥"贴桥头 3 下内塌、隔河 3 下不塌"。

## 六、没做的事 / 已知取舍

- **没给敌方资源（粮、材）也上锁**：这次只按需求藏金币。要藏就得连"他还有多少粮"一起藏，
  那是另一条规则（资源也是战略情报），留到需要的时候再说。
- **观战位不遮**：观战是全图视角，遮金币会和顶栏那句"全图视角"打架。
- **点桥面＝走过去，开火要按 Shift**：这是唯一一个"点一个敌方东西却不开火"的例外。
  更好的做法大概是"点一次选中、再点一次走上去"，但那要多一步点击，而桥是过河的必经格。
  先按"最常用的动词胜出"处理，靠提示补上另一半。
- **AI 只在自己城门口或推进方向上拆桥**：它不会为了"掐对面补给线"去拆远处那座桥——
  那座桥它自己可能也要用。这条保守一点，比反过来（见桥就拆）更像人。
