# AI 能力审计：哪些是"验收过的"，哪些只是"顺带支持"

2026-11-06 · 起因：地图尺寸这条从没被写成验收项，结果 V2 在 12×12 上卡了一整天没人发现。
这份是把**所有对外宣称过的能力**逐条翻出来，标清楚它到底有没有硬验收。

## 判定口径

| 记号 | 含义 |
|---|---|
| **硬验收** | 有脚本/用例，跑不过就红，且断言的是**行为或数值**，不是"能不能跑" |
| **冒烟** | 有用例，但只断言"不崩 / 能走完 / 维度对得上" |
| **无** | 只有文档或界面文案，没有任何自动检查 |
| **已挡** | 界面上根本不给这个组合，或在入口拦掉 |

## A. 网络 AI（`aiBrain: 'net'`）能遇到的组合

| 能力 / 组合 | 对外宣称在哪儿 | 现有验收 | 判定 |
|---|---|---|---|
| 10×10 青铜局 | 面板、README、`test:net` | `eval.ts` 每轮 40 局打分 | 硬验收（**只测胜率，不测行为**） |
| 12×12 青铜局 | 同上 | 同上 | 硬验收（同上） |
| 其他尺寸（8/14/16/32） | 面板："别的尺寸……会很弱" | 无 | **无** |
| 起始时代 2~6 | 面板："……与时代会很弱" | 无 | **无** |
| **扩展包**（奇想 / 时代军备 / 古文明…） | **面板一个字没提** | 无（训练只开 `bloodbath`） | **无** |
| **选卡模式（BP）** | **面板一个字没提** | 无（训练 `draftMode = false`） | **无** |
| 迷雾 | 明示"自带全视野" | 无（故意的） | 已声明 |
| 3/4 人局 | 面板不出现 | `setup.ts:223` 的 `aiOpponent = twoSeats && …` 让多人局根本没有 AI 对手（**结构性挡掉，没有专门用例**） | 已挡 |
| 指挥官模式 | 面板说明"这一档不提供" | `netAllowed` + smoke 用例 | 已挡 |
| 自定义兵种（兵种编辑器） | 无 | 无 | **无** |
| 天气/季节扩展 | 无 | 无 | **无** |
| 权重版本兼容 | — | `test:net` 断言 `spec.state/action == STATE_DIM/ACTION_DIM` | 硬验收 |

补充一条客观事实：动作特征里 RECRUIT/BUILD 用的是**兵种属性**（造价/攻/血/射程……），
不是 id one-hot。所以开扩展进来的新兵种**不是"完全看不见"**，是"看得见但没练过"。
这降低了风险的量级，但没有降低"没验收"这件事。

## B. 网络 AI 的行为能力（真正的洞）

`npm run test:net` 现有 4 条用例：权重逐字节一致、spec 维度对齐、按产品口径走完一局、同种子确定性。

**这四条全是"完整性检查"，没有一条检查它做了什么。** 也就是说：一个"只会造弓手、
从不升级、从不盖房"的策略，可以永远绿灯——事实上它已经绿灯了一整天。

| 行为 | 应有验收 | 现在 | 实测（6 局 12×12） |
|---|---|---|---|
| 会招募 | 招募次数 > 0 | 无断言 | 543 次 ✓ |
| 兵种多样性 | 招募种类 ≥ 3 | 无断言 | 9 种，但 **83.2% 是弓手** ⚠ |
| 会造建造单位 | 建造单位 > 0 | 无断言 | **0 次** ✗ |
| 会盖建筑 | BUILD > 0 | 无断言 | **0 次**（因为没建造单位）✗ |
| 会升时代 | UPGRADE > 0 | 无断言 | **2 次 / 8718 决策**（0.02%）✗ |
| 会造经济单位 | 经济单位 > 0 | 无断言 | 2 次（占 0.4%）✗ |

## C. 为什么会漏到今天

1. **验收标准写的是"胜率"，不是"行为"。** `RL-PLAN-v2.md §八` 定了三条统计规矩
   （分扩展报、分削弱档报、分意图报），**唯独没有"分行为报"**。
   胜率是"结果"，它能被一种畸形战术（堆弓手）刷到 54%，于是掩盖了"只会一种打法"。
2. **两个尺寸混着报胜率，掩盖了"一个涨一个不涨"。** 10×10 从 54→71 的好消息
   盖住了 12×12 卡在 30% 的事实，而我把后者归因成"样本少"。
3. **面板文案成了唯一的"能力边界说明"。** 它只写了尺寸与时代，
   没写扩展包和选卡模式——而这两条同样是训练分布外。

## D. 建议（按"能防住下一次"排序）

1. **给 `test:net` 加行为断言**（最高优先，几小时）：
   跑 3 局 12×12 青铜局，断言「招募种类 ≥ 3」「建造单位 > 0」「UPGRADE ≥ 1」。
   **当前会红**——这正是它的价值：把"顺带支持"变成一次红灯。
2. **面板补齐两条**：扩展包、选卡模式，都归到"训练分布外，会明显变弱"。
3. **建一张组合矩阵**（尺寸 × 时代 × 扩展 × 选卡 × 迷雾 × 人数），
   每个组合标「训练内 / 训练外」，训练外的在面板上标黄。
   这张表进 `setup.ts` 的注释和面板文案，作为**新增能力时的默认动作**。
4. **把"能力验收"写进 `RL-PLAN` §八**：能力 = 行为断言，不是胜率。
   一条能力上线，必须同时有一条能让它变红的断言。
