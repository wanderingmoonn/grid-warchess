# AI 的三回合计划：把候选落到局面上再打分

2026-11-04 · 架构：`positionValue` + `simRound/simSteps` + `PLAN_WORTHY` 门控

---

## 〇、为什么动这一刀

这一层不是第一次被点了。三条独立证据都指向"决策层已经饱和"：

| 证据 | 结果 |
|---|---|
| 高级 vs 中级（多一整套战术层） | **+0 点**（`UPDATE-2026-11-02-ladder.md`） |
| 五条结构性改动（推演 / 记忆 / 换血 / 两翼 / 换家） | 46.0%（n=200） |
| 按战术平移采购配比 | 43.9%（n=800，显著更弱） |
| 速攻期加攻城器 | 50.3%（n=800，中性） |

共同点：**都在给"单个动作"打分**。评分再准，也看不见"这一步之后对面怎么还手、
我还接不接得上"。所以这次不是调权重，是换判据——把候选**真的落到局面上**，
走完对面一回合、再走一步我自己的，然后拿局面的估值来比。

## 一、架构

```
候选（前 2 名）
  └─ applyAction(我这一步)            ← 一次深拷贝
      └─ simRound：结束我的回合 → 对面走 3 步 → 结束它的回合
          └─ simSteps：我再走 3 步
              └─ positionValue(局面, 我) − positionValue(原局面, 我)
```

- **`positionValue`**：`城×120 + 我方军队(按 unitValue, 血量为权) − 敌方军队×0.9
  + 金×0.35 + 时代×40`。城给最高权重是刻意的：城全丢才输，三回合里多一座城
  比多存两百金重要得多。
- **`simRound` / `simSteps`**：模拟里调的还是**这套 AI 自己**（`depth=1` 关掉深推），
  所以不会递归爆炸。
- **门控**：只有 `depth===0`、非指挥官/非点名、非沙盒、且动作属于
  `RECRUIT / UPGRADE / ATTACK / SIEGE` 才跑。走位不跑——一步走位三回合后
  几乎看不出差别，却要在每格付 80 ms。
- **不翻白不翻**：换掉启发式第一名要过 `max(40, 5%)` 的线，否则维持原判。
  深推本身有噪声（只走 3 步），贴着边翻只会让 AI 抽风。

## 二、克隆开销：实测，不靠感觉

`scripts/bench-clone.ts`，16×16、30 个兵的中局：

| 操作 | 耗时 |
|---|---:|
| `applyAction`（含深拷贝） | **0.52 ms** |
| 一次 `aiNextAction`（浅评估） | **6.6 ms** |

结论和直觉相反：**贵的不是克隆，是模拟里的打分**（13 倍）。所以宽度不能按
"克隆几次"定，得按"模拟几次打分"定。最终取 `PLAN_K=2`、`PLAN_STEPS=3`：
2 组候选 ×（1 段 simRound + 1 段 simSteps）× 3 步 ≈ 12 次打分 ≈ 80 ms。

单局耗时从 **5.7s 涨到 ~30s**（AI 自对弈、40~60 回合）。对玩家来说是一次决策
多 60~100 ms，回合内十几步就是 1 秒上下——可以接受，但没有再放宽的余地。

## 三、确定性

- 全程不碰 `Math.random`；
- 模拟里唯一的随机来源是既有的 `aiNoise(seed, …)`——它本来就是"同一局面同样应对"；
- `depth` 显式传参，不靠模块级计数器（那样 UI 的提示调用会打乱计数，等于破坏确定性）。

所以存档、复盘、联机对账仍然成立。

## 四、两个踩出来的坑

1. **计划把玩家点名的动作否掉了**。指挥官模式里玩家指定"升这座城"，深推却在
   算"升另一座更划算"。用例「「升级时代」那一格也能指定升哪座城」当场变红。
   修法：`planAllowed` 里加 `!commander && !order && !orderSite`——**那一格是玩家的
   决定，不是 AI 的**。
2. **估值没有"对面"这一项，于是 AI 学会了绕着走**。第一版 `positionValue` 只算
   "我的兵值多少"，于是"打他一刀、自己挨一下"在账上是净亏，深推一致选择撤退。
   用例「贴脸的矮人王照样扔斧头」就是这样红的（第二手从 ATTACK 翻成 MOVE）。
   修法：加入 `− 敌方军队 × 0.9`——打掉对面一个兵和保住自己一个兵本来就该同权。

## 五、行为实测（`npm run probe:plan`）

```
3 局 · 2124 次决策 · 计划跑 728 次（34.3%）· 翻盘 107 次（占计划 15%）· 107s
```

也就是说：**三分之一的决策会进计划，其中六分之一真的被计划改了主意**。
它不是一个"装上去但从不触发"的机制——这一点上一次（换血）栽过，所以这次先量。

## 六、胜率：**中性**

对照 = 动手前那一刻的 `src/core/ai.ts`（`scripts/baselines/ai-87b9829.ts`，含单位改动、
不含计划），配对种子，时代 3。

| 实验 | 局数 | 新 / 旧 / 平 | 计分胜率 | z | 均回合 |
|---|---:|---:|---:|---:|---:|
| 三回合计划全开 | 400 | 197 / 201 / 2 | **49.5%** | −0.20 | 57.1 |

**读法**：机制确实在跑（34% 的决策进计划、15% 被翻盘），但胜负动不了。
这不是"没生效"，是"生效了也不值钱"——和 11-02 那批（46.0%）、今天的配比实验（43.9% / 50.3%）
是同一个结论的第四次复现。

**为什么没用**，现在能说得比之前具体：

1. **估值里城占绝对权重，可三回合内城几乎不变**。120 分一座城的设定让"多打一座城"
   压倒一切，而 3 步模拟根本走不到破城，于是计划分的大部分方差来自军队价值的微小波动——
   而那一项启发式评分本来就已经在算了。
2. **模拟太浅**：一回合真打起来可能十几步，`PLAN_STEPS=3` 常常在"部队还在路上"时就停了，
   于是"进攻失败"和"进攻成功"在估值上长得一样。
3. **对手是自模型**：对面按我们的打法还手，换来的信息量比想象中小。

**结论**：这一层本身不产生收益，但它是"更深的搜索"的地基（探针、确定性、克隆预算、
亏损来源都摸清了）。所以代码留着，`PLAN_ON` 这个开关写在 `ai.ts` 里，
将来接 MCTS / 对手模型时从这里往下走。

## 七、已知局限（写清楚，免得被当成"会下棋了"）

1. **模拟的对手是我们自己**（自模型，不是对手模型）。真实人类会犯错也会出怪招，
   这一层看不见；它买到的是"我三步之后接不接得上"，不是"我能不能赢人"。
2. **只看 2 个候选、只走 3 步**。这是预算决定的，不是设计偏好。
3. **迷雾**：模拟跑在 `playerView` 上，看不见的敌人不存在——所以"对面有一支
   正在赶来的部队"这件事，深推算不到。
4. 没有 MCTS / 没有对手建模 / 没有开局库。这三样才是"像人一样下棋"的下一步。

## 八、把搜索做深（同一天，第二轮）

第一版中性之后，按"太浅"的假设加深：`PLAN_K 2→3`、`PLAN_STEPS 3→6`，
同时把模拟里的 lookahead 关掉（`depth>0` 时不做那一步——外层深推已经把对面
整回合走了一遍，再算"最狠一刀"是重复付钱，而且是最贵的一笔）。

### 成本：深度是拿时间换的，而且不是线性

| 配置 | 单局耗时（AI 自对弈） | 说明 |
|---|---:|---|
| 无计划（基线） | ~6 s | |
| K=2 / 1 轮 / 3 步 | ~30 s | 第一版，400 局中性 |
| K=3 / **2 轮** / 6 步 | **~150 s** | 直接翻五倍，跑不下去 |
| K=3 / 1 轮 / 6 步 | ~122 s | 这一轮实际用的配置 |

关键发现：**每多一轮，成本翻倍**，而成本大头不在克隆（0.52 ms）、也不在 lookahead
（模拟里已经关了），而在"每个模拟步都要把候选全枚举一遍"——30 个单位、
每单位十几种走法，一次就是几毫秒。所以"更深的搜索"在这套代码里不是调参数，
是要重写模拟策略（见第十节）。

### 行为：这次真的动得多

| 配置 | 进计划比例 | 翻盘（占计划） |
|---|---:|---:|
| K=2 / 3 步 | 34% | 15% |
| K=3 / 6 步 | **47%** | **26%** |

翻盘率从 15% 涨到 26%，说明更深的搜索确实"看见"了启发式看不见的东西。

### 结果：**还是中性**

| 配置 | 局数 | 新 / 旧 / 平 | 计分胜率 | z |
|---|---:|---:|---:|---:|
| K=2 / 1 轮 / 3 步 | 400 | 197 / 201 / 2 | 49.5% | −0.20 |
| K=3 / 1 轮 / 6 步 | 240 | 118 / 120 / 2 | 49.6% | −0.13 |
| 上一行 + 节奏项 | 200 | 98 / 99 / 3 | 49.8% | −0.07 |
| **合计** | **840** | — | **49.6%** | — |

深度翻倍（翻盘率 15% → 26%）、判据换掉（加入"谁会先被打死"），
胜负一点没动。**所以默认关掉**（`PLAN_ON = false`）：它是中性且贵 5~20 倍的东西。

## 九、这一轮真正学到的东西

**"AI 太笨是因为想得浅"这个假设是错的。**

如果真是想得浅，加深度就该有收益；如果没有，那就是**它想的东西本身不对**——
而这一轮连"想的东西"（判据）也换了，还是没动。把三次负结果和之前几次放在一起：

| 干预 | 类型 | 结果 |
|---|---|---|
| 五条结构性改动（推演/记忆/换血/两翼/换家） | 决策层 | 46.0%（n=200） |
| 按战术平移采购配比 | 采购层 | 43.9%（n=800）显著更差 |
| 速攻期加攻城器 | 采购层 | 50.3%（n=800） |
| 三回合计划（浅） | 搜索 | 49.5%（n=400） |
| 三回合计划（深） | 搜索 | 49.6%（n=240） |
| 深计划 + 节奏判据 | 判据 | 49.8%（n=200） |

六次干预、约 2000 局，**平均值全部落在 46~50%**。这不是"还没找对参数"，
这是一个**平台**：在这套决策结构里，无论怎么调深度、判据、权重，对上一个版本的
胜率都是 50% 上下。

**平台下面是什么**，真实对局数据其实已经指了方向（第九节那份）：

1. **添油式接战**：输的局里 阵亡数 > 造兵数，说明起始部队也在被吃，一个兵一个兵地送；
2. **经济暴露**：planter / herder / priest 三样吃掉三成伤害、打出零伤害；
3. **不会弃子**：明知守不住还要往里填兵（`withdrawal` 那条判据要求三个条件同时成立，
   实战里几乎不触发）。

这三件都不是"这一步选得对不对"，而是**一段时间的编排**：什么时候集中、什么时候撤、
什么时候把经济单位收回来。深搜三个回合看不见它们，因为它们的时间尺度是 8~15 回合。

## 十、下一步（如果还要继续）

按证据强度，我建议的顺序：

1. **别再动决策评分了**。六次干预的数据在那一层是平的。
2. **做"战役级"编排**：把"这几回合集中兵力打哪条线 / 什么时候收缩防守"做成显式的、
   跨 5~10 回合的目标，再用现有的单步评分去执行它。这是换结构，不是换判据。
3. **用真实数据当尺子**：3/4 人局的报告从今天起能入库了，跑一周以后按 `build` 切，
   直接看"新 AI 的 dealt/taken 比有没有改善"——比自对弈有说服力。
   注意：报告里**没有动作序列**，所以只能做诊断，不能重放。
4. 如果要做真正的搜索，先重写**模拟策略**（现在每一步都要全量枚举候选，
   深度一提就线性爆炸）。那是另一件工程，不是参数。

## 十二、结构改动第一刀：经济单位回撤（已回退）

按"平台在结构、不在判据"的判断，动了第一处结构：**经济单位在威胁两回合外就回城**，
不再是"等挨打才躲"（老写法只看 `exposure`，敌人还在四格外时照挖不误）。

### 先解决"拿什么量"

自对弈里经济单位只吃 **7.8%** 的伤害，真实人机对局是 **30%**——
**两个 AI 都不打对方经济**，所以"护经济"在自对弈里没有对手可以防。
为此新写了一个尺子：`scripts/script-raid.ts`，一个只杀工人、不围城不抢时代的脚本。

结果：**这把尺子也不好用** —— 它对 AI 是 0 胜 8 负（连工人都摸不到就输了）。
所以最后还是回到 KPI：直接量"经济单位承伤占比 / 阵亡数"，两个臂各 8 局同种子。

### 结果：没有效果，还拖慢了经济

| | 经济承伤占比 | 经济单位阵亡 | 造兵 |
|---|---:|---:|---:|
| 基线（不回撤） | 7.8% | 62 | 539 |
| 加回撤 | 8.0% | 72 | 598 |

承伤占比没降，工人多死了 10 个，而造兵数从 539 涨到 598——**仗被拖长了**。
能解释得通：撤退让工人少干活，产出下来、兵力跟不上，反过来被压得更久。

**所以回退了**，连那条"两回合就该撤"的用例一起删掉（不留验证不了的机制）。

### 这一刀真正留下的东西

1. **`probe-economy.ts`**：以后任何"护经济 / 保兵力"的改动，都能先用它看 KPI，
   不必等 15 分钟的胜率批次；
2. **`script-raid.ts`**：抢经济对手（虽然太弱，但它证明了"自对弈不打经济"这件事
   是可以被构造出来的——以后要做更强的对手，从它往上加）；
3. **一条方法论结论**：**自对弈测不了"防偷袭"类改动**。这类行为只有在对手真的偷袭时
   才有意义，而两个 AI 都不偷袭。要验证它，只有真实人机数据这一条路
   ——这也是为什么下一步应该先收数据，而不是继续改 AI。

## 十三、第七刀：战役级"集结闸门"（2026-11-06，**中性偏负，已回滚**）

按第九节的建议（"平台在结构，不在判据"），做了一次真正的结构改动：
**没到齐就不主动开战**。判据放在候选过滤（不是评分）——因为它是"能不能开战"的许可。

### 第一版判据是错的，根本没生效

先写的判据是全局比例："我方战斗单位里，距最近敌人 ≤6 格的比例 ≥0.5 就算到齐"。

800 局跑完 **50.0%（391:391，18 平）**，但探针查出来 **闸门触发 0 次**：

```
G1（兵太少/没敌人）  13 次
G2（"已到齐"）      514 次   ← 一半决策在这里就返回
GATE（真正设闸）       0 次
```

在 12×12 上两军一接触，这个比例天然接近 1 —— 它量的是"打没打起来"，不是"到没到齐"。
**那 800 局 50.0% 是"什么都没改"的结果，不是"改了没用"。**

> **方法论**：看到中性结果，先验证改动有没有真的跑起来。这一条如果漏了，
> 会得出完全错误的结论（"第七刀也失败"），而实际是判据写错了。

### 第二版：局部支援判据

改成逐动作、局部判断：主动攻击或朝敌人贴的走位，要求**目标点周围三格内我方战力
≥ 对面 × 0.9**；守城反击、后撤、横向集结放行；全局战力压过对面 1.4 倍或第 60 回合后放闸。

触发率正常了（约 15 次/局）。800 局结果：

| | 胜 | 负 | 平 | 计分胜率 | z | 均回合 |
|---|---:|---:|---:|---:|---:|---:|
| 新（集结闸门） | 376 | 405 | 19 | **48.2%** | -1.03 | 83.3 |
| 旧（冻结 b54e247） | 405 | 376 | 19 | 51.8% | — | 83.3 |

**中性偏负，不显著。** 回合数一模一样（83.3），说明它没有把局面拖长，也没有换来更少的送兵。
改动已回滚，patch 留档在 `.tmp/gather-gate-r7.patch`。

### 八次干预的合并结论

| 干预 | 层 | 结果 |
|---|---|---|
| 五条结构性改动 | 决策 | 46.0%（n=200） |
| 按战术平移采购配比 | 采购 | 43.9%（n=800）显著更差 |
| 速攻期加攻城器 | 采购 | 50.3%（n=800） |
| 三回合计划（浅） | 搜索 | 49.5%（n=400） |
| 三回合计划（深） | 搜索 | 49.6%（n=240） |
| 深计划 + 节奏判据 | 判据 | 49.8%（n=200） |

**约 3600 局、八次干预，全部落在 43.9~50.3%。** 这不再是"还没找对参数"，
而是这个决策结构的收敛值。要继续，只能换掉"评估函数"本身（学一个价值头），
而不是在它上面再加规则。
