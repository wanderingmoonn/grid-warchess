## 一、起因：AI 短视

现象（人机对局里反复出现）：

| 现象 | 实测数据 |
|---|---|
| 开局把钱拆成散兵往前推，到对面城下时对面已换代 | 12×12 上 **60 回合卡在 2 代**，对面 3 代 |
| 投资类的东西永远排不上（建了也白建） | 20×20 纵河图 4 局，AI 造桥 40 座，**船坞 0 座** |
| 修真包全开，宗门 / 藏经阁 / 研发 **全是 0** | 79 次交棒的对局统计 |
| 造船坞之后又造太多 | 修完后 4 局 7 座，但招兵只占 16% 钱——**"造太多"一半是统计口径** |

根因不是"某个数调错了"，是**结构上没有一个地方能表达"先发展、晚点打"**：

- 现有 AI 每一步都是"当场比分数取最大"，投资的第一步永远输给"再买一个兵"；
- 姿态只有 `push / elite / turtle / trade`，而 `turtle` 只在**挨打时**触发，
  **没有"我主动选择先不打"这一档**；
- 于是只要有兵就往前推，钱永远变不成产能。

## 二、目的

做一个**由"目标状态机"驱动远期规划**的 AI：

```
远期：我想打到第几代 / 我要多少产能 / 什么时候开打   ← 状态机管
局部：这个兵走到哪、打谁、买哪个                      ← 老启发式管（不动）
```

判断成功的标准不是"更像人"，而是两条可测的：

1. **机制计数**（船坞/电站/素体/灵田/宗门/修士/研发）稳定不为 0；
2. **胜率**对冻结的老 AI 有提升，且**未决率不上升**（别变成两边龟缩）。

### 3.5 已知的坑（都真踩过）

1. **`buildSiteError` 里含"建造者离得太远（最多 2 格）"**：扫图判"这格能不能盖"时，
   必须把工人**假想站在目标格**再判，否则永远返回"太远"。
2. **工地不盖完，建筑永远"施工中"**：`unitActions` 返回空，报错会变成
   "当前规则里没有这种操作"，极具误导性。探针里要手动 `buildDone = buildNeed`。
3. **`s.cities = []` / 清光敌方单位会让席位当场判负**：做无敌人实验时会
   直接终局，`END_TURN` 被拒、状态冻结。
4. **扩展里不能 `import '../rules.ts'`**：会形成 `EXPANSIONS` 未初始化的循环依赖。
   要用的算法自己抄一份（灵田的地形产出就是这么处理的）。
5. **`registerCoreGoal` 同 id 幂等**（原来抛错）：两份 AI 同时加载会崩。
6. **不要"内容没变就跳过写"**：`cost` / `since` / `seen` 每回合要刷新，
   漏写会让"意向过期"判断走偏（指纹立刻变）。

## 四、离线求解器给出的关键结论

参数：5 代目标 / 100 金 / 城产 20 / 名额 2 / 农民 45 金→7、好地 6 块。

| 策略 | 到 5 代 | 终局收入 |
|---|---|---|
| 不投经济 | 91 回合 | 20 |
| 投 3 个 | 50 | 41 |
| 投 5 个 | 40 | 55 |
| 贪心（回本期允许就投） | **32 回合** | 96（15 个经济单位） |

三条结论：

1. **投经济确实更快**（91 → 32），人类的"先发展"是对的；
2. **目标时代越低投得越少**（只到 3 代时贪心只投 6 个）——和直觉一致；
3. **纯"最快"的解是"全部名额投经济、0 兵"，不能打** →
   目标函数必须是"**到 T\* 时战力最大**"，不能是"最快到 T\*"。
