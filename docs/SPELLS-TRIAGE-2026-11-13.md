# 法术清单归类（85 条草稿）

> 日期：2026-11-13　范围：只归类，不定数值、不写代码。
> 输入：纸上草稿里先抄下来的 85 条（名字 + 效果），作者说"后面越来越离谱就没抄完"。

## 0. 结论

| | 数量 | 说明 |
|---|---|---|
| 能落进"族"的数据行 | **约 59** | 写进表里，一行一条，只填参数和开关 |
| 真正要独立文件的 | **约 26** | 每个都在改一条"地基规则"，不是改数值 |
| 需要的族文件 | **11 个** | 每族要写一次 handler，之后第 2~N 条几乎免费 |

所以：**85 个法术 ≈ 11 次"实现" + 48 行数据 + 26 个独立文件**，落在 37 个文件左右。
不是 85 次从零开始。

一条要提前认清的事：**族里"第一条"很贵，第 2~N 条很便宜**。
这决定了排期——先把 11 个族各做一条（11 次实现），
剩下 48 条就是填空题；如果反过来一条一条做，等于把同一段代码写 59 遍。

## 1. 十一个族

参数一栏写的是"这族里哪些东西是数、哪些是开关"。开关超过 4 个就该考虑拆族。

### 族 1 · 直伤 `spell-bolt`

| 项目 | 内容 |
|---|---|
| 成员 | 掌心雷（已有）、灭神枪、元磁神光、不周山断、五雷正法 |
| 参数 | 基伤、每境界加成、射程、是否直线、是否无视护甲 |
| 开关 | 击退 / 禁行动 / 沉默 / 连锁扩散（次数） |
| 备注 | 五雷正法的"扩散 5 次"是族内唯一的递归逻辑，写成开关即可；不周山断的击退若复用族 5，这里只剩沉默 |

### 族 2 · 范围伤害 `spell-blast`

| 项目 | 内容 |
|---|---|
| 成员 | 如来神掌、厚土镇岳、百里毒瘴、移山填海、摘星拿月、焱、垚、鑫、淼、森 |

| 备注 | **这是最划算的一族**：10 条法术一套代码。焱垚鑫淼森本质是"大范围攻击 + 一个附带状态"，那 5 条应该只是 5 行数据 |

## 2. 独一份的 26 条，按"要动的引擎能力"再聚簇

这 26 条不是"没归类好"，是它们都在改一条规则本身。按"改的是哪条规则"分簇，
同一簇里的可以共用一个新能力，只是触发条件不同。

### 簇 A · 时间与序列（8 条）

天衍四九（回档）、烂柯棋局（消失 3 回合）、缩地成寸（延迟到下一回合）、
虚空放逐（进世界阴面）、冥天大梦（梦境相位）、苍蜣登阶（每 5 回合检定）、
**天外飞仙（蓄力位移）**、**一颗金丹（行动经济重置）**

共享能力：「单位暂时不在场，但状态要保住」。
`hideUnit` 能藏，但**藏起来的单位算不算死亡/视野/胜负判定**要逐条定。
天衍四九最重：它要保存和恢复整个 state，和 `snapshot.ts`、回放格式正面对撞。

### 簇 B · 记录与延迟处决（2 条）

斩仙飞刀（记录 3 回合，9 的倍数回合清空直线）、钉头七箭书（记录 + 猜年龄）

共享能力：「往 `custom` 里存一张观察表，每回合扫一遍」。
技术上不难，难在 UI：钉头七箭书要玩家**输入数字**，而 `SkillDef.targeting`
只有 `'none' | 'point' | 'direction'` 三种，没有"输入文本/数字"这一档。

### 簇 C · 规则豁免与全局改写（8 条）

大道三千（无视流派要求）、一元复始（清空身上所有效果）、诸邪辟易（属性不下降）、
平等图腾（境界动态化）、天下皆白（跨扩展包伤害乘回合）、绝地天通（封印兵种）、
万族之劫（按兵种数量加成）、法相天地（改占地面积）

前四条走现成钩子（`modifyStatAtk`、`modifyDamage`、`canCommand`、`produceBlocked`）；
**大道三千要注意**：它会绕过 `spells.ts` 里 `spell.schools` 那道闸，得改在那个函数里而不是法术自己里。

### 簇 D · 效果转移（2 条）

替劫灵身、张冠李戴（把对自己的一切影响转到目标身上）

`redirectDamage` 只覆盖"伤害"，而这两条要的是"所有影响"（含 debuff、拉拽、转化）。
**得先定义"影响"的边界**，否则做出来只有伤害会被转走，其余照旧。

### 簇 E · 特殊复合（6 条）

拘魂索命（抽魂 + 拉拽 + 禁行动 + 灵魂单位）、以气御剑（依赖另一把剑的距离）、
虚无生道（灵力耗尽时重置）、不周山断（击退 + 沉默，若不复用族 1 就独立）、
摘星拿月（击退 + 改地形 + 灵气转伤 + 击落 + 眩晕，五合一）、
**穷极 / 破碎虚空（绕射程校验）**

摘星拿月建议**拆开放进族 2 + 族 3**，别当一个法术做——五合一的法术是最难测的。

## 3. 三个会反噬地基的问题（比文件怎么分重要）

### 3.1 转化类会污染很多地方

"把敌人变成自己人"看着只是 `u.owner = X`，实际上会牵连：
城市归属、编制上限、视野（`visibleSet` 重算）、寿元与境界（`custom` 字段要不要重置）、
胜负判定（`checkWinner`）、AI 的敌我划分。族 10 那 5 条一起做之前，
建议先把"归属变更"写成一个函数，所有转化都走它，否则会散在五个地方各改一遍。

### 3.2 回档类会撞回放

天衍四九要"保存 → 打几回合 → 回到保存点"。你们有 `snapshot.ts` 和 `replay-file.ts`，
存档是既有约束。**这类法术要不要进回放、进回放后怎么重演**，得先定，
否则做完之后回放一放就歪，而且很难查。

### 3.3 AI 现在完全不会放法术

`ai.ts` 的 `heroSkillCandidate` 只读 `def.skills`（兵种自带），
`extraSkills` 里的法术它根本不看；评分还是 `switch (k.effect)` 硬编码。
所以：

- 族越少，将来补 AI 越省事（11 个 case，不是 85 个）；
- 但簇 A~D 那些"消失 / 转化 / 回档 / 改规则"的法术，**AI 不是加个 case 就能懂**，
  它需要理解"我这回合消失了""这个敌人现在是我的"。这批建议先只给人玩。

## 4. 建议的落地顺序

> 这里只是方向。可执行、可中断、带门禁的版本见 `docs/SPELLS-PLAN-2026-11-13.md`
> （那份把批次、地基、进度勾选框都定死了，是真正照着走的那份）。

**第一批（能最快看到规模）**：族 2（范围伤害，10 条）、族 5（五行免耗，7 条）、族 1（直伤，5 条）。
三族 = 22 条法术，只需 3 次实现。先做完这批，你会立刻有"法术很多"的手感。

**第二批（补齐手感差异）**：族 6（自身增益）、族 3（场域）、族 4（拉拽）、族 7（攻击附加）。
这批决定"法术之间像不像"，也就是我上轮说的那个真风险——别让 85 个法术都是同一发火球的换皮。

**第三批（要动地基，单独排期）**：族 10（转化）、族 8（召唤）、族 11（死亡触发）、簇 A~D。
这批每一条都要单独想清楚副作用，不适合和学习其他系统并行。

**随时可以插的**：簇 E 里的穷极、破碎虚空（只是绕过射程校验，改动小）；
族 9 的炼灵、行万里（纯资源转换，无副作用）。

## 5. 已经核对过的：哪些钩子现成、哪些要新造

| 需求 | 现状 |
|---|---|
| 改伤害 / 护甲 / 移速 / 射程 / 视野 / 攻击次数 | 已有 `modifyDamage`、`modifyArmor`、`modifyMove`、`modifyRange`、`modifyVision`、`modifyAttacks` |
| 伤害转移 | 已有 `redirectDamage`（只覆盖伤害） |
| 禁行动 / 混乱 | 已有 `canCommand`（返回字符串 = 不能，附带理由） |
| 禁建造 / 封印兵种 | 已有 `produceBlocked` |
| 产量 / 收入改造 | 已有 `modifyYield`、`modifyIncome` |
| 单位隐藏 / 相位 | 已有 `hideUnit`（语义要扩，见簇 A） |
| 死亡后复活 | `onUnitKilled` 能收到通知，但"能不能在里面复活"要先验清理顺序 |
| 延迟 / 每回合检定 | `onTurnStart` + `custom` 字段，够用 |
| 玩家输入文字或数字 | **没有**。`targeting` 只有 `'none' | 'point' | 'direction'` |
| 改单位归属 | **没有**封装，得自己写并统一走一处 |
