# 关卡模式 · 现状与交接（2026-11-15）

> **接手的人先读这一份。** 它只讲"现在是什么样、哪里有雷"。
> 想写一张新关卡 → `GUIDE-LEVEL-AUTHORING.md`；想知道当时为什么这么定 → `PLAN-LEVEL-MODE-2026-11-14.md`（历史决策）；
> 想看最初的设计意图 → `DESIGN-LEVEL-MODE-2026-11-14.md`。
> 这一块 2026-11-15 告一段落，下面是它的完整状态。

---

## 一句话现状

**关卡模式能用了**：四张玩家关（孤城 / 斩首 / 黄雀 / 护送）+ 五个测试夹具，选关走任务简报页，
地图 / 席位 / 部署 / 事件 / 胜负 / 关卡兵种 / 扩展三档 / 关卡专属 AI 参数都已落地，
`npm run test` 全绿（含 26 段关卡探针）。

**但"难度"只验到"AI 对 AI 能跑完"，没验过"人玩起来爽不爽"**——那部分只能靠实机，见最后一节。

## 现在有什么

| 能力 | 写在哪 | 备注 |
|---|---|---|
| 手摆地图 | `level.map.rows`（字符画）或坐标 paint | 尺寸 8~40；字符表见 GUIDE |
| 席位 | `level.seats` | 2~4 家、逐席 AI、`hidden`（中途登场）、`cityEra` |
| 锁开局设定 | `level.setup` | `startEra` / `firstSide` / `twoCities`，**锁时代＝锁开局金币** |
| 开局兵力 | `level.deploy` | 一写就替代自动撒兵（含经济单位） |
| 事件 | `level.events` | 触发：turn / unitDied / enter；动作：say / spawn / doctrine / deploy / terrain |
| 胜负 | `level.goals` | survive / escort / assassinate，按数组顺序判 |
| 关卡独有兵种 | `level.units` | `summonedOnly` 表示"只由事件刷出，谁也造不出来" |
| 扩展三档 | `level.expansions` | `require` 必须开 / `forbid` 禁 / **`warn` 能开但会变难** |
| 关卡专属 AI | `level.ai` | `riskAversion`（进攻性主旋钮）/ `cohesion`（战线收拢）/ `appetite`（战意） |
| 测试夹具 | `level.dev: true` | 不进玩家菜单，但保留在注册表里给探针用 |

界面上：选了关卡之后，「战役」页变成**任务简报**（目标 / 双方兵力 / 固定项 / 扩展入口），
「地图」页整页消失，所有锁死的开关**不渲染**（不是灰掉）。扩展走一个抽屉，复用原来那份列表。

## 七条坑（接手前必读，都是踩出来的）

1. **AI 不会自己渡河进攻。** 不是"胆小"，是投送能力不行：过河的兵会停住堵桥头，
   大部队被自己人卡在窄桥上。调 `riskAversion` / `cohesion` 只能让它多过去一两个，
   城照样不掉血。**要重压力就用事件把兵送到对方那侧**（孤城的两翼骑兵就是这么来的）。
2. **援军要从地图边缘进场。** 直接刷在玩家腹地，玩家的第一反应是"AI 在耍赖"，
   不是"远处来了援军"。探针钉着"骑兵必须落在 y=0 或 y=h-1"。
3. **`spawn` 落点被占时会就近找位**（半径 1~2）。这是 2026-11-15 才有的：
   之前直接放弃，只在战报留一句"这一格站不住"，作者根本不会去看。
   即便如此，坐标仍要错开——挤得太满还是可能站不下。
4. **`spawn` 的兵种必须在本局兵种表里。** 缺了会被静默跳过（战报留一句"本局没有这个兵种"）。
   **`补（2026-11-16 实测）`**：这句原来写的是"青铜开局写 `knight`（铁器）会被跳过"，**不准确**——
   默认配置下 `enabledUnits` 就是全部兵种，`createMatch` 的 `unitTypes` 里**有** `knight`，
   所以青铜局刷一个铁器兵是**能成功**的（真跑过：场上出现了 1 个）。
   真正会被跳过的是三种：id 根本不存在、这个兵被 `enabledUnits` 关掉了、
   或者它来自一个没启用的扩展。时代差只是"玩家自己造不出来"，不影响刷兵。
   （`level-lint.ts` 按这个口径写：不存在=警告，时代差=警告，都不是错。）
5. **关卡校验失败会静默回落成随机地图**（`createMatch` 里 `level` 变 null）。
   现在会打 `console.warn`，但最快的定位办法是跑 `npm run probe:level`——第 1 段逐条列错因。
   最常见的原因：**两个兵写在同一个坐标**。
6. **存档跑的是关卡快照**（`config.level` 整包进 state）。改了关卡，旧存档仍跑旧内容，
   这是自洽的、不会崩。**想看新版请开新局**，或者地址栏加 `?fresh=1` 清档
   （别做成默认行为——那会连「继续上一局」和配置记忆一起干掉）。
7. **探针不许钉死具体数值。** 钉过"第 9 次炸桥"、"炸成深水"、"4 近战 4 远程 2 斥候 2 农民"，
   作者一调就报红。断言要跟着数据走（读事件里的 `when.at` / `terrain.to`），
   或者退回结构性要求（"兵够多""有塔""兵种存在于本局"）。

## 没做的（下一段从这里接）

- **斩首关的 AI 参数没调。** 现在用 `doctrine: hold` 硬压着守方不动。
  更自然的做法是 `riskAversion: 1.5` + `cohesion: 1.5`：让它自己判断"这个人不能死"。
  参数已经有了，只是没试。
- **难度曲线没有系统验证。** 所有结论都来自 AI 对 AI 的四五个种子 + 你的实机手感。
  "出兵慢会不会被打烂""出兵对能不能守住"这类问题，只有人玩才知道。
- **扩展包的"玩法包 / 规则微调"分档没做。** 27 个包平铺，靠 `blurb` 一句说明。
  讨论过（换世界 vs 调口味），但 `Expansion` 没有分类字段，等包再多到看不过来时再说。
- **关卡编辑器：E0~E6 全部落地（2026-11-16）**。**接手请读 `STATUS-LEVEL-EDITOR-2026-11-16.md`**
  （文件清单、五条不变量、已知的坑）。能做的：
  选关页「我的关卡」新建/编辑/删除、改 JSON、看问题列表、**画地图**（笔刷/矩形/城位/
  撤销/改尺寸）、**摆兵**（全时代货架 + 当场拒绝放不下的位置）、**席位**（几家/托管/
  中途登场/每家城的时代）、**事件**（卡片式"当…就…"，区域拖框、落点点击、五个模板、
  **时间轴**）、**胜负条件**（守住/护送/斩首，顺序可调）、**关卡独有兵种**、
  **扩展三档 + AI 旋钮**、**试玩**（直接开局）和**自打 3 局**（能不能跑完）、
  **管理**（改名/复制/删除/导出导入/云端分享）。存的是本机 localStorage，
  云端是可选的（要手动执行 `sql/warchess_levels.sql`）。计划见 `PLAN-LEVEL-EDITOR-2026-11-15.md`，
  事件表单的细节方案见 `DESIGN-LEVEL-EVENT-FORM-2026-11-16.md`。
  **所有字段都有面板了**：地图 / 席位 / 兵力 / 事件 / 胜负 / 兵种 / 扩展 / AI。
  JSON 现在是"高级改法"，不再是唯一入口。
- **合作模式先不做**（三条原则之一：可以不写进规则，靠口头结盟）。

## 怎么验证

```bash
npm run probe:level    # 关卡探针 26 段：校验 + 隔河白打 + 桥面 + 骑兵落点 + 刷兵
npm run test           # 全套（lint:boards / 样式 / 规则 / 界面 / 联机 / 启动 …）
```

实机验一张关：开新局（或 `?fresh=1`），看战报该出的事件有没有出，
看棋盘上该来的兵有没有来。**"改了没生效"九成是①在看旧存档 ②坐标冲突 ③兵种不在表里。**

## 一段值得留给后人的判断

这一版反复改了很多轮，几乎每一轮都在回答同一个问题：
**"为什么玩家不按我设计的打法打？"**

- 玩家蹲在河岸隔河点农民 → 因为地图给了他一个零代价的输出位；
- AI 缩在桥头不动 → 因为它算下来"过河不划算"，而这不划算来自**投送能力**，不是勇气；
- 加了援军玩家看不见 → 因为援军刷在视野外的地图边缘，而且中间三波连播报都没写。

三次的教训是同一句：**难度不来自数值，来自"有没有安全位""有没有必须回应的威胁""玩家能不能看见发生了什么"。**
调数值之前先问这三句，比加兵加时间有用得多。
