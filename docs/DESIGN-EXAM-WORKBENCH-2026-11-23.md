# 出题工作台方案（2026-11-23）

> 问题：出题现在很模糊，看不出"一格局面长什么样"。想做成关卡编辑器那样**画出来**，
> 再加个"录制人的解题动作"。但这些都是开发者功能，塞进游戏面向玩家不合适。
>
> 结论：**不用新做开发者功能。游戏里已经有三层挡板**，考卷挂在现成的关卡体系上就行。

---

## 一、三层挡板（都已经存在，直接用）

| 挡板 | 是什么 | 证据 |
|---|---|---|
| **关卡编辑器本来就是玩家功能** | 菜单里有「编辑器」一栏，玩家能画地图、摆兵、存关卡 | `level-manager.ts` → `openLevelEditor`，子面板 `level-canvas` / `level-army` / `level-lint` |
| **`dev: true` 不进玩家菜单** | 关卡上一个字段，三处菜单过滤全部排除它 | `core/level.ts:2899 / 2921 / 2930 / 2941` |
| **`?debug` 是既定的开发者入口** | 同类已有 `?fresh` / `?aihud` / `?roguedebug`，一律走 URL 参数、不进菜单 | `main.ts:1841` `renderDebugHud()` |

所以"玩家看得见"这件事根本不用靠"新做一个隐藏页面"来避免——
**做出来的东西标 `dev: true`，它就天然对玩家不可见**；需要工具的入口挂在 `?` 参数上，
玩家不点那条链接就永远不知道它存在。

---

## 二、方案：考卷 = 一个 dev 关卡 + 两个小钩子

```
出题 ──①游戏里画（编辑器，已有）
      ├─②脚本造 → 转关卡 → 粘进编辑器继续改（已实现）
      └─③脚本造 → 直接出快照（残血局面，绕开关卡）

答题 ──④按题号直达（待做，~20 行，挂 ?exam=）
      └─⑤（不想改代码时的替代）临时把 dev 改成 demo，从「编辑器」栏进

录制 ──⑥导出动作（待做，~20 行，挂 ?debug）
```

### 2.1 出题：三条路，按局面复杂度选

**① 游戏里画 —— 已经能用，零成本。**
「编辑器」→ 画布画地形 → 摆兵面板放兵 → 存关卡。
适合"我脑子里有个画面"的出题方式。这就是你要的"像关卡编辑器那样自定义局面"。

**② 脚本造 + 转关卡 —— 已实现（`scripts/scene-to-level.ts`）。**
`scenes/*.json`（ASCII 地图 + 城 + 兵）→ 关卡 JSON → 粘进编辑器 → 在画布上继续改。
好处是脚本能批量生成、能进版本库、能用 `make-scene.ts` 直接判分；
编辑器负责"给你看、给你改"。

**③ 脚本造 + 直接出快照 —— `make-scene.ts`。**
残血局面（城只剩 28 血、某个兵只剩 2 血）走这条，因为关卡格式表达不了血量。

### 2.2 答题：给测试员一个链接

测试员拿到 `?exam=S-001`，打开就是那一格。**待在 `main.ts` 加一个小函数**：
读 `?exam=` → `levelById('level:s-001')` → 用 `createMatch` 开局，然后照常 `render()`。
它和现有的 `?fresh` / `?loadSave` 是同一种东西，玩家永远碰不到。

不改代码的临时替代：把考卷的 `dev: true` 改成 `demo: true`，它会出现在「编辑器」栏里，
测试员从菜单点进去。缺点是和示例关混在一起，而且玩家也能看到。

### 2.3 录制：`actionLog` 已经有了，缺一个出口

现状（都已存在，只是没接到界面上）：

- `main.ts` 有个 `actionLog`，AI 和玩家**每一步都记**（`noteStep`），带 `by` 标明谁走的；
- 前提是 `config.recordDetail === true`（面板上那个"记录详细数据"）；
- 上限 1500 步 / 120 KB，对我们这种几十步的答案远远够；
- 它已经会进 `buildMatchReport`，也就是**报告和回放里本来就带着动作序列**。

缺的只是"给人一个导出按钮"。做法：`?debug` 下多一个「导出动作」，
把那串 `actionLog` 存成 JSON。然后判分器用 `--answers` 直接吃。

> 这条打通之后，"人的答案必须绿"才第一次可验证。
> 现在判据的可行性只能靠 v1/v3 背书（`S-001` 就是这么立住的）。

## 三、关卡能表达什么、不能表达什么（都是实测的）

拿 `scenes/S-001.json` 转成关卡、再用 `createMatch` 开局对照：

| 局面要素 | 关卡能不能表达 | 怎么表达 / 差在哪 |
|---|---|---|
| 地图地形 | ✅ | `map.rows`，**字符表和游戏完全一致**（`. f h ~ ^ = P v w d`） |
| 城的坐标 | ✅ | `map.citiesA / citiesB` |
| 兵种与站位 | ✅ | `deploy[A/B]`，每项 `type/x/y` |
| 逐席时代 | ✅ | `seats.cityEra`（A 3 代、B 4 代都对上了） |
| 谁交给电脑 | ✅ | `seats.ai: ['B']` |
| **起始金** | ⚠️ 近似 | 没有"直接指定"，只能用第 1 手的 `gold` 事件扣。**实测会多出 61 金**（扩展开局还会加钱），要精确就用快照 |
| **城的血量** | ❌ | 城血由时代决定（4 代 = 99），不能写成 28 |
| **兵的血量** | ❌ | `deploy` 只有坐标，一律满血 |
| 雾 | ❌ | 要塞进 `expansions` 规则，转换器直接拒绝 |

所以：**"满血、双方同代、金不敏感"的局面走关卡；其余走快照。**
两类题都能用同一套判分器，只是题卡里的 `snap.json` 来源不同。

## 四、为什么不新做一个"出题界面"

1. **已经有三个**：画布、摆兵、事件表单。再做一个就是第四份"改地形"的代码，
   而 v3 的教训正是"同一个概念多份实现"。
2. **新界面必然要玩家可见**（放进菜单），而现成的 `dev` 标记不用改一行就能隐藏。
3. **编辑器是给玩家的**，所以它的打磨程度（草稿箱、另存为副本、逐条列错）比我们临时做的强。
4. 我们真正缺的只有两件事：**按题号直达**、**导出动作**。各 20 行，都藏在 `?` 参数后面。

## 五、落地顺序（三步，每步都能单独停）

| 步 | 做什么 | 状态 |
|---|---|---|
| 1 | 用现成编辑器画第一张题（不改代码） | ✅ 已验（S-001 粘进去能改） |
| 2 | `?exam=<id>` 直达 | ✅ 已做 |
| 3 | 「导出动作」（`?exam` 局才出现这颗按钮） | ✅ 已做 |

### 已经能跑的一整条路

```bash
# 1. 造局面 → 转关卡
node --experimental-strip-types scripts/make-scene.ts --scene scenes/S-001.json
node --experimental-strip-types scripts/scene-to-level.ts --scene scenes/S-001.json --out levels-out/S-001.level.json

# 2. 游戏里：「编辑器」→ 新建 → 把上面那份 JSON 粘进左边文本框 → 保存
#    （必要时在画布上改）→ 记住它给你分配的 id（形如 user:xxxx）

# 3. 按 id 直达这一局（换了浏览器/没保存过就找不到，用户关卡存在本机）
#    地址栏： localhost:5173?exam=user:xxxx
#    内置关卡也行：?exam=lone-city（会被补成 level:lone-city）

# 4. 在游戏里把这一局打完，然后「设置 → 导出动作」→ 复制到剪贴板 → 存成 a.json

# 5. 转成判分器的答案格式
node --experimental-strip-types scripts/actions-to-answers.ts --in a.json --me A --out answers/S-001.json

# 6. 判分
node --experimental-strip-types scripts/exam-grade.ts --exam exams/S-001 --answers answers/S-001.json
```

`?exam=` 三条行为都是刻意的：

- **强制打开 `recordDetail`**（否则动作不被记录，第 4 步会拿到空）；
- 找不到题号就**退回普通开局**并打一行警告，不许把页面搞死；
- 用户关卡存 localStorage，所以**换台机器就没有了**——题目正本仍是
  `scenes/*.json` 与 `exams/*/snap.json`，关卡只是"拿来看和改"的那一层。

冒烟覆盖在 `scripts/smoke-dom.ts` 末尾两条（能开起来 / 题号写错不抛错）。

## 六、风险

| 风险 | 说明 |
|---|---|
| 关卡带"从开局打"的语义 | 对考题正好（把局面摆成开局那一刻就等于"从这一格开始"），但它也带进来 `goals`/`events` 那套，出题时要克制，别不小心做成一关剧情 |
| 关卡开局有额外加成 | 实测起始金多 61，时代/兵数不受影响；判据里涉及金时要按实际值写，别按场景文件 |
| `dev` 关卡在选关列表里看不到 | 玩家没事，但**测试员必须先拿到 id**，所以第 2 步（直达链接）迟早要做 |
| 关卡数据在 localStorage | 编辑器存的是本机草稿/用户关卡，**不进版本库**。所以"题目"的正本仍应是 `scenes/*.json` 和 `exams/*/snap.json`，关卡只是编辑手段 |
