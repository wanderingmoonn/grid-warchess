# AI 的五个结构性缺口：逐条改法、验证与实测

2026-11-02 · 五条全部实现并落测；**胜负上量不出收益**，原因见最后一节

---

## 〇、一句话结论

五条都按"能指出代码位置"的方式改完了，每条都有用例钉住、有行为计数证明它真的在跑。
但**对上一版的成对胜率是 46.3%（n=80，z=−0.67）——量不出变强，也量不出变弱**。
这不是"改失败了"，而是这套 AI 的决策层已经饱和：`UPDATE-2026-11-02-ladder.md` 里
"高级 → 中级 +0 点"已经先给出了同一个答案。要判断"对人是不是更强"，得用第三条尺子
（人类打法脚本），AI 打 AI 看不出来。

## 一、搜索：一层对手应对推演

**问题**：`aiNextAction` 给每个动作打个分取最高，没有"我走完这一步，对面会怎么还手"。
唯一的风险感知是 `tactical.exposure(unit)`，只管"**我要走的那个兵**下回合能吃多少伤害"。

**改法**（`ai.ts`）：

```ts
// 对手下一回合全军的输出，按金币计价
export function foeOutput(s, me): number   // 逐敌"最强一刀"再求和
```

选择流程从"排序取第一"改成"前 6 名各落一次子，再问一次对面":

```ts
const reply0 = foeOutput(view, me);              // 我什么都不做时的威胁
for (const c of candidates.slice(0, K)) {
  const applied = applyAction(view, c.action);    // 真落一次（返回新状态，不污染原局）
  v = c.score - LOOKAHEAD_W * Math.max(0, foeOutput(applied.state, me) - reply0);
}
```

三个细节都是踩出来的：

- **逐敌求和，不取最大值**。取最大值时"杀掉三个射手之一"几乎不改变结果（另两个还在），
  于是"打瞎对面"这个动作在评分上等于没做——这正是它一开始几乎无效的原因。
- **差分**而不是绝对值：加分的是"这一步让对面少打我一点"，扣分的是"把贵的东西递过去"。
- `LOOKAHEAD_W = 0.35`、只推演前 6 名。全候选各克隆一份状态，一回合克隆几十次只换来
  "第 7 名和第 6 名的细节"。

**目的**：把"我这步之后对面会怎么还手"接进评分，让 AI 学会打瞎射手、撤走肉盾、
不把贵的东西递到刀口上。

**效果**：推演把纯评分的第一名换掉了 **1.5~5.4 次/局**（`aiTrace.lookaheadFlip`）。
用例：威胁值按"打贵的那一刀"计价、摘掉贵目标后威胁值塌 40% 以上。

## 二、跨回合记忆：攒钱目标粘住

**问题**：计划每个动作现算。第 15 回合决定攒英雄把钱冻住，第 17 回合 mood 一抖
（放弃的城被拆了）`savingFor` 变 null，攒的钱当场散回产线。

**改法**：`GameState` 新增按玩家的 `aiIntent`（`types.ts`），`buildPlan` 读写它。
两半机制：

1. **粘性**：上一次的目标还在候选表里、且没超过 `INTENT_TURNS = 8` 回合时，
   新目标必须比它高 `INTENT_MARGIN = 1.3` 倍才许换。两个分数咬得很紧的目标
   （4.72 vs 4.41）每回合互换一次的下场是两边都攒不够。
2. **复活**：整段攒钱分支被跳过（兵掉到 `armyGate` 以下、弃城状态翻掉）时，
   只要目标还站得住（还在卖 / 那座城还升得动 / 废墟还在）就接着攒，
   价格按现在重问，并要求**视野之内够得着**——不然就成了"拿产线换一个到不了的数"，
   那正是上一版掉到 38.8% 的坑。

`buildPlan` 拿的是雾图副本，所以 `aiNextAction` 里有一行把记忆搬回真状态；
这是它唯一一处写状态的地方，不改任何合法动作。

**目的**：让"我这一路就是要攒英雄"能跨回合站住。

**效果**（诚实版）：

| 指标 | 旧版 | 新版 |
|---|---:|---:|
| 攒钱目标"还买不起却丢了"（次/局） | 9.0 | 8.0 |
| 意向复活次数（次/局） | — | 48~70 |

只降了一点，因为**丢目标最多的场合是"城下有人"**——那种时候本来就不该攒
（`urgent` 一票否决），探针分不开"该丢"和"不该丢"。机制本身由三条用例钉住：
跨回合保持、目标消失就换（不抱死目标）、走 `aiNextAction` 时落在真状态上。

## 三、编制换血：满编时解散最差的

**问题**：`grep DISBAND src/core/ai.ts` 是空的，而 `CONFIG.maxUnits = 24` 是硬的。
满编之后招募在 `armySize >= maxUnits` 那一行直接返回 null，新兵永远进不来。

**改法**：新增 `swapOutCandidate()`，排在候选表**之前**、直接返回动作（不进打分）。
理由是"满编造不出更好的兵"是硬状态，放进候选表会被一批四十分的走位压住。

- 替代目标**问采购**（`recruitCandidate(..., ignoreCap = true)`）：不另起一套理解，
  拿到的就是"这一回合它真正想买的那个兵"。
- 只换**明显更好**的（性价比 ≥ `SWAP_GAIN = 1.35` 倍，大致等于跨一代）。
- 只换**后方**的（离敌 5 格内不换）、没有急事时换、攒钱期不换（攒的就是兵时例外）。
- 自限：解散后 `armySize = 23`，同一回合不会再触发。

**效果**：用例两种场景（满编换血 / 有空位不拆兵）都过。但**在 AI 自对弈里它一次都没触发**——
598 次检查全是"编制没满"：

```
换血被挡的原因：编制没满×598
```

也就是说这条改的是"人类会堆满编制"那种局面，AI 自己很少把 24 格填满
（局均 60 回合内结束，收支平衡下兵数在 10~15 徘徊）。这条的价值在人机对局，不在自对弈。

## 四、阵型意图：两翼分工

**问题**：全军只有 `focusCityId` 一个目标，所有人挤一条线压同一座城。
对面把主力摆在那一座前面就够了，剩下几座城等于不存在。

**改法**：新增 `flankSplit()`，产出 `{ flankCityId, flank: Set<unitId> }` 放进 `Fields`。

- 佯攻目标 = 离主攻方向**最远**的那座敌城（隔壁那座不算另一翼）。
- 分派判据：**离那座城比离主攻城近 2 格以上**。这样分派自洽——从左边出发的那一路
  自然去打左边的城，不需要"整体旋转阵型"这种复杂指令。
- 上限全军三分之一（至少 1 个）：佯攻是牵制，不是分兵；分到跟主攻一样厚，两路都打不动。
- 只在"≥2 座敌城 + 陆军 ≥6"时成立。
- `tacticalMoveScore` 的推进量改成按**自己那一翼**的目标城算（`objective`）。

**目的**：逼对面分兵，同时让"从哪个方向来"决定"去哪里"，而不是所有人朝一个点挤。

**效果**：**100~160 单位·次/局**（`aiTrace.flankUnits`），也就是每个回合有 2~3 个兵
被分到另一翼。用例：分派上限、两翼目标选择、兵太少不分兵。

## 五、威胁视野与换家

### 5a 两回合威胁（`TacticalMap.soon`）

**问题**：`exposure` 只估"下回合能吃多少伤害"。六格外磨刀的重骑兵对它等于不存在，
于是 AI 会站在开阔地中间，等它走到跟前才发现被围了。

**改法**（`ai-tactics.ts`）：新增 `soon()`——敌人的**射程 + 两回合移动力**够得着就算威胁，
伤害按现在的站位折算再打 `SOON_DAMP = 0.55` 折（他还要走过来，路上可能被拦）。
地形不参与，这一层是**预警**不是账本，宁可高估。已经算进 `exposure` 的不重复计。
接到走位评分里，权重只有"眼前这一刀"的一半左右。

**效果**（同种子自对弈，走位落点统计）：

| | 落进"两回合威胁圈"的走位 |
|---|---:|
| 旧版 | **36.1%**（406/1124） |
| 新版 | **30.1%**（261/868） |

### 5b 换家姿态（`stance: 'trade'`）

**问题**：`stance` 只有 push / turtle / elite，三条都在回答"怎么打这一仗"，
没有一条回答"**这一仗还该不该在自家城下打**"。两线被攻时它只会来回折返。

**改法**：`buildPlan` 新增第四档，四条件同时成立才触发：家门口有城 ≤ 半血且敌人贴到 3 格、
身价被压到 1.6 倍以下（`TRADE_AT`）、还有 ≥4 个战斗单位、我的人已摸到对面某座城 8 格内。
触发后 `aiNextAction` 改三件事：`commit = true`（全军压城，不再追野）、
`guardCityId = null`（不回去送死）、主攻方向换成**血最少**的那座敌城。
招募按"精兵"花钱。

**效果**：**0~1 次/局**。触发条件严，是刻意的——1.3 太松（略处下风就弃城），
2.0 太紧（等它压到城下才想明白，那时候人已经挪不动了）。用例：崩盘时换家 / 势均力敌不弃城。

## 六、实测：胜负与消融

**量法**：`scripts/ai-duel.ts --old ./baselines/ai-6c3c992.ts`。同一颗种子两边各执一次先手，
所以先手优势和地图不对称都抵消掉。对手是**动手之前那一刻的 `src/core/ai.ts`**
（`git show 6c3c992:src/core/ai.ts` 原样抄一份，只改导入路径），不是几轮之前的基线——
否则前几批改动的收益会混进这一批。

| 实验 | 局数 | 新胜 / 旧胜 / 平 | 胜率 | z | 均回合 |
|---|---:|---:|---:|---:|---:|
| **五条全开**（第一批） | 80 | 37 / 43 / 0 | **46.3%** | −0.67 | 58 |
| **五条全开**（第二批） | 120 | 55 / 65 / 0 | **45.8%** | −0.91 | 59 |
| 两批合计 | 200 | 92 / 108 / 0 | **46.0%** | −1.13 | 58 |
| 关掉两翼 | 40 | 17 / 22 / 1 | 43.8% | −0.79 | 56 |
| 关掉换家 | 40 | 18 / 22 / 0 | 45.0% | −0.63 | 61 |
| 关掉两回合威胁 + 一层推演 | 40 | 20 / 20 / 0 | 50.0% | 0.00 | 53 |

**怎么读**：

1. **没有一个数能和 50% 分开**。120 局那批的 95% 区间是 37–55%；40 局一臂的是 ±15 点。
   要把"46% 和 50%"分开，得每臂 400 局以上——那是另一件事的预算。
2. **但两批独立样本都是 46%**（46.3 / 45.8），加起来 200 局 46.0%。
   这不足以说"更弱"，也不足以说"一样"——正确的说法是：**没有证据说它更强，
   也不能排除它弱几个点**。所以第九节写清了下一轮该先剪哪一刀。
3. **方向是"略偏保守"**。唯一落在 50% 上的那一臂，恰好是把两个"谨慎"项
   （两回合威胁 + 一层推演）关掉的那一臂。谨慎在自对弈里是**对称**的：
   两边都更会躲，等于都没占到便宜，只是把对局拖成"谁先失误"。
   均回合从旧版的 69 掉到 58~59，也符合这个解释——更早分出胜负。
4. **真正的原因在别处**。`UPDATE-2026-11-02-ladder.md` 量过：高级 → 中级（多一整套战术层）
   是 **+0 点**。决策层早就饱和了，再往上叠五层也叠不出胜率。这套 AI 与"认真打的人"的差距
   不在"每一步算得更细"，而在人类会**抢时代、控节奏、选战场**——那三件事它现在才刚有雏形。

## 九、没做到的

- **量不出"更强"**。要证明对人更强，只有第三条尺子（人类打法脚本）。
- 换血在 AI 自对弈里从没触发（编制从不上限），只证到"条件正确"，没证到"实战有用"。
- 换家触发太稀（0~1 次/局），样本不足以判断它对不对；目前只能靠用例守"别乱弃城"。
- 跨回合记忆的收益被"城下有人就攒钱"（`urgent`）这条硬规则盖住了大半。
- **点估计偏低（46%），下一轮该先剪这两刀**（按证据强弱排序）：
  1. `LOOKAHEAD_W` 0.35 → 0.15，或让它在 `all.commit` 时完全失效
     （已经决定破城了还在犹豫，正是"谨慎拖慢节奏"的典型）；
  2. `soon()` 的权重 `12 + min(30, cost*0.1)` 砍一半。
  这两条的消融臂是唯一摸到 50% 的那个组合，方向明确；但**必须先量再改**，
  8 个 40 局一臂的样本只够说"可能有用"，不够说"确实更好"。

## 十、追问之后补的一刀：人类打法脚本

五条改完，胜率没动。那么"AI 到底差在哪"这个问题必须换个问法：
**一个什么都不计算的玩家，能打成什么样？**

`scripts/script-ai.ts` 是这个问题的答案载体——**六条常识，零评分**：

1. 能打就打（能一击打死的优先，否则打最近的）；
2. 贴着敌城就砸城墙（挑血最少的）；
3. 钱够就升主城（时代最高的那座），每回合一次；
4. 先铺到"每座城两个经济单位"，之后只造**买得起的最强陆军**；
4b. 城格被自己人站满时，把里面的人挪出来一个（不然产兵停摆）；
5. 全军朝最近的敌城走，不做任何威胁评估。

它不做的事：不算交换比、不看对面射程、不集火、不守城、不分兵、不弃城、
不换血、不攒大件、不评估"这一仗该不该打"。

**结果（同种子成对，30 种子＝60 局，era3、20×20、上限 160 回合）**：

| | 局数 | 胜负平 | 胜率 | 95% 区间 | 均回合 |
|---|---:|---:|---:|---:|---:|
| 六条规则脚本 vs **当前 AI** | 60 | 24 / 30 / 6 | **45.0%** | 33–58% | 97 |

把两个数摆在一起看：

```
五条"改进"（对上一版）          46.0%  [39–53]
六条规则脚本（对当前 AI）        45.0%  [33–58]
```

**这套 AI 打不过一个只会"造兵、升主城、往对面走、见谁打谁"的脚本，只是打平。**

### 该怎么读

1. **AI 缺的不是算术。** 它算交换比、算威胁圈、算编队配比、算性价比、算跨回合计划，
   对方一样都不算，结果打平。多算的部分没有换成胜势。
2. **也不缺"更多战术层"。** 上一张表：高级 → 中级（多整套战术层）= +0 点。
3. **差的是"把一条策略从头执行到尾"。** 脚本有两条铁律，AI 一条都没有：
   - **钱永远先给主城升级**（`抢时代`），脚本每次都是这个优先级，从不改主意；
   - **只在一条线上推进**，脚本从不分兵、不弃城、不换打法。
   而 AI 的攒钱目标实测**每局中途丢掉 8~9 次**，stance 在 push/turtle/trade 之间摆，
   进攻方向每回合重算——它每一步都"更聪明"，整局却没有一条贯彻到底的线。
4. **这也是"真人不用计算就能赢"的机制解释**：真人赢的不是逐格伤害，
   是三件不需要计算的事——**抢时代、攒够一波再上、只打一个方向**。
   第一件值多少？`UPDATE-2026-11-02-ladder.md` 量过：**白送一个时代 = +27.5 点**，
   比"把决策水平从初级提到中级"（+23.3 点）还贵。AI 恰恰把这件事放在了
   "每回合重新和英雄/大件/废墟比一遍"的队列里。

### 六条规则的边界（别过度解读）

- 60 局的区间是 33–58%，所以只能说"打平"，不能说"脚本更强"。
- 脚本也不是"真人的下限"：它不会撤退、不会佯攻、不会换家，输的 30 局里
  大多数是被反推回来打死的。真人比它强的地方，恰恰是"哪一仗不该打"。
- 但它证明了**至少这一档的胜率不需要每秒计算**。要往上走，缺的是执行纪律，
  不是评分公式。
