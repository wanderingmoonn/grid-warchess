# 版本 0.3.8 · 2026-11-01 · 改名、特性数据化、群岛高山

一句话：**四个工兵换了名字，载具和兵营的能力写进了兵种数据，群岛不再"每张图必有高山"。**
规则数值一个没动（除了前进基地产兵九折，见第三节）。

---

## 一、四个单位改名（链式替换）

| id（未变） | 原名 | 新名 | 图标字 |
|---|---|---|---|
| `laborer` | 劳工 | **奴隶** | 工 → 奴 |
| `miller` | 磨坊主 | **民夫** | 坊 → 夫 |
| `engineer` | 工程师 | **劳工** | 师 → 劳 |
| `foreman` | 厂长 | **工程师** | 长 → 师 |

这批名字构成一条首尾相接的替换链（工程师→劳工 之后，新"劳工"不能被 劳工→奴隶 再吃一次），
所以是**一次性同步映射**，不是按顺序连改。id、时代、造价、攻甲血、建造点数全部没动，
存档与联机房间里的 id 引用照旧成立。

## 二、载具「装载」写成数据

以前的写法是 `transport: true` + `capacity: N`，航母的机位另存在一张 `DECK_SPECS` 常量表里。
现在统一收在兵种自己的 `carry` 上：

```ts
carry: {
  hold?: { max: 2, allow: { domains: ['land'] } },      // 货舱：陆军装进来，随船走，途中不能作战
  deck?: { max: 4, launchRange: 2, allow: {...} },      // 甲板：战机停驻，能起飞
}
```

- 两个槽位独立：渡船只填 `hold`，航母只填 `deck`，两栖攻击舰 `hold 4 + deck 2` 同时成立；
- `allow` 是准入白名单（兵种 id / 类别 / 陆海 / 地空）+ 黑名单，条件之间是"与"；
- 那张 `DECK_SPECS` 表**删掉了**，加一艘能带飞机的船只改兵种数据一处；
- 老存档里的 `transport + capacity` 仍然认，翻译只在一处（`carryOf`）。

## 三、兵营「产兵」写成数据

以前是 `barracks: true` 一个布尔，于是所有兵营除了攻/甲/血之外完全一样。现在是：

```ts
produce: {
  units?: ['militia', 'archer'],  // 能产哪些兵（不写 = 按时代与城市供给放开）
  everyTurns?: 2,                 // 每几回合一批（默认 1 = 当回合）
  costScale?: 0.9,                // 造价倍率（默认 1）
  pop?: 1,                        // 这座营占几格编制（默认 0）
}
```

四条都在生效：白名单外的兵**面板里根本不会列出来**（规则与界面用同一个判据，不会
"面板能点、点了被拒"）；生产间隔记在营身上（`custom.lastProduceTurn`），存档跟着走；
造价倍率按资源包逐项缩放；`pop` 计入编制统计。

**当前只有前进基地（camp5）做了差异**：在它这儿产兵便宜一成（`costScale: 0.9`），
理由是它把兵工厂和补给站搬到了前线。其余六座营走默认值，行为和 0.3.7 完全一致。

> 这一条是本版唯一会改变手玩数值的地方。如果你希望这版是纯结构改造，
> 把 `config.ts` 里 camp5 的 `produce` 改回 `{}` 即可。

## 四、群岛地貌：高山不再"固定生成"

**问题**：群岛的高低场会按排名摊平成均匀分布（为了海/陆比例不随种子漂），
于是阶梯里的"最高 1% = 高山"变成了**精确配额**——不管这张图多平，那几格一定变高山。
80 张群岛图里 68% 长出了高山，而且常常只是孤零零一两格。

**改法**：新增可选的 `mountainGate`——归一化**之前**的原始海拔要够高，那一格才允许是高山，
否则降回下一档（台地）。群岛：配额 1% → 0.4%，门槛 **0.72**。

| 指标 | 改前 | 改后 |
|---|---|---|
| 长了高山的图 | 68% | **39%** |
| 高山占格子 | 0.5% | **0.15%** |
| 平均每图 | 1.8 座 | **0.51 座** |
| 海 / 浅滩 | 27.7% / 7.6% | **27.7% / 7.6%（完全一致）** |

高原 / 峡谷 / 沼泽 / 大川的配方没有 `mountainGate`，走的分支一字未变。
