# 肉鸽模式 · 设计稿 v1（2026-11-19）

> 一句话：**一局 run 是一串“短战斗 + 撤离 + 换兵”的循环**，城市是唯一的持久资产，
> 金币只能靠战果赚，遗物靠“打谁”而不是“抽到谁”。

---

## 1. Run 结构

- **3 幕 × 3 场 = 9 场**（第 3 场为幕 Boss）。目标总时长 60~75 分钟。
  - 早先按 12 场算过，按每场“战斗 6~10 手 + 撤离 1~2 手”≈ 8 分钟，12 场就是 96 分钟，
    对肉鸽太长。9 场是上限，首版先做 3 场切片再定。
- 每场结束后：**结算 → 三选一 → 选下一场路线**（2~3 个候选，战前可见敌人构成）。

## 2. 单场流程

```
开场（你带进来的兵摆在城里/城边）
  → 战斗阶段（无回合硬上限，但有增援压力）
  → 敌人全灭 → 进入「撤离阶段」
  → 撤离结束 → 结算金币 → 奖励三选一 → 选路线
```

### 撤离阶段（新增，核心机制）

- 触发：**敌方全部单位清空**那一刻，倒计时开始。
- 时长：普通关 **2 手**，Boss 关 **1 手**，有护送 / 拆营 / 宝箱未拿的任务关 **3 手**。
- 规则：只有**走进城内**的单位算带走；倒计时结束仍在城外的，按身价 **50%** 折金币（“阵亡抚恤”）。
- 设计意图：让“最后一波贪不贪”有明确的代价。增援事件一般压在倒计时最后 1 手，
  所以“多打一手”经常等于“回不去”。
- **入城数受兵额限制**（见 §3）：兵额满了的，多出来的排不进去，必须当场选。

## 3. 兵额（= 城市容量）

**兵额 = 这一关结束时能进城、并被带进下一关的单位数。不另设数字面板，空间就是兵额。**

| 城的状态 | 兵额 |
|---|---|
| 初始城（2×2，4 格） | 4 |
| 城墙升级（3×3） | 9，但贵，且要吃掉一场的经济 |
| 兵营附属 | +2 |

- 驻军本来就有加成（城内 +3 护甲、每回合回血 8%），兵额让“回城”同时具备收益和代价：
  城里挤满 = 没有机动纵深。
- 兵额满了时，**新兵种卡的价值归零**——这就是“换人还是强化”的来源。

## 4. 金币

**城市收入砍掉**（也不造经济单位）。金币只有一个来源：战果。

```
结算 = 基础（关数 × 40）
     + 撤离带走的人数 × 15
     + 提前结束（每省 1 手 +8，上限 +40）
     + 拆掉营地/前哨（+60）
败退（未清场就主动结束）：只给“已消灭敌人 × 三成”
```

- 常数要按兵种造价校准（长弓 90 这个量级），上面的数只是占位。
- 没有收入 → 拖延无收益 → 战斗自然变快；同时必须保留“败退保底”，否则一次崩就静默死亡。

## 5. 奖励与遗物

### 战后三选一（含“不选”）

- **兵种卡 70%**：解锁该兵种进本 run 池 + 一次免费招募；
- **战术卡 30%**：一次性（空投援军 / 改一片地形 / 免费升级）；
- **永远并列一个「不选，拿钱」**（+60~100 金）。没有收入的体系里，这是唯一的止损阀。

### 遗物（四类来源，按可靠性排序）

| 来源 | 可靠性 | 说明 |
|---|---|---|
| **强力敌人固定掉落** | 必得 | 地图上标出“这个敌人带 X”，可以绕开 |
| **宝箱** | 必得 | 地图上 1 格物件，走上去即开（事件 `enter` 触发） |
| **事件奖励** | 看选择 | 护送 / 抉择类事件，完成给 |
| 三选一 | 已移除 | 不再从随机池里抽，避免“运气决定构筑” |

遗物池草案（每个都绑定一个“守门敌人”或一种事件）：

| 遗物 | 效果 | 来源 |
|---|---|---|
| 铁壁 | 城防 +2，城内单位减伤 15% | 重装守卫（固定） |
| 瞭望 | 视野 +1，对空 +20% | 空袭者（固定） |
| 工事 | 每场战后免费修城一次 | 攻城车（固定） |
| 驮马 | 兵额 +2 | 宝箱 |
| 号角 | 第 1 手的增援免费（应急兵 2 个） | 事件 |
| 军械 | 城内单位战后回满 HP | 事件 |
| 吝啬鬼 | 「不选拿钱」金额翻倍 | 三选一（稀有） |
| 捷径 | 路线候选从 2 个变 3 个 | 宝箱 |

## 6. 事件（用现成的事件系统）

事件已支持：`turn / unitDied / enter` 触发，动作有 `spawn / say / doctrine / deploy / terrain / reveal / gold`。

### 护送任务（示例）

```
when: { kind: 'turn', at: 2 }
do:   [ { kind: 'say', text: '车队从东侧进入，护它到城里。' },
        { kind: 'spawn', owner: 'A', units: [{ type: 'cart', x: 18, y: 3 }] } ]
goal: { kind: 'escort', seat: 'A', zone: <你的城>, unitType: 'cart', label: '车队' }
reward: 遗物【军械】或 120 金（二选一）
```

- 护送的单位若在撤离阶段没进城 → 按普通单位抚恤，**但任务奖励作废**；
- 提示：`escort` 目标已经在规则里，`zone` 就是城的 2×2 格。

### 其它可复用的事件类型

| 类型 | 触发 | 作用 |
|---|---|---|
| 伏兵 | `enter`（走进某片林子） | `spawn` 敌人 + `reveal` 那片 |
| 增援 | `turn`（撤离倒计时最后 1 手） | 封退路，逼玩家算清“贪一手”的代价 |
| 抉择 | `enter`（宝箱旁） | `say` 两个选项 → 拿钱 or 拿遗物 |
| 地形变化 | `turn` | `terrain` 把桥打断 / 放水 |

## 7. 敌人池与主题

- 按“幕 + 威胁等级”加权抽，但**每场主题固定**：空中场 / 攻城场 / 伏击场 / 重甲场。
  纯随机 + 迷雾 = 无解感。
- 敌方只有**营地 / 前哨**（耐久低、拆了给钱），**不设可占领的城**——
  否则“抢敌人的城”会把“只有我的城能带兵”这条规则搞乱。

### 7.0 敌人池分强弱（2026-11-19 定）

敌人也从池子里抽，但**分两个池**：前 60% 的战斗关走**弱怪池**，之后走**强怪池**。

- 3 场 → 2 弱 1 强；5 场 → 3 弱 2 强；9 场 → 5 弱 4 强。
- 为什么分池而不是"按威胁加权抽一个"：加权会出现"第 1 关就撞骑士"，玩家没处躲；
  分池把难度曲线写在**池子边界**上，一眼能看懂也好调。
- 池子成员按"处理难度"而不是纯数值挑：骑士/长弓/十字弩/铰炮这类"难处理"的进强池。
- 抽取是**有放回**的（小队里两个民兵很正常），但同一兵种每多抽一个权重就减半，
  避免整队同型；命中地图标签的兵权重 ×2（见 §7.1）。

实现：`src/core/roguelike/enemy-pools.ts`（`poolForStage` / `pickEnemies`，确定性随机）。


### 7.1 敌人 ↔ 地图类型绑定（2026-11-19 加）

敌人不是"丢到任意地图上都成立"的。**先定地图类型，再从相配的敌人里抽**，
而不是先抽敌人再随便配张图：

| 地图类型 | 适合的敌人 | 不适合的 |
|---|---|---|
| 林地（多森林） | 伏击者、斥候、远程 | 攻城器械（走不动） |
| 城郊（有建筑/废墟） | 步兵线、攻城 | 纯骑兵（没纵深） |
| 关隘（窄道） | 重装、盾墙 | 大群轻骑（展不开） |
| 水岸（河/浅滩） | 两栖、远程 | 重甲（过不了水） |
| 开阔平原 | 骑兵、远程对射 | 伏击型（没处藏） |

实现两条路子选一条，别都做：

1. **敌人写偏好**：每个敌人带 `arenaTags: ['forest','ambush']`，抽敌人时按地图标签加权；
2. **地图写名单**：每种地图类型维护一份"允许的敌人 id"，抽的时候只在名单里挑。

倾向 **1**：一张图可以有多个标签、一个敌人也能适配多种地形，不会因为漏登记抽不到人。

### 7.2 强力敌人配专属地图

守门人 / Boss 这一档**不参与随机**，直接配一张手工地图：

- 用现成的 `LevelDef.map`（`rows` + `citiesA`），写进 `stages.ts`；
- 可以写死"只能从哪个方向进"（窄口）、"哪块地形必须存在"（桥/高地）——随机生成器做不到；
- 好处：**每幕高潮是设计出来的，不是抽出来的**；代价：内容成本高，一期只做 1~2 张。

## 8. 失败与重开

- 丢城：给一次**弃城撤退**——全城单位按 50% 折金，run 继续但从此无城（只能靠战后兵额临时带兵）。
  城直接爆掉 = 更可玩，也比“结束 run”更少挫败。
- **重开本关**：每幕一次，保留金币和遗物，不保留本关战果（也不给奖励）。
- 兵额为空且没钱：run 结束。

## 9. 与现有系统的对接

| 需要 | 现状 |
|---|---|
| 无城敌人小队 / 营地 | ✅ `cityless` 席位已有（兵打光即输） |

| **撤离阶段判定** | ❌ 新造：敌人全灭 → 倒计时 → 入城结算 |

| **随机小队与宝箱生成** | ❌ 新造 |

## 10. 验收指标（别看时长，看这三条）

| 指标 | 目标 | 超标说明 |
|---|---|---|
| 单场行动次数（中位数） | 6~10（含撤离） | >15：敌人太硬或地图太大 |
| 一次 run 里被选的卡片种类 | ≥6 | 说明三选一没有真选择 |
| run 完成率 | 15~25% | 太高=太简单，太低=惩罚过重 |

## 11. 垂直切片范围（第一步只做这些）

1. **3 场手写遭遇**（第 1 关无城敌人 / 第 2 关带营地 / 第 3 关带遗物守门人）；
2. **撤离阶段**（敌人全灭 → 2 手倒计时 → 入城计数 → 抚恤折算）；
3. **一次三选一**（兵种卡 / 战术卡 / 不选拿钱）；
4. **一次路线选择**（2 个候选，战前可见敌人）；
5. 不做：宝箱、护送、随机生成器、局外解锁、遗物表全量。

够 10 分钟体验就能判断“这个循环成不成立”。

## 12. 决策记录

### 2026-11-19 · 兵种分支暂缓

- 做过两版：按战术角色（步战/远程/…）→ 每条只剩 3 个兵，抽卡没有随机性；
  改成按主题线（冷兵器/奇想/修真/信息化/空军/海军）→ 冷兵器 113 个、奇想 72 个，
  随机性解决了，但**一代可用兵种严重不均**：信息化/空军/海军是 **0**，奇想 3 个，冷兵器 20 个。
- 结果"选哪条线"退化成"能不能在第一关抽到牌"，不是有意义的选择；而且分支↔扩展包是硬编码映射。
- **决定：先不接线上，代码留在 `src/core/roguelike/branches.ts`（有 978 项测试覆盖），
  界面与 runner 都不要引用它。** 后续两条路：
  1. 分支自带起始时代（信息化从 3 代起）——最省事；
  2. 拆成两层：**包 = 卡池**、**分支 = 权重**。
