# 事件系统总览

一局关卡里会发生很多"不该由玩家操作、但又不是常规规则"的事：第 7 次行动时北面裂开、
主角走进山谷就塌方、守到第 15 次行动援军抵达……这些都写在 **`events`** 里。

一句话：**一条事件 = 「当 X 就做 Y」。默认只触发一次。**

```json
{
  "id": "ambush",
  "when": { "kind": "turn", "at": 7 },
  "do": [
    { "kind": "say", "text": "北边的林线上冒出人影——是骑兵。" },
    { "kind": "spawn", "owner": "B", "units": [{ "type": "horseman", "x": 6, "y": 2 }] }
  ]
}
```

`id` 不只是名字：**"这条事件触发过没有"是按 id 记的**。改 id 等于换一件事。

---

## 一、什么时候（`when`）

### 叶子：五种基本判断

| 写法 | 含义 |
|---|---|
| `{ kind: 'turn', at: 7 }` | 第 7 次**行动**（不是第 7 轮；两家局一轮 = 两次行动） |
| `{ kind: 'turn', at: 7, op: '<=' }` | 第 7 次行动之内。`op` 可选 `>=`（默认）`<=` `=` `>` `<` |
| `{ kind: 'unitDied', owner: 'A' }` | A 的任何兵死了（可再加 `type` 限定兵种） |
| `{ kind: 'enter', zone: {...} }` | 有单位从区域外走进来（可加 `owner`） |
| `{ kind: 'fired', id: 'ambush' }` | 另一条事件**已经发生过** |
| `{ kind: 'fired', id: 'trap', times: 3 }` | 已经发生过 **3 次**（只有 `repeat` 事件次数会超过 1） |
| `{ kind: 'cityEra', seat: 'B', op: '>=', value: 2 }` | B 家**最高的那座城**的时代等级 |
| `{ kind: 'cityHp', seat: 'B', op: '<=', value: 20 }` | B 家**最低的那座城**的血量 |
| `{ kind: 'gold', seat: 'A', op: '>=', value: 300 }` | A 家手上的金币 |

前三种是**事件型**（"发生了"），后三种是**状态型**（"现在是什么样"）。
`fired` 介于两者之间：它记的是历史，但一旦成立就永久成立。

### 组合：`all` / `any` / `not`

```json
{
  "all": [
    { "kind": "turn", "at": 9, "op": "<=" },
    { "kind": "fired", "id": "ambush" },
    { "not": { "kind": "enter", "zone": { "x0": 2, "y0": 2, "x1": 3, "y1": 3 } } }
  ]
}
```

可以互相嵌套，**最多 3 层**。空组是错误（不是"永远成立"）。

### 一个必须理解的区别

| 类型 | 例子 | 什么时候为真 |
|---|---|---|
| **状态型** | `turn >= 5`、`cityHp <= 20` | 每手都能判"现在真不真" |
| **边沿型** | `unitDied`、`enter` | 只在"刚刚发生"的那一手为真 |

所以 `enter ∧ unitDied` 的意思是"**同一个动作里**既有人进区域又有人死"，不是
"之前死过人、后来有人进区域"。后者要写成两件事 + 一个 `fired`。

## 二、做什么（`do`）

动作按数组顺序执行，**每一条都会生效**（没有"失败就跳过"）。

| 动作 | 作用 |
|---|---|
| `{ kind: 'say', text }` | 往战报写一句（双方都看得到）。**带 `say` 的事件会把战报自动展开** |
| `{ kind: 'spawn', owner, units }` | 凭空刷兵，不看钱不看产线，只看格子站不站得住 |
| `{ kind: 'doctrine', seat, strategy }` | 改这一席 AI 的打法：`auto` / `rush` / `boom` / `hold` |
| `{ kind: 'deploy', seat }` | 让"中途登场"的席位上场（放城 + 摆它写好的兵） |
| `{ kind: 'terrain', zone, to, only? }` | 改地形（炸桥、塌方、水淹） |
| `{ kind: 'reveal', zone, turns? }` | 点亮一片区域（`turns: -1` = 一直亮） |
| `{ kind: 'gold', seat, amount }` | 加 / 扣金币（负数扣，封底 0） |
| `{ kind: 'win', seat }` | **直接判这一席胜利**，一局只认第一次 |
| `{ kind: 'branch', when, then, else? }` | 按条件分两支（下面细说） |
| `{ kind: 'damage', zone, amount, ignoreArmor?, times?, owner? }` | 对区域内的每个单位造成伤害 |

### 区域伤害：炸一片

```json
{ "kind": "damage", "zone": { "x0": 5, "y0": 5, "x1": 8, "y1": 8 },
  "amount": 6, "times": 3, "ignoreArmor": true }
```

- 不写 `ignoreArmor` 就**走护甲**（甲先减，最低 0）；写了就是真的无视。
- `times` 是**多段**，每段单独过甲——"3 段 6 点"打重甲比"1 段 18 点"更弱。
- 不写 `owner` 就是**不分敌我**；写 `"owner": "B"` 只打 B 家。
- 不针对城，只打单位。
- 打死的单位**会记进这一手**，所以同一批里等 `unitDied` 的事件能看到它。

### 分支：同一次触发里走两条路

```json
{
  "kind": "branch",
  "when": { "kind": "gold", "seat": "B", "op": ">=", "value": 500 },
  "then": [{ "kind": "say", "text": "敌军补给充足，全线压上。" }],
  "else": [{ "kind": "say", "text": "敌军补给不足，只派了一支小队。" }]
}
```

三条语义：

1. **条件读的是"执行到这一步时"的局面**，不是事件触发那一刻。所以"先加钱、再判断"能工作。
2. **边沿条件仍指"这一手"**：`enter` / `unitDied` 写在分支里，判的还是这次动作的差量。
3. `then` / `else` 各自是一组动作，可再嵌（最多 3 层）；空分支校验报错。

**分支真正的用武之地是 `repeat` 事件**：两条"相反条件"的事件各自只会触发一次，
第二次就不响了；分支每次都按当时的局势选一支。

## 三、引擎怎么跑

理解这一段，才能解释"为什么我写了却没触发"。

1. **每次动作之后检查一次**（`applyAction` 结束）。没有"实时轮询"。
2. **只比较动作前后的两个局面**：这一手死了谁、谁挪了位置。事件自己刷出来的兵
   **不参与**这个比较——否则"在区域里刷一个兵"会立刻触发"有人进入区域"，自己点燃自己。
3. **多遍扫描，最多 3 遍**：第一遍执行 A，第二遍引用 A 的 B 才看得到。
   每遍用"这一遍开头的记录"判断，所以**和事件在数组里的先后无关**。
4. **一次动作最多 32 条事件生效**，超了打一条控制台日志（不静默）。
5. **触发记录存在局面里**（`fired` 数组 + `counts` 次数），不放在程序里。
   理由：AI 会"试走"每一种走法，程序里的状态会被试走改乱。

第 5 条决定了另一个约束：**条件只能读局面**，不能读随机数、时间、外部状态。
读了的话，试走和真走会算出两套答案。

## 四、六种常见剧本

### 1. 伏击

```json
[
  { "id": "ambush", "when": { "kind": "turn", "at": 7 },
    "do": [
      { "kind": "say", "text": "北边的林线上冒出人影——是骑兵。" },
      { "kind": "reveal", "zone": { "x0": 4, "y0": 0, "x1": 9, "y1": 2 } },
      { "kind": "spawn", "owner": "B", "units": [{ "type": "horseman", "x": 6, "y": 1 }] }
    ] }
]
```

`reveal` 和 `spawn` 一起写：刷兵的同时把那片点亮，玩家能看见"那儿有人"。

### 2. 限时任务

```json
[
  { "id": "deadline", "when": { "kind": "turn", "at": 9 },
    "do": [{ "kind": "say", "text": "桥被炸断了。" },
           { "kind": "terrain", "zone": { "x0": 12, "y0": 8, "x1": 13, "y1": 8 }, "to": "deep" }] },
  { "id": "win-early",
    "when": { "all": [
      { "kind": "enter", "zone": { "x0": 2, "y0": 2, "x1": 3, "y1": 3 }, "owner": "A" },
      { "kind": "turn", "at": 9, "op": "<=" } ] },
    "do": [{ "kind": "say", "text": "信使在天亮前到了。" }] }
]
```

### 3. 波次（第 N 次才发生）

```json
[
  { "id": "trap", "when": { "kind": "enter", "zone": { "x0": 6, "y0": 6, "x1": 8, "y1": 8 }, "owner": "B" },
    "repeat": true, "do": [{ "kind": "say", "text": "轰。" }] },
  { "id": "blow", "when": { "kind": "fired", "id": "trap", "times": 3 },
    "do": [{ "kind": "terrain", "zone": { "x0": 6, "y0": 6, "x1": 8, "y1": 8 }, "to": "deep" }] }
]
```

`trap` 必须写 `repeat: true`——普通事件只触发一次，次数永远到不了 2。

### 4. 条件援军

```json
{ "id": "rescue",
  "when": { "all": [
    { "kind": "turn", "at": 5, "op": ">=" },
    { "kind": "cityHp", "seat": "A", "op": "<=", "value": 20 } ] },
  "do": [{ "kind": "say", "text": "城墙塌了一半，援军终于到了。" },
         { "kind": "spawn", "owner": "A", "units": [...] }] }
```

### 5. 看局势分支（每次进来都判断）

```json
{ "id": "wave", "when": { "kind": "turn", "at": 6 }, "repeat": true,
  "do": [
    { "kind": "gold", "seat": "B", "amount": 100 },
    { "kind": "branch",
      "when": { "kind": "gold", "seat": "B", "op": ">=", "value": 400 },
      "then": [{ "kind": "spawn", "owner": "B", "units": [...] }],
      "else": [{ "kind": "say", "text": "敌军还没攒够补给，这一手按兵不动。" }] } ] }
```

### 6. 剧情判胜

```json
{ "id": "reunion", "when": { "kind": "fired", "id": "talk" },
  "do": [{ "kind": "say", "text": "两支部队会合了。" },
         { "kind": "win", "seat": "A" }] }
```

给"胜利条件写不出来的赢"用：剧情走完才算赢。

## 五、在编辑器里怎么加

**入口**：开始对局 →「编辑器」→ 选一张关 →「复制成我的关卡」→ 顶部「事件」。

面板左边是事件卡片，右边是地图（选区域、点落点都在这儿）。

- 条件那一行的下拉，上半是五种基本判断，下半是「改成组合」——选「全部满足」
  就把这个条件换成一个组，组下面会多出「+ 条件」「+ 或组」。
- 动作那一行的下拉，最后一项是「如果…就…（分支）」。
- 每个组 / 分支右边有 `×` 删掉；根条件、根动作不能删（可以改成单条件）。

编辑器里还有一份**速查**（面板右上角），内容和本文一致，只是压缩成一屏。

## 六、校验会拦什么

| 写法 | 结果 |
|---|---|
| 引用了不存在的事件 id | **报错**：条件永远不会成立 |
| A 等 B、B 等 A | **报错**：两条都不触发 |
| 要它发生 2 次，但它不是 `repeat` | **报错**：永远等不到 |
| 引用 `repeat` 事件但没写次数 | 提醒：第一次之后恒真 |
| 空组 / 空分支 / 嵌套超过 3 层 | **报错** |
| 无条件引用自己 | **报错** |
| 无城席位写 `cityEra` / `cityHp` | 提醒：这一条恒为 0 |
| `turn` 用 `=` | 能用，但某次结算没跑到就永久错过（默认 `>=` 就是为了这个） |

改完点「保存」会跑一遍校验，问题列在面板底部。

---

## 七、目前没有做的

- **随机分支**（条件只能读局面，随机数会让 AI 试走和真走算出两套答案）
- **循环 / 重复 N 次**（用计数条件 + 多条事件能表达）
- **延迟 / 等待**（事件是"每手检查一次"的纯函数，加延迟就不是了）
- **自定义计数器**（现在只能"某条事件发生了 N 次"）
- **拖拽式条件编辑**（现在用缩进树，数据不用改也能换）

字段的完整定义和更多写法见 **[关卡开发指南](GUIDE-LEVEL-AUTHORING.md)** 第 6 节。
