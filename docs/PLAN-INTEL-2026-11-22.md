# 侦查与情报：设计与分阶段计划（2026-11-22）

> 现状是"AI 完全没有侦查概念"，不是"侦查做得不好"。所以这份计划的核心不是加一个
> 派兵动作，而是先让 AI **知道自己在猜**，再让它**派人去不猜**。

## 一、现状核实（代码事实）

| 事实 | 位置 | 含义 |
|---|---|---|
| AI 只取 `playerView(s, me).state` | `ai-v3.ts:8501` | 丢掉了 `ghosts`（记忆单位，带 `seenAt`）、`visible`（可见格）、`rememberedCities` |
| AI 从不读 `memory` | 全仓库 | 早期看到的情报**全部作废** |
| 基础雾只遮单位，不遮城市 | `fog.ts` 不裁 `cloned.cities`；`ui/board.ts:1128` 的 `lit` 只在 blackout 下才判 | 默认规则下**玩家也看得见所有城的位置和血量**，AI 与玩家一致 |
| 浓雾蔽野（blackout）下才有三档 | `ui/board.ts:1116`、`ui/panel.ts:1632` | 玩家：活数据 / 旧情报 / 未探明；AI：**仍拿全量城 + 真实血量 → 这一步是真作弊** |
| 敌方战力只算可见单位 | `armyStrength` 遍历 `unitsOf(view, me)` | 看不见的兵 = 0 → 投影比虚高 |
| 敌方产能只看可见建筑 | `productionCapacity` | 看不见的军营/工厂不计 |
| 斥候在 AI 眼里是普通兵 | `unit-value.ts:72`（stealth 折 0.06） | 没有"掩体偏好"、没有"蹲点不开火"、也没有模拟"敌人看不见我" |
| 潜行规则对蹲点友好 | `abilities.ts:194` | 森林/丘陵 + **未出手** → 贴脸才发现；**移动不破潜行**；视野是纯圆，地形不挡视线 |
| `intelKnown` 恒为 false | `ai-plan.ts:69` | 留给这一轮的接口，目前没有消费者 |

**第 3 条的结论**：默认规则下"城市全知"不是 AI 作弊，是规则本身如此（玩家同样全知），
不需要改。要修的是 **blackout 下 AI 与玩家信息不对等**——那条只在浓雾扩展里生效，
所以放到最后一步（对默认对局零影响，可以先做零变化验证）。

## 二、拍板的口径（2026-11-22）

1. **情报过期**：记忆按 `0.85^age` 衰减，`age > 8` 归零（age = 当前行动序号 − `seenAt`）。
2. **置信度可调**：`PLAN_TUNING.intelTrust`（0~1），默认 **0.4 = 保守**。
   收缩公式 `ratio' = 1 + (ratio − 1) × (intelTrust + (1 − intelTrust) × conf)`，
   **只作用于 attack 阈值，不动 holdFire**（上一项的教训：更保守会让平局率涨）。
3. **城市信息与玩家一致**：默认规则不动；blackout 下让 AI 也只见"活 / 记忆 / 未探明"三档。
4. **侦查单位可以牺牲**：死亡 → 冷却 12 回合；连续死 2 次 → 冷却 25 回合。

## 三、分阶段计划

### 阶段 0：先量"信息差"（不改任何行为）

**要解决的疑问**：看不见到底把决战判断扭曲了多少？如果扭曲很小，后面全是白做。

- 新增 `npm run probe:intel`：同一局面分别用 `playerView(s, me, true)`（全图）和
  迷雾视图算 `decisiveOf` 的 ratio，输出差值分布（中位数 / p25 / p75 / 最大）。
- 在真实对局里抽样：每 5 回合记一次差值与"目标城 age"。

**验收**：中位差 ≥ 0.15 → 继续；< 0.05 → 停止这一项，转去查采购/编队（说明瓶颈不是情报）。

#### 阶段 0 实测结果（2026-11-22，123 个样本）

同一局面的同一时刻，迷雾视角 vs 全图视角各算一次 `decisiveOf`，差的定义是
`ratio(迷雾) − ratio(全图)`，正数 = 高估自己（看不见对面）。

| 队列 | 样本 | 中位差 | p25 | p75 | 迷雾高估占比 | 敌方战力漏算中位 |
|---|---|---|---|---|---|---|
| Q1 12×12/era2 | 4 | +0.25 | +0.08 | +0.25 | 75% | 372 |
| Q2 16×16/era3 | 53 | +0.25 | −0.06 | +4.62 | 70% | 3783 |
| Q3 24×24/era2 | 22 | +0.65 | +0.33 | +1.66 | 86% | 560 |
| Q4 24×24/era4 | 44 | +0.95 | +0.60 | +1.30 | 98% | 4060 |
| **合计** | **123** | **+0.67** | **+0.19** | **+1.66** | — | — |

结论：**远超阈值，阶段 1 继续**。三点值得记：

- 大图 / 高时代越严重（Q4 中位 +0.95、98% 的样本都在高估）：地图越大，看不见的部队越多。
- Q2 的 p75 到 +4.62 —— 对面主力完全在雾里时，分母接近 0，判断会从"打不动"直接翻成"打得动"。
- 漏算的敌方战力中位数是几千量级（Q2 3783、Q4 4060），说明"只算可见单位"不是小偏差，是把分母砍掉一大半。

复现：`npm run probe:intel`（四条用例约 3 分钟；`--every` / `--case` / `--verbose`）。
Q4 那局 222 回合、单局 119 秒，是最慢的一条。


### 阶段 1：记忆计入 + 过期（修"看不见 = 0"）

**要解决的问题**：AI 把自己看见过的东西全忘了，等于每回合从零开始判断。

- AI 入口保留 `PlayerView`，不再只取 `.state`。
- `foePower = 可见单位战力 + Σ 记忆单位 × 0.85^age`（age > 8 丢弃）。
- 敌方产能：可见建筑 + 记忆城市；看不见的部分不计（保守）。
- 新增 `IntelState { conf, age, live, remembered, unknown }`，从"目标城周围 N 格最近一次可见"算。

**验收**：
- `probe:intel` 新增 6 条断言：看不见计 0、记得的按衰减计、过期归零、记忆比可见少算、
  目标城 age 正确、conf 随 age 单调下降。
- 24 局配对（对手 `ai-9efb961`）：不显著变差（允许 ±1 局），平局率上升 ≤ 3pp。

**风险**：ratio 整体变小 → 更保守 → 平局涨。若变差，先只保留"记忆计入"、不接 conf。

### 阶段 2：置信度接入决战判决（可调，默认保守）

**要解决的问题**：让"不知道"影响下注大小，而不是假装知道。

- `PlanCtx` 加 `intelConf`（0~1），`decisiveOf` 输出它；`decideCallOf` 按上面的公式收缩。
- `intelTrust` 进 `PLAN_TUNING`，默认 0.4；调成 1 = 完全相信估算（回到今天的行为）。
- `aiCalls` 日志加 `conf / foeAge`，回放里能看出"这次判决是猜的还是看的"。

**验收**：
- 参数开关验证：`intelTrust=1` 时 24 局与阶段 1 逐局一致（证明只在收缩上起作用）。
- 默认 0.4：配对不降、平局率 ≤ +3pp，"首次 attack 的回合"中位数不提前（不能因为不确定反而乱打）。

### 阶段 3：`scout` 计划（选人 / 走位 / 蹲点 / 放弃）

**要解决的问题**：让侦查真的发生，并且用上潜行。

- `scout` 计划：`value = 主攻城 age > 3 且在主攻方向`；`focus` = 目标城；`needSquad: 1`（口子已留）。
- 选人：`stealth` + `vision ≥ 4` 优先，排除编队成员；没有就退化成任意散兵。
- 走位：目标城外围 3~5 格（视野 4 能罩住城中心），森林/丘陵加分；到位后"不动、不开火"高分。
- 潜行：**只在 scout 当值时**给掩体偏好（否则全军钻林子）；用 `isHiddenFrom(view, self, foe)`
  判"是否暴露"，暴露且掉血 → 撤。
- 收场：连续 2 回合看清目标城守军 → done；死亡按第二节的冷却。

**验收**：
- `probe:scout` 10 条：能选中斥候、走到林子、蹲住不动、目标城进入视野、连续 2 回合完成、
  死亡计数、冷却生效、编队成员不被抢、无斥候时退化、计划与进攻计划不打架。
- 回放（Q2/Q3 各一局）：能看到"斥候先到、编队后到"。
- 24 局配对：胜率不降、平局率 ≤ +3pp。

**风险**：斥候送死、编队少一人、计划抢人。冷却与"只在散兵里挑"是两道闸。

### 阶段 4：请求通道（进攻计划 → scout）

**要解决的问题**：侦查不该是"自己想去看"，而是"有人需要看"。这是反向通讯的第一条上行请求。

- `PlanOrders` 加 `needIntel: cityId | null`，由 mass / decisive / breakthrough 填
  （条件：目标城 age > 3）。
- `scout` 的 value 读 `needIntel`：被请求时优先级抬高、目标直接锁定该城。
- 计划层排序时"请求方当值 + scout 不在当值"→ 允许 scout 插队一次。

**验收**：
- 日志可追踪：某回合 `mass` 报 `needIntel=city3` → 下一回合 `scout` 当值、focus=city3。
- 24 局配对不低于阶段 3；请求被响应的比例 ≥ 60%。

### 阶段 5：blackout 信息对等（只在浓雾扩展生效）

**要解决的问题**：浓雾下 AI 能读全量城与真实血量，玩家不能。

- `fog.playerView` 在 `terrainHidden` 时裁 `cloned.cities`：未探明移除；有记忆用快照覆盖
  `owner/era/ruined`，并标 `seenAt`；`hp` 不给（AI 侧按 `maxHp` 估并降 conf）。
- AI 侧所有读城的地方（`decisiveOf` 的敌城清单、攻城目标、`turnsToRaze`）走同一个"未知"口径。

**验收**：
- 默认（无 blackout）24 局**逐局不变**（零变化验证）。
- blackout 探针：未探明城不在 AI 视图里；记忆城字段等于快照；AI 不会对未知城做"守军 = 0"的判断。

**风险**：AI 在浓雾图里找不到目标 → 需要"探索"兜底，阶段 3 的 scout 正好提供。

## 四、最终成果

1. AI 的决战判断从"看不见就说打得动"变成**知道自己在猜**：不确定时不下重注，看清之后敢打。
2. 斥候与潜行成为真实战术：蹲森林/丘陵、不出手、持续开视野，而不是当便宜兵送掉。
3. 反向通讯有了第一条上行请求（编队/计划 → 侦察），与既有的 `AiSquadReport`（下行汇报）配对。
4. 情报过期、置信度、请求通道三样是**通用机制**，以后的扩展（空间站舱段、暗影领域）能直接复用。
5. AI 与玩家信息对等（含浓雾），跑批出来的平衡数据才不是"AI 作弊换来的"。

## 五、顺序与停止条件

`0 → 1 → 2 → 3 → 4 → 5`，每一步单独提交、单独跑批。

- 阶段 0 不达标 → 这一项整体停，转去查采购/编队。
- 阶段 1 变差且找不到"只保留记忆计入"的可用子集 → 停，只留测量工具。
- 阶段 3/4 若胜率下降但"决战回合更准"（回放可证），保留机制、把 scout 的 `value` 权重调低，
  而不是整段删掉。
