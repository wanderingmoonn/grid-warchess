# 重构与规则审查

本次以仓库提交 `2c28884` 为基础，保留五时代、地图生成、扩展包、中文界面和 `applyAction` 的纯函数 API。第一轮完成模块拆分与缺陷修复；随后根据用户授权确定并实现了 v5 的胜负、平局和指挥官产能规则，详见 [v5 规则说明](rules-v5.md)。兵种价格和基础属性保持原样。

## 模块边界

- `src/core/rules.ts` 负责行动校验与状态迁移；`rules/queries.ts` 负责棋盘/实体查询，`rules/modifiers.ts` 负责扩展和能力修正，`rules/combat.ts` 负责伤害和攻击预览，`rules/action-validation.ts` 检查输入行动形状。原有调用者仍可从 `rules.ts` 导入。
- `src/app/ai-turn.ts` 负责单次 AI 回合与可恢复预算；`commander.ts` 负责生产估算和固定指挥方的五轮批次；`room-session.ts` 负责联机交接和终局识别。`main.ts` 负责连接界面、存档和这些模块。
- `src/core/validation.ts` 校验兵种数据；`src/storage/validation.ts` 校验 v4/v5 对局，`migrate.ts` 统一迁移；`src/net/protocol.ts` 校验云端快照和提交交接。它们都可以脱离浏览器或云服务测试。
- `src/core/rules/outcome.ts` 统一城市胜负和轮数裁决，`production.ts` 统一持久化产能和计划约束；AI、界面与存档共用规则。

## 已落地的行为修复

### 行动与战斗

- 移动、建造和卸载必须落在整数坐标，不能用小数坐标产生索引别名；未知或畸形行动返回失败结果。
- 船舱内乘员仍占非建筑编制，装船不能额外腾出产兵名额。
- 不允许在敌方城市格建造，也不允许军营向敌城格生成部队。
- 攻击预览正确计算「先手」免反击；「破甲」对城市护甲生效，攻城计入攻击方指挥光环。
- 主动攻击和自动建筑火力遵守敌军可见性/潜行规则；自动火力也遵守拆桥必须相邻的限制。

### 调度与数据

- 指挥官批次固定操作方，每轮完成己方行动及对手行动；计划不会因 `current` 切换而被复制给对手。
- AI 的已用采购/升级预算跨暂停保留；取消、换局或切换会话后，旧异步任务不能继续写入新局。极快 AI 也会保存最终状态。
- 预算估算遇到买不起的兵种时按空过处理，不扣不存在的支出。
- 联机支持同一回合内结束的胜局；服务器快照必须与外层回合和当前方一致，写入结果必须确认成功。真实防作弊仍需要服务端权威规则。
- 联机提交失败可从顶栏重试，刷新后保留待提交信息；没有有效房间草稿时回到本机对局，旧邀请请求不能覆盖新开的对局。
- 本地对局与各房间的草稿、元数据分别存储。损坏存档不会进入界面，也不会覆盖有效存档；仍兼容缺少可选字段的旧 v4 存档。
- 兵种导入校验必要字段，重新编号时同时更新自定义建筑引用；存储失败不会报告成功。编辑器保留失败草稿以便重试。
- 棋盘、侧栏、开局面板和指挥官栏转义导入名称、图标及实体标识，名称中的 HTML 作为文本显示。
- 每局兵种表深复制能力、建造清单和地形收入，修改一局不会污染全局或另一局。开局配置保留实验参数，重复启用同一兵种不会改变出生编组。

## 本轮已确定并实现的规则

这些决定已落实到内核、AI、界面、存档和离线联机协议，不再由界面内存单独约束。

| 问题 | v5 决定 |
| --- | --- |
| 无兵且现金不足 | 仍有城市就继续，允许等待收入重建；失去全部城市才判负 |
| 指挥官生产上限 | 每回合招募或升级合计一次，城市与军营共用，成功次数持久化；普通模式不增加这一总量限制 |
| 同时失败 | 一次行动的完整效果结算后判定；双方无城平局，不按玩家检查顺序挑胜者 |
| 长期对峙 | 双方各行动 100 次后按城市数裁决；同数城市平局，B 完成最后行动后才裁决 |

## 仍保留的边界

| 问题 | 当前行为 | 后续方向 |
| --- | --- | --- |
| 爆炸的连带结算 | 自爆/焦土不递归触发连环爆炸 | 连带击杀是否发放战争经济奖励、计入老兵，以及如何归属击杀者 |
| 云端公平性 | 全局状态由客户端计算并上传，迷雾只约束正常界面/AI | 若用于竞争性联机，应由服务端校验行动并向每方提供裁剪后的视图 |

城市位置、历史平衡实验和兵种数值保持原样。攻城破甲、运输编制和隐形目标选择修复会影响部分对局结果，旧平衡报告不能直接视为本次版本的新评估。

```sh
npm ci
npm test
npm run check
npm run manual
npm run build
npm run dev
```

第一轮重构验证共 **299 项通过**：原规则 178、规则回归 16、开局/兵种库 9、应用调度与离线联机集成 17、存档/协议 12、渲染转义 3、DOM 冒烟 64。类型检查、生产构建、Git 空白检查通过，规则书重复生成结果一致。另对古典与现代对局的 427 个 AI 动作逐步校验，均得到有效存档状态。v5 新增的规则、迁移和界面验证见 [v5 规则说明](rules-v5.md)。
