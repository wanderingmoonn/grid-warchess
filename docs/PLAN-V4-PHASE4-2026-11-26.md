## 3. 实战与考题交错（本阶段的主结构）

### 3.1 v4 起步时就定过：胜率不是刻度

原文在 `docs/PLAN-V4-2026-11-23.md`，四条结论照抄（**改之前先读这四条，别滑回去**）：

| 位置 | 原文 |
|---|---|
| 开头 | "判断对错的尺子从**胜率**换成**考卷**，因为 v3 的实测已经证明：24 局胜率的噪声（换种子 ±30 个百分点）比任何一次改动的信号（±10 个点）都大。" |
| 第 3 条 | "**胜率不是日常刻度。** 只在里程碑跑一次，用来看'有没有崩'，不用来比大小。" |
| §5.1 | 三条理由：**噪声大于信号** / **早期必然低**（看胜率只能得出"更差了"）/ **胜率能被畸形打法刷高**（v2：83% 弓手、0 建筑、0 升级，一路绿灯） |
| §6.4 | "只在里程碑跑一次，看两件事：有没有出现 **0 胜**（能力崩了）、**平局率有没有超过 50%**（收不了尾）。" |
| 红线表 | "又滑回'看胜率调参'"被列为明确禁止 |

同一份文档 §5.7 给了"实战与考题怎么分工"的原话：

> **"真实回放提供证据，手工小局提供能判的题。"**

`V4-CODE-MAP` 9.25 还记着一条反向的口径（用户当时否决了"发展→开战"那种题）：

> "不出实战题，出纯转换题 `E-2-03`（用户否决了'发展→开战'那种，理由：**等于实战、红绿无法归因**）。"

**合起来就是阶段四的口径**：实战**不能当题**（红绿无法归因），但实战**必须跑**（不然没人知道考题漏了什么）。
它提供**形状**，考题提供**红绿**。

### 3.2 为什么现在要加实战

阶段三结束时，36 道题 34 绿——但这 36 道**全是手摆单考点**：

- 每题只隔离一个机制（架桥、守城、两波、投送）；
- 局面是**人造的**：桥的位置、金钱、敌人的远近都替 v4 摆好了；
- 组合起来会发生什么（架桥 + 守城 + 采购 + 升级同时进行）**没有任何题在验**。

实战正好补这一段：随机图、双方同时做全部的事、有迷雾、有经济。它不是更难的题，是**另一种东西**。

### 3.3 口径（三条，避免滑回老路）

1. **实战不判红绿，只交形状**：一局打完只回答"输在哪一类"（城先塌 / 终局兵少但城在 / 撞上限），不打分、不算"改进了几个百分点"。
2. **实战发现的东西必须切成题才能修**：切不出可判据的题，就先记着——说明还没看懂。
3. **改了代码必须回考题跑 36 题**：实战好转不能当验收；考题翻红要回来看（这正是阶段三的纪律）。

### 3.4 一个循环（本阶段的节奏）

```
① 实战跑一批（形状） → ② 挑最差的一类 → ③ 切成一道题（可归因）
      ↑                                        ↓
⑤ 回实战看形状变没变 ← ④ 修 + 题绿（36 题不翻红）
```

**一轮 ≈ 一个 W 步**。一轮只挑**一类形状**，不并行修两处（阶段三的纪律：一次只动一处）。

### 3.5 实战台：为什么不用 `ai-duel`

现成的 `ai-duel` 能跑 v4（`--new ../src/core/v4/ai-v4.ts`），但有两个坑，所以新写了 `scripts/v4-duel.ts`：

| 坑 | 后果 |
|---|---|
| **v4 有模块级缓存**（`cache` 键 = `回合:当前方:单位数:金币:城数`） | 同一进程连跑几十局，新局第一手**可能命中上一局的 `world`**。`ai-duel` 不调 `resetV4()` |
| **只有胜负，没有形状** | 17% 胜率看不出"没出兵 / 没送到 / 送到打不动" |

`v4-duel` 做三件事：**每局 `resetV4()`**、输出终局形状（双方城血 / 兵数 / 金 / 桥数）、
把输的局按三类归形状。

```bash
# 12×12 / 3 代 / 20 颗种子（40 局，约 7 分钟）
node --experimental-strip-types scripts/v4-duel.ts --games 20 --era 3
# 24×24 长局形状
node --experimental-strip-types scripts/v4-duel.ts --games 10 --era 3 --size 24
# 对手换 v3
node --experimental-strip-types scripts/v4-duel.ts --games 20 --era 3 --foe v3
```

| 镜像自对 | 24×24 | 4 代 | 200 手 | 僵持与收尾（见下） | 参数已定，待跑 |

**镜像自对到底看什么**（用户问过一次，记在这里）：双方同一套脑子、同一张对称图，
**唯一的差别是先手**。所以它排除掉两件事——"地图偏谁"和"对手强弱"，
剩下的就只有"这套脑子自己会不会把事情做完"：

- 两边都推不动 → **收尾/僵持**的问题，且与对手无关（实测 era7 24×24：321 手、
  双方城满血、兵 19/10、各 2.5 万金没花）；
- 一边稳定赢 → 这套脑子**吃先手**，先手优势大到能决定胜负（12×12 火器那 6 局就是这个形状）。

它不是"更强的对手"，是一面**照自己的镜子**：实战里输给旧 AI 时，先说清"是不是先手/地图的锅"。

### W1.6 ✅ 采购会造工兵（W2b 提前做，2026-11-26 21:10）

**症状**（用户 2026-11-26）：「需要造桥的时候不会造工兵去架桥，有些平局就是这样。」

**根因**：全项目**没有任何一处会造建造单位**——采购只认 `category === 'combat'`，
工兵是第三类（`builder`）。决定层连着 22 手判"走不到、要架桥"（`16×16 era1 seed900` 实测），
计划层却永远拿不出工兵队，桥一格没铺，钱还在"留桥钱"。**手工小局里工兵是人手摆好的**
（`P-2-03`），所以考题一直没考出来。

**改法**（三层各一句，没有加新的"要不要"）：

| 层 | 做什么 |
|---|---|
| 决定层 | 不动（`kind:'bridge'` 早就有） |
| 计划层 | 架桥分支里多问一句：**手上 0 个工兵** → 找一座造得出来、买得起的城，给一张单（最便宜优先，同价挑近的） |
| 动作层 | 只把这个单发出去（同 `upgrade` 的写法），排在"照模式造兵"之前 |

**验收**：① 16×16 era1 seed900 先手，从**负（74 手城塌）→ 平（121 手，桥 2，打到对岸）**；
② 同图其余 5 局**逐字未变**（901/902 四行读数完全一致）；③ 36 题矩阵**零变化**
（S-002/S-011/S-013 绿、S-012 红——这四条与改动前逐题对照过，是 11-25 旧基线造成的差异，
不是这次改的）。**未验**：工兵被打死后能不能补上（代码路径通，没有实测局）。

### 4.2 ⚡ 插队：把"绝对身价"换成"相对战力"（2026-11-27 00:10，用户定）

**为什么插队**：守的时候买错兵、进攻时升级不积极、爱拿一群低时代兵打高时代兵——
三件事读的是**同一把错尺子**（`身价 = 攻 + 血 + 射程×4`：没有护甲、没有多段、速度当没有）。
尺子不换，后面两条（提前看见威胁 / 经济单位离开火线）都会继续绕圈。

**新口径（用户定的"相对战力"）**：

```
每回合伤害 = 单发伤害（previewAttack，带护甲/破甲）× 一回合几发（attacksPerTurn）
白打回合   = 我射程比它远时，它走过来之前我能白打 ceil((我射程 − 它射程) ÷ 它移动力) 回合
战力       = 每回合伤害 × (我的血 ÷ 它每回合伤害 + 白打回合)
```

- **参照敌人用一组、不找"最强"**：同代陆军里 **最贵 / 最厚 / 射程最远** 三个，战力取**最小值**
  （"对最难缠的假想敌能打出多少"）。三个参照都由设计数据选出，不需要任何战力排序，所以不会循环；
- **每格 = 战力本身，每金 = 战力 ÷ 单价**——同一个数换个分母，分母选谁由"这一手格子紧还是钱紧"判；
- 采购里那两道闸（三发打得穿 / 穿过射程活不活得下来）**并进公式**：打不穿 → 伤害 0 → 战力 0。

**探针已写好（只读，不进决策）**：`scripts/probe-combat-value.ts`

```bash
node --experimental-strip-types scripts/probe-combat-value.ts --era 3 --gold 400
```

它打四张表：① 旧身价 vs 新战力的排名差；② 单挑胜负有没有三元环；③ 等金群战（集火模型）；
④ 等量群战。**读数（1 代 / 3 代）**：

| 代 | 旧"每金"第一 | 新"每金"第一 | 单挑三元环 | 等金不一致场次 |

| 1 代 | 民兵 180 | **民兵 103** | 无 | 2/12（弓手×8 赢 戈兵×10） |
| 3 代 | 戟兵 75 | **戟兵 46** | 无 | 2/12（火枪×3 **赢** 戟兵×4；臼炮×2 赢 骠骑×2） |

**S0 已做（2026-11-27 00:15）：探针加了"前线上限"（`--frontage`，默认 6，野战经验值 4~6；
守城看地形、说不清，所以只做参数）+ 拿真引擎做了交叉验证。**

- 加了前线上限之后，公式里**仍然是斥候赢弓手**（6v6 剩 5、20v20 剩 3）；
- 但**真引擎实测反过来**：用同一套打法（贴身就打、否则朝最近敌人走）让两边对打，
  **弓手×6 赢斥候×6（剩 4）**、**弓手×6 赢民兵×6（剩 3）**；
  3 代更极端：**火枪×6 打戟兵×6 → 6:0**、火枪×4 打戟兵×4 → 剩 2。

**结论：闭式公式算不出群战强弱，射程的价值比我估的大得多。** 原因不是"白打几回合"这一个数，
而是**排队 + 逐个到达**：近战要走过去、只能贴上去的那几个打，远程从头到尾全队都在输出。
这两件事是**场面的属性**，不是单兵对的属性。

### 4.4 ✅ S1：身价换成相对战力（2026-11-27 00:55）

**公式怎么拟合出来的（用户要求写清）**：

1. **先有表**：`scripts/lib/duel.ts` 让同代每一对兵在引擎里**正反各打一次**，按两次的净胜人数排名
   （先手优势自己相抵）。表在 §4.3。
2. **再定公式形状**（4 个待定参数）：

```
dmg(u→r)   = 单发伤害（previewAttack，带护甲/破甲）× 一回合几发
tank       = 我的血 ÷ r 的每回合伤害                   ← 能活几回合
stand      = (GAP − r 射程) ÷ r 移动力                  ← 我射程更远时，它走过来之前我白打几轮
power(u|r) = dmg × (wHp × tank + wStand × stand) × (我射程更远 ? kRange : 1)
```

3. **打分函数**：每一代里两两比"公式说谁强"和"实测谁净胜多"，方向对上记 1 分，
   五个时代合计成**方向一致率**。
4. **网格搜**：`wHp ∈ 0.1~1.5`、`wStand ∈ 0.5~4`、`kRange ∈ 1~1.5`、`GAP ∈ 4~10`，
   共 1008 组（`scripts/fit-combat-formula.ts`，只读）。
5. **结果**：最优 `wHp=0.3 / wStand=1 / kRange=1.1 / GAP=5`，**一致率 88%**（旧身价 46%）。

**两个必须写下来的经验**（都是试出来的）：

- **参照组要取平均，不能取最小**：取最小时"射程最远"那个参照就是远程兵**自己**，
  对着自己算没有白打回合 → 1 代弓手被自己拖到最后一名。
- **射程的价值取决于接敌距离**（`GAP`）：光算"我射程 − 它射程"只有 0~1 回合，解释不了
  "火枪 6:0 戟兵"。改成"它从 GAP 格走进我射程要几轮"，公式才和引擎对上——`GAP=5` 是拟合出来的。

**已知没对上的一处**：4 代公式把装甲车排最后（实测它第一）。它赢在**护甲 5 + 54 血**，
公式里 `tank` 对它只值 1.7 轮。这一处留着（S1 只换尺子不改形状）。

**S1 落地**：`world.ts` 的 `unitWorthOfType` 换成上面这套（参数写成常量 + 注释指向标定台），
**四处读者一行不改**（守城三档 / 升级阶梯 / 一批派几个 / 分兵额度）。

**读数（39 题）**：**37 道零变化**；`D-3-01` 城 0/2 → **1/2**（仍红）；
`S-002` 绿 → **红**（损失 20→22，那是用户 2026-11-25 明说"不管"的综合题）。

其余全零变化，且它是后面 S2/S3/S4 的地基。

### 4.6 S3 升级：两个真因，一个是坑（2026-11-27 01:20）

### 4.10 GAP 是错的（用户指出），但换掉会翻红两道发展题（2026-11-27 09:10）

**用户的问题**：`stand = (GAP − r 射程) ÷ r 移动力` 里为什么有 GAP？不该是**两者射程相减**吗？

**对。** 只要两边都在朝对方走，"谁先进入自己的射程"只差一个**射程差**，与初始距离无关：

```
stand = (range(u) − range(r)) ÷ 走过来的那个人的移动力        ← 正负都要算
        · 我射程远：它多走 Δ 格才能还手 → 我白打 Δ ÷ 它移动力 轮
        · 它射程远：反过来，我少活这么多轮（旧式子只算了自己占便宜的一半）
```

**GAP 为什么"拟合得出来"**：它在替**别的东西**打工——同代里大家的移动力/血/射程都差不多，
`Δ射程 ÷ 移动力` 只有 0~1 轮，解释不了"火枪 6:0 戟兵"。真原因是**排队/集火**
（远程全程输出，近战要走过去、且只有贴上去的几个能打）。拟合没有那一项，就把误差塞进了 GAP。

**实验读数**：换成射程差（无 GAP）后，拟合一致率 **81% → 88%**，
而且 5 代排序第一次全对（火炮 > 坦克 > 步兵班 > 重机枪）。

**但它让 `E-2-03` / `E-2-05` 两道发展题翻红**（采购挑的兵变了），所以**代码里暂时还是旧式子**
（`world.ts` 回退），正确的口径只落在拟合器 `scripts/fit-combat-formula.ts` 里。
待办：把"排队/集火"补进公式之后，再一次替换掉 GAP。

**顺带测到一条关键样本（4 代为什么永远"没收益"）**：跨代实测
**火枪×6 打装甲车×6 = 净 −10（装甲车赢）**、火枪 打 5 代步兵班/火炮各 −12，
而公式把火枪（16）排在装甲车（9）前面。所以 `eraLadder` 认为"4 代不如 3 代"。
跨代样本可以进拟合（`--cross`），但一轮要跑十几分钟，先记着。

### 4.13 集火能力进公式（2026-11-27 10:15）：4 代修好了，拟合 96% + 代际 100%

**用户推导的集火几何（已核）**：引擎射程是**曼哈顿距离**，两军方阵贴住之后，
一个敌人能被几个自己人打到 = 我方半平面内距离 ≤ r 的格数 = **r²**（1 / 4 / 9 / 16…），
再被 `min(N, f(W))` 截断（N=6 标定军力；W=5 时 r=3 正好吃满 9 格）。**"平方律"这个名字就是从这来的。**

**进公式的方式**：

```
power = 每回合伤害 × (1.5 × 能活几回合 + 0.5 × 白打几轮) × (focus(r) ÷ N)
```

`focus(r)/N` = "我这一格能参与集火的比例"；参照组改成取**最小**（有了集火项之后，
"远程被自己拖死"那个副作用消失了，拟合也选了 min）。

**拟合读数**：

|---|---|---|
| 同代内部 | 88% | **96%** |
| 代际递增 | 75%（3→4 ❌） | **100%** |
| 4 代内部 | 1/3（装甲车垫底） | **3/3**（装甲车 > 步枪 > 机枪，与实测一致） |
| 5 代内部 | 6/6 | 5/6（坦克 vs 火炮 反了） |

**升级阶梯（这才是我们要的）**：

```
改前  弓手29 → 弩兵52 → 火枪71 → 火枪71 → 火炮?      ← 4 代认错兵
改后  弓手29 → 弩兵52 → 火枪71 → 装甲车71 → 坦克132   ← 每代认对了，且逐代上升
```

#### ① 提前量（服务层 `defensible`）

判据是**回不来得及**，不是"敌人多近"：

```
earliestEta = 最早一批自己人回城的手数
firstAt     = 敌人第几手开始打这座城（cityStand 早就有这个数，这次才暴露给上面）
soon        = firstAt ≤ 3 且 earliestEta ≥ firstAt
              且 城里没人（onSiteWorth = 0）且 门口没人（foe.here = 0）
              且 earliestEta < rounds（现在动也赶不上 → 干脆别动）
              且 来打城的那个敌人没被我贴住（blocked）
```

五个条件每一道都是被一道题逼出来的：

| 条件 | 谁逼出来的 |
|---|---|
| `firstAt ≤ 3` | `S-011`（敌人 5 手外、12 打 2）被判"来不及"，全军回城、前线散了 |
| `earliestEta < rounds` | `S-011` 同一处：现在动也赶不上，召回只是白丢战术动作 |
| 城里没人 `onSiteWorth = 0` | 城里有守军时提前召回 = 拿战术动作换安全感 |
| 门口没人 `foe.here = 0` | 已经贴脸时走老口径，别抢"当下该不该打"的判断 |
| **`blocked`（敌人被贴住）** | **`X-2-01`**：离城最近的敌人正被我方贴着打，它根本走不过去拆城；这一条一加，`X-2-01` 立刻从红变绿 |

`blocked` 是这一轮的关键：`earliestEta >= firstAt` 只回答"谁先到"，回答不了"它到得了吗"。
判据是几何的：离城最近的那个敌人，身边一格内有没有我的人。

#### ② 守的动作（计划层 `guardSplit` + `interceptAt`）

原来守 = 全部钉在城格上等挨打，站不下的挤在门口，一整场不出拳
（`D-3-01` 实测：3 个人站在离敌人两格的位置，40 手没打出一拳）。

现在一座城的守军分两拨，三条判据全是数：

1. **城撑不满 4 轮就不出城**（出城一趟来回要 4 手）——`D-1-01`/`D-1-03` 城只能撑 3 轮、
   `D-2-02` 撑 2 轮，分兵会让它们直接翻红；
2. **敌人 2 手内就要开打**才谈得上迎击——`S-013` 敌人 5~6 手外，那时分兵会丢城；
3. **出去的人要赶得上**：`marchTurns(到迎击位) ≤ firstAt`，赶不上的留城里；
4. **城里留 2 个**（吃 +3 护甲，而且城格得有人站着）。

迎击位 `interceptAt` = 离城最近的敌人旁边、不在城格、没站人、能走的一格，
多个候选挑**离城最远**的（在城外接火，不把战场摆在城门口）。

**要解决的现象**：城挨打时，站到城边的那几个兵不会打人，只会挪位置躲开"必须空出来的格子"。

#### 改法：一张需求表 + 一次座位分配

**① 需求表**（计划层产物，替掉 `keepClear` 那张几何名单）。每条需求都带**来源、名额、等级**：

| 需求 | 谁产生 | 要哪些格 | 名额 | 等级 |
|---|---|---|---|---|
| 产兵 | 这一手的采购单 | 该城城格 | 这一手要造几个（0~3） | 硬 |
| 架桥 / 过桥 | 工兵建造目标 / 过桥队落点 | 那一格 / 桥面 | 1 | 硬 |
| 守军站位 | 守城分兵（城内几个 + 迎击点） | 城内格 + 城边格 | 分兵算出来的数 | 停驻 |
| 出征 | 某支队的**下一步落点** | 落脚那一格 | 队人数 | 路过 |
| 经济岗位 | 认领表 | 岗位格 | 认领数 | 停驻 |

**名额是灵魂**：现在名单写的是"城圈一格都不许停"，真正的需求是"**留出够用的几格**"。
名额让它变成一个能数的整数，而不是几何常数——这也是守军问题的解：挨打时**产兵名额可能是 0~1**，
守军就自然能站进去，不需要"整块豁免"。

**② 座位分配**：一格一个人，按等级往下分：**硬 > 停驻 > 路过**（用户 2026-11-27 12:20 确认）。

- 硬：站上去功能就没了（产兵格站满，引擎直接拒）→ 输不了；
- 停驻：站在那儿**就是它的任务**（守军守城边、牧民守林地）；
- 路过：只是途经，多走一格代价最小。

**分到座位的人不动，没分到座位的人才是让位候选。** 守军有座位（停驻）→ 不会被抽走；
出征队是路过 → 它自己绕一格。**这条规则不需要"守军"这三个字。**

#### 可以借的两套现成算法（用户 2026-11-27 12:20 指出）

**（a）经济岗位的配岗**（`constrain.planEconPosts`）——**让位应该学它，因为方向正好相反**：

| | 经济配岗 | 现在的让位 |
|---|---|---|
| 先有什么 | **先有人，再挑格** | 先有洞，再找人 |
| 代价 | 这个兵走到这个岗的**真实步数** | 无（只看"离最近的洞"） |
| 结果 | 已经在岗上代价 0 → 天然不动 | 方向随机 → 越让越远 |

配岗是"全局配对"（每对的代价 → 从最便宜的开始配，配过的兵和岗划掉），
所以**方向天然正确**；让位是"就地塌陷"，所以**方向由洞决定**。让位要改成"先有人、再挑格"。

**（b）编队行军**（`constrain.planMarch`）—— 解决"一群人同时让开"的次序：

- 分排 + **同序配对**（人按一条轴排、阵位按同一条轴排，序号对序号）→ **路线不交叉**；
- 窄道（桥、关隘）**整队交给打分层**排队走，计划层不排阵型；
- 接敌时不排阵型，各自找最靠近敌人的位置。

**（c）两边共用的执行技巧**（要保住，别当成决策）：引擎没有"两人交换位置"这个动作，
所以任何"一人一格"的分配，执行时必须**从空位那一端倒着派**（`planYield` 现在这段是对的）。
**决策 = 配对；执行 = 倒着派。现在代码把两件事混在一条链里了。**

**（d）"把洞挪到人身上，别让人绕远路到洞上"**（用户 2026-11-27 12:31 补的一条，人越多越关键）。

这是配岗那段"建链搬运"的真正要点，也是让位该抄的第二件事：

> 出现一个空位时，**不要**挑"离空位最近的那个人"让他走过去——
> 而是让**空位沿着人链往回走**：贴着空位的人先挪一格，空位就往前挪一格，
> 一回合里整列都动一格，洞从很远处"传"到真正要腾位的那个人身上。

为什么这比"谁近谁去"好：挑一个远处的人走过来，中间那些人这一手全部白站；
而链式递补**一回合能清多格**，且每个人只走一格（引擎允许的幅度）。
现在的 `planYield` 已经是这个形状（从洞那端倒着派），**批 3 别把它改成"就近指派"**。

差别在"落点从哪来"：现在洞是"最近的空格"（方向随机），要换成"这条链的终点是**需求格本身**"——
洞代表的是"这一手要用的那一格"，不是"随便哪个空格"。这两件事在批 3 里必须同时成立：
**洞 = 需求格（有方向）；人的移动 = 沿链递补一格（幅度小、一回合清多格）。**

### 4.23 ⚡ 让位重做：按「格子的四种身份」重写（用户 2026-11-27 14:58 定）

> 前面 §4.22 的 3a/3b/3c 是"修让位的口径"，两次试做都不成立。用户提出另一个模型：
> **每个格子在每一手有四种身份**，让位只是其中一种冲突的结果。本节按这个模型重排。

#### 四种身份 = 两个原始量

| 身份 | 这一手有人要**进**来 | 站着的人要**出**去 | 现在的代码怎么处理 |
|---|---|---|---|
| 自由 | 0 | 0 | 不在名单里 |
| **入口** | ≥1（走过来，或**直接造出来**） | 0 | 一律按"必须空" |
| **出口** | 0 | ≥1 | 一律按"必须空" |
| **通道** | ≥1 | ≥1（= 入口 ∩ 出口） | 一律按"必须空" |

**关键：四种身份都是"这一手的"，不是永久的。** 现在把"城的外一圈"永久登记成关键格，
等于**永久宣布它是通道**——而大部分回合根本没人要过。这就是"范围写宽了"的准确说法。

#### 只有一种组合需要挪人

| 格子这一手 | 站着的人这一手 | 要不要挪 |
|---|---|---|
| 入口 / 通道（有人要进） | **要出去**（有落点 / 路过） | **不用**——他自己就会走 |
| 入口 / 通道（有人要进） | **不走**（停驻：守军、岗位、待命） | **要**——唯一真冲突 |
| 自由（没人要进） | 任何 | 不用 |
| 出口 | 任何 | 不用（出口是对**人**的要求，不是对格的要求） |

**一句话：只有"有人要进这一格"且"站着的人不走"时才挪人。其余一律不动。**

这条一句话就解释了三个旧现象：
- **桥面被赶下来**：把"出口"（人要出去）当成了"入口"（有人要进）；
- **守军在城边被抽走**：城圈被永久当通道 → 入口需求恒真 → 守军是"不走的人" → 被挪；
- **城圈清空后 8 个兵往外退一格**（3a 试做，`S-002` 翻红）：清的是真通道需求，却把人推出了射程位。

#### 先量了一次（2026-11-27 15:00，`probe-yield4 --seat`，全册 39 题）

只数**站在"必须空"格子上的战斗兵**，按"这一手有没有产出"分五类：

| 全册合计 | 会走（有落点） | 守/工 | 能打（人/城） | 待命 | **闲人** |
|---|---|---|---|---|---|
| **637 人次** | 15 | 3 | 24 | **19** | **576** |

⚠️ 第一次量出来是"待命 502"，那是因为把 `order:'yield'` 那个**只有标签、没有终点的空队**
也算成"有队"了。剔掉之后真正的分布是上表：**90% 是"闲人"**（没落点、没岗位、不在守/工队、打不到人）。

**为什么闲人这么多（已归因）**：`rest` 那一行按位置过滤——**站在"必须空"格子上的人不进编队池**，
于是他们不属于任何队、拿不到落点，而让位链是唯一会碰他们的机制（方向随机）。
所以"闲人 576"和"让位 114"是同一批人的两个侧面：**576 个站着没人管，其中 114 个被随机推了一下。**

**第 1 步的定义（按这个数修正）**：不是"给待命的人排阵位"，而是——
**把站在关键格上的人收回编队（`rest` 不再按位置摘人）**，让他们拿到落点。
座位表（守军防御圈）在第 1 步的后半段做，不从这一步开始。

#### 已定的两条边界（用户 2026-11-27 14:58）

1. **出口走不了就原地不动**（不拿别的格去补），但必须能数出来——探针记"出口被堵"。
2. **排队先不管**：一格宽的桥真实约束是"一回合过几个人"（次序问题），这一轮不动它。
   只做"通道不再赶人"这一半。

**归因（两道红都不是"别处迁就旧让位"，而是编队分配本身）**

- `S-002`：第 9/13 手决定从 `press/expand` **翻成 `defend@c1`**，主力回防 → 城伤不够。

**为什么"给座位"反而变差（这是本轮最重要的一条）**

`rest` 一放开，这些人不是被**指派**了座位，而是**落进了现有的编队分配**——
