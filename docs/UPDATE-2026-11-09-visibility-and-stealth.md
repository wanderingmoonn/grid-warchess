# 视野收口 + 隐匿统一（2026-11-09）

线上版本 v0.3.70。同一批还修了一个跨局污染的真 bug。

## 一、视野：从"攻击/攻城"扩到"反击/塔"

原来"看得见才打得到"只拦了两条路：手动攻击、攻城。另外两条完全绕过了它。

| 路径 | 之前 | 现在 |
|---|---|---|
| 攻击候选 `attackableTargets` | 只看地形可见 | 地形可见 **且** 对方没藏起来 |
| 攻城 `siegeTargets` | 城有任意一格在视野 | 不变 |
| **挨打后的反击** | 只要够得着就还手 | 先得看得见攻击者 |
| **塔的自动开火** | 直接扫 `s.units`，**完全不看视野** | 地形可见 + 没藏起来 |

统一判据是 `rules.unitInSightOf(s, 方, 单位)`：把"那片地你熟不熟"（`tileVisibleTo`）
和"那个兵露不露头"（`isHiddenFrom`）分开问。只查地形会漏掉后者——蹲在林子里的斥候，
格子是亮的、人却不显形。

三处必须同时改，否则会互相打脸：

1. `attackableTargets` 与 `doAttack` 的校验必须是**同一个函数**，不然 AI 会提一个
   必被拒的动作、界面会画一个点不动的红框（`doAttack` 里那句注释就是为这个写的）。
2. `previewStrike` 的反击预估也要过同一条判据，否则伤害预览会画一次不会发生的反击。
3. 塔不走候选表，改在 `fireBuildings` 的选靶过滤里加。

## 二、隐匿：四条能力统一成"出手即现形"

| 能力 | 兵 | 之前 | 现在 |
|---|---|---|---|
| `stealth` 潜行 | 斥候 / 轻盾兵 / 努比亚弓手 / 盗贼 / 猎兵 / 堑壕突击队 / 突击队 / 特种部队 | 只看地形，**出手不现形** | 加 `!acted` |
| `nv-submerge` 潜航 | 4 艘潜艇 | `hidden: () => true` 常驻 | `!acted`，`noCounter` 保留 |
| `af-stealth` 隐身 | 隐身战斗机 | `hidden: () => true` 常驻 | `!acted`，`noCounter` 保留 |

为什么必须改：近战兵要打就得贴脸，贴脸早就暴露了，所以 `!acted` 对它们**零成本**；
而射程 4 的兵蹲在林子里可以每回合白打，距离 4 本身还不吃反击——
"潜行 + 超出反击距离的射程"就是无风险打靶。潜艇（300 金 / 62 攻 / 射 3）和
隐身机（900 金 / 86 攻 / 射 4）的常驻隐匿是同一个洞，只是身价更高。

`noCounter` 保留：那一发仍然是先手，对方只是**之后**能还手。找补的代价从
"永远打不着"变成"打完要撤出视野"。

判定顺序值得记一笔：`doAttack` 先在结算伤害**之前**算 `isHiddenFrom`（战报因此写
"视野外的一击"，不给攻击者名字），之后才置 `acted`。所以偷袭那一发仍然匿名，
暴露的是发射位。

## 三、碉堡：视野拉到和射程一致

塔要看得见才开火之后，`vision < range` 不再是"塔看得近一点"，而是**射程被悄悄砍掉**——
造价和攻击都是按 `range` 定的。5 座受影响的全部拉平：

| id | 名称 | 视野 | 射程 |
|---|---|---|---|
| `bunker` | 碉堡 | 3 → **4** | 4 |
| `ind_pillbox` | 机枪碉堡 | 3 → **4** | 4 |
| `mod_mgbunker` | 重机枪地堡 | 3 → **4** | 4 |
| `cnt_bunker` | 加固地堡 | 3 → **4** | 4 |
| `ct_pillbox` | 混凝土碉堡 | 4 → **5** | 5 |

不变量写成了用例（全量目录扫 `autoAttack` 单位，`vision >= range`），以后新加一座塔
忘了写视野会直接红。

## 四、明确不做的

- **溅射可以打到看不见的人**：一发炮打中看得见的目标，旁边藏着的潜行兵照样吃伤害。
  保留。炮火覆盖本来就是炮的意义，收掉会变成"炮打不着林子"，那是另一条规则。
- **`unit-value.ts` 的 `stealth: 0.06` 估值权重不动**：潜行确实变弱了，但按止损规则
  不在同一个旋钮上连着投，等有动作变化率的读数再说。

## 五、顺带修掉的：兵种表跨局污染

`setup.createMatch` 对兵种表只做浅拷贝，`builds` 数组和模块级 `UNIT_TYPES` 是同一份；
海军包 `attachShipyards` 用 `push` 往里加船坞。于是**同一进程里开过一局带海军的之后，
后面每一局的工程兵都多了三样造不出来的建筑**（本局兵种表里没有，点了才报错）。

浏览器里一局一载，平时看不出来；返回主菜单再开一局就会带着污染。
`test-rules` 里选卡那条用例就是这么炸的（`s.unitTypes['nv-dock']` 是 undefined）。

修在 `setup.ts`：`{ ...def, builds: def.builds ? [...def.builds] : undefined }`——
这一层的契约本来就是"每个 state 一份私有的兵种表"，让它真的私有，比让十几个扩展
各自记得"别 push"可靠。回归用例：先造一局带海军的，再看下一局。

## 六、已知债：先验表过期

`bunker` 的视野改了，而 `vision` 参与 `unit-digest` 指纹 → `card-prior.table.ts`
被判为过期。运行端会**自动关掉先验**（`src/` 里本来也没有引用，它只用于离线分析），
不会用错的分。重生成需要 `.tmp/draft` 那 400 局数据（已清空）+ `npm run draft:prior`，
属于一次完整实验，这次没跑。

两条相关用例因此改成"查安全侧"：
- 「乘数本身仍然算得对」→ 直接逐行核公式，不再经过新鲜度门槛；
- 「指纹对不上时整张表一律不生效」→ 新鲜就查乘数，过期就断言每一行都回落到 1。
