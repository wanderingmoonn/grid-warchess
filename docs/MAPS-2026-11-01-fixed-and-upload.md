# 固定地图 + 地图上传（2026-11-01）

两件事一起做，因为它们共用同一份数据：**一张地图就是一份地形**。
内置的那几张和玩家上传的那几张，进游戏走的是同一条路——`layoutFromRows`。

一句话概括：开始界面从"一页设置"变成**左侧两页**（战役 / 地图）；「选图」和
「传图」都放在地图页里——上面挑，下面传，传完那张图立刻出现在同一个画廊里。**别人
打开自己的开始界面就能看到并选到它。**

---

## 〇、为什么要先有"开始界面"

原来所有设置是一条长卷：数据收集 → 对手 → 时代 → 尺寸 → 角色 → 选卡 → 地貌 →
固定地图 → 对称 → 兵种池 → 扩展规则 → 种子。它解决的是"一局怎么打"，可地图上传
是"给所有人供货"，天然不属于任何一局。上一版把上传塞进上帝模式侧栏，结果是同一条
流水线的两头被拆到两个互不相干的地方：作者画完图得先想"我该去哪个面板"。

现在开局弹的不再是一个对话框，而是一张两栏的台面：

```
┌──────────────┬──────────────────────────────────────────┐
│ 时代与回旋镖  │  战役 / 地图  ← 标题与一句话说明          │
│  回合制战棋   ├──────────────────────────────────────────┤
│ ┌──────────┐ │                                          │
│ │ 战役     │ │   只有这一块滚动；左侧导航与底下那颗      │
│ │ 规则·时代 │ │   「开始对局」始终在视野里                │
│ ├──────────┤ │                                          │
│ │ 地图     │ │                                          │
│ │ 选图·上传 │ │                                          │
│ └──────────┘ ├──────────────────────────────────────────┤
│              │ 12 × 12 · 古典 · 随机地形   取消  开始对局 │
└──────────────┴──────────────────────────────────────────┘
```

- 底部那行摘要是两个页签之间的**共同真相**：在地图页选了 16×16 的图，抬眼就能看到
  这一局会打成多大，不用切回去确认。
- 左栏底部写死一句"同一个种子永远生成同一张地图"——它原来在长卷最下面，现在
  挪到常驻位置，因为种子这件事正好是两个页签的分界线（选了固定图就不生效）。

## 一、固定地图：展示形式与切换逻辑

### 1.1 展示形式：缩略图网格，不是列表

**地图页**上半部分，卡片式网格（`repeat(auto-fill, minmax(104px, 1fr))`），
第一张是「随机地形」，后面是四张内置图，再下一栏是玩家上传的：

```
「这一局的地图」
┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐
│ ▨▨ 随机 │ │ ▩▩ 双河 │ │ ▩▩ 山脊 │ │ ▩▩ 中央 │ │ ▩▩ 十字 │
│  随机地形│ │ 双河渡口 │ │ 山脊隘口 │ │ 中央湖  │ │ 十字路口 │
│ 按种子生成│ │ 16×16   │ │ 16×16   │ │ 16×16   │ │ 16×16   │
└─────────┘ └─────────┘ └─────────┘ └─────────┘ └─────────┘

「玩家上传」                      [刷新]
┌─────────┐ ┌─────────┐
│ ▩▩ 两桥  │ │ ▩▩ 池子  │        ← 来自 warchess_maps，按时间倒序
│ 两桥之间 │ │ 三岔湖  │
│ 16×16 · 老王│ │ 12×12 · 小李│
└─────────┘ └─────────┘
```

**为什么是缩略图而不是列表**：地图的差别在"长什么样"，不在名字。一行文字
"双河渡口 16×16" 没法让人判断"我要不要在这张图上打一局"；而 96px 的方块图
一眼就能看出"这张中间有湖，我不喜欢"。列表在这种场合是把信息量丢掉之后再展示。

**缩略图怎么画的**：内联 SVG，一格一个 `<rect>`（`src/ui/map-thumb.ts`），
颜色和 `style.css` 里那套地形色**同一份值**。所以缩略图上看着像水的，进局就是水——
不存在"预览图是另一套画法"这种最伤人的不一致。

> 用 SVG 而不是 canvas：canvas 要等 DOM 插进去之后再跑一遍绘制代码，而开始界面
> 每次重绘（换时代、勾扩展、点兵种）都得补一次；SVG 是纯字符串，跟着面板一起出现。

### 1.2 默认选中项：随机地形

**默认永远是「随机地形」**，第一张卡、默认高亮。理由很实际：开局面板的默认值
必须等于"不选"。如果默认记着上一局的固定地图，新玩家第一局就会莫名其妙地进一张
别人画的图；而且"怎么取消"会变成一个需要学习的问题。

「随机地形」这张卡把 `config.fixedMap` 清成 `undefined`——**选得进去，也退得出来**。

### 1.3 切换逻辑：状态同步与实时生效

| 环节 | 行为 |
|---|---|
| 点一张卡 | `config.fixedMap = fixedMapById(id)`，随即 `config.size = map.w`，立刻重绘 |
| 点「随机地形」 | `config.fixedMap = undefined`，尺寸保留上一次的值 |
| 重绘 | 面板整块 `innerHTML` 换掉，滚动位置与焦点由既有的 `paint()` 保留逻辑搬回去 |
| 生效时机 | **下一局**。开局面板是"这一局的参数"，改它不会动正在打的局 |
| 上一局的地图 | 会作为初始值带回面板（`initial.fixedMap`），连着打同一张图不用每次重选 |
| 地貌 / 对称 / 种子 | 选了固定地图后这三项**不生效**，提示条会直接写出来：「已选『双河渡口』：这一局的地貌、对称、尺寸与种子都不生效」 |

**为什么不是"选中即改当前对局"**：开局面板和战场是两个状态，正在打的对局有一份
自己的 `state.config`。让面板实时改战场等于中途换地图，那是一次"所有人都没同意过的
重置"。所以"实时生效"的准确含义是——**面板上立刻反映，开局时立刻采用**。

### 1.4 数据与建局的连接点

```ts
// setup.ts
const fixed = config.fixedMap ? validateFixedMap(config.fixedMap) : null;
const layout = fixed?.ok
  ? layoutFromRows(fixed.map.rows, fixed.map.citiesA, fixed.map.citiesB, spawnPool, citySize)
  : generateLayout(...);   // 原来的随机生成
```

- 固定地图**在 setup 里再校验一次**，而不是信调用方：`config` 会跟着存档、联机房间、
  分享链接一路传，谁都能改它。校验不过就退回随机生成——一张坏图不该让整局建不起来，
  但也不能让它带着半张地形进场。
- 城位只存**左上角**，边长由局内 `citySize` 决定：同一份地图，没开「城郭」时是 2×2
  的城，开了就是 3×3——地图数据一个字都不用改。
- 开局部队仍由 `spawnsAround` 撒（和随机地图同一条规则）：手绘图**不该自己定
  "谁站哪"**，那部分规则一旦两处各写一份，改一处就会漂。

## 二、地图上传：入口、格式、校验、入库、生效

### 2.1 入口位置与可见性

**开始界面 → 左侧「地图」页 → 最下面「上传地图」**。

- 入口**对所有玩家可见**，不再藏在上帝模式里。理由只有一个：这张表存在的意义
  就是"给别人用"，而"给"和"用"在同一个画廊里，才叫一件事。
- 上帝模式侧栏里那个「地图工坊」已经撤掉。同一件事留两个门，只会让人在
  "我该去哪个面板"上多花一次时间。
- 地图页上从不隐藏一切正常的东西：**门槛不靠藏，靠校验**——坏文件进不来，
  所以入口可以大方摆着。
- 地图库拉不到（断网 / 表没开通）时，这一块照样在，只是提示改成一句原因，
  不会把整个上传流程灰掉：拉不到列表和传不上去是两回事。

### 2.2 支持的文件格式与大小限制

| 项 | 值 |
|---|---|
| 扩展名 | `.json` / `.txt`（`accept` 也放了 `application/json,text/plain`） |
| 单文件上限 | **256 KB**（`MAP_MAX_BYTES`），客户端先挡一次，服务端策略再挡一次 |
| 地图尺寸 | **8 ~ 40 格见方** |
| 地形字符 | `.` 平原 `f` 森林 `h` 丘陵 `~` 水 `^` 山 `=` 桥 |
| 城位 | 每方 1~8 座；只写左上角；离边界至少 1 格；互相不重叠 |

**纯文本格式**（可直接在记事本里画，模板在 `maps/example-map.txt`）：

```
name: 两桥之间
................
..ff.......ff...
..ff.......ff...
................
..~~..~..~~.....
.~~~~.~.~~~~....
..~~..~..~~.....
................
.A...........B..
................
```

- 第一行带字母/汉字就当地图名；
- 行内空格忽略（方便对齐着画），行尾不足自动补平原；
- `A` / `B` 标的是双方城的**左上角**；连着糊一片 `A` 也只算一座城；
- 城位字母本身不是地形，落地时还原成平原。

**JSON 格式**（程序生成 / 从别处导出）：

```json
{ "name": "两桥之间", "rows": ["...", "..."],
  "citiesA": [{ "x": 1, "y": 8 }], "citiesB": [{ "x": 13, "y": 8 }] }
```

两种格式走**同一个校验函数**（`validateFixedMap`），不存在"JSON 能过、文本不能过"。

### 2.3 校验与失败提示

三道门，顺序固定：

1. **选文件时**：超过 256KB 直接挡（不再读内容）；
2. **解析时**：`parseMapFile` → `validateFixedMap`，把**能改的都指出来**（最多显示 3 条）；
3. **上传前**：再校验一次 + 量一次体积（防止"解析之后又被改过"）。

错误提示是**带坐标**的，不是"格式错误"四个字：

```
第 3 行第 4 列是「X」，不是可用地形（. 平原 / f 森林 / h 丘陵 / ~ 水 / ^ 山 / = 桥）
城位 (14, 13) 贴边了：城要离边界至少 1 格（2×2 的城左上角最大是 13, 13）
第 4 行长度是 15，和第一行（16）不一致
甲方一座城都没有（citiesA）
```

**扩展地形（`P` 台地 / `w` 沼泽 / `s` 浅滩 …）一律不收**：一份"给所有人玩"的地图用了
它们，在没开对应扩展的局里会还原成平原甚至未知格子。固定地图要能跨房间分享，
所以门槛画在这里——想用扩展地形，那种图只该留在自己的存档里。

### 2.4 上传成功后的处理流程

```
① 解析      parseMapFile(file.text())
② 预览      「看一眼再传」——缩略图 + 名字 + 尺寸 + 双方城数（就地展开在同一块里）
③ 上传      uploadSharedMap() → 云端表 warchess_maps
④ 登记      registerUserMaps([…]) 进本机注册表
⑤ 选中      config.fixedMap = 新图、config.size = 图宽——传完就能直接用
⑥ 提示      「已上传『两桥之间』，现在所有玩家都能在地图库里选到它（本局已选中）」
```

**为什么是"两步"（先预览再上传）**：上传是**公开且不可撤回**的动作——传上去别人
就能选到。作者至少该看一眼缩略图，确认自己没传错文件。所以解析完不会自动上传。

**为什么传完顺手选中**：作者传一张图，下一步十有八九是"就在这张图上打一局试试"。
让他再去上面的画廊里把自己刚传的那张找出来点一遍，是纯粹的多余动作。

**存储**：云数据库 `public.warchess_maps`（建表脚本 `sql/warchess_maps.sql`）：

| 列 | 含义 |
|---|---|
| `id` | 自增；前端拼成 `user:<id>` 作为地图 id |
| `created_at` | 上传时间，列表按它倒序 |
| `name` / `author` | 地图名 / 作者昵称（可空） |
| `w` / `h` / `rows` | 尺寸与地形（`rows` 是字符串数组） |
| `cities_a` / `cities_b` | 城位（`[{x,y}]`） |
| `listed` | 是否公开列出（留着以后做"隐藏某张图"的余地） |

权限和报告表**刻意不同**：报告表只写不读（谁都能交、没人能把别人的拉下来）；
这张表**公开读、公开写**——它的存在意义就是给别人用。安全边界不放在权限上，
放在校验上：前端只认 `validateFixedMap` 放行的数据，一份坏图最多是"列表里点不动"，
不会被执行。表里只存地形和坐标，没有任何脚本、URL 或可执行内容。

RLS：

```sql
create policy warchess_maps_read   on public.warchess_maps for select using (listed);
create policy warchess_maps_insert on public.warchess_maps for insert
  with check (w between 8 and 40 and h between 8 and 40 and length(name) between 1 and 24);
```

### 2.5 让所有人可玩的生效方式

四段链路，缺一段就断：

1. **公开可读**：任何人打开开局面板 → `listSharedMaps()` 拉 `warchess_maps` 里
   `listed = true` 的行 → `registerUserMaps()` 登记进本地注册表 → 画廊里就多出这些卡
   （卡上标「· 玩家地图」）。
2. **断网也能玩**：最近一次成功拉取的结果会写进 `localStorage`
   （`warchess.maps.cache.v1`），下次打开面板先同步登记缓存。云端拉不到时列表照常有。
3. **联机不出岔**：建局时整份地图**内嵌进 `config.fixedMap`**，而不是只存一个 id。
   房间存的是整份 `GameState`，所以对面进来时地图已经在 state 里——两边一定是同一张图。
   存 id 的话就会出现"对方没拉过这张图 → 两边各打一张不同的图"，而且不会报错。
4. **复盘/重开**：`initial.fixedMap` 会带回开局面板，同一张图连着打几局不用重选。

新增的规则用例：

- **内置图能开成局，地形与数据逐格一致** —— 四张内置图逐个建局，256 格逐格比对，
  并检查两边都有开局部队；
- **坏数据被挡住，报错要指出是哪一处** —— 尺寸太小 / 非法字符（要报行列）/ 没城 /
  贴边的城 / 扩展地形；
- **纯文本格式能直接画** —— `A`/`B` 标记、行尾补齐、JSON 等价、空文件与坏 JSON 的提示。
