# 剧情关：投稿与发布

这份文档回答一件事：**一张用关卡编辑器做出来的关，怎么从"我本机的草稿"变成"所有玩家在「关卡」栏里能打的剧情关"。**

面向两类人：

- **作者**：会打开编辑器、会点「上传」，但不一定碰代码。
- **审核 / 维护**：有审核台口令，以及仓库的提交权限。

---

## 先说最容易误解的一点

> **审核台「放行」≠ 进主线。**

「放行」只决定“别人能不能在云端看到这张卡片”。它进的是「编辑器」栏里的**“别人的关卡”**。

要进「关卡」栏（主线 / 教学），必须经过**仓库一次提交**。原因在最后一节，先记住结论。

---

## 全景

```
作者    编辑器里做关 ──→ 本机自测 ──→ 上传（进云端，待审）
                                        │
审核    &admin=1 打开审核台 ──→ 查看 / 试玩 ──→ 放行
                                        │
                                 详情里「下载 JSON」
                                        │
维护   放进 src/levels/story/ ──→ index.ts 加两行 ──→ 提交 ──→ 发布
                                                                    │
玩家                                                          「关卡」栏可见
```

三道关，分别解决三件事：**内容对不对**（作者自测）、**能不能公开**（审核）、**算不算主线**（仓库）。

---

## 一、作者：做一张关

**入口**：游戏主菜单 →「开始对局」→ 左侧「编辑器」→ 选一张示例关「复制成我的关卡」，或点「新建关卡」。

编辑器里七个按钮对应七块内容：

| 按钮 | 做什么 |
|---|---|
| 画地图 | 地形、城的落点 |
| 摆兵 | 每家开局有什么兵、摆在哪 |
| 席位 | 几家、谁交给电脑、谁中途登场、谁没有城 |
| 事件 | 第几次行动发生什么（刷兵、改地形、旁白） |
| 胜负 | 守住多少回合 / 把某人送到某处 / 斩首 |
| 兵种 | 这一关独有的单位（守将、信使），以及**禁止玩家造的兵** |
| 扩展与 AI | 必须开 / 禁止哪些扩展包；AI 的攻击性旋钮 |

字段细节、事件写法、已经踩过的坑，看 **[关卡开发指南](GUIDE-LEVEL-AUTHORING.md)**。这份文档只管流程。

> **地图不用单独上传。** 教学关的地图是关卡的一部分（编辑器「画地图」画的就是它）。
> 地图库那个上传口是给"我想拿这张图打自由对局"用的，和剧情关是两条线。

**自测**（存之前就该做）：

- 底部「试玩」——直接用当前数据开一局，看目标、事件、兵力是不是你要的。
- 底部「跑 3 局」——让 AI 两边对打，看会不会僵住、会不会三回合就结束。

**本机预览进主线**（可选，方便看最终效果）：

勾上编辑器里的「**这一关是剧情关**」→ 保存。这张关会立刻出现在「关卡」栏。

这个勾选只写进你本机的关卡数据，**别人看不到**，上传也不会因此把它塞进别人的主线。它只是让你提前看到"进了主线长什么样"。确定要发布时，把勾去掉也无妨（发布走的是另一条路）。

---

## 二、作者：上传

1. 编辑器里「保存」。
2. 左侧「编辑器」→「我的关卡」→ 右上角「**管理 / 导入导出**」。
3. 在列表里找到那张关 → 点「**上传**」。

上传前会被拦的情况：

- 数据过不了校验（编辑器右下角已经列出来了）——先改。
- 数据超过 **256KB**（正常关卡远到不了，通常是地图字符画写得过大）。

成功之后界面上会写：**「已提交「XX」，等审核放行后别人才能看到。」**

到这一步你的活基本干完了。**上传 ≠ 发布**，别人现在看不到它。

---

## 三、审核：放行 + 导出

1. 游戏链接后面加 `&admin=1`（例如 `...?admin=1`），打开审核台，输入口令。
2. 切到「关卡」tab。待审的会标「待审」。
3. 点「**查看**」：能看到地图缩略图、几家、事件数、目标数，可以「**试玩这张关**」（会在游戏里直接开一局，不影响存档），也能展开原始 JSON。
4. 没问题就点「**放行**」。之后所有玩家都能在「编辑器」栏的“别人的关卡”里看到它（只读）。

**进主线还要多做一步**：在「查看」的详情里点「**下载 JSON**」。

这个文件就是这张关的全部数据。把它交给有仓库权限的人（或者你自己就是）。

---

## 四、维护：放进主线

1. 把下载到的文件重命名成有意义的名字，放进仓库：

   ```
   src/levels/story/ch-01.json
   ```

2. 打开 `src/levels/story/index.ts`，加两行：

   ```ts
   import ch01 from './ch-01.json' with { type: 'json' };

   export const STORY_RAW: unknown[] = [ch01];
   ```

   加第二关就是再 import 一个、塞进数组。

3. 提交、发布。

下一版发布之后，**所有玩家的「关卡」栏都有它**，不联网也能玩。

**加载时会自动校验**：每份 JSON 都过一遍关卡校验，不合格的那一份会被跳过，并在浏览器控制台打一条 `[story] 主线关数据不合法，已跳过：…`。一份手改坏的 JSON 不会让整个游戏打不开——它只是不出现。

发之前建议跑一次 `npm run probe:level`：它会把注册表里每张关过一遍，包括你刚放进来的这张。

---

## 五、发布之后

- 玩家在「关卡」栏看到它，点进去 → 底部「确定」→ 看简报、挑扩展 → 「开始对局」。
- **是快照**：作者之后在云端改了自己的那份，已经发布的主线**不会**跟着变。想更新主线，重新走一遍「下载 JSON → 覆盖文件 → 提交」。
- 「编辑器」栏里的那张云端副本仍在，玩家可以复制成自己的关卡改着玩——不影响主线那份。

---

## 为什么不能"放行即主线"

审核台明明能看到数据，为什么还要绕一次仓库？三个理由：

1. **离线**。主线是产品的一部分，不是订阅内容。如果「关卡」栏靠实时拉云端，断网 / 飞机上就打不开。仓库里的文件跟着版本走，永远在。
2. **快照**。作者可以随时改自己云端那份。主线需要的是"发布时的那一版"，不能被作者后来的改动意外改变。
3. **可审阅**。`git diff` 能看到每一关的每一次改动。出了平衡问题，能查是哪一次改坏的。

代价是每加一关要有一次提交——这是有意的：往主线里加内容本来就该是一次有意识的动作。

## 常见问题

**Q：我放行了，为什么玩家在「关卡」栏看不到？**
A：放行进的是「编辑器」栏的“别人的关卡”。进「关卡」栏要经过第四节那次提交。

**Q：我勾了「这一关是剧情关」，朋友说看不到？**
A：那个勾选只作用在本机。要让所有人看到，走上传 + 审核 + 仓库。

**Q：上传时报"数据有问题"？**
A：编辑器右下角会逐条列出来（比如"城位越界""事件引用了不存在的兵种"）。改完再存一次。

**Q：上传按钮点了没反应 / 说太大了？**
A：单张关的 JSON 上限 256KB。多数情况是地图字符画写得过大，或者事件铺得太密。

**Q：作者自己改了一版，主线会变吗？**
A：不会。主线是你提交进仓库的那份快照。要更新就重新下载、覆盖、提交。

**Q：能不能一次发布多关（一章）？**
A：现在 `STORY_RAW` 是一个扁平数组，加几关都行，顺序就是数组顺序。章节 / 解锁进度还没做，等主线设计定下来再加。

**Q：地图也能进主线吗？**
A：不需要。教学关自带地图。地图库的上传是给自由对局选图用的，和剧情关无关。

## 发布前检查清单

- [ ] 编辑器里「试玩」跑通，目标 / 事件 / 兵力都对
- [ ] 「跑 3 局」没有僵局，也没有一回合结束
- [ ] 上传成功，审核台能看到并试玩通过
- [ ] 放行 + 下载 JSON
- [ ] 文件放进 `src/levels/story/`，`index.ts` 加了 import
- [ ] 控制台没有 `[story] 主线关数据不合法` 警告
- [ ] `npm run probe:level` 通过
- [ ] 提交、发布、在「关卡」栏实机点进去开一局
