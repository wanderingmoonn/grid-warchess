# 选兵标准（P2 的判据，2026-11-25 讨论稿）

> 讨论的起点：防守时"按对面兵种挑自己造什么"，到底用哪种办法。
> 四种意见——① 按射程/溅射/多段/移动/甲/血/攻的优先级，挑"超过或克制"的；
> ② 所有属性加权求和；③ 直接选最强；④ 还要算特殊能力。
>
> **本文的结论：① 的方向对，但"优先级"要改成"顺序否决"；② 不能用；③ 只能当兜底；
> ④ 不是另加一项，它就是否决链里的一条。**

---

## 1. 先确认：这些属性引擎里都真实存在

`UnitTypeDef`（`core/types.ts:450`）：

| 用户提的 | 字段 | 说明 |
|---|---|---|
| 射程 | `range` | 曼哈顿距离 |
| 溅射 | `splash`（半径）、`splashLine`（直线） | 主目标周围一圈 / 一条线 |
| 多段 | `burst` | 每回合几次独立攻击，**每次可换目标**、独立触发反击 |
| 移动 | `move` | 移动力（地形有额外消耗） |
| 甲 | `armor` | **伤害 = 攻击 − 护甲，直接相减**，没有系数 |
| 血 | `maxHp` | — |
| 攻 | `atk` | — |
| 特殊能力 | `abilities[]` | 见 `core/abilities.ts` |

24 个战斗兵种里：

- **溅射 2 个**：迫击炮（3 代，射程 4，splash1）、火炮（5 代，射程 5，splash2）；
- **多段 3 个**：机枪队（4 代，burst3）、重机枪（5 代，burst4）、装甲车（4 代，burst2）；
- **特殊能力 11 个**，战斗相关的就三类：
  - `armor-pierce` **破甲**（无视目标一半护甲）—— **7 个兵有**，最普遍；
  - `shield-wall` **盾墙**（本回合没移动过时受伤 −2）；
  - `siege-master` **破城**（攻城伤害 ×2）；
  - 另有一个 `stealth`（斥候潜行）。

**一个关键事实**：这些能力**不需要我们另写公式**。引擎的 `previewAttack` 已经把它们算进结果：

```
previewAttack(s, 攻方, 守方) → { toDefender, toAttacker, toSplash, counter }
```

实测（火枪 vs 坦克，甲 10）：`atk 23 − 甲 10 = 13`，但 `previewAttack` 给 **16**——破甲生效。
所以**判据一律读 `previewAttack`，不自己拿 atk 减 armor**（这条在 X-2-01 已经踩过一次）。

## 2. 四种意见，逐条判

### ① 按优先级挑"超过或克制"的 —— **方向对，但"优先级"这个词要换掉**

对的地方：它承认属性之间有**先后**，不是平权的。
错的地方：**排序键 ≠ 否决**。排序键回答"哪个更好"，否决回答"这个有没有用"。

差别在哪：
- 排序键：射程不够的兵会排在"射程够但攻低"的后面，**但仍然在候选里**；预算只够买它时，
  它还是会被买下来。
- 否决：射程不够 = 这一手贡献 0 = 不买；宁可攒钱。

S-002 就是排序键的后果：45 个射程 1 的民兵排在"够不着"的位置上，但它们便宜，
所以一直被买——排序键从来没有把它们**排除**过。

### ② 所有属性加权求和 —— **不能用**

三条理由，一条比一条硬：

1. **量纲不同**：射程是格、攻是点、血是点、移动是格。加法没有物理意义，权重只能靠拍。
2. **加权表达不了"一票否决"**：射程 1 的兵，攻 100 也打不出伤害。加权会把它算成
   "攻很高，综合分不错"。
3. **克制是局部的，权重是全局的**：同一个兵，对炮、对步枪、对坦克的价值完全不同
   （对炮要散、对步枪要贴、对坦克要破甲）。一张全局权重表只能给一个**平均答案**，
   而平均答案在每一种具体情况下都是错的。

这第 3 条正是 v3 的死法：**一张加权表同时管"该不该打 / 打谁 / 走哪"**，
最后所有判断都塌成一个全局 argmax。用户自己的怀疑（"算权重搞不出克制关系"）是对的——
克制是"能不能"的布尔关系，不是"多好"的连续关系。

### ③ 直接选最强 —— **只能当兜底**

它在一种情况下确实对：**代差碾压**（我 4 代打对面 3 代），选最贵最强的没错。
但它有两个前提：① 钱够；② 没有更便宜的解法。

它失败的样子就是 S-002：45 个"最便宜"的兵，从来不是"最强"。
"选最强"如果不看敌人，等于"选最贵"，会先把经济拖死。

所以它的位置是**候选池空了之后的兜底**（"至少比不还手强"），不是主判据。

### ④ 特殊能力 —— **不是另加一项，它就藏在否决链里**

不需要给能力单独设权重，因为它影响的是三条否决中的某一条：

| 能力 | 影响哪一条 |
|---|---|
| 破甲 | **打得穿**（对高甲目标，13 变 16） |
| 破城 | 打得穿（对城） |
| 盾墙 | **挨得住**（站住时受伤 −2） |
| 潜行 | 不在这三条里，是"看不看得见"的问题（P6 侦查） |

而且只要读 `previewAttack`，前三个**自动生效**，不用为能力写任何分支。

## 3. 判据：三段否决 + 候选内比性价比

对敌方画一张"威胁画像" `E`（怎么取见 §4），然后每个候选兵种 `c` 过三道闸：

### 闸 1：打得到吗（射程 / 移动）

```
c.range >= E.reach            // 对射不吃亏
或 c.move >= E.reach - c.range // 这一手能走进射程（贴脸）
```

两条都不成立 → **否决**。它对这场仗的攻击贡献是 0，只能挨打。

### 闸 2：打得穿吗（对最硬的敌人有实际伤害）

```
previewAttack(c → E 里最厚血的那个).toDefender >= 1
```

等于 0 → 否决（打不动就是 0 输出，堆十个也是 0）。

### 闸 3：挨得住吗（用"会反击的那个伤害"，不是 atk）

```
previewAttack(E 最强单发 → c).toAttacker < c.maxHp
```

注意读的是 **`toAttacker`**（含反击判定、含盾墙），不是 `E.atk`。
若 `E` 有溅射或多段，标准提高一档：**两发不死**（溅射会同时打多个，多段会连打）。

**三条全过 = 可用**。三者是"与"，不是加权。

### 候选内再比：每金的有效输出

过了三闸的候选通常不止一个。这时才谈"性价比"，而且**只在这一个维度上比**：

```
价值 = (toDefender × 能挨几发) / 价格        能挨几发 = ceil(c.maxHp / max(1, 对方单发))
```

这个式子只用来**排候选池内部的顺序**，不用来跟"没过的候选"比——
没过的已经被否决了，不参与排序。

### 候选池空了怎么办

**攒钱，不买。** 这是 P1 已经确立的方向（"买不起像样的就攒"），也是人类的行为。
兜底只有一种情况：这一手不还手就要丢城 → 退回"攻击最高的"（原来的兜底保留）。

## 4. 敌方画像 `E` 怎么取（这里有个坑）

不能只取极端值（"最高甲 + 最厚血"），那样会挑出一个**对谁都不专精**的兵。
也不能取平均，那会把"一群步枪兵里混一个坦克"平均成一个不存在的敌人。

建议取**两张画像**，分别过闸，取**并集**：

| 画像 | 取法 | 用途 |
|---|---|---|
| `E_main` **多数** | 数量最多的那一类（按 `type`） | 决定"这一手主要打谁" |
| `E_hard` **最硬** | 血最厚 / 甲最高的那一个 | 防"打不穿"（专门对付混编里的硬点） |

选兵的顺序：先满足 `E_main`（多数决），再用 `E_hard` 复核闸 2——
**两个都过不了的候选才否决**。这样"打杂兵够用、打硬点也能蹭一点"的兵会留下来。

这一节是 P2 里最需要实测的部分，先不写死。

## 5. "堆量"到底什么时候成立（用户 2026-11-25 的判断）

用户的说法：

> 敌方射程大但**无溅射、无多段** → 可以选射程 ≥ 敌方、或移动快、或护甲高的；
> **最后才是**用许多不符合要求的兵充数、以伤换伤。
> 但如果敌方有**多段或溅射**，连"堆量"这条也要排除，得尽量散开前进。

翻成判据只有一句：

> **堆量不是一种战术，是"敌方无法有效清理你"时的默认选项。**

所以：
- 敌方有溅射 / 多段 → **堆量是负资产**（一发清一片），闸 3 直接否掉"血薄量多"的路线；
- 敌方射程远、无溅射 → 堆量是**最后手段**（以伤换伤），排在"射程够/移动快/甲高"之后；
- 这条正好是 P1 删掉 `outnumbered` 的延续：**人数本身不是质量**，
  只有在"敌人清不掉你"的前提下，人数才变成优势。

**"散开前进"这件事**（用户明确说现在不考察）记在 §7，不进 P2。

## 7. 不做清单（这些别试）

- **属性加权求和**（量纲不同 + 表达不了否决 + 克制是局部的）。
- **给每个候选兵算一个"综合战斗力"再比大小**（同上，只是换了个名字）。
- **按"当前这一手缺不缺"来采购**（那是 P2 之后的"编成"，现在先做"这一手该造什么"）。
- **用单颗种子的绿当结论**（一直的规矩）。

## 8. 记下来但**不做**的（用户 2026-11-25 明确）

- **散开前进**：敌方有溅射/多段时，正确做法是散开接敌，而不是堆在一条线上。
  这需要"阵型"概念（现在的编队只有"落点去重"，没有"间距"）。
  **等 P4（投送）之后再谈**，因为它和行军是同一套代码。
- **"预警 / 侦查 / 袭击经济"三种行军目的**：见 `PLAN-V4-PHASE2` 的 P5 / P6。
