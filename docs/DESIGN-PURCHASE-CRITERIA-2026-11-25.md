# 选兵标准（P2 的判据，2026-11-25 讨论稿）

> 讨论的起点：防守时"按对面兵种挑自己造什么"，到底用哪种办法。
> 四种意见——① 按射程/溅射/多段/移动/甲/血/攻的优先级，挑"超过或克制"的；
> ② 所有属性加权求和；③ 直接选最强；④ 还要算特殊能力。
>
> **本文的结论：① 的方向对，但"优先级"要改成"顺序否决"；② 不能用；③ 只能当兜底；
> ④ 不是另加一项，它就是否决链里的一条。**
>
> 2026-11-25 二稿（用户意见）：**"打得穿"提到第一**；**"打得到 + 挨得住"合成一条**
> （抵近途中不死就算有输出）；候选内比较改成**双口径**（每金 / 每格），按瓶颈选——
> 守城时产兵格只有 4 个，只看每金会选出"放不下"的答案。

## 1. 先确认：这些属性引擎里都真实存在

`UnitTypeDef`（`core/types.ts:450`）：

| 用户提的 | 字段 | 说明 |
|---|---|---|
| 射程 | `range` | 曼哈顿距离 |
| 溅射 | `splash`（半径）、`splashLine`（直线） | 主目标周围一圈 / 一条线 |
| 多段 | `burst` | 每回合几次独立攻击，**每次可换目标**、独立触发反击 |
| 移动 | `move` | 移动力（地形有额外消耗） |
| 甲 | `armor` | **伤害 = 攻击 − 护甲，直接相减**，没有系数 |
| 血 | `maxHp` | — |
| 攻 | `atk` | — |
| 特殊能力 | `abilities[]` | 见 `core/abilities.ts` |

24 个战斗兵种里：

- **溅射 2 个**：迫击炮（3 代，射程 4，splash1）、火炮（5 代，射程 5，splash2）；
- **多段 3 个**：机枪队（4 代，burst3）、重机枪（5 代，burst4）、装甲车（4 代，burst2）；
- **特殊能力 11 个**，战斗相关的就三类：
  - `armor-pierce` **破甲**（无视目标一半护甲）—— **7 个兵有**，最普遍；
  - `shield-wall` **盾墙**（本回合没移动过时受伤 −2）；
  - `siege-master` **破城**（攻城伤害 ×2）；
  - 另有一个 `stealth`（斥候潜行）。

**一个关键事实**：这些能力**不需要我们另写公式**。引擎的 `previewAttack` 已经把它们算进结果：

```
previewAttack(s, 攻方, 守方) → { toDefender, toAttacker, toSplash, counter }
```

实测（火枪 vs 坦克，甲 10）：`atk 23 − 甲 10 = 13`，但 `previewAttack` 给 **16**——破甲生效。
所以**判据一律读 `previewAttack`，不自己拿 atk 减 armor**（这条在 X-2-01 已经踩过一次）。

## 2. 四种意见，逐条判

### ① 按优先级挑"超过或克制"的 —— **方向对，但"优先级"这个词要换掉**

对的地方：它承认属性之间有**先后**，不是平权的。
错的地方：**排序键 ≠ 否决**。排序键回答"哪个更好"，否决回答"这个有没有用"。

差别在哪：
- 排序键：射程不够的兵会排在"射程够但攻低"的后面，**但仍然在候选里**；预算只够买它时，
  它还是会被买下来。
- 否决：射程不够 = 这一手贡献 0 = 不买；宁可攒钱。

S-002 就是排序键的后果：45 个射程 1 的民兵排在"够不着"的位置上，但它们便宜，
所以一直被买——排序键从来没有把它们**排除**过。

### ② 所有属性加权求和 —— **不能用**

三条理由，一条比一条硬：

1. **量纲不同**：射程是格、攻是点、血是点、移动是格。加法没有物理意义，权重只能靠拍。
2. **加权表达不了"一票否决"**：射程 1 的兵，攻 100 也打不出伤害。加权会把它算成
   "攻很高，综合分不错"。
3. **克制是局部的，权重是全局的**：同一个兵，对炮、对步枪、对坦克的价值完全不同
   （对炮要散、对步枪要贴、对坦克要破甲）。一张全局权重表只能给一个**平均答案**，
   而平均答案在每一种具体情况下都是错的。

这第 3 条正是 v3 的死法：**一张加权表同时管"该不该打 / 打谁 / 走哪"**，
最后所有判断都塌成一个全局 argmax。用户自己的怀疑（"算权重搞不出克制关系"）是对的——
克制是"能不能"的布尔关系，不是"多好"的连续关系。

### ③ 直接选最强 —— **只能当兜底**

它在一种情况下确实对：**代差碾压**（我 4 代打对面 3 代），选最贵最强的没错。
但它有两个前提：① 钱够；② 没有更便宜的解法。

它失败的样子就是 S-002：45 个"最便宜"的兵，从来不是"最强"。
"选最强"如果不看敌人，等于"选最贵"，会先把经济拖死。

所以它的位置是**候选池空了之后的兜底**（"至少比不还手强"），不是主判据。

### ④ 特殊能力 —— **不是另加一项，它就藏在否决链里**

不需要给能力单独设权重，因为它影响的是三条否决中的某一条：

| 能力 | 影响哪一条 |
|---|---|
| 破甲 | **打得穿**（对高甲目标，13 变 16） |
| 破城 | 打得穿（对城） |
| 盾墙 | **挨得住**（站住时受伤 −2） |
| 潜行 | 不在这三条里，是"看不看得见"的问题（P6 侦查） |

而且只要读 `previewAttack`，前三个**自动生效**，不用为能力写任何分支。

## 3. 判据：两段否决 + 双口径比较（2026-11-25 按用户意见改）

原来的写法是"打得到 → 打得穿 → 挨得住"三段平列。用户提了三条修正，都成立：

1. **"打得穿"要排第一**——打不穿的一切都该直接省略（0 输出，堆十个也是 0）；
2. **"打得到"和"挨得住"要合成一条**——因为常常**不得不造一些兵抵近攻击**；
   只要能活着走到射程内，它最终就有输出，不该因为"现在够不着"被否掉；
3. **"每金有效输出"不够**——防守时产兵格有限（陆军产兵点就是城自己的格子，
   2×2 城只有 **4 格**），所以只看每金会选出"便宜量多但放不下"的答案。

### 闸 1：打得穿吗（一票否决，对**多数决目标**）

```
previewAttack(c → E_main).toDefender >= 1
```

`E_main` = 数量最多的那一类敌人（不是最硬的那个，见 §4）。
等于 0 → **否决**。这类兵对这场仗的主要威胁毫无贡献。

### 闸 2：送得到 + 活得到吗（合并成一条）

这一条回答的是"**它能不能产生输出**"，而"现在够不够得着"只是其中一种情况：

**先承认一件事：到达有两条路，取较快的那条。**

```
① 等它来：foeEta(我射程边缘)  —— 敌人几回合自己走进我的射程（用 9.7 那份步场，不用新代码）
② 我走过去：ceil(max(0, 距离 − c.range) / c.move)
到达回合 = min(①, ②)
```

防守时绝大多数情况是①——敌人正在往城走，我不该迎上去，站住等它进射程就行。
只有"敌人不动、我必须去打"时才用②。

然后：

```
if (到达回合 > 决定的剩余期限)          → 否决（送不到）
if (到达回合 == 0)                      → 通过（现在就打得到）
单发     = previewAttack(E_main → c).toDefender   // 敌人打我一下多少（注意方向）
挨打次数 = 到达回合 × (E_main.burst ?? 1)         // 多段会加倍
if (挨打次数 × 单发 >= c.maxHp)         → 否决（死在路上）
```

⚠️ **方向别搞反**（2026-11-25 踩过）：`previewAttack(s, A, B).toDefender` 是 **A 打 B** 的伤害；
`toAttacker` 是 **B 反击 A** 的伤害。算"敌人打我"要用 `previewAttack(敌人, 我).toDefender`。

要点：

- **"够不着"不再是死罪**，只是"迟几手才有输出"。只要路上死不了，它就算有输出——
  这正是用户说的"不得不造一些兵抵近攻击"。
- 读的是 **`toAttacker`**（含反击判定），不是 `E.atk`；有溅射/多段的敌人，
  `burst` 直接进"挨打次数"。
- **"决定的剩余期限"**是硬的：决定层说"守到第 8 手"，送不到第 9 手的兵就不该造。
  这条同时解决了"造了兵赶不上"的老问题（以前完全没有这个检查）。

#### 拿 S-002 验一遍（15 格外、12 个 4 代步枪兵：36 攻 / 射程 4 / 甲 3）

| 候选 | 血 / 甲 | 射程 / 移动 | 步枪打它 | 它打步枪 | 走过去要几手 |
|---|---|---|---|---|---|
| 民兵 | 28 / 2 | 1 / 2 | **34** | 10 | 7 |
| 长枪兵 | 40 / 3 | 1 / 2 | 31 | 12 | 7 |
| 戟兵 | 46 / 5 | 2 / 2 | 32 | 18 | 7 |
| **火枪兵** | 36 / 3 | **4** / 2 | **33** | **22** | **6** |
| 骑士 | 40 / 4 | 1 / 3 | 33 | 14 | 5 |

- **民兵**：闸 1 过（10 伤害），闸 2 **不过**——走 7 手、每手挨 34、只有 28 血，**第一发就死**。
  这正是"打不穿"和"活不到"的区别：它打得穿，但活不到能打的那一刻。
- **火枪兵**：射程 4，可以**等它来**（敌人 4 格内才挨打），36 血挨 33 不死 → 能形成输出。
  所以 S-002 的正解是火枪，不是民兵。

这条也说明为什么"射程"不能只看大小：民兵射程 1 的 7 手是**暴露在射程里的 7 手**，
火枪射程 4 的 6 手里有 3 手是**在敌人射程外走的**。两者风险完全不同。

### 闸过完之后：两个口径，按**瓶颈**选

候选池里通常不止一个。这时不谈"综合分"，只谈"这一个单位的产出"，而且**算两种**：

| 口径 | 公式 | 什么时候用 |
|---|---|---|
| **每金输出** | `(toDefender × 能挨几发) / 价格` | 钱是瓶颈（进攻、开阔地，位置不受限） |
| **每格输出** | `(toDefender × 能挨几发)` | **格子是瓶颈**（守城：城格就 4 个，站满了连兵都造不出来） |

**谁是瓶颈由场景决定**，不是加权：

- `decision.kind === 'defend'`，**且钱能把城格全填上**（`金 ≥ 城格数 × 池内最贵候选的价格`）→ **每格**；
- 其他 → **每金**。

> **2026-11-25 实测修正（P2-2c）**：第一版写的是"只要是守就按每格"，**这条是错的**。
> 无条件按每格会把 **S-012 / P-1-01 / P-1-02 三道一起弄红**：每格口径挑最贵的强兵（骠骑兵 150 一匹），
> 300 金只买得起 2 个，4 个城格只填了 2 个；而 3 个戟兵（100）能填 3 个。
> **"每格"的前提是钱能把格子填满**；填不满时瓶颈还是钱——这是个背包问题
> （`Σ n ≤ 格数, Σ n·价 ≤ 金`，最大化 `Σ n·值`），贪心解就是"每金最划算"，
> 而 P1 又实测过那条路会选回民兵。所以两个极端都不对，判据必须带上前提。
>
> 另外：**"每金"最终没有实现成 `输出 ÷ 价格`**，而是保持 P1 的字典序（价格只在同分时做最后一档）。
> 原因同上——价格一做分母就选回 1 代民兵（S-001 造 21 个、S-002 造 45 个）。
> 落地的条件写在 `constrain.ts` 的 `bottleneck` 与 `V4-CODE-MAP` 9.19。

为什么这一条必须单独说：防守时钱再多也只能站 4 个（城格），
按"每金"会选 4 个民兵，按"每格"才会选 2 个戟兵——**同样的钱，后者总输出更高**。
用户那句"很可能被格子数约束住"就是这个。

### 池子空了怎么办

**攒钱，不买。** 兜底只有一种：这一手不还手就要丢城 → 退回"攻击最高的"。

## 4. 敌方画像 `E` 怎么取（这里有个坑）

不能只取极端值（"最高甲 + 最厚血"），那样会挑出一个**对谁都不专精**的兵。
也不能取平均，那会把"一群步枪兵里混一个坦克"平均成一个不存在的敌人。

取**两张画像**，但**只有 `E_main` 参与否决**：

| 画像 | 取法 | 用途 |
|---|---|---|
| `E_main` **多数** | 数量最多的那一类（按 `type`） | **闸 1、闸 2 都用它判**——它代表"这场仗主要打谁" |
| `E_hard` **最硬** | 血最厚 / 甲最高的那一个 | **不参与否决**，只用来排序：同样过闸的候选，对 `E_hard` 也有伤害的优先 |

为什么 `E_hard` 不能参与否决：混编里有一个坦克，按"最硬"判会把所有候选都否掉
（3 代兵打不动 5 代坦克），结果是"一手不造、城被杂兵推平"。**打不动硬点不等于没输出**，
硬点应该交给专门的兵（破甲）或者绕开。

这一节是 P2 里最需要实测的部分，先不写死。

## 5. "堆量"到底什么时候成立（用户 2026-11-25 的判断）

用户的说法：

> 敌方射程大但**无溅射、无多段** → 可以选射程 ≥ 敌方、或移动快、或护甲高的；
> **最后才是**用许多不符合要求的兵充数、以伤换伤。
> 但如果敌方有**多段或溅射**，连"堆量"这条也要排除，得尽量散开前进。

翻成判据只有一句：

> **堆量不是一种战术，是"敌方无法有效清理你"时的默认选项。**

所以：
- 敌方有溅射 / 多段 → **堆量是负资产**（一发清一片）：闸 2 的"挨打次数 × 单发"里
  `burst` 会加倍，血薄的兵在路上就死光了，根本到不了候选池；
- 敌方射程远、无溅射 → 堆量是**最后手段**（以伤换伤），排在"射程够/移动快/甲高"之后；
- 这条正好是 P1 删掉 `outnumbered` 的延续：**人数本身不是质量**，
  只有在"敌人清不掉你"的前提下，人数才变成优势。

**"散开前进"这件事**（用户明确说现在不考察）记在 §7，不进 P2。

## 6. 落地分三档（每档都能单独测）

| 档 | 做什么 | 修的是什么 | 验收 |
|---|---|---|---|
| **2a 打得穿** | 闸 1（`toDefender ≥ 1`） | "造了一堆对主要威胁 0 伤害的兵"（弓手打 5 代坦克） | 新题 `P-1-03`（高甲对手）；全量不许有题退 |
| **2b 送得到 + 活得到** | 闸 2（到达回合 ≤ 期限；挨打次数 × 单发 < 血） | **S-002 的真病根**：民兵走 7 手、每手挨 34、只有 28 血——它不是"打不穿"（一发 10），是**第一发就死在路上** | S-002 里射程 1 的兵不再进候选（应改买火枪）；`P-1-03` 绿；S-012 / S-001 不退 |
| **2c 双口径** | 候选内按"每格 / 每金"（守城 → 每格） | 守城时"钱够但放不下"（城格 4 个） | ✅ **2026-11-25 完成，但口径加了前提**：`守 + 金 ≥ 城格数 × 最贵候选` 才切每格；无条件每格会把 S-012 / P-1-01 / P-1-02 弄红。27 道零变化（现有题都到不了这个金的量级）。题 `D-2-01`；`D-1-03` 不退。详见 `V4-CODE-MAP` 9.19 |
| **2d 能力** | 只在排序里体现（`E_hard` 那一维） | 破甲对高甲 | 等有题 |

**注意 S-002 的归因**：民兵 `atk 13 − 甲 3 = 10`，它**打得穿**；它死在"抵近"这一段。
所以修 S-002 要靠 2b，不是 2a。这条写在 2a 的验收里，防止以后又归错。

**为什么不一次做完**：2a 只用伤害与距离两个数，改坏了容易归因；2b 才开始用"单发伤害"
（`toAttacker`）；2c 只在"同类候选不止一个"时才起作用。分开做，红了知道是哪一档。

## 7. 不做清单（这些别试）

- **属性加权求和**（量纲不同 + 表达不了否决 + 克制是局部的）。
- **给每个候选兵算一个"综合战斗力"再比大小**（同上，只是换了个名字）。
- **按"当前这一手缺不缺"来采购**（那是 P2 之后的"编成"，现在先做"这一手该造什么"）。
- **用单颗种子的绿当结论**（一直的规矩）。

## 8. 记下来但**不做**的（用户 2026-11-25 明确）

- **散开前进**：敌方有溅射/多段时，正确做法是散开接敌，而不是堆在一条线上。
  这需要"阵型"概念（现在的编队只有"落点去重"，没有"间距"）。
  **等 P4（投送）之后再谈**，因为它和行军是同一套代码。
- **"预警 / 侦查 / 袭击经济"三种行军目的**：见 `PLAN-V4-PHASE2` 的 P5 / P6。
