# V2 策略网络：缺陷与结论（2026-11-06 收工记录）

这份不是计划，是**收工时把问题钉在纸上的记录**。写它的目的只有一个：
以后谁（包括我自己）想再碰这条路，先把这几十条看完，别从同一个坑再掉一遍。

所有数字都标了口径与出处；能在代码里对到行的都写了文件名 + 行号。

---

## 零、一句话结论

**在当前配置下（3.3 万参数、单帧观测、候选集 64、终局 ±1 奖励、浏览器推理、约 1536 局 / 160 万步训练），
这条路走不通。** 不是强化学习不行，是这个量级配上这些实现缺陷不行。

最硬的一条证据：**它的兵种选择 83.2% 是弓箭手，建造单位 0 次，一局里升级时代 0.02% 次。**
这不是"训练不够"，是"看不见 + 选不到"——下面 A、B 两节全部是这一条的成因。

---

## 一、现状数字（先看结果，再看原因）

| 指标 | 数值 | 口径 |
|---|---|---|
| 12×12 对不削弱手写 AI | **25.0 / 32.5 / 36.3 / 23.8%** （四次，统计上无差异） | 每格 40 局，95% 区间 ±14 点 |
| 10×10 同上 | 54.4%（34 轮时）→ 71.3%（最后一次） | 160 局 → 40 局，区间 ±8 → ±14 |
| 招募构成 | **archer 83.2%**、longbow 8.5%、militia 3.7%，**建造单位 0** | 6 局 12×12 / 543 次招募 |
| 时代升级 | 被选 **2 次 / 8718 次决策** | 同上 |
| 动作构成 | 走子 72.5%±0.9、攻击 14.0%±0.7、建筑 0.0%±0.0 | mix2 12 轮，每轮 64 局 |
| 12×12 撞回合上限丢弃 | **34%**（32 局丢 11） | rollout-11 |
| 训练量 | 约 1536 局 / 160 万步 | mix1+mix2，各 12 轮 × 64 局 |

对照手写 AI：龙骑兵采用率 3/100 局，而专用脚本用龙骑兵打出 **95% 胜率**。

## 二、A 类：观测缺陷（**看不见**）

看不见的东西，训练再多也学不到。这是最致命的一类。

| # | 缺陷 | 证据 | 影响 |
|---|---|---|---|
| A1 | **兵种特征缺 hp / move / vision / domain / 能力** | `src/rl/features.ts:841-849` 只有 category / atk / armor / range / cost / era / hero / economy | **83% 弓手的直接原因**：能看见的四项里，弓手的"每金攻防"是龙骑兵的 2.3 倍；真正让龙骑兵值 265 的（移 5、冲锋 +5、58 血）一个都不在特征里 |
| A2 | **地图尺寸不可见** | `span = max(w,h)` 只当归一化分母（`features.ts:426`）；没有任何一格表示"这是 16×16" | 结构上无法"按尺寸换打法"；实测 10×10 与 12×12 的行为几乎一致（弓手 86.4% vs 83.2%） |
| A3 | **城市血量只有平均值** | `f[26]` 双方城墙血比、`f[35]/f[36]` 双方平均；平面 2 只存归属 | 不知道"西南那座城只剩 12 血"，只知道"我方平均 62%" |
| A4 | **驻军 / 经验 / 等级 / 击杀数未编码** | `features.ts` 全文 grep 不到 `garrison` / `kills` / `vet` | 老兵和新兵在它眼里一样；无法判断某座城危不危险 |
| A5 | **地形被粗化到 6×6** | `BOARD_N = 6`，平面 0 是该粗格内所有格的**平均**可通行度 | 16×16 每格约 2.7×2.7、32×32 约 5.3×5.3；单格山/河口被平均掉，大图无法精确走位 |
| A6 | **对方兵种只有统计量** | `f[17]/f[18]` 兵种熵、`f[19]` 远程占比、`f[20]` 经济占比 | 不知道"对面是 7 个弓手"，无法针对性出兵（对面全远程该上骑兵） |
| A7 | **扩展开关只有 4 位** | `f[45..48]` 只有血战 / 行动点 / 地形高差 / 先手补偿 | 奇想、时代军备、古文明、天气、浓雾开了等于没告诉它 |
| A8 | **迷雾开关有编码但训练从没打开** | `f[44] = s.fog ? 1 : 0`，而 `TRAIN` 恒 `fog = false` | 这一格永远是 0，它从没见过 1；产品默认开雾，等于一直活在下见过的状态里 |
| A9 | **动作特征里发起单位缺 hp 比例** | `features.ts:770-777` 有 atk/armor/range/move/cost/era，无 `hp/maxHp` | 残血兵和满血兵在"要不要动它"这件事上没有区别 |

**为什么会出现 A1**：`src/core/unit-value.ts` 的头注释里写着这件事的历史——
"第二把尺子只读三个数，于是**移速、视野、多段、能力全都不算钱**……AI 的采用率只有 1%，
它不是'知道强却不买'，是它的尺子量不出来"。那次修了 `ai.ts` 的采购，
**但没有修到特征层**，于是同一个坑换了个地方又踩一次。

## 三、B 类：动作空间缺陷（**选不了**）

候选集是"策略能选的动作集合"。它被剪得太狠，等于把选择权收走了。

| # | 缺陷 | 证据 | 影响 |
|---|---|---|---|
| B1 | **候选上限固定 64，不随合法动作数变化** | `policy.prescreen` 取 top-K（K=64） | 12×12 平均每步 91 个合法动作 → 覆盖率天生不足；图越大越糟 |
| B2 | **RECRUIT 有一半的步数整类进不了候选** | 12×12：进候选率 26.9%，**53.4% 的决策步一个招募候选都没有**；10×10 也有 14.7% | 招募决策退化成"在能进来的那一两种兵里挑" |
| B3 | **UPGRADE 被剪掉 87.6%** | 12×12：进候选率 11.0%，87.6% 的步数无候选；全 8718 步只被选 2 次 | 城市永远 1 代 → **3 代以上兵种从未进入合法动作**（龙骑兵造不出来） |
| B4 | **从不造建造单位 → BUILD 从未成为合法动作** | 6 局 543 次招募，建造单位 0 次；诊断里 BUILD 类型根本没出现 | 0 建筑。这一条是 B2 的下游：经济/建造兵没进候选，就永远没有建造动作 |

**因果链**：候选剪枝 → 招募只剩廉价战斗兵 → 没有建造单位 → 没有 BUILD → 0 建筑 →
收入只有城市基础产出 → 升不起时代 → 高代兵种用不了 → 只剩"走 + 打 + 造弓手"。

## 四、C 类：训练信号缺陷（**学不动**）

| # | 缺陷 | 说明 |
|---|---|---|
| C1 | **奖励只有终局 ±1** | 造民夫、盖房子、升级时代，当回合没有任何回报 |
| C2 | **折扣让发育的回报趋零** | "造建筑 → 3 回合后多产出 → 8 回合后能出高级兵"折完几乎为 0，而"现在多一个弓手"当回合就能打 |
| C3 | **撞回合上限的局整局丢弃** | 12×12 丢 34%（32 局丢 11）；这些局的前 100 回合是有内容的，全丢 |
| C4 | **不能让平局得分** | `ppo.py` 里试过"平局给 0（比输的 −1 好）"，结果策略学会拖时间，中位回合 22 → 40，所以后来改成整局丢弃。现在 34% 的丢局率就是这条约束的代价 |
| C5 | **意图机制存在但训练没用** | `INTENT_NAMES = [rush, harass, boom, auto]`，编码在 `f[40..43]`，rollout 支持 `--intent random`，但训练一直 `auto` | 
| C6 | **座位固定 A（已修）** | 曾经只让策略坐先手；修后实测 A/B 座差 22.5（10×10）/ 27.5（12×12），但这主要是游戏的先手优势（先手方胜率 62~65%，训练口径没开先后手补偿） |

## 五、D 类：验收与工程缺陷（**问题看不见**）

这一类是最值得后来者警惕的：前三类都是"它不会"，这一类是"我们不知道它不会"。

| # | 缺陷 | 后果 |
|---|---|---|
| D1 | **`test:net` 只有完整性检查** | 4 条用例：权重逐字节一致、维度对齐、能走完一局、同种子确定。**没有一条检查它做了什么**——所以"83% 弓手 / 0 建筑 / 不升级"这个状态可以一直绿灯 |
| D2 | **评估只看胜率** | `RL-PLAN-v2.md §八` 定了"分扩展报、分削弱档报、分意图报"，**唯独没有"分行为报"**。胜率能被一种畸形战术刷上去，正好掩盖"只会一种打法" |
| D3 | **训练尺寸与产品尺寸错位** | 训练 `[10, 12]`，产品预设 `[12, 16, 20, 32]`，自定义 4~64。16/20/32 一个都没练过 |
| D4 | **面板文案只交代了尺寸与时代** | `setup-panel.ts:495` 写了"别的尺寸与时代会很弱"，**没写扩展包、没写选卡模式**——这两条同样是训练分布外 |
| D5 | **没有组合矩阵** | 没有一张"尺寸 × 时代 × 扩展 × 选卡 × 迷雾 × 人数"的表标明"训练内 / 训练外"，所以每条新能力都是"顺带支持" |

## 六、根因：三条

1. **特征是人手挑的，两个 AI 盲在同一处。**
   老 AI 的采购公式只算 `攻 × √血 × 射程`，V2 的兵种特征只有 `攻/甲/射程/造价`。
   **同一把残缺的尺子**，所以两个都看不见"贵、快、能打"那一档。
   龙骑兵在两边都被低估，不是巧合。

2. **候选剪枝把"选择"变成伪命题。**
   在"造什么"这一步只有 1~2 个选项时，"按局面换战术"无从谈起。
   先有选项，才谈得上选择——这个顺序不能反。

3. **验收只看胜率，行为退化不可见。**
   胜率是结果，可以被一种畸形战术刷到 54%。
   没有行为断言，就没有任何东西会变红。

## 七、如果重来：给后来者的顺序

1. **先写观测契约，再写编码器。**
   把条件变量（尺寸、时代、扩展开关、迷雾开关、可用兵种集合）**在第一版就占好位置**，哪怕当时只用一种设置。
   维度只会增加不会减少，每一次增加都意味着重跑预训练。

2. **先写行为断言，再跑训练。**
   一条能力上线，必须同时有一条能让它变红的断言：
   "招募种类 ≥ 3"、"建造单位 > 0"、"升级 ≥ 1"、"雾里看不见的敌人绝不在候选里"。
   这套断言应该是**第一天**就有的，不是第 N 天才补。

3. **小规模验证"能不能学会一件事"，再谈通用。**
   先验证"能不能学会用机动单位打经济"，而不是一上来做"适应所有设置的通用 AI"。
   前者的成功/失败一天就能看到，后者要几周。

4. **量级要对得上。**
   1536 局 / 160 万步是玩具级。AlphaZero 级是百万局 + 搜索 + 大模型。
   如果目标是"超过一个手写专家系统"，投入量差 2~3 个数量级时，先别怪算法。

5. **对手是浏览器时，模型规模被物理限制。**
   推理在玩家浏览器（`public/ai/net-v2.json` 175 KB + `src/rl/` 的 JS），
   服务器零计算、零并发成本。代价是不能上大模型、不能上深搜索。
   要"更强"就得把推理搬到服务器——那是另一套成本结构。

## 八、RL 在这类游戏里的定位（诚实的结论）

RL 的本质优势只有一条：**不用人写规则就能获得策略**。其余都是派生的。

当人类已经能写出不错的规则时（回合制、离散动作、规则透明、无实时微操——正是本游戏），
RL 的边际价值就很小。它真正值钱的场景是"规则写不出来"（围棋、星际微操）。

所以在这个项目里，RL 的现实价值**不是"更强的对手"，而是"更会试的测试员"**：
生产多样化的对局数据、给平衡表提供"兵种在不同使用水平下的区间"。

但要拿到这个价值，也要先修完 A、B 两类缺陷——否则它连"试"都试不到（83% 弓手、0 建筑）。

## 十一、最后一句

这批代码里真正有价值的东西不是那个 3.3 万参数的权重，而是：
**一个确定性的引擎、一套可复现的训练管线、一批能量化"它到底在做什么"的诊断工具。**

权重可以丢，这三样别丢。
