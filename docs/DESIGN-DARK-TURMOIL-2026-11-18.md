# 「黑暗动乱」· 设计草案与最小实现

> 2026-11-18。依赖修真包（`requires: ['cultivation']`）的剧情扩展。
> 这一版只做到**最小可跑**：衰老 → 寿元见底 → 吞同伴续命 → 还是老死。
> 仆从、诡异、攻城、波次、数值全未做。

---

## 1. 设计草案（作者口述，原样记录）

- **尸骸仙帝**：实力凌驾于九级修士之上（修真包最高 9 级），但**和九级修士不同，它还会老**。
- 平时在**沉眠地**休整，年龄增长缓慢；寿元濒临耗尽时出来发动「黑暗动乱」，
  清洗天地间所有生物换取寿元，然后回去接着睡。
- 单位分两类：
  - **仆从**：帮仙帝压制玩家成长；
  - **诡异**：增生的怪物，按自己的逻辑行事，不听指挥。
- 仙帝缺"食物"（敌人不够吃）时，会**清理同阵营单位，从低级往上**。
- 所有单位 / 建筑**都不能造**，只能由关卡模式生成。
- 「不迎战」的代价：仙帝隔一段时间来把玩家基建打爆；诡异可能直接攻破城市；
  仆从会定点清理高威胁单位。
- 寿元对玩家只给**模糊描述**，不给数字。

---

## 2. 三个机制决策（已落地）

### 2.1 不走修真的境界系统

`MAX_RANK = 9`，且 9 级的寿元是 `Infinity`。往修真包里塞"第 10 级"会牵动属性公式、
经验墙、面板、规则书和整套平衡，而本包只是**借**修真那套语义。

所以：尸骸仙帝不是修士兵种，`isCultivatorUnit` 不认识它；属性直接给一组
高于九级修士的固定值（九级大约：攻 +257 / 甲 +119 / 真伤 66 / 每回合 5 段攻击）。

**好处**：修真包一行没改；将来修真包调数值，这个 boss 不会跟着漂。

### 2.2 年龄用引擎的 `u.age`，不去拦核心

核心在回合开始时给**所有**单位 `age += 1`（`rules.ts` 的回合开始）。
我们的钩子在这之后跑，所以：

- 不在沉眠地 → 再 `+1`（合计 **+2**/回合）；
- 在沉眠地（2 格内）→ 不加（合计 **+1**/回合）。

这就是"沉眠地延缓衰老"。核心的年龄规则一个字没动，也没去"倒扣年龄"。

### 2.3 寿元存在 `custom.lifespan`（自己读写）

修真包的 `getLifespan` 优先读这个字段、且要求是有限数——所以给 9 级兵写一个
有限寿元它也会认。但**修真包的 `isDoomed` 只对修士生效**，我们的 boss 不在其列，
所以判死得自己做（我们在钩子里比 `age > lifespan`）。

顺带：寿元不落"Infinity"，所以序列化没坑。

## 5. 实跑发现（重要，别当结论丢了）

关体实跑 40 个行动的结果：

```
仙帝年龄 194 / 寿元 210 · 吞噬 1 次 · 场上同伴 3 个 · 胜者 B
```

两件事：

1. **"吃自己人"这条循环在真关里确实会触发**（吃了 1 次，寿元 200 → 210）。
   不是只在探针里成立。
2. **40 个行动内玩家被清场**。300 攻 / 130 甲 / 1600 血 对 2 代修士是碾压。
   这不是 bug，是"占位数值 + 没做关卡节奏"的必然结果。

**所以这个关现在不能当难度关看**，它只是"循环跑得通"的证据。

## 5b. 暗影领域（2026-11-18 已实现，探针验过）

诡异投下的黑雾。**基础效果**：一个单位站在暗影里（视野菱形内**超过一半**是暗影），
它的**视野和射程减半，向上取整**。后续的联动效果（吸血、召唤、骨堆……）都还没做。

### 口径（写死，别改着玩）

| 项 | 值 |
|---|---|
| 形状 | 曼哈顿距离的菱形（和视野、射程同一套度量） |
| 分母 | 只数**地图内**的格子（贴边时不把界外算成"没被覆盖"） |
| 触发 | 严格**超过一半**（正好一半不触发） |
| 减半 | 向上取整，不低于 1（视野 11→6、射程 4→2、射程 1→1） |
| 叠加 | 多个诡异不叠乘，只判"是/否"一次 |

### 三个实现决策

**① 每回合末整份重铺，不跟着诡异走。**
诡异一边移动一边刷新，一次走 3 格就要重铺三片菱形；而 `visionOf` / `effectiveRange`
是每个兵、每个候选、每一帧都要问的热路径。代价是"当回合它走了，黑雾还留在原地"——
这是**故意的**，玩家因此能看见"它挪开之后哪里露出来了"。

**② 存在局面里（`GameState.overlays.shadow`），不是实时算。**
这样规则层、AI、界面读的是**同一份**，不会出现"高亮显示能打、点下去说射程不够"。
`playerView` 是 `structuredClone`，视图天然带着它（已验：雾图算出的视野 = 真局算出的视野）。
副作用是存档里多一份格号数组——每回合末重写，不累积。

**③ 界面用现成的棋盘视图，不碰渲染代码。**
`boardViews` 注册一个「暗影」色层，核心的 `onlyVisibleCells` 会按迷雾过滤，
所以雾里的黑斑画不出来，也不会被拿去反推"雾里站着几个诡异"。

### 一个必须记住的陷阱

**`modifyVision` 里不能回头调 `visionOf` / `playerView`**：`playerView` 算迷雾时
正在逐个单位调 `visionOf`，回头一查就是死循环。只能用钩子给 `base`。

### 已知限制

- **只在**地球**上算**（`overlays` 存的是 `tiles` 的下标）。多图之后要按图分开，
  现在的写法会把月球单位的暗影画到地球上。等真的有多图关卡再处理。
- 当回合不跟随移动，所以"走进去的瞬间"不会立刻被削——要等下一次重铺。

### 验证：`npm run probe:shadow`（8 段）

铺得对（半径 8 = 145 格）/ 视野 9→5 与射程 4→2 / 走出去恢复 /
边界（90/181 不减半、91/181 减半）/ 当回合不跟随、交棒后重铺 /
雾图与真局一致 / 没有诡异时零影响 / 没开这个包的局完全不受影响。

## 5c. 影系三兵（2026-11-18，行为逻辑跑通）

诡异的第一支。**不听指挥**靠 `aiAutonomy: 1` + `Expansion.unitAi` profile：
核心照样给它们算候选，但 profile 在"它有自己的想法"时用更高分压过全局的推进。

| 兵 | 名字 | 定位 | 占位数值 | 本能 |
|---|---|---|---|---|
| `shadow-beast` | **蚀影**（补的名字，备选影蚀体/侵影） | 慢速近战，被暗影侵蚀的生物 | 血 55 / 甲 6 / 攻 22 / 射 1 / 移 2 / 暗影 3 | 走向**暗影边界**（下一步就能扑进亮处） |
| `shade` | **暗影** | 快、飞行、多段攻击，一团会杀人的影子 | 血 40 / 甲 18 / 攻 10 / 射 2 / 移 5 / 3 段 / 暗影 1 | 跟同类**散开**（都挤在一起等于浪费） |
| `shadow-lord` | **影主** | 远程、厚、高甲，第一任是仙帝的影子 | 血 220 / 甲 15 / 攻 40 / 射 4 / 移 2 / 2 段 / 暗影 7 | **不贴身**（被贴住就只剩肉盾价值） |

通用技能 **暗影跳跃**：瞬移到任意暗影格，用掉之后 `moved = true`（不能跳完再走）。

### 真伤为什么叫「暗蚀」

修真那边叫"真元"——那是修士的词。诡异用同一个词出戏，所以单独起名 **暗蚀**。
实现和真元是同一条路：`DAMAGE_STAGE.trueDamage` 上加一段固定伤害，
**物理被护甲吃光时它照样进**。探针里用 999 甲靶子验过：伤害正好等于暗蚀值。

### 两条"越打越多"的因果

- **暗影击杀 → 原地长出蚀影**（`onUnitKilled` + `api.spawn`）。所以清场顺序变得重要：
  先清暗影，否则每杀一个杂兵就多一具会走路的尸体。建筑不触发（影子从石头里长出来太出戏）。
- **影主召唤**：`custom.summonIn` 计时器，正常 4 回合一个暗影；**它攻击过的回合算 2 格**。
  计时器拆成两半：回合末记"这回合打没打"，下回合初走格子——因为回合开始的钩子跑在它出手之前。
  表现上"它越凶，暗影来得越勤，但差半拍"，玩家有机会在召唤前打断。

### 一个架构教训（写下来免得再踩）

包一开始想 `import { registerUnitAiProfile } from './unit-ai.ts'`，结果**模块初始化顺序爆炸**：
`unit-ai.ts` 在模块顶层遍历 `EXPANSIONS`，而 `EXPANSIONS` 正在导入这个包 → 循环。
正确做法是走 `Expansion.unitAi` 字段（它本来就是为此设计的）。同理不要从包里 import 任何会
反向依赖 `expansions.ts` 的东西——和 `ai-meta.ts` 顶部那条警告是同一件事。

### 顺带改的核心

`UnitAiCtx` 加了 `foes` / `allies`（由核心筛好，含同盟判定）。理由和 `SkillAiCtx` 一样：
一次决策要给每个兵问一遍，profile 各自 `filter` 全图是 O(兵²)，而"谁是敌人"各写一遍迟早漏。

### 目标偏好（2026-11-18 第二轮）

| 兵 | 优先打谁 | 判据 |
|---|---|---|
| 蚀影 | **落单的生物** | 两格内没有同伴的敌人——它是伏击者，扑进人堆只会被围死 |
| 暗影 | **补刀** | 射程内血最少的 |
| 影主 | **威胁最大的** | 射程内 `atk + magicAtk` 最高的——它怕的就是这个 |

顺序也是设计的一部分：蚀影"先扑落单 → 再守边界 → 最后才考虑走位"；
影主"先开火 → 贴脸就退 → 没敌人才藏"。

### 影主没事往哪走：选「暗影最深处」，不选重心

两个候选我都算了，选**"离边界最远的那一格"**：

- **重心可能落在暗影外**。一团环形、或者两块分开的黑雾，重心正好在中间那块**亮处**——
  影主会主动走进玩家的视野里。这不是理论问题，是很容易在关卡里出现的形状。
- 重心还会被一块又长又细的影子拉偏，落在边界上。
- "离边界最远"这一格**按定义就在暗影里**，而且越深越安全：玩家得把整片黑雾翻开才找得到它。

实现是一条多源 BFS（从贴边的暗影格往里推层数），按 overlay 数组对象缓存——
同一回合里数组不变，所以每个回合只算一次。

### 暗影跳跃：改了什么

| 项 | 现在 |
|---|---|
| 攻击后 | **不能跳**（`acted` 挡）；跳完**能攻击** |
| 走完 / 跳完 | 都能——跳跃不占移动额度（不改 `moved`） |
| 冷却 | 1 个自己的回合（等于每回合一次），另由 `skillTurn` 兜"一回合一次" |

**它们自己会用**（不是只有玩家能点）：

- 蚀影：够不着的落单目标旁边若有一格暗影 → **跳过去伏击**（165 分）
- 蚀影：走不到边界时 → 跳到最近的边界格（130）
- 影主：暗影深处还很远（超过移动力 +2）→ **直接化进去**（140）；近了才走

> 影主那条是刻意做成"远则跳、近则走"的：不然它每回合都在闪，看着像 bug。

### 验证：`npm run probe:shade`（50 条）

三个兵进表 / 不可建造 / 有暗影半径与自主分 / 暗蚀无视护甲（0 甲 30、10 甲少 10、999 甲仍 8）/
蚀影贴边 / 暗影散开 / 影主计时器（4 回合 vs 攻击时 2 回合）/ 击杀原地生成（别的兵种不生成）/
跳跃（跳不进无暗影处、攻击后不能跳、走完能跳、跳完能走、冷却 1）/
目标偏好三条 / 影主藏身与"远则跳" / 蚀影跳跃伏击。

## 5d. 支线关「影潮」（2026-11-18）

**菜单加了第三栏**：主线栏是别人按顺序填的，支线不占它的位置。

| 栏 | 判定 | 说明 |
|---|---|---|
| 关卡 | 不写 `demo` / `side` | 主线 / 教学，一关接一关 |
| 支线 | `side: true` | 共用世界观，但不要求顺序、不占主线位置 |
| 编辑器 | `demo: true` | 编辑器示例关 |

代码上：`LevelDef.side`、`sideLevels()`（`storyLevels` 排除 side）、`setup-panel` 多一页。
优先级 `demo > side > 主线`——示例关不会偷偷进支线。

### 关卡：影潮（`level:shadow-tide`）

18×18，玩家 1 城（第 5 代），B 席 `cityless`：2 影主 + 3 暗影 + 2 蚀影，分在右上 / 右下。

**目标是"守住 34 次行动"，不是"杀掉影主"。** 这一条是实跑之后改的：

- 第一版写"杀光两个影主"，实跑 32 个行动，玩家一个影主都没杀掉——影主在射程 4 上
  边打边退，玩家要顶着**半视野半射程**走进黑雾。这是设计，不是 bug。
- 错的是目标：把「杀光」当胜利条件，等于逼玩家打一场打不赢的仗。
- 现在：主目标是守住；顺手宰掉两个影主也算赢（`group: 1` 给斩杀，`group: 2` 给守住）。

**实跑（AI 打 AI，一个种子）**：暗影 3 → 7~10，蚀影来回波动，玩家 32 个行动还剩 7 个兵，
第 34 个行动按"守住"判玩家赢。节奏是"越拖越紧但守得住"。

### 修了两个老关的同一个 bug（重要）

`goals` 里**不写 `group` 的多条会被当成同一组，组内是"且"**。
所以下面两关的"提前宣布胜利"从来没生效过：

- `level:behead`（斩首）：斩杀守将 + 守方撑满 18 → 两条对立，永远不同时成立；
- `level:dark-turmoil`（黑暗动乱）：斩杀仙帝 + 撑满 60 → 同上。

实测：把目标兵种全删掉再交棒，胜者是"未决"。补上 `group: 1/2` 之后立刻恢复正常。

`probe:level` 加了一条**永久断言**：任何有 ≥2 条目标的关，每条都必须写 `group`。
这条能挡住以后所有人再踩一次。

## 5e. 菜单、面板、规则书（2026-11-18 第三轮）

### 关卡栏改成两块可折叠

```
关卡栏
├─ ▾ 自由对局 / 主线          （主线现在只有「自由对局」）
└─ ▾ 支线                    （按 chapter 分卷）
     └─ 黑暗动乱
          ├─ 黑暗动乱
          └─ 影潮
```

- `LevelDef.chapter`：支线的卷名，同名归一组。
- 折叠状态存在渲染闭包里（和 `tab` 一样），**不用原生 `<details>`**——
  面板每次点击都整块重绘，`<details>` 的展开状态会被重置（点一张关分组就自己收起来）。
- 「关卡」栏不再平铺：主线会一直长，支线还要分卷，平铺下去一屏放不完。

### 玩家看不见的东西，补上了

实机反馈三处"只写了名字没写数字/机制"，都补在 `getUnitPanelLines` 里：

| 兵 | 面板现在写 |
|---|---|
| 蚀影 | 暗影领域半径 3 格 · **暗蚀 8 点**（每次攻击额外结算，无视护甲） |
| 暗影 | 暗影领域半径 1 格 · 暗蚀 4 点 · **击杀单位后原地生出一个蚀影** |
| 影主 | 暗影领域半径 7 格 · 暗蚀 15 点 · **每 4 个自己的回合分裂出一个暗影（攻击过则更快）** |

口径照修真那册（`真元 ×1.5（33 点）`）：**数字写出来，别只写能力名**。

### 去掉 `element: 'dark'`

属性（element / weak / resist）是奇想包带进核心的规则，本包一个都不借。
五个兵种的 `element: 'dark'` 全部删掉——它们本来也没有 `weak/resist`，
删掉之后伤害一分不变（探针里的 30 / 8 点伤害对得上）。

> 更大的那一层污染（核心伤害管线里有 `DAMAGE_STAGE.elementMul`、`applyElementMul`）
> 这次没动：那是奇想包的命根子，抽出来是独立一轮，记在 PLAN 的污染清单里。

## 5f. 血系三兵（2026-11-18）

| 兵 | 名字 | 占位数值 | 本能 |
|---|---|---|---|
| `blood-pool` | **淤血** | 血 45 / 甲 10 / 攻 14 / 射 2 / 移 3 / **3 段** / 暗影 1 | 贴着血肉走、去咬**经济单位** |
| `flesh` | **血肉** | 血 160 / 甲 12 / 攻 26 / 射 1 / 移 2 / 暗影 1 / 暗蚀 5 | 离血核远一点、挑**薄甲** |
| `blood-core` | **血核** | 血 200 / 甲 10 / 攻 45 / 射 3 / 溅射 2 / 暗影 4 / 暗蚀 12 | 待在**暗影最深处**、打**威胁最大**的 |

四条机制（全是副作用，不是技能——它们不需要谁去点按钮）：

| 机制 | 效果 | 谁有 |
|---|---|---|
| 化血 | 造成伤害累计成"血"，每 60 点长一滩淤血（**一回合最多两滩**） | 三个都有 |
| 侵染 | 击杀的单位**变成血肉** | 三个都有 |
| 汲取 | 按造成的伤害等量回血 | 血肉 / 血核 |
| 增生 | 每回合回 12 血；**满血**攒 3 回合，剥出一团血肉 | 只有血核 |

### 三个实现决策

**① 尸体归谁：靠"最后补刀的是谁"分。** 暗影杀 → 蚀影；血系杀 → 血肉。
同一条 `onUnitKilled` 里分叉，不再排除建筑（作者要求"杀什么都能长"）。

**② 化血/增生放在"自己回合开始"结算，不放在伤害当刻。**
一次溅射可能同时打死三个人、触发三次生成，插在伤害结算中间会让"谁先被算死"变得难以预料。
放到回合边界上，场上状态先稳定，再长新东西——玩家看到的是"打完这一轮，血又厚了一层"。
（顺带一个技术原因：`TurnEndCtx` 里没有 `api`，spawn 不了。）

**③ 一回合最多长两滩淤血。** 不封顶的话，一次溅射打五个兵就会长五滩，两回合滚成十几滩。
这个上限是防止"雪崩"的，不是平衡数值。

### 验证：`npm run probe:blood`（33 条）

三个兵进表 / 不可建造 / 暗影半径 / 自主分 / 不带属性 / 淤血 3 段 / 血核溅射 2 /
化血记账与长出淤血（含"最多两滩"）/ 汲取按伤害回血且淤血不回 / 侵染变成血肉且长在尸体上 /
增生满血 3 回合剥出血肉、不满血只回血 / 三条目标偏好 / 三条走位。

## 5g. 三张对称关 + 第一组强度数据（2026-11-18）

同一张 18×18 图、同一批玩家兵力（6 个第 5 代兵、1 座城），**只有两群敌人的成分不同**：

| 关 | 两只队伍 | 头领 |
|---|---|---|
| 影潮 | 影 + 影 | 2 影主 |
| 血潮 | 血 + 血 | 2 血核 |
| 浊潮 | 影 + 血 | 影主 + 血核（**两个都死才算赢**） |

一群固定 4 个：1 头领 + 2 中坚 + 1 杂兵（影：影主/暗影/蚀影，血：血核/淤血/血肉）。

**为什么是 4 个而不是 6**：第一版按"1+3+2"配，两群 12 个，比改动前的影潮（7 个）多近一倍，
AI 打 AI 直接从"玩家能压着打"变成"20 个行动被打穿"。编队规模要贴着原来那关走。

**混编两个头领必须写在同一组**（`group: 1`）：组内是"且"，所以两个都得死；
分到两组就成了"杀一个就赢"。

### 第一组数据（AI 打 AI，5 个种子，玩家侧也是 AI）

| 关 | 结果 | 敌方峰值 |
|---|---|---|
| 影潮 | B 胜，20~34 个行动 | 8 → 11~17 |
| 血潮 | **多数打不完**（70 个行动封顶），偶有 A 胜（63 个行动） | 8 → 16~22 |
| 浊潮 | B 胜，26 个行动 | 8 → 25~36 |

三条结论：

1. **影系是滚雪球**：8 个涨到 17 个。召唤 + 击杀生成叠在一起，玩家越拖越打不过。
2. **血系是僵持**：玩家能涨到 27 个兵，但杀不动血核（200 血 + 每回合回 12 + 10 甲），
   双方都涨、谁也推不动。AI 不会集火头领，人打应该好得多——但"打不完"本身就是个警号。
3. **混编是乘法**：浊潮的敌人涨到 36 个，远超两支单独的 17 / 22。
   **两套"越打越多"叠在一起不能直接相加**，这是以后关卡混编必须先量的一条。

### 基于数据做的三个调整（都是占位值的第二次修正）

| 项 | 改动 | 理由 |
|---|---|---|
| 影主召唤 | 4 回合 → 5 回合 | 30 个行动涨 11 个，不是"难"，是滚雪球 |
| 化血阈值 | 60 → 100 | 三滩淤血一起打 1.5 回合就长一滩，滚得比玩家清得快 |
| 血肉护甲 | 12 → 8 | 160 血 + 12 甲 + 每回合吸 31，第 5 代打上去净伤害是负的 |

**没有继续调**：再往下调就是猜了——玩家侧是 AI，它不会集火头领、不会撤残血，
所以这组数字只能当"下限"，真正的手感要人打。

## 5h. 词条化 + 数值回调（2026-11-18 第四轮）

### 所有机制都成了「词条」

以前它们按兵种 id 写死在扩展钩子里（`if (u.type === SHADE)`），想给新兵加一条就得改代码；
面板还得另写一行说明——**所以血肉/血核的暗蚀只在面板上有，规则书里查不到**。

现在一条机制 = 一个 `AbilityDef`，挂在谁身上谁就有：

| 词条 | 效果 | 挂在 |
|---|---|---|
| 暗蚀 | 每次攻击附加无视护甲的固定伤害 | 影系三兵 + 血肉 + 血核 |
| **暗影侵蚀** | 击杀单位时在原地生成蚀影 | 暗影 |
| **化影** | 每 N 回合分裂一个暗影，攻击过则更快 | 影主 |
| **化血** | 伤害累计成"血"，攒够长一滩淤血 | 血系三兵 |
| **侵染** | 击杀单位时变身血肉 | 血系三兵 |
| **汲取** | 按造成的伤害等量回血 | 血肉 / 血核 |
| **增生** | 满血攒够回合剥出一团血肉 | 血核 |

代价是要给 `AbilityDef` 加一个 `valueLabel`（这条能力在某兵身上的具体数值），
面板和规则书都问它——**改一处两边一起变**。

> 名字不能叫 `valueOf`：那是 `Object.prototype` 上的方法，写在接口里会和所有
> 对象字面量的继承成员打架（TS 报"返回值 Object 不能赋给 string"）。

### "攻击过则更快"怎么记

`unit.acted` 读不到：能力的 `onTurnStart` 跑在回合开始时，那一刻它已经被重置。
所以「化影」用 `onStrike` 写一个 `custom.hit = 1`，回合开始读一次再清零。

### 血肉"喜欢聚集"的 bug

原来是"挑离血核最远的那一格"——对**每一团**血肉都是同一个全局最优，
于是它们全往同一个角上跑，看起来就是越散越挤。
现在打分 = 离血核 + 1.2 × 离最近同伴，两者都远才是好位置。

### 数值回调（作者定的口径）

| 项 | 值 | 说明 |
|---|---|---|
| 化血阈值 | **80** | 60 太密、100 太疏 |
| 化影间隔 | **4 回合** | 从 5 调回 4 |

**校准原则（记下来，以后别再按 AI 跑批削）**：
> AI 能打赢的局，对玩家来说其实很简单。以后测试只要 **AI 输得不太难看**就没必要削弱。

已经撤回的两处（影主召唤 5 回合、化血 100）就是按这条改回来的。

## 5i. 骨系三兵（2026-11-18）

三系列里唯一**能造出前两系列**的一支：骸骨吞血肉变尸骸、尸骸吞暗影变不详；
死了还要掉一地零件。所以它真正的威胁不是个体强度，是"清场顺序不对就滚成一支队"。

| 兵 | 占位数值 | 本能 |
|---|---|---|
| `bone-skeleton` **骸骨** | 血 70 / 甲 8 / 攻 20 / 射 1 / 移 3 / 暗影 1 | 去找**血肉**（吞了变尸骸）；没有就朝血最少的敌人爬 |
| `bone-corpse` **尸骸** | 血 150 / 甲 10 / 攻 32 / 射 3 / 溅射 1 / 暗影 3 | 朝**暗影**走；没暗影就不动 |
| `bone-unnamed` **不详** | 血 140 / 甲 12 / 攻 38 / 射 3 / 2 段 / 溅射 1 / 暗影 5 | 朝仙帝走但**到 4 格就停**；看不见仙帝就沉进暗影最深处 |

### 六个新词条

| 词条 | 效果 | 挂在 |
|---|---|---|
| **寻躯** | 回合末吞掉相邻血肉，自己变尸骸 | 骸骨 |
| **复苏** | 回合末吞掉相邻暗影，自己变不详 | 尸骸 |
| **腾空** | 本回合攻击过就升空；没打过就降落，落点被占则延后 | 尸骸 / 不详 |
| **拼装** | 死亡时留一个**半血**骸骨 + 两滩淤血 | 尸骸 |
| **点化** | 击杀生成骸骨 + 淤血 + 暗影各一个 | 不详 |
| **解离** | 被击杀时散成 2 淤血 + 1 骸骨 + 1 暗影 | 不详 |

### 为它加的一个核心钩子

`AbilityHooks.onTurnEnd`（2026-11-18）。能力原先只有 `onTurnStart`，而"本回合攻击过就起飞"
「相邻有血肉就吞」这两件事**必须看清这一回合做过什么**——`onTurnStart` 跑在回合开始时，
`acted` 已经被重置了。

实现位置：`doEndTurn` 里切人之后、`resetUnitsFor` 之前，按"刚结束回合的那一方"逐个跑。
这个位置能读到 `acted / moved`，也能看到这一回合打出来的结果（谁死了、谁站在旁边）。

### 三个踩过的坑

1. **死亡钩子里"原地生成"必然失败**（清场在钩子之后，尸体还占着那一格）。
   `拼装`/`点化` 都改成"先试原地、不行落相邻格"。
2. **`flight: true` 等于"一直在空中层"**，不是"会飞"。不详原本写了它，结果近战打不到
   （报"目标超出射程"）——它的"飞"应该由「腾空」改 `unit.layer` 来表达。
3. **探针里用同一方的兵当凶手会被拒**（"只能给自己人下命令"是另一条，别混）。
   表现是"死亡能力一条都没触发"，很容易误判成能力没实现。

### 验证：`npm run probe:bone`（30 条）

三个兵 / 寻躯与复苏（相邻才生效、变形后血量不超上限）/ 腾空三种情形（打过就飞、
没打过就落、地面被占就飘着）/ 拼装与解离的掉落清单 / 点化现场拼队 / 三条目标偏好 /
四条走位（含"到 4 格就停""看不见仙帝就沉底"）。

| 三血 | 血血血 | 单系基线 |
| 三骨 | 骨骨骨 | 单系基线（骨系首次出场） |
| 影血 | 影影血 | 两系 |
| 影血骨 | 影血骨 | 三系全上 |

五张关的玩家兵力、地图、群数完全相同，只有三队成分不同——所以是一条可比下来的线。

菜单里归到新的一卷「黑暗动乱 · 大势」，和原来的三张「潮」关分开。

| 关 | 结果 | 敌方数量 |
|---|---|---|
| 三影 | 未决，敌 11 | 8 → 峰值 22（**被压住**） |
| 三血 | 未决，敌 29 | 8 → 峰值 31 |
| 三骨 | **B 胜，26 个行动** | 8 → **59** |
| 影血 | 未决，敌 37 | 8 → 39 |
| 影血骨 | 未决，敌 51 | 8 → 54 |

骨系补了两个种子：**38 个行动 B 胜（敌 69）、46 个行动未决（敌 75）**。

### 结论：骨系是乘法，而且没有上限

- 影系会滚，但**玩家清得动**（峰值 22 → 打完剩 11）。
- 血系滚得慢，靠"杀不干净"拖住你。
- **骨系一回合能翻两三倍**：拼装（死后掉零件）+ 点化（击杀现场拼队）+ 解离（自己死也掉）

这不是数值问题，是**结构问题**：别的系"越打越多"是线性的（召唤/吸血），
骨系是"你打死它，它还多出三个"。要压住它得给"生成"本身设上限
（比如每个席位最多 N 个诡异，或者同类单位超过 M 个就不再生成），
而不是削它的攻击力。

> 顺带：60~75 个单位同场，AI 每步的耗时也上去了。真要做三系合关，
> 生成上限同时也是性能保护。

## 5k. 三系平衡第一轮（2026-11-18）

作者操作后的判断：**滚雪球其实不快**——格子占满就动不了，每个系列的顶点又倾向于聚合，
生成点位不多。真正的问题在别处。

### 1. 血系太肉 → 血肉 160 → 130

它一边给影系铺暗影、一边还打不死，等于占了两份便宜。

### 2. 骨系：变形加一回合间隔

原来"吞下→立刻变形"，玩家没有反应窗口。现在两段式：

1. 回合末吞下相邻目标，记 `custom.formTo`；
2. **下一个自己回合结束时**（这一回合它被锁住移动）才变形。

锁移动的办法：能力的 `onTurnStart` 把 `u.moved` 置真。引擎的 `canMove` 只看这个标记，
而 `grantTurnTo`（重置 moved）跑在 `turnStartSkills` **之前**，所以这一手能撑满一回合。
攻击不受影响——它只是"原地不动"，不是"不能动"。

**变形血量改成按比例换算**：一具满血 70 的骸骨变 150 的尸骸就是满血；半血 35 变 75。
原来的 `min(hp, newMax)` 等于"变形白送一堆血"。

### 3. 影系太弱 → 三个补强

| 项 | 改动 |
|---|---|
| 蚀影 | 加「化影」 |
| 影主 | 加「暗影侵蚀」 |
| 暗影半径 | 蚀影 3→4、暗影 1→2、影主 7→8 |

> 顺带：影主有了「暗影侵蚀」之后，探针里"只有暗影杀人才生蚀影"这条不成立了。
> 判据从"是不是暗影"改成了"有没有这条词条"——这正是词条化的收益。

### 4. 顶点不聚合：影主 / 血核保持 2 格

`kinCrowd()`：同类之间按距离扣分，**2 格及格，1 格和同格才扣**。
和"往暗影最深处走"叠加，平衡点落在 2 格左右。

- 影主 × 影主：扣分；血核 × 血核：扣分；
- **影主 × 血核：不扣**（各是各的根，凑一起反而好看）；
- 不详：不加（它本来就容易被造出一堆）。

顺手去掉了"已经站在最深处就直接返回"的早退——那条会让两个叠在一起的顶点永远不散开。

## 5l. 影系回摆 + 规则书补两处（2026-11-18）

### 影系强过头了：把"自己繁殖"还给血系

上一轮给蚀影加了「化影」，结果是**暗影杀人→蚀影，蚀影又生暗影**——
这支队伍自己就能闭环繁殖，把血系"越打越多"的特点抢走了。

| 兵 | 现在挂的词条 |
|---|---|
| 蚀影 | 暗蚀 + **暗影侵蚀** |
| 暗影 | 暗蚀 + 暗影侵蚀 |
| 影主 | 暗蚀 + 暗影侵蚀 + **化影** |

也就是说：**三系人人都有暗影侵蚀（杀死的东西站起来），但只有影主能生出新暗影**。
蚀影不再是繁殖单位，只是"尸体回收站"。

配套两处数值：

- **化影一次分裂两团**（暗影太脆，一个一个来根本铺不开）；
- **暗影更薄更"没实体"**：血 40 → 30、甲 12 → 16。

### 规则书：诡异的行动倾向进了「特殊规则」

玩家看不到它们为什么往那边走，这套东西就不可学习。放「特殊能力」那栏既不对也太长，
所以走 `Expansion.manualNotes`——它专门印在**特殊规则**那一节：

- 开头一句说清"它们不听指挥，倾向前全是固定的"；
- 然后每个单位一行：蚀影扑落单 / 暗影补刀且散开 / 影主打威胁最大的、贴脸就退、
  没事躲最深处、同类隔 2 格 / 淤血咬经济 / 血肉挑薄甲 / 血核打威胁最大的 /
  骸骨找血肉 / 尸骸朝暗影 / 不详朝仙帝但 4 格停。

## 5m. 不成系的三个：黑蝗 / 黑茧 / 诡异（2026-11-18）

三者之间有一条链：**黑蝗聚成团 → 结茧 → 升华成影主或血核**。
所以它们本质上是"给另外三支供料"的。

| 兵 | 占位数值 | 本能 |
|---|---|---|
| `black-locust` **黑蝗** | 血 20 / 甲 4 / 攻 1 / 射 1 / 移 5 / 3 段 / 暗影 **0** | 往暗影里钻、躲攻击力高的；咬**甲厚**的 |
| `black-cocoon` **黑茧** | 血 200 / 甲 14 / 攻 1 / 射 5 / 3 段 / 暗影 6（**建筑，不会动**） | 打**最近**的 |
| `unnamable` **诡异** | 血 60 / 甲 6 / 攻 12 / 射 3 / 移 5 / 暗影 6 | 补刀**血最少**的；没目标沉暗影最深处 |

### 暗影半径支持 0

以前 `shadowRadius ?? 0` 把"半径 0"和"没有暗影"当成了同一件事。现在：
`undefined` = 不投下暗影，**`0` = 只有脚下那一格**（黑蝗）。
免疫判定也跟着改：只要**投下暗影**（含半径 0）就不吃自己的雾。

### 三条新词条

| 词条 | 效果 |
|---|---|
| **繁殖** | 回合末，若相邻某格的 8 邻域恰有 2 只黑蝗、那一带全在暗影里、且没别的单位 → 在那里再生一只 |
| **结茧** | 回合末，四周都是黑蝗且脚下没有地面单位 → 吞掉它们，自己变黑茧（落地、不再飞） |
| **升华** | 回合末，两格内有暗影/血肉 → 自己消散，把它催成影主/血核（对方停一回合、按比例回血） |

繁殖**按个体算**：每只黑蝗每回合最多生一只，所以在场的两只各生一只——
成团之后每回合翻倍，这就是它必须靠"结茧"收束的原因。

### 「凝结」基建从词条里提了出来

升华的目标是**别人**（黑茧吞掉自己，让旁边的暗影变影主），而那只暗影身上
并没有寻躯/复苏那条能力。所以"锁移动 + 完成变形"不能再挂在词条里：

- `freezeForming`（回合开始）：有 `custom.formTo` 的单位 `moved = true`；
- `completeForming`（回合结束）：按比例变形并清标记。

词条只负责**触发**（吃什么、记什么）。顺序上有讲究：扩展的 `onTurnEnd` 跑在
能力的 `onTurnEnd` **之前**，所以"这一回合刚标记的"不会被当场完成，必须等下一回合。

### 「无形」只做了前半条

`hidden: !acted` = 不攻击时看不见（相邻也看不见），出手就现形。

**后半条没做**——"破隐后只有被命中的目标打得中它"：引擎里没有"谁能打谁"的钩子，
`AbilityHooks.hidden` 只回答"看不看得见"，不参与攻击合法性检查。
要做的话得给核心加 `canBeAttackedBy(ctx)`，在 `doAttack` 的检查里问一次。
先把看得见的那半做出来，那一半等方案定了再说。

### 验证：`npm run probe:odd`（26 条）

三个兵进表 / 黑茧是建筑且不会动 / 半径 0 只铺脚下、自己不掉视野、隔壁不受影响 /
繁殖（两只各生一只、中间格被填上）/ 结茧（四周同类才成、脚下有人就不成、落地不再飞）/
升华（黑茧消失、暗影停一回合、按比例变 110/220）/ 无形（未出手看不见、出手现形）/
三条目标偏好 / 三条面板词条。

## 5n. 无形凝视 + 满潮关（2026-11-18）

### 「无形」的后半条做出来了

方案按作者给的走，只是最后一步没去"换单位"，而是**让这一下打空**：

1. 它打中谁，就给谁贴一层「**无形凝视**」（`status`，2 = 撑过目标一整个回合）；
2. 它挨打时，打它的人身上没有凝视 → **伤害归零**，战报写"挥了一记，什么都没碰到"。

为什么不真做"把 victim 换成假单位"：换单位要新建、删除、还要处理追击和连带伤害，
一次攻击里能改的东西太多；"伤害为 0"在表现上完全一样（血没掉、人还在），只碰一个数。
以后真要做"假目标"（诱骗走位那种），再单独做。

技术上没加核心钩子：`onHit` 贴状态、`damage` 钩子在 `attackFlat` 阶段把伤害清零，
后面的乘法/减法都作用在这个 0 上。

### 满潮：32×32、两座城、三家

`level:full-tide`，C 席位 `cityless`，铺满**全系列**：
影主 + 2 暗影 + 蚀影 / 血核 + 2 淤血 + 血肉 / 不详 + 尸骸 + 骸骨 / 黑茧 + 2 黑蝗 + 诡异（15 个）。

- A、B 是**同盟**（`seats.teams`），各一座城，中间一条竖河隔开，只有两处渡口；
- 目标：三个头（影主 / 血核 / 不详）全砍掉（同组 = 且）。

### 一个真 bug：回合末钩子会"当回合连锁"

`doEndTurn` 里跑能力的 `onTurnEnd` 时直接遍历 `s.units`（活数组）。
黑蝗繁殖会往数组里 push 新单位，**这些新单位在同一回合里继续跑自己的回合末钩子**，
于是黑蝗在一回合内自己翻倍。

实测（41 个行动）：修之前敌方 139 个（其中黑蝗 96），修之后 68 个（黑蝗 35）。
`for (const u of [...s.units])` 一行的事——`sweepDead` 早就是快照写法，这里漏了。

> 剩下的 35 只仍然是指数（2 → 35 / 41 个行动）。这是"每只每回合生一只"这条规则本身的性质，
> 不是 bug——要不要封顶、封多少，是设计决定。

## 5q. 仆从：青铜卫 + 两条城市词条（2026-11-19）

剧情上两支东西不是一类：**诡异**是仙帝掉下来的污染物（自主扩散），
**仆从**是他的追随者（听总体指挥，也有自己的脑子）。

| 词条 | 效果 | 挂在 |
|---|---|---|
| **断传承** | 占下一座城，那座城的时代降 1 级（最低 1） | 青铜卫（以后的仆从都挂） |
| **痴愚** | 不明白城市是什么：进不了废墟、占不了城 | **全部 12 只诡异** |

### 怎么做到"不污染核心"

核心全代码只有**一处**城市易手（`doMove` 里入驻废墟那一段，注释里就写着
"这是全代码里唯一一处城市易手"）。在那里加两个**由能力回答**的钩子：

- `canCaptureCity(ctx): string | null` —— 返回非空 = 不能，字符串原样给玩家看；
- `onCityCaptured(ctx)` —— 易手之后的通知。

核心不认任何兵种，只问"这个兵挂了什么能力"。「痴愚」和「断传承」各自在自己的文件里说话。

一个位置细节：`canCaptureCity` 在**移动之前**问（和"重建费够不够"同一个位置）。
放在之后会留下"人站在废墟上、但没占下来"的中间态，那种状态没人收拾得干净。

### 青铜卫（占位）

`bronze-guard`：第 2 代，血 80 / 甲 6 / 攻 12 / 射 1 / 移 3，**自主分 0**（听总体指挥），
只挂「断传承」。它不是诡异，所以**没有暗影半径**——站在黑雾里和其它单位一样掉视野。

顺手在「满潮」里放了两只（(20,10) / (20,22)），这样「断传承」在实战里看得见。
**这也意味着玩家现在真的会丢城**：之前 C 全是诡异（痴愚），永远占不了城。

### 验证：`npm run probe:servant`（18 条）

青铜卫进表 / 不可建造 / 自主分 0 / 不带暗影 / 挂断传承；
12 只诡异**全部**挂痴愚（逐个数过，仙帝不挂）；
断传承（走进去 → 城易手 → 时代 4→3；1 级的城不再掉）；
痴愚（诡异走不进去、理由是「痴愚」、城没动、走普通空地不受影响、换一只结论一样）；
两条面板词条。

### 断传承改成"破城时"（作者定的）

核心新增 `onCityRazed`，接在 `destroyCity` 里；`destroyCity` 多了一个可选参数

## 5s. 仆系三只（2026-11-19）

仆系是"干活的追随者"，和卫系（钉在原地的机关）分工不同。三只共有的纪律：
**不往人堆里扎**——敌人成群（同一处 2 格内 ≥3 个）时就往后站；
但只要有人摸到仙帝（或裔系，id 前缀 `heir-`）3 格内，这条立即作废，它们会扑上去。

| 兵 | 特殊能力 |
|---|---|
| **傀儡师** | 「傀儡制造」：每 3 回合造一具（青铜卫 → 暗影卫 → 号卫，每种 ≤2，满了跳过） |
| **勾魂使** | 「暗影潜行」+「勾魂」：6 格内任何单位回合末有余力就被拽进黑暗（**不分敌我**） |
| **血医** | 「增生光环」：治疗 3 格内不分敌我的一半缺失血量（上限 12），但会打入等量「影蚀之血」 |

### 「影蚀之血」的完整闭环

```
血医治疗 → 回血 + 积影蚀之血（治多少积多少）
         → 积过最大生命 30% → 单位死亡，化成 1 血肉 + 1 暗影
         → 挨打会把这份污染冲淡（掉多少扣多少）
```

所以血医真正的用法是"**先打一顿再治**"：一边回血一边把污染洗掉。
一直治、从不挨打，反而会把人治死。这条闭环是这个包设计得最"活"的一处。

### 两个实现细节

1. **勾魂写在扩展层，不在词条里**：它要影响**别的单位**（包括敌人），
   而能力钩子只会在"挂着这条能力的那个兵"身上跑。所以词条只声明存在，
   真正拉人由 `pullSouls` 统一做。为此给扩展的 `TurnEndCtx` 补了 `api`——
   没有它就只能自己 `u.x = ...`，正好绕开"站位只有一个判定"那条纪律。
2. **暗影潜行只回答"此刻藏没藏住"**：`hidden` 返回"在暗影里且没出手"。
   "相邻会被发现"是引擎通用规矩（`isHiddenFrom` 里贴脸那一段），不用重写。

### 验证：`npm run probe:court`（34 条）

三只进场 / 自主分在 0 与 1 之间 / 能占城且没有痴愚；
傀儡制造（两回合不造、第 3 回合先出青铜卫、跑十几回合每种正好 2 个且不超）；
暗影潜行（暗影里看不见、出手现形、走出暗影现形）；
勾魂（被拽向深处、动过的不拽、六格外不管）；

不往人堆里扎（成群就退、散开就不退）；四行面板。

## 5t. 裔系三只（2026-11-19）

仙帝的直系：眷属 → 后裔 → 子嗣。它们不是来抢地盘的，是来**巡视**的。

### 避城：看到弱城就撤十回合

**时代 ≤ 3 的敌方城市**在视野里 → 进入 10 回合撤离期：退回沉眠地附近，
没有沉眠地就沉进暗影最深处，连那个都没有就往远离那座城的方向走。
十回合后照旧出来巡视。

> 这条给了玩家一条反向的活路：**把城打残、让它掉级，能换来十回合安宁**。
> 配合「断传承」（破城掉一级），"自毁城墙换时间"变成了一个真实的选择。

撤离期的判断写在 `onTurnStart`（写进 `custom.retreatUntil`），
走位由 profile 用 220 分压住一切——所以它不是"AI 想不想撤"，是**纪律**。

「不据城」三只都有：不屑于占据人类的废墟（`canCaptureCity` 直接拒）。

### 三条"会变成别人"的词条

| 词条 | 效果 |
|---|---|
| **归附**（眷属） | 在场上待够就变成**仆系**单位；等多久 = **2 + 场上仆系数**；变成三种里**最少**的那种 |
| **传裔**（后裔） | 每 3 回合生一个眷属，上限 2 |
| **衍嗣**（子嗣） | 每 2 回合生一个后裔，上限 2 |

「归附」的"变成最少的那种"是自动补短板：场上没仆从时变青铜卫，
一堆青铜卫的时候它会去补暗影卫。等于**裔系会自己长出一支仆从队伍**。

### 「真元」的处理（改过一次）

子嗣"同时拥有真元和暗蚀"。真元在这套引擎里是**修士境界系统的产物**（`maxManaOf` 按 rank 算），
子嗣不是修士，硬塞会牵动境界/经验墙/面板三处。

**第一版我用魔法段（`magicAtk`）顶替，作者否了**：魔法段也是奇想包"污染核心"的产物，
这个包不该借，不然两条扩展线就粘在一起了。最终做法是**并进暗蚀**——
子嗣的暗蚀值是全包最高的 20 点，其它裔系不带暗蚀。

这条记在这里是因为它是个判据：**扩展之间可以共享机制，但不该共享"象征物"**。
暗蚀是这个包自己的语言，魔法段不是。

### 验证：`npm run probe:heir`（33 条）

三只进表 / 暗影 1 / 会跳 / 三条共有词条；避城（进撤离期、撤离期不攻击、5 代城不触发）；
不据城（走不进废墟、理由是「不据城」）；归附（无仆从 2 回合就变且变青铜卫、
有 3 个仆从要等 5 回合、变最少的那种）；传裔（3 回合第一个、封顶 2）；
衍嗣（2 回合第一个、封顶 2）；撤离到期后回到听指挥；三行面板。

## 5u. 不好分类的三件（2026-11-19）

两个建筑 + 一个强者，是仙帝这条线的**前因与后果**。

| 件 | 关键规则 |
|---|---|
| **骨灰罐** | 血 20000 / 甲 2000，不会动不会打。「超脱」：仙帝倒下就以 **0 岁 / 寿元减半 / 生命上限减半** 复活，一次比一次薄，跌破 200 就没了 |
| **成帝碑** | 「知识污染」：视野一半内（`ceil(视野/2)`）的敌人变成 1 不详 + 2 黑蝗；6 级以上修士免疫 |
| **红尘仙** | 八级水准、和仙帝一样会老；不能吃同伴所以出山更频繁 |

### 三条值得记的设计点

**① 骨灰罐的"递减复活"是一道倒计时。** 每次复活生命上限减半，第 n 次是 `基础 / 2^n`。
所以仙帝不是"打不死"，是"你要打 4 次"——而每打一次他也更弱。
复活次数记在**罐子**的 `custom.revives` 上（不是仙帝身上）：换了个仙帝，账还得接着算。

**② 知识污染的半径按"看的人"算。** `ceil(该单位视野 / 2)`——看得越远的越先中招，
这反直觉但说得通：你眼睛尖，才先读懂它。普通民兵视野 2 → 半径 1（要贴身），
子嗣/仙帝视野 8 → 半径 4。**这条让高视野单位（尤其是侦查型）在碑附近变成负担。**

**③ 读碑是"用命换时间"。** 6 级以上修士会看到「阅读碑文」按钮（走的是
`Expansion.unitActions` + `onUnitAction`，和炼丹炉同一套交互）：
境界 +1、拿两回合「仙帝凝视」，三回合后必死，尸体原地站起一名**红尘仙**（归仙帝那一方）。
所以"读碑"永远是给敌人送人，只有在"我这一回合必须要那 +1 级"时才划算。

### 红尘仙与仙帝共用一套老化逻辑

`tickMortals` 和 `tickEmperor` 是两条平行的小循环（各自的寿元、各自的初始年龄）。
没有合并成一个：仙帝还有"吞同伴续命"这条特权，红尘仙没有——**能吃的和不能吃的，不该写在同一个 if 里**。

### 验证：`npm run probe:relic`（26 条）

三件本体（血量/甲/建筑/暗蚀）；超脱（复活、年龄清零、寿元 200→100、上限 1600→800→400、
复活计数、上限太低不复活）；知识污染（贴身转化出 1 不详 + 2 黑蝗、6 级免疫）；
读碑（6 级看得到按钮、5 级看不到、境界 +1、拿到凝视、三回合后死、原地站起红尘仙且归 B 方、八级）；
红尘仙（记寿元、会老、寿元耗尽会死、寿元将尽时出山收割）。

## 5v. 对标修士：仙帝与红尘仙重调（2026-11-19）

作者查表发现：仙帝「超越九级修士」根本不够看，只有护甲那一项达标。先算基准，再改数。

### 基准（现算，不是抄的）

一个**九级炼气士** = 基础（攻 10 / 甲 0 / 血 20 / 射 1 / 移 2 / 1 段）
+ 境界加成（攻 257 / 甲 119 / 血 9976 / 真伤 66 / 射 +4 / 移 +3 / 5 段 / 溅射 2）
= **攻 267 · 甲 119 · 血 9996 · 真伤 66 · 射 5 · 移 5 · 5 段**。

八级同法：**攻 153 · 甲 89 · 血 3948 · 真伤 50 · 射 5 · 移 4 · 4 段**。

### 改后

| | 血 | 甲 | 攻 | 暗蚀 | 射 | 移 | 段 | 溅射 |
|---|---|---|---|---|---|---|---|---|
| 九级修士 | 9996 | 119 | 267 | 66 | 5 | 5 | 5 | 2 |
| **仙帝** | **12000** | **140** | **340** | **80** | **6** | 3 | **5** | **2** |
| 八级修士 | 3948 | 89 | 153 | 50 | 5 | 4 | 4 | 2 |
| **红尘仙** | **3948** | **89** | **153** | **50** | 5 | 4 | **4** | **2** |

- 仙帝**每一项都在九级之上**，唯一例外是移动力 3（修士 5）——那是刻意的弱点：
  追不上你，但它射程 6，你也别指望跑掉。
- 红尘仙按八级**逐项照抄**，所以它和"真练到八级的修士"是同一把尺子量出来的。

### 顺手清掉一处越界

仙帝原来有 `magicAtk: 120 / magicRes: 25` ——**魔法段是奇想包的东西**，
这个包不借（前面子嗣那次已经定过这条）。120 点并进暗蚀，仙帝现在挂
`shadow-erosion`（80 点）并且投下 6 格暗影（它本来就是黑暗的源头）。

### 防漂移：断言现算

`probe:relic` 里那组对标检查**不写死数字**，而是当场调
`realmAtkBase / realmArmorBase / totalHpBonusForRank / trueDamageForRank / extraAttacksForRank`
算出九级、八级的"总账"再比。修真包一改公式，这里立刻知道仙帝还够不够格。

### 一个必须说的后果

仙帝现在 12000 血、五段、每段 340——`level:dark-turmoil` 那条"刺杀仙帝"的目标
基本打不动了，实际变成"撑到第 60 回合"（那条关本来就有 survive 目标兜底）。
要让它重新可打，得动关卡而不是动仙帝：抬玩家起始时代、给攻城手段、或者把目标改成纯存活。

## 5w. 黑暗的源头：仙帝与红尘仙的词条化（2026-11-19）

作者要求：作为黑暗的源头，不能只有白板。给的强度非常大——**只有走修真路线练到高层才对得上线**。

### 尸骸仙帝

- 暗影领域 6 → **8**，并且**会飞**（空中层）+ 暗影跳跃
- 十二条词条：化血 / 勾魂 / 化影 / 侵染 / 暗影侵蚀 / 断传承 / 汲取 / 痴愚 / 增生 / 点化
  + 黑暗之源 + 衍脉

等于把三系的核心机制全挂在**一个兵**身上：自己繁殖、杀什么长什么、越打越厚、
把人往黑暗里拽、破城还断传承。

### 红尘仙

- **会飞** + 暗影跳跃
- 化血 / 暗影侵蚀 / 断传承 / 痴愚

比仙帝克制得多——它是"读过碑的人"，不是源头。

### 两条新召唤

| 词条 | 效果 | 挂在 |
|---|---|---|
| **黑暗之源** | 每 3 回合爬出 1 只黑蝗（上限 3） | 仙帝 + 骨灰罐 |
| **衍脉** | **每回合**生出 1 个子嗣（上限 2） | 仙帝 + 骨灰罐 |

两条都复用 `heirSummon` 工厂，但**必须用不同的计时器键**（`locustIn` / `heirIn`）：
仙帝身上同时挂着这两条，共用一个 `custom.spawnIn` 会让它们互相偷计时器。

### 一个设计上的意思

仙帝现在同时是"召唤源 + 三系机制集合体 + 飞行单位"。对玩家的含义是：
**不能靠磨**（它有汲取/增生/再生），**不能靠拖**（它每回合生子嗣），
**不能靠近战换**（它在空中）。唯一的路是修真路线那种"直接打到它血条够长"的打法。

这正是作者说的"只有走修真路线才能对抗"——现在它在数值和机制上同时撑住了这个说法。

### 验证

`probe:relic` 加了两组：词条齐全（十二 + 五 + 罐子两条）、两条召唤的节奏与封顶
（衍脉第 1 回合就出、黑暗之源第 3 回合出、子嗣封顶 2、黑蝗封顶 3、两个计时器不打架）。

## 5x. 天气把仙帝淋死了（2026-11-19 修的 bug）

同事开「季节与气候」时看到仙帝一回合掉 **1000 点**血。查下来不是新代码的锅：

`src/core/seasons/index.ts` 里"潮湿天交不出维护费"那条：

```
生命上限 × 10%，没有封顶
```

普通兵 20~100 血 → 每回合掉 2~10 点，没人察觉。仙帝 **12000 血** → 每回合掉 **1200**，
四个回合被雨淋死，而且战报写的是"天气让 1 个部队共损失 1200 点生命"。

**修法**：封顶 10 点（`WEATHER_UPKEEP_HP_CAP`），抽成 `weatherUpkeepHpLoss(maxHp)` 便于测。
普通兵的数值一个都没变（40 血还是掉 4、100 血还是掉 10），变的是那些"血条特别长"的东西。

> 这类 bug 的共性：**按比例的消耗在"小而多"的兵上永远看不出问题**，
> 一旦有个大血条的东西进来就变成一击必杀。以后给 boss 加血之前，
> 先 grep 一遍 `maxHp * 0.`。
