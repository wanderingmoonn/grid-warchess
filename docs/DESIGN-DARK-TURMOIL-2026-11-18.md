# 「黑暗动乱」· 设计草案与最小实现

> 2026-11-18。依赖修真包（`requires: ['cultivation']`）的剧情扩展。
> 这一版只做到**最小可跑**：衰老 → 寿元见底 → 吞同伴续命 → 还是老死。
> 仆从、诡异、攻城、波次、数值全未做。

---

## 1. 设计草案（作者口述，原样记录）

- **尸骸仙帝**：实力凌驾于九级修士之上（修真包最高 9 级），但**和九级修士不同，它还会老**。
- 平时在**沉眠地**休整，年龄增长缓慢；寿元濒临耗尽时出来发动「黑暗动乱」，
  清洗天地间所有生物换取寿元，然后回去接着睡。
- 单位分两类：
  - **仆从**：帮仙帝压制玩家成长；
  - **诡异**：增生的怪物，按自己的逻辑行事，不听指挥。
- 仙帝缺"食物"（敌人不够吃）时，会**清理同阵营单位，从低级往上**。
- 所有单位 / 建筑**都不能造**，只能由关卡模式生成。
- 「不迎战」的代价：仙帝隔一段时间来把玩家基建打爆；诡异可能直接攻破城市；
  仆从会定点清理高威胁单位。
- 寿元对玩家只给**模糊描述**，不给数字。

---

## 2. 三个机制决策（已落地）

### 2.1 不走修真的境界系统

`MAX_RANK = 9`，且 9 级的寿元是 `Infinity`。往修真包里塞"第 10 级"会牵动属性公式、
经验墙、面板、规则书和整套平衡，而本包只是**借**修真那套语义。

所以：尸骸仙帝不是修士兵种，`isCultivatorUnit` 不认识它；属性直接给一组
高于九级修士的固定值（九级大约：攻 +257 / 甲 +119 / 真伤 66 / 每回合 5 段攻击）。

**好处**：修真包一行没改；将来修真包调数值，这个 boss 不会跟着漂。

### 2.2 年龄用引擎的 `u.age`，不去拦核心

核心在回合开始时给**所有**单位 `age += 1`（`rules.ts` 的回合开始）。
我们的钩子在这之后跑，所以：

- 不在沉眠地 → 再 `+1`（合计 **+2**/回合）；
- 在沉眠地（2 格内）→ 不加（合计 **+1**/回合）。

这就是"沉眠地延缓衰老"。核心的年龄规则一个字没动，也没去"倒扣年龄"。

### 2.3 寿元存在 `custom.lifespan`（自己读写）

修真包的 `getLifespan` 优先读这个字段、且要求是有限数——所以给 9 级兵写一个
有限寿元它也会认。但**修真包的 `isDoomed` 只对修士生效**，我们的 boss 不在其列，
所以判死得自己做（我们在钩子里比 `age > lifespan`）。

顺带：寿元不落"Infinity"，所以序列化没坑。

## 5. 实跑发现（重要，别当结论丢了）

关体实跑 40 个行动的结果：

```
仙帝年龄 194 / 寿元 210 · 吞噬 1 次 · 场上同伴 3 个 · 胜者 B
```

两件事：

1. **"吃自己人"这条循环在真关里确实会触发**（吃了 1 次，寿元 200 → 210）。
   不是只在探针里成立。
2. **40 个行动内玩家被清场**。300 攻 / 130 甲 / 1600 血 对 2 代修士是碾压。
   这不是 bug，是"占位数值 + 没做关卡节奏"的必然结果。

**所以这个关现在不能当难度关看**，它只是"循环跑得通"的证据。

## 5b. 暗影领域（2026-11-18 已实现，探针验过）

诡异投下的黑雾。**基础效果**：一个单位站在暗影里（视野菱形内**超过一半**是暗影），
它的**视野和射程减半，向上取整**。后续的联动效果（吸血、召唤、骨堆……）都还没做。

### 口径（写死，别改着玩）

| 项 | 值 |
|---|---|
| 形状 | 曼哈顿距离的菱形（和视野、射程同一套度量） |
| 分母 | 只数**地图内**的格子（贴边时不把界外算成"没被覆盖"） |
| 触发 | 严格**超过一半**（正好一半不触发） |
| 减半 | 向上取整，不低于 1（视野 11→6、射程 4→2、射程 1→1） |
| 叠加 | 多个诡异不叠乘，只判"是/否"一次 |

### 三个实现决策

**① 每回合末整份重铺，不跟着诡异走。**
诡异一边移动一边刷新，一次走 3 格就要重铺三片菱形；而 `visionOf` / `effectiveRange`
是每个兵、每个候选、每一帧都要问的热路径。代价是"当回合它走了，黑雾还留在原地"——
这是**故意的**，玩家因此能看见"它挪开之后哪里露出来了"。

**② 存在局面里（`GameState.overlays.shadow`），不是实时算。**
这样规则层、AI、界面读的是**同一份**，不会出现"高亮显示能打、点下去说射程不够"。
`playerView` 是 `structuredClone`，视图天然带着它（已验：雾图算出的视野 = 真局算出的视野）。
副作用是存档里多一份格号数组——每回合末重写，不累积。

**③ 界面用现成的棋盘视图，不碰渲染代码。**
`boardViews` 注册一个「暗影」色层，核心的 `onlyVisibleCells` 会按迷雾过滤，
所以雾里的黑斑画不出来，也不会被拿去反推"雾里站着几个诡异"。

### 一个必须记住的陷阱

**`modifyVision` 里不能回头调 `visionOf` / `playerView`**：`playerView` 算迷雾时
正在逐个单位调 `visionOf`，回头一查就是死循环。只能用钩子给 `base`。

### 已知限制

- **只在**地球**上算**（`overlays` 存的是 `tiles` 的下标）。多图之后要按图分开，
  现在的写法会把月球单位的暗影画到地球上。等真的有多图关卡再处理。
- 当回合不跟随移动，所以"走进去的瞬间"不会立刻被削——要等下一次重铺。

### 验证：`npm run probe:shadow`（8 段）

铺得对（半径 8 = 145 格）/ 视野 9→5 与射程 4→2 / 走出去恢复 /
边界（90/181 不减半、91/181 减半）/ 当回合不跟随、交棒后重铺 /
雾图与真局一致 / 没有诡异时零影响 / 没开这个包的局完全不受影响。

## 5c. 影系三兵（2026-11-18，行为逻辑跑通）

诡异的第一支。**不听指挥**靠 `aiAutonomy: 1` + `Expansion.unitAi` profile：
核心照样给它们算候选，但 profile 在"它有自己的想法"时用更高分压过全局的推进。

| 兵 | 名字 | 定位 | 占位数值 | 本能 |
|---|---|---|---|---|
| `shadow-beast` | **蚀影**（补的名字，备选影蚀体/侵影） | 慢速近战，被暗影侵蚀的生物 | 血 55 / 甲 6 / 攻 22 / 射 1 / 移 2 / 暗影 3 | 走向**暗影边界**（下一步就能扑进亮处） |
| `shade` | **暗影** | 快、飞行、多段攻击，一团会杀人的影子 | 血 40 / 甲 18 / 攻 10 / 射 2 / 移 5 / 3 段 / 暗影 1 | 跟同类**散开**（都挤在一起等于浪费） |
| `shadow-lord` | **影主** | 远程、厚、高甲，第一任是仙帝的影子 | 血 220 / 甲 15 / 攻 40 / 射 4 / 移 2 / 2 段 / 暗影 7 | **不贴身**（被贴住就只剩肉盾价值） |

通用技能 **暗影跳跃**：瞬移到任意暗影格，用掉之后 `moved = true`（不能跳完再走）。

### 真伤为什么叫「暗蚀」

修真那边叫"真元"——那是修士的词。诡异用同一个词出戏，所以单独起名 **暗蚀**。
实现和真元是同一条路：`DAMAGE_STAGE.trueDamage` 上加一段固定伤害，
**物理被护甲吃光时它照样进**。探针里用 999 甲靶子验过：伤害正好等于暗蚀值。

### 两条"越打越多"的因果

- **暗影击杀 → 原地长出蚀影**（`onUnitKilled` + `api.spawn`）。所以清场顺序变得重要：
  先清暗影，否则每杀一个杂兵就多一具会走路的尸体。建筑不触发（影子从石头里长出来太出戏）。
- **影主召唤**：`custom.summonIn` 计时器，正常 4 回合一个暗影；**它攻击过的回合算 2 格**。
  计时器拆成两半：回合末记"这回合打没打"，下回合初走格子——因为回合开始的钩子跑在它出手之前。
  表现上"它越凶，暗影来得越勤，但差半拍"，玩家有机会在召唤前打断。

### 一个架构教训（写下来免得再踩）

包一开始想 `import { registerUnitAiProfile } from './unit-ai.ts'`，结果**模块初始化顺序爆炸**：
`unit-ai.ts` 在模块顶层遍历 `EXPANSIONS`，而 `EXPANSIONS` 正在导入这个包 → 循环。
正确做法是走 `Expansion.unitAi` 字段（它本来就是为此设计的）。同理不要从包里 import 任何会
反向依赖 `expansions.ts` 的东西——和 `ai-meta.ts` 顶部那条警告是同一件事。

### 顺带改的核心

`UnitAiCtx` 加了 `foes` / `allies`（由核心筛好，含同盟判定）。理由和 `SkillAiCtx` 一样：
一次决策要给每个兵问一遍，profile 各自 `filter` 全图是 O(兵²)，而"谁是敌人"各写一遍迟早漏。

### 目标偏好（2026-11-18 第二轮）

| 兵 | 优先打谁 | 判据 |
|---|---|---|
| 蚀影 | **落单的生物** | 两格内没有同伴的敌人——它是伏击者，扑进人堆只会被围死 |
| 暗影 | **补刀** | 射程内血最少的 |
| 影主 | **威胁最大的** | 射程内 `atk + magicAtk` 最高的——它怕的就是这个 |

顺序也是设计的一部分：蚀影"先扑落单 → 再守边界 → 最后才考虑走位"；
影主"先开火 → 贴脸就退 → 没敌人才藏"。

### 影主没事往哪走：选「暗影最深处」，不选重心

两个候选我都算了，选**"离边界最远的那一格"**：

- **重心可能落在暗影外**。一团环形、或者两块分开的黑雾，重心正好在中间那块**亮处**——
  影主会主动走进玩家的视野里。这不是理论问题，是很容易在关卡里出现的形状。
- 重心还会被一块又长又细的影子拉偏，落在边界上。
- "离边界最远"这一格**按定义就在暗影里**，而且越深越安全：玩家得把整片黑雾翻开才找得到它。

实现是一条多源 BFS（从贴边的暗影格往里推层数），按 overlay 数组对象缓存——
同一回合里数组不变，所以每个回合只算一次。

### 暗影跳跃：改了什么

| 项 | 现在 |
|---|---|
| 攻击后 | **不能跳**（`acted` 挡）；跳完**能攻击** |
| 走完 / 跳完 | 都能——跳跃不占移动额度（不改 `moved`） |
| 冷却 | 1 个自己的回合（等于每回合一次），另由 `skillTurn` 兜"一回合一次" |

**它们自己会用**（不是只有玩家能点）：

- 蚀影：够不着的落单目标旁边若有一格暗影 → **跳过去伏击**（165 分）
- 蚀影：走不到边界时 → 跳到最近的边界格（130）
- 影主：暗影深处还很远（超过移动力 +2）→ **直接化进去**（140）；近了才走

> 影主那条是刻意做成"远则跳、近则走"的：不然它每回合都在闪，看着像 bug。

### 验证：`npm run probe:shade`（50 条）

三个兵进表 / 不可建造 / 有暗影半径与自主分 / 暗蚀无视护甲（0 甲 30、10 甲少 10、999 甲仍 8）/
蚀影贴边 / 暗影散开 / 影主计时器（4 回合 vs 攻击时 2 回合）/ 击杀原地生成（别的兵种不生成）/
跳跃（跳不进无暗影处、攻击后不能跳、走完能跳、跳完能走、冷却 1）/
目标偏好三条 / 影主藏身与"远则跳" / 蚀影跳跃伏击。

## 5d. 支线关「影潮」（2026-11-18）

**菜单加了第三栏**：主线栏是别人按顺序填的，支线不占它的位置。

| 栏 | 判定 | 说明 |
|---|---|---|
| 关卡 | 不写 `demo` / `side` | 主线 / 教学，一关接一关 |
| 支线 | `side: true` | 共用世界观，但不要求顺序、不占主线位置 |
| 编辑器 | `demo: true` | 编辑器示例关 |

代码上：`LevelDef.side`、`sideLevels()`（`storyLevels` 排除 side）、`setup-panel` 多一页。
优先级 `demo > side > 主线`——示例关不会偷偷进支线。

### 关卡：影潮（`level:shadow-tide`）

18×18，玩家 1 城（第 5 代），B 席 `cityless`：2 影主 + 3 暗影 + 2 蚀影，分在右上 / 右下。

**目标是"守住 34 次行动"，不是"杀掉影主"。** 这一条是实跑之后改的：

- 第一版写"杀光两个影主"，实跑 32 个行动，玩家一个影主都没杀掉——影主在射程 4 上
  边打边退，玩家要顶着**半视野半射程**走进黑雾。这是设计，不是 bug。
- 错的是目标：把「杀光」当胜利条件，等于逼玩家打一场打不赢的仗。
- 现在：主目标是守住；顺手宰掉两个影主也算赢（`group: 1` 给斩杀，`group: 2` 给守住）。

**实跑（AI 打 AI，一个种子）**：暗影 3 → 7~10，蚀影来回波动，玩家 32 个行动还剩 7 个兵，
第 34 个行动按"守住"判玩家赢。节奏是"越拖越紧但守得住"。

### 修了两个老关的同一个 bug（重要）

`goals` 里**不写 `group` 的多条会被当成同一组，组内是"且"**。
所以下面两关的"提前宣布胜利"从来没生效过：

- `level:behead`（斩首）：斩杀守将 + 守方撑满 18 → 两条对立，永远不同时成立；
- `level:dark-turmoil`（黑暗动乱）：斩杀仙帝 + 撑满 60 → 同上。

实测：把目标兵种全删掉再交棒，胜者是"未决"。补上 `group: 1/2` 之后立刻恢复正常。

`probe:level` 加了一条**永久断言**：任何有 ≥2 条目标的关，每条都必须写 `group`。
这条能挡住以后所有人再踩一次。

## 6. 下一步（按依赖顺序）

1. **数值与关卡节奏一起调**：现在没法单独调某一项——boss 多强、玩家需要多少兵、
   沉眠地给多少喘息时间，三者是同一个方程。
2. **仆从**：帮仙帝压制玩家成长。技术上就是 `unitAi` profile（优先打经济单位 / 高威胁单位）。
3. **诡异**：影系三个已跑通（见 5c）。血系、骨系待作者给定位；暗影的联动效果
   （吸血、召唤、骨堆）还没做——它们各自要挂不同的钩子，等机制定了再动。
4. **"不迎战"的代价**：定时攻城 / 拆基建。适合放关卡事件（`turn` 触发 + `spawn`），
   不需要新机制。
5. **波次与"清洗"**：现在只有单体 boss，还没有"黑暗动乱"的场面。

## 7. 已知的坑 / 待确认

- **老死有一回合延迟**：`killUnit` 发生在回合开始钩子里，而胜负判定在它之前跑过一次。
  表现是"它已经化成白骨了，但游戏要等下一次交棒才结束"。要修得给 `checkWinner`
  加一次调用——先记着，别现在动。
- **吞噬没有手动入口**：`targeting: 'point'` 但没注册可点格子，所以真人操作仙帝时
  点不出这个技能。现在它只由 AI 使用（关卡里 B 是电脑），等真要做"玩家操控仙帝"
  再补 `registerSkillTargetCells`。
- **`START_AGE` 的初始化只认"年龄 ≤ 1"**：如果以后有别的路径给 boss 设了年龄，
  这条会不生效。写在 `tickEmperor` 里，改的时候看清楚。
