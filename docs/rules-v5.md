# v5：胜负、平局与产能

这版规则围绕现有的城市争夺、经济增长和五回合生产计划设计。核心目标是让战局能够公平结束，让失去部队的一方仍能重整，并让生产计划在刷新和联机后继续有效。

## 1. 城市决定胜负

- 一方失去全部城市，另一方获胜。仍有军队或金币也不能免于失败。
- 还有城市时，无兵、无钱都不会立即判负。下一回合仍可获得收入，再组织部队。
- 先完成本次行动的所有直接伤害、反击、溅射与阵亡效果，再统一判定，避免按处理顺序提前挑出胜者。
- 若双方都没有城市，则平局。双方部队全灭但仍各有城市时继续，不算平局，因为经济和生产仍能恢复战争。

理由：城市已经承担科技、招募与收入功能，自然适合作为胜负目标。用“当前现金低于最低兵价”判负会忽略未来收入，也不适用于不同兵种池或时代。

## 2. 100 完整轮的公平裁决

**回合**是某一方的一次行动机会；**完整轮**是 A、B 各行动一次。行动序号 1 为 A 的第一回合，2 为 B 的第一回合，199 和 200 是双方第 100 回合。

在 B 完成第 100 回合并选择结束行动时：

1. 若已因失去城市产生终局，保留该结果。
2. 否则比较当前控制的城市数量，多者获胜。
3. 城市数量相同，则正式平局。

不比较金币、军队价格、剩余血量或城市等级。它们都可通过囤积或自定义兵种改变；城市数量是公开、易读且与攻城目标一致的指标。100 轮给时代升级、架桥和后期攻城留下空间，同时限制无限拉锯。轮数上限集中在 `CONFIG.maxRounds`。

最后一轮必须给后手完整机会：A 在第 199 次行动夺得第三座城市，B 仍可在第 200 次行动夺回一城，形成 2∶2 平局。裁决在开始第 101 轮之前完成，不额外结算下一方收入、休整或建筑火力。

正式平局和胜局都锁定后续行动、停止 AI/指挥官批次，并可同步到联机对手。模拟工具若提前停止，状态仍是“未决”，不能计作平局。平衡报告分别记录 `draws` 和 `unresolved`；历史对比表的合计列明确写作“平局或未决”。

## 3. 指挥官的一份产能

每方每回合共享一份生产额度，可用于以下一项：

- 从任意己方城市或军营招募 1 个非建筑单位；或
- 升级 1 座己方城市。

所有生产点共用额度，不能换城市多造，也不能先招募再升级。新兵被击杀、装船、卸载、修改计划、切换 AI 都不会返还额度。只有成功的行动记账；金币不足、无空格、时代不足等失败不会扣钱或消耗额度。

计划以队首约束本回合：点名兵种只能招募该兵种；`@upgrade` 只能升级；空格不能招募或升级。没有显式计划时，AI 可自主选择其中一项。无论有没有生产成功，结束回合都会消耗这一格计划；未来的格子不会因失败而顺延。

建筑沿用建造者的行动限制，不占这份额度。这样保留工程队架桥、前线军营和后方经济建设的独立作用。普通模式仍由金币、时代、编制、城市占位及建造者行动限制，不增加全军“一回合一次”的生产限制。

`turnProduction` 持久保存当前方、行动序号、已招募数与已升级数；规则内核记录并检查它，AI 和界面读取同一份数据。普通模式也记录次数，供 AI 续走时恢复自己的预算。暂停、刷新、存档导入、联机同步都不会清空 v5 的已用额度。

## 4. 旧存档

- 新局为 v5；本地加载、导入和云端快照通过同一条迁移路径处理旧 v4。
- 已结束的旧局保留既有结果，不因为新规则而重新开局或改判。
- 已超过 100 轮的旧进行中对局，在下一次 B 结束行动时裁决；若当前轮到 A，会给 B 对等的行动机会。
- 旧 v4 没有可靠产能账本，战报又可能被截断，因此不根据中文日志猜测是否生产过。旧指挥官局首次载入时，将当前回合标记为生产已封存；现有部队仍可行动，下一次轮到该方时恢复额度。
- v5 必须包含与当前方及行动序号一致的有效账本。删除账本、负次数或指挥官超过一次的记录会作为损坏存档拒绝，防止意外恢复额度。
- 联机双方应使用相同版本。完整状态仍由客户端维护；这些规则检查改善正常游戏的一致性，不代替服务端防作弊。

## 5. 验证

`npm test` 包含穷兵恢复收入、失城胜负、完整轮裁决、后手最后一次夺城、正式平局锁定、共享产能与计划、失败不扣额度、刷新/导入恢复、v4 迁移、平局联机往返和界面状态测试。类型检查、规则书生成与生产构建使用原有命令。

本次验证：345 项测试全部通过；`npm run check`、`npm run manual` 和 `npm run build` 均通过。五个时代各一个固定种子的普通模式 AI 对局全部产生终局，分别在第 61、164、23、144、34 次单方行动结束。额外两局指挥官模式中，古典在第 35 次行动决出胜负，工业在第 200 次行动按城市数判为正式平局。联机验证使用离线房间快照与提交测试，未连接真实云端房间。

这些对局用于检查运行与终局流程，样本量不足以证明平衡。规则没有更改兵种价格或攻防基础数值；新的终局和产能约束会改变旧版本的对局分布，历史平衡报告不能直接代表本版本胜率。
