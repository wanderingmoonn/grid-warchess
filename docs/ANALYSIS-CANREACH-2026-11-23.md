# P1 前置查清：判决只有一条，但"行军回合"在同一回合里会从 40 跳到 3（2026-11-23）

> 结论先说：**不是两条判决在打架，是同一条判决在一回合里被重算了十几次，
> 而它的输入（行军回合）自己会跳。** 跳的原因是"桥"。三个观测（宽浅流、池塘造船、
> 平局其实是对方不会收废墟）都指向同一个根：`canReachEnemyByLand` 那句"能不能过去"。

## 一、日志里那两条是怎么来的

日志（`s.aiCalls`）只在 `call` 变化时记一条，写入点是
`resolved.memo.pockets['decisive'].call`——**判决只有一份**，存在 `DECISIVE_PLAN` 的口袋里。

但 `aiNextActionCoreInner` 是**每个动作跑一次**的，每次都会重算 `decisiveOf`、
再走一遍 `decideCallOf`。所以同一回合里 `call` 可能翻好几次，日志就记下几条。

临时插桩（已撤）打出来的 T35：

```
[dec] T35 city=c4 cost=157 march=40  桥单位=6 桥面=6
[dec] T35 city=c4 cost=157 march=40  桥单位=6 桥面=6
[dec] T35 city=c4 cost=13  march=4   桥单位=7 桥面=7     ← 多了一座桥
[dec] T35 city=c4 cost=12  march=3   桥单位=7 桥面=7
[dec] T35 city=c4 cost=156 march=39  桥单位=6 桥面=6     ← 桥没了
```

- 同一个兵、同一座城，成本 **157 → 12 → 156**；
- 桥上"多一座 / 少一座"正好对应那两次跳变；
- `call` 跟着从 develop 翻成 attack 又翻回 develop，**最后算的那次赢**（所以停在 develop）。

所以 P1 的判断成立，而且比我原来写的更具体：
**过河与否的估计对"桥在不在"极度敏感**（40 回合 ↔ 3 回合），而它每个动作都重算一次。

## 二、`marchTurns` 是什么

```ts
marchTurns = ceil(minCost / 最大移动力)     // minCost = 所有我方战斗单位到最近敌城的最小代价
minCost 来自 `land` 场 = min( 严格旱路 , 涉水估价 )
```

- 严格旱路把水当墙；涉水估价把水按 `WADE_COST`（很贵但能过）计价；
- 有桥（地形变成 `bridge`）就走桥价，成本从 ~157 掉到 ~12；
- 桥可能是我方的，也可能是**敌方的**——`passable('bridge')` 不看归属。所以"对面在自己家门口架了一座桥"，
  也会让我们以为 3 回合就能到。

## 三、三个观测，同一个根

### 1. 很宽的浅流会不会被当成渡口？

**会，只要够宽。** `canReachEnemyByLand` 的 BFS：

- 只认 `passable`，**浅流（`shallow`）和沼泽都是"陆地路"**，能走；
- 但步数按 **1 格 = 1 步**记，不看地形成本；
- 超过 `min(宽,高)`（24×24 上是 24 步）就判"过不去"。

所以一条 20 格宽的浅流 + 几格接近距离，很容易越过 24 → 判"过不去" → 过河计划激活
→ 在浅流上修桥（明明能趟过去，只是慢）。**窄浅流没事，宽浅流会被当成河。**

### 2. 小池塘里造很多船

`seaDemandNow`：

```ts
if (waterShare < 0.08) return 0;          // 水太少 → 不要海军
if (!canReachEnemyByLand(s, me)) return 1; // 陆路不通 → 全额需求
if (waterShare >= 0.14) return 0.5;
return 0.2;
```

两条都能被"错误的不通"点燃：

- **只要 `canReach` 是 false（哪怕是上面那种宽浅流、或 24 步误判），海军需求直接拉满**；
  这时运输船每艘 +40（凑到 3 艘），战舰 +10；
- 而它**从不检查这片水通不通向敌城**。一个封死的池塘（我城挨着水，水只有 6 格）：
  只要池塘占全图 ≥8%、陆路又因为别的原因判 false，就会开始造船。
- 即使 `seaDemand = 0`，水军的总惩罚也只有 `-8 - 10 = -18`，便宜的船照样能赢过别的候选。

### 3. "平局"其实是对面不会收废墟

`src/core/ai.ts`（v1 内核，跑批的对手 `baselines/ai-9efb961.ts` 就是它）**没有任何收废墟的逻辑**
（全文搜 `reclaim` 无结果；`废墟` 只出现在"别往废墟里造兵"这类判断里）。

所以当我们的城全被打成废墟、对面占优时，**对面没法把废墟拿下来**——
它既不能攻城（废墟不能再攻），也不会走进去接管——只能等到回合上限判平。

**这意味着跑批的"平局"里有一部分是我们的真实败局**（对手不会收尾），
反过来也可能低估我们。以后看平局要先确认：**是不是"还剩废墟没被占"**。
`diag:replay` 输出的"陆路最小步数"和"废墟"两列就是干这个的。

## 四、方案（按这个根重新排）

### P0 把"能不能过去"这一句换掉（**三个观测共享它**）

现在的判据：等步数 BFS + `min(w,h)` 上限。
建议：**按代价判**（用现成的 `advance` 场），并把"绕路"做成相对量：

```
可通行 = 存在一条到敌城相邻格的路径，且 代价 ≤ 直线代价 × k
```

- 浅流不再是"1 步 1 格"，而是按 `stepCostBetween` 的真实成本算 → 宽浅流不会被当河；
- 真河无桥时代价爆炸（`WADE_COST` 很大）→ 仍然判"过不去"，桥计划照旧；
- 上限从一个绝对步数变成相对倍数，不同尺寸的地图不用各调一次。

这一条同时修好：宽浅流被当渡口、`seaDemand` 被误拉满、`marchTurns` 被误判。

### P1 决战判决：别用"涉水价"估行军（改在 P0 之后再看）

P0 之后 `marchTurns` 会稳定一些，但"没桥时 40 回合"仍然存在（因为涉水价本来就贵）。
两条候选：

- a. `canReach` 为假（过河计划当值）时，`marchTurns` 改用"桥通之后"的估计；
- b. `crossing` 当值时把 call 钉成 attack。

### P2 海军：加一条"这片水是不是死水"

从**我方挨着的水**做水域洪泛，看能不能摸到敌城附近的水（或任何一个通向外面的口子）。
摸不到 → `seaDemand = 0`，不管 `waterShare` 多大。
这条能直接消掉"池塘里造船"。

### P3 `canReach` 的上限（并入 P0）

### P4 平局要标注"是不是还剩废墟没被占"

2. **P2**（海军死水）：一条洪泛，风险小。
