# 版本 0.3.2 · 2026-10-31 · 观战人数、聊天两态、筛选解锁与打击感

六项改动：三项是新的（观战人数、聊天折叠/屏蔽、受击动画），
一项是修 bug（筛选锁死），两项是规则调整（空军免疫地形）。
每项都写清实现思路与影响范围，方便以后翻账。

## 一、观战人数实时显示

**做了什么**：顶栏房间码右边多一颗「观战 N 人」，12 秒一次心跳，45 秒没动静就算离开。

**实现思路**

- 新表 `warchess_presence`（`sql/warchess_presence.sql`，已在云端执行）：
  `(room, client_id)` 做主键，一行一条在线状态，`role` 区分 `watch` / `seat`。
- **为什么不往 `warchess_rooms` 加一列**：房间那一行是整局快照，提交回合时用
  `turn` 做乐观锁。往同一行写在线状态，就会和"提交这一回合"抢同一行——
  观战者每次心跳都可能把一次提交挤掉。独立成表，各写各的。
- **为什么是心跳而不是"进来 +1 / 走了 -1"**：浏览器可以被直接杀掉、标签页可以
  永远后台挂着，那个"走了"的事件根本不会发出。只记"最后见到你是什么时候"，
  超时即离开——这是在线状态唯一靠谱的做法。
- 客户端 `src/net/presence.ts`：先 `update` 再 `insert`（SDK 这层没有 upsert），
  `countWatchers()` / `watchLabel()` / `presenceFromRow()` 是纯函数，有测试盯着。
- 顶栏元素由 `panel.setWatchCount()` 单独维护，**不进 `PlayerView`**：
  观战人数不是对局状态，不该进存档、更不该参与规则计算。

**影响范围**：仅联机房间。单机对局没有房间码，这颗 chip 一直隐藏。
观战者自己也计入（含他自己）——两边看到的数字必须一致，给自己减一只会让两个屏幕对不上。
表没建时只少一个数字，不影响下棋（错误文案会明说是哪张表、执行哪个 sql）。

## 二、"关闭聊天框"拆成折叠与屏蔽

**做了什么**：标题栏原来那颗 × 换成两颗——**折叠（–）** 与 **屏蔽**。

| | 折叠 | 屏蔽 |
|---|---|---|
| 面板 | 收起 | 收起 |
| 继续拉消息 | **是** | 否（连请求都不发） |
| 对方发言时 | **自动展开**并提示 | 不展开、不计数 |
| 入口那颗按钮 | 「聊天 · N」（未读数） | 「聊天 · 已屏蔽」（虚线灰） |

**实现思路**

- 以前只有一个 `chatOpen` 布尔，"收起来但别错过"和"这一局不想听"被压成同一件事。
  现在 `chatMode: 'open' | 'folded' | 'muted'`，存在本机 `warchess:chat-mode`。
- 折叠状态下**轮询必须继续**——这是两种模式真正的分水岭：不拉消息就谈不上"自动展开"。
- 自动展开的判据抽成 `shouldAutoExpand(mode, fresh, mine)`（`net/chat.ts`）：
  只有折叠、且新消息来自**对方**才展开。自己刚发那条会被增量拉回来，
  拿它触发展开会变成"我一说话，面板弹到自己脸上"。
- 屏蔽时面板里有一条横幅 + 「恢复」按钮，避免"我是不是屏蔽了对方"这种只能靠猜的状态。

**影响范围**：只影响聊天面板的显示与轮询，聊天内容、水位与去重逻辑一行未动。

## 三、修 bug：筛选兵种后切换城市会锁死在空页面

**现象**：在 A 城把筛选切到某个扩展包/某个时代，再切到没有这类兵的城 →
列表空了，而**筛选栏整条消失**（它只在"至少两档可选"时才画），于是没有任何按钮能取消筛选，
只能靠刷新页面。

**根因**：`packRow` / `eraChipRow` 在"这一屏只剩一档"时返回空串，
没有考虑"当前生效的筛选值恰好不在这份名单里"——此时那一档既不在列表里，也没有出口。

**修法（三处，缺一不可）**

1. 生效中的筛选值**始终保留在筛选栏里**（计数写 0），所以永远有得按；
2. 空结果提示里加一颗「清掉筛选」（`data-act="recruit-clear"`），一次清空
   搜索词 / 扩展包 / 时代三个维度；
3. 筛选栏在"当前有筛选"时不再因为只剩一档而整条消失。

**影响范围**：城市产兵面板与军营产兵面板共用同一套组件，两处一起修好；
上帝模式货架用的是同一个函数，行为同步改善（它本来就不受城市切换影响）。

## 四、空军不再受任何地形影响

**做了什么**：空中单位不吃地形护甲、不吃高差射程/视野加成、飞越时步耗恒为 1。

| 地形影响 | 地面单位 | 空中单位 |
|---|---|---|
| 森林/丘陵掩体护甲（+2 / +3） | 吃 | **不吃** |
| 台地俯射 +1 / 谷地仰攻 −1 射程 | 吃 | **不吃** |
| 沙丘/台地视野 +1、林地 −1 | 吃 | **不吃** |
| 爬坡附加步耗 | 吃 | 不适用（飞行 1 步/格） |

**实现思路**

- 规则层：`computeDamage` 与 `effectiveStats`（面板）里那两处 `terrainDef` 都加了
  `!isAirborne(...)` 判断——**面板与结算读同一个判断**，不会出现"写着 10 点、按 7 点算"。
- 扩展层：`height-terrain` 的两条钩子（`modifyRangeAgainst` / `modifyVision`）在算之前
  先看单位是不是空中层，是就原样放行。它自己判而不改核心钩子签名，是为了不让"地形高差"
  之外的东西（比如季节与气候）被动地跟着失去效果。
- AI：两处"往高地挪"的打分对空中单位归零，免得飞机为了掩体在山上打转。

**影响范围**：只影响 `layer: 'air'`（含旧数据里的「掠空」）的单位。
**天气仍然生效**（浓雾压视野、暴雨减射程）——那是气候不是地形，
飞在云上也躲不开天气，这条有意保留。

## 五、打击感：受击抖动与出手前冲

**做了什么**：受击的单位左右震一下（260ms），出手的单位往前一顿（200ms）。

**实现思路**

- "谁挨打了"不靠每处扣血代码各喊一声——扣血路径有交战、反击、溅射、中毒、灼烧、
  攻城好几条，逐条挂必然漏。改成渲染层做**前后两帧的血量差**：
  这一帧比上一帧少，就是刚挨了一下（`main.ts` 的 `hpSeen`）。
- "谁出手了"血量差看不出来，由 `dispatch` 在 ATTACK/SIEGE 成功后记一笔，绘制时消费一次。
- 动画用 Web Animations（`composite: 'add'`），叠加在 FLIP 位移上而不是覆盖它；
  jsdom 没有 `Element.animate`，那里直接跳过——动画是锦上添花，不该让渲染依赖它。
- 同一次绘制只播一次（`paintStamp` 记账），避免"同一份状态反复重绘 → 持续抽搐"。

**影响范围**：纯表现层，不碰规则与存档。移动动画、FLIP、迷雾标记都不受影响。

## 六、血条：快速缩短 + 橙色残留

**做了什么**：受击时绿条 0.12 秒缩到新血量；身后留一段橙→黄渐变的残留，
先停 40% 的时间（看清楚掉了多少），再追上血线并淡出（总时长 0.62 秒），
结束后不残留任何第二种颜色。

**实现思路**

- 血条拆成两层：`.hp-lag`（橙，垫底）与 `.hp-now`（绿/黄/红，在上）。
  残留可见部分正是两者的宽度差，所以"掉了多少"是画出来的，不是算出来的。
- 旧血量记在节点 `data-hp-ratio` 上：棋盘是增量补丁，节点会复用，
  重写 innerHTML 之前先把旧值读出来，写完之后再决定要不要演这一段。
- **只在掉血时演**：回血冒一条橙条会让人以为又挨了一下。
- 残留条的终点与起点通过 CSS 变量传进去（`--chip-from` / `--chip-to`），
  动画本身留在 CSS 里，JS 只负责"这一次从哪到哪"。

**影响范围**：单位血条。城市耐久条保持原来的 0.25 秒过渡（它是整块 HTML 重写的，
加动画会在每次重绘时重播）；城里挨打另有 `siege-pulse` 提示。
