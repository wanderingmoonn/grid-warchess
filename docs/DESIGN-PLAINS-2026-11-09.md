## 二、目标与判据

| 指标 | 现在 | 目标 | 说明 |
|---|---|---|---|
| 平原（基准地貌） | 50.1% | **≥ 66%** | "大幅"要有量级：+16pp |

## 三、三个方案

### 方案 A：只加一种地貌风格（`plains`）

`MAP_STYLES` 加一项「旷野」，玩家在地貌栏自己选。改动最小，但要玩家主动去选，不满足"推出新扩展规则"。**保留它作为方案 B 的可见形态。**

### 方案 B：新扩展「旷野」+ 生成器里一个受门控的后处理（**推荐**）

扩展 `plains`（`name: '旷野'`, `scale: 'large'`）只声明目标参数，真正的活儿在 `mapgen` 里做（理由见 §4.0）。

### 方案 C：改默认

不建议。老存档、录像、`test-rules` 里那批钉死坐标的用例全废。

## 四、方案 B 的实现落点

### 4.0 为什么不放在扩展的 `afterTerrain` 里

我最初的写法是"扩展用 `afterTerrain` 压平城郊"。查了签名之后否定：

```ts
afterTerrain?: (g: Terrain[], w: number, h: number, keep?: ReadonlySet<number>) => void
```

它拿不到三样必需的东西：

- **城位**：只有"城 + 一环"的格子合集，2×2 城会被拆成四个孤格，凑不回一座城；
- **`zoneOf`**：`fair` 地貌靠"两侧格数相等"保证公平，后处理必须按区分别计数；
  而 `symmetrize()` 只在 `mirror` 模式下生效，救不了 `fair`；
- **执行顺序**：它必须跑在高差的 `softenPeaks` 之后，而现在的顺序取决于玩家勾扩展的顺序（§4.5b）。

所以改成：**扩展只声明目标，`mapgen` 里加一个受它门控的后处理**。

```ts
// MapOptions
plainsTarget?: number;   // 0~1，缺省不生效；由「旷野」扩展写入（基准 0.66）

// 生成流程末尾（afterTerrain 之后、symmetrize 之后、开凿之前）
if (opts.plainsTarget) raisePlains(c, plan, opts.plainsTarget);
```

`raisePlains` 做两件事：**先压城郊，再补全图占比**。顺序不能反——先补全局会把城郊的份额
算进去，压平之后又超标。

### 4.1 城郊：逐级降平

```
for 每座城 c（A/B/C/D 全算）：
  取 c 向外半径 4 的方块（9×9）
  反复执行，直到「这块里的 plain 连通块 ≥ 25 格」：
      在这块里找"与 plain 相邻、且高度最高"的非水域格，把它降**一级**
      （台地→丘陵→平原；森林→平原；只降一级，不跳级）
  超过 12 轮还不达标就放弃，并记一条日志（不静默）
```

四个必须写死的例外：

- **不碰水域**：`WET = {water, deep, shallow}` 三态全跳过。港湾填平了，海军就废了。
- **不跳级**：`台地 → 平原` 是两级的悬崖，会留断层；逐级降才和「地形高差」的等高线兼容。
- **不碰城格与一环**（复用现有 `keepAroundCity`）。
- **按区计数**：A/B（以及 C/D）各自统计、各自执行，保证 `fair` 模式两侧降掉的格数相等。

### 4.2 全图：从现有平原"长出去"，不凭空挖

```
target = round(tiles * plainsTarget)
need   = target - count('plain')
while need > 0:
    候选 = 与现有 plain 相邻、非水域、高度 ≤ 1 的格子（森林/丘陵/沼泽）
    在候选里挑"plain 邻居最多"的那个，改成 plain
    没有候选就停（并把 need 打进日志）
```

要点：

- **只吃森林/丘陵/沼泽**（高度 ≤1）。台地/高原/火山**不动**——这是"不抹掉风格"的底线。
- **贴着平原长**，不随机撒：平原会连成片，而不是满地雪花。
- 每改一格重看邻居 → 天然"从边缘往里吃"，形状接近原来的团块。

### 4.3 配比仍然要调（让后处理少干活）

后处理是保底，只靠它会让所有图都"最后统一削一遍"，费时且不可预测。所以基准配方照旧调：

| 位置 | 现在 | 改成 | 贡献 |
|---|---|---|---|
| `mapgen.ts:2005` 森林 `r` | 0.11（open 0.06） | **0.05（open 0.03）** | +6pp |
| `mapgen.ts:2006` 丘陵 `r` | 0.08（ridge 0.13） | **0.04（ridge 0.07）** | +4pp |
| `mapgen.ts:2007` 山地 `r` | 0.03（open 已是 0） | **0.01** | +2pp |
| `enrichTerrain` 成片森林 + 短山脊 | 按尺寸成对生成 | **关掉**（湖/支流保留） | +2~3pp |
| `fillEmptyRegions` `keepPlain` | 0.9 | **0.97**，`minRegion` 6%→8% | +1~2pp |

合计 **+15~17pp**，配方自己就能到 65%~67%，后处理只兜底城郊和少数"地形全堆一边"的图。

### 4.4 多人图与微图

- `generateMultiLayout` 是另一条生成器，**必须同步**同一套配比与后处理，否则"开了扩展只有 1v1 是平原"。
- `tinyLayout`（≤5 格）不动：本来就全是平原。
- 上传/固定/存档读回：不经过生成器，天然不受影响。

### 4.5 与「地形高差」的互操作（本次重点）

高差扩展在两个地方插手生成，两处都要应付。

**（a）它自己的六种地貌会接管生成器。** `mapStyles[].build` 一旦存在，`mapgen` 就不走本体配方
（代码注释写得很清楚："扩展自己长完地形就到此为止：本体的加料/填空白会把等高线打碎"）。
**所以 §4.3 的配比调节对高差局完全无效**——这就是必须有 §4.2 那个与生成器解耦的后处理。

但高差局平原只有 20.8%~38.6%，补到 66% 就得把台地、河谷、沼泽全拍平，「高原」就变成「旷野」了。
所以定三条规矩：

1. **风格优先**：高差局目标不是 66%，而是 `min(0.55, 基线 + 0.15)`。
   高原 28.9%→44%，峡谷 20.8%→36%，群岛 38.6%→53%（封顶）。**只升不降**。
2. **只许降一级的白名单**：森林 / 丘陵 / 沼泽（高度 ≤1）。台地、高原、火山**不参与**全图提升——
   它们是那个风格的地标。
3. **城郊照旧硬保证**（§4.1，逐级降平），与风格无关。在高原图上城郊会从 37% 提到 75%，
   代价是城门那圈台地被削成缓坡——这是"城必有开阔地"的应有之义，写进规则书。

**（b）它的 `afterTerrain`（`softenPeaks`）会补山脚。** 顺序错了会互相打脸：

| 顺序 | 后果 |
|---|---|
| 旷野先、高差后（现在的数组顺序可能就是） | `softenPeaks` 在城郊补丘陵/台地，把刚压平的城郊又啃掉一块，**城周 75% 失效** |
| 高差先、旷野后（**要的这个**） | 旷野最后压平，保证成立；削出来的坡仍逐级，不产生悬崖 |

所以给 `afterTerrain` 加优先级字段（`afterTerrainOrder?: number`，缺省 100），`mapgen` 按它排序后执行；
高差用缺省，旷野用 200，`raisePlains` 放在全部钩子之后。

### 4.6 水域守卫（硬约束）

`WET = { water, deep, shallow }`（`mapgen.ts:330`）——**浅滩也算水**，这是口径基准。
守卫靠三层，不靠自觉：

1. **白名单**：后处理只把 `forest / hill / marsh` 改成 `plain`，`WET` 一个都不在名单里；
2. **位置**：后处理跑在 `topUpWater`（20% 补足）**之后**，做的只是"陆地内部再分配"，
   水的分子分母都不动 → 数学上占比不可能下降；
3. **断言**：测试比对"开/关扩展、同一颗种子"的水域格数与占比，要求**完全相等**，不是"差得不多"。

`deep`（深水）是「海战」在 `afterTerrain` 里由 `water` 改写来的，也在 `WET` 里；
若海军包在旷野之后跑，它把 `water` 改 `deep`，占比不变，无需处理。

> §1.3 那个既有偏差本次**不动**，只在文档和测试里记基线，免得将来有人拿"水域应该 20%"去告状时找不到出处。

## 五、风险清单

1. **骑兵与战车明显变强。** 平原没有移动/视野惩罚，冲锋线变长。这一条**不在本次解决**。
   注意 `scripts/probe-agreement.ts`（同局面动作一致率）**不适用这里**：它比的是同一局面上
   两套**策略**的分歧，而地形变了是**局面**变了。该用 `npm run sim` / `npm run ladder`
   跑"开/关扩展"对照，读三个数：骑兵出场率、潜行兵出场率、局均回合数。
2. **潜行被削弱。** 森林 13% → 5%~6%，藏身位少一半。叠上 11-09 那次"出手即现形"，
   斥候/盗贼在旷野局可能彻底没位置。**这正是要盯的指标。**
3. **高差局被削平。** §4.5 三条规矩是防线，但"城郊削台地"仍会改变高原图手感，需实测。
4. **城郊太平 → 开局容易被一波冲脸。** 若出现"三回合城下被围"，后手是给城郊外圈留一条丘陵带（本次不做）。
5. **老录像/老存档**：不勾不受影响；勾了自然对不上（确认 `plains` 进录像的扩展列表）。
6. **性能**：`raisePlains` 每格重算邻居，64×64 最坏 O(tiles×轮数)。缓解：用一次宽度优先的
   "由外向内"队列，单轮 O(tiles)；验收要求 64×64 < 30ms（现有 32×32 约 6ms）。

## 八、明确不做的

- **不动水域**：`WET` 三态一格不减，测试用"逐格相等"钉死。
- **不修沼泽 13% 那个既有偏差**：修它会动所有沼泽老图。
- **不抹平高差风格**：台地/高原/火山不进提升白名单，全图目标在高差局封顶 55%。
- **不动默认地图**：不勾扩展，一格不改。
- **不在这一轮调兵种数值**（骑兵、潜行、弓手）。
- **不给城郊加"丘陵护城墙"**：先看实测。
- **不做"玩家自定义平原比例"**：一个开关够了。
