# 空军扩展 · 设计说明

> 两个包：**「空军」**（`air-corps`，第四~第五时代，9 种飞机）+ **「现代空军」**（`air-modern`，第六时代，9 种飞机）。
> 6 条能力、1 套航母甲板实现（`AirwingOps`）、0 处引擎改动。

---

## 一、放在哪里

| 文件 | 内容 | 性质 |
|---|---|---|
| `src/core/air-packs.ts` | 6 条能力、18 个兵种、两个 `Expansion`、`AirwingOps` 的空军侧实现 | 扩展区，**新文件** |
| `src/core/naval-carrier.ts` | 甲板契约（`DECK_SPECS` / `StowedPlane` / `AirwingOps` / `stowPlane` / `popPlane`） | 上一批已有，**这轮只被实现、没被改** |
| `src/core/expansions.ts` | 两行：`import` + 展开进 `EXPANSIONS` | 注册处 |
| `src/core/rules.ts` | 一行：飞行单位可停深水（`tileStandsOk`） | 引擎规则，上一批随深水一起加的 |
| `scripts/build-manual.ts` / `src/ui/books.ts` | 规则书分册「空军扩展」 | 配套 |
| `scripts/test-rules.ts` | 9 条「空军扩展」用例 | 验证 |

**这一轮引擎一行都没改。** 空中层（`layer: 'air'`）、掠水（`flight: true`）、
"地面打空中 +1 格"（`strikeDistance`）、多段伤害管线、光环、隐身与先手——
全是既有规则，空军只是**用**它们。上一批为了让 2×2 的航母能走，动过
`reachableTiles`；这一批不需要任何新开关。

## 二、设计思路

### 2.1 飞行不是免伤

这条必须写在最前面，否则整批数值都会被读错。

飞机待在空中层，地面单位射程 2 就能打到相邻的它（"地面打空中"多算一格距离）。
所以一架飞机贴着防空炮站，等于把肚子亮出来；防空巡洋舰的「区域防空」（+12）
和战斗机的「制空」（+12）同口径，两条可以叠——一起咬一架轰炸机，
是这套规则里最贵的死法。

**飞行买的是机动与视野**：移动 8~12、视野 7~13，全游戏最快最远的单位都在天上。
它也因此能停在河、浅流、深水上（掠水），包括航母头顶那片外海。

### 2.2 每种飞机只擅长一件事

三条攻击向能力各自只认一个层，互不串味：

| 能力 | 加成 | 只对 | 挂它的飞机 |
|---|---|---|---|
| 制空 `af-superiority` | +12 | `layer === 'air'` | 活塞机、喷气机、隐身机 |
| 对地攻击 `af-ground-strike` | +14 | 非空中层 | 强击机、攻击机、武装直升机、无人机 |
| 反舰 `af-anti-ship` | +12 | `domain === 'water'` | 俯冲轰炸机、舰载机 |

结果是：制空的打不动地、对地的打不过制空、轰炸机只能炸城和堆、支援机不会打架。
想全都要，就得多带几种——这正是空军该有的编制压力。

### 2.3 便宜的一定脆，贵的一定有短板

无人机 280 金、视野 10，但只有 40 血：用法是"去看、去换、去逼对方开火"，不是去赢。
战略轰炸机 950 金、200 血、溅射 2 + 破城，但射程只有 3、打不动制空机，必须有人护航。
预警机视野 13、相邻友军 +2 攻，**自己攻击 0**——打掉它，整支编队的输出都掉一档。

### 2.4 数值口径

与陆军、海军同一把尺子：
`V = 攻 + 0.45×血 + 5×甲 + 3×射程 + 2.5×移 + 1.5×视野（溅射每级 +4）`。

| 时代 | V/价区间 | 说明 |
|---|---|---|
| E4（气球~双翼机） | 0.36 ~ 0.50 | 侦察机 0.50 是全场最高，代价是几乎打不动人 |
| E5（二战机群） | 0.29 ~ 0.43 | 重型轰炸机 0.29，它的价值在城不在兵 |
| E6（喷气与电子战） | 0.20 ~ 0.40 | 预警机 0.20、电子战机 0.21 是最低的两档，它们本来就不杀伤 |

**越往后越"不值"是刻意的**：贵兵天然更不值，这是被编制上限压出来的设计，不是漏洞。
同代陆军的 V/价比飞机高得多——一架飞机的钱能买两三个陆军单位，
它贵在"够得着哪儿"，不贵在"打多少"。

## 四、六条能力

| id | 名字 | 效果 | 实现方式 |
|---|---|---|---|
| `af-superiority` | 制空 | 对空中层 +12 | `damage` @ `DAMAGE_STAGE.attackFlat` |
| `af-ground-strike` | 对地攻击 | 非空中层 +14 | 同上 |
| `af-anti-ship` | 反舰 | `domain === 'water'` +12 | 同上 |
| `af-stealth` | 隐身 | 迷雾里贴脸才现形；攻击不挨反击 | `hidden: () => true` + `noCounter: true` |
| `af-command` | 空中指挥 | 相邻友军 +2 攻 | `aura: { allyAtk: 2 }` |
| `af-jam` | 电子压制 | 相邻敌军 −2 攻 | `aura: { foeAtk: -2 }` |

三条加成全在 `attackFlat` 段（`DAMAGE_STAGE.attackFlat = 100`），也就是在
护甲削减、属性倍率、反击折减**之前**。好处是它们和"破甲""齐射"这些既有能力
按同一顺序结算，不会出现"先乘后加"的账目分歧。

隐身复用了两条现成机制（`hidden` 走潜行判定、`noCounter` 是先手那个旗标），
所以"迷雾局里贴脸才发现"对隐身机和潜艇是同一条规则——一致性白拿。

## 五、航母甲板：两包之间的那道接口

### 5.1 职责边界

海军包（`naval-packs.ts`）负责：

- 船本身：数值、造价、`capacity` 个机位、起飞半径（`DECK_SPECS`）；
- **容器**：把飞机从棋盘上摘下来存进 `carrier.custom.airwing`，以及反过来放回棋盘
  （`stowPlane` / `popPlane`）；
- 回合开始时把"轮到你整备了"这个时机转告空军（`deckUpkeep` → `airwingOps()?.onDeckTurnStart`）；
- 界面上的那一行「甲板 2 / 4」（`deckLine`）。

空军包（`air-packs.ts`）负责：

- 飞机是**它**的兵种：属性、造价、整备、损失；
- `canBoard`：什么飞机能上什么船；
- `launch`：起飞后落在哪一格、这一回合还能不能动；
- `recover`：能不能回收、收进来存什么；
- `onDeckTurnStart`：每回合轮到航母时干什么。

**两条硬线**：

1. 海军包永远不创建、不定义飞机。没有空军扩展时，航母就是一艘视野很远的指挥舰
   （`nv-fleet-command`），照常能打完一整局。
2. 空军扩展永远不直接改船的数值。要改只能走 `ExpansionHooks.modify*`，
   那些是纯函数，不会把船写成半成品。

### 5.2 能上舰的是哪四种

```ts
const CARRIER_CAPABLE: ReadonlySet<string> = new Set([
  'af_naval_plane',   // 舰载机（E5）
  'af_jet',           // 喷气战斗机（E6）
  'af_attack_jet',    // 攻击机（E6）
  'af_awacs',         // 预警机（E6，E-2 那类本来就是舰载的）
]);
```

这是一份**白名单**，不是"按属性猜"：能不能上舰是工程问题（起落架、机翼折叠、
弹射与拦阻），不是数值问题。重型轰炸机、战略轰炸机、运输机永远上不去。

### 5.3 调用方式

海军侧只需要三行（已经在 `naval-packs.ts` 里）：

```ts
const ops = airwingOps();
if (!ops?.onDeckTurnStart) return;
ops.onDeckTurnStart({ state, carrier: u });
```

空军侧在模块加载时注册（`air-packs.ts` 末尾）：

```ts
registerAirwingOps(AIRWING_OPS);   // 只有一份，谁开航母都走它
```

界面或未来的"起飞/返航"按钮用显式入口：

```ts
import { launchFromCarrier, recoverToCarrier } from './air-packs.ts';

launchFromCarrier(state, carrier);          // 放飞甲板上第一架
recoverToCarrier(state, carrier, planeUnit); // 把贴着母舰的这架收进甲板
```

### 5.4 每回合的整备顺序：先收、再修、后放

```
onDeckTurnStart
  ├─ 1) 收：贴着母舰的舰载机自动返航进甲板（每架都查 canBoard 与机位）
  ├─ 2) 修：甲板上的飞机各回 8 点，上限是兵种血量
  └─ 3) 放：每回合最多放一架，出不去就留着
```

顺序是有讲究的：先收再修，返航那架当回合就能补血；只放一架，
"机位数量"这个数字才有意义——否则四架一起飞出去，甲板只是个装饰。

三项保证：

- **起飞失败不损失飞机**。`launch` 返回 `ok: false` 时不会 `popPlane`，
  飞机原样留在甲板上，下回合可以再试；
- **甲板上的飞机不占棋盘格**。否则一艘航母四个机位，周边八格全被堵死；
- **关掉扩展就什么都不做**。`launch` / `recover` / `onDeckTurnStart` 开头都查一次
  `airEnabled(state)`，所以"注册了实现"不等于"这一局有空军"。

### 5.5 一个真实踩到的坑：钩子跑两遍

两个海军包（`naval-fleet` / `naval-modern`）都挂了 `onTurnStart`，所以回合开始时
`deckUpkeep` 会被叫两遍。空军那边是"收→修→放"完整一套，跑两遍的后果不是放两架，
而是**刚放出去的那架立刻被收回来再修一次**——玩家看到的是"飞机原地没动、血却多回了 8 点"。

修法和 `portRepair` 同一个办法：在船身上记一个本回合的哨兵。

```ts
if (u.custom?.deckUpkeepTurn === state.turn) continue;
u.custom = { ...(u.custom ?? {}), deckUpkeepTurn: state.turn };
```

测试里那条「先修 8 点再放飞：40 → 48」就是这道哨兵的守门人——哨兵丢了，
它会变成 56。

## 六、兼容性处理

### 6.1 与「现代」扩展

`air-modern` 写了两条前置：

```ts
requires: ['pack-contemporary', 'air-corps']
```

- `pack-contemporary`：第六时代是「现代」开出来的。单勾 `air-modern` 会得到一堆
  造不出来的飞机——那是"包坏了"，不是设计；
- `air-corps`：现代机用的 `af-superiority` / `af-ground-strike` 声明在基础包里。
  能力表是**全局合并**的，同一条不许在两处各写一份（重复的那份会被核心静默覆盖，
  改它等于白改），所以现代包只能引用、不能重发；既然引用，就得保证那份一定在场。

开局面板勾选时会自动补齐前置（`setup-panel.ts` 的 start 分支），
所以玩家点「现代空军」不会得到"勾了却不生效"的开关。

### 6.2 与海军扩展

- 没有海军扩展时，十八种飞机照常造、照常打，只是没有航母可上；
- 没有空军扩展时，四条带甲板的船（航母、轻母、航战、两栖舰）甲板是空的，
  面板写「空军扩展未接入」，数值一行不变；
- 两个方向都不存在"必须先开另一个包"——它们互相**可选**，不是互相依赖。

### 6.3 与地形

飞机是 `flight: true`，所以 `tileStandsOk` 里那条"飞行单位可以停在水面上"
对它们直接生效——包括上一批新加的深水（海上空域也是空域，不让飞机停在航母
头顶上说不通）。浅流本来就可通行，不用单列。

### 6.4 与旧存档 / 自定义兵种

- 兵种 id 一律带 `af_` 前缀，和 `nv_` / 原版 id 不冲突；
- 能力 id 带 `af-` 前缀，进 `ability-registry` 的合并表，自定义兵种编辑器里能勾到；
- 存档里 `expansionIds` 带着 `air-modern` 但没带前置时，`enabledExpansionIds`
  会把它剔掉（跑到不动点），不会出现"有一半飞机的对局"。

## 七、验证

`npm run test:rules` 里新增 9 条（共 410 项）：

| 用例 | 守的是什么 |
|---|---|
| 两包都注册上，18 个兵种全在空气层 | 漏写 `flight` 就会出现"飞不过河"或"和地面单位抢格子" |
| 现代空军依赖「现代」与基础空军 | 前置链断了会得到造不出来的飞机 |
| 制空：打空中比打同血同甲的地面更疼 | 这条能力失效时，战斗机就只是"飞得快的高攻单位" |
| 对地/反舰：两条加成各管一层 | 加成串味会让"每种飞机只擅长一件事"整条设计塌掉 |
| 隐身：贴脸才现形，打完不挨反击 | 复用的两条老机制确实接上了 |
| 舰载机白名单：只有四种上得了甲板 | 白名单被"顺手加一个"是这类设计的常见死法 |
| 甲板起降：多一架 / 少一架，带伤起飞带着伤 | 起飞失败的兜底不能被写成"扣了飞机" |
| 整备：先收、再修 8 点、后放一架 | 双钩子跑两遍（哨兵丢了会变成 56） |
| 掠水：飞机能停深水，陆军不能 | 新地形与空中层的交叉判定 |

另外全量回归：`smoke-dom`（142 项）、AI 优化（26 项）、AI 评估（7 项）、
`tsc --noEmit`、`vite build`、`npm run manual`（8 册 / 扩展兵种 206 个全部入册）。

## 八、已知边界

- **没有燃油与返航半径**。飞机不会因为"飞太远"掉下来，也不会因为没有航母就摔。
  加燃油就要给每个兵种记一个当前油量字段，那要么改 `Unit`（核心类型），
  要么在 `custom` 里存一份影子状态——两条都会让"扩展不改引擎"这条线破掉。
- **甲板整备是自动的**。现在每回合自动收、自动修、自动放一架，玩家不能选择
  "这一回合我不放飞"。要变成手动，需要一个新的 `Action` 类型，那是核心的活。
- **没有防空这一层"高度"**。高度地形（`height-terrain.ts`）对空中单位不给修正
  （`TERRAIN_RANGE_MOD` / `TERRAIN_VISION_MOD` 对空中层为 0），
  所以飞在山上和飞在平原上空是一样的。真要区分，得给空中层单独一张高度表。
