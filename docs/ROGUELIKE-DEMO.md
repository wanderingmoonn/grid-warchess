# 肉鸽 2.0（if 线，L1–L3）实现说明

> 一句话：**主游戏原封不动，标题页多了一个「肉鸽 2.0」。**
> 两个入口：标题页的「肉鸽 2.0」按钮，或 `npm run dev` 后打开 `http://127.0.0.1:5178/?rogue=1`。
> 设计依据见 `ROGUELIKE-FLOW.md`（结构）与 `ROGUELIKE-STORY.md`（叙事）；本文件只讲**做了什么、怎么跑、差在哪**。

## 〇、它和标题页那个「肉鸽」是什么关系

**两套东西，并存、互不影响。**

| | 原版肉鸽（另一位合作者） | 肉鸽 2.0（本目录） |
|---|---|---|
| 定位 | **原版规则的线性切片**，DLC 随时可加，纯粹原版也能跑 | **if 线**：把整个游戏几乎所有的部分都揉进肉鸽 |
| 结构 | 三幕 × 三场 = 9 关（每幕第 3 场是 boss），节点只有 battle / rest | 每层 **10 步 × 2 门 = 20 房**，三层，房型含事件 / 商店 / 营地 |
| 战斗 | 沿用原版的城与经济 | **玩家前三层没有城**；遭遇/精英**双方都没城**（兵打光算输），攻坚/层末才攻城 |
| 代码 | `src/core/roguelike/*` + `src/ui/roguelike/run-screen.ts`，接在 `main.ts` 里 | `src/roguelike/*`，**不引用对方任何模块** |
| 存档 | 有自己的 run 存档 | 不落盘（刷新即重开） |

**约定（对方原话）**："不要覆盖，留着""你自己搞个肉鸽 2.0""搞好就让它在你原版肉鸽旁边再加个接口"。
所以本实现唯一动到的共享文件是**标题页加了并排的一个按钮**，原版肉鸽的代码一个字节都没改。

## 二、怎么跑

```bash
cd grid-warchess
npm run dev
#   标题页 →「肉鸽 2.0」（在「肉鸽」右边）
#   或直接开 /?rogue=1
#   内容预览：/?rogue=1&rogueAuto=win —— 所有战斗直接判胜，一层层看事件/商店/结算
```

界面上「← 返回标题」在开局页右上角、层地图顶栏右侧、结算页；它走的是整页重载回不带参数的地址，
所以退出后主程序是干净的（不会留下被隐藏的棋盘或半截状态）。

生产构建也通（已验）：`npx vite build`，肉鸽被拆成独立 chunk（`app` 18 KB、`battle-screen` 9 KB、`ai` 63 KB），
只有真的进战斗才会去拉 AI。

自动验证：

```bash
node --experimental-strip-types scripts/rogue-smoke.ts      # 逻辑：房间图 / 流程 / 真打一场
node --experimental-strip-types scripts/rogue-ui-smoke.ts   # 界面：开局 → 战斗 → 结算 → 三层走完
npm run test:boot                                           # 确认本体没被影响
```

两条冒烟脚本不进 `npm test`（那是本体自己的回归），也不改任何既有脚本。

## 三、已实现（对齐 `ROGUELIKE-FLOW.md` 的部分）

| 项 | 试玩版实现 |
|---|---|
| 层数 | **3 层**，L4 不做 |
| 每层房间图 | **10 步 × 2 扇门 = 20 房**，房间种类与位置随机 |
| 房型比例 | **战斗 10（普通 6 / 精英 2 / 攻坚 2）· 事件 4 · 商店 2 · 营地 4 = 20** |
| 入口锚点 | 第 1 步两扇门都是战斗；第 3/7 步各有一扇商店；第 4/8 步各有一扇营地 |
| 层末 boss | 不走房间图，走完 10 步后单独一场（L1/L2 从三家名字里随机，L3 固定钟楼） |
| 时代钟 | 本层已进房数，越高敌人预算越大、越可能上高代兵 |
| 跨层保留 | 军队、金币、藏品跨层带走；阵亡的单位不回队（随军医官除外） |
| 四种战斗的区分 | 遭遇（8×8，双方无城）/ 精英（10×10，双方无城，编成更硬）/ 攻坚（10×10，敌 1 城）/ 层末（12×12，L1–L2 敌 1 城、L3 钟楼 2 城）；**每深一层四种各 +2** |
| 地图 | 自己写的固定图：**平原 ≈80%、森林 ≈14%、丘陵 ≈6%，没有水/山**（不绕路）；尺寸随层与房型 8→16 |
| 时代 | **L1 = 第 1–2 代 / L2 = 第 3–4 代 / L3 = 第 5–6 代**（城随低代：1/3/5，层末敌人用高代），第 6 代由「信息化」扩展解锁 |
| 跨层换代 | **不自动换装**。旧兵原样带走，换代靠玩家自己：战利品、商店、层末奖励。层末必给**一个下一层的初级兵**当落脚点 |
| 敌人换代节奏 | 每层按时代钟分三段：**钟 0–2 用上一代**（L2 是 e2、L3 是 e4）/ 钟 3–5 本层低代 / 钟 6 以后与层末用高代（2 份高代 + 1 份低代混编） |
| 阵型 | 开局按**射程越远越靠后、跑得快的站两翼**自动排；只看谁站哪，不重挑格子（不会踩城/水/山） |
| 战斗上限 | 遭遇 16 / 精英 18 / 攻坚 28 / 层末 40 轮，超时判负 |
| 手感 | 选中一次即可"先走再打"；**撤回**按钮 + Ctrl+Z；无招募（玩家没城，只打这一支部队）；**鼠标悬停任意单位看属性**（和本体一样的攻/甲/血/移/射/视野） |
| 补员 | **没有后台补员**：兵只从战利品、商店、层末奖励来（上一版每胜一场白送 1 个兵，现在取消——战利品本身就是"兵 or 钱"）；敌人只在有城的关补，整场最多 1–2 个 |
| 方略 | 3 个（边军 / 射手 / 骑军），各带初始编成 + 一条规则级被动 |
| 事件 | 9 个，每个 2–3 个选项，效果＝金币 / 加兵 / 藏品 / 下一战攻击或护甲加成 |
| 营地 | 从 5 个里抽 3 个：补员 / 募饷 / 演武 / 加固 / 征召 |
| 战斗奖励 | 普通/攻坚：**1 个本层兵**（攻坚 2 个）／**略高于 1 兵价的钱**／整训。精英：**3 个兵**／**3 兵价的钱**／**1 兵 + 1 藏品**。层末：**不给选择，全给**——1 藏品 + 1 本层高级兵 + 等价钱 + 1 个下一层的初级兵 |
| 奖励给什么兵 | 按时代钟抽：钟越靠后越可能给高代兵（p = 钟/10），但**低代抽最贵的、高代抽最便宜的**，所以钟到一半时两边拿到的战力接近 |
| 结局 | 走完 L3 层末 → **常规结局「破钟」**；单位打光或城破 → 失败结算 |
| 失败判定 | 有城的席位按"城全空"判；**没城的席位（玩家，遭遇战里的双方）按"兵打光"判** —— 引擎自带的 `seats.cityless` |
| 城的作用 | 攻坚/层末敌人才有城：攻坚**整场最多补 1 个**、层末最多 2 个（有上限，不是无限磨），且这两类关卡的 AI 改为守城（`aiDoctrine: 'boom'`），出城抢攻只发生在无城的遭遇/精英 |
| 临战决议 | 层末 boss 前**固定出现**，从 5 个里抽 3 个（夜袭 / 强攻 / 买通 / 就地征召 / 工兵破墙），只影响这一场 |
| 商店 | **三行货架**（兵种 3 / 藏品 2 / 补给 1），买完不关店可以接着买，40 金刷新；有「行军图」时全场 8 折 |

## 四、和设计文档不一样的地方（都是刻意的，且都能改回去）

1. **无城关卡走的是引擎自带的 `seats.cityless`（关键改动）。**
   一关现在是一份 `LevelDef`（`core/level.ts`）：固定地图 + 席位 + 开局部署 + 开局时代，
   交给 `createMatch` 建局。`seats.cityless` 的语义就是"这一席没有城，兵打光即出局"——
   于是**玩家前三层没有城、遭遇战双方都没有城**这件事不用改规则层就成立了。
   （上一版是靠"给双方各发一座营城"绕过去的，方向是错的，已删。）

2. **敌人一律"抢攻"（`aiDoctrine: 'rush'`）。**
   手写 AI 默认会先算经济再推——那是完整对局的正确打法，但一关只有二三十轮，屯兵等于让玩家干等。
   `aiDoctrine` 是**现成的脚本接口**（产品界面不暴露），这里正好用上。

3. **只放地面战斗兵进场；地图是我们自己写的。**
   放开全表的话 AI 会把回合拿去做农民、修桥、盖房子（实测 30 轮 0 次交火）。
   地形也不再靠 `mapStyle` 抽——抽出来的图一半是水，陆军全得绕路。
   代价是**没有水战、没有野外建造**——这两条不在试玩范围。

4. **无城关卡关雾。**
   没有敌方城市当方向来源时，AI 只能靠"看见的敌人"推进；`setup.ts` 里那条实测写得很清楚：
   没城又开雾，两排兵能站到第 80 回合谁都不动。小图（8~18 格）全亮也更像短兵相接。
   有城的攻坚关同理关雾，免得玩家找不到城。

5. **两边都不许补员**：AI 那一侧用 `AiBudget.maxRecruit = 0` 关掉（玩家没城本来就不能造）。
   不关的话，敌人靠城市收入每两回合摸出一个兵，玩家再能打也磨不过。

6. **回合上限比设计值低**（16–30 轮，设计里是 120/300）。没有 L4 的 40×40 大会战，
   小图上十几轮就能分出结果；上限只是兜底，不是期望值。

7. **敌人强度按"层 + 房型"定，只按 25% 跟随我方部队**（`BALANCE.base / w / follow`）。
   不写成"完全镜像我方造价"是实测出来的：那样会滑向**兵越少越强**——小地图上
   同一时间只有三四个兵能交手，多出来的挤在后面挨打；而敌人预算跟着总造价涨，
   于是"拿兵"反而让对面也变强（纯选兵通关率一度比纯选钱低 10 个百分点）。
   现在层决定对面有多强，我方成长只带 25% 的回响，"变强"才是真的变强。
