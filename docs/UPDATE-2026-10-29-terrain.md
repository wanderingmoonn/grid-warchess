# 更新公告 · 2026-10-29 · 地形高差：山脚与尺度

> 一句话：勾上「地形高差」之后，本体那四种地貌不再"原样照发"——每座山都要补出
> **丘陵 → 台地**两圈山脚；随机地貌里扩展自带的那六种也从"一半对局"变成"七成"。
> 火山群的阶梯顺序顺带修了：火山口终于在山顶、熔岩回到山脚。

| # | 改了什么 | 落点 |
|---|---|---|
| 1 | `softenPeaks` 从"削孤峰"改成"补山脚"（BFS 两圈） | `src/core/height-terrain.ts` |
| 2 | 随机袋：扩展地貌进两次、本体各一次（原来本体占 6/14） | `src/core/mapgen.ts` |
| 3 | 火山群阶梯改成按高度排：平原→熔岩→丘陵→台地→高山→火山口 | `src/core/height-mapgen.ts` |
| 4 | 收尾回调多收一个 `keep`（城与城郊），跑完再补一次镜像 | `src/core/expansions.ts` / `src/core/mapgen.ts` |

---

## 一、问题长什么样

用同一颗种子生成 24×24，只切扩展开关，数三样东西：

- **软地面悬崖**：山格的四邻里还有平原/林地/丘陵的边数（也就是"一步从 2 层跨到 5 层"）；
- **高地占比**：高度 ≥3 的格子比例；
- **高地块尺度**：所有"高度 ≥3"的连通块平均有多少格。

改之前（`ridge` / `river-h` / `open` 各四个种子）：

| 地貌 | 软地面悬崖 | 高地占比（关→开） | 备注 |
|---|---|---|---|
| 山岭 `ridge` | 18~21% | 32% → 32% | 种子 21 上开关两边的统计**逐项相同** |
| 横河 `river-h` | 37~60% | 14% → 14% | 只是多了几段浅滩（那是开凿改成浅流的副作用） |
| 开阔 `open` | 8~25% | 11% → 13% | 唯一的区别是几根孤峰被削成了台地 |

对照扩展自己的地貌（高原 2~10%、峡谷 1~5%），差距一目了然：
**勾了扩展之后，一半对局拿到的还是原来那张图，只是山上多了几块台地；
另一半对局的坡倒是平滑的，但那是因为它们根本没走本体那条分支。**

## 二、根因

### 2.1 `softenPeaks` 只会"削"，不会"补"

旧实现是一句话：**"一格高山，四邻里没有台地/高山，就降成台地"**，跑最多四遍。

问题在于它挑的是"孤峰"：

- 一条 20 格的山脊、一个 2×2 的山包，每格都有山邻居，于是**一格都不降**——
  整条山脊的边照样直接贴着平原，一道从 2 层到 5 层的墙；
- 被降的那几根孤峰，是变成"台地贴着平原"（2 → 4），悬崖只是往外挪了一格，并没有消失；
- 它的注释写着"结果是一座山的边缘永远有一圈台地托着"——**它从来没有造过这一圈**。

这条也就是最早那条测试（"高山底下都得有台地托着"）能过、而地图看着仍然生硬的原因：
判据是"四邻里**至少有一个**高邻居"。山脊中段的格子当然有，边缘那格的邻居也是山——
于是"有没有山脚"这件事被"有没有山邻居"顶替了。

### 2.2 随机袋里本体地貌占多数，而本体分支一格都不读扩展

石头袋是"每种一次，河道与山岭各两次"：本体 `open×1 + ridge×2 + river-h×2 + river-v×1 = 6`，
扩展 `6`，合计 12 —— **一半对局抽到本体地貌**。抽到之后走的是撒团块配方，
`afterTerrain` 只在最后跑一遍 `softenPeaks`（见 2.1，几乎什么都没改）。
于是"开了扩展和没开一样"。

### 2.3 火山群的阶梯顺序写反了

旧阶梯：`平原 → 丘陵 → 台地 → 熔岩 → 火山 → 高山`。两个后果：

- 最后一档是 `mountain`，也就是说**最高的那圈是"高山"，火山口反而是山腰**；
- 高度只有 1 层的熔岩夹在 4 层的台地和 5~6 层的山顶之间——
  每座锥子外面套了一圈**三层深的坑**（实测火山图的软地面悬崖 13~28%）。

`height-terrain.ts` 的高度表注释一直写着"火山脚下那圈熔岩"，代码和注释是矛盾的。

## 三、修复

### 3.1 补山脚：从"削孤峰"改成"两圈 BFS"

```ts
// src/core/height-terrain.ts
从所有 mountain / volcano 出发做一次 4 邻 BFS（水与浅流不传播）；
  第 1 圈 → 台地(4)，第 2 圈 → 丘陵(3)，只抬 plain / forest / hill。
```

于是任何一座山从外往内一定是 **平原(2) → 丘陵(3) → 台地(4) → 高山(5)**，每步只差一层；
`hugLand` 与 `clearAroundCity` 好不容易清出来的城郊则被 `keep` 名单挡住（见 3.3）。

不再"削孤峰"：一根孤峰配上两圈山脚就成了一座小丘，没有理由再把它削平。

### 3.2 随机袋：扩展地貌进两次

```ts
// src/core/mapgen.ts
for (const id of styles) {
  bag.push(id);
  if (isExt(id)) bag.push(id);                       // 扩展地貌进出两次
  else if (extCount === 0 && (id === 'river-h' || id === 'ridge')) bag.push(id);  // 老优惠只留给没开扩展时
}
```

理论占比 12/16 = 75%；实测 40 张随机图 **72.5%** 落在扩展那六种上（改之前是 50%）。
没开扩展时袋子不变——本体那 12 张图一张不差。

### 3.3 收尾回调多一个 `keep`，跑完再补一次镜像

- `afterTerrain(g, w, h, keep?)`：`keep` 是"城市 + 城郊一圈"，补山脚不碰它。
  否则城门口那片清出来的平地会被抬成台地——出生点站不下人，攻城也变成爬坡。
- `afterTerrain` 是在 `symmetrize()` **之后**跑的。补山脚本身是"对称进、对称出"
  （只看地形、不看 rng），所以镜像局今天不会因此歪掉；但下一个写 `afterTerrain`
  的人未必守这条，所以收尾跑完还是补一次 `symmetrize()`（空转，很便宜）。

### 3.4 火山群：阶梯按高度重排

```
平原(2) → 熔岩(1，脚下溢流) → 丘陵(3) → 台地(4) → 高山(5) → 火山口(6)
阈值 0.36 / 0.44 / 0.60 / 0.78 / 0.92，最后一档留 1.01 的余量（高度场被 clamp 在 1）
```

阈值刻意压在"山脚"那一段（0.36~0.44）：高度场是单调外降的，这样熔岩才会**绕在山脚**，
而不是像旧版那样散到图边去（旧版熔岩的阈值落在 0.74~0.96，等于贴着山顶）。

## 四、验证

### 4.1 关掉扩展：600 张图指纹一致

```
12/16/20/32 四种边长 × open/ridge/river-h/river-v/random × fair/mirror × 12 颗种子
= 600 张图，行字符串 + 出生点数 + 实际地貌 + 无渡口标记的 SHA1
改前 51d2b6aa… / 改后 51d2b6aa…（完全一致）
```

也就是说：没勾「地形高差」的对局、老存档、老回放，一格都没变。

### 4.2 开着扩展：山脚补齐、尺度变大

24×24，三张本体地貌 × 六个种子：

| 地貌 | 软地面悬崖（改前 → 改后） | 高地占比（关 → 开） | 高地连通块平均（关 → 开） |
|---|---|---|---|
| 山岭 `ridge` | 18~21% → **0~3%** | 28~32% → **39~47%** | 16.9 格 → **43.3 格** |
| 横河 `river-h` | 37~60% → **0~1%** | 13~14% → **22~26%** | 6.5 格 → **16.7 格** |
| 开阔 `open` | 8~25% → **0~4%** | 10~14% → **13~22%** | 8.4 格 → **13.2 格** |

剩下的 1~4% 全是 `keep` 保护下的城郊（实测逐条都落在城的 3 格内），
以及水/谷地/熔岩这些"本来就该是断的"地形——补山脚只抬"软地面"。

火山群的软地面悬崖 13~28% → **0**；熔岩贴着山顶/山体的边数 → **0**。

### 4.4 双 AI 对局

200 回合上限、双边 AI，数"打到上限还没决出来"的局数：

| 地貌 | 样本 | 改前未决 | 改后未决 | 备注 |
|---|---:|---:|---:|---|
| 山岭 `ridge` 12×12 | 4 | 2 | 3 | 高地 32% → 47%，推得更慢 |
| 山岭 `ridge` 16×16 | 4 | 3 | 3 | 一样慢 |
| 山岭 `ridge` 20×20 | 4 | 3 | 2 | |
| 高原 `highland` 12×12 | 4 | 2 | 1 | |
| 峡谷 `canyon` 12×12 | 4 | 0 | 0 | 四局回合数**逐局相同**：峡谷本来就是等高线，补山脚无事可做 |
| 火山群 `volcanic` 12×12 | 8 | 2 | 3 | 地图本身变了（阶梯重排），不是同一张图 |
| 沼泽 `marsh` 12×12 | 6 | 4 | 4 | 逐局相同：沼泽一格高山都没有 |

结论：**"山岭 + 高差"本来就慢**（爬坡每层 +1、最多 +2，这是扩展的规则，不是这批引入的），
差异都在噪声里。真正变的是地形本身：高地面积从三成涨到接近五成，山体从 17 格的碎块
长成 43 格的整片。想要快节奏，挑河谷/峡谷，或者别同时开「地形高差」+ 山岭。

## 五、没做的事

- **没有重写本体地貌的生成器**。原版撒团块的手感（开阔图就该平）保持不变，
  扩展只在它上面补山脚。真要"整张图都按高度场重算"，那是另一个包（比如"全套等高线"）。
- **没有动"爬坡 +1 / 封顶 +2"那条规则**。山岭 + 高差推到 200 回合不决的情况仍然存在，
  但它是扩展的规则设计（高地难打），不是地形的锅。
- **没有给沼澤/群岛加山脚**：这两种地貌一格高山都没有（实测 peaks=0），补山脚那段是空转。
- **城郊依然是平的**（`keep` 保护）。所以城堡贴着山时，城门那一侧会有一格"平地 → 台地"的
  小台阶——这是刻意的：出生点比山的形状重要。
