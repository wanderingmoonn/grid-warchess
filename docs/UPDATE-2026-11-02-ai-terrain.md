# AI 的地形/特性决策重构 + 「好兵没人造」归因 · 2026-11-02

两件事：先让 AI 看懂"这个兵站在这块地上值多少"，再查"数据好的兵为什么没人造"。

---

# 一、地形与特性：AI 之前根本不认识

## 1.1 病灶

伤害结算**早就**吃地形了（`computeDamage` 读 `CONFIG.terrainDef` 和 `statArmor` 钩子），
所以"树人站丘陵真的多 5 点甲"这条规则一直是对的。坏的是**决策层**：

| 位置 | 原来的写法 | 后果 |
|---|---|---|
| `tacticalMoveScore` | `terrainDef[terrain] * 1.5 - 1` | 与兵种无关的常数：树人站丘陵和民兵站丘陵同分 |
| `scoreMove` | `terrainDef[terrain] * 2` | 同上 |
| 走位候选 | 只有"去哪"，**没有"不动"** | 只要还能走一步，AI 必定挪走——从丘陵挪到平地，白丢 5 甲换来 0.5 分推进 |
| 招募评分 | 无 | 图上森林丘陵再多，也不会多造一个吃这口饭的兵 |

一句话：**"丘陵值多少"是知道的，"树人站丘陵值多少"从来没人算过。**

## 1.2 改动

### M1 兵种特性识别：把地形加成变成可读的数据

`ability-hooks.ts` 新增声明字段 `terrainArmor`，`ability-registry.ts` 新增 `terrainArmorOf(def)`：

```ts
// fantasy-packs.ts · 林地之主
terrainArmor: [{ terrains: ['forest', 'hill'], bonus: WOODLAND_ARMOR }],
statArmor: [ ... 读同一个 WOODLAND_ARMOR ... ]
```

**同一份数据两个消费者**：`statArmor` 拿它算实际护甲，`ai.ts` 拿它估地形。
之前两边各写一个 `3`，改一处就会静悄悄不一致。现在只有 `WOODLAND_ARMOR` 一个常量。

### M2 地形加成计算：从"这格值多少"改成"这个兵值多少"

```ts
function tileDefenseValue(def, terrain): number {
  if (airLayer(def)) return 0;                       // 空中单位不吃掩体
  return CONFIG.terrainDef[terrain] + (terrainArmorOf(def).get(terrain) ?? 0);
}
```

两处调用点全部换掉。树人站丘陵 = 3（丘陵掩体）+ 3（林地之主）= 6；民兵站丘陵 = 3。
**比值从 1:1 变成 2:1**，AI 这才有理由把树人往林子里放。

### M3 作战决策：`holdScore` + 把"不动"变成候选

```ts
function holdScore(s, unit, all, traits): number
```

四条同时成立才守：① 脚下这格对这个兵有 ≥2 甲的价值；② 它是守得住的兵（移动≤2、近战、甲≥5）；
③ 4 格内有敌人；④ 站着不会死。另外：全军压城（`commit`）时不守，隘口（可站邻格≤2）加权 ×1.7。

接入点：

```ts
const stay = holdScore(s, unit, all, traits);
if (best && best.score >= stay) out.push(best);   // 否则这一回合不产出走位候选
```

开火是另一组候选，所以"站着"不等于"不还手"。

### M4 招募侧：地形契合

图上森林+丘陵占比 > 20% 时，对有地形加成的兵给 `min(12, 加成 × 占比 × 10)` 分
（3 甲 × 三成糙地 ≈ +9）。平原图上不给——面板写着 +3 但没有林子，那是废纸。

# 二、「数据好却没人造」：归因与修复

## 2.2 定位手段

原来的追踪只有一句汇总（"钱不够×3"），定位不到**具体哪个兵被谁挡住的**。
这次给 `aiRecruitTrace` 加了按兵种的拒绝计数，并把三处"池级"拒绝也纳入统计
（时代未解锁 / 英雄已在场 / 召唤物不采购）——它们以前根本不进统计，
所以"某个兵没人造"永远查不到原因。

4 局采 361 次采购决策，得到的原因分布：

| 单位 | 拒绝总次数 | 主要原因 |
|---|---|---|
| 榴弹炮 | 10,434 | **时代未解锁 84%**、钱不够 15% |
| 圣剑勇者 | 10,640 | **时代未解锁 83%**、钱不够 17% |
| 坦克 | 9,728 | **时代未解锁 75%**、钱不够 24% |
| 天使 | 10,249 | **时代未解锁 71%**、钱不够 29% |
| 铁甲舰 | 5,542 | 时代未解锁 60%、水域太少 27%、钱不够 12% |
| 装甲车 | 7,760 | 钱不够 53%、时代未解锁 43% |
| 不死鸟 | 9,710 | 钱不够 65%、时代未解锁 34% |
| 皇家骑兵 | 6,363 | **钱不够 89%**、分数偏低 10% |
| 炼金术士 | 5,251 | 钱不够 81%、**分数偏低 18%** |
| 鹰身女妖 | 4,962 | 钱不够 75%、**分数偏低 22%** |

## 2.3 三个结论

### ① era4+ 的兵：主因是**时代门**，不是选兵逻辑

榴弹炮/圣剑/坦克/天使 有 71%~84% 的拒绝来自"时代未解锁"——城市还没升到那一代，
`eraWindowOk` 直接把它们踢出候选池。

**这属于升级节奏问题**（上一轮已定位：AI 摊开升城、主城只拿到 33~60% 的升级、
到现代已经打到 60~90 回合），改采购评分对这一类**完全无效**。

### ② 同代可选的兵：主因是**当回合金币不足**，而且这是个被误标的 bug

皇家骑兵 89%、炼金术士 81%、鹰身女妖 75% 的拒绝是"钱不够"。

而修改前，这些全被记成「**粮食/建材不够**」——因为判定写的是 `canPay(quote.total)`，
而 `total` **包含金币**，于是"差 30 金"也被归到粮材上。顺着这四个字去查粮材产出，
方向完全是错的（我第一版就被它带偏了）。

**修复**：拆分判定——先判非金币资源，金币交给它自己的闸门。

```ts
const nonGold = { ...quote.total }; delete nonGold[GOLD];
if (!canPay(s.players[me], nonGold)) { deny('粮食/建材不够', d.id); continue; }
if (gold < quote.gold) { deny('钱不够', d.id); continue; }
```

修复后上表的原因分布才成立（皇家骑兵从"粮材 89%"变成"钱不够 89%"）。
这条是**诊断正确性**的修复，不改变行为。

### ③ 剩下的才是评分问题：炼金术士、鹰身女妖

它们各有 18%/22% 的拒绝是"分数偏低"——够强，但每回合都输给同价位的选择。
这一类才是真正需要动评分的，但量级只有两成。

## 2.4 试过并否掉的两个修复（都实测了）

### 方案 A：「为大件攒钱」

判据：这一回合能买的只是便宜货、而两回合内够得着明显更好的兵 → 本回合不买。

**实测反而更糟**，已回退：

| | 改前 | 改后 |
|---|---|---|
| 局均招兵 | 100.7 | **70.5** |
| 局均军费 | 14,082 | **11,060** |
| 皇家骑兵 建造 | 33 | 15 |
| 炼金术士 建造 | 2 | 0 |
| 鹰身女妖 建造 | 119 | 81 |

原因：省下的钱，下一回合也没买成那个大件（它照样输给中价位），
但**少买的那些兵是实打实的战力损失**。这个游戏里便宜兵每金吸伤是贵兵的 2.8~3.6 倍，
"停手攒钱"本身就是亏的。

### 方案 B：降低线性单价惩罚（0.035 → 0.02）

| | 0.035 | 0.02 |
|---|---|---|
| 皇家骑兵 | 33 | 39（+18%） |
| 装甲车 | 54 | 62（+15%） |
| 鹰身女妖 | 119 | 95（−20%） |
| 铁甲舰 | 12 | 5（−58%） |
| 局均招兵 / 未决 | 100.7 / 9 | 98.7 / 5 |

**中性偏噪**：只是在贵兵之间重新分配，总量没涨。已回退。

## 2.5 还没做、但已定位的两条（需要你定）

1. **编制满 = 永久锁死**。`armySize ≥ 24` 时 `recruitCandidate` 直接 `return null`，
   晚期没有任何"换血"路径——早期堆的便宜兵占满名额，贵的兵永远进不来。
   要修得给 AI 加"拆一个最弱的换一个更强的"（DISBAND + RECRUIT 组合），属于新能力，不是调参。
2. **升级节奏**。这是 era4+ 那一类的总闸，方案在 `docs/UPDATE-2026-11-02-modern-fantasy-tune.md`：
   集中度 `+6/-4 → +18/-10`，主城买不起时不升副城。

# 三、追加：「人类的两条战术，AI 为什么用不好」

## 3.1 直接原因：AI 没有"这一笔钱是留给谁的"

`refreshMemory` 只维护战争迷雾，**AI 没有任何跨回合状态**。每一次 `aiNextAction` 都是一次
全新的 argmax：走位、采购、升级、建造全部混在同一个候选池里比分数。

唯一的"攒钱"设施是 `buildPlan` 的 `savingFor` + `allowance`：

```ts
const allowance = savingFor ? Math.max(0, gold - targetCost) : Infinity;
if (!isTarget && price + unlockFee > plan.allowance) { deny('攒钱冻结'); continue; }
```

它能表达"为某件东西留出这笔钱"，但**只有三个目标**：英雄、升时代、收废墟。
普通兵种从来进不了这套机制。

## 3.2 集中升城：机制本身指向了错的那座城

```ts
// 改前
const eraCost = eraCosts.length > 0 ? Math.min(...eraCosts) : null;
```

`Math.min` 取的是**最低代那座城**的升级价——也就是副城。
于是"攒钱升时代"这条机制在这几年里一直推着 AI 往副城上花钱：
副城便宜、先够得着、先升上去，主城永远差一口气。

而人为什么集中升？因为**只有到顶的那座城能造新一代兵**（`rules.ts` 的 `eraWindowOk` 逐城判定）。
"均匀升"在数值上等于把三座城各升一级，谁也不能造新兵；"集中升"等于提前解锁整代兵池。

**修法**（三处，都在这条主线上）：

1. `eraCost` 改成主城（最高代那城）的升级费，不再取 min；
2. 攒钱升时代期间，`upgradeCandidate` 只允许升主城——否则副城的升级会在同一轮 argmax 里把这笔钱花掉，预留就是漏的；
3. 集中度权重 `+6/-4 → +18/-10`。

## 3.3 攒大件：我先踩了代码注释里已经记过的坑

`ai.ts:3037` 的注释写着：

> 部分照样可以买兵（见 allowance）——**第一版是硬停采购，实测直接掉了两成胜率**：
> 钱是攒下来了，可对面在这几个回合里多出四五个兵，城下再也没站起来过。

我第一版实现就是"硬停"（`return null`），实测复现了同一个结果：

| | 基线 | 硬停版 |
|---|---|---|
| 局均招兵 | 100.7 | **70.5** |
| 局均军费 | 14,082 | 11,060 |
| 皇家骑兵 建造 | 33 | 15 |

第二版改成复用 `allowance` 预留 + 目标到店加权（`score += 40`），结果好得多：

| | 基线 | 预留版 |
|---|---|---|
| 局均招兵 | 100.7 | 93.4（−7%） |
| 局均军费 | 14,082 | 13,495 |
| 均回合 / 未决 | 108.4 / 9 | 103.9 / **6** |
| era5+ 建造占比 | 5.2% | **5.6%** |
| 坦克 建造 | 16 | **26** |
| 不死鸟 建造 | 28 | **52** |
| 皇家骑兵 建造 | 33 | 37 |
| 天使 建造 | 27 | 22 |
| 鹰身女妖 建造 | 119 | 100 |

## 3.4 还剩什么没解决

1. **`allowance` 对普通兵种仍然近似"硬停"**：目标价 550 的时候 `allowance` 恒为 0，
   非目标采购全被拒。它的本意是"只花超出目标的那部分"，但这个游戏里普通兵的价和收入比
   决定了"超出部分"长期为 0。要真正做到"边攒边打"，得给一个按回合数分配的花钱额度，
   而不是"够不够"的二值判断。
2. **目标由 AI 自己的性价比公式挑**，而那个公式（`atk×sqrt(hp)×射程/价格^0.8`）
   和实测的每百金输出排序并不一致——挑出来的不一定是实测最好的那个。
3. **人类能赢还有一层原因**：人攒钱的时候，AI 正在把钱换成便宜兵（数量优势）；
   人攒到的是**质变**（新代兵/英雄），AI 攒到的往往是同代里贵一点的量变。
   同样的"忍一手"，收益不对称。
