# v4 出题手册（给人看的）

> 面向：出题人（你）+ 测试员。**不讲架构**，只讲怎么把一局棋变成一道有标准答案的题。
> 配套：`docs/PLAN-V4-2026-11-23.md` 第五节（考卷为什么是地基）。
> 本手册不写代码；里面的"工具"指阶段 0 要做的三个小东西（导出 / 判分 / 打印面板）。

---

## 一、结论先说：局面能在游戏里看，这是对的

出题不靠字符表格，靠**游戏自己渲染**。现在有两条现成的入口：

| 入口 | 怎么进 | 能走子吗 | 适合 |
|---|---|---|---|
| **导入对局** | 首页「导入对局」→ 粘贴一段文本 | **能**，想怎么试都行 | 测试员上手、试走几步看结果 |
| **复盘** | 导入整局回放文件 → 拖进度条 | 不能，只读 | 看"这局是怎么走到这一步的" |

技术上的依据（给以后看代码的人）：`importMatch` 认 `kind: 'snapshot'`，
所以一份单帧快照直接粘进去就站在那一格上；复盘走的是 `importReplayFile`，
需要整局的动作序列，**单帧进不了复盘**。

**建议两道都发**：整局回放给"背景"，单帧局面给"上手"。

---

## 二、必须先处理的一个坑：导入后 AI 会自己接手

导入对局之后，游戏会检查"现在轮到谁"——**如果轮到 AI，它当场就开始走**
（`main.ts` 的 `kickAiIfNeeded`）。测试员还在看局面，AI 已经把棋走完了。

**修法（出题时做，只改数据不改代码）**：导出局面时把两个席位都标成人类：

```
state.aiControl = { A: false, B: false }
```

`isAiSide` 会先读这个字段，它一出现就压过所有其他设置。
所以这一条设对了，导入后棋盘就是静止的，谁也不会自己动。

**自检**：导入后停三秒，看有没有单位自己动。动了就是这里没设对。

## 三、迷雾：不许为了"看得清"关掉

如果原局开了雾，导入后测试员只看得见我方的视野。**这是对的，不要关。**

"看不看得见"本身就是考点：AI 也只看得见这些。人要是能看见全图，答案的难度就和 AI 不是同一道题了。

只有一种情况允许关雾：**这题的考点与视野无关**（比如双方都看得见的桥头拥堵）。
而且关雾要在题卡里写明"本题视野不参与"，否则以后看回放的人会以为搞错了。

## 四、单位怎么指认（游戏里没有编号）

**单位没有独立名字**（2026-11-23 核对过：`Unit` 只有兵种，`utype().name` 是兵种名）。
所以"把兵改名成 w1/s1"这条路走不通，别试。

实际做法：

1. **测试员不用编号**，只说"桥头那个弩兵往左挪一格"这类**位置 + 兵种**的描述；
2. **出题人**手上有一份带编号的面板（`author.md`），把它翻成坐标；
3. 编号只在出题人内部用：`w1` 是经济单位、`s1` 是战斗单位、`b1` 建造单位、`c1` 建筑，
   按"兵种 → 坐标"排序，同一局同一格永远同一个号。

两个同名兵是最容易搞错的地方。所以题目要尽量让"被问到的那个兵"在位置上唯一——
如果实在不唯一（两个剑士并排站着），**换一个局面出题**，别指望描述能说清。

## 五、一道题 = 四个文件

```
exams/
  Y-012/
    snap.json    # 局面。游戏「导入对局」直接粘
    card.md      # 给测试员：看得见的东西 + 问题 + 请他回的三件事
    answer.md    # 标准答案 + 判据 + 红线。机器只读这一份
    author.md    # 给出题人：带坐标的面板 + 被雾挡住的敌人 + v3 实际动作
```

四个而不是三个，是因为 `card.md` 要发给测试员，**里面不能有他被雾挡住的敌人**，
也不能有"v3 刚才做了什么"（那是答案的一半）。这两样单独放进 `author.md`。

用 `scripts/make-exam.ts` 生成，四份自动拆好（见 `exams/README.md` 第六节）。

## 六、答案怎么写

答案分两栏：**人话**（测试员说的）和**机器**（你翻的）。

| 谁 | 做什么 | 到哪儿（人话） | 机器 | 为什么 |
|---|---|---|---|---|
| s1 | 走 | 桥左边一格 | `MOVE s1 → (5,3)` | 让开桥点，敌人下回合就要过桥 |
| s2 | 走 | 桥右侧、别占桥点 | `MOVE s2 → (5,6)` | 换到能堵的一侧 |
| w1 | 走 | 离开产金的那格 | `MOVE w1 → (2,6)` | 腾出格子给兵站 |

**同一目的的不同做法，都要记下来**（这叫"替代解法"）：

```
替代解法：s1 走到 (4,3) 也算让开——
          判据不关心具体格，只关心"桥点空了"
```

替代解法不是凑数，它是在提醒你：**判据不能写成"必须走这一步"**，否则就把 AI 训成"模仿人的动作"
而不是"达到人的目的"。

**顺序有意义**：先走的和后走的会互相影响（先让位才能站过去），所以答案是有序列表，不是集合。

---

## 七、判据怎么写：四段模板

每道题都按这四段填，缺一段就会出问题：

```
1. 做到了什么（必填）
   几条硬事实，每条带时间窗。例：3 回合内 (5,4) 空出来；
                               期间跨过这座桥的我方单位 ≥ 1

2. 没破坏什么（必填）
   防止用蠢办法达成。例：桥对岸 3 格内我方伤亡 ≤ 1；唯一那座桥还在

3. 时间窗（必填）
   例：3 回合。不给"慢慢来"留空间——不给时间窗，等 40 回合也算做到

4. 不看什么（选填，但很推荐）
   例：不看具体走哪一格、不看谁去让、不要求和标准答案一致
```

### 三种写坏的判据（都会让题变废）

| 坏判据 | 为什么坏 |
|---|---|
| ✗「s1 必须走到 (5,3)」 | 这是抄答案，不是判据。换一种同样正确的走法就判错 |
| ✗「这一回合要动 ≥ 2 个单位」 | 随便动两个无关的兵也能过 |
| ✗ 只写「桥通了」 | 敌人自己过桥也算通。必须写"谁"通了、"什么时候" |

判断标准很简单：**把这条判据念给另一个测试员听，他能不能不带疑问地判红绿？**
不能，就是写得不够硬。

## 八、什么叫好题（五条）

1. **一句话说得出错在哪**：这题在考"AI 会站着不动"，不是"这局打得不好"。
2. **判据能机器判**：不靠"看起来更合理"。
3. **有多解**：人不止一种做法。如果只有一种，多半是题太窄（或者你把答案当判据了）。
4. **答案是"人会做的"**，不是"AI 做不到的"。别把"AI 不会"直接当标准答案——
   人可能也不会，那这题就是坏题。
5. **能说出对应 v3 的哪个病**：桥头让位、攒钱没出口、收尾投多少兵、死水造船……

### 坏题长什么样

- **局面太复杂**（十个兵、三个战场）→ 答错也归因不明，考不出任何东西。
- **答案"随便都行"** → 说明判据一定松，改成判断题或换局面。
- **需要用到测试员看不见的信息**（雾里的敌人）→ 人会答错，题就废了。
- **靠运气**（骰子、先手）→ 同一局面跑三次结论不同，不是好题。

## 九、填完自检（四条，一分钟）

1. **导入 `snap.json`，AI 有没有自己动？**（动了 = `aiControl` 没设对，见第二节）
2. **照答案走一遍，每步都被接受吗？**（被拒 = 坐标写错，工具会当场报出来）
3. **走完之后判据满足吗？**（不满足 = 答案和判据对不上，改一个）
4. **跑判分器，v3 红不红？**（不红 = 这题没在考 v3 会犯的错，**作废重出**）

第 4 条是硬门槛。四题里三题不红，说明你出的不是"题"，是"AI 本来就擅长的东西"。

## 十、测试员那一侧的流程（这段话可以直接发给他们）

> 1. 打开游戏 → 首页「导入对局」→ 把我发你的那段文本粘进去，回车。
> 2. 现在这盘棋轮到 **XX 方**，你就当这一方。
> 3. **可以随便走、随便点**，看会发生什么，弄坏了也没关系（只影响你本机的存档）。
> 4. 但最后请告诉我三件事：
>    - **这一回合你会怎么做**，按顺序，每步一句"为什么"；
>    - 如果局面里有一个"必须马上处理"的东西，是哪一件？
>    - **这题你觉得简单还是不公平**，为什么。
>
> 第 4 条里最后那个问题最有价值——"不公平"通常意味着我们漏了一个约束。

## 十一、常见错（都容易犯）

| 错 | 后果 | 怎么避免 |
|---|---|---|
| 忘了设 `aiControl` | 导入后 AI 抢着走，测试员看不到局面 | 自检第 1 条 |
| 开雾的题为了好看关掉雾 | 难度变了，答案不可信 | 第三节；关雾要写进题卡 |
| 判据只写"做到了什么" | 能被蠢办法刷过 | 第七节的四段模板 |
| 用 30/31/32 种子出题 | 已被 v3 调参污染 | 出题用 50~59，见 PLAN 第十节 |
| 判据写成"必须走这一步" | AI 学会模仿动作，不会达成目的 | 判据看结果，答案只是示范 |
| 出完题以为能永久用 | 规则一改，旧快照可能直接不合法 | 见第十二节 |

## 十二、题库会腐烂，要定期体检

局面快照里存的是**整个局面**（`isValidState` 会检查结构版本）。规则一改，
旧快照可能出现"这个兵种不存在了""这个单位站在不可通行的格子上"这类问题，
导入会被拒或算出来不一样。

所以：**每次改引擎/规则/兵种表，题库要整套重跑一遍**，报出哪几道题失效。
失效的题不一定要重做——多数情况是"重新导一份快照"，答案和判据不用动。

这件事建议做成一条命令（阶段 0 的工具之一）：`题库体检`。
它同时充当"规则改动有没有破坏题目"的回归线。

## 十三、这套流程最省事的地方

你不用担心"测试员的描述我怎么翻译成机器动作"：

- 测试员只说**相对位置**和**意图**，不说坐标；
- 你只填坐标（手上有可读面板）；
- **坐标填错会被工具当场拦住**（`applyAction` 拒绝非法动作）；
- 判据不认动作、只认结果，所以"翻译得不够精确"不会毁掉这道题。

所以三个人的分工是：测试员出**判断**，你出**坐标**，工具出**对错**。

## 十四、从真实失败局出题的两条现实（2026-11-23 实测）

第一批局面已经从三局 v3 失败局里切出来了，两条结论要先认下来：

### ① 真实局面多数是"综合判断"题，不是"单机制"题

v3 的失败不是"少做了一个明确动作"，是"整体判断错了"。所以真实局面切出来，
答案一定有分歧（这座城守还是弃、这波打还是等），判据也就写不硬。

**这不算失败**——真实回放的价值是"证据"：它证明这个病真的发生过、造成了多少损失。
但题目本体最好靠**手工摆小局面**，把一个病单独隔离出来。v3 的探针就是这么做的
（`probe:bridge-block` 摆的是"桥头被自己人堵住"），它们能把病钉死，
只是当时没能治好——那不是探针的错。

### ② 大图上切出来的局面很快就没法用

24×24 的局到第 31 手就 28 个单位、第 151 手 64 个。手册第八节把"十个兵、三个战场"
列为坏题，理由是**答错了也归因不明**。

**单机制题优先从 12×12 挖。** 大图留给整局过程指标，以及手工小局。

### 因此第一批 15 题的构成

| 类型 | 数量 | 作用 | 判据 |
|---|---|---|---|
| 真实局面（综合判断） | 3~5 | 验流程、给测试员真实感 | 松，允许"大方向对就行" |
| 手工小局（单机制） | 10+ | 真正能判红绿的主力 | 硬，必须机器判 |

详见 `exams/README.md` 第四节。
