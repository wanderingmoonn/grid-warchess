# 关卡事件表单 · 设计方案（2026-11-16）

> 这是 **E4 的详细方案**，写来先讨论、再动手。计划本体在 `PLAN-LEVEL-EDITOR-2026-11-15.md`，
> 字段语义的权威说明在 `GUIDE-LEVEL-AUTHORING.md` 第 6 节。
>
> 一句话：**事件是这套编辑器里唯一"有逻辑"的东西，也是唯一必须写代码才能表达的东西。**
> 地图和摆兵已经能点了，剩下的门槛全在这一块。

---

## 一、这块要解决什么

现在要做一个"第 10 次行动炸桥"，作者得写：

```ts
{ id: 'blow', when: { kind: 'turn', at: 9 },
  do: [{ kind: 'say', text: '桥被炸断了。' },
       { kind: 'terrain', zone: { x0: 7, y0: 7, x1: 8, y1: 7 }, to: 'deep' }] }
```

五处会让新手卡住：

| 卡点 | 为什么卡 |
|---|---|
| `turn: 9` | 它是**行动序号**不是回合数。两家局一轮两次行动，写 9 实际上是第 5 轮 |
| `zone: {x0,y0,x1,y1}` | 四个数字，得在脑子里把棋盘坐标翻译一遍 |
| `id` 必须唯一 | 复制粘贴两条事件忘了改，整张关卡校验不过 |
| `do` 是数组 | "炸桥还要说一句"＝两个动作，很多人只写一个 |
| `terrain.to` 有限制 | 不能改成桥（`syncBridges` 会改回水面）、不能改成城 |

目标：**这五件事全都不用想**。做出来的东西应该长这样（示意）：

```
┌─ 第 9 次行动 ──────────────────────────── 约第 5 轮（两家局） ─┐
│ 就做这些：                                                    │
│  ① 播报  [桥被炸断了。                    ]           [删除]  │
│  ② 改地形  区域 [7,7 → 8,7  重新框选]  改成 [深水 ▾]  [删除]  │
│  ＋ 再加一个动作                                              │
└───────────────────────────────────────────────────────────────┘
```

---

## 二、边界（先说清不做什么，否则会做成一门语言）

| 不做 | 理由 |
|---|---|
| 条件分支（如果…否则） | 引擎没有。`when` 只有三种触发，触发后动作按顺序全执行 |
| 事件触发事件 | 引擎没有链式依赖。要"同一时刻做几件事"就写在同一个 `do` 里 |
| 变量 / 表达式 / 计数器 | 同上。加了这个就不是表单，是脚本 |
| 拖拽连线（节点图） | 三条触发 × 五种动作，卡片就够；节点图会让新手更晕 |
| 新增触发类型或动作类型 | **编辑器只暴露引擎已有的能力。** 想要新能力单独开引擎批次 |

这条边界是硬的：一旦破了，后面所有"保存格式、校验、试玩"的约定都要跟着改。

---

## 三、数据结构（不变）

表单只是 `LevelEvent[]` 的图形界面，**不改数据格式**：

```ts
interface LevelEvent {
  id: string;          // 自动生成，默认不让人看见（见 §5.4）
  when: LevelWhen;     // 三种
  do: LevelDo[];       // 五种动作，按顺序执行
}
```

单向流：`表单操作 → 事件数组 → 序列化成 JSON 文本 → 编辑器统一保存`。
**没有第二份状态**（和画布、摆兵同一条约定）。

## 四、字段 → 控件对照表

### 4.1 触发（`when`）：三选一的下拉

| 触发 | 控件 | 要特别处理的 |
|---|---|---|
| `turn` 第 N 次行动 | 数字输入 + 一行小字"约第 X 轮（N 家局）" | 换算必须跟着**席位数**变：两家局 N/2，三家局 N/3 |
| `unitDied` 某家的兵死了 | 席位下拉（只列这一关坐人的席位）+ 兵种下拉（可留空＝任何兵） | 兵种下拉**全时代都列**（不按开局时代过滤） |
| `enter` 有单位走进区域 | 席位下拉（可留空）+ 区域框选 + `repeat` 勾选 | 默认只触发一次；`repeat` 要显眼，不然"反复触发"永远没人发现 |

### 4.2 动作（`do`）：一行一个，可增删可调序

| 动作 | 控件 | 要特别处理的 |
|---|---|---|
| `say` 播报 | 单行文本 | **必填**。空文本不许加进去（`validateLevel` 不拦，但玩家会看到一行空白） |
| `spawn` 刷兵 | 席位 + 兵种（可反复选）+ **在网格上点落点** | 见 §5.2。落点列表为空时不许保存 |
| `doctrine` 换打法 | 席位 + 打法（自动/速攻/发育/固守）+ 可选"目标席位" | 四个值就是引擎那四个，别自创 |
| `deploy` 让某家登场 | 席位下拉（**只列 `hidden` 里的席位**） | 没有 hidden 席位时这个动作用不了，要灰掉并说明 |
| `terrain` 改地形 | 区域框选 + 改成什么（下拉）+ 可选的"只改原本是…的地形" | 下拉只给 `LEVEL_TERRAINS`（不含城/虚空/桥），并解释为什么 |

### 4.3 顺序

动作按数组顺序执行。界面上就是"① ② ③"，带上下移动。
**不要做成可拖拽排序**：键盘/按钮更稳，而且拖拽在触屏上会和滚动打架。

## 五、三个真难点，逐个给方案

### 5.1 区域怎么选（`zone` / `enter` 的落点）

**方案**：复用摆兵面板里那块网格，抽成一个共用组件 `src/ui/level-grid.ts`。

现在画布（`level-canvas.ts`）和摆兵（`level-army.ts`）各写了一份"格子怎么摆、城怎么标、点击怎么算坐标"。
E4 再抄第三份就是灾难。所以 **E4a 的第一步是抽这个组件**，然后：

```
区域选择 = 网格 + 拖拽框选 + 实时高亮 + 尺寸读数（"3×2 格"）
```

要点：
- 框选过程中要**看得到现在框了哪几格**（半透明高亮），松手才确定；
- 显示选区尺寸和四个角坐标（作者要能对着 GUIDE 核）；
- 允许先框再改：卡片上显示"区域 7,7 → 8,7"，点一下重新框。

### 5.2 刷兵的落点怎么选（`spawn.units`）

这是**唯一一个"一个动作对应一组坐标"**的地方，也是最容易做歪的。

**方案**：不弹第二个窗口。在事件卡片里做一个小列表：

```
② 刷兵  蓝方 · [游骑 ▾]  [＋ 在地图上点位置]
        落点： (2,0) [x]   (3,0) [x]        [一键贴到北边缘]
```

- 「＋ 在地图上点位置」把上面那块网格切成"选点模式"，点一次加一个点；
- 每加一个点，列表里多一行，可以单独删；
- 兵种可以中途换（先点两个游骑，再点一个弓手）；
- **「一键贴到北/南边缘」**：解决 GUIDE 里那条踩过的坑——援军直接刷在玩家腹地，
  玩家的第一反应是"AI 在耍赖"。按钮做的是"把已选的兵按顺序排到指定边缘的第一排空位"。

**不做**：刷兵数量的批量输入（"3 个游骑排成一行"）。点三下比填表单快，
而且作者本来就要决定排在哪。

### 5.3 时间轴（能一眼看出节奏）

把所有事件按 `at` 拉到一条竖线上，例如：

```
第 6 次  ● 斥候出现
第 10 次 ●● 炸桥（播报 + 改地形）
第 15 次 ●●● 两翼骑兵 + 水退
```

价值在于：**现在这个信息只能靠读代码得到**。作者改完一个数字，看不到它和前后事件的关系。
也是验收物——"能不能看出这关的节奏"。

**放到 E4b 做**，E4a 先给一个极简摘要（"共 N 条事件，最早第 X 次，最晚第 Y 次"）。

### 5.4 事件 id 怎么办

`levelState.fired` 按 id 记录"这条触发过没有"。所以：

- **自动生成**：`e1`、`e2`…… 新增时取最小可用编号；
- **复制一条事件**时重新生成（不会撞）；
- id 藏在卡片折叠区里（"高级"），默认看不见 —— 它不是给人填的；
- **改 id 不改触发历史**：存档里是快照，改 id 只影响新开的局。这条要写进提示里，
  否则作者会以为"我改了 id，老存档会不会重放"。

## 六、校验分三层，各管各的

| 层 | 时机 | 管什么 | 表现 |
|---|---|---|---|
| 表单内 | 每次编辑 | 结构完整（区域没框、播报为空、刷兵没落点、deploy 指向非 hidden） | 卡片标红 + 保存被拦 |
| `lintLevel` | 保存前 | 语义问题（改地形没播报、hidden 没人叫上场、兵种 id 不存在、改地形改成桥） | 问题列表（已有） |
| `validateLevel` | 建局时 | 数据能不能建出一局 | 兜底，编辑器不该让它走到这一步 |

**表单内不重复 lint 的活**：同一句话在两个地方说，作者会以为有两处错。

## 七、分两步走

### E4a：表单（能编）

1. 抽 `ui/level-grid.ts`（画布和摆兵一起改成用它，**行为不变**，测试要全绿）；
2. 事件卡片列表：新增（先选模板或空白）、删除、上下移动；
3. 三种触发 + 五种动作的控件（按 §4 的对照表）；
4. 区域框选、刷兵选点、一键贴边缘；
5. 表单内校验 + 保存拦截；
6. 摘要行（事件数、最早/最晚）。

**验收**：不写代码把孤城那 5 组事件（12 次刷兵、1 次炸桥、1 次水退、1 次夹击）做出来，
导出的 JSON 和手写版结构一致；故意做三件错事（同一 id 两条、给不存在的席位刷兵、区域框在界外），
每条都要**就地**报错。

### E4b：时间轴 + 模板库（好用）

1. 五个模板一键插入：炸桥 / 边缘援军 / 中途登场 / 换打法 / 定时塌方；
2. 时间轴视图（§5.3）；
3. 时间轴上标出"这一步会改哪些格 / 会多出几个兵"。

**验收**：能在时间轴上一眼说出"这关第 10 次有事、第 15 次最凶"；
用模板从零做一张"三波援军 + 一次炸桥"的关，全程不碰 JSON。

## 八、已知的坑（做的时候逐条对）

1. **`turn` 是行动序号。** 输入框旁边必须写"约第几轮"，否则十个人里九个算错。
2. **`spawn` 落点被占会就近找位**（半径 1~2），挤满了才刷不出。所以"贴边缘"要检查那一排够不够站。
3. **援军从地图边缘进场**。模板默认落点就取边缘，并写一句为什么（这个坑花了两轮才认下来）。
4. **`terrain` 不能改成桥/城/虚空**：桥由桥单位维持，事件写的桥面下一步会被 `syncBridges` 改回水面。
5. **`assassinate` 的目标必须 `summonedOnly`**（lint 已在拦，表单里选兵种时要标出来）。
6. **区域越界 = 条件永远不成立**，作者会以为"事件没生效"。框选时就该拦住。
7. **三级以上席位才有 C/D**：事件里的席位下拉必须跟着 `seats.count` 走，别列出没坐人的席位
   （`validateLevel` 会拒，但那已经是保存之后了）。

## 九、待定的三个选择

写在这儿等拍板，拍完就动手：

1. **卡片还是表格？** 我建议卡片（一条事件一张卡，动作是卡里的行）。
   表格一屏能看十条，但每条有"触发 + 若干动作 + 区域"，塞进一行会挤成天书。
2. **时间轴放 E4a 还是 E4b？** 我建议 E4b。E4a 先把"能编"做扎实，
   时间轴改的是视图不是数据，晚做不会返工。
3. **刷兵要不要"一键贴边缘"？** 我建议要。它是把 GUIDE 里那条踩过的坑变成按钮，
   成本很低，收益是作者不会再犯"援军刷在玩家脸上"的错。
