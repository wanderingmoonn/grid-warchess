> 更重要的是量出了一个新事实：**它把 AI 推进了"兵很多但打不完"的区域**

## 一、为什么要改（病根）

升级选城的老判据是"**时代最高的那座城**"：

```ts
// buildPlan：攒时代的钱攒给谁
const mainCity = myCities.filter(...).sort((a, b) => b.era - a.era || ...)[0];
// upgradeCandidate：集中升一座
if (city.era >= myEra) score += 18; else score -= 10;
```

这是个**自我加强的循环**：谁先升级，谁就是"最高代"，下一笔升级还给它。
于是升的永远是**已经领先的那座**（通常是后方城），前线的城一直停在低一代。

而 `eraWindowOk` 让低代城**造不出当代兵**。`probe:city-role` 的样本原样写着：

```
T19 halberdier 出在 c2（离敌 7 格）· 最近的是 c1（3 格）· 多跑 4
                              · 产兵格 c1(e2):1格 c2(e3):2格
```

**"兵从后方来"的真因是这个，不是采购选址。**（P0-4 那轮把选址项做完才量出来。）

## 二、设计

`hubCityOf`（`ai-v3.ts`）：算出"这一局该把钱投给哪座城"。

```
候选条件：!ruined、不是要弃的城、slots ≥ 1、heat < 0.75
打分：  -6 × (到 needCityId 的行军回合) + min(12, slots × 3)
```

- `needCityId`：有城在挨打就是那座城，否则是主攻的敌城（P0-4 已经有了）；
- **必须粘住**：`prev.goal === 'era'` 时沿用上次那座城。不粘的话枢纽在两座城之间抖，
  升级价 360/540 跟着变、`since` 被重置——`ANALYSIS-SAVE-FREEZE` 里那条
  "攒钱目标永远差一口气"有一半就是这么来的。

三个接入点：
1. `buildPlan` 的 `mainCity`（攒时代的钱攒给谁）→ 枢纽城；
2. `upgradeCandidate` 的"集中升一座 +18 / 其余 −10"→ 判据换成"是不是枢纽城"；
3. `upgradeCandidate` 的 `savingFor==='era'` 闸门（原本只许升"最高代那座"）→ 枢纽城。

开关：`aiHub`（`types.ts` + `setup.ts` 白名单 + `bench:ai --hub` /
`export-bench-replay --hub`）。**关着时行为一个字节都不变**（Q1|30|A 负 78、
Q3|31|A 负 84、Q4|30|A 胜 101 都逐局复现）。

## 三、实测（对手 `baselines/ai-9efb961.ts`，每组 12 局）

| 变体 | Q1/Q2 | Q3/Q4 | 说明 |
|---|---|---|---|
| 基线 | 10-2-0 | 11-1-0 | — |
| **v1 枢纽城**（+18 给枢纽，slots +0~12，heat≥0.85 −8） | 9-3-0（1↑2↓，**Q1 单组 5-1**） | **5-2-5（0↑6↓）** | 四局胜变 261 回合平 |
| v2 只加分不换枢纽（slots 加分 + heat） | — | 7-1-4（0↑4↓） | 三局胜变 261 回合平 |
| v3 只扣分（slots ≤ 1 → −12，heat≥0.85 → −8） | — | 8-1-3（0↑3↓） | 同样三局胜变平 |

**三版都净负，而且大图上是同一批对局翻车（Q3\|30\|A、Q3\|32\|B、Q4\|30\|A、Q4\|32\|A）**。
v2/v3 连"换枢纽"都没做，只是改了升级打分的常数——照样翻车。
说明这不是参数没调好，而是**只要升级节奏一动，那几局就滑进僵持**。

### 为什么"升级更对"反而输：兵多但打不完

两个 261 回合平局的终局快照（`replay-city-timeline.ts`）：

```
Q4|30|A  T241  A: 兵41 经12 金511 | c1 e4 … · c2 e5 产26(squad,artillery,tank,…)
Q3|30|A  T241  A: 兵29 经12 金389 | c1 e5 产17(squad,…) · c2 e4 产7(rifleman,…)
```

**41 个兵、6 座城之外只剩对面那座，261 回合打不下来。** 基线同一颗种子是 101 回合胜。

这跟 P0-4 那轮的教训是同一句：**"更早、更多"不等于"更强"**。
v3 的进攻依赖编队成形 + 压城判决（`commit`），单位数量上去以后，
后勤/成形/收尾那一条没跟上——瓶颈从"产不出兵"移到了"打不完"。
