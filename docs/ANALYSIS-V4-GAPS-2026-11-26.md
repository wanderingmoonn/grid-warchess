## 1. 海军：v4 里根本没有"水"这个概念

### 1.1 数出来的事实

| 文件 | 提到 `water` | 提到 `domain` |
|---|---|---|
| `ai-v4.ts` / `decide.ts` / `constrain.ts` / `tactics.ts` / `project.ts` / `types.ts` | **0** | **0** |
| `world.ts` | 7 | 1 |

`world.ts` 里那唯一一处 `domain === 'water'` 是**排除**，不是使用：

```
// bestPerCell：某一代"每格战力最强"的兵
if (utype(s, o.type).domain === 'water') continue;   // 注释：会算成"去造一堆开不上岸的船"
```

也就是说：**v4 对水兵的全部认知是"别把它算进战力"**。除此之外没有一处判断知道世界上有船。

### 1.2 为什么"造出来也用不上"

| 环节 | 现状 | 后果 |
|---|---|---|
| 服务层的距离 | `marchTurns` / 距离场按陆地的 `passable` 算，水面不通 | 船到任何目标的"几回合"都是 `Infinity` |
| 采购 | 候选 = `need.usable`（三发打得穿多数决敌人）× `survivable` | 船有可能被选中造出来（城边有水就能造），但只是**站在城里** |
| 编队 | 船算在 `myCombat` 里，进队后按陆地距离算 | 永远是"走不到"，不会接到任何目标 |
| 打分层 | 落点按陆地图取 | 没有"下水/靠岸"这类动作 |

所以现在的形态是"**要么不造，要么造一堆开不动的船**"——和 v3 当年 `seaDemand` 补丁的毛病同源。

### 1.3 要做的话该走哪条路（**只记，不做**）

v3 的结论写在 `docs/GUIDE-AI-GOAL-2026-11-20.md`：**别在评分函数里加 if，写一个产业链目标（`AiGoal`）**。

> 原文把海军列为第一个反例：「海军 | `seaDemand` + 船坞额度 + 特殊分支 | `rawBuildScore`」，
> 结果是"船坞在河道图上 80 回合造不出来，因为桥的分数刚好比它高几分"。

v4 的对应落点（按三层各一句，还没动手，先写清楚归属）：

1. **服务层**要能回答两件事实：这座城能不能下水（临水格 + 出兵格）、水面这块值多少（能不能打到对岸城 / 能不能绕开窄口）；
2. **决定层**加一个 `kind: 'navy'`（和 `bridge` 同级：都是"地形走不通 → 换一种走法"），期限 = 到对岸的回合数；
3. **计划层**把它翻成"船坞 + 船 + 登陆点"三样东西（船坞是建筑，船是单位，登陆点是格），钱要留；
4. **打分层**要有水上动作（上船/下船/沿水走）。

**顺序建议**：先有"一条带水的题"（现在没有；见 1.4），再谈实现——否则又是一个红绿无法归因的改动。

### 1.4 顺带查出来的一条：`mapStyle` 现在不生效

`scripts/v4-duel-replay.ts --style isles|river|marsh|open` 跑出来的地形**完全一样**
（12×12、seed 900：除了 `open` 以外都是 23 格水、城位一模一样）。
原因是地貌风格由**扩展**提供：

```
mapgen.ts: mapStylesFor(opts.expansions)   // 默认配置只开 bloodbath + turn-order-comp → 没有风格
```

所以"造一张水图来考海军"这件事，现在得靠 `height-terrain`（群岛/大川那几颗 chip）或者手摆局面
（`scenes/*.json` 里直接写 `~` 和船）。**记下来：以后跑实战别指望 `--style`。**

## 2. 不回防：判据把"能赶回来"当成"已经在守"

### 2.1 两局的读数（先看形状）

| 局 | 地图 | 城的命运 | 决定层分布 |
|---|---|---|---|
| `A-快检-900-后手-29手崩` | 12×12 火器 | 第 **4** 手开始掉血，第 **28** 手塌 | `press` **13 次 / `defend` 0 次** |
| `B-快检-901-先手-90手崩` | 12×12 火器 | 第 **79** 手开始掉血，第 **87** 手塌 | `press` **40 次 / `defend` 0 次**（另有 `expand` 3 次） |

两局都是：**城里一直在掉血，决定层一次都没说过"守"**。

### 2.2 为什么：`defensible` 数的是"谁**能**回来"

```ts
// world.ts defensible()
const window = min(6, 城还能撑几轮)
const inWindow = (u) => !skip?.has(u.id) && marchTurns(u, city) <= window
const defWorth = myCombat.reduce((n,u) => n + (inWindow(u) ? unitWorth(u) : 0), 0)
const hold = defWorth > foeWorth          // 守军身价 > 来犯身价
```

`myCombat` 是**全部**战斗兵——包括正在对面城下推进的那批。只要它们 6 手内走得回来，就算守军。
于是出现一个自证的循环：**兵越多、离城越近 → 越判"挡得住" → 越不会回头 → 城掉到 0**。

探针读数（同一份回放，逐手重算 `defensible`）：

| 手 | 我城血 | 敌人几手能到 | 判据 | 它写的理由 |
|---|---|---|---|---|
| T4 | 75/81 | 1 | **挡得住** | 守军 180 + 6 轮补 0 ≥ 来犯 89 |
| T6 | 69/81 | 1 | **挡得住** | 守军 347 ≥ 来犯 72 |
| T10 | **33**/81 | 1 | **挡得住** | 守军 448 ≥ 来犯 121 |
| T20 | 另一座 81 | 2 | 挡得住 | 守军 656 ≥ 来犯 17 |

到 T10 城里只剩 33 血，判据还写着"挡得住 448 ≥ 121"——因为外面那 10 个兵全被算进来了。
`H-16x16-era1-修后-先手` 更极端：T35~T95 守军 **1000~1700**、来犯 **100~370**，
120 手一次 `defend` 都没有。

**这一条就是用户猜的那个病，而且它可数**：`hold` 用的是"在场身价"，不是"被派回去的身价"。
修法有两个方向（**都没动**）：

- 让"外面那批人"不算守军（`skip` 由"正在进攻的所有队"填，不只是 `mem.bands`）；
- 或者给 `hold` 加一条：**判据成立但城已经在掉血**时，先派一部分人回去（把人真的派回去，而不是把身价记进来）。

### 2.3 两座城：确实不区分

| 事实 | 代码位置 | 后果 |
|---|---|---|
| 城角色只在"敌人 **1 手**内能摸到"时才算 `threatened` | `world.ts` `role` 计算 | 两城时，另一座可能正在被 2~3 手外的敌人磨，却只算 `front` / `safe`，不进守城评估 |
| 一手只能有一个 `cityId` | `Decision.cityId` | 不能同时宣布"守 A 和守 B" |
| `prev.kind === 'defend'` 只重新检查**上一手那座城** | `decide.ts` 继承段 | 守 A 的时候，B 塌了也不会被看见（`prev.cityId` 之外全不看） |
| 召回是"整队召回 + 太远的不回" | `constrain.ts` 守城分支 | 没有"分一半人守 B"这种拆法 |

对照：**进攻**是可以多线的（编队 id 是 `main-<城>`，几座敌城就几支队），**防守只有一条线**。
这就是用户说的"一个方向进攻时，抵抗不了另一个方向的进攻"——不是没看见，是**结构上只能选一个**。

### 2.4 ✅ A 已落地（2026-11-26 22:10）：三档判据

用户定的方案 A：**把"守得住/守不住"两档拆成三档，中间加"需要增援"**，回防按**编队**（整队改任务），不按单兵。

| 档 | 判据（全部是数） | 动作 |
|---|---|---|
| `hold` 守得住 | 门口稳（门口没敌人，或在场比对方多）**且**算上援军能赢 | 不动 |
| `reinforce` 需要增援 | 门口不稳，但"在场 + 窗口内能回"能赢 | **整队召回**（编队任务从"打某城"改成"守某城"） |
| `lose` 守不住 | 算上援军也赢不了 | 召回（城不能白送） |

两条地板：`rounds === Infinity`（按现在这股火力打不塌）→ 一律 `hold`；两边用**同一把尺**量
"在场（1 手内）/ 会来的（窗口内）"，否则会出现"来犯 0、在场 0"这种假比较。
（第一版就栽在这：`T-2-01` 的敌人还在 10 手外，第 3 手就被召回守城，五道题一起翻红。）

**读数**：37 道题**零变化**（判据变了，但现有题里没有一道覆盖"需要增援"这一档——这本身就是缺口）；
`900/后手` 那局从"一次守都没有"变成 **T10~T16 连着判"需要增援"**（在场 0 + 能回 221 ≥ 来犯 121）。

**但还是丢了**（31 手）。查下去是下一层的问题：**城是被"抢走"的，不是被血打光的**——
T12 城的归属直接变成对方（血还有 25），当时我方 4 格内有 5 个人、城里没人。
召回的人在路上，`yield`（让路）那几支还在排队。所以下一步不是"再算准一点"，
而是**守城时让路要让位给回防**（防守优先于整理队形），以及"城格上必须留人"。

### 2.6 三条排查（用户 2026-11-26 22:30 指出的，**只查不改**）

#### ① 城破时守军会被逐出城外 —— 用户说得对，"城里没人"是正常现象

`rules.ts` 的 `destroyCity()` 是攻城的**唯一真相**：城变废墟的同一个函数里，把城格上的守军
用 `freeNeighbor` **逐出城外**（找不到落脚点的会在日志里写"被围在废墟里无路可退"）。

所以看回放时要注意：`T11 城 33 血 → T12 归属变成对方`，中间那一手城其实**已经归零破了**，
城里的人是被规则赶出来的，不是 AI 把城丢空。以后不要再把"城里没人"当成摆烂的证据。

#### ② 经济单位**没有**被当成守军 —— 假设不成立

| 判据 | 数的是谁 |
|---|---|
| `defensible` 的"在场 / 能回" | 只遍历 `myCombat`（`category === 'combat'`） |
| `CityInfo.defenders`（城角色用） | `myCombat` |
| 采购、战力估值（`unitWorth`） | 只对战斗兵调用 |

实测那一局 T10：城 4 格内确实有 7 个单位，其中 **4 个是经济单位**——它们**一个都没进**那两个数
（判据写"在场 0"是对的：城边一个战斗兵都没有）。所以"经济单位被算成有战斗力"不成立。

#### ③ 经济单位堵产兵格 —— 这条成立，而且有一个明确的开关

`keepClear`（必须空出来给产兵/出城用的格子）平时包含**城格 + 外一圈**，但有一条例外：

```ts
// world.ts，算 keepClear 时
const inside = dx >= 0 && dy >= 0 && dx < n && dy < n;
if (inside && info.foeEta <= 1) continue;   // ← 敌人下一手能摸到城时，城格不算"必须空出来"
```

也就是说：**越挨打，"让路"越不管城格**（当初是故意开的口子，为了让守军站进城吃地形加成）。
后果是经济单位可以合法蹲在城格里——城格只有 4 个（2×2），蹲 2~3 个经济单位 + 1~2 个守军，
`recruitSpawnCells` 直接返回空，**有钱也造不出兵**。

实测同一局：T6 城内 `economy3`、T8 `economy3+combat1`、T10 `economy2+combat1`、T11 `economy2+combat2`；
T10 手上 238 金。这条和 ② 是两件事：**不算守军 ≠ 不占格子**。

## 3. 渡口来回翻（`P-2-05` 挖到的，已降级为 soft）

两条一样窄的渡口（都 3 格）时，服务层每次挑"最窄"，平手按当前单位位置破平；
工兵一动，破平结果就变，于是目标在 (8,6)↔(8,7) 隔手翻一次，工兵来回走，40 手只铺 1 格。
`P-2-03` 没露是因为那两个人手给的奴隶让破平稳定在 (8,7)。

**口径**：`P-2-05` 的 `cityDamaged ≥60` 先放 soft，护栏只锁"有人 + 桥出第一格"；
等渡口稳下来（挑一次就记住，或按"到城的总步数"破平）再提回 must。详情见 `exams/P-2-05/review.md` §4。
