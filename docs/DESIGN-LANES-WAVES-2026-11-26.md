# 兵线与波次：v4 怎么像人一样投送兵力

> 2026-11-26。用户提出：**v4 的主语是"这支队伍"，人的主语是"这条线路"**。
> 主力部队是**消耗品**，沿一条线一波一波地送上去；一条线受阻就减每波兵力、把钱转产能，
> 直到产能撑得起两条线。本文把这个模型写成可落地的形状，并给出第一步（影子模式）。
> 阶段二排序随之调整：P4 / P5 并入本文的 W 系列（见 `PLAN-V4-PHASE2` §3 的 W 节）。
>

> 与用户心里的"一批人"不是一回事，已重写（§3）。同时补上第一版缺的一条判断——**下一波什么时候上路**（§3.3），

## 0. 一句话

**先让 v4 看见"线"和"波"，再谈这条路好不好走。**

现在的 v4 能算"这队人走到城下要几手"，但它心里的主语是一支**要活下来**的队伍；
人心里的是**一条能反复用的通道**，队伍只是通道上的一批货。

## 1. 为什么必须改主语（四条代码事实）

| # | 事实 | 在哪儿 | 为什么它是"资产口径" |
|---|---|---|---|
| 1 | 攻守按**总量身价比**定：我 > 敌×1.25 才推，跌破 1.0 就不推，敌 > 我×0.9 就守 | `decide.ts` 的三条 return | 兵少了就不打。**天生不会用一支部队去换城血**——打不动就退，退了更攒不回 1.25 |
| 2 | 队伍的 `want`（要几个人）**12 手内不缩** | `ai-v4.ts` 的 `squadMemo` | 在资产模型里对（防越打越小），在波次模型里反了：**每一批应该重算**，上一批打光了就该编新的 |
| 3 | 三个存量一个都没有：前线（能打到城的）/ 在途 / 产能 | —— | 有 `eta`（全队最慢几手到），但**只写进回放、不参与判断**；没有"前线空了没有"，就没有"要不要再来一波" |
| 4 | 分队只看"哪座城被威胁" | `constrain.ts` 的 `planMains` | 那是守。没有"往哪条线投"的概念；P5 文档写过"只有一支部队 + 几个特殊队" |

结论：**"兵是消耗品"这句话在当前代码里无法表达**。不是缺一条规则，是缺两个对象（线、波）
和一个账本（换到了什么）。

## 2. 模型：线、波、三存量、一本账

### 2.1 两个对象

| 对象 | 定义 | 现在的状态 |
|---|---|---|
| **线** | 通往一座敌城的进攻通道，**可以反复用**。有身份（往哪座城、开过几波、上一波换到什么、现在还通不通），**不存路径** | 不存在，只有"这一手打哪座城" |
| **波** | **一批人**：某一手（或相邻几手）编成、一起去这座城的兵。有出生手、人数、出发手、到货数 | 不存在"批"，只有整支主队 |

**同一条线上允许同时有多波在途**（前面在打、后面在造、中间在路上）——这是用户的模型，也是判据的基础（§3.3）。
一条线只在"受阻且换线"时才废弃；线本身没有终点，"打下城"或"放弃这座城"才结束。

### 2.2 三存量

| 量 | 含义 | 谁算 | 现在的状态 |
|---|---|---|---|
| `front` | **能打到目标城的人**（到任一城格 ≤ 自己的射程） | 服务层 | W1 已有 |
| `road` | **沿这条线在途的人**（已属于这条线、还没进前线） | 服务层 | W1 已有（数总数） |
| `make` | **这一回合能造出几个**（空产兵格 × 钱够不够） | 服务层 | W1 已有 |

三个量都**不分波**：它们是"这条线现在的状态"。波是流量的单位，存量按线算。

### 2.3 一本账（W3 之前必须按线拆开）

`gain / loss` = 这一手被击杀的敌方单位造价 / 我方被击杀单位造价（按造价，不按残血）。

**现在只有一本总账**（全图所有战线混在一起）。W2 只有一条线时够用；
**W3 一开第二条线，总账会把两条线的功过混在一起，"哪条线亏了"就查不出来**——
所以开第二条线之前，账必须按线分（按单位位置归属到最近的线，归属规则和同一处写一次）。
这是 §6 W1.5 的第 2 条。

**线的身份**（记忆里，和 D5 的 `eraPlan` 同一个形状）：这条线是往哪座城、开到第几波、
上一波换到了什么、现在还通不通。**不记路径**——敌人一动路径就过时；只要"通行能力"
（几步、最窄几格宽、敌人能不能半路切断），路线每手用距离场现算。

## 3. "一波"的定义（2026-11-26 第二版，用户拍板）

> **一波 = 一批人。某一手编成、一起去这座城的一批兵。**
>
> 它不是"一段战斗"，**也不是"一支队的一次行军"**。它是货，不是车。

第一版把它定义成"从出发到第一次开火"，那实际上是"整支主队的一次行军"，
和用户心里的东西不一样：代码里后来造的兵直接并进主队，被记成同一波的"到货"，
所以**一批一批往上送这件事，代码里根本没被记下来**（§6 W1.5 第 1 条）。

### 3.1 波的边界

- **出生**：这一批人第一次被编成、领到这座城的那一手。
- **出发**：这一批在"该走了"的那一手开拔（判据见 §3.3，不是"够了就走"）。
- **结束**（三种出口，取先到的）：
  1. **到齐**：活着的人全部进入前线（能打到城 / 已接火）→ 这批人并进前线存量，波结束；
  2. **打光**：这一批人全灭 → 按"未到达"记，记人数与金币；
  3. **撤回**：被调走 / 线废弃。
- **已经到城下的人不再属于任何一波**。前线是存量，波只是"投送的单位"。

### 3.2 由此得到的关键事实

- **同一条线可以同时有多波在途**：一批在打、一批在路上、一批还在造。
  这是用户的原话（"前一波战死了，后一波能立刻接上"），也是判据的落点。
- **"一波花了多少手"不再是主指标**。士兵在路上和在城下是同时发生的，
  按波算时间会把两件事混在一起。主指标换成 **断档**（§3.3）。
- **阵亡不分波**。城下的伤亡属于交换账（§4），不属于投送成绩。
  所以"送到几手"和"换到多少钱"是两个账本，不能互相解释。

### 3.3 什么时候送下一波：流水线，不是等死光

用户 2026-11-26 指出：第一版只写了"受阻 → 减人 → 换线"（撤退逻辑），
**没写"什么时候投下一批"（补给逻辑）**。人的做法是流水线——不等前面死光，而是算下一批赶不赶得上。

落成两条可数的判断：

**① 断档**（这是新的主指标）

```
断档 = 前线人数 = 0 且 在路上人数 = 0
```

连续几手断档就叫一次断档。**它比"波次"诚实**：只要流水线在转，断档恒为 0；
一旦出现，说明该造的在造、该走的在走，中间还是断了一截。

**② 该编下一批的条件**

```
预计断档前能不能接上：
  前线人数 ÷ 每回合消耗  <  下一批到城下的回合数  +  造一批要的回合数
  →  现在就得编下一批
```

- **每回合消耗**：近 6 手平均每手死几个（交换账里已经有这个数，只差取出来）。
- **造一批要的回合数**：这一批的人数 ÷ 每回合能造几个（产能）。
- 两个数都是**已经量出来的量**，没有新系数。产能为 0 时这条判断自动变成"先投产能"，
  正好接上 W3 的"钱转产能"。

**为什么不用"等打光再送"**：那样永远慢一批——造兵要钱、走路要手，
等前线归零才开始，断档就已经发生了。用户的原话是"前一波战死了后一波能立刻在前线接上"，
"立刻"只能靠提前编。

### 3.4 关于「是否交战」：不并 `planTactics`，统一底层事实（2026-11-26 讨论）

用户提醒：v4 里已经有一处"编队进入交战"的判断——`planTactics` 会打开编队的战术动作开关
（集火 + 为集火点挪一步）。要不要统一？

**结论：不拿那个开关当"交战状态"，但两边统一到同一个事实。**

- `planTactics` 打开回答的是「**值不值得全队打同一个目标**」——是**选择**，而且要求
  `≥2` 个有攻击力的兵。**单兵或两人的波次永远开不了**，拿它当"交战"会漏掉最需要看的那些波。
- 真正的**事实**是"谁能打到什么"。现在 `laneStats` 同时给：
  - `front`：到城 ≤ 自己的射程（能攻城）；
  - `engaged`：原地能打到某个敌兵（已接火）。
  **「进入交战」= `front + engaged > 0`**，两个都算——进城前先和守军接火是常态，
  只看 `front` 会把这段时间判成"还在路上"（用户指出的偏差）。
- 不把 `planTactics` 改成读这个事实：它多算了"走一步再打"和伤害门槛，那是它自己的判据；
  改它等于改行为。真要彻底统一，等 W2 把"能打到谁"抽成服务层一个函数，两边再一起读。

### 3.5 通过量怎么算：它不是几何量（2026-11-26 用户提问）

用户问得对：**代码里没有"路"这个对象**，那怎么算一条线的通过量？

**答案：不在路上量，在终点边界上量。** 通过量不是几何量，是**到货率**：

```
这一手有几个"新人"第一次进入前线（能打到城 或 已接火）
```

按人去重，所以它不会把"到达 / 伤亡 / 补人"混在一起——那正是"前线现在几个人"
这个数做不到的。

**它单独不能证明"通道窄"。** 队伍出发时本来就站得散，先到后到差好几手；
到货率 1.2/手 可能只是"人本来就在不同距离上"。所以要配两样一起看：

| 现象 | 含义 | 该做什么 |
|---|---|---|
| 到货 > 0 | 通道在工作 | 继续投 |
| 到货 = 0、在途 > 0（连续几手，记 `stuck`） | **堵**：路上有货过不来 | 换路线 / 减规模 / 修路（W4） |
| 到货 = 0、在途 = 0（连续几手） | **断档**：不是通道问题 | 提前编下一批（§3.3）或换线 |

`stuck` 是"连续几手到货为 0 而在途不为 0"，它把"人站得散"排除了——散的人也会陆续到，
只有真堵住才会连续 0 到货。它和 `断档` 是两件事：一个是有货过不来，一个是没货可过。

**真正的"容量"（几何）留给 W4**：最窄处几格宽 × 每格能过几个人。那才需要路形。
对"该不该再送一波"这个问题，到货率 + 断档已经够用。

## 4. 攻守判据：从"兵力比"换成"金币交换账"（用户 2026-11-26 定）

### 4.1 口径

每个单位有一个**金币成本**：`recruitPriceOf(s, owner, type).gold`（**按造价，不按残血**）。

一回合的交换账：

```
收益 gain = Σ 这一手被击杀的敌方单位的造价
损失 loss = Σ 这一手被击杀的我方单位的造价
```

**窗口 W = 6 手**（和 `DECIDE_HORIZON` 同尺度，滚动）。判据只有一条：

```
Σgain(窗口) ≥ Σloss(窗口)   →   进攻"赚"，可以继续 / 加码
Σgain(窗口) <  Σloss(窗口)   →   "亏" → 降这条线的预算 / 换线 / 转经济
```

允许**短期小亏**：因为只看窗口累计。长期大亏才动，这就是用户说的"不要被抖动带跑"。

### 4.2 三种窗口状态（必须分开，否则会卡死）

| 窗口里发生了什么 | 结论 | 为什么 |
|---|---|---|
| 有交换，且 Σgain ≥ Σloss | 赚 | 正常推进 |
| 有交换，且 Σgain < Σloss | 亏 | 降预算 / 换线 |
| **没有交换**（两边都没死人） | 看**城血**：掉了 ≥ 阈值 → 按赚；一点没掉 → **按"卡住"（stalled）** | 只砸墙不死人也是收益；两边都不动才是"受阻" |

**用户 2026-11-26 已确认这条**：窗口里两边都没死人、城血也没掉 → 判「卡住」，
**此路难通，降这条线的预算，准备开另一条线**。不然 `0 ≥ 0` 会把"僵住"判成"赚"，
部队会一直站着互相看着。

### 4.3 这条判据会带来什么（要说清楚）

- **便宜的兵换掉贵的兵 = 赚**。这正是用户要的口径，但也意味着 v4 会开始"用民兵换坦克"
  ——实际打不动就打不死，所以自然有别的原因拦住它（采购门槛）。
- **敌方也是钱**。堵住敌方出兵、拖垮敌方经济，在账本上都算"赚"，这会自然长出 P5 的袭扰。
- **"不进攻"也要有账**：不推的时候窗口是静止的（都是 0）。所以判据必须配一条"什么时候
  重新开始推"——用 §3.3 的接不上条件（前线撑不到下一批到）和 `make`（产能）一起说，
  不另立一条"产能超过一波成本"的门槛。

### 4.4 账要按线分（W3 的前置）

现在是一本**总账**：全图谁死了都记进同一笔。W2 只有一条线时没问题；
W3 一开第二条线，"两条线的功过"就混在一起了——一条线赚 500、另一条亏 800，总账看着只亏 300，
结果是**赚钱的那条被一起砍掉，亏钱的那条继续送**。

所以开第二条线之前必须做两件事（都只动观测，不动行为）：

1. 每一笔击杀**记上它发生的位置**，按"离哪条线最近"归属（同一条规则只写一次）；
2. 判据读的是**这条线自己的窗口**，不是全图窗口。

## 5. 钱往哪投：开几条线 = 产能 ÷ 每波成本

用户描述的阶梯：

> 一条线受阻 → 减少每支主力部队的兵力 → 经济继续投入 → 产能支持投送 2 支 → 两路进攻

落成三步**可数**的判断：

1. **受阻** = 窗口里 `stalled`（既无交换、也无城血进展）。
2. **减每波兵力** = 这条线的 `men`（一批多少人）减半，省下的人力和钱转进 `make`（投经济）。
3. **开第二条线** = `make × 期限 ≥ 两条线各自一波的成本`（除法，不是"兵多了就多派"）。

第 3 条是关键：**线数由产能决定，不由场上现有兵力决定**。现在的 v4 只会看"我场上几个兵"。

**要和 §3.3 分清**：这一节管的是"**开几条线**"（宏观，几天一次）；
§3.3 管的是"**这条线上什么时候再编一批**"（微观，几乎每手都在算）。
两件事都读 `make`，但一个是"够不够养一条新线"，一个是"来接不接得上"。
**不要合并成一个判断**——那会让"再开一路"和"补几个人"互相挤压，最后两边都不动。

## 6. W 系列（每步单独验收，先影子后接线）

### W1 影子模式（**✅ 2026-11-26 10:20 完成**，只打印，不改行为）

**做什么**：
- 服务层算出 `front / road / make`（三个数），和"这一波从出发到交战花了几手"。
- 记忆里记**交换账**（逐手差分）与**波次记录**（`startedTurn / men / arrivedTurn / lost`）。
- 每手打一行到 `V4_LANE_LOG`（或探针）：
  `[lane] T=7 front=3 road=4 make=2 · 波#2 出发T5 到T7 路上损2(130金) · 交换(T1..T6) 赚420/亏180`

> ⚠️ **按第二版的定义，W1 记的"波"名不副实**：它记的是"整支主队的一次行军"
> （`wave` 只有一个槽位，按城市 id 认，后来补的人被记成同一波的到货）。
> 数本身没错（到货率是准的），但**名字和定义错了**，W1.5 要正名。

**判据**：不接任何动作。`npm test` 21/21；34 题**逐字节零变化**（只多日志）。
**验收**：在 `S-000` / `S-001` / `S-002`（长局、有伤亡）上人工核对 3~5 行：
出发手数对不对、路上损失对不对、交换账和回放的击杀数对不对得上。

- **第二次读数（2026-11-26 10:30，加 `engaged` 之后；S 系列是综合题，只作参考）**：

  | 题 | 出发时人数（旧记法） | 出发 → 接火 | 20 手后的 `front` | 到货（人 / 均每手） | 交换（6 手窗口） |
  |---|---|---|---|---|---|
  | `S-000` | 10 人 | T1 → **T3**（1 人接火） | 涨到 7~8 | **7/10 · 1.4/手** | 赚 275 / **亏 0** |
  | `S-001` | 18 人 | T1 → **T5**（2 人接火） | **仍 0~2** | **12/18 · 1.3/手**（T19） | 赚 720 / **亏 720** |
  | `S-002` | 25 人 | T1 → **T5**（1 人接火） | **长期 0** | **6/25 · 1.2/手**（T11） | 赚 1000 / **亏 2600** |
  | `S-012` | 无波 | —— | —— | —— | 赚 750 / 亏 130 |

  到货率三道题都在 **1.2~1.4 人/手**——**差别不在"通道快慢"，在"送进来的人能不能站住"**：
  S-000 到 7 个、S-002 到 6 个却打不动。所以"堵"不是主要矛盾，
  **是"送到了也换不到东西"**（看交换账）。这条结论比"窄道慢"重要得多。

  四件立刻能看见的事：

### W3 ✅ 一批多少人（2026-11-26 12:45，**1 题变绿，0 题变红**）

   到货率（`arrivedIds / 有到货的手数`）× 期限。

   （用户 2026-11-26 指出；第一版写死 8，已删）。第一批本身就是那次测量。
   **下限**：至少凑得够打死一个守军（最厚守军的血 ÷ 我方单发）——
   不加这条会掉进死循环：到货率只数"第一次进前线的人"，越打不过 → 率越低 → 批越小，
   P-2-01 实测从 10 人缩到 1 人一批。
2. **约束层只派这一批**：按离城近取前 `men` 个，余下留家当预备队；前排死了自动补位。
   **已经在城下的人不许被分批挤出去**（够得着城的人无条件留在队里，上限只卡"后面补上来的"）
   ——否则 `men` 小于前排人数时，会有几个人被落下、原地不动。
3. **留多少看产能**：`men = min(总兵, max(能展开, 总兵 − 每回合能造几个 × 6))`。

### W3.6 编队生命周期归位（**在 W4 之前**，方案见 `PLAN-V4-PHASE3` §3）

一句话：编队现在是"约束层组队、没人负责撤编"，于是 `ready` 拿新队的目标人数去卡老兵
（全队 blocked）、决定一切换就被另一条分支顶掉（攻城后全消失）、关键格和守城的人
还会被静默剔出 `rest`（名册对不上）。v3 的做法是**有状态、有超时、有明确撤编条件、
缺口回传采购**——按它把这一层补齐，再谈路况。

**已落地**：第 1 步（状态 + 收拢期吸收 + 10 手超时）、第 2 步（名册只因人死而缩；
全灭 / 不足四成 / 无敌城才撤编）、第 3a 步（**打空转接管：整队保留，只换任务名**）、
第 3b 步（**整队召回守城**：`world.defensible` 判"挡不挡得住"，`marchTurns` 判"回不回得来"，
回不来的继续打原来的城）、第 3c 步（**决定层改成"每队一条任务"** `Decision.bandTasks`：
发展只改钱和后方，不再把正在攻城的队叫回家）。

**任务转换的边界**（3a 查清的事实）：执行层只认"任务名 + 目标城"（`squadOf` 按兵找队），
所以**换任务是改两个字段，拆队/重建完全没必要**。真正的限制在决定层——它一次只下一个
全局结论，说不出一队一条任务。因此：

- 目标城不变（打空 → 接管）：整队转，成本最低；
- 目标城变（老家被压 → 守）：方向相反（攻城在城外、守城在城里），要"整队召回"，
  且必须有**距离门槛**——队伍太远就不回（用户 2026-11-26：照条件切换，不是无条件切）；
- 一队守、一队继续打：**已经能表达了**（3c 的 `Decision.bandTasks`）。现在只有"回防"这一处用；
  多线（同时往两座城各出一条线）等有经济的长局再用——那时"预算"才有落点。

## 8. 不做 / 风险

- **不许把宏观决策变成"逐动作打分"**（v3 的死法）。交换账是**一层的一句结论**
  （赚 / 亏 / 卡住），不是每个兵一个分数，也不许拿它去逐动作比较。

  **但战术层的局部打分是允许的，也是必要的**（用户 2026-11-26 指出）：
  一支队接上敌人之后，宏观决策管不了微观战场，这时"打谁、要不要为它挪一步"就该由局部算。
  边界是三条，不是"禁止打分"：
  1. **只在开关打开时**（约束层判定"这一手值得全队办同一个目标"），关着就和没有一样；
  2. **不许自己挑目标**，目标只能来自约束层；
  3. **不许反过来影响宏观**：战术层算出来的东西不能改写"这条线赚不赚"，
     那本账只认金币与城血。
  现有 `planTactics` 就是按这三条写的（≥2 人能打到同一个、打不死也要打掉一半、
  只有本来没仗可打的人才被拉去补一刀）。
- **不给"线"存路径**。只存通行能力（步数、宽度、能不能被切断），路线每手现算。
- **不用推进格数当收益**。推进会被地形骗（绕路也是推进）；收益只认金币与城血。
- **不加"士气/撤退"这类新状态**，除非影子数据显示必须。
- **风险**：W2 会翻一批题；如果出现"大批红 + 归因不清"，停下回 W1 补数据，
  不要靠调窗口长度去凑红绿。
