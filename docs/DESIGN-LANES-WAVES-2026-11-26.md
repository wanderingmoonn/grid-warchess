# 兵线与波次：v4 怎么像人一样投送兵力

> 2026-11-26。用户提出：**v4 的主语是"这支队伍"，人的主语是"这条线路"**。
> 主力部队是**消耗品**，沿一条线一波一波地送上去；一条线受阻就减每波兵力、把钱转产能，
> 直到产能撑得起两条线。本文把这个模型写成可落地的形状，并给出第一步（影子模式）。
> 阶段二排序随之调整：P4 / P5 并入本文的 W 系列（见 `PLAN-V4-PHASE2` §3 的 W 节）。

---

## 0. 一句话

**先让 v4 看见"线"和"波"，再谈这条路好不好走。**

现在的 v4 能算"这队人走到城下要几手"，但它心里的主语是一支**要活下来**的队伍；
人心里的是**一条能反复用的通道**，队伍只是通道上的一批货。

## 1. 为什么必须改主语（四条代码事实）

| # | 事实 | 在哪儿 | 为什么它是"资产口径" |
|---|---|---|---|
| 1 | 攻守按**总量身价比**定：我 > 敌×1.25 才推，跌破 1.0 就不推，敌 > 我×0.9 就守 | `decide.ts` 的三条 return | 兵少了就不打。**天生不会用一支部队去换城血**——打不动就退，退了更攒不回 1.25 |
| 2 | 队伍的 `want`（要几个人）**12 手内不缩** | `ai-v4.ts` 的 `squadMemo` | 在资产模型里对（防越打越小），在波次模型里反了：**每一波应该重算**，上一波打光了 |
| 3 | 三个存量一个都没有：前线（能打到城的）/ 在途 / 产能 | —— | 有 `eta`（全队最慢几手到），但**只写进回放、不参与判断**；没有"前线空了没有"，就没有"要不要再来一波" |
| 4 | 分队只看"哪座城被威胁" | `constrain.ts` 的 `planMains` | 那是守。没有"往哪条线投"的概念；P5 文档写过"只有一支部队 + 几个特殊队" |

结论：**"兵是消耗品"这句话在当前代码里无法表达**。不是缺一条规则，是缺两个对象（线、波）
和一个账本（换到了什么）。

## 2. 模型：三存量 + 一个账本 + 线的身份

| 量 | 含义 | 谁算 | 现在的状态 |
|---|---|---|---|
| `front` | **能打到目标城的人**（到任一城格 ≤ 自己的射程） | 服务层 | 没有 |
| `road` | **沿这条线在途的人**（主队里还没到射程的） | 服务层 | 有 `eta`，但没有计数 |
| `make` | **这一回合能造出几个**（空产兵格 × 钱够不够） | 服务层 | 分两处算过（`cityTiles`、`affordableCombat`），没有合成一个数 |
| `gain / loss` | **这波换到了什么**：敌方被击杀单位的造价 / 我方被击杀单位的造价 | 记忆（逐手差分） | 没有（引擎不报"击杀事件"） |

**线的身份**（记忆里，和 D5 的 `eraPlan` 同一个形状）：这条线是往哪座城、开到第几波、
上一波换到了什么、现在还通不通。**不记路径**——敌人一动路径就过时；只要"通行能力"
（几步、最窄几格宽、敌人能不能半路切断），路线每手用距离场现算。

## 3. "一波"的定义（用户 2026-11-26 定）

> **一波 = 一支进攻编队从出发，到它进入交战状态、开始战术动作为止。**

落成代码里的判定：

- **出发**：主队（`main`，目标敌城）从 `assemble` 变成 `march` / `siege` 的那一手。
  也就是现有 `ready` 第一次为真——**不新增条件**。
- **结束（这一波的交战时刻）**：这一波里**任何一个兵第一次执行 `ATTACK` / `SIEGE`** 的那一手。
- **中途全灭**：这一波的兵全死光 → 这一波按"未到达"记，`lost` 记人数与金币。
- 一支队在城下打完、又补人继续打，**不再算新的一波**（那是同一波的补充）；
  只有当它退回集结、或者被换掉之后重新开拔，才开新的一波。

为什么要这个边界：用户要量的是**投送**，不是战斗。一波的"成绩"是"几手送到、路上亏了多少"；
到了城下之后的消耗属于下一层（交换账），两者混在一起就归因不了。

---

### 3.1 关于「是否交战」：不并 `planTactics`，统一底层事实（2026-11-26 讨论）

用户提醒：v4 里已经有一处"编队进入交战"的判断——`planTactics` 会打开编队的战术动作开关
（集火 + 为集火点挪一步）。要不要统一？

**结论：不拿那个开关当"交战状态"，但两边统一到同一个事实。**

- `planTactics` 打开回答的是「**值不值得全队打同一个目标**」——是**选择**，而且要求
  `≥2` 个有攻击力的兵。**单兵或两人的波次永远开不了**，拿它当"交战"会漏掉最需要看的那些波。
- 真正的**事实**是"谁能打到什么"。现在 `laneStats` 同时给：
  - `front`：到城 ≤ 自己的射程（能攻城）；
  - `engaged`：原地能打到某个敌兵（已接火）。
  **「进入交战」= `front + engaged > 0`**，两个都算——进城前先和守军接火是常态，
  只看 `front` 会把这段时间判成"还在路上"（用户指出的偏差）。
- 不把 `planTactics` 改成读这个事实：它多算了"走一步再打"和伤害门槛，那是它自己的判据；
  改它等于改行为。真要彻底统一，等 W2 把"能打到谁"抽成服务层一个函数，两边再一起读。

## 4. 攻守判据：从"兵力比"换成"金币交换账"（用户 2026-11-26 定）

### 4.1 口径

每个单位有一个**金币成本**：`recruitPriceOf(s, owner, type).gold`（**按造价，不按残血**）。

一回合的交换账：

```
收益 gain = Σ 这一手被击杀的敌方单位的造价
损失 loss = Σ 这一手被击杀的我方单位的造价
```

**窗口 W = 6 手**（和 `DECIDE_HORIZON` 同尺度，滚动）。判据只有一条：

```
Σgain(窗口) ≥ Σloss(窗口)   →   进攻"赚"，可以继续 / 加码
Σgain(窗口) <  Σloss(窗口)   →   "亏" → 降这条线的预算 / 换线 / 转经济
```

允许**短期小亏**：因为只看窗口累计。长期大亏才动，这就是用户说的"不要被抖动带跑"。

### 4.2 三种窗口状态（必须分开，否则会卡死）

| 窗口里发生了什么 | 结论 | 为什么 |
|---|---|---|
| 有交换，且 Σgain ≥ Σloss | 赚 | 正常推进 |
| 有交换，且 Σgain < Σloss | 亏 | 降预算 / 换线 |
| **没有交换**（两边都没死人） | 看**城血**：掉了 ≥ 阈值 → 按赚；一点没掉 → **按"卡住"（stalled）** | 只砸墙不死人也是收益；两边都不动才是"受阻" |

**用户 2026-11-26 已确认这条**：窗口里两边都没死人、城血也没掉 → 判「卡住」，
**此路难通，降这条线的预算，准备开另一条线**。不然 `0 ≥ 0` 会把"僵住"判成"赚"，
部队会一直站着互相看着。

### 4.3 这条判据会带来什么（要说清楚）

- **便宜的兵换掉贵的兵 = 赚**。这正是用户要的口径，但也意味着 v4 会开始"用民兵换坦克"
  ——实际打不动就打不死，所以自然有别的原因拦住它（采购门槛）。
- **敌方也是钱**。堵住敌方出兵、拖垮敌方经济，在账本上都算"赚"，这会自然长出 P5 的袭扰。
- **"不进攻"也要有账**：不推的时候窗口是静止的（都是 0）。所以判据必须配一条"什么时候
  重新开始推"——建议用 `make`（产能）恢复到"一波的成本"以上作为重新开线条件。

## 5. 钱往哪投：开几条线 = 产能 ÷ 每波成本

用户描述的阶梯：

> 一条线受阻 → 减少每支主力部队的兵力 → 经济继续投入 → 产能支持投送 2 支 → 两路进攻

落成三步**可数**的判断：

1. **受阻** = 窗口里 `stalled`（既无交换、也无城血进展）。
2. **减每波兵力** = 这条线的 `men` 减半，省下的人力和钱转进 `make`（投经济）。
3. **开第二条线** = `make × 期限 ≥ 两条线各自一波的成本`（除法，不是"兵多了就多派"）。

第 3 条是关键：**线数由产能决定，不由场上现有兵力决定**。现在的 v4 只会看"我场上几个兵"。

## 8. 不做 / 风险

- **不把交换账做成"逐动作评分"**（v3 的死法）。它是**一层的一句结论**（赚/亏/卡住），
  不是每个兵一个分数。
- **不给"线"存路径**。只存通行能力（步数、宽度、能不能被切断），路线每手现算。
- **不用推进格数当收益**。推进会被地形骗（绕路也是推进）；收益只认金币与城血。
- **不加"士气/撤退"这类新状态**，除非影子数据显示必须。
- **风险**：W2 会翻一批题；如果出现"大批红 + 归因不清"，停下回 W1 补数据，
  不要靠调窗口长度去凑红绿。
