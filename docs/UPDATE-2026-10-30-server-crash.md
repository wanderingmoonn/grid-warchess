# 线上崩溃：一个畸形 URL 打死了整个服务

> 现象：游戏突然登不进去，没有任何征兆，重启就好；过一阵又崩。这一批修掉根因，
> 顺手把两处"让登录变慢"的实现改掉。

## 一、根因：一个 `/%` 就能让进程退出

线上跑的是 `scripts/serve-static.mjs`（托管构建产物的静态服务器）。它在请求处理器里直接解 URL：

```js
let clean = decodeURIComponent(urlPath.split('?')[0] ?? '/');
```

`decodeURIComponent` 遇到不完整的百分号编码会抛 `URIError`：

```
curl "http://host/%"
URIError: URI malformed
    at resolvePath (serve-static.mjs:55)
    at Server.<anonymous> (serve-static.mjs:119)
```

要命的是这个抛出位置：它在 `async` 的请求处理器里、`try` 之外。
Node 对 async handler 的 rejection 不做兜底，于是**整个进程退出**——
不是这个请求 500，是全服一起下线。

复现（本地，一行就够）：

```bash
PORT=3000 node scripts/serve-static.mjs &
curl "http://127.0.0.1:3000/%"     # → 进程消失，后续请求全部拒连
```

所以"随机崩、重启就好"就解释通了：任何爬虫、端口扫描器、或者用户手打半截地址
（`/%`、`/%E0%A4%A`、`/%ZZ`）都会踩到。这跟对局数据、玩家操作都没有关系，
所以从战报里查不出任何异常——这也是它一直没被定位的原因。

### 修法（四层，从里到外）

1. **就地吃掉解析错误**：`safeDecode()` 捕获 `URIError` 返回 `null`，调用方回 400。
2. **整个处理器兜底**：`handle(req,res).catch(err => fail(...))`，任何漏网异常只影响这一个请求。
3. **文件流用 `pipeline`**：裸 `createReadStream().pipe(res)` 的 `'error'` 事件没人接手，
   同样是能让进程退出的口子（构建中途换文件、客户端半路断开都会踩到）。
4. **进程级保险**：`uncaughtException` / `unhandledRejection` 打日志后继续服务；
   `clientError` 回 400 关连接。线上没有终端，崩溃前那行错误是唯一线索。

## 二、顺手修的两处"慢"

### 2.1 资源 404 被首页顶替

老逻辑是"文件不存在就给首页"（单页应用的回退）。但 `/assets/index-xxx.js` 这种
**资源**请求也走了这条，浏览器拿到一坨 HTML 当 JS 执行，控制台只剩一句语法错误，
真正的原因（这个文件没发上去）被盖掉。现在带扩展名的路径老实回 404，
只有页面导航才回退到首页。

### 2.2 每次请求都同步压一遍主包

`gzipSync` 是同步的，压在事件循环上。主包 468KB，压一次几十到几百毫秒，
这段时间整个进程什么都干不了——包括 `/__health`。线上 CPU 很薄，
一个人开页面就会把别人的请求一起拖住。

现在按 `size-mtime` 键缓存压缩结果（产物带内容哈希，重建后 mtime 也变，不会发旧内容），
第二次起直接发字节，零 CPU。

另外把 `keepAliveTimeout` 从 Node 默认的 5 秒抬到 65 秒：服务端要比前置代理晚关连接，
否则请求会撞在正在关闭的 socket 上，等代理超时重试。

## 三、回归测试

新增 `scripts/smoke-serve.ts`（`npm run test:serve`，已接进 `npm test`），10 条，
守的全是这类**线上事故**而不是功能：

| 用例 | 守什么 |
|---|---|
| 畸形百分号编码回 400，进程不退出 | 这次的根因本身 |
| 路径穿越被挡住 | `../` 与 `..%2f` 都要 400 |
| 缺资源 404 / 缺页面回首页 | 两种"没有"不能混为一谈 |
| HEAD 与 405 | 只服务读取 |
| 带 hash 产物可长缓存、index.html 必须回源 | 否则更新发不出去 |
| gzip 解出来是原文，连发两次一致 | 缓存不能发旧内容 |
| 连接空闲 6 秒后还能复用 | 服务端不能比代理先关 |
| 30 个并发之后仍然健康 | 一个请求打不死服务 |

## 四、这次上线带上去什么

- 崩溃修复 + 上述四层兜底；
- 空军扩展（18 种飞机、6 条能力、航母甲板接口）与规则书新分册 `manual-pack-air.html`；
- 构建产物 `index-Cwg3V0JE.js`（430KB / gzip 163KB），首屏 3 个请求。

部署后用 `/%` 连打 5 次：全部 400，之后 `/__health` 与首页仍然 200——
崩溃向量已被挡住。

## 五、还剩下的问题（不在代码里）

线上延迟分布不均：暖着的时候 0.5 秒，偶尔 5~10 秒，**连 `/__health` 这种
一个字节都不读的路径也一样**。这一条不像代码问题——慢的不是文件，是请求到达沙箱
那一段（`ttfb` 就等于 `total`，TLS 握手只占 0.13 秒）。

代码这边能做的两件事（少一次压缩、连接晚关）已经做了；剩下的属于沙箱侧
冷启动/调度，需要在平台层面看。
