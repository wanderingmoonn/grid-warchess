# 2026-10-29 · 城市纵深改成"两侧共用一组数"

上一批把两侧的纵深钉成了同一个值（四座城纵深完全相同），代价是横河图上四座城固定落在两行，
纵向的随机性彻底没了。这一批把它换成**同一组数**：两座城能错开一行，但两个半区拿到的
多重集逐格相同——不是"统计上差不多"，是每一张图都相等。

顺带修掉两条由它暴露出来的真问题，和两条测试尺子的问题。

---

## 1. `planCities`：纵深从"一个数"改成"一组数"

**以前**（上一批）：

```ts
const placeAt = (side, taken) => { const a = side === 0 ? alongLo + pad : alongHi - pad; ... }
```

四座城全落在 `pad` 上。公平了，但同一侧的两座城永远并排——横河图上整张图只有两行有城，
玩家一眼能看出"这是生成的"。

**现在**：

```ts
const depth: [number, number] = [pad, pad > 0 && rng() < 0.5 ? pad - 1 : pad];
const placeAt = (side: 0 | 1, d: number, taken: Pos[]): Pos | null => {
  const a = side === 0 ? alongLo + d : alongHi - d;
  ...
};
```

三处取舍，都是为"公平"服务的：

- **第一个钉死 `pad`**：这样无论错不错开，**最近的那一对城**始终在 `pad` 上，
  目标间距不会因为错落被动变宽。
- **第二个只退一格**：`pad` 就是"两军刚好隔 target"的位置，再退两格就不像同一张图上的对局了。
- **两侧共用同一组数**：所谓"上下等距"就是两侧到各自底线的距离分布一样，而"分布一样"
  最省事的写法就是同一组数——远侧不是另抽一次，是把这组调个顺序用。

第三点在**对角布局**上还得多写一行：对角时 A 拿 `side0[0] + side1[0]`、B 拿 `side0[1] + side1[1]`，
如果两侧照抄同一个顺序，A 会吃下两个"深"的、B 两个"浅"的——那是新的不公平。所以对侧用 `depth[1 - k]`。

实测（各 200 张，量"城到己方底线空了几格"）：

| 棋盘 | 上一批（全是 `pad`） | 现在（多重集） | 同一侧两座城错开 |
|---|---|---|---|
| 16×16 | 2.27 / 2.27 | 2.07 / 2.07 | 71/200 |
| 20×20 | 3.22 / 3.22 | 3.03 / 3.03 | 81/200 |
| 32×32 | 6.19 / 6.19 | 6.03 / 6.03 | 92/200 |

均值降了 0.2，就是"退一格"那一半概率的期望；两侧永远相等。
小图上 `target` 可能吃满纵深、`pad` 退化成 0，那就不存在"退一格"，城回到同一行——
这是约束下的唯一解，不是没生效。

## 2. 天堑图的城门口：不留徒涉口子

**以前**：城郊那圈水，`shallowOk` 时一律填成浅滩：

```ts
for (const t of ring.slice(2)) put(c, t.x, t.y, c.shallowOk ? 'shallow' : 'plain');
```

"无渡口河"讲究"过河只能造桥"，而城边正是最要命的位置——留一格能徒涉的浅滩，
等于在城门口架了一座不用造的桥。

**现在**：这张图上河身那几格保持深水，其余城郊的水直接填平地：

```ts
for (const t of ring.slice(2)) {
  if (fordless && riverCells.has(t.y * c.w + t.x)) continue; // 河身保持深水
  put(c, t.x, t.y, c.shallowOk && !fordless ? 'shallow' : 'plain');
}
```

普通地图（含勾了「地形高差」的）不变：城门口照旧是浅滩，船能停、陆军能涉水出城。

发现路径：新纵深让河重新走了一遍，`river-h#77` 出现一格浅滩在 `(4,18)`，紧贴 A 城 `(2,19)`，
被「过河的口子是浅滩，不是一段平原」抓住。

## 3. 两条测试尺子（不是放宽，是原来那把量错了地方）

**「等高线：高山底下都得有台地托着」**：`open#1234` 报 `(11,6)` 有一格高山没有高邻居。
探针一查，四邻全是水。`height-terrain` 的补山脚那一趟是**故意**不跨水的
（"隔着一条河的对岸不该被算成这座山的山脚"），所以湖心一块石头本来就是孤零零的——
那不是缺山脚，是它确实站在水里。判据补一个 `land > 0`：只有**陆地**上的高山才要求有台地托着。

**「AI 会主动离开基地推进战线」**：改成多重集之后，B 的起始部队落点变了，
AI 这一局挑的目标城换成了另一座，而尺子量的是 `citiesOf('A')[0]`——
于是"AI 集中兵力打另一座城"被读成了"十回合原地不动"。

探针数据（十回合，同一张图）：`MOVE` 每回合 4~8 步、`ATTACK`/`SIEGE` 共 23 次，
B 的战斗单位从第 3 行推到第 8 行。不是龟缩，是尺子钉错了城。
改成"离**最近那座**敌城还有多远"，这才是"敢不敢往前压"。

改完做了变异验证：把 AI 的移动评分乘 0（回到这条测试当初防的那个 bug），
这条连同另外 7 条一起变红；把纵深改回 `[pad, pad]`，新加的"错开"断言变红；
把远侧的 `alongHi - d` 改成 `alongHi - d - 1`，多重集/均值断言变红。

**「状态能改攻击力」**：`(4,3)` 在新图上正好压在河身上（城市挪位后河道跟着重走），
用例要测的是"状态怎么改数值"，不是"水里能不能站人"，所以先 `clearArea` 铲平这一小片。
