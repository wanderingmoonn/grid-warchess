## 零、为什么这件事现在能做

先说结论：**编辑器不需要改引擎。** 关卡在代码里本来就是一份纯数据，而"读一份来路不明的关卡数据"
这件事，`createMatch` 早就在做了。

| 已经有的 | 在哪 | 对编辑器意味着什么 |
|---|---|---|
| 关卡是纯数据 + 一个统一校验入口 | `src/core/level.ts` 的 `LevelDef` / `validateLevel(raw)` | 编辑器只要产出"这个函数能吃的 JSON"就行，不用碰规则 |
| 关卡整包快照进存档 | `setup.ts` 的 `createMatch` | 编辑器改关卡不会污染老存档，也不需要迁移 |
| 地图是字符画 + 文本互转 | `fixed-maps.ts` 的 `validateFixedMap` / `mapToText` / `parseMapFile` | 画布和导入导出都有现成的地基 |
| 上帝模式已有地形刷子 | `ui/god-panel.ts`、`core/sandbox.ts` | 笔刷语义、货架筛选可以直接借 |
| 自定义兵种已走通全套 | `core/customUnits.ts` + `ui/unit-editor.ts` | "localStorage + 导入导出 + 编辑界面"这个模式照抄一遍即可 |
| 玩家地图云库已有先例 | `net/maps.ts` | 以后要云端分享关卡，表结构和审核口径都有参考 |

所以这不是"从零写一个大系统"，是**给一份已经能用的数据配一个不写代码的入口**。

一句话记住：**编辑器 = 关卡数据的图形界面 + 本机存储 + 试玩闭环。**
一旦发现"某件事必须改引擎才能表达"，那不是编辑器批次该干的活，先记成"引擎缺口"单独做。

## 一、四条原则

### 1. 只有一种格式：`validateLevel` 能吃的 JSON

编辑器不许发明第二种格式，也不许"先存草稿、保存时再转一次"。
存下来的就是能直接喂给 `createMatch` 的对象，导出、分享、云端上传全是同一份。
多一种格式就多一个"两边对不上"的 bug，而这个 bug 只在玩家那里出现。

### 2. 玩家数据永远不进代码

`LEVELS` 是内置关卡的数组，探针 26 段和 `npm run test` 都直接读它。
玩家做的关卡**另开一个注册表**（照 `fixed-maps.ts` 的 `userMaps` 做法），
`levelById` 先查内置再查用户。谁往 `LEVELS` 里 push，谁就是在让测试变得不可重复。

### 3. 每一批都要能"真造出一张关"

不做只有按钮没有产出的功能。每一批结束时，都要能用这一批的东西做出**一张以前做不出来的关**，
哪怕很丑。这和上一份计划的"每批配一关"是同一条经验：机制对不对，只有真造一张才知道。

### 4. 草稿和成品分开存

编辑器的中间状态（当前选中哪一格、抽屉开在哪、撤销栈）**不许写进关卡对象**。
原因很实在：`validateLevel` 会静默忽略未知字段，所以多出来的字段不会报错，
只会跟着存档、房间、分享链接一路走，而且没人知道它在那儿。

| E2 | 地图画布 | 不再需要"开上帝模式刷图，再复制文本粘进代码" | 用鼠标画完直接存 | 中 | 中 |
| E3 | 摆兵面板 | 部署和刷兵点不再靠数坐标 | 点格子放兵，放不下会当场变红 | 中 | 中 |
| E4 | 事件编辑器 | 事件不再只能写代码，这是唯一的真难点 | "第 9 次行动炸桥"能点出来 | **大** | **高** |
| E5 | 试玩闭环 + AI 自打 | 改完不知道有没有生效、要打几局才知道 | 改完一键试玩，回来接着改 | 中 | 中 |
| E6 | 关卡管理 + 分享 | 关卡多了会乱；想给别人玩 | 列表、复制、导出文件、云端分享 | 中 | 中（云端另算） |
| **F1** | **无城对战**（**引擎批，不属这条线**） | "没有城"在引擎里等于"立刻出局" | 双方或一方无城，靠初始兵打一场 | **大** | **高（动地基）** |

"小"≈ 批次 0 的一半，"中"≈ 批次 2/6 那个量级，"大"≈ 批次 3+4 加起来。
E4 单独标大，是因为它本质上是一门小语言，不是一堆输入框。
**F1 单独一条线**，见第八节——它改的是"出局"这个所有对局共用的地基，
混进编辑器批次会让"出问题分不清是谁的错"。

## 三、每一批展开

### 批次 E0：用户关卡注册表 + 草稿箱（不动任何界面）

**要解决的问题**

现在关卡写死在 `level.ts` 的 `LEVELS` 数组里，`allLevels()` / `playableLevels()` / `levelById()`
三个函数都直接读它。玩家做的关没有地方待——这是编辑器一切功能的前提，
也是唯一一处"做晚了要返工"的地方（和上一份计划的"关卡快照"同理）。

**做什么**

- 新增 `src/core/userLevels.ts`，照 `customUnits.ts` 的结构：
  - `KEY = 'warchess:user-levels:v1'`，存 `{ v: 1, items: [{ level, updatedAt }] }`
    ——数组天然带"最近改过的排前面"，比给 `LevelDef` 加 `updatedAt` 字段好；
    加了也会被 `validateLevel` 丢掉（它只拷认识的字段）；
  - `loadUserLevels()` / `saveUserLevel()` / `deleteUserLevel()` / `exportLevelText()`
    / `parseLevelText()` / `cloneAsUserLevel()`；
  - 内存注册表 + 一个 `registerLevelSource(fn)` 挂到 `level.ts`（见下）——
    **不直接改 `LEVELS`**，也不让 `level.ts` 反过来 import 用户关卡（那是循环依赖）。
- 改 `level.ts` 那三个查询函数：`allLevels()` 把外部来源拼在内置之后，
  `levelById()` 先查内置再查外部。**改这三处就够了**，别处不许直接读 `LEVELS`。
- 草稿箱单独一个 key（`warchess:level-drafts:v1`），存"还没校验通过的半成品 JSON 文本"，
  和成品完全分开。理由见原则 4。
- id 用 `user:<时间戳>-<随机>`，不用行号。改名**不改 id**——存档和日后"这张关更新了"
  都靠 id 对账，id 一变就成了另一张关。
- 保存时 `version` 自增（目前没人消费，但以后"这个存档用的是第几版"要用，便宜就先留着）。
- 草稿箱单独一个 key：`warchess:level-drafts:v1`，存"还没校验通过的半成品"。

**成果**

不需要界面。你知道"游戏能装玩家关卡"这件事成立了，后面每一批都是在这个容器里添东西。

**验收**

- 探针里塞一张用户关卡：能被 `levelById` 找到、能开局、能存能读、能从复盘重走；
- 把这张用户关卡删掉，再读之前存的存档：**照样能开**（跑的是快照），只警告不丢档；
- `npm run probe:level` 26 段全绿（内置关卡一条都没被影响）。

**这一批不碰**：任何界面。没有入口，全靠探针验。

**✅ 已完成（2026-11-16）**

- `src/core/userLevels.ts`（新）：`{ v: 1, items: [{ level, updatedAt }] }` 存 localStorage，
  内存一份镜像；`saveUserLevel` 先过 `validateLevel` 再存（存的是深拷贝），版本号自增；
  草稿箱另存文本。
- `level.ts`：加 `registerLevelSource(fn)`，`allLevels()` / `levelById()` 会拼上外部来源。
  **没有反向 import**——`userLevels.ts` 要 `validateLevel`，反过来引就是循环依赖。
- 三处保护，都是探针钉着的：
  1. **内置 id 不许被占用**（`saveUserLevel` 直接拒），否则用户表里会留一份永远查不到的
     "假冒孤城"，作者会一直以为自己改的是它；
  2. **同 id 只留一份**，版本号 +1；
  3. `levelById` **内置优先**，玩家的关顶不掉官方关。
- 顺手修的一个自身 bug：`loadUserLevels()` 原来在"没有 localStorage"时会把内存表清空
  （探针里表现为"刚存的关没了"）。改成"没有磁盘就什么都不做"。

**实际遇到的问题**

- 一开始想用 `{ [id]: LevelDef }` 存，后来改成数组：顺序天然是"最近改的在前"，
  不用给 `LevelDef` 加 `updatedAt`（加了也会被 `validateLevel` 丢掉，它只拷认识的字段）。
- **探针能在 node 里跑，靠的是"没有 localStorage 就退化成纯内存"**。代价是
  "真的写到磁盘"这条路只能在浏览器里手验——写进了下面的固定动作第 3 条。

**坑**

- `save.ts` 的 `loadMatch` 用 `levelById(snap.id)` 找"现在的版本"做对比，找不到就跳过——
  删关卡这条路已经安全了，**别顺手改成"找不到就当存档无效"**（上一份计划里踩过，代价是
  「继续上一局」和配置记忆一起没了）。
- localStorage 在隐私模式下写不进去。照 `customUnits.ts` 的做法吞掉异常，
  但要在界面上说一句"这次没存住"，不然玩家以为存了。

### 批次 E1：校验收口 + 导入导出 + 另存为（第一批"能用"的东西）

**要解决的问题**

三个真实的痛点：

1. 关卡校验失败会**静默回落成随机地图**（`createMatch` 里 `level` 变 null），
   玩家看到的是"点了孤城进来是张随机图"，而真实错因在某个字段上。
2. 有些错**引擎根本查不了**：兵种在不在这一局，要等建局拿到兵种表才知道。
   `spawn` 写个 `knight`（铁器兵放青铜局）会被静默跳过——作者永远不知道。
3. 想改现成的三张关，现在只能去改代码。

**做什么**

- 新增 `src/core/level-lint.ts`：补一层"引擎查不了、但编辑器必须拦"的检查。
  - 事件/部署里的兵种 id 是否存在（全局兵种目录 + `level.units`）——**不存在才是错**；
    时代的差异只报警告："这是第 2 时代的兵，本关开局青铜，玩家造不出来，只能靠事件刷"。
    （2026-11-16 实测：默认配置下 `unitTypes` 就是全部兵种，所以青铜局刷 `knight`
    **是能成功的**。`STATUS` 坑 4 里"会被静默跳过"说的是"id 不存在 / 被 `enabledUnits`
    关掉 / 来自没启用的扩展"这三种，不是时代。别照着那句写死规则。）
  - `spawn` / `deploy` 的落点是否能站人（水、山、城格、别人的兵）；
  - `assassinate` 的目标兵种是否 `summonedOnly`（不设的话对面一直补，条件永远不成立）；
  - `hidden` 的席位有没有对应的 `deploy` 事件（没有就永远不上场）；
  - 每个 `terrain` 动作有没有配 `say`（不配音玩家只会看到地形自己变了）。
  这些都给"人话 + 坐标"，不给英文码。
- 新增 `src/ui/level-editor.ts` 第一版，只有三块：
  1. 基本信息：id（只读）/ 名称 / 一句话简介；
  2. 一份 JSON 文本框：可以粘贴、可以复制；
  3. 问题列表：`validateLevel` 的错 + `lintLevel` 的警告，分组显示，**每条都带坐标**。
- "**另存为我的关卡**"：把内置关（含 `dev` 夹具）深拷贝一份、换 id 换名，直接进编辑器。
  这是新手的最低门槛——不用从空白开始，改孤城一个字就能得到自己的关。
- 选关列表加一个"我的关卡"分组（`setup-panel.ts`），空的时候给一句"还没有，去编辑器做一张"。
  **入口就放这里**（2026-11-16 定）：玩家在选关时就想做关，多一个菜单项反而找不到。
  每张"我的关卡"卡片上带一个"编辑"，点它进编辑器；再做一张就走分组末尾的"＋ 新建"。
  不做地址栏 `?editor=1` 的隐藏入口——那会变成"只有作者会用的功能"。
- 导出/导入：`exportLevel()` 返回格式化后的 JSON 字符串（带缩进，人能读），
  `importLevel(text)` 走 `validateLevel`，失败就把错误原样返回。

**成果**

**不写一行代码，能造出一张"孤城"级别的关**——地图还是靠上帝模式刷完复制文本，
但事件、部署、胜负都能靠粘 JSON 改出来。这一批结束时，编辑器已经有一半价值了。

**验收**

- 把孤城的 JSON 粘进去 → 校验通过 → 存成本机关卡 → 出现在选关列表 → 能开局 → 能打完；
- 故意写错三处（两兵同格、兵种不存在、事件 id 重复），问题列表要**同时**列出三条，
  不是改一处报一处；
- 另存为孤城副本 → 原版孤城一个字没变（这条最容易在"深拷贝没做干净"时出问题）；
- `npm run probe:level` + 新增的 `probe:level-editor` 全绿。

**这一批不碰**：画布、摆兵、事件表单。地图还是粘字符画。

**✅ 已完成（2026-11-16）**

- `src/core/level-lint.ts`（新）：第二层校验。能确定的报错（摆山上、摆进别人城、
  `hidden` 席位没人叫它上场、斩首目标是能造出来的兵种、事件改地形改成桥/城），
  不确定的只警告（兵种 id 找不到、时代比开局高、改地形没配播报）。
  **"能确定才报错"是硬规矩**——虚报一个错，作者会去改一个本来就对的地方。
- `src/ui/level-editor.ts`（新）：左边 JSON、右边问题列表；名称/简介两个输入框
  在失焦时写回 JSON；输入防抖 300ms 校验；草稿自动保存；关窗时若没存会问一句。
- 选关页（`setup-panel.ts`）：新增「我的关卡」分组 + 「新建关卡」+ 选中后的
  「编辑这张关 / 复制成我的关卡 / 删除」。**预制关卡必须先摘出去**
  （`playableLevels()` 现在会带上用户关卡，不摘就一张关出现两次）。
- `scripts/probe-level-editor.ts` + `npm run probe:level-editor`：9 段、40 项，
  已挂进 `npm test`；`scripts/smoke-dom.ts` 补了 5 条界面用例。

**实际遇到的问题**

1. **文档里的坑 4 是错的**。`STATUS` 写着"青铜开局写 `knight` 会被静默跳过"，
   实测**能刷出来**（默认 `enabledUnits` 是全部兵种）。差一点照着这条写死 lint 规则，
   那就会对每一张正常的关卡报假错。已回填到 `STATUS` 和 `GUIDE` 的口径里。
2. **"Unexpected end of JSON input" 没有位置**，翻成人话才好用：
   "JSON 语法错：内容没写完，括号或引号没有闭合。"
3. jsdom 里 `new Event(...)` 不是那个 window 的 Event，必须用 `new window.Event(...)`；
   `confirm` 也没实现，用例里得自己盖一个。
4. 保存后**不关窗**（作者多半还要接着改），面板等关闭时再刷新——
   中途回传会让 `config.level` 跟着半成品闪。

**坑**

- `validateLevel` **会静默忽略未知字段**。所以导入时不许把 JSON 里的多余字段悄悄留住，
  也不许自己往里加 UI 字段（见原则 4）。
- 错误列表的顺序是"先结构、后语义"，别按顺序只显示第一条。作者要一次看到能改的全部。
- 深拷贝用 `structuredClone`，不要 JSON 往返：`undefined` 字段会被往返吃掉，
  之后分不清"这个字段没写"和"写了空"。

### 批次 E2：地图画布

**要解决的问题**

现在画一张图要绕一大圈：开上帝模式 → 刷 → 打开地图面板 → 复制文本 → 粘进关卡对象的 `rows`。
而且上帝模式是**对局内**的界面，刷完不能撤销，也没法一边画一边看"城摆得对不对"。

**做什么**

- 新增 `src/ui/level-canvas.ts`：一张独立的网格画布，不依赖 `GameState`。
  - 笔刷：地形笔刷（单一地形）、矩形填充、擦除（回平原）、城位；
  - 撤销/重做（至少 20 步）；
  - 网格与坐标提示（鼠标停在格子上显示 `x,y`）；
  - 尺寸 8~40，改尺寸时问一句"会裁掉边缘，继续吗"。
- 地形选项**从 `TERRAIN_CHARS` 派生**，不要再手写一份列表——手写的那份一定会和引擎漂移。
- 城位：把 `map.citiesA/B` 和 `seats.cities.C/D` **合成一个"摆城"操作**。
  画布上只问"这是第几家的城"，写进哪两个字段由代码决定，作者不用知道。
  城默认占 2×2（`config.citySize` 可被「城郭」抬到 3），画布要按当前 `citySize` 落格子。
- 存盘时只产出 `rows` + 城坐标，走 `validateFixedMap`，不自己拼字符串。

**成果**

鼠标画完直接存。想验证画得对不对，把 `rows` 复制出来和手写的一模一样。

**验收**

- 画一张 14×14、竖河两列、桥面 2×2 的图 → 存 → 开局，河和桥和预览一致；
- 撤销 20 步再重做 20 步，地形一字不差；
- 城画在河上 / 画在山里，要当场提示，不能等校验时才说；
- 导出的文本和 `mapToText` 的输出格式一致（同一份地图两种路径，结果必须相同）。

**这一批不碰**：摆兵。画布只管地形和城。

**✅ 已完成（2026-11-16）**

- `src/ui/level-canvas.ts`（新）：独立弹窗画布。地形笔刷（14 种）、矩形框选一次刷满、
  城位笔刷（点一下摆一座、再点撤掉）、撤销/重做（40 步）、尺寸 8~40、坐标读数。
- **格子直接套 `.tile.t-<地形>`**，和棋盘共用同一份样式——画布上看到的就是进局后的样子。
  自己没有第二个配色表。
- 正方形格子靠容器的 `aspect-ratio: w / h` + 格子 `1fr` 均分。**这条和对局棋盘同源**：
  先算一格多大再反推外框（`fitBoardBox`），不要再拿一个边长当尺寸。
- 出图走 `validateFixedMap`，不自己拼校验；每家零城、城压在水上、城伸出边界都会被拦，
  拦下来时给的是人能读的理由（"城的范围里有一格是水域"），不是字段名。
- 应用后只改编辑器里的文本，**不自动保存**：底部写明"点「保存到我的关卡」才会存下来"，
  同时补一次草稿（代码改 `textarea.value` 不触发 input，不补就会丢）。

**实际遇到的问题**

1. `CHAR` 里 `shadow` 和 `shallow` **共用字符 `s`**，所以调色板里不会出现"阴影乱流"，
   `s` 一律按浅流解释。这是引擎既有的口径（`TERRAIN_CHARS` 也这么算），不是画布漏了。
2. 空间站的三个字符（`#` 虚空 / `_` 甲板 / `%` 破口）**不进调色板**：地表关卡用不上，
   放进去只会让人手滑画出一格虚空，然后整张图的通行判定变得莫名其妙。
3. 撤销栈最容易堆垃圾：点一下空地、点同一种地形，什么都没变却压了一条快照。
   现在整笔结束时如果 `dirty` 为假就把那条快照弹掉。
4. **实机反馈（2026-11-16，当天修）**：尺寸控件原本在画布**下面**，玩家没找到，
   以为"没法改地图大小"。已挪到画布上方、加「改尺寸」按钮。
   顺带定了个约束：**改小是破坏性的，所以不跟着输入实时改**——
   想把 12 改成 21，敲到 "2" 那一瞬间就缩到 8 且已经裁掉了。

**教训**：能用的功能和找得到的功能是两件事。控件放在滚动区外面、
或者放在一屏之外，等于没做。以后加面板先问一句"它进来第一眼看得见吗"。

**坑**

- **地图字符表 ≠ 事件可改地形表。** 地图 `rows` 能用 `=`（桥）、`#`（虚空）、`_`（甲板）、
  `%`（破口），但事件的 `terrain` 动作**只能改成 `LEVEL_TERRAINS`** 那一份（不含 city / void / bridge）。
  画布和事件表单要用两个不同的地形下拉，混用会做出"存得进去、跑起来被拒"的图。
- 地图自带的桥面在 `state.mapBridges` 里登记过，`syncBridges` 会跳过它们，不会自己塌。
  编辑器画 `=` 是安全的——但别顺手去做"地图桥的维护"，那是引擎的活。
- 城格在画布上是"占用 2×2"，但 `rows` 里就是普通 `.`。别想着在字符画里标城（那是文本地图
  文件的格式，关卡格式会直接拒掉）。

### 批次 E3：摆兵面板（部署 + 事件刷兵共用一套点选）

**要解决的问题**

`deploy` 和 `spawn` 现在是"写坐标"：`{ type: 'archer', x: 3, y: 7 }`。三个具体后果：

- 坐标落到水上/城格上会被**静默跳过**，战报里只留一句"摆不上去"，作者根本不会去看；
- 兵种只能写"本局存在的"，写错时代（青铜关写 `knight`）同样静默跳过；
- `hidden` 的席位必须靠 `deploy` 事件上场，忘了写就永远不来，而且"还剩几家"也不算它。

**做什么**

- 一个货架 + 一块画布的组合：
  - 货架 = **本局兵种表**（内置该 `startEra` 能造的 + `level.units` 的关卡独有兵种），
    不是全部兵种。这样从源头上就写不出"铁器兵放青铜局"。
  - 点格子放兵、点兵删掉、拖动换位。
  - 放不下（水、山、城、已有单位）当场标红并说明原因，不等到校验。
- 一套点选同时服务三个地方：开局部署、事件的 `spawn`、goal 的 `zone`（框选）。
  三处共用同一个"在图上选区域/选格子"的交互，别各写一套。
- 兵种面板给一行关键数值（血/移/射程/造价）——摆兵时最常算的就是这四个，
  而 `archer` 射程是 3 这件事，光看名字永远会算错。

**成果**

摆一个"3 兵守桥"的开局，从"数坐标 + 试错 + 看战报"变成"点三下"。

**验收**

- 摆一张孤城级别的开局（守方 3 兵 + 1 城，攻方 10 兵 + 2 塔），不看战报也能摆对；
- 故意往水上放一个兵，当场红，且说得清"水，陆军进不去"；
- 换 `startEra` 之后，货架跟着变（青铜看不到铁器兵）；
- 存盘后 `deploy` 的 JSON 和手写的一致。

**这一批不碰**：事件的其他动作（只做"选格子"这个交互）。

**补（2026-11-16，当天按用户要求放开限制）**

原来的货架按开局时代过滤（"青铜关不能摆铁器兵"），这在设计上是错的：
**空投一辆坦克本身就是一种关卡设计**。已改成全时代分组列出、都能选。
同时去掉 lint 的"跨时代"警告（保留"兵种 id 根本不存在"的警告，那才是真错）。

顺带补了一个漏掉的面板：**席位**（`ui/level-seats.ts`）——几家、谁托管、谁中途登场、
**每家城的时代等级**（`seats.cityEra`）、开局时代（`setup.startEra`）。
这几样框架一直支持，但编辑器没入口，等于只有会背字段名的人能用。

两个必须知道的实现细节：
1. 加到 3/4 家时会**自动给新席位塞一座城**。不这么做会死锁：没城 → 过不了校验 →
   打不开画布 → 而画布才是摆城的地方。
2. 席位面板显式写 `ai: []`（空数组＝全是真人），不留给面板去猜。空数组和"没写"
   在 `applyLevelToConfig` 里是两种意思。

**✅ 已完成（2026-11-16）**

- `src/ui/level-army.ts`（新）：席位页签 + 兵种货架 + 点格子摆兵。
  - 货架 = **本时代能造的**（`era <= startEra`）+ `level.units` 里这一关自带的，

  - 点格子放兵、点自己的兵撤掉；放不下当场拒绝并说明原因

**实际遇到的问题**

1. `npm run lint:boards` 会把 `unitAt(` 当成"默认地球那一格"的投影函数来拦。

2. 两个弹窗都有 `[data-foot]`，测试里 `doc.querySelector` 只能拿到编辑器那一层，

- 塔（`tower`）占格且不可通行，摆完要能看出来它挡路，否则作者会画出"自己把自己围死"的图。

### 批次 E4：事件编辑器（**真难点，拆两小步**）

> **详细方案已单独成文：`DESIGN-LEVEL-EVENT-FORM-2026-11-16.md`**（字段→控件对照表、
> 三个难点的解法、三层校验、E4a/E4b 分工、七个已知坑、三个待拍板的选择）。
> 下面这一节是概览，动手前先读那份。


**要解决的问题**

事件是关卡唯一"有逻辑"的部分，也是唯一必须写代码的部分：

```ts
{ id: 'blow', when: { kind: 'turn', at: 9 },
  do: [{ kind: 'say', text: '桥被炸断了。' },
       { kind: 'terrain', zone: { x0: 7, y0: 7, x1: 8, y1: 7 }, to: 'deep' }] }
```

对新手来说这里有五个坑：`turn` 是**行动序号**不是轮次、`zone` 是四个数、`id` 必须唯一、
动作要写成数组、`terrain` 不能改成桥或城。目标是让它变成一句话能读懂的表格。

**E4a：句子式表单**

- 一条事件 = "**当** … **就** …"：
  - 当：第 N 次行动 / 某家的某个兵死了 / 有单位走进某片区域；
  - 就：播报一句 / 刷一批兵 / 让某家登场 / 改某家的打法 / 改一片地形。
- 参数全下拉 + 点选，**没有自由文本**（除了播报文案）。这样写不出语法错。
- 区域一律框选，不让人手填 `x0/y0/x1/y1`。
- 一条事件可以有多个动作，按顺序执行——就是要写成列表，界面上就是"再加一条动作"。
- 地形下拉只给 `LEVEL_TERRAINS`（不含 city / void / bridge），并解释为什么不能改桥：
  桥面由桥单位维持，事件写的桥面下一步会被 `syncBridges` 改回水面。

**E4b：模板库 + 时间轴**

- 五个预设模板，一键插入再改数字：
  - **炸桥**：第 N 次行动 → 播报 + 把某片桥面改成深水；
  - **边缘援军**：第 N 次行动 → 播报 + 从地图边缘刷几个高机动兵；
  - **中途登场**：第 N 次行动 → 播报 + 让 `hidden` 的某家上场；
  - **换打法**：第 N 次行动 → 改某家电脑的打法（rush / boom / hold）；
  - **定时塌方**：第 N 次行动 → 播报 + 一片地形变化（可限定只改原本是水的格子）。
- 时间轴：把所有事件按 `at` 排成一条竖线（没有 `at` 的按触发类型分组），
  一眼能看出"第 9 次炸桥、第 14 次骑兵、第 15 次东西夹击"——现在这个信息只能靠读代码得到。
- 时间轴要同时显示**推演出来的效果**：某次行动后，哪些格子会变、会多出几个兵。
  不给预览的话，作者改一个数字完全不知道后果。

**成果**

**不写代码做出孤城那张事件表（5 组事件、12 次刷兵、1 次炸桥）**。这是整个编辑器里
唯一"以前完全做不到"的能力。

**验收**

- 用模板搭一张"第 6 次斥候、第 10 次炸桥、第 15 次两翼骑兵"的关，导出的 JSON
  和手写的孤城事件表结构一致；
- 故意做三件错事（同一 id 用两次、给不存在的席位刷兵、区域框在界外），
  每条都要在表单上就地报错，而不是存盘时才报；
- 时间轴上能看出每个动作的落点（哪几格、几个兵、哪一家）；
- 这一批做完，`GUIDE-LEVEL-AUTHORING.md` 要加一节"用编辑器做这些事"，和代码写法对照。

**这一批不碰**：新的触发类型、新的动作类型。**编辑器只暴露引擎已有的能力。**
想加"上一件事发生过"这种链式条件，是引擎批次的活（现在写在同一个 `do` 里也能达到同样效果）。

**坑**

（这一批的坑最多，做的时候逐条对）

1. **`turn` 是行动序号，不是轮。** 两家局一轮 = 两次行动。界面上不要写"第 9 回合"，
   要么写"第 9 次行动"，要么写"约第 5 轮（两家局）"——两者都写最好。
2. **援军必须从地图边缘进场。** 直接刷到玩家腹地，玩家的第一反应是"电脑耍赖"。
   模板里默认落点就取边缘，并在界面上写一句为什么。
3. **刷兵落点被占时会就近找位**（半径 1~2），但挤满了还是刷不出来。
   lint 要检查"这个区域够不够站"。
4. **`spawn` 的兵种必须在本局兵种表里**，否则静默跳过（见 E1 的 lint）。
5. **`assassinate` 的目标必须是造不出来的兵种**（`summonedOnly`），
   否则对面一直补，条件永远不成立。
6. **`terrain` 的三条兜底是引擎做的**：城格跳过、格上站着兵就挤到最近空地、必须播报。
   编辑器只管"提醒配一句 say"，别自己实现兜底。
7. **`enter` 想反复触发要写 `repeat: true`**，默认只触发一次。这个开关藏在表单里，
   要放在显眼位置。

### 批次 E5：试玩闭环 + AI 自打

**要解决的问题**

前四批做完，最大的问题是"改了不知道有没有生效、好不好玩"。
现在验证一张关的办法是两个：跑 `npm run probe:level`（只看机制通不通）、
或者手动开一局（要知道该看哪一步）。中间那段"打得起来吗、多久结束、会不会卡住"没人管。

**做什么**

- **一键试玩**：`createMatch({ ...DEFAULT_CONFIG, level })`，打完（或中途退出）能**回到编辑器**，
  草稿原样还在。这条比界面漂亮重要得多。
- **AI 自打 N 局**：把 `GUIDE-LEVEL-AUTHORING.md` 第 11 节那段脚本搬进浏览器，
  跑 3~5 个种子，输出三行：
  - 能不能跑完（有没有卡死、有没有赢家）；
  - 平均多少行动结束；
  - 谁赢得多（如果守方 5 局全输，说明这关难度已经失衡，不一定代表不好玩）。
- **进度条 + 可中断**：一局 AI 对 AI 可能几十秒，直接同步跑会把界面卡死。分批跑，
  每局之间让出主线程（或直接上 Worker）。
- **设计检查清单的半自动化**：把 `GUIDE` 第 14 节那五个问题里能算的算出来——
  比如"玩家有没有安全位"（有没有一格能打到人、又不在对方射程内）、
  "AI 有没有实际能走到玩家城的路"。算不出来的一律写"这条只能人玩才知道"，不要假装能验。

**成果**

改一版 → 自打 3 局 → 15 秒内知道"这关能不能跑完、大概多长"。
不用再去命令行敲脚本。

**验收**

- 试玩后返回，草稿、撤销栈、上次选中的标签页都还在；
- 孤城跑 3 个种子，都能跑完，且和命令行的结果一致（同一套 `aiNextAction`，不一致就是 bug）；
- 故意做一张"玩家必死"的关，自打结果要能说出来"守方 3 局全输"，不是静默出个"完成"；
- 自打过程中点"停止"，界面不卡、能立刻回到编辑器。

**这一批不碰**：用自打结果自动调难度。**AI 对 AI 的结果不能当"这关好玩"的依据**——
电脑不会集结兵力、不会保护关键单位、地形一变也不会重新选路。它只能回答"能不能跑完"。

**坑**

- 浏览器里跑 AI 对局是同步的，`applyAction` 一次几十毫秒，一局上千步。**必须让出主线程**，
  否则页面假死，玩家会以为崩了。
- 试玩用的 `config` 不要写进 `state.config` 的默认值，否则下次开局会带着上次的关卡。
- 自打用的种子要显示出来（"种子 21：守方赢，第 34 次行动"），否则复现不了。

### 批次 E6：关卡管理 + 分享

**要解决的问题**

到这一步玩家手里可能有十来张关：会乱（分不清哪张是哪张）、会丢（清了缓存就没了）、
想给别人玩（现在只能靠截图或者口述）。

**做什么**

- 关卡列表：按更新时间倒序，显示"名字 / 尺寸 / 几家 / 有无事件 / 最近改于"；
  操作：改名（不改 id）、复制一份、删除（二次确认，说清"删了不影响已存的存档"）、导出。
- 本地文件进出：导出成 `.json` 下载，从文件导入。**这是最小可用的分享方式**，先把这个做扎实。
- 云端（可选、可后置）：照 `net/maps.ts` 建 `warchess_levels` 表，
  `sql/` 下加建表脚本，字段 `name / author / data(jsonb) / listed`，
  读取策略同地图（公开可读、校验后入库、列表上限 60）。
  单条上限要重新定——关卡比地图大得多（400×400 字符的地图 + 事件表），
  先量一份真实关卡的大小再定，别照抄地图的 256KB。

**成果**

能备份、能分享、能理清楚自己做了多少张。

**验收**

- 导出 → 清 localStorage → 导入，关卡一字不差（包括事件顺序）；
- 删掉一张关，再打开一张引用它的老存档：能开、有警告、不崩；
- 云端上传一张坏关卡（改一个字母），被拒，且作者能看到错因。

**这一批不碰**：玩家之间的关卡订阅/评分/"热门关卡"。先解决"能给别人"。

**坑**

- 云端表一旦上线，**删不掉的历史数据会一直在**。上传口径要定死：只收 `validateLevel` 通过的，
  且只存数据不存任何可执行内容（和地图同一条原则）。
- 关卡快照会跟着联机房间和分享链接传。40×40 的图 + 一堆事件，体积明显比地图大，
  **上传之前先量一次真实的 payload 大小**，别到线上才发现房间建不起来。

## 四、五个里程碑

| 里程碑 | 包含 | 达成时能说什么 |
|---|---|---|
| **M1 能装** | E0 + E1 | "把一份 JSON 粘进去，游戏就认得这张关，还能开打" |
| **M2 能画** | E2 + E3 | "地图和兵力用鼠标摆，不用数坐标" |
| **M3 能编故事** | E4a + E4b | "炸桥、援军、中途登场，点几下就有" |
| **M4 能调** | E5 | "改完自打三局，知道这关能不能跑完" |
| **M5 能分享** | E6 | "能导出发给别人，也能从云端拿别人的关" |

**M1 单独成里程碑是有意的**：它没有画布、没有事件表单，看起来最不像"编辑器"，
但它是唯一一批"做完立刻就有新能力"的——你从"改代码"变成"改数据"。
如果中途要停，停在 M1 也不算白做。

**F1（无城对战）不在上表里**：它是一条独立的引擎线，建议夹在 M2 和 M4 之间，
由另一个人并行做（详见第八节）。它不阻塞编辑器，编辑器也不等它。

## 五、每批结束时的固定动作

照上一份计划的规矩，贴在墙上：

1. `npm test` 全绿（含 `probe:level` 26 段——内置三张关一条都不许被影响）；
2. 新增的 `probe:level-editor` 全绿；
3. 手动走一遍：做一张关 → 存 → 开一局 → 存盘 → 读回来 → 复盘；
4. 删掉这张用户关卡，再开刚才那个存档：能开、只警告、不崩；
5. 打开一个**老存档**（关卡模式之前存的）：行为一个字没变；
6. 在本文件对应批次后面补 `✅ 已完成（日期）` 和"实际遇到的问题"。

第 6 条别省。E4 大概率会比预计的久，久在哪只有当时的记录说得清。

## 六、明确不做（防止范围膨胀）

| 不做 | 理由 |
|---|---|
| 可视化节点图（拖线连逻辑） | 事件已经是"当…就…"，句子式表单够表达；节点图会让新手更晕 |
| 编辑器里加新规则 | 编辑器只暴露 `level.ts` 已有的能力，新能力单独走引擎批次 |
| 玩家关卡进内置列表 / 进 `LEVELS` | 测试会变得不可重复，且"官方关卡"和"我的关卡"混在一起 |
| 关卡内自由编辑 AI 权重 | 只给 `riskAversion` / `cohesion` / `appetite` 三个旋钮，其余是引擎的黑盒 |
| 多人同时编辑一张关 | 冲突合并的复杂度远超收益 |
| 一键发布到公开列表（免审核） | 一旦开放就是内容审核问题，先走"导出文件"和"审核后公开" |
| 关卡配音、过场、剧情分支 | 纯内容，不阻塞机制，也不验证任何东西 |
| 从编辑器直接改内置关卡 | 内置关是平衡基准和回归夹具，只允许"另存为副本" |

## 七、已定的三件事（2026-11-16）

原先是三个待定问题，你已经拍了，记在这儿免得以后又讨论一遍：

1. **编辑器入口放选关页**——「我的关卡」分组里"＋ 新建"和每张卡片上的"编辑"。
   不做主菜单项，也不做 `?editor=1` 的隐藏入口（隐藏入口等于"只有作者会用的功能"）。
2. **用户关卡允许进多人房间**——技术上是自动的（关卡快照跟着 `config` 走），
   先不动代码，**但要在 E6 之前量一次真实 payload**：一张 40×40 + 十几条事件的关，
   塞进房间创建请求里有多大。太大了再考虑"房间只传关卡 id"。
3. **第一张用编辑器做的关 = 孤城的变体**——换河宽、挪两波援军。
   这是最好的验收物：你对它最熟，改完立刻能判断"对不对"。

## 八、单开一批：无城对战（F1，引擎批）

> 这一批**不属于编辑器序列**（E0~E6），也不是"编辑器顺手能带出来的"。
> 有人提出"双方或一方没城，靠初始兵打一场"——这件事在现在的引擎里做不到，
> 而且卡在三个最要命的地方。

### 为什么现在做不到（都查过代码了）

| 卡点 | 现在是什么样 | 在哪 |
|---|---|---|
| 出局判定 | **没有城 = 立刻出局**。`isEliminated` 就是 `citiesOf(s,p).length === 0` | `rules.ts` 的 `isEliminated` |
| 收入 | `baseIncome` + 每座城 + 经济单位。无城还有底薪，但**产线在城市格上**，钱没处花 | `incomeResOf` |
| 胜负收场 | 两人局一方出局就结束；三家以上还会**把出局者的兵全撤掉**（`retireLostSeat`） | `checkWinner` / `retireLostSeat` |
| AI | `enemyCitiesOf` / `citiesOf` 二十多处，AI 的目标就是"打城"。没城可打，它会不知道干嘛 | `ai.ts` |

所以"无城"不是一个配置项，是**把出局的定义、钱的定义、AI 的目标一起改**。

### 已有的两块地基（好消息）

- **`deploy` 一写就替代自动撒兵**——"纯初始兵开局"这件事已经能表达了，不用新机制。
- **`godMode` 和 `hidden` 是两个现成的豁免先例**：`isEliminated` 里已经写着
  "上帝模式不算出局""未登场不算出局"。无城席位就是**第三个豁免**，
  分支怎么加、加在哪，照着这两个抄就行，不用重新设计。

### 要做的事（按风险从低到高）

1. **给关卡加一个席位标记**：`seats.cityless: PlayerId[]`（关卡级，不是全局 config）。
   为什么放关卡：无城模式天然需要"谁带几个兵、什么时候补兵、怎么算赢"这一整套，
   而这些恰好全在关卡里（`deploy` / `events` / `goals`）。做成全局开关的话，
   每个普通对局都要处理"没产线的空面板"。
2. **出局判定**：cityless 席位改成"**兵打光才算输**"。实现就是在 `isEliminated` 里加一条
   和 `godMode` 同形的豁免，然后交给 `checkWinner` 的第二条（没兵又造不起）。
   注意：cityless 一定"造不起"（没产线），所以实际就是"最后一个兵死 = 出局"。
3. **建局**：cityless 席位不建城、不自动撒兵，**`deploy` 必须写**（不写就是开局即出局）。
   校验要拦："这一席标了无城，但 `deploy` 里没有它"。
4. **胜负**：现在的 goal 少了"把对方兵全灭"这一条（`assassinate` 要指定兵种）。
   要加 `annihilate: { winner, loser }`。没有它，无城对局只能靠"守到第 N 次行动"收场。
5. **面板**：无城席位不要显示城血和收入；金币那一栏要写清"没有产线，金币不产出兵"。
   否则玩家看着一栏钱花不出去，会以为是 bug。
6. **AI**：无城席位的目标从"攻城"退成"歼灭最近的敌人"。这是这一批**最花时间**的一块，
   也是最容易做出"AI 杵着不动"的一块——务必用 AI 对 AI 跑够局数再下结论。

### 成果

"双方各带 8 个兵、没有城、谁先打光谁输"这种**遭遇战关卡**能做出来。
它可以只是一张关卡（一方无城），也可以是一种玩法（双方无城）。

### 验收

- 双方无城的关：能开局、能打完、有明确赢家、不出现"半天不收场"；
- 一方无城的关（比如守方有城、攻方只有兵）：攻方兵打光即判负，守方城破照旧判负；
- **普通对局、三张内置关、老存档、老复盘：行为一个字没变**（这是这一批的硬要求）；
- AI 对 AI 跑 3 局，无城那一方不能出现"全员原地不动"。

### 排序建议

**排在 E3（摆兵）之后**，理由很实在：做无城关必须摆兵，没摆兵面板就得回去手写坐标。
如果你们两个人并行，可以让一个人做 E4（事件编辑器），另一个人做 F1——
两条线几乎不碰同一个文件（只在 `LevelDef` 上加字段时会碰一次）。

**但不能和 E4 同时给同一个人做。** F1 改的是"出局"，E4 改的是"事件"，
一旦出了问题（比如某张关卡的兵莫名其妙没了），分不清是谁的错。

### 明确不做

- 无城席位"从虚空造兵"（营地/传送门产线）——那是新机制，先靠 `deploy` 和 `events` 补兵；
- 无城席位专属的经济体系（招募点、修理费）——金币先当一个死数字，够用；
- 无城模式进排位/匹配规则——先把关卡跑通。
