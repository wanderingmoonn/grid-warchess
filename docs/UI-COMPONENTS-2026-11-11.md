## 一、两条正交的轴：主题与动效

| 轴 | 属性 | 取值 | 入口 |
|---|---|---|---|
| 主题 | `<html data-ui>` | `legacy`（默认）/ `modern` | 设置弹窗 · 外观；`?ui=modern`；控制台 `__ui('modern')` |
| 动效 | `<html data-motion>` | `full`（默认）/ `reduced` | 设置弹窗 · 外观 |

- **回退方式**：删掉属性就是旧观感，不需要重新加载、不碰任何规则。
- 两个属性可以任意组合（`modern` + `reduced` 是最常用的"深色且不晕"）。
- 棋盘、地形色**不跟主题变**：`.tile` 永远浅底深字（`color: var(--on-light)`），
  认得出地形比"整体统一"重要。

### 1.1 白字压深底：用 `--a-fill` 而不是 `--a`

`--a` 一身两职（文字强调 + 填充底色）。modern 下提亮之后，白字压 `--a` 只有 2.6:1。
所有**填充**场景（主按钮、选中 chip）一律 `background: var(--a-fill); color: #fff`，
文字强调才用 `--a`。

### 1.2 四道对比度体检（`npm run test:contrast`）

1. token 两两对比（正文 4.5:1、描边 1.5:1），legacy / modern 各跑一遍；
2. 反色态：`color: #fff` 压 token 底色的 10 条组合；
3. 亮底规则：亮度 > 0.7 的底色必须配深字（64 条，含 rgba 半透明白）；
4. **状态切换**：`:hover / :active / :focus` 规则里"背景换了、字色没换"的组合（18 条）。
   这条是 2026-11-11 补的，起因是 `.btn-primary:hover` 写死 `#1f1d19`：
   legacy 下黑底白字没毛病，modern 下那个按钮是**反相**的（`background: var(--text)`
   是浅色、`color: var(--panel)` 是深色），一悬停就变成黑底黑字。
   补上之后又顺带抓到 `.zoom-btn:hover`（深色主题下深底压深褐字，1.11:1）
   和 `.btn-danger:hover`（4.15:1，差一点点）。

**第三道曾经空跑过一次**（复用只含 9 个变量的表，`--a-fill` 不在里面，照样"通过"）。
空跑的检查比没有检查更危险——所以每一道都要打印"检查了多少条"，数字为 0 就是 bug。

第四道的两个实现要点，改它之前先看：

- **必须处理继承**：状态规则通常不写 `color`，靠基础选择器继承。不建"基础选择器 → color"
  的表，`亮底规则` 会把它们一律当成 `--text`，误报一片。
- **`stripState` 要整块去掉 `:not(...)`**：`.btn:hover:not(:disabled)` 只删 `:hover`
  会剩下 `.btn:not(:disabled)`，和 `.btn` 对不上，这一类（项目里最多的一类）
  全被跳过——第一版覆盖率只有 10 条，修完 18 条。

### 1.3 字阶：11 档，全库只剩 `var(--fs-*)`

2026-11-11 第二批。动之前是 14 种字号散在 112 处声明里，其中三档 token
（`--fs-title` / `--fs-h1` / `--fs-h2`）**定义了却一次都没被引用**——
用的人全在直接写 `font-size: 17px`。建了变量没人用，等于没有。

| Token | 值 | 用在哪 |
|---|---|---|
| `--fs-micro` | 10px | 角标、`kbd`、行内元信息（原来那两处 9px 并进来） |
| `--fs-xs` | 11px | 次级说明：分组标题、meta 行、面板注释 |
| `--fs-sm` | 12px | 小号正文：表格、浮层、列表副行 |
| `--fs-body` | 13px | 正文：按钮、输入、卡片内容（用得最多，37 处） |
| `--fs-md` | 14px | **基准字号**（`body` 默认） |
| `--fs-h2` | 15px | 小节标题 |
| `--fs-h1` | 16px | 标题；输入框也必须是它（iOS 上小于 16px 聚焦会放大整页） |
| `--fs-title` | 17px | 面板标题 |
| `--fs-xl` | 18px | 弹窗大标题（原来的 19 / 20 并到这儿） |
| `--fs-num` | 30px | 房间码这类要一眼看清的大数字 |
| `--fs-hero` | 40px | 首页主标题 |

三条规矩：

1. **别再往这条链里加新值。** 要更大的字，先回答"它比 17 大多少、为什么"。
2. **唯一例外是棋盘**：7 处 `font-size: calc(var(--cell) * 0.19)` 这类，
   字号必须跟着格子大小走（32×32 的格子放不下 13px）。改棋盘时别把它们"顺手修正"成 token。
3. 验收一条命令：`grep -c "font-size: [0-9]*px" src/style.css` → 0（只剩注释里那处示例）。

### 1.4 棋子贴图：一个随时能关掉的附加层

2026-11-11 试了用混元生成兵种美术，结论是「建筑和载具能看，人形在 1x 屏上糊」。
还没定论，所以做成**开关**而不是直接替换——关掉就完全回到汉字，不用回滚版本。

**开关**：设置 → 外观 → 棋子贴图（默认**关**）。落在 `<html data-art>`，
和 `data-ui` / `data-motion` 同一套思路：切换只改一个属性，不重载样式、不碰存档。
调试可以带 `?art=on` 强制打开，和 `?ui=modern` 一样用来做 A/B。

**资源约定**（加图不用改代码）：

     public/art/units/<兵种id>.png     256×256、透明底、脚踩同一条基线
     public/art/units/manifest.json    由 npm run art:index 生成（build:static 已串上）

**三条不能破的规则**：

1. **没图必须回退汉字**。清单里没有、清单没拉到、开关关着——三种情况都走汉字。
   棋盘上出现一个没有任何标识的方块，玩家没法判断那是什么。
2. **不靠 404 试探**。用 manifest 而不是"逐张试加载"，否则 330 个兵种会刷 330 条红字。
3. **有图时让出填充色**。像素图压在高饱和的队伍色上会糊成一团（第一版就是这样），
   所以 `.unit-inner.has-art` 改用中性浅底 + 阵营描边。

**两个反直觉的坑**（都踩过）：

- **清单是异步的，第一帧一定没有它**。启动时拉一次没用——那一刻还没有渲染入口，
  拉到了也没人重画。要在 `render()` 里惰性触发，到货后补一帧。
- **棋子的 diff key 要带上"有没有图"**。棋子层按 key 判断"内容没变就不写"，
  第一帧（无图）已经把节点写进缓存，清单到货后 key 不变就会被跳过——
  开关打开了、棋盘照旧全是汉字，看着像开关失效。

| 断点 | 管什么 |
|---|---|
| `360px` | 极窄屏：`.stat-grid` 退回单列（"基础 1 / 1"自己折行会看着像另一条属性） |

## 三、组件清单（每条都写了"为什么"，改之前先看）

### 3.1 属性表 `.stat-grid`（单位卡、城市卡）

```
生命        移动力
28 / 28     2
攻击 / 护甲   射程 / 视野      ← 有修正时这一格整组跨两列
13 / 2      1 / 2
```

- **竖排**（标签在上、数值在下），不是"标签—数值"并排：并排时一格只剩 ~150px，
  `攻击 / 护甲 13 / 2（基础 1）` 必然折行，折完就分不清哪段属于谁。
- `.stat-span`：跨两列，内部**也是两列**（左数值、右修正明细）。
  明细铺在下层会把后面的格子挤成半格，右边空一整格——看着像数字没加载出来。
- `.stat-wide`：单行跨两列（城市卡的「驻军休整」那种一整句话的值）。
- 没有修正明细时**不要**加 `.stat-span`：民兵也会空出右边一整格。
- `grid-template-columns: repeat(2, minmax(0, 1fr))`——用 `minmax(0, 1fr)` 不用 `1fr`，
  否则一条长数值会把整列撑宽顶出侧栏（和 `.main` 那次是同一个坑）。

### 3.2 折叠卡 `.card-fold`（操作 / 战报 / 升级解锁）

- 用原生 `<details>`：键盘、焦点、读屏全白送。
- **`toggle` 事件不冒泡**，监听挂在 `#side` 上用捕获阶段，按 `el.dataset.fold` 分派：

  | `data-fold` | 状态变量（`src/main.ts`） |
  |---|---|
  | `log` | `logOpen` |
  | 其它 / 无 | `opsOpen` |

- 面板是**整块重建**的（每回合、每次金币变动都重写 `innerHTML`），`<details>` 的
  `open` 一重建就没了——所以状态必须存在 main，渲染时带回去。
- 判断"该不该折叠"的标准只有一条：**低频 + 常驻会顶走主按钮**。
  目前折叠的是：操作说明（看懂一次）、战报（每回合都在长）、升级后可解锁（三四十个兵种名）。

### 3.3 侧栏固定底栏 `.footer-main`（≤920px）

- 手机上侧栏会长到两三屏，而「结束行动」每回合必点——它贴在屏幕底部。
- **只固定主按钮那一层**：认输和"每步自动存档"仍随内容滚，它们不该常驻遮挡。
- `.side` 必须留 `padding-bottom: 84px`，否则滚到底时最后一行永远差半行。
- 同层还有几个 `position: fixed` 的东西，加新浮层前先看这张表——**也数一遍四个角**：
  右下角原来挤着缩放条和聊天按钮，左下角现在挤着地图列表和缩放条，
  两次都是"两个都该在角落"的东西撞在同一个角上。

  | 元素 | z-index | 位置 |
  |---|---|---|
  | `.footer-main` | 45 | 底部整条 |
  | `.handoff`（交接遮罩） | 50 | 全屏 |
  | `.zoom-bar` | 60 | 手机上并进底栏左侧 |
  | `.board-list`（地图列表） | 60 | 左下角；手机上抬到底栏上方 64px |
  | `.toast` | 60 | 底部（手机抬到 84px） |
  | `.draft-mask`（选卡） | 70 | 全屏 |
  | `.tut-card`（教程） | 75 | 底部居中 |
  | `.title-screen`（首页） | 80 | 全屏 |
  | `#hover-tip` | 90 | 跟随鼠标 |
  | `.bc-mask`（战报卡） | 96 | 全屏 |
  | `.modal-mask`（弹窗） | 100 | 全屏 |

### 3.4 顶栏分层

- **明面**：回合胶囊、交给 AI、设置。
- **≤640px 收进设置**：「联机」（开局前的事）、「迷雾」（开局面板里就定死了）。
  渲染由 `settingsHtml({ compact })` 控制，**桌面上这组不出现**——顶栏本来就有，
  两处状态就是两条路径。
- 手机上点迷雾**不关弹窗**，原地重画：玩家刚点的就是这一屏上的开关。
- 兜底：`.topbar [data-act='settings']` 在 ≤640 是 `position: sticky; right: 0`，
  320px 之类更窄的屏上也不至于够不着。
- 顶栏骨架**只插一次 DOM**，之后只改文本/class/hidden——AI 每走一步都 render，
  重建按钮会让 `mousedown` 与 `mouseup` 之间换掉节点，点击直接丢失。

### 3.5 手机上的卡片顺序

- `.card-detail-live`（≤920 时 `order: -1`）只在**真的选中了东西**时生效。
  无条件前置的副作用是：什么都不选时第一张是「操作」折叠行，
  而"轮到谁、双方还有多少钱"被挤到它后面。
- 桌面顺序不动：侧栏在棋盘右边，席位栏第一张是对的。

### 3.6 设置弹窗 `.set-row`

- 桌面：左边名字 + 一句解释，右边控件。
- ≤560px：改**上下两段**（左标签右控件在 340px 里会互相挤，"减少动态效果"那条解释被压成四行）。
- 解释文字**常驻**，不藏进 `title`——这些选项一辈子只调一次，调的时候看不懂就再也不会回来。

## 四、一个反复踩的坑：中文 + flex 会塌成一列字

`起始时代` + 一句解释并排时，窄屏会变成"起/始/时/代"竖着排。

**原因不是字号**：中文的 `min-content` 就是一个字，两个中文 flex item 都能合法地缩到 1 字宽，
浏览器就这么分了。修法是把容器改成 `display: block`（标题一行、解释一行），不是调字号。

**判据**：凡是"中文长标签 + 长解释并排"的 flex，窄屏都要试一遍
（`npm run shot` 带 `mobile` / `w=360`）。

## 五、怎么验证（改完 UI 一定要跑）

```bash
npm run shot                                                     # 桌面 1440×900，legacy
node --experimental-strip-types scripts/ui-shot.ts modern        # 桌面 + 深色
node --experimental-strip-types scripts/ui-shot.ts mobile        # 手机 390×844 @2x
node --experimental-strip-types scripts/ui-shot.ts mobile w=360  # 安卓常见窄屏
node --experimental-strip-types scripts/ui-shot.ts draft         # 选卡两屏（默认关，平时拍不到）
```

产物在 `.tmp/shots/`。**用 Edge 无头 + CDP，零依赖**（不需要 playwright）。

三个必须知道的细节：

1. **1440 的画布上一处窄屏问题都复现不出来。** 手机适配必须按真尺寸拍。
2. `<summary>` 展开**必须用 CDP `Input.dispatchMouseEvent`**，合成 `MouseEvent` 不触发。
3. 脚本每次运行前会 `localStorage.clear()` 一次。不清的话，上一次跑 `draft`
   点过的「开启选卡模式」会留在同一个 Edge profile 里（那个开关"勾一次就记住"），
   下一次拍普通对局拍到的却是一屏 BP——**图看着没报错，内容却是错的**。

配套的自动闸门：

```bash
npm run test:css        # 样式表结构（未定义变量、重复选择器等）
npm run test:contrast   # 三道对比度体检
npm run test:ui         # jsdom 跑真入口，227 项
```
