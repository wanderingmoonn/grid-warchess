# v0.3.27：开雾跑 64×64 不再崩

一句话：**迷雾不再给每一个格子挂 CSS `filter`**——那是四千个离屏合成层，正是标签页崩溃的来源。

## 现象

有玩家反馈：**开迷雾 + 64×64 会闪退，关掉迷雾就正常**。32×32 开雾没事。

## 我怎么查的

先把"不涉及 DOM"的那一半全量一遍（`scripts/probe-fog64.ts`）：

| 项目 | 64×64 实测 |
|---|---|
| 建局 | 32ms |
| `refreshMemory`（每步都跑） | 0.1ms |
| `playerView`（每帧都跑） | 7.3ms |
| AI 一次决策 | 78ms |

规则层完全不是瓶颈，也没有递归/死循环。再用真浏览器的探针（`scripts/make-fog-probe.ts`）
把 4096 格的盘面渲染出来，抓 `window.onerror`：**零 JS 错误**，开雾关雾都正常结束。

也就是说：不是算错了，是**画崩了**。

## 根因

开雾时唯一多出来的一条规则，是给视野外的格子压暗：

```css
.board.fog .tile.out { filter: brightness(0.74) saturate(0.55); }
```

`filter` 不是"改个颜色"那么便宜——它要求浏览器**为这个元素单独开一张离屏缓冲**再合成回来。
64×64 是 4096 格，开雾时其中 4000 多格同时带 `filter`，就是 4000 多张缓冲；
再叠上 64×64 必然要"放大 + 滚动看"（`.board-scroll.zoomed` 开 `overflow:auto`，
滚动会持续触发重绘），显存和合成器队列就顶穿了。

所以症状才这么怪：不是变卡，是**直接崩**；而且只在"大图 + 开雾"这个组合下出现
——小图格子少、大图不开雾就没有那 4000 个 filter。

## 改了两件事

**1. 压暗从 `filter` 换成盖层。** `.tile::after` 本来就是高亮层（可达 / 可攻击 / 选中都用它），
现在是给视野外那格铺一层半透明灰：`rgba(74, 70, 62, 0.52)`。纯色填充只走绘制、不进合成器。
混的是灰不是黑，所以除了变暗，颜色也会被冲淡，观感和原来的 brightness+saturate 接近。
浓雾扩展的"记得但看不见"那一档同样换成盖层（更重一档）。

**2. 大地图模式（`> 1024` 格）。** 棋盘多一个 `big` class，把逐格的过渡与闪烁关掉：

```css
.board.big .tile::after { transition: none; }
.board.big .tile.placeable::after { animation: none; }
```

过渡本身不贵，贵在"同时"：每帧重绘有成百上千格换 class，每个 `::after` 都带 0.12s 过渡，
就是成百上千条同时跑的动画。小图上这是"好看"，64×64 上格子只有 18px，根本分辨不出来，
纯属看不见的账。

阈值选 1024（=32×32）：32×32 关雾打起来是流畅的，64×64 才需要保护。

## 顺带留下的三件工具

- `scripts/probe-fog64.ts` —— 规则层的体检：建局 / 记忆 / 视图 / 决策各花多少毫秒、堆峰值多少。
- `scripts/make-fog-probe.ts` —— 生成"内嵌存档 + 自测"的探针页。存档要内嵌而不是跳转后写：
  `localStorage` 必须和应用同源、且在 bundle 执行前写好，跳转一次脚本就断了。
- `scripts/make-fog-fixture.ts` —— 单独造 64×64 的存档（开雾 / 关雾两份），喂给上面那个探针。

## 用例

界面 **174 项**（+2），规则 549、静态服务 11，全绿。新增两条守规模与实现：

1. `> 1024` 格才加 `big`：12×12 不带、64×64 带，且开雾时视野外超过 3000 格
   （就是这批格子把渲染压垮的）；
2. 逐格的 `.board.fog .tile.out` / `.board.blackout .tile.remembered` 上**不许再出现 `filter`**
   ——谁图省事改回去，这里立刻红。

而不是"亲眼看着它从崩到不崩"。麻烦让那位朋友更新后再开一局 64×64 迷雾试试；

还是"整个浏览器退出"——那能区分是显存顶穿还是别的。
