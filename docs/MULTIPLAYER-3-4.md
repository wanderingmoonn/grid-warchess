# 三人 / 四人联机：改动方案

> 状态：**已落地（2026-11-01）**。第二节的"落地情况"写的是实际做成的样子，
> 与下面原方案有出入的地方都以那一节为准（原方案保留，方便对照"当初为什么这么想"）。
>
> 起点回顾：现有代码是按"双方"写的，这不是加一个选项的事——
> `PlayerId` 是个只有两个值的联合类型，35 处 `other(p)`、19 处 `for (const p of ['A','B'])`、
> 34 条 `own-A/own-B` 配色规则、6 个 `seat_a/seat_b` 列，全都建立在"只有两方"上。

---

## 一、模式与配置

### 1.1 配置里怎么表达

`MatchConfig` 新增**一个**字段，不引入"模式字符串"这种二手概念：

```ts
playerCount?: 2 | 3 | 4;   // 缺省 2 = 现在的全部行为不变
```

- 缺省值 2，所以老存档、老房间、分享链接读回来一个字都不用改；
- 席位就是 `PlayerId`，人数决定用前几个：2 人 → `A/B`，3 人 → `A/B/C`，4 人 → `A/B/C/D`；
- **不做 3v1、2v2 这类"阵营"**：本方案里每个席位就是一个独立阵营，各自为战。
  真要做组队，那是另一个维度（队伍与外交），不该混进人数这个开关。

### 1.2 每方一座城：从"生成"到"约束"

现在 `createMatch` 拿地图布局里的 `citiesA/citiesB` 直接落城，数量由生成器决定
（`mapgen` 会给 1~3 座）。三人/四人模式下改成**硬约束**：

```
城数 = 人数，每人恰好 1 座。
```

落点由地图布局提供（见第二节），`placeCity` 之后再加一道断言：
`cities.filter(owner === p).length === 1`，不满足就退回"每人一城"的兜底布局
（在棋盘上按角度均分撒城）。这条断言要留在规则层，不能只写在生成器里——
`config.fixedMap`（玩家上传的图）也会走到这里。

> **落地时的修正**：两人局仍然是每家两座城（老地图、老平衡一个字都没动），
> "每家一座"只对三人四人局成立——它本来就是那个模式的定义，不是全局规则。
> 所以没有加"断言失败就撒城"的兜底：多人局只有一条生成路径（`generateMultiLayout`），
> 固定地图在 `twoSeats === false` 时直接不参与，用不上兜底。

连带的几处：
- **开局那两个经济单位**：现在写死给 `A`/`B` 各两个，改成"每个席位各两个"；
- **城市面板**：一座城的玩家不存在"哪座城出兵"，产兵点就是唯一那座城；
- **失去唯一的城 = 出局**（现在的 `checkWinner` 正是这么判的，天然成立）。

## 二、地图：3 人和 4 人怎么摆才公平

这是整件事里**唯一需要新算法**的地方。方格棋盘没有 120° 旋转对称，所以：

| 人数 | 摆法 | 公平性来源 |
|---|---|---|
| 2 | 现状（对角 / 同边对峙 + 镜像或旋转对称） | 完全对称 |
| 4 | **四角 + 90° 旋转对称**：只生成左上四分之一，旋转四次铺满 | 严格相同（地形逐格镜像） |
| 3 | **三角**：三座城摆在最大内切圆的三等分点上 | 近似公平：地形**数量**配平，形状不同 |

3 人图的具体做法（`mapgen` 里新增 `layoutForThree`）：

1. 三座城落在以棋盘中心为圆心、半径 `0.36 × 边长` 的圆上，角度 `-90° / 30° / 150°`
   （顶点朝上，视觉上最像"三足鼎立"）；
2. 地形按"区域"生成：把每格归给最近的那座城（Voronoi），
   每块区域里的森林/丘陵/水**分别**按同一份数量表撒，保证三家资源量一致；
3. 中央留一圈公共区（谁都能到），避免三家被山水割开成三个独立小局。

> 3 人做不到逐格对称，只能做到"数量公平"。这一点要在选图界面上写清楚，
> 否则玩家会觉得"我这边的山比他多"。4 人图没有这个问题，优先推荐。

数据层：`MapLayout` 的 `citiesA/citiesB/spawnsA/spawnsB` 改成
`cities: Map<PlayerId, Point[]>` 与 `spawns: Map<PlayerId, SpawnDef[]>`
（内部字段名保持可读），`fixed-maps.ts` 里玩家上传的地图仍然只收 A/B 两个城位，
**3/4 人模式不允许选固定地图**（这是最省事也最诚实的边界）。

## 三、联机：房间、席位、轮次

### 3.1 云端表加两列

```sql
alter table public.warchess_rooms
  add column if not exists seat_c text,
  add column if not exists seat_d text;
```

`grant select, insert, update` 是表级的，不用再补；RLS 策略也不用改
（现在的策略是"任何人都能读、能写自己那行"）。
`RoomSnapshot.seats` 从 `{A, B}` 变成 `Record<PlayerId, string|null>`，
但**只返回本局实际用到的席位**，否则界面上会凭空多出两个空座。

### 3.2 建房与入座

现在的流程是"谁建房谁坐当前该行动的那一方"，另一人用房间码进来占另一个座。
三人/四人沿用同一套，只是席位多了：

- 建房：房主坐下来，`config.playerCount` 决定这张桌子有几个座；
- 入座：进房页面列出 `A/B/C/D` 四个位子，**空着的都能点**，已占的显示"已入座"；
- 满员才能开局（3 人局必须坐满 3 个，缺一个就等）；
- 席位就是阵营颜色，先到先选（谁想要红方就早点进）。

### 3.3 "轮到我"与提交

现在判"是否轮到我"是 `state.current === mySeat` —— 这条**不用改**，
`current` 在 N 人局里就是"现在轮到谁"，天然成立。
提交时的乐观锁也一样：`turn` 列存的仍是那个单调递增的版本号。

### 3.4 掉线与认输

- 认输：`SURRENDER` 现在是"我认输 = 对方赢"。N 人局改成**我出局**，
  由剩下的人继续打（`s.out[]` 记谁已经出局，`current` 跳过他们）；
- 掉线：不自动判负，房里其他人可以点"接管这家"（代打）或"判他弃权"。
  这条不做也能上线，但要写进说明——否则三人局里一个人掉线，这局就废了。

## 四、回合、补偿、胜负

| 项 | 现在（2 人） | 3/4 人 |
|---|---|---|
| 回合切换 | `other(current)` | 按 `A→B→C→D` 环转，跳过已出局 |
| `state.turn` | 每一次"半回合" +1 | **保持原样**，但所有"第 N 回合"的门槛改成按**轮**算 |
| 血战（第 50 回合） | `turn >= 50` | `round >= 50`，`round = ceil(turn / playerCount)` |
| 先后手补偿 | 只给 B | 给**除第一个行动者之外的所有人**（同一个比例） |
| 胜负 | `checkWinner` 里"谁没城谁输" | 只在**剩一家**时结束；出局的人继续观战 |
| 战报 | 两方过滤 | 按席位过滤，出局后自动转观战视角 |

`round` 这一条容易漏：4 人局里 `turn` 涨得比 2 人局快一倍，不改的话血战会在
"第 12 轮"就触发，后期节奏全乱。

## 五、界面上怎么体现、怎么区分

### 5.1 开局：人数是一等公民

开始界面的**「战役」页**在"对手"上面加一行「人数：2 / 3 / 4」。
选了 3 或 4 之后：

- 「对手」那栏自动切成"全部真人"（见第七节，AI 暂不进 3/4 人局）；
- 棋盘大小、时代、扩展照旧可选；
- **底部摘要**从 `12 × 12 · 古典 · 随机地形` 变成 `12 × 12 · 古典 · **3 人** · 随机地形`。

地图页：3/4 人模式下**固定地图整块置灰**，并写清原因
（"上传的地图只有两个城位"）；缩略图网格换成该人数下生成的三/四角示意图。

### 5.2 对局中：一眼看出这是几人局

三处，都要有：

1. **顶栏徽章**：`3 人局` / `4 人局`，和房间码排在一起；
2. **玩家条**：现在侧栏顶部是"A vs B"两行，改成 N 行——
   每行一个色点 + 名字 + 城数 + 兵力 + 金币，**轮到谁那一行加亮**；
3. **配色**：红 / 蓝 / 绿 / 黄（中国棋盘习惯），
   城市方块、单位底色、血量条、战报名字统一走这一套；
   新增 `own-C` / `own-D` 与 `.vs-dot.c/.d`，共 34 条配色规则要补。

### 5.3 三种"人数"在别处也要分得开

- **选卡模式**：蛇形顺序要按 N 个席位排（现在是 A-B-B-A 两轮）；
- **复盘/观战**：`reveal` 全图，N 人局一样；
- **结算卡**：现在写"红方/蓝方胜"，改成"XX 胜 · 3 人局"；
- **战绩上传**（`warchess_reports`）：加一列 `player_count`，不然统计里 3 人局和
  2 人局混在一起，胜率没有意义。

## 七、AI 怎么办（必须先定）

`ai.ts` 的 25 处 `PlayerId` 背后是一整套"我方 vs 敌方"的判断：
威胁场、推进方向、集火目标、经济预算，全都假设只有一个敌人。
让 AI 进 3/4 人局，等于重写目标选择（"打最近的那家"还是"打最弱的"），
工作量比其余部分加起来还大。

**建议：3/4 人模式先只支持全真人**（本地热座也行，联机也行），
AI 仍然只在 2 人局出场。等这套跑顺了，再单独做"AI 托管某一家"。

## 八、落地顺序（每步都能跑、都能测）

1. **类型与人数的地基**：`PlayerId` 扩到四值、`playersOf/others`、`MatchConfig.playerCount`、
   `createMatch` 按人数建玩家与城（2 人行为逐字不变）；
2. **地图**：4 人旋转对称 → 3 人三角配平；
3. **回合与结算**：环转、`round`、出局、胜负、先后手补偿；
4. **联机**：表加两列、席位列表、满员开局、观战/接管；
5. **界面**：人数选择、配色 C/D、玩家条、徽章、地图页置灰、结算文案。

每步都要有回归：现有 469 条规则用例必须在 `playerCount=2` 下全绿，
另外每个新人数加一组"建局 → 打三轮 → 判负"的用例。

## 九、落地情况（2026-11-01）

这一节是**实际做出来的样子**，可以直接当手册用。下面每条都对应一处改动，
写完就跑了回归：规则 480 条、界面 159 条、服务 11 条、AI 36 条。

### 9.1 要改的配置：只有一个字段

| 位置 | 字段 | 说明 |
|---|---|---|
| `MatchConfig` | `playerCount?: 2 \| 3 \| 4` | 缺省 2。老存档、老房间、分享链接读回来一个字都不用改 |
| `GameState.config` | `playerCount: 2 \| 3 \| 4` | **必须白名单抄进去**（这个对象是逐字段手抄的，漏一个就等于被吃掉，席位会退回两个） |
| `GameState` | `out?: PlayerId[]` | 已经退出的席位（认输 / 被判定出局）。判负、轮转、顶栏都读它 |
| `warchess_rooms` | `seat_c` / `seat_d` | 两列可空。见 `sql/warchess_rooms_seats.sql` |
| `warchess_reports` | `player_count` | 见 `sql/warchess_reports_player_count.sql`；没跑也能传（代码会自动省掉这一列重写一次） |

联机这块的配置约定：

- **座位数由房间里的那一局 `state.config.playerCount` 决定**，不由房间表决定。
  房间表只是四列令牌位，`seatsOf(state)` 才是"这张桌子几个座"的唯一判据——
  老房间没有这个字段，读出来是 2，行为与以前完全一致；
- `claimSeat` 抢座仍然靠 `is(column, null)` 的原子更新；三人四人局多了两份座位列；
- 满员才能开局：房主建房后，界面把空位标成「（空着）」并写着还差几位；
- 两人局的老房间在没跑迁移的库上照常能建：`createRoom` 撞上"列不存在"会自动
  省掉 C/D 两列重写一遍（三人局则会明确报错，让你去跑那条 alter）。

### 9.2 玩家与城市的数量对应

| 人数 | 席位 | 每家城数 | 开局兵力（每家） | 地图 |
|---|---|---|---|---|
| 2 | A / B | 2 | 5 战斗 + 2 经济 | 随机生成 **或** 固定地图（含玩家上传） |
| 3 | A / B / C | **1** | 3 战斗 + 2 经济 | 只能生成：三角城位，Voronoi 分区配平地形数量 |
| 4 | A / B / C / D | **1** | 3 战斗 + 2 经济 | 只能生成：四角 + 90° 旋转对称（逐格严格相同） |

- **失去唯一那座城 = 出局**（`isEliminated`：认输过，或没城且不是沙盒）；
- 认输在两人局是"对面赢"，在三人四人局只是**这一家退出**：兵从盘上撤走、
  城留在原地（别人打下来就是战利品），行动权交给下一位；
- 只剩一家时才结束（`checkWinner` 改成"算出还活着的席位，只剩一个才判胜"）。

### 9.3 游戏里怎么区分这两种模式

1. **开始界面 · 战役页**：第一组就是「人数 2 / 3 / 4」。选了 3 或 4 之后
   「对手」那栏换成一句说明（AI 不进多方局），「指挥官模式」「上帝模式」「选卡模式」
   一起收起——它们全是按两边写的，留着就是"点了没反应"；
   地图页的固定地图整块置灰（"上传的地图只有两个城位"）；底部摘要变成
   `16 × 16 · 中世纪 · 3 人 · 随机地形`；
2. **顶栏**：`A vs B` 换成一列 `.seat-row`，**一行一席**：色点 + 名字 + 城数 + 兵力 + 金币，
   轮到谁那一行加亮，退出的那行划掉。行数就是人数——这是最快认出"这是几人局"的地方；
3. **配色**：红 / 蓝 / 绿 / 黄（`--team-c` `--team-d`），城市方块、单位底色、
   血条、`turn-badge`、热座交接遮罩的徽章全部走同一套；
4. **热座交接遮罩**：标题从"把设备交给对方"改成"把设备交给下一位"，
   三家四家局里正文会写"另外几家都算别人"；
5. **联机面板**：席位 chips 按这一局的座位数渲染，空位标「（空着）」，
   状态行写"还差 N 位没进来"；进场顺序是"自己记着的座位 → 依次试空位"；
6. **结算卡**：`红方胜 · 4 人局`，并加了一行 `· N 人 ·` 的报告摘要。

### 9.5 明确**不做**的（写在这里免得以后当成 bug）

- **AI 不进三人四人局**：`ai.ts` 的目标选择、经济预算、先后手补偿全假设"只有一个敌人"，
  让它进多方局等于重写打法。`createMatch` 里 `twoSeats` 这道闸把它关死了，
  不依赖界面记得关；
- **多人局不开选卡 BP**：规则层已经支持 N 个席位（`draftPickOrderFor`），
  但选卡界面只有两栏。等界面改了再开；
- **多人局不用上帝模式 / 固定地图**：一个按两边写、一个只有两个城位；
- **掉线不自动判负**：仍然要人点。三人局里一个人掉线，剩下的人可以先用「只看」看完；
- **不做 3v1 / 2v2 阵营**：人数 = 席位数，各打各的。组队是另一个维度（队伍与外交）。
