# 法术系统更新计划（2026-11-13 定）

> 配套文档：`docs/SPELLS-TRIAGE-2026-11-13.md`（85 条归类的结论）。
> 这份计划只回答两件事：**先做哪批、每批开工前要备什么地基**。
> 目的：中途停一个月回来，看第 0 节和第 3 节就能接着干。

## 0. 这份计划怎么用

### 三条抗中断的规矩

1. **进度只认勾选框。** 第 3 节那张表是唯一的进度真相，不写"大概做到一半"。
   每完成一条就当场打勾，别攒着"等这批做完一起勾"。
2. **没跑通的法术不许登记进 `SPELLS`。** 登记即上线：`SKILL_EFFECTS[effect]`
   查不到实现时会当场抛错。所以半成品留在数据表里、注释掉或放 `DRAFT` 数组，
   游戏永远是能玩的。中断在"表格填了一半"是最安全的断点。
3. **每批开工先写一行"接手提示"。** 在 `docs/` 里新建当批的笔记，
   开头一句话写清"现在做到哪、下一件事是什么"，比事后回忆便宜一百倍。

### 中断后回来的三个动作

1. 看第 3 节进度表，找到最后一个没打勾的框 → 那就是断点。
2. 看第 4 节对应批次的"接手第一件事"。
3. 跑 `npm run test:cultivation`。**绿的就说明断点之前的东西是好的**，
   直接往下做；红的先修红，别往红上面加东西。

## 1. 地基清单：哪块现成、哪块要造

**要修正一句口头结论**：归类时我把族 3 说成"要自己造场域/地雷系统"，核对代码后不对——
`marks.ts` 就是那套东西（`MarkKindDef` + `onEnter` + `onTurnStart` + 引擎管次数与可见性，
注释里写明这一层就是补"原来靠隐形单位假装的地雷"。族 3 和万仞刀山因此从"重活"降成"接线"。

### 为什么地基不一次造完

因为 G4~G7 只服务少数几条法术，提前造完就是提前背债（写完没人验证，等真用上时
接口已经过时）。原则是：**只备下一批要用的那一块**，G1/G2 例外——所有族都依赖它们。

## 2. 批次

每批都有"门禁"（DoD）。**门禁没过不许开下一批**，哪怕法术已经能跑。
门禁过不了的典型原因是"规则书没重生成"或"老测试红了"，这两种必须在批次内解决。

#### P1b 完成记录（2026-11-14）—— 族 2 也立起来了，P1 完结

作者当场纠了四处口径，都按原话改了（**这几条是设计口径，不是实现细节**）：

1. **移动从不走斜线**，所以"斜着的直线攻击"不该存在。直线改为**复用剑气纵横**的几何：
   四方向吸附 + 定长射线。几何抽到 `spell-kernel.ts` 的 `rayCells`，
   剑气纵横和灭神枪共用一份（`sword-sweep.ts` 里那份私人实现已删）。
   直线的长度由**射程**决定，不看点击距离。
2. **连锁穿迷雾，且不是"挑最近的一个"**：一层里半径内的**全部**未命中敌人同时挨打，
   最多 5 层。用 `c.state.units`（不是 `view`），但仍**不跨图**。
3. **罡风的高亮原来是错的**：方框会点亮四个斜角，而实际命中是曼哈顿。
   现在统一按曼哈顿画（"能打到的格子才画"），`SpellRow.blastShape` 这个过渡字段删掉。
4. **击落 = 动 `layer`**；落点上已有地面单位时**比血量**：多者活、少者死，
   活着的那个扣掉死者的血量（相等按"被挡下"算，坠落方死）。
   **改地形 = 改成平原**（`view.tiles[i] = {...tile, terrain:'plain'}`，
   保留 `cityId` 与 `custom`），以后可能扩成别的目标地形。

做了什么：
- `skills/blast.ts`：族 2 唯一实现 + 10 条数据行。开关：`physical`、`downAir`、
  `root`、`sunder`、`lifesteal`、`knockback`、`flatten`、`element`、`soulBound`。
- `spell-statuses.ts`：新增状态「定身」（`modifyMove → 0`，**只禁移动不禁攻击**），
  以及 `timedStatusFor()` —— `+1` 只写在这一处，防止再有人把 `turns` 直接交给 `putStatus`。
- **五行属性存在技能自己的 `custom.element` 上**，不往 `Unit` 开字段：
  族 5 的免耗判定以后直接读它。这就是之前"五行存哪"那个待拍板问题的答案。
- `spell-kernel.ts`：`rayCells`、`blastCoords`（flatten 要坐标）、`spellRadius` 镜像。

- `hooks.ts`：给 `modifyDamage / modifyRange / modifyVision / modifyAttacks /

两条这次踩到的坑（都已写进注释）：
1. **`strikeDistance` 返回的是"距离"，不是"射程"**。想断言射程要用 `effectiveRange`。

2. **加持的回合数不能套 `+1`**。`stunFor` 的 +1 是为了活过**对方**接手回合的 tick；

#### P4a 完成记录（2026-11-14）—— 护体灵光是「盾」，不是召唤物

作者澄清了一件会改变归类的事（原话）：**"护体灵光我的意思是一个护盾，不是生成了
一个单位，有自己的护甲和血量，打烂之后顺带把那一次攻击溢出的伤害吃掉。"**

所以它从族 8（召唤）挪出来，单独成一条**护盾机制**。理由不只是"叫法"：
召唤物是场上的一个单位（能点、能挡路、能被打死、算编制），护盾挂在人身上，
不占格、不进编制、碎了就没了——两者的生命周期完全不同，硬塞进一个族会互相污染。

实现（`skills/shield.ts`）：
- 数值放 `Unit.custom.shield`（`{hp, maxHp, armor}`），**是否生效看状态**
  `spell-shield`——状态到期钩子就读不到盾，不用在死亡/驱散/换回合三处各写清理。
- **自己的护甲**：走 `modifyArmor` 加在单位甲上（法术无视护甲，所以也无视盾甲，
  和法术本来的口径一致）。
- **自己的血量 + 溢出被吃掉**：新增核心钩子 `absorbDamage`，在 `hurtUnit` 里
  **扣真血之前**被调用。`amount >= 盾血` 时返回**整个 amount**（不是盾血），
  于是碎盾那一击不穿透——这是作者明确要的手感。

#### P4b 完成记录（2026-11-14）—— 复活分两种，别混

**先验证了那个风险点**：`killUnit` 的顺序是"先从 `s.units` 摘掉、再通知钩子"，
所以钩子里把**同一个对象** push 回去就是复活。`killUnit` 开头的幂等判断认 id，
同一具不会被重复结算。结论：**钩子里能复活**，族 11 可以按草案做。

两种复活被明确分开（这是这一批最重要的决定）：
- **免死**（主角光环、替死转生）：放回去的是同一个 `Unit`，所以**境界、经验、
  寿元、学过的技能全在**——G6 那条门禁靠的就是"对象没换"。复活后
  `moved/acted` 置真，这一回合不能再动（否则凭空多一个回合）。
- **招魂**（忘川逆流）：从 `s.fallen` 用 `api.spawnNear` 造**新形体**，修为不回来。
  这和核心里已有的「招魂」是同一口径：救回来的是兵，不是老兵。

族 8 只做了「撒豆成兵」：`api.spawnNear` / `freeNeighbor` 都是现成的，
所以"造一个单位"一点都不难——难的是**绑定关系**（替劫灵身要代死、
魂灯要留锚点、众妙之门要来回穿），每一种都要动不同的地基，留给 P4c。

#### P6b 完成记录（2026-11-14）—— G5 输入通道 + 三条

**G5 是一条从数据到界面的纵切**，所以先说它，再说法术：
- `SkillDef.input?: { kind: 'number' | 'text'; label: string; placeholder?: string }`
  —— 声明要填什么，**界面和校验都由它决定**，新加一条要填值的法术不用碰 UI。
- `Action.HERO_SKILL` 加 `input?: string`，`SkillCtx` 加 `input`。
- `doHeroSkill` 在**动手之前**拒掉空值。不在这里挡的话，法术会带着 `undefined`
  跑到结算里：`Number('') = 0` 会被当成"猜年龄 0 岁"。
- 面板：要填值的技能那一行变成**静态卡片**，下面单独一行"输入框 + 施放"。
  输入框**不在按钮里**——嵌套交互元素点击会冒泡，玩家还没打完字法术就放出去了。
- 瞄准类技能（钉头七箭书要选目标）把 `input` 存进 `pendingSkill`，
  选完落点再一起派发；取消瞄准不会扣灵力、也不占回合。

#### P6c 完成记录（2026-11-14）—— 张冠李戴：改两个入口，不列影响清单

作者的口径是"**一切**以施法者为目标的动作都转到目标上"，并且给了实现路子：
"直接改传入的 victim，看看有没有现成的钩子"。

沿着这个路子找下去，游戏里"以某人为目标"的入口只有两个：
1. **`redirectDamage`**（核心已有的钩子）——攻击、地雷、反伤都在 `hurtUnit` 里问它；
2. **`resolveCast`**（骨架里所有单体/范围法术挑完目标的地方）——在那儿把

所以没有做"影响类型枚举"。那张清单永远不完整，而且每加一条新法术都要回来补一行。

替身死了、或状态到期，`daiTargetOf` 就返回 undefined——转移自动失效，
不需要在死亡/驱散/换回合三处各写一次清理。
