# 法术系统更新计划（2026-11-13 定）

> 配套文档：`docs/SPELLS-TRIAGE-2026-11-13.md`（85 条归类的结论）。
> 这份计划只回答两件事：**先做哪批、每批开工前要备什么地基**。
> 目的：中途停一个月回来，看第 0 节和第 3 节就能接着干。

---

## 0. 这份计划怎么用

### 三条抗中断的规矩

1. **进度只认勾选框。** 第 3 节那张表是唯一的进度真相，不写"大概做到一半"。
   每完成一条就当场打勾，别攒着"等这批做完一起勾"。
2. **没跑通的法术不许登记进 `SPELLS`。** 登记即上线：`SKILL_EFFECTS[effect]`
   查不到实现时会当场抛错。所以半成品留在数据表里、注释掉或放 `DRAFT` 数组，
   游戏永远是能玩的。中断在"表格填了一半"是最安全的断点。
3. **每批开工先写一行"接手提示"。** 在 `docs/` 里新建当批的笔记，
   开头一句话写清"现在做到哪、下一件事是什么"，比事后回忆便宜一百倍。

### 中断后回来的三个动作

1. 看第 3 节进度表，找到最后一个没打勾的框 → 那就是断点。
2. 看第 4 节对应批次的"接手第一件事"。
3. 跑 `npm run test:cultivation`。**绿的就说明断点之前的东西是好的**，
   直接往下做；红的先修红，别往红上面加东西。

## 1. 地基清单：哪块现成、哪块要造

这一栏是这份计划里最该先读的部分。造地基比写法术贵，能不造就不造。

| 编号 | 地基 | 现状 | 谁需要 | 放在哪批 |
|---|---|---|---|---|
| **G1** | 法术骨架：目标校验、扣灵力、射程预览、战报，加一个循环批量注册就绪检查 | **要造**。现在每个法术文件自己抄一遍 | 所有族 | P0 |
| **G2** | 族数据行的结构（哪些是数、哪些是开关） | **要造**。可以照抄 `marks.ts` 的 `MarkKindDef` 那个模式 | 所有族 | P0 |
| **G3** | 格子场域：法术在格子上落一个 mark | **几乎现成**。`marks.ts` 已有 `onEnter` / `onTurnStart`、可见性、次数耗尽，只差"法术能落一个 mark"这一步接线 | 族 3、万仞刀山 | P2 开头 |

| **G5** | 输入文字/数字 | **要造**。`SkillDef.targeting` 只有 `none/point/direction` | 钉头七箭书、呼名落马术 | P6b 开头 |

| **G7** | 回档与回放对齐 | **要定，不是要写**。`snapshot.ts` 有，但"这类法术进不进回放"没结论 | 天衍四九 | P6c 开工前 |
| **G8** | AI 会放法术 | **完全没有**。`ai.ts` 只读 `def.skills`，法术（`extraSkills`）不看 | 全部法术 | 最后，独立排 |

**要修正一句口头结论**：归类时我把族 3 说成"要自己造场域/地雷系统"，核对代码后不对——
`marks.ts` 就是那套东西（`MarkKindDef` + `onEnter` + `onTurnStart` + 引擎管次数与可见性，
注释里写明这一层就是补"原来靠隐形单位假装的地雷"。族 3 和万仞刀山因此从"重活"降成"接线"。

### 为什么地基不一次造完

因为 G4~G7 只服务少数几条法术，提前造完就是提前背债（写完没人验证，等真用上时
接口已经过时）。原则是：**只备下一批要用的那一块**，G1/G2 例外——所有族都依赖它们。

## 2. 批次

每批都有"门禁"（DoD）。**门禁没过不许开下一批**，哪怕法术已经能跑。
门禁过不了的典型原因是"规则书没重生成"或"老测试红了"，这两种必须在批次内解决。

#### P1a 完成记录（2026-11-14）—— 族 1 已立起来

P1 实际拆成了两半：**P1a 族 1（直伤）已完成**，P1b 族 2（范围）还没开工。
拆的理由是族 1 需要现造三样东西（眩晕状态、直线命中、连锁），先把它们验通，
族 2 才不会一边写一边改地基。

做了什么：
- `skills/bolt.ts`：族 1 的唯一实现，四条法术共用。参数全在数据行的 `custom`：
  `base/perRank`、`trueMul`（灭神枪用真元×2）、`line`、`chain/chainRadius`、
  `stun`、`physical`（true = 走 `hurtPhysical` 按护甲结算）、`soulBound`。
- 新增法术：灭神枪（70 灵力 / 3 期）、元磁神光（60 / 2 期）、五雷正法（80 / 4 期）。
- `spell-statuses.ts`：新增状态「麻痹」，`stunFor` 存 `回合数 + 1`；
  `hooks.ts` 的 `canCommand` 接上它（和已有的「封印」共用一条通道，封印优先报理由）。
- `spell-kernel.ts`：`defineSpellSkill` 把 `cost/range` 镜像进 `custom`；
  新增 `spellCustom<T>()` 取值、`strike/strikeAll` 增加 `physical` 选项。
- 规则书：法术章节**改为从 `SPELLS` 生成表格**（原来三条是手写散文，
  加一门漏一门，而且没有任何测试会红）。手写的三段导读保留。

门禁结果：`test:cultivation` 142（+3）、`test:rules` 887、`test:ui` 245 全绿；
`npm run build` 通过；`npm run manual` 重生成后三门新法术都进了手册。

踩到的坑（后面别再踩）：
- **状态的剩余回合是"按持有者自己的回合数"**：状态在轮到谁时先 tick 再减 1，
  所以写 1 等于没写，要拦对方一整回合必须存 2。`stunFor` 里做的就是这个 +1，
  不是补丁。
- 测试文件里有个 `unitOf(s, 兵种, 玩家)`，**第二参是兵种不是 id**。
  按 id 取单位要用 `byId`。

**P1b 接手提示**：族 2（范围伤害）的 handler 还没写。第一件事是照 `bolt.ts` 的形状
建 `skills/blast.ts`（`resolveCast` 用 `mode:'area'`，受害者从它返回的 `victims` 拿），

#### P1b 完成记录（2026-11-14）—— 族 2 也立起来了，P1 完结

作者当场纠了四处口径，都按原话改了（**这几条是设计口径，不是实现细节**）：

1. **移动从不走斜线**，所以"斜着的直线攻击"不该存在。直线改为**复用剑气纵横**的几何：
   四方向吸附 + 定长射线。几何抽到 `spell-kernel.ts` 的 `rayCells`，
   剑气纵横和灭神枪共用一份（`sword-sweep.ts` 里那份私人实现已删）。
   直线的长度由**射程**决定，不看点击距离。
2. **连锁穿迷雾，且不是"挑最近的一个"**：一层里半径内的**全部**未命中敌人同时挨打，
   最多 5 层。用 `c.state.units`（不是 `view`），但仍**不跨图**。
3. **罡风的高亮原来是错的**：方框会点亮四个斜角，而实际命中是曼哈顿。
   现在统一按曼哈顿画（"能打到的格子才画"），`SpellRow.blastShape` 这个过渡字段删掉。
4. **击落 = 动 `layer`**；落点上已有地面单位时**比血量**：多者活、少者死，
   活着的那个扣掉死者的血量（相等按"被挡下"算，坠落方死）。
   **改地形 = 改成平原**（`view.tiles[i] = {...tile, terrain:'plain'}`，
   保留 `cityId` 与 `custom`），以后可能扩成别的目标地形。

做了什么：
- `skills/blast.ts`：族 2 唯一实现 + 10 条数据行。开关：`physical`、`downAir`、
  `root`、`sunder`、`lifesteal`、`knockback`、`flatten`、`element`、`soulBound`。
- `spell-statuses.ts`：新增状态「定身」（`modifyMove → 0`，**只禁移动不禁攻击**），
  以及 `timedStatusFor()` —— `+1` 只写在这一处，防止再有人把 `turns` 直接交给 `putStatus`。
- **五行属性存在技能自己的 `custom.element` 上**，不往 `Unit` 开字段：
  族 5 的免耗判定以后直接读它。这就是之前"五行存哪"那个待拍板问题的答案。
- `spell-kernel.ts`：`rayCells`、`blastCoords`（flatten 要坐标）、`spellRadius` 镜像。

门禁结果：`test:cultivation` 146（+4）、`test:rules` 891、`test:ui` 245 全绿；
`npm run build` 通过；`npm run manual` 重生成后 10 条全部入册。

还没做的（都写在 `blast.ts` 文件头，别当成漏写）：
- 焱 / 百里毒瘴 的**持续伤害场** → 等 P2 的 G3（marks）；
- 淼 的**减攻** → `StatusDef.modifyAtk` 引擎还没接上；
- 摘星拿月的**灵气转伤害**、以及焱垚鑫淼森的**外灵代偿** → 都还没到。

## 4. 每批的"接手第一件事"

中断回来只想干一件事，就是这条。

- **P0 中断** → 先看骨架文件里哪些函数已经被掌心雷用上；没被用上的就是没写完的。
- **P1 中断** → 打开族 2 的数据表，数已填几条、`SPELLS` 里登记了几条，差值是剩余量。
- **P2 中断** → 先手动放一次火海，看走进来的人掉不掉血。掉血 = 接线通了，接着填数据。
- **P3 中断** → 先测五行免耗第 3 次还扣不扣灵力。扣 = 计数器没清，先修它。
- **P4 中断** → 先测主角光环：打死一个带它的单位，看复活后的境界是不是掉了。掉了就是 `custom` 没搬。
- **P5 中断** → 先测转化后视野有没有跟着变。变了才继续，不然越做越歪。
- **P6 中断** → 看簇里还剩哪几条没勾，优先挑"不需要新地基"的。

## 5. 五条红线

1. **不先造 G4~G7。** 除了 G1/G2，地基都用到了才造。
2. **不许把半成品登记进 `SPELLS`。** 登记即上线，会让游戏在放法术时抛错。
3. **不许在法术文件里内联数值魔法数字。** 数值放数据行，面板和规则共用一份。
4. **改 `spells.ts` 的 `schools` 闸要在大道三千之前想清楚**——它会绕过这道闸，
   得改在那个函数里，不能只改法术自己。
5. **一次只开一个批次。** 两个批次并行时，出错分不清是谁引起的；
   真要并行，就一人一批不同族（族之间不共享状态，冲突面小）。
