## 3. 这一轮试过什么、为什么都没采用

方法一致：对手固定 `baselines/ai-9efb961.ts`，每条 24 局（Q1/Q2 + Q3/Q4 各 12），
主指标是**配对方向**（同队列、同种子、同席位，逐局比）。

| 尝试 | 结果 | 为什么没采用 |
|---|---|---|
| 城画像 + 采购选址（`aiCitySite`） | 小图 1↑1↓；大图 **0↑3↓** | 大图净负。"兵从后方来"的真因是**时代**，不是选址 |
| 升级选城（`aiHub`，枢纽城） | 小图 1↑2↓；大图 **0↑6↓** | 同上；顺带量出"平局终局 29~41 兵仍打不完" |
| 三件套（升级+出兵+守军让位） | 小图 **11-1-0（2↑1↓）**；大图 4-3-5 | 小图确实变好，但大图僵持更重；配套的收尾没做 |
| 废墟安全闸（`aiRuinSafe`） | 对基线 **0↑0↓**；叠三件套 2↑0↓ | 只给三件套配套；单开是空操作（基线本来不抢废墟） |
| "能不能走过去"按代价判（`aiReachCost`） | 小图 0↑0↓；大图 **0↑3↓** | 24 步上限本身在编码"绕远不如修桥"，换掉它 AI 就去绕路 |
| 攒钱按兵力比关闸 | 10-2-0 → **8-4-0** | 判据错：AI 用造价自评，并不认为自己落后 |
| 产出距离场（更早） | 21-3-0 → 19-3-2 | 净负，已回退 |

**共同点**：所有"小修"都在动同一批对局，而那批对局输/平的真正原因是
**兵再多也收不了尾**（Q4\|30\|A 开 P0 后 126 个兵、4848 金、陆路已通，261 回合没打完）。

## 4. 已确认、但没修的病灶（v3 就停在这里）

按"证据强度"排（新种子验收已经把第 1 条钉死：24×24 上 40~50% 的局是"打不完"）：

1. **收尾**：兵堆到 100+ 也打不完一座城。缺"投多少兵压上去"和"什么时候收手"
   （`commit` 门槛写死 8 兵；没有进攻配额）。**这是 v3 最大的洞。**
2. **攒钱没有出口**：只有"进入攒钱"和"暂停"两个开关，没有"放弃/重估/生死"三条出口。
   实测一局里 136 个回合停在 develop，账上 200~500 金不造兵。
3. **渡口**：选点不看"这片水有多宽能不能铺过去"；桥是建筑、要逐格造，修岔了就是纯亏。
4. **`canReach` 判据**：等步数 + `min(w,h)` 上限。宽浅流会被当成河（但改判据会牵动三处，见第 5 节）。
5. **海军**：只看"水占全图多少"+"陆路通不通"，不看这片水是不是死水（池塘里造船）。
6. **废墟接管**：不看周围有没有敌人，同一座城能被反复抢 20 次、花几千金。
7. **跑批的对手有缺陷**：v1（`baselines/ai-9efb961.ts`）**没有收废墟逻辑**，
   所以"对面占优也拿不到最后一座废墟"会拖成平局。看平局要带平局形状一起看。

## 5. 为什么不在 v3 上继续改

不是"改不动"，是**改一处的代价不可估**：

- 这条代码是从 v1 长出来的，`ai-v3.ts` 已经一万多行、十几个 `ai*` 开关；
- 同一个概念有好几份互相不一致的实现：
  "该守哪座城 / 该打哪座城 / 兵回哪座城"三个口径并存，
  "城"的角色没有唯一真相（这次想补，补到一半发现要同时改四处）；
- 关键判据是**隐式共享**的：`canReachEnemyByLand` 一句，同时被修桥计划、海军需求、
  决战判决（行军回合）吃。改它等于同时改三个系统——本轮实测就是这么翻车的（0↑3↓）。

**v4 的架构建议**（写在收尾时，免得忘）：

1. **一层服务，一份真相**：地形可达性/距离场做成带版本缓存的服务层，
   上层只能问"到某城要几回合/能不能走"，不许自己再算一张图。
2. **城的角色只有一个来源**：前线/后方/受威胁/要放弃，算一次，所有决策读同一份。
3. **三层决策**：意图（打不打、发展还是攒）→ 计划（怎么办）→ 动作（这一手）。
   下层反过来影响上层需要慎重。
4. **数量级先立住**：所有分数进入同一把尺子之前先归一化，否则"抢废墟 220 分"
   会比"打死一支骑士 132 分"还值。
