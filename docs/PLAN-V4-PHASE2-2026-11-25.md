## 0. 一句话

**阶段一修的是"该不该做"**（意图怎么定、格谁必须空、打谁、要不要挪一步）；
**阶段二修的是"资源往哪投"**——金币投给哪个兵种、投给升级还是投给兵、兵投给哪条战线。

这两件事分开做，是因为它们的失败形状不一样：阶段一的病是"动作不对"，阶段二的病是
**"动作全对，但每一分钱都花在最没用的地方"**。

## 2. 四个病灶（2026-11-25 实测，不是猜的）

### 2.1 有钱就买 1 代民兵（最刺眼，且是正反馈陷阱）

跑 `S-001 / S-002 / S-011` 全程，统计 v4 造了什么：

| 题 | 造兵 | 升级 | 结果 |
|---|---|---|---|
| S-001（我 20 个 3 代打 4 代 8 守军） | **民兵 ×21** | 0 次 | 25 手赢，但**损失 16 / 线 16** |
| S-002（30 打 12 个 4 代步枪兵） | **民兵 ×45** | 0 次 | 41 手**未分胜负** |
| S-011（12 打 1 炮 + 1 护卫） | **民兵 ×8** | 0 次 | 11 手赢 |

价格与属性（`recruitPriceOf` + `unitTypes`）：

| 兵 | 代 | 价 | 攻 | 射程 | 血 |
|---|---|---|---|---|---|
| 民兵 | 1 | **25** | 13 | **1** | 28 |
| 长枪兵 | 2 | 65 | 15 | 1 | 40 |
| 戟兵 | 3 | 100 | 21 | **2** | 46 |
| 火枪兵 | 3 | 130 | 23 | **4** | 36 |
| 步枪兵 | 4 | 200 | 36 | 4 | 38 |

**根因是三行代码叠在一起**：

```ts
// constrain.ts:1358 —— 质量门槛只在"人数不占优"时才有
const outnumbered = world.myCombat.length <= foes.length;
const need = foes.length > 0 && outnumbered ? {hp, atk} : undefined;

// world.ts:662 —— 候选池按价格升序
return out.sort((a, b) => a.gold - b.gold);

// tactics.ts:692 —— need 为空时，直接取第一个
const pick = ok.length > 0 ? ... : need ? ... : opts;   // opts[0] = 最便宜的 = 民兵
```

**为什么这是正反馈陷阱**（这条最重要）：

```
买民兵 → 我方人数上去了 → outnumbered = false → 质量门槛关掉 → 继续买民兵
```

所以它不只是"贪便宜"，而是**人数本身把质量闸关掉了**。S-002 的 45 个民兵打 12 个射程 4 的
步枪兵，摸都摸不到——41 手打不完，就是这么来的。

**注意 S-002 留过一条反向结论**（`constrain.ts` 的注释）："数量本身就是答案，硬按'挨得住一发'筛
会把便宜的量产兵全筛掉，实测 S-002 从绿变红"。所以第 1 步**不能简单地改成"永远按质量挑"**，
要保留"人多时可以堆量"，只是不许堆 **1 代**、不许堆射程 1 去打射程 4。

### 2.2 不会升级时代

`src/core/v4/` 里 grep 不到 `UPGRADE`（9.10 第 1 项）。引擎的 `doUpgrade` 做两件事：

1. 城 `maxHp` 与 `护甲` 涨上去（按两个时代的差值）；
2. **解锁这座城造更高代的兵**。

**注意：升级不会让已有的兵变强。** 所以"升级"只在两种情况下值：
① 要在这座城造高代兵；② 城要扛住。没有谁在算这笔账——包括把它和"再造 4 个民兵"比较。

### 2.3 编队堆积（投送）

S-001 实测：40 手里 **25 个兵只有 6 个过河**，56 次攻击有 **32 次是在西岸打的**。
v3 的老病也在这儿（`V3-BACKLOG`：大量编队堆在河边，建造编队靠不近、架不了桥）。

v4 的行军是"多起点 → 多终点、一人一格"（`planMarch`），窄地形会排队，
但**没有任何地方估计"排完队要几手"**。所以它不会因为"排不上"而改路线，也不会因为
"人太多挤不进去"而少派。

v3 的老账印证了同一件事（`V3-CLOSEOUT-2026-11-23.md` 第 80 行）：
"**渡口**：选点不看'这片水有多宽能不能铺过去'；桥是建筑、要逐格造，修岔了就是纯亏"。
同文第 65 行还有一条更反直觉的："`24 步上限`本身在编码'**绕远不如修桥**'"——
也就是说 v3 的"过河"决策是靠一个上限数隐式表达的，不是算出来的。

所以投送在 v4 里是**两层都缺**：① 怎么排队（行军）；② 要不要铺路（建筑，见 P7）。

### 2.4 行军只有一种目的

`press` 的目标只有"城 + 城下守军"。人类行军还有：

| 行为 | v4 现状 |
|---|---|
| 侦查未知区域 | 没有"去看"这个动作（9.10 第 2 项） |
| 预警重要关口 | 地形只被当"形状"读，没被当"价值"读（9.10 第 3 项）；`foeEta` 已经能算，但没人用它看关口 |
| 袭击敌方经济单位 | **`foeEcon` 这个概念不存在**（grep 不到），press 不打经济兵 |

所以用户那句"只考投送到城市下方无法实现这些"是对的：**投送是"怎么到"，不是"到了干什么"。**
两者要分开考。

## 3. 七步

排序依据只有一条：**先修"每一分钱都花错"（P1~P3），再修"兵怎么到"（P4），
再修"兵分到哪"（P5），最后修"看不见的地方"和"造东西"（P6~P7）。**

先说依赖：P5 依赖 P1（不然分出去的是民兵）；P3 依赖 P2（要先知道造兵值多少，才能比升级）；
P4 独立，随时可以插队。

### P1 采购·把"最便宜"换成"够用"（✅ 2026-11-25 15:20 完成）

- **解决**：2.1（民兵 ×21 / ×45 / ×8）。
- **怎么做**（三处，都在既有分层里）：
  1. `need` 去掉 `outnumbered`——**有敌人就按"够用"筛**，人数不再参与"要不要讲质量"；
  2. `need` 加 `range`（对面最大射程）；
  3. `tactics` 的排序：**价格从第一键挪到最后一键**；"先手"改成"**射程压过对面**才算"，
     压不过就比血（血薄的会被溅射一次清掉）。
- **"人数占优仍允许堆量"这条没有保留**（用户 2026-11-25 的判断）：人类会去**基建出最强的
  单位来堆**，不会靠血少攻低的单位堆。堆不堆量是"数量够不够"的问题（`planMains` 的 want 管），
  不该混进采购。S-002 那条"数量就是答案"的反向结论随之作废（那道题用户不管）。
- **结果**：

  | 题 | 改前 | 改后 |
  |---|---|---|
  | **S-012（采购 + 收尾）** | 红（敌损 1 / 金 634） | **绿（敌损 3 / 金 97）**，四颗种子 |
  | **S-001** | 绿（损 16 / 线 16） | 绿（**损 13**） |
  | S-002 | 绿\*（55/20） | 红（45/22）——用户不管 |
  | S-011 | 绿\*（默认种子 6/6） | 红（5/6，四颗种子）——见下 |
  | 其余 21 道 | — | 红绿与读数不变 |

- **S-011 掉 1 个的原因**：判据是"15 手内 ≥6 个到城下"，纯数量。以前靠 8 个民兵凑数，
  现在造 4 个更厚的兵（更贵 → 更少）→ 到 5 个。它不是"不敢冲"（11 手就赢了），是"兵少了"。
  **判据没动**——为了保绿去放宽手数就是改线挑结果。
- **`E-2-01` 没有按原题面出**（2026-11-25 修正）：原计划是"给 200 金、0 个战斗单位、无敌人，
  问造什么"。这个题面**测不到采购**，因为 `ai-v4.ts` 里有一条 `needArmy`：
  **看不见敌人 + 处于发展期 → 一个战斗兵都不造**（这是对的行为，S-015 就是靠它不乱花钱）。
  所以 v4 在这种局面里压根不会走到采购。
  **这反过来暴露了"发展·2"那一格的语义问题**："造什么战斗兵"必须有目的（打谁 / 守谁），
  没有目的就不该造——所以它**不属于发展轨**。这一格要么改成"经济兵选型"（S-015 已覆盖），
  要么并入 P2（有敌人时挑兵种）。**先空着，别硬填。**
- **风险（已发生）**：以"数量"为判据的题会掉——S-011 是第一个。以后碰到这类题，
  先分清"不敢冲"和"兵少了"，别一律当成退化。

### P3 升级（金币的第二个出口）

- **解决**：2.2。现在金币只有"造兵"一个出口，所以永远造兵。
- **怎么做**：约束层加一个**比较**（不是新机制）：这一笔钱用来升级，还是用来造兵？
  判据两条：① 对面代差 ≥1 且我造不出对应代的兵 → 升级；② 城血 < 一轮齐射 → 升级。
  其余情况造兵。
- **验收**：新题 `P-1-04`（敌 4 代城 + 4 代守军；我 3 代城、金 400、0 兵；
  问"先升级还是先造兵"），判据"N 手内城升到 4 代"或"N 手内造出 4 代兵"。
  S-001 不许为了升级而变慢（它靠数量能赢）。
- **风险**：**升级不会让已有兵变强**。如果新题里"升级"看起来没用，说明我把它的价值估高了——
  那就退回"只在城要扛的时候升级"。

### P4 投送（兵怎么到）

- **解决**：2.3（堆积、排队没人估）。
- **怎么做**：`planMarch` 加一个**期限估计**：这一队按当前路线到城下要几手（用 `marchTurns`），
  超过决定的期限就改（换集结 / 少派人 / 换路线）。**不加分数项**，只做"来不来得及"的二值判断。
- **验收**：新题 `P-2-01`（开阔地形 + 远城，判据"N 手内 K 个兵到城下"——像 S-005 那样数人头，
  不看 `win`）。
  **不要再用 S-001 的过河兵数当验收**（2026-11-25 复核：长弓/火枪射程 4、河只 1 格宽，
  西岸隔着河就能打城；它的判据只有 `win`，25 个兵只过河 6 个也照样赢）。
  过桥这件事另有前提：**先做 9.18 的方案 B**（挡路兵不摘出主队），否则一格宽的桥必然
  "归属在队里、这一手走不动"，排队无从谈起。
- **风险**：窄桥的排队是算术（9.16 的结论）。所以新题要**开阔地形**，别用桥；
  桥只作为"最难的一种"留在 S-005。

### P5 多编队（兵分到哪：分兵 / 袭击经济 / 守军站位）

- **解决**：2.4 的一半 + S-013 + 9.11。这三件事在代码里是**同一件事**：
  现在只有"一支部队 + 几个特殊队"，没有"按目的分预算"。
- **怎么做**：约束层把兵力分成"按目的"的几份（不是按位置），最少三份：
  主力（打城）、守城（按 `foeEta` 分到受威胁的城）、袭扰（去打敌方经济兵）。
- **验收**：① S-013 转绿（我城 2/2）；② 新题 `P-2-02`（敌方 2 个伐木工在远处，
  问"派不派兵去打"，判据"10 手内打死 ≥1 个经济兵"）；③ 9.11 的守军站位可以一起做。
  **③ 有个已测到的前提**（2026-11-25）：单做"站位带方向"**27 道零变化**，已回退。
  原因是 `hold` 队几乎只在 `foeEta <= 1` 时才成立，那时 `underFire`（进城吃 +3 甲）已经接管。
  所以顺序必须是**先有"野战守军"这个编制**（城留 1~2 人、其余推出去），再谈站位朝向。
  引擎的两条硬规则约束了编制长什么样：`cityRegenOf` 要**城格里有自己人**才回血（3/6），
  `siegeTargets` **不看城外守军**（站外面挡不住攻城）——所以是"留人守城 + 其余野战"，
  不是"全队出城"。
- **风险**：用户说过"分兵对人类都难，往后放"。放在 P5 是因为它需要 P1/P2 先稳
  （否则分出去的是民兵）。如果 P1/P2 不稳，**这一步不做**。
