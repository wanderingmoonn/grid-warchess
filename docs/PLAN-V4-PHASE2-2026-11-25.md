**阶段一修的是"该不该做"**（意图怎么定、格谁必须空、打谁、要不要挪一步）；

## 2. 四个病灶（2026-11-25 实测，不是猜的）

> **状态（23:50 复核）**：2.1 采购（P1 + P2）、2.2 升级（P3 的 A/B）都已修，
> 2.3 投送、2.4 分兵**还没修**——它们就是 P4 / P5。
> 四节保留原文不动，因为"当时怎么测出来的"比结论有用。

### 2.1 有钱就买 1 代民兵（最刺眼，且是正反馈陷阱）——✅ P1 + P2 已修

跑 `S-001 / S-002 / S-011` 全程，统计 v4 造了什么：

| 题 | 造兵 | 升级 | 结果 |
|---|---|---|---|
| S-001（我 20 个 3 代打 4 代 8 守军） | **民兵 ×21** | 0 次 | 25 手赢，但**损失 16 / 线 16** |
| S-002（30 打 12 个 4 代步枪兵） | **民兵 ×45** | 0 次 | 41 手**未分胜负** |
| S-011（12 打 1 炮 + 1 护卫） | **民兵 ×8** | 0 次 | 11 手赢 |

价格与属性（`recruitPriceOf` + `unitTypes`）：

| 兵 | 代 | 价 | 攻 | 射程 | 血 |
|---|---|---|---|---|---|
| 民兵 | 1 | **25** | 13 | **1** | 28 |
| 长枪兵 | 2 | 65 | 15 | 1 | 40 |
| 戟兵 | 3 | 100 | 21 | **2** | 46 |
| 火枪兵 | 3 | 130 | 23 | **4** | 36 |
| 步枪兵 | 4 | 200 | 36 | 4 | 38 |

**根因是三行代码叠在一起**：

```ts
// constrain.ts:1358 —— 质量门槛只在"人数不占优"时才有
const outnumbered = world.myCombat.length <= foes.length;
const need = foes.length > 0 && outnumbered ? {hp, atk} : undefined;

// world.ts:662 —— 候选池按价格升序
return out.sort((a, b) => a.gold - b.gold);

// tactics.ts:692 —— need 为空时，直接取第一个
const pick = ok.length > 0 ? ... : need ? ... : opts;   // opts[0] = 最便宜的 = 民兵
```

**为什么这是正反馈陷阱**（这条最重要）：

```
买民兵 → 我方人数上去了 → outnumbered = false → 质量门槛关掉 → 继续买民兵
```

所以它不只是"贪便宜"，而是**人数本身把质量闸关掉了**。S-002 的 45 个民兵打 12 个射程 4 的
步枪兵，摸都摸不到——41 手打不完，就是这么来的。

**注意 S-002 留过一条反向结论**（`constrain.ts` 的注释）："数量本身就是答案，硬按'挨得住一发'筛
会把便宜的量产兵全筛掉，实测 S-002 从绿变红"。所以第 1 步**不能简单地改成"永远按质量挑"**，
要保留"人多时可以堆量"，只是不许堆 **1 代**、不许堆射程 1 去打射程 4。

### 2.2 不会升级时代

`src/core/v4/` 里 grep 不到 `UPGRADE`（9.10 第 1 项）。引擎的 `doUpgrade` 做两件事：

1. 城 `maxHp` 与 `护甲` 涨上去（按两个时代的差值）；
2. **解锁这座城造更高代的兵**。

**注意：升级不会让已有的兵变强。** 所以"升级"只在两种情况下值：
① 要在这座城造高代兵；② 城要扛住。没有谁在算这笔账——包括把它和"再造 4 个民兵"比较。

### 2.3 编队堆积（投送）

S-001 实测：40 手里 **25 个兵只有 6 个过河**，56 次攻击有 **32 次是在西岸打的**。
v3 的老病也在这儿（`V3-BACKLOG`：大量编队堆在河边，建造编队靠不近、架不了桥）。

v4 的行军是"多起点 → 多终点、一人一格"（`planMarch`），窄地形会排队，
但**没有任何地方估计"排完队要几手"**。所以它不会因为"排不上"而改路线，也不会因为
"人太多挤不进去"而少派。

v3 的老账印证了同一件事（`V3-CLOSEOUT-2026-11-23.md` 第 80 行）：
"**渡口**：选点不看'这片水有多宽能不能铺过去'；桥是建筑、要逐格造，修岔了就是纯亏"。
同文第 65 行还有一条更反直觉的："`24 步上限`本身在编码'**绕远不如修桥**'"——
也就是说 v3 的"过河"决策是靠一个上限数隐式表达的，不是算出来的。

所以投送在 v4 里是**两层都缺**：① 怎么排队（行军）；② 要不要铺路（建筑，见 P7）。

### 2.4 行军只有一种目的

`press` 的目标只有"城 + 城下守军"。人类行军还有：

| 行为 | v4 现状 |
|---|---|
| 侦查未知区域 | 没有"去看"这个动作（9.10 第 2 项） |
| 预警重要关口 | 地形只被当"形状"读，没被当"价值"读（9.10 第 3 项）；`foeEta` 已经能算，但没人用它看关口 |
| 袭击敌方经济单位 | **`foeEcon` 这个概念不存在**（grep 不到），press 不打经济兵 |

所以用户那句"只考投送到城市下方无法实现这些"是对的：**投送是"怎么到"，不是"到了干什么"。**
两者要分开考。

## 3. 七步

排序依据只有一条：**先修"每一分钱都花错"（P1~P3），再修"兵怎么到"（P4），
再修"兵分到哪"（P5），最后修"看不见的地方"和"造东西"（P6~P7）。**

先说依赖：P5 依赖 P1（不然分出去的是民兵）；P3 依赖 P2（要先知道造兵值多少，才能比升级）；

### P1 采购·把"最便宜"换成"够用"（✅ 2026-11-25 15:20 完成）

- **解决**：2.1（民兵 ×21 / ×45 / ×8）。
- **怎么做**（三处，都在既有分层里）：
  1. `need` 去掉 `outnumbered`——**有敌人就按"够用"筛**，人数不再参与"要不要讲质量"；
  2. `need` 加 `range`（对面最大射程）；
  3. `tactics` 的排序：**价格从第一键挪到最后一键**；"先手"改成"**射程压过对面**才算"，
     压不过就比血（血薄的会被溅射一次清掉）。
- **"人数占优仍允许堆量"这条没有保留**（用户 2026-11-25 的判断）：人类会去**基建出最强的
  单位来堆**，不会靠血少攻低的单位堆。堆不堆量是"数量够不够"的问题（`planMains` 的 want 管），
  不该混进采购。S-002 那条"数量就是答案"的反向结论随之作废（那道题用户不管）。

### P5 多编队（兵分到哪：分兵 / 袭击经济 / 守军站位）

## 4. 不做清单（阶段一证伪的，别重试）

  后三者是"到了干什么"，必须分开考。

  克制是局部的（同一个兵对炮/对步枪/对坦克价值相反）。详见 `DESIGN-PURCHASE-CRITERIA`。

  记忆里的承诺（D5）；采购那处允许保留，但注释里必须写明"这不是升级的门"。
