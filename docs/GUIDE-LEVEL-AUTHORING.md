# 关卡模式开发指南

写给要加关卡、改地图的人。**不是引擎文档**，只讲"怎么写一张关卡、怎么验它"。

代码全在 `src/core/level.ts`。这个文件里从上到下是：类型定义 → 校验 → 建局换算 → 内建关卡表。

---

## 0. 先找对地方

| 想改什么 | 去哪 |
|---|---|
| 加一张新关卡 / 改现有关卡 | `src/core/level.ts` 的 `LEVELS` 数组 |
| 改地图地形 | 同一个关卡对象里的 `map.rows`，或者文件顶部的 `SOLO_PAINT` / `CUT_PAINT` / `TRI_PAINT` 这类坐标常量 |
| 改开局兵力 | 关卡对象的 `deploy` |
| 改事件 | 关卡对象的 `events` |
| 改胜负 | 关卡对象的 `goals` |

**"找不到在哪改地图"的标准答案**：`map.rows` 就是一张字符画，一行一个字符串，`.` 是平原、`~` 是水、`f` 是森林。直接改字符就行。

---

## 1. 画地图的两种写法

### 写法 A：直接写字符画（推荐，改起来最直观）

```ts
map: {
  id: 'levelmap:my-map',
  name: '我的图',
  w: 12,
  h: 8,
  rows: [
    '............',
    '............',
    '....f...f...',
    '~~~~=~~~~~~~',   // 一条横河，桥在中间
    '............',
    '............',
    '....f.......',
    '............',
  ],
  // 城的**左上角**坐标。注意：关卡里的城只写在这里，
  // 字符画里不能出现 A / B（那是"纯文本地图文件"那种格式的写法，见下面）
  citiesA: [{ x: 1, y: 1 }],
  citiesB: [{ x: 8, y: 5 }],
  source: 'builtin',
},
```

规则：`rows.length === h`，每行长度 `=== w`，`w`/`h` 都在 **8~40** 之间。
`citiesA` / `citiesB` 是城的**左上角**坐标，城默认占 2×2（`config.citySize` 可改）。

> **两种写城的方式别混**：
> - **关卡对象里**（`level.ts`）：城写在 `citiesA` / `citiesB` 坐标里，字符画里**不能出现 `A`/`B`**，会被校验拒掉。
> - **纯文本地图文件里**（`.txt` 上传）：可以用 `A`/`B` 标城，解析时会被抽成坐标并替换成 `.`。
>
> 这是两套格式。关卡是代码，直接给坐标；文本文件是给人手写的，才需要字母占位。

**字符表**（`TERRAIN_CHARS`，写错一个字母整张图会被拒）：

| 字符 | 地形 | 备注 |
|---|---|---|
| `.` | 平原 | 城不单独占字符，格子是不是城由 `citiesA/B` 决定 |
| `f` | 森林 | 掩护 |
| `h` | 丘陵 | 视野/防御 |
| `~` | 水域 | 陆军过不去 |
| `s` | 浅流 | 陆军能涉水（一步算两格） |
| `D` | 深水 | 只有船能进 |
| `^` | 山 | 不可通行 |
| `=` | 桥面 | **见下面的坑 3** |
| `P` | 台地 | |
| `v` | 谷地 | |
| `w` | 沼泽 | |
| `d` | 沙丘 | |
| `r` / `c` | 月壤 / 环形山 | 月球图用 |
| `#` / `_` / `%` | 虚空 / 甲板 / 破口 | 空间站专用，地表图不要用 |

### 写法 B：坐标列表（适合程序生成 / 成片刷地形）

```ts
const MY_PAINT: Array<[number, number, string]> = [
  [7, 7, '~'], [7, 8, '~'],
  [4, 4, 'f'], [5, 4, 'f'],
];
// 用的时候：
rows: rowsOf(14, 14, MY_PAINT),
```

好处是"只写跟平原不一样的那几格"，改一个坐标不影响别的。

### 写法 C：上帝模式画完导出（不想手敲字符就用这个）

1. 开一局**上帝模式**（沙盒）；
2. 左侧有地形笔刷，直接在棋盘上刷；
3. 打开地图面板（`god-map-upload`），点**「复制文本」**；
4. 粘进关卡的 `rows`。

刷子和引擎用的是同一套地形定义，导出的字符和手写的完全一样。

## 2. 一张关卡由什么组成

```ts
{
  id: 'level:xxx',          // 必填，全局唯一
  version: LEVEL_VERSION,   // 照抄
  name: '孤城',              // 最多 24 字
  brief: '一句话，会印在选关卡片上',
  map: { ... },
  seats: { ... },           // 几家、谁托管、谁晚到
  setup: { ... },           // 锁死开局时代 / 先手
  deploy: { ... },          // 开局摆兵（一写就替代自动撒兵）
  events: [ ... ],          // 什么时候发生什么
  goals: [ ... ],           // 怎么算赢
  units: { ... },           // 这一关独有的兵种（可选）
  expansions: { ... },      // 必须开 / 必须禁的扩展包（可选）
  dev: true,                // 测试夹具：不进玩家菜单（可选）
}
```

## 3. 席位 `seats`

```ts
seats: {
  count: 3,                              // 2 | 3 | 4
  cities: { C: [{ x: 12, y: 12 }] },     // 第三、四家的城（A/B 用 map.citiesA/B）
  ai: ['B', 'C'],                        // 谁交给电脑；不写 = 全是真人
  hidden: ['C'],                         // 开局不在场上（见下）
  cityEra: { C: 2 },                     // 这一席的城一开局就是铁器
}
```

- **`count: 3` 就必须给 C 的城，`4` 就 C 和 D 都要给**。没城的席位第一回合就被判出局（出局的定义就是"城全丢光"），校验会拦。
- **`hidden`（未登场）**：开局没有城、没有兵、不占回合、不算出局，也不参与"还剩几家"的统计。靠一个 `deploy` 事件把它叫上场。
- **`cityEra`（逐席时代）**：城的时代本来就是逐城独立的（收入、可造兵种、升级都读它）。这里只是让某一席的城一开局就是高一级的。注意**时代的领先是暂时的**——玩家花两三次金币就追平了，想让"晚到的一家"真的强，要靠它入场那一刻的兵力和兵种，别指望科技差一直压着。

## 4. 开局设定 `setup`（锁死玩家的自由度）

```ts
setup: { startEra: 1, firstSide: 'A', twoCities: false }
```

**写了就锁，没写就归玩家。**

- `startEra`：**这条最重要**。时代直接决定开局金币（青铜 120，每升一级 +240）。一张"3 个兵守 20 次行动"的关，玩家把时代调到信息化，光开局那笔钱就能堆出一条防线——难度设计当场失效。锁了时代就等于锁了金币。
- `firstSide`：只收 `'A' | 'B'`。多人局的先手是随种子抽的（席位顺序牵着城位），关卡指定不了。
- 面板上对应的按钮会整个消失（不是灰掉），简报页会写明"这一关固定：青铜时代（开局 120 金）"。

**规则层也认**：`createMatch` 里是 `level.setup.startEra ?? config.startEra`。只锁界面不够——config 会跟着存档、房间、分享链接一路传。

## 5. 开局兵力 `deploy`

```ts
deploy: {
  A: [{ type: 'militia', x: 3, y: 6 }, { type: 'archer', x: 3, y: 7 }],
  B: [{ type: 'militia', x: 9, y: 3 }, { type: 'farmer', x: 13, y: 3 }],
}
```

- **一旦给某一席写了 `deploy`，那一席就不再自动撒兵**（包括经济单位）。所以想要农民就得自己写进去。
- 坐标必须是**站的住**的格子（不能是水、山、别人的城）。站不住会被跳过，并在战报里留一句"关卡部署里的 X 摆不上去"——**不报错，就是不生效**，所以要自己看一眼战报。
- 兵种只能写本局存在的（默认 = 玩家能造的那些）。

**常用兵种速查**（青铜时代，设计摆兵时最常算的就是这几个数）：

| 兵种 | id | 血 | 移 | 射程 | 说明 |
|---|---|---|---|---|---|
| 民兵 | `militia` | 28 | 2 | 1 | |
| 戈兵 | `ge` | 30 | 2 | 1 | |
| 弓手 | `archer` | 22 | 2 | **3** | 射程是 3，比直觉远 |
| 斥候 | `scout` | 26 | **4** | 1 | 高机动 |
| 农民 | `farmer` | 16 | 2 | 1 | 经济单位 |
| 箭塔 | `tower` | 30 | 0 | 3 | 建筑，**占格且不可通行** |
| 木桥 | `bridge` | 40 | 0 | 0 | 建筑，架在水上 |

顺带：`archer` 射程 3 这条最容易算错。河宽 1 格 = 距离 2，弓手站自家岸边就能打对岸；河宽 2 格 = 距离 3，刚好还是够得着。**要真的隔开，得河宽 2 格 + 把目标再往后推一格。**

## 6. 事件 `events`

```ts
events: [
  {
    id: 'blow',                       // 必填，全局唯一（这条事件只触发一次，靠它记）
    when: { kind: 'turn', at: 9 },
    do: [
      { kind: 'say', text: '桥被炸断了。' },
      { kind: 'terrain', zone: { x0: 7, y0: 7, x1: 8, y1: 7 }, to: 'deep' },
    ],
  },
]
```

### 什么时候触发（`when`）

| 形状 | 含义 |
|---|---|
| `{ kind: 'turn', at: 9 }` | 第 9 次**行动**（不是第 9 轮；两家局一轮 = 两次行动） |
| `{ kind: 'unitDied', owner: 'A' }` | A 的任何兵死了（可再加 `type` 限定兵种） |
| `{ kind: 'enter', zone: {...} }` | 有单位走进区域（可加 `owner` 限定） |

默认每条只触发一次。`enter` 想反复触发要写 `repeat: true`。

### 做什么（`do`）

| 形状 | 作用 |
|---|---|
| `{ kind: 'say', text }` | 往战报里写一句（双方都看得到） |
| `{ kind: 'spawn', owner, units }` | 凭空刷兵，**不看钱不看产线**，只看格子站不站得住 |
| `{ kind: 'doctrine', seat, strategy }` | 改这一席电脑的打法：`'auto' \| 'rush' \| 'boom' \| 'hold'` |
| `{ kind: 'deploy', seat }` | 让 `hidden` 里的某一席上场（放城 + 摆它在 `deploy` 里写好的兵） |
| `{ kind: 'terrain', zone, to, only? }` | 改地形（炸桥、塌方、水淹） |

**`terrain` 的三条兜底**（引擎做，作者不用管）：
1. 城格跳过；
2. 格上站着兵就挤到最近能站的空地，挤不到才没了（会说一声）；
3. 必须播报——所以记得配一句 `say`，并且那几格会闪一下。

`only` 用来限定"只改原本是这些地形的格子"，比如"只让河水退，别把桥墩也变浅"：
`{ to: 'shallow', only: ['water'] }`。

**能改成什么**：`plain / forest / hill / water / shallow / deep / mountain / plateau / valley / marsh / dune / regolith / crater`。
**不能改成** `city`（城有自己的机制）、`void`（"这里还没铺"）、`bridge`（见坑 4）。

## 7. 胜利条件 `goals`

```ts
goals: [
  { kind: 'survive', seat: 'A', untilTurn: 30 },
  { kind: 'assassinate', winner: 'A', loser: 'B', unitType: 'warden', label: '守将' },
]
```

| 形状 | 含义 |
|---|---|
| `{ kind: 'survive', seat, untilTurn }` | 某一席守到第 N 次行动还活着就赢 |
| `{ kind: 'escort', seat, zone, unitType? }` | 某一席的兵走进区域就赢 |
| `{ kind: 'assassinate', winner, loser, unitType?, label? }` | `loser` 场上再没有这个兵种时，`winner` 赢 |

**多条 goal 同时挂着时，按数组顺序判，先成立的赢。** 想表达"限时击杀"，就用：

```ts
goals: [
  { kind: 'assassinate', winner: 'A', loser: 'B', unitType: 'warden' },  // 写前面 = 玩家优先
  { kind: 'survive', seat: 'B', untilTurn: 18 },                          // 敌方撑住就赢
]
```

不需要给胜负判断加任何新东西。

**注意**：goal 只是"额外的胜负捷径"，**没有取消默认判定**——城丢光、兵打光照样按普通规则判输。所以守城关不用另写一条失败条件。

## 8. 关卡独有兵种 `units`

```ts
units: {
  warden: {
    id: 'warden', name: '守将', short: '将',
    era: 1, category: 'combat',
    cost: 60, move: 2, atk: 18, armor: 9, maxHp: 70, range: 1, vision: 3,
    summonedOnly: true,   // ← 关键
  },
}
```

- 这些兵种**不进全局表**：别的对局看不到、规则书里没有、AI 也不会采购。
- `summonedOnly: true` 的语义是"**不进产线、AI 不采购**"，正好就是"只此一个、谁也造不出"。想做"斩杀某个特定单位"，必须用它——普通兵种对面会一边死一边补，`assassinate` 永远不会成立。
- `id` 以 map 的 key 为准（写 `warden: { id: 'xxx' }` 会被纠正成 key）。

## 8.5 关卡专属 AI `ai`

同一套 AI 要在"渡过一条窄河攻坚"和"守着一个人别送死"里都表现正常，靠全局参数做不到。
关卡可以带一份自己的调节：

```ts
ai: { riskAversion: 0.6, cohesion: 0.4, appetite: 1.5 }
```

| 字段 | 范围 | 默认 | 作用 |
|---|---|---|---|
| `riskAversion` | 0.2~2 | 1 | **进攻性主旋钮**。AI 走一格要算"这落点会挨多少打"，再拿它抵掉推进收益。调小 = 愿意用伤亡换推进；调大 = 极度惜命 |
| `cohesion` | 0~2 | 1 | 战线收拢强度。AI 会让"跑得太靠前"的停下等队友（推进分砍到 15%）。0 = 谁快谁先上 |
| `appetite` | 0.2~3 | 1 | 放大/缩小"朝目标推进"的分数 |

**什么时候用**：

- 关卡要"敌人压过来"：`riskAversion: 0.5~0.7`，配合 `cohesion: 0.3~0.5`。
- 关卡要"某个单位别死"（护主、护送）：`riskAversion: 1.5`。
- 写错了会被夹回区间，不会让整张图被拒。

**但要知道它的边界**：这几个参数只改"评分里的几笔账"，改不动 AI 的**投送能力**。
实测（孤城：两格宽的河 + 一座桥）：把 `riskAversion` 压到 0.3、`cohesion` 归零，
过河的人数从 3 变成 4，守方城的血**一滴没掉**——因为它过河之后就停住堵在桥头，
后面的人被自己的部队和窄通道卡住。

**所以真正的重压力关卡，别指望 AI 自己过来，要用事件把兵送过去**：

```ts
// 关卡自带兵种：从边缘奔袭的骑兵
units: {
  raider: { id: 'raider', name: '游骑', short: '骑', era: 2, category: 'combat',
            cost: 95, move: 4, atk: 16, armor: 3, maxHp: 36, range: 1, vision: 3,
            summonedOnly: true },
},

// 从地图南北边缘进场
{ id: 'flank-north', when: { kind: 'turn', at: 14 },
  do: [{ kind: 'say', text: '北边的林线上冒出人影——是骑兵。' },
       { kind: 'spawn', owner: 'B', units: [
         { type: 'raider', x: 2, y: 0 }, { type: 'raider', x: 3, y: 0 }] }] }
```

四条经验：
1. **落点在对方那一侧的边缘**，不是对方身边。试过直接送到玩家腹地——玩家的第一反应是
   "AI 在耍赖"，不是"远处来了援军"。从画面外跑进来才叫合围。
2. **用高机动兵种**：骑兵 `move 4` 才有包抄的味道；`move 3` 的会被一步步点掉，
   逼不出分兵。
3. **时间要早**——晚到第 16 次以后，守方已经攒了六七个兵，两三个兵落地就被吃掉。
4. **每波都要播报**，否则玩家只看到"忽然多出几个人"。

## 9. 扩展包规则 `expansions`

```ts
expansions: {
  require: ['last-stand'],                    // 这一关必须开
  forbid: ['turn-order-comp'],                // 这一关必须禁
  warn: ['blitz', 'high-mobility'],           // 能开，但会明显变难——只提醒，不锁
}
```

| 档位 | 行为 | 用在什么场合 |
|---|---|---|
| `require` | 强制勾上且点不动 | 这一关的玩法依赖它（比如守城关要「哀兵必胜」） |
| `forbid` | 强制空着且点不动 | 它会**抹掉这一关的设计前提**（比如先后手补偿会填平 1 城对 2 城的强弱差） |
| `warn` | 照常可勾，只在简报页和条目上标「这一关会变难」 | 它不会破坏设计，只是把难度推到你没调过的区间 |

**三者的区别**：前两个是关卡对规则的硬要求，玩家没得选；`warn` 是作者的建议——
玩家想挑战就该让他试，但得先说一声。别把"会变难"写成 `forbid`：那等于替玩家做了决定。

**没提到的一律归玩家**——这是有意的：玩家可以换一套包重打同一张关，那是重玩价值。

## 10. 收进菜单 / 标成夹具

- 默认**会**出现在玩家选关列表里。
- 加 `dev: true` 就不出现，但**仍留在注册表里**——探针二十多段测试靠这些夹具跑，删了就丢回归覆盖。

菜单用 `playableLevels()`（过滤 dev），探针和内部跳转用 `allLevels()`。

## 11. 改完怎么验

```bash
npm run probe:level     # 关卡探针：注册表校验 + 二十多段机制断言
npm run test:ui         # 界面：选关卡片、简报页、抽屉
npm run test:rules      # 规则内核（关卡改动一般不会碰，但跑一下放心）
```

改完关卡**至少跑前两条**。探针第 1 段会把 `LEVELS` 里每张关卡过一遍校验，写错一个字段就会直接报出来。

想单独看某张关的实际效果，用 AI 对 AI 跑几局：

```bash
node --experimental-strip-types -e "
import('./src/core/level.ts').then(async (L) => {
  const { createMatch, DEFAULT_CONFIG } = await import('./src/core/setup.ts');
  const { applyAction } = await import('./src/core/rules.ts');
  const { aiNextAction } = await import('./src/core/ai.ts');
  for (const seed of [3, 21, 77]) {
    let s = createMatch({ ...DEFAULT_CONFIG, level: L.levelById('level:我的关') }, seed);
    for (let n = 0; n < 900 && !s.winner; n++) {
      const r = applyAction(s, aiNextAction(s) ?? { type: 'END_TURN' });
      s = r.ok ? r.state : applyAction(s, { type: 'END_TURN' }).state;
    }
    console.log(seed, s.winner, s.turn);
  }
});"
```

> **别把 AI 对 AI 的结果当成"这关好玩/难打"**。电脑不会集结兵力撕口子、不会保护关键单位、
> 地形一变也不会重新选路。它能告诉你"这关能不能跑完"，不能告诉你"打起来爽不爽"。

## 12. 十三个坑（都是踩过的）

1. **`archer` 射程 3，不是 2**。想隔开一段距离，算的时候按 3 算。
2. **时代锁 = 金币锁**。不锁 `startEra`，玩家调高时代就能靠开局金币堆防线。
3. **地图上的桥没有单位撑着，但它不该自己塌**。引擎在 `state.mapBridges` 里记了"地图自带的桥面"，`syncBridges` 会跳过它们。你自己画 `=` 是安全的。（2026-11-15 之前的版本不是，那会儿地图桥第一步就塌，站在上面的兵直接落水。）
4. **事件不能把地形改成 `bridge`**。桥面由桥单位维持，`syncBridges` 每步对账，事件写的桥面会在下一手被悄悄改回水面。要修桥就让工兵去修。
5. **城格改不了**。城压在格子上、格子指向城，把城格改成水会得到一座悬空的城。引擎跳过，但你别指望它生效。
6. **`deploy` 一写就替代自动撒兵**。写了 `deploy` 的那一席不会有系统送的经济单位，农民要自己写。
7. **坐标落到城格/水上会被静默跳过**。战报里有一句"摆不上去"，但很容易被忽略。改完城位之后**一定要回头检查所有 spawn 坐标**——我改孤城的城位时，两波援军就落到了城格上，白刷了。
8. **`hidden` 的席位必须靠 `deploy` 事件上场**。没人叫它，它就永远不来，而"还剩几家"也不会算它。
9. **`assassinate` 的目标必须是造不出来的兵种**，否则对方一直补，条件永远不成立。写错兵种 id 时（本局没有这个兵种）目标会**直接不成立**而不是白送胜利——这是保护，不是 bug。
10. **"桥宽"说的是过河方向的通行格数，不是桥跨了几列河**。河是竖的、过河走横向，
    所以通行口宽不宽只看桥面在 **y 方向**占了几个格子。只画 `(7,7)(8,7)` 是"跨过两列河、
    只开一个口子"，还是一个兵堵得死；要两条通道，桥面得是 `(7,7)(8,7)(7,8)(8,8)` 四格。
    改完记得把炸桥事件的 `zone` 也跟着盖住四格——少写一行，桥就只塌一半，
    看起来像"炸桥没生效"。
11. **改完地图要开新局看，旧存档跑的是快照**。`createMatch` 把关卡**整包**快照进
    `config.level`，事件、城位、部署全从快照读——所以存下来的对局是自洽的，
    只是不含你的新改动。启动时 `loadMatch()` 优先于 `createMatch()`，
    于是"我改了图，外面预览变了、进去没变"十有八九是在续旧档。
13. **关卡校验没过时，这一局会静默按随机地图开**。看起来就是"点孤城进去是张随机图"，
    而真实原因在某个字段上——最常见的是**两个兵写在同一个坐标**（复制粘贴时忘了改）、
    某一行长度不等于 `w`、或者字符表里没有的字母。
    控制台会打一行 `[关卡] 「xxx」过不了校验`，但最快的办法是跑 `npm run probe:level`，
    第 1 段会把每张关卡的错因逐条列出来。
12. **回合数说的是"行动序号"**。两家局一轮 = 两次行动。写 `untilTurn: 30` 大约等于 15 轮；顶栏显示的是行动序号，所以玩家会看到"第 30 回合"。

## 14. 设计检查清单

写一张新关之前，先回答这五个问题：

- [ ] **这一关教什么？** 一张图只教一件事，不要又炸桥又夜袭又三方混战。
- [ ] **玩家的"安全位"在哪？** 如果他有一处站着不掉血、还能输出，压力就等于零。地形挡人的时候，也要问它挡不挡视野、封不封得住输出。
- [ ] **玩家能绕开设计意图吗？** 比如"守住 N 回合"的关，如果他能反攻灭掉对方，那也是一种赢——想清楚这算不算数。
- [ ] **时长多少？** 30 次行动（约 15 轮）大概是一局人的耐心上限；再长要保证每 3~4 轮有新东西。
- [ ] **输了知道为什么吗？** 三种输法（城破 / 首领跑了 / 时间到）体验完全不同，靠播报把它们区分开。
