## 0. 一句话

**先让每个判断都有主人，再谈判断对不对。**

D1~D3 是**搬家**：把已经写好的判断搬到该在的层，判据一个字不改，所以 33 道题的读数必须
**一字不变**（变了就是搬错了）。只有 D4/D5 才换判据，因为要换掉的正是"用状态门治沉没成本"
这种补丁本身。

## 1. 为什么插队

### 1.1 v1/v3 的死法是"判断和动作混在一处"

v3 六千行系数、每步重新评估、判据和动作写在同一段里——所以出了问题只能看到
"这局输了"，看不到"是哪一条判断错了"。**同一个问题在两处各有一个答案**，就是它的病根
（`V3-BACKLOG`：`24 步上限` 隐式编码了"绕远不如修桥"，没人算过这笔账）。

### 1.2 v4 骨架对了，但"钱"没有主人

`decide.ts` 通篇**不读金币**（只比"我方兵的身价总和"对"对方兵的身价总和"）。
于是第二阶段要修的整件事——钱给哪个兵种、给升级还是给兵、给经济还是给兵——
全部落在下面两层，甚至落在入口的动作顺序里：

| # | 判断 | 现在在哪 | 病 |
|---|---|---|---|
| 1 | 造经济兵还是战斗兵 | `ai-v4.ts:275` 入口里的一个布尔（`preferEcon`） | 最典型的战略取舍，写在动作选择器里 |
| 2 | 看不见敌人就不造兵 | `ai-v4.ts:284`（`needArmy`） | 同上；它让 `E-2-01` 压根走不到采购 |
| 3 | 攒钱接管废墟 | 三处各写一半：`decide.ts` 判阶段、`constrain.ts:1680` 压上限、`ai-v4.ts:274` 又判一次 | 同一句话三个读者，谁改都怕 |
| 4 | 应急升级（城快塌才升） | `constrain.ts:488`（`planUpgrade`） | **决定层完全不知道**；和"守/攻"是两套互不通气的守城模型 |
| 5 | 每格战力升级（钱花不完就升代） | `constrain.ts:616`（`planUpgradeEcon`） | 同上，而且用"场上有兵就永久不规划"来治漂移 |
| 6 | 城还能撑几轮 | `constrain.ts:521`（计划层自己算） | 决定层想用也用不到——它在计划层后面才跑 |

还有两处"算完没人读"：
- `Constraints.upgrade.why`（`types.ts:294`）写了"城 2 轮会塌、升完能撑几轮"，**全项目没有读者**，
  回放和面板都不带升级（`v4Snapshot` 只交 decision / squads / keepClear）。
- `project.ts` 的投影（先投经济到第几手、升到第几代）只打印（C2 的验收），**没有接线**。

最后一条**顺序依赖**：入口把动作排成
「让开 → 打 → **升级** → 造兵 → 走」（`ai-v4.ts:244`）。
"升级优先于造兵"是一条资源取舍，却只能靠代码行的位置表达——没人能反驳它，
也没有任何一层的输出里能看见它。

### 1.3 为什么不能直接做 P4 / C3

- **C3**（发展期投到第几手）的输出是"投到第 k 手、升到第几代"。如果照现在的形状接，
  这个结论会落在计划层——等于**再造一个游离点**，而且它读的 T 现在有两个意思（见 D2）。
- **P4**（投送）的判据是"这一队到城下要几手、超过期限就改"。这个"期限"就是 D2 要统一的那个数；
  不先统一，P4 会发明第二套期限。

所以顺序是：**D（本文件）→ P4（顺带吃掉 C3 的题）→ P5**。

## 2. 目标形状

三条铁律（后面每一步都按这个检查）：

1. **枚举属于服务层，选择属于决定层，价格与可行性属于计划层。**
   "每一代每格能打出多少"是数据（服务层枚举）；"升到第 3 代"是一句能被人反驳的话（决定层）；
   "要 580 金、这条路封着"是翻译（计划层）。
2. **同一个问题只准有一处回答。** "守得住吗""钱够不够""造不造兵"——各只能有一个主人。
   出现第二个答案，就是下一次"不知道哪个参数错了"。
3. **入口只剩"排序 + 派动作"。** 除了缓存键（`keyOf` 里的金币是"局面变了的指纹"，不是判断），
   入口不许再出现资源判断。

```
GameState
   ↓
服务层 world.ts        事实：距离 / 威胁 / 收入 / 城能撑几轮 / 每一代的每格战力
   ↓
决定层 decide.ts       做什么 + 期限 + **资源段落**（攒钱 / 投经济 / 造兵 / 救城 + 上限 + 升级目标）
   ↓
计划层 constrain.ts    翻译：哪座城 / 哪几格 / 谁归哪队 / 钱够不够 / 路线通不通
   ↓
动作层 tactics.ts      照做：一个动作
```

决定层新增的字段（**上限 4 个，只准枚举、金额、期限、一句话理由，禁止分数**）：

```ts
spend: {
  mode: 'save' | 'econ' | 'army' | 'wall',  // 攒钱(接管废墟) / 投经济 / 造兵 / 救城
  cap?: number,        // 这一段最多花多少（接管时 = 金币 − 重建费）
  untilTurn: number,   // 和决定共用同一个期限
  why: string,         // 一句话，能被人反驳
}
upgrade?: { cityId: string; targetEra: number; why: string }  // 只由决定层给
```

## 3. 六步

> **进度（2026-11-26 00:00）**：**D1 ✅ · D2 ✅** · D3~D6 未做。

每步都必须单独提交、单独回退。**判据"零变化"是指 33 道题的结论 + 记录项

### D1 决定层开口：加"资源段落"（纯搬家，零变化）

- **做什么**：把上表第 1~3 条搬进 `decide`，判据一个字不改：
  - 接管废墟的 save 阶段 → `mode:'save'`、`cap = 金币 − 重建费`；
  - 发展期或看不见敌人 → `mode:'econ'`；发展期且看不见敌人 → 明确写"不造兵"；
  - 其余 → `mode:'army'`。
  计划层的 `spendCap` 改成读 `decision.spend.cap`；入口删掉 `preferEcon / needArmy / saving`
  三个局部量。
- **为什么先做这步**：后面 D4 要给"救城"分钱，必须先有一个能装钱的字段。
- **判据**：33 题读数一字不变。**变了就是搬错了，不准顺手改判据。**
- **验收**：`v4Snapshot` 能打印出 `spend.mode / cap / why`；`grep preferEcon ai-v4.ts` 归零。
- **风险**：决定的**沿用机制**（`mem.decision` 在 `untilTurn` 内复用）必须把 `spend` 一起带过去，
  否则会出现"沿用了决定、忘了沿用资源段"的默认值 bug。沿用分支逐一检查。

**(D1 完成记录，2026-11-25 23:58)**：

- 形状：`Decision.spend = { mode, cap?, untilTurn, why }`，`mode` 四个取值
  `save / econOnly / econThenArmy / army`（`types.ts` 的 `SpendMode`）。
  `spend` **必填**——漏一个 return 就编译不过，不用靠肉眼查"忘了抄"。
- 判据原样搬进 `decide.ts` 的 `withSpend`（三条二值判断，一个字没改）；
  约束层的 `spendCap` 改成 `decision.spend.mode === 'save' ? decision.spend.cap : undefined`
  （只转发，不再自己算"金币 − 重建费"）；入口那三个局部布尔删掉。
- **验证**：33 题 × v4 **逐字节比对全部一致**（`.tmp/d1-before` vs `.tmp/d1-after`，
  用 `diff -rq` 而不是只看红绿）；`npx tsc --noEmit` 干净；`npm test` 21/21；
  矩阵仍是 空壳 0 / v1 20 / v3 14 / **v4 29**。
- 探针 `scripts/probe-v4.ts` 新增"钱："一行，四种模式都实测到了：
  `E-2-01` econOnly、`S-013` econThenArmy、`D-1-01` army、`T-2-01` save。
  面板（`v4-hud`）同步显示模式 + 上限 + 一句话。
- **一个语义说明**：接管废墟的 `enter` 段（钱已经够了）也归 `save`——因为这一手的钱
  要留给重建费、花掉就进不了城。行为与改动前一致，只是把理由写准了
  （原来会显示"钱够了还在攒钱"）。这条留给 D4 一起想。

### D2 统一"发展期还剩几手"的口径（纯搬家，零变化）

- **做什么**：现在同一个 T 有两个意思——投影（`project.ts`）当它是**窗口长度**
  （从第 1 手数到第 T 手），升级闸（`constrain.ts:623`）当它是**绝对回合号**
  （`left = T − 当前手数`）。而 `planHorizon` 算出来的 T 是"主力走到敌城要几手"，是长度。
  所以"剩余手数"被少算了"当前手数"那么多：第 1 手少 1、第 6 手少 6，到第 T 手直接变 0，
  **闸门自己静默关掉**。
  统一成：服务层只给 `horizon.left`（还能发展几手，长度），所有读者读同一个数。
- **判据**：`grep "horizon.*s.turn"` 归零（只有打印"看到第几手"那一处允许出现 `s.turn + left`）。
- **验收**：`V4_HORIZON_LOG=1` 的单手打印，四颗种子一致；33 题零变化。
- **风险**：现在这个坑被 D5 要拆掉的"有兵就不规划"挡着，改完会**首次暴露**——
  所以 D2 必须排在 D5 之前，别让两个变化同时上线。

**(D2 完成记录，2026-11-26 00:00)**：

- 形状：`Constraints.horizon` 的字段从 `turns` 改名 **`left`**，含义写死成
  "**从现在起还要几手**（长度）"。升级闸直接用它，`constrain.ts:623` 的 `T - s.turn` 删掉。
  改名的理由不是好看：`turns` 看不出"这是长度还是第几手"，而歧义就是两处读者各理解成一样的来源。
- **实测这个数真的变了**：`E-2-03` 第 1 手 `left=7`（改前 `7 − 1 = 6`）。
  升级理由从"4格×6手×30"变成"4格×7手×30"，算出来的产能从 24 个变成 28 个——
  **但选的代没变（还是 3 代）**，所以 33 题读数逐字节一致。
- 另一个副作用（好的）：`left` 每手按**当前阵位**重算，队伍越走越近它就越小，
  于是"发展期结束"由**实际行军距离**表达，不再由"第几手"表达。地图兜底那一路
  仍是静态（城到城的距离），所以它不会自己关——那要等 D5 的承诺。
- **验证**：33 题逐字节一致（`.tmp/d1-after` vs `.tmp/d2-after`）；`npx tsc --noEmit` 干净；
  `npm test` 21/21。探针新增"升级："一行（顺手为 D4/D6 铺路）。

### D3 服务层补"这座城还能撑几轮"（纯搬家，零变化）

- **做什么**：`world.cityStand(city)` 返回两个数：按当前能打到的敌人**逐轮推进**
  还能撑几轮；升一级后能撑几轮。
  "逐轮推进"= 第 1 轮只有射程内的人开火，第 2 轮才把走得到的人加进来。
  现在的算法（`constrain.ts:510`）把"两轮内能到"的敌人按**现在就在全额开火**算，
  所以"还能撑几轮"偏小、更容易被判成"2 轮就塌"。
- **为什么放服务层**：决定层跑在计划层**之前**，它想让"要不要救城"用这个数，
  就只能把算法放到服务层（"算一次，全层读"）。
- **判据**：单城、单敌人、贴在城边 vs 隔 2 格两个例子，人工手算能对上。
- **验收**：`P-1-03` / `P-1-04` 打印出两个轮数，与手算一致；33 题零变化
  （此时还没人读它，只打印）。
- **风险**：`burst`（一回合多段）必须乘进去——这条已经踩过（P-1-04 漏了它，
  装甲车被当成 14/轮，实际 28/轮）。

### D4 升级的"要不要"上移到决定层（**换判据**）

- **做什么**：分三块切开：
  | 谁 | 管什么 |
  |---|---|
  | 服务层 | 枚举：每一代的升级累计价、这一代每格战力最强的兵、那一格值多少（`eraLadder`） |
  | 决定层 | 选择：读 `cityStand` + `eraLadder`，按三条**二值**规则给 `spend.mode` 和 `upgrade.targetEra` |
  | 计划层 | 翻译：路线通不通、钱够不够、升完还剩不剩一个打得穿的兵；不过就否掉并写原因 |

  三条二值规则（就是现有闸 A / 闸 B 的判据，只是换了位置）：
  1. 撑不过 2 轮 **且** 升完多撑 ≥1 轮 → `mode:'wall'`，升这一级；
  2. 钱花不完（金币 > 产能 × 剩余手数 × 当前代最强兵价）→ 允许升代，`targetEra` 取
     "产能 × 剩余手数 与 钱÷单价 取小之后，总战力最大"的那一代；
  3. 其余 → 不许升。
- **同时拆掉顺序依赖**：入口里"升级排在造兵之前"改成由 `mode` + `cap` 表达（救城可以花到某个上限，
  造兵用剩下的）。**入口不再靠代码行位置决定优先级。**
- **验收**：`P-1-03`（该升）绿、`P-1-04`（钱 900 也不许升）绿、`E-2-03` 绿且读数不变
  （3 代 / 12 个 / 平均 74.8）；33 题零回归；四颗种子。
- **风险**：这是**第一次让决定层读金币**，会有阈值抖动。靠两条压住：期限（`untilTurn`）
  + 沿用机制；不允许在决定层写"钱够就升"这种无期限规则。

### D5 用"承诺"替代"有兵就不规划"（**换判据**）

- **做什么**：记忆里加一条承诺：`eraPlan: { cityId, targetEra, decidedAt, spent }`。
  决定层只在**没有承诺时**规划一次（沿用现有 12 手有效期的写法）；计划层每手只执行"下一级"，
  把花掉的钱累加进 `spent`；重算时把 `spent` 计进账（所以不会漂）。
  删掉 `world.myCombat.length > 0` 那道门。
- **为什么**：现在的做法是"军 队一成型就永久关闭升级规划"，副作用是
  **先造 1 个兵、然后才暴富，就再也升不了**。根因是升级费是沉没成本、每手重算都像从零开始
  （E-2-03 上从 3 代漂到 5 代）。正解是记账，不是禁止重算。
- **判据**：承诺期内目标代不再变；城丢了 / 超过有效期 → 作废重算。
- **验收**：`E-2-03` 保持 3 代 / 12 个；**新题 `E-2-05`**（第 1 手买得起 1 个兵、第 2 手才暴富）
  现在红、改后绿，四颗种子。
- **风险**：承诺 + 记忆是 v3 的耦合温床。**只准记三个数**（目标代、立的回合、已花），
  不许往里面塞"为什么"以外的任何状态。

### D6 理由进回放（可诊断性）

- **做什么**：回放/面板带上这一段：`spend.mode / cap / why` + 升级判断
  （撑几轮 / 升完几轮 / 花多少钱 / **为什么没升**）。
  `Constraints.upgrade.why` 从"写完就扔"变成有读者。
- **判据**：不读代码，能回答三个问题——这一手为什么不造兵？为什么升/不升？钱按什么分的？
- **验收**：面板与回放读得出；不影响任何读数。

## 6. 不做

- **不在决定层写真值表 / 权重 / 分数**。决定层只准交一句能被人反驳的话 + 一个期限。
- **不让计划层保留"要不要"**。它只回答"哪座城 / 哪几格 / 多少钱 / 通不通"。
- **不为了链路好看改判据**。D1~D3 是搬家；判据的改进留给 D4/D5 和之后的阶段。
- **不把投影摊成逐动作打分**（v3 的死法，见阶段一不做清单）。
- **不给"资源段落"加第五个字段**。要加先证明现有四个装不下。

## 7. 顺序与依赖

```
D1 资源段落 ──► D2 期限口径 ──► D3 城能撑几轮 ──► D4 升级归位 ──► D5 承诺记账 ──► D6 回放
                                                   │
                                                   └──► 之后 P4（投送）用同一个期限
                                                   └──► 再之后 C3（投第几手）用同一套选择
```

- **D1 必须最先**：没有地方装钱，D4 无处落。
- **D2 必须在 D5 之前**：D5 拆掉那道门之后，T 的两义会第一次真的生效。
- **D3 是 D4 的输入**：决定层要在计划层之前就知道"城还能撑几轮"。
- **D6 最后**：它只是把已经存在的理由接上读者。
