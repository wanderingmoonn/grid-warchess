## 1. 城市到各自底线的距离

**以前**：两边的"纵深窗口"不是镜像的。近侧永远是 `[底线, 前线]`（只有 1~2 格，
城只能贴着自己的边），远侧是 `[前线, 对面底线]`（把整张图的余量一个人吃下来）。
于是同一张图上，上半区的城被逼在墙角，下半区的城坐拥纵深。

实测（各 200 张，量"城到己方底线之间空了几格"）：

| 棋盘 | 改前 上 / 下 | 改后 上 / 下 |
|---|---|---|
| 16×16 | 1.78 / 3.27（差 1.5） | 2.27 / 2.27（差 0） |
| 20×20 | 2.65 / 4.33（差 1.7） | 3.22 / 3.22（差 0） |
| 32×32 | 4.04 / 7.33（差 3.3） | 6.19 / 6.19（差 0） |

镜像模式（`symmetry: 'mirror'`）本来就是对称的，一行没动。

**改在哪**：`src/core/mapgen.ts` 的 `planCities`。`make(front, lo, hi, taken)` 换成
`placeAt(side, taken)`，两侧的纵深由同一个 `pad` 说了算：

```
pad = floor((alongHi - alongLo - target) / 2)
近侧前沿 = alongLo + pad        远侧前沿 = alongHi - pad
```

`target` 还是老公式抽出来的"两军该隔多远"，所以**平均间距没变**（12×12 仍落在
6.3~7.6 那条带里），变的是余量怎么分：一人一半。

**关键判断**：

- 纵深不抽签。反推出来的 `pad` 已经"刚好等于 target"，再往上加只会让两军离得更远，
  评分（`score`）也会把它按下去。地图的多样性留给横向——那一整条边随便挑。
- 对称的只是**纵深**。横向两半区各抽各的，不做镜像：真要镜像就是 `symmetry: 'mirror'`
  那条路（`mirrorBlock` 是 180° 点对称），公平图要留着自己"两边城墙不在同一段"的样子。
- 小图上 `target` 可能吃满纵深，`pad` 退化成 0：两侧各只剩一行，城退回"同一行、
  横向拉开"的老样子——那是约束下的唯一解。

**验证**：新增 `test-rules` 用例「城市到各自底线的平均距离：上半区与下半区一样」，
12 / 16 / 20 / 32 × fair / mirror，**逐图**断言两侧均值相等（不是统计相等）。
变异：把远侧改回贴边 → `12×12 fair 第 0 张：上边均值 2、下边均值 1` 立刻红。

**代价**：横河图上四座城现在落在两行里（纵深由抽到的走廊宽度决定），纵向的随机性
没了。想"既错落又等距"得让两侧共用同一个纵深多重集（比如都取 `{pad, pad-1}`），
这版没做，见文末。

**连带**：开局部队是跟着城市摆的，城挪到中间之后落点也变了，5 条写死坐标的规则
用例（击退 / 隐匿 / 属性抗性 / 画笔 / 地形高差统计）按新落点重新校准——不是放宽断言：
击退和隐匿先清场，抗性和画笔改成"挑一格平原"，高差那条允许 12 张里有一张净增为负
（扩展里"任何一张图都得走得通"的兜底会把挡路的山削成丘陵）。

## 2. 大地图缩放：放大了缩不回去，开新局也缩不回去

**根因有三条，叠在一起才成了"一直缩不回去"**：

1. 换局 / 导入存档 / 进房间都只写了 `boardZoom = 1`，没把 `boardDirty` 打上。
   `render()` 里那句 `const remeasure = boardDirty || !canWatchResize;` 因此不成立，
   `fitBoard()` 根本不跑——棋盘尺寸、`zoomed` 类、右下角档位标签全停在上一局的放大状态。
   变量是 1、画面是 3×。
2. `setZoom` 开头 `if (clamped === boardZoom) return;`。上一条已经把变量改成 1 了，
   于是点「−」算出 1、判定"没变"、直接返回——按键彻底失灵，而且**每一局都会重现**。
3. 拖动地图之后的 `suppressClick` 会吞掉"下一击"。它不分对象，连缩放条和顶栏一起吞；
   拖着地图松手时正好压在「−」上，看着就是"按键失灵"。

**改在哪**：`src/main.ts`。

- 新增 `resetZoom()`：档位、`boardDirty`、滚动位置、两层 `zoomed` 类一次归位。
  导入存档、开新局、进房间、退房间四处都改成调它。
- `setZoom` 不再早退：值没变也重绘一次、重量一次，把 DOM 拉回档位。
- `zoomStep` 改用 `zoomIndex()`（最近的一档），不再拿 `indexOf` 的 -1 去 `+dir`。
- `render()` 里那条判断加了**对账单** `lastFitZoom !== boardZoom`：档位换了但 DOM
  没跟上，下一帧无条件补量一次。`resetZoom` 是"记得标脏"，这一条是"忘了也能自愈"。
- `suppressClick` 只吞落在 `.board` 里的那一下；缩放条是 `board-wrap` 的子元素、
  不在 `.board` 里，照常生效。

**验证**：新增两条 UI 用例——

- 「拖过地图之后，缩放按钮还得点得动」：在 1.5× 上 pointerdown/move/up 拖地图，
  再点「−」，断言宽度真的变小。
- 「换一局之后缩放必须回到「适应」，而且还能再放大缩小」：放到 2× → 开新局 →
  断言回到基准尺寸、`zoomed` 摘掉 → 再放大缩小一轮。

变异：拆掉 `resetZoom` 与那条对账单 → `换局之后应该回到基准尺寸 1292 !== 646` 红；
恢复无条件吞点击 → `969 → 969` 红。

**顺带**：`scripts/smoke-dom.ts` 补了一个假的 `ResizeObserver`。jsdom 没有它时
`canWatchResize` 为假，`main.ts` 走"每帧都量"的老路——那条路上档位和 DOM 永远不会
脱钩，这条 bug 在测试里根本复现不出来（写多少断言都是绿的）。

## 4. 棋子移动抽搐

**三处叠在一起**：

1. `.unit` 上有 `transition: left .16s, top .16s`，而 `board.ts` 又在做 FLIP
   （先写 `left/top` 到新格子，再用一段 `translate` 把它拉回旧位置）。两条曲线各走
   各的，合起来就是"先窜出去再缩回来"——这就是抽搐的主因。
2. AI 快档两次重绘只隔 70ms，而一格要滑 170ms。新动画总是从"新格子的上一格"起步：
   棋子先跳到新格子，再往回补那 170ms 里没走完的一截。
3. 极快档每 6 步才重绘一次，`movePath` 只覆盖最后一步，却被拿去演两三格的位移——
   第一帧直接跳到终点附近。

**改在哪**：

- `src/style.css`：删掉 `.unit` 的 `left/top` transition。一个位移只留一个动画源。
- `src/ui/board.ts`：补间改成"接力"——线性缓动，按**节点**记 `{起点偏移, 时刻, 时长}`
  （`slides`，WeakMap，换局换节点自动回收）。下一帧先算上一段"欠"了多少
  （`dx += prev.dx * (1 - k)`），把它加进本次起点，再开新动画，并 `cancel()` 旧的。
- 路线只在 `route[0]` 等于上一格时才用，否则退回直线；时长按距离给：一格 150ms、
  封顶 420ms，沿路线仍是 70ms/格（这个数还管着 AI 那边"等动画播完再走下一步"的停顿，
  两边必须同一口径）。

**验证**：`tsc` + 141 项 UI 冒烟（jsdom 没有布局，量不到补间本身）。手测路径：
32×32 观战、AI 速度调到「极快」，看长距离行军是否还抽。

## 5. 聊天框可以拖着走

**改在哪**：

- `src/main.ts`：`chatShift`（相对出厂位置的偏移）+ `bindChatDrag()` + `clampChatShift()`。
  抓手是**标题栏**：面板里有滚动的聊天记录和输入框，整块可拖会把"选中一句话 / 拖滚动条 /
  点输入框"统统变成"挪窗口"。`×` 被显式排除。
- 位移只写 `transform`，不动 `right/bottom`——出厂位置按视口右下钉着，改定位属性就得
  跟着视口尺寸重算，而偏移量与基准无关。拖动范围夹在视口内，最少留 8px。
- 打开面板时夹一次（`clampChatShift`）：窗口在上次关掉之后被改小、或者手机转过屏，
  不夹一下就有半块在屏幕外而且抓不回来。
- `src/style.css`：`.chat-head { cursor: grab; user-select: none; touch-action: none }`
  （触摸端不写 `touch-action: none`，往下拉会变成滚页面），`will-change: transform`。

**顺带修掉一个真 bug**：`hidden` 是 UA 的 `display: none`，会被 `.chat-panel{display:flex}`
盖掉——面板其实**收不起来**，一进房间就永远摊在棋盘上。补了 `.chat-panel[hidden]`。

**验证**：新增 UI 用例「聊天面板能按住标题栏拖动，拖不出视口，点 × 不算拖」。jsdom 没有
布局、矩形一律是 0，所以塞了一个"会跟着 transform 走"的假矩形进去，验的是位移怎么算、
边界怎么夹：拖 (40, -30) → `translate(40px, -30px)`；一直往右 → 夹在
`1024 − 280 − 8 = 736`；点 `×` 不移动。变异（拆掉夹取）→ `translate(1380px, ...)` 红。

## 没做的事

- **城市**：纵深不再随机（这是等距的代价）。要做到"错落 + 等距"，得两侧共用同一个纵深
  多重集，这版没动。
- **缩放**：档位仍是 1 / 1.5 / 2 / 3，没有捏合手势；也没有"记住上一局的档位"。
- **移动**：路线还是四连通 BFS（画动画用），飞行单位过河仍是一条直线。
- **聊天**：位置只活在这一次会话里，没落盘；面板不能改大小。
