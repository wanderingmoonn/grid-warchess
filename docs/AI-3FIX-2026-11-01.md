# AI 三类问题修复：建造 / 选卡 / 交战（2026-11-01）

承接 `ANALYSIS-AI-2026-11-01.md`。那份体检的结论是"AI 输在防线，不输在经济"，
这一份处理三个具体的窟窿：**它盖了太多没用的东西、它在选卡就把自己选死了、
它的伤害是散的**。

三类的排法不是随手写的：建造和选卡都是**一次决策、长期生效**的杠杆，改一个常量
就能改变整局形状；交战层相反，它是每次行动都在发生的局部判断，改坏了很难看出来。
所以前两类改得狠，第三类只动"打谁"和"什么时候停"、不动"打不打"。

> **第二版修订（同日）**：第一版有三处走过头或写错了，这次都改了，并在文中标明：
> ① 选卡压到了平均时代 1.38（从一个极端跳到另一个极端）→ 改成时代梯子；
> ② "架桥要缩短路"的判据用错了距离图，**把该架的桥也拦掉了**（中世纪档因此掉了 3 胜）；
> ③ "集结"被理解成了"往队友身边靠"，方向就错了 → 重写成"战线 + 间距"。

## 一、建造：AI 在给自己盖一座集市

### 1.1 定位

建造决策只有一条链路：

```
unitCandidates → scoreBuild → rawBuildScore
```

`rawBuildScore` 按兵种分成五档（桥 / 军营 / 经济 / 自动开火 / 纯工事），各自有
数量上限，但**没有一层总闸**，而且有两处把"不该建"写成了"分数很低"。

实测（`scripts/diag-build.ts`，3 局 16×16 双 AI）：

| 兵种 | 次数 | 平均敌距 | 敌距 > 8 格 |
|---|---|---|---|
| bridge | 49 | 5.9 | 7 |
| camp | 8 | 7.4 | 3 |
| tower | 7 | 4.9 | 1 |
| mill | 5 | 10.4 | 4 |
| 其他 | 5 | — | — |
| **合计** | **74** | | **15（20%）** |

两个直接问题：

1. **架桥占了 66%**。判据只看"对岸离目标够不够近"（`24 - farDist`），
   于是任何一座通向地图中间的桥都能拿到十来分。
2. **纯工事在没敌人时返回 4 分**。建筑候选和走位候选在同一个池子里比大小，
   而一步普通行军常常只有几分——4 分是真的能赢的，于是在平静的后方一块一块地砌墙。

另外线上对局库里出现过 **31 座建筑**的局（id=54，77 回合），产能全在盖房子。

### 1.2 改法

| 位置 | 改动 | 为什么 |
|---|---|---|
| `rawBuildScore` 开头 | 建筑总量上限 `min(16, 城数×4)`（桥不算） | 各兵种自己的上限加起来能把一座城的设施区撑到十几座，需要一层总闸 |
| 架桥分支 | 全局桥数上限 `min(10, 城数×3)`（见 1.4 的更正） | 按数量管，不判断单座桥值不值 |
| 纯工事分支 | 敌人不在 7 格内：`return 4` → `return -999` | "挨打才砌墙"这句话写成 4 分等于没写 |
| 经济建筑分支 | 格子产出 ≤ 0 时 `-999` | 一格不产出的地盖上磨坊，产的是 0 |

### 1.3 结果

同样的 3 局：

| 指标 | 改前 | 改后 |
|---|---|---|
| BUILD 总次数 | 74 | **56（-24%）** |
| 其中 bridge | 49 | **37** |
| 远离战场（>8 格）的建造 | 15 | **11** |

桥仍然是最大项（12 座/局，16×16 河图）——这张图上确实有几条要过的河。
再往下压就得判断"哪座桥没用"，而第一版正是败在这里（见 1.4）。

### 1.4 更正：第一版"架桥要缩短路"是错的

第一版加的是这条：

```ts
// 过桥之后到目标的距离，必须真的比站在这儿更近，否则不建
if (Number.isFinite(nearDist) && gap.farDist >= nearDist - gap.steps) return -999;
```

它在中世纪档把胜率从 **7 胜 5 负打到 4 胜 8 负**（同一批种子，`results/ab-mi-*.json`）。
原因很具体：

- `nearDist` 取自 `advance` 距离图，而那张图的定义是"**旱路优先、涉水兜底**"——
  水面只是"很贵但能过"。
- 所以站在自己这边时，脚下这个值里**已经含了涉水的代价**；对岸那个值只会更小一点点，
  甚至更大。`gap.farDist >= nearDist - steps` 于是**几乎恒真**。
- 判据的实际含义变成了"除非完全走不通，否则不许架桥"。

验证方式是直接关掉这一句：`results/ab-mi-bridge.json` 立刻回到父版本的水平
（10 胜 14 负、中世纪 7-5），说明差异全在这一句上。

**正确的比较必须在"严格旱路"（水＝墙）的图上做**——只有那样，"对岸到不了"才是
真的到不了。但 `all.land` 在 `aiNextAction` 里已经被 `mergeAdvanceField` 和涉水图
合并过，拿不到纯旱路版本；要么每回合多算一套全图 Dijkstra（AI 决策时间会涨
三成），要么不做。这一轮选择不做，改成按数量管。

## 二、选卡：AI 把六个名额全砸在造不出来的兵上

### 2.1 定位

`src/core/draft.ts` 的 `aiDraftPick` 只有一个评分：

```ts
function draftValueOf(def) { return def.atk + 0.4 * def.maxHp + 3 * def.armor + 3 * def.range; }
```

**纯数值，没有任何"这一局用不用得上"的概念**。而数值和时代几乎单调相关，
于是 AI 每次都挑最高时代的大件。

问题是：城市是从 `startEra`（默认 1 级）起步的，`eraWindowOk` 只放行
`def.era <= 城市等级` 的兵——**选到 ≠ 造得出**。

实测（`scripts/draft-compare.ts`，6 局同种子，只看乙方的 8 个名额）：

| | 平均时代 | 平均单价 | 开局就能造 |
|---|---|---|---|
| 原评分 | **4.48** | **325 金** | **0 / 48（0%）** |
| 第一版（按"现在能不能用"单向压） | 1.38 | 64 金 | 31 / 48（65%） |
| **第二版（时代梯子）** | **2.50** | **154 金** | 8 / 48（17%） |

老评分选出来的队伍，**48 个名额里没有一个在开局城市里造得出来**。
这和线上数据对得上：13 局人机败局里 AI 的开局阵容常年是 0~2 个单位。

### 2.2 第一版错在哪：从一个极端跳到另一个极端

第一版把"开局就能造"当成硬指标（`ready = 1/(1+0.55·lead²)`），一路压到平均时代
**1.38**——六个名额全是 1 级兵。开局是爽了，但**整局没有上限**：中期以后每一波
都是同样的兵，对面升一级就换不过。这是"走极端"，不是"修正"。

根因是这条公式**只有一个方向**：它只会惩罚"比开局时代高"，不会惩罚"比该有的时代低"。

### 2.3 改法：时代梯子

会玩的人不是把所有名额压在同一个时代上，而是让**队伍的时代成为一条阶梯**：
前几签买现在就打得动的，往后逐签抬高，最后留一两个位置给决战用的东西。

所以每一签先算一个**目标时代**，再按"离目标时代多远"打分（双向，不是单向）：

```ts
targetEra = startEra + min(4, round(名额序号 × 0.4 × ...))   // 8 签 → 目标 1,1,2,2,3,3,4,4
eraFit    = 1 / (1 + 0.85 × |def.era - targetEra|)            // 双向，一级之内几乎不罚
perGold   = (80 / max(20, cost))^0.3                          // 单价，指数从 0.45 降到 0.3
score     = raw × eraFit × perGold
```

`perGold` 的指数必须降：0.45 时它和时代折扣叠在一起，同样把高时代兵一起压死。
0.3 让它只是"微调性价比"，而不是"只买便宜的"。

另外四条覆盖规则（`aiDraftPick`）：

| 规则 | 目的 |
|---|---|
| 手里没有便宜身体（cost ≤ 70）时 +16 | 前二十回合总得有东西能出门 |
| 手里一张"现在造得出"的都没有时 +26，且只在此时代里挑 | 防止第一签落空 |
| 已经有一张建筑卡就不许再选建筑 | 线上 AI 终局常摆着两座塔，同一局却凑不出一支部队 |
| 水军按地图水面占比打折（≥14% ×0.9 / ≥8% ×0.5 / 否则 ×0.2） | 旱地图上选两条船，整局开不出港口 |

禁用（`aiDraftBan`）**没有动**：ban 掉对面最贵的核心本来就是正确打法，贵＝对面指望它。

### 2.4 结果

同一批种子下，队伍从"六个 5 级大件"（老）→"六个 1 级兵"（第一版）→
**"2 个 1 级 + 2 个 2 级 + 3 个 3 级 + 1 个 4 级"**（现在）。实际序列：

```
anc_elephant era1 54金 ✔   anc_ram    era1 46金 ✔   med_trebuchet era2 128金
med_manatarms era2 78金    cataphract era3 205金    halberdier    era3 100金
gp_cuirassier era3 185金   ind_railwaygun era4 265金
```

开局有两个能立刻造出来的身体，中段有攻城器和重步兵，后期有胸甲骑兵和列车炮。
其他开局时代也验过：`startEra=3` 时平均时代 4.25（老评分 4.48）、开局可造 25%（老 4%）；
`startEra=6` 时两者都能全造。

## 三、交战：战线、间距、集火

### 3.1 定位

`tacticalMoveScore` 是**逐单位**算的：每个兵各自挑"自己这一走最划算"的格子。
没有任何东西约束"我这一走是不是已经跑到全队前面去了"，也没有东西约束"我是不是
贴在自己人身上"。

线上数据（15 局带 timeline 的败局）：**AI 造 432 个兵、死 375 个（87%）；
人类同期只死 114 个。** 这种交换比不是"伤害不够"，是**兵一个一个上去送**。

### 3.2 "集结"的准确含义（第一版理解错了）

第一版把集结理解成"让部队往彼此身边靠"，做法是给"靠近队友"加分、给"孤军"扣分。
**方向就是错的**——那是把部队揉成一团，正好送给对面一发溅射。实测两个变体
都是负收益：

| 方案 | 48 局子集 |
|---|---|
| 基线（都不加） | 32 胜 14 负 2 未决（66.7%） |
| 战力密度：孤军 −16 / 集结 +10 / 攻击端 −20 | 29 胜 15 负 4 未决（60.4%） |
| 只留"靠近队友 +10" | 29 胜 16 负 3 未决（60.4%） |

真正的集结是**队形**，不是**堆叠**：

- **部分军队先停止前进**——最前面那几个不再抢推进分，停下来等；
- **后面的人照常往上补**——线自然收拢；
- **中间留出间隔**——不挤在同一条格线上，免得一发溅射吃两份伤害。

三件事分别对应三个机制，互不重叠。

### 3.3 改法一：战线（谁该停）

每回合算一次**战线**：我方**最靠前那四分之一**战斗单位的推进距离。

```ts
// 只算陆军；少于 3 个兵就不算（两三个人还互相等，这局不用打了）
lineRef = 25% 分位(advanceDistance of my combat units)
```

然后：**已经在战线之前**（`before < lineRef`）的单位，这一回合的推进分乘 0.15。

```ts
const advanceWeight = aheadOfLine ? 0.15 : 1;
score = progress * 6 * appetite * ... * advanceWeight;
```

效果是"最冒尖的那几个停下，后面的追上来"，而不是"全体原地立正"。
`commit`（全军强攻）时这条不生效——优势期还互相等，等于把优势让回去。

**英雄和攻城器豁免这一条**：它们本来就是"单点突破"的工具，跟着队形走反而不会打仗。
第一版没有豁免，英雄档直接从 15 胜 1 负掉到 11 胜 5 负；加上豁免后同一批种子
（`--profiles heroes,ancient --pairs 6`）从 16-8 回到 **17-7**（英雄 8-4 → 9-3）。

### 3.4 改法二：间距（别挨着站）

每回合算一张**站位密度图**：每格相邻 8 格里有几个我方战斗单位。
走到"已经站着人"的格子旁边要扣分，**而且只在对面有溅射单位时才扣**：

```ts
if (def.category === 'combat' && all.foeSplash > 0) score -= crowd * 3;
```

一开始写的是"无论如何都扣（−2.5，有溅射时 −6）"，测得 58.3%，**比不加还差**。
原因：这个游戏里贴在一起是有用的（互相掩护、围城要围满一圈），只有在**真有溅射**
的时候，分散才划算。所以现在只在 `foeSplash > 0` 时生效，而且罚分降到 3。

### 3.5 改法三：集火（打谁）

`scoreAttack` 逐目标算分，没有任何机制让全军把伤害落在同一个人身上——五个人打
五个目标，每个都半血，对面回一轮血、换个目标，全程没人被击杀。

新增 `pickFocusTarget`，每回合选一次、全军共用：按"残血 × 值钱 × 有几个我方够得着"
挑一个目标，`scoreAttack` 对它 +26。取 26 是为了**只改"打谁"、不改"打不打"**：
一次本来就不划算的交换，加完 26 还是负分。

### 3.6 结果

| 方案（48 局子集，ancient/medieval/gunpowder/combined） | 结果 |
|---|---|
| 基线（上一提交） | 32 胜 14 负 2 未决（66.7%） |
| 战线 + 硬间距（−2.5 / −6）+ 集火 | 28 胜 15 负 5 未决（58.3%） |
| 只加硬间距 | 28 胜 16 负 4 未决（58.3%） |
| **战线 + 软间距（仅溅射时 −3）+ 集火** | **33 胜 14 负 1 未决（68.8%）** |

平均回合数 84.6 → 82.7（**没有变成互相干瞪眼**），决策耗时 19.1ms → 18.6ms（没变慢）。

## 四、中世纪 / 工业两档的退步

全量评测里这两档是唯一退步的：中世纪 9-6-1 → 6-10，工业 5-11 → 4-12。

排查顺序：

1. **建筑总闸**？把 `min(16, 城数×4)` 放宽到 `+3` 再跑 —— **一格不变**
   （`ab-mi-base` 与 `ab-mi-cap` 完全相同），说明总闸在这两档根本没咬到。
2. **直接和父提交对跑**（同 profiles 同种子）——父：10-14（中世纪 7-5、工业 3-9）；
   改后：6-18（4-8、2-10）。**确认是真的退步，不是噪声。**
3. **逐项关掉 3fix 的改动** —— 关掉"架桥缩短路"这一句，立刻回到 10-14。
   **就是它。**（诊断细节见 1.4）

修法就是 1.4 里说的：删掉那句距离判据，换成全局桥数上限。修完这两档
**9-15（中世纪 6-6、工业 3-9）**，基本回到父版本水平。

剩下的 1 局差距来自桥的总量上限（10 座）——中世纪图河多，10 座有时不够铺第二条
通道。这一条没有继续放宽，理由是它同时压着"河上摆家具"的另一头；要精确解决，
得把"严格旱路图"补上（见 1.4 结尾），那是下一轮的事。
