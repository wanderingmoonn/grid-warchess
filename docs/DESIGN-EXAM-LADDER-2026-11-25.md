# 考题的两根轴：内容 × 复杂度（2026-11-25 修订）

> **这份文档是什么**：题库的**组织方式**。题分几条轨、每轨分几档、局面怎么摆才能只考到那一档。
> **这份文档不是什么**：不是新题库（一道题都没写）；也不是 `GUIDE-V4-EXAM-2026-11-23.md` 的替代——
> 那份讲"一道题怎么填六个文件"，这份讲"这道题属于哪一轨哪一档、凭什么"。
>
> **修订说明**：本文件 10:00 那版只有一根"八级阶梯"，按复杂度排。用户当场指出两件事：
> ① 人类的打仗能力是多方面的（经济、升代、侦查、编成、时机、关口、兵种），一根线塞不进去；
> ② 第 1 级"一个兵走到指定格"不知道怎么摆局面。两条都成立，第②条在第五节重做了，
> 因为它撞上一个更根本的事实：**这套架构里没有"走到指定格"这个决定**。

读的顺序：本文 → `docs/GUIDE-V4-EXAM-2026-11-23.md`（一题怎么做出）
→ `exams/README.md`（现在有哪些题、每道什么状态）→ `docs/PLAN-V4-2026-11-23.md` 第五节（为什么用考卷）。

**题号（2026-11-25 用户定）**：旧题沿用 `S-xxx` 不动；新题 `字母-档位-序号`，
字母就是下面四个意图的英文词首（`E` 发展 / `P` 打 / `T` 接管 / `D` 守），
档位是 `1/2/3`，序号是这一格里的填入顺序。完整规则见 `exams/README.md` 开头。

## 一、为什么一根线排不出来

用户列的能力，其实落在两根**正交**的轴上：

- **内容（考什么）**：经济建设、升级时代、侦查敌情、组织军队、建军时机、识别关口、兵种搭配……
- **复杂度（多难）**：一件事 / 两件事有先后 / 在对抗下

正交的意思是：经济的第三档（被打断时还守不守得住岗位）比收尾的第一档难，但它们不在同一条线上。
硬塞进一根线，必然有一半放错位置——这就是"不知道塞哪一层"的来源，不是想不清楚。

还有第三件事，比前两根轴都优先：**这套架构有没有给这件事留位置。**
没有位置的能力，写多少题都是永久红；它不是"难"，是"不可能"。

### 1.1 架构里有没有位置（2026-11-25 逐个核对）

按用户列的能力逐条去代码里找，结果是四类：

| 用户列的能力 | 归谁 | 位置 |
|---|---|---|
| 经济建设（造几个、站哪） | 约束层：经济岗表 + 认领表 | ✅ 有 |
| 组织军队（编成、人数） | 约束层：编队规模 + 采购门槛 | ✅ 有 |
| 兵种搭配 | 打分层采购：挨得住一发、三发打穿、先挑射程 | ✅ 有（但是写死的规则） |
| 投送（把兵送到城下） | 约束层：落点表 + 队形 | ✅ 有 |
| 收尾（兵多也打不下） | 决定层分段 + 打分层 | ✅ 有 |
| 建军时机（什么时候开始造） | 决定层的切换（兵力比 1.25 / 0.9） | ⚠️ 有，但只有一个数 |
| **升级时代** | —— | ❌ **没有主人**：v4 代码里 grep 不到"升级" |
| **侦查敌情** | —— | ❌ **没有主人**：没有"去看"这个动作，视野由引擎给 |
| **识别关口** | —— | ❌ **半个**：地形只被当"形状"读（窄道排队、分路），没被当"价值"读 |
| **守（该守哪座）** | 决定层 + 服务层 | ⚠️ **威胁场已就位（2026-11-25 修 9.7）**：城的角色改按"敌人几回合摸到"判，最低档现在能出题；"该守哪座 / 怎么分兵"还差 9.1 |

四条 ❌ 要分开理解：

- **升级、侦查**：任何一层都不许表达。写题就是写永久红。要考它，先得加一个决定种类或一个动作，
  那是**架构改动**，不是出题。
- **关口**：地形"形状"有人读，"战略价值"没人读。所以能考"过桥时别堵"（S-005），
  不能考"这个口子必须守住"。
- **守**：有位置，但判断依据不全。一座城的角色只有两种判法——我只有一座城就叫"老家"，
  否则看它离**敌人城**几格。敌人离这座城多近不参与判断。这就是守轨写不出题、
  S-013 红了定位不到的原因。缺的那个数是"敌人最快几回合到城下"（= 待办 9.7）。

> 结论：**"升级时代放第几层"这个问题没有答案，因为它哪一层都不在。**
> 这类能力不进题库，进"架构欠账"清单。

## 二、第一根轴：四个意图

决定层只能输出四种意图，这是架构自己的词汇，也是"考什么内容"的天然分轨：

| 意图 | 什么时候会被选中（当前规则） | 谁执行 | 对应人类能力 |
|---|---|---|---|
| **发展** | 其它三条都不成立 | 约束层岗位表 → 打分层 | 经济、站位、造兵、选型 |
| **打** | 有敌城，且我身价 > 对面 1.25 倍 | 约束层编队与落点 → 打分层 | 投送、编成、兵种、清场、攻城 |
| **接管** | 场上有废墟（优先级高于打） | 约束层单兵指派 → 打分层 | 打空之后的收尾 |
| **守** | 我的城被判成"老家/被威胁"，且对面身价 > 我 0.9 倍 | 约束层编队 → 打分层 | 判威胁、分兵、守哪座 |

四条轨的成熟度完全不同，这本身就是重要信息：

- **发展**：经济岗与意图**无关**（约束层无条件算），所以发展轨的题其实考不到决定层，
  只考约束层和打分层。这解释了 S-006 / S-015 为什么能稳定绿、且是 v4 唯一领先的两道。
- **打**：第一、二档已经立住（S-016 / S-017），第三档全红（S-002 / S-011 / S-012）。
- **接管**：第一档没有题，第二档是 S-001（但 S-001 还带着过桥，不是干净的一道）。
- **守**：威胁场已就位（`world.foeEta`），最低档（敌人下一手能摸到、兵少 → 守）**现在可以出题了**，但还没出；
  第二档"两座城怎么分兵"要等 9.1 的触发条件改完。

## 三、第二根轴：复杂度只有三档

原来的八级里，有两级根本不是"难度"：

| 原来的 | 现在归到哪 |
|---|---|
| 会挪一格 | **单元测试**，不进题库。一兵一城、跑一手、看输出是不是合法动作，`npm test` 就够 |
| 不做无用功 | **判据的第二段**。每道题的判据模板里本来就有"没破坏什么"，不需要单独一级 |
| 整局 | 不进题库，用整局跑批（M1 经济实产 / M2 升代时间） |
| 会走路、一件事做对、两件事排序、分得开、打得过、收得掉 | 压成三档（下面） |

三档的定义，判断标准只有一个：**这一档要求几件事同时正确**。

| 档 | 定义 | 判断题 | 过关长什么样 |
|---|---|---|---|
| **1 一件事** | 一个意图、一个执行者、一个后果 | 它会不会做这件事 | 状态或数量达标 |
| **2 两件事** | 两件事有先后，或要在两处分工 | 它会不会按对的顺序做 | 两段的判据都达标 |
| **3 在对抗下** | 对面会回应：会反击、会逃跑、会分兵，会有伤亡和取舍 | 它会不会算这笔账 | 战果达线且伤亡不超线 |

"不做无用功"在每一档都出现，形态是判据的第二段（例：不许为了腾格子把兵送进炮口）。

## 五、局面怎么摆：让决定层只会得出一个意图

这是上一版最不成立的地方。上一版写"第 1 级：一个兵走到指定格"，**这个题面和架构对不上**：

决定层只输出四种意图，没有"把某个单位挪到某格"这种说法。走动是意图被分解到约束层之后的结果。
所以题面写"把这个兵走到那格"，等于要求它读出题人的心思，而不是达成目的——
和项目自己的规矩（判据看结果、不看动作）直接冲突。

正确做法是反过来：**不指定走哪一格，而是把局面收窄到只剩一个意图能成立**，唯一的那个兵自然就会动。

### 5.1 四个开关（按决定层的判断顺序，一个个关掉）

| 顺序 | 判断 | 怎么关掉 |
|---|---|---|
| 1 | 上一手立下的决定没到期 | 用**第 1 手**出题（没有上一次决定） |
| 2 | 守：我的城被判成"老家 / 被威胁"，**且对面身价 > 我 0.9 倍** | 让我明显更强，或对面 0 个战斗单位（0 不大于 0） |
| 3 | 接管：场上有废墟 | 局面里不留废墟 |
| 4 | 打：有敌城 **且** 我身价 > 对面 1.25 倍 | 我方 0 个战斗单位（身价 0，不大于 0） |
| 5 | 剩下唯一可能 | 发展 |

一条陷阱必须先知道：**对手必须至少有一座城，否则引擎判他出局。**
所以"场上没有敌人"永远等于"有一座空城"；空城 + 我有战斗兵 = 必定"打"。
要一个纯发展的局面，必须**一个战斗单位都没有**。（S-015 能考经济，正因为它是"我 0 兵"。）

第二条要知道：**经济岗与意图无关**。约束层每回合无条件算岗位表，不管决定层说的是发展还是打。
所以发展轨的题测不到决定层；反过来，只要局面里有战斗兵，它们会按决定层的意图走开，
这会让"顺便考经济"的题变得不可解释。

### 5.2 三个最低局面（各自轨道的第 1 档）

**发展·1 — 唯一的岗**（已落地：`exams/E-1-01` + 一换 `exams/E-1-02`，2026-11-25）
12×12，我一座 2 代城、**金 0**、0 个战斗单位、1 个伐木工站在平原；它东边 4 格外的 (8,9) 有一格森林，
附近没有第二格森林；敌方一座城在远角、0 兵。
判据：3 手内伐木工站上那格森林。
为什么只能这么做：没战斗兵所以不能打；没废墟所以不能接管；对面身价 0 所以不用守；
金 0 所以造不出兵。只剩"把人挪到岗位上"，而岗只有一格可选。

**实测（四颗种子）**：空壳 3 / v1 3 / v3 3 / **v4 12**（判据只要求 12）。
v1 和 v3 是**一手都不动**，不是挪错格——它们在没有明确的仗可打时就不动作。

**一换（E-1-02）**：把兵种-地形换成牧民＋丘陵，其余同形。
实测空壳 4 / v1 4 / v3 4 / **v4 8**，同样四颗种子一致。
两道一起才说明"派岗是按兵种-地形配对，不是把'森林=好东西'写死"。

**踩过的坑（出题规矩）**：第一版把丘陵放到 6 格外，按"移动力 3、6÷3=2 次行动"算，错了——
**丘陵进场要 2 点移动力**（地形表 hill=2、平原=1），实际要三次行动。
**算时间窗要按移动点算，不能按格数算。**

**打·1 — 空城**
我 2 个三代兵；敌城 0 守军；无废墟；无其它敌兵。
判据：8 手内把城打空。
为什么：有战斗兵、对面身价 0 → 必"打"；城下没有守军 → 直接砸。

**接管·1 — 钱够、没人、走进去**（已落地：`exams/T-1-01` + 一换 `exams/T-1-02`，2026-11-25）
场上 1 座废墟离我 1~3 格、周围无威胁、金 200 ≥ 重建费 158、我 **3** 个长枪兵。
判据：3 手内那座废墟归我。
为什么：有废墟就必接管；钱够 → "入驻"那一刻只需一个兵走进去。

**为什么是 3 个兵而不是 1 个（原计划写的是 2 个，实测后改的）**：
守家兵规则（`role === 'home'` 无条件留 2 个）会先把人扣走。1 个兵时它被扣下、
`captureId` 为空、接管根本发不出去（那个兵一路走回城）。3 个兵时扣 2 剩 1，才有一个能派。
**这是 9.7 的第三处症状，而且比以前两处都硬：不是做错，是"没人可派"。**

**一换（T-1-02）**：多一座 14 格外的废墟，窗口内只够得着近的那座。
实测两道都是空壳红 / v1 v3 v4 绿——**T 轨第一档是护栏格，没有问题可修**，
它的作用是把地基钉住，让 T-2 / T-3 红了能归因。

这三道不是"一道比一道难"，是**三条轨道的起点**。这一点是上一版最大的错。

## 六、两条轨道的内部阶梯（现成的）

四个意图里，只有"接管"和"打"天生带阶段，这给了现成的档位划分：

**接管轨**：入驻（钱够、无威胁）→ 攒钱（钱不够，不许花）→ 清场（废墟旁有敌人）

对应第 1 / 2 / 3 档。S-016 → S-017 已经是"加一个守军"长出来的一对，是"加一法"最好的示范。

**发展轨**：站对一格 → 造几个造哪种 → 被打断时守不守得住。
第三档写不出来（缺威胁判断）。

**守轨**：三档都写不出来。

## 七、"加一法"（上一版唯一完整保留的机制）

**新题 = 最近一道绿题 + 改一处。**

- 红了 → 就是这个改动代表的那项能力缺；
- 绿了 → 这个改动没考到东西，降级成护栏题（防退化，不计成绩）；
- 改两处以上 → 红了也归因不了，不许这样做。

同一个轨道、同一档位内才有"加一"的意义。跨轨道不叫加一，叫换题。

已无意中验证过一次：S-016（空城）绿了之后加 4 个守军 → S-017（先清场再砸），
一道改动抓出真 bug（打分层把"按计划走一格"排在"攻城"前面）。

**步子 = 新题与最近一道绿题差几处，目标 1。** 拿这把尺子量：S-002 差 6 处
（推进、队形、清场、攻城、兵种交换、伤亡）。六处的题出现在"打·3"是合理的，
出现在别处就不合理。

## 八、题卡要带坐标（已做成工具行为）

`card.md` 头部多一行，写着就不是黑箱：

```
> 轨道：发展　档位：1 一件事　上一道：—（本格第一道）
```

`prev` 里写"上一道是哪道 + 只加了什么"，例如 `E-1-02` 写的是
`E-1-01（伐木工 + 森林）→ 本题只换一对：牧民 + 丘陵`。

**这行不是手写的**：`scenes/*.json` 里写 `track` / `grade` / `prev` 三个字段，
`make-scene.ts` 会把它抄进题卡（`exam-kit.ts` 的 `meta`）。不写就不出现，不影响老题。

有了这一行，"这道题红了该往哪儿修"就有了默认答案：先看上一道是不是绿的。

## 九、要改的旧规矩

| 旧规矩（出处） | 现在的问题 | 改成 |
|---|---|---|
| 新题必须先红（PLAN 5.5 第 1 条） | 护栏题天生就是绿的 | 分两类：**探路题**必须先红；**护栏题**允许绿，作用是防退化。题卡上明写 |
| 只动一道题 = 高度怀疑补丁（PLAN 5.5 第 10 条） | 同一格只有一道题时，"只动一道"是正常的 | 先问"这一格有几道题"再判断。所以每格配两道是这条的前提 |
| 一道题 = 六个文件（GUIDE 第五节） | 有效 | 不变；题卡加第八节那三行 |
| 判据只能用四种形态（README 第七节） | 有效（数量、次数、状态、累计量） | 不变 |
| 判据必须先被跑绿（PLAN 5.5 第 7 条） | 有效 | 不变；另外三段观测（开动了吗/到位了吗/达成目的了吗）的第一、二段也要有观测样本 |
| 题库会腐烂，定期体检（GUIDE 第十二节） | 有效 | 不变；失效报告多一列"哪一轨哪一档" |
| 种子卫生（README 第十节） | 有效 | 不变 |

## 十、代价与风险

| 风险 | 说明 | 预案 |
|---|---|---|
| 分轨以后"每条轨都会、合起来不会" | 四个意图各自成立，但一局里要来回切 | 切轨本身就是第 3 档的内容（建军时机）；再加"混合题"，判据只和上一道混合题比 |
| 发展轨的题测不到决定层 | 经济岗与意图无关 | 承认它只考约束层；不要把"发展轨全绿"当成"决定层没问题" |
| 补底下的格子短期看不到变强 | 这几天全是写题 | 事先接受。换来的是"每次红都知道红在哪一格" |
| 守轨封存太久 | 整行空着，看起来像漏了 | 在题库里留一行"封存：等 9.7"，别让它变成隐形欠账 |
| 四个意图将来可能不够 | 升级、侦查、关口都需要新的意图或新的动作 | 这是架构改动，单独立批；不混进出题 |
