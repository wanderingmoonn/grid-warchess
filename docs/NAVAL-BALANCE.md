# 海军阵营批量对局 · 平衡数据与 AI 改动

- 场景：**火药时代开局（era 3）· 群岛地貌（`isles`）· 20×20**，双 AI（`advanced`）对打
- 扩展：`bloodbath`、`height-terrain`（群岛地形由它提供）、`naval-fleet`，加上这一轮要求的现代组
  `pack-contemporary`、`pack-contemporary-war`、`naval-modern`
- 局数：**50 局 × 2 轮**（改动前 = `base`，改动后 = `v2`），同种子 `900..949`
- 回合上限 200，打满算"未决"

## 一、怎么跑的（可复现）

| 环节 | 做法 |
|---|---|
| 单局 | `scripts/balance-report.ts --era 3 --style isles --games 1 --seed <n>` |
| 并行 | `scripts/naval-batch.ts`：一局一个进程，32 并发（机器是 32 逻辑核 / 16 物理核） |
| 合并 | `scripts/naval-merge.ts`：**先加原始量、再重算比率**，不对比值取平均 |
| 复现 | 第 i 局种子恒为 `900+i`；分片、并发、顺序怎么变，合并结果一致（已实测两局分片 == 连续跑） |

实测：50 局墙钟 **144s**，单局 CPU 合计 2299s，**加速比 16.0×** —— 正好等于物理核数，
说明 32 个进程已经把 16 个物理核吃满，再提并发只是互相抢 SMT 线程。

产物：`results/naval/merged-{base,v2}.json`、`report-{base,v2}.md`。

## 三、诊断：为什么"群岛局没有海战"

三条，按影响排序：

1. **AI 根本不会装船。** `unitCandidates` 只生成 ATTACK / SIEGE / BUILD / MOVE，
   **没有任何 LOAD / UNLOAD**。船能开炮、能走位，但永远运不了人。
2. **群岛图永远留一条陆路。** 地图生成器用"一条浅滩带把两岸连起来"（`height-gen` 的
   `buildIsles`），实测 **50/50 局**双方都能徒步走到敌方城下。于是"陆路不通"这个条件
   一次都没成立过，船也就从来没有过刚需。
3. **采购里水军只有固定减分。** `-8`（水少时再 `-10`），不区分"这片水能不能绕开"。

## 四、改了什么（`src/core/ai.ts`）

| 改动 | 位置 | 说明 |
|---|---|---|
| 新增 `navalTransferCandidates` | `unitCandidates` 尾部 | 运输船的 LOAD / UNLOAD 候选，AI 第一次会装人 |
| 上船判据：比两种到场 | 同上 | 船走水路几步 vs 那个兵走陆路几步，**水路快 4 格以上**才装；走不到（∞）当然运 |
| 下船判据：到对面那侧才放 | 同上 | `enemySideScore > 0`（离敌方城比自家城近），落点还要真能站人 |
| 新增 `seaDemand()` | 采购 | 0 = 船是奢侈品，1 = 船就是路（陆路不通），0.5 = 水域宽，0.2 = 点缀 |
| 水军减分按需求缩放 | `recruitCandidate` | `-8×(1-demand)`，运输船另加 `40/22 × demand`（没有船时最急） |

三条守门用例（`scripts/test-ai-optimization.ts`）：两座岛、中间整条深水时
必须装船 → 到对岸必须放人 → 把海填成平地后**不许**装船（防"一船船往回运"）。

## 六、平衡意见

### 偏强

| 对象 | 证据（基线） | 方向 | 预期影响 |
|---|---|---|---|
| **火炮**（E5，320 金） | 每百金输出 75.5（全场第一，是步枪兵的 1.9 倍）、交换比 6.48、造 79 个 | 造价 320 → 380~400，或把射程优势从"全距离"收成"远距离"（近身 −30%） | 每百金输出回落到 55~60，仍是最强支援，但不再是"有錢就无脑造" |
| **浅水重炮舰**（E4，330 金） | 交换比 3.22、每百金输出 40.9、承伤仅 12.7（海军里最能打又最耐） | 造价 330 → 370，或射程 3 → 2 | 水军内部会让位给潜艇/巡洋舰，避免"一条船打穿一条河" |

### 结构性建议（不是数值）

1. **让群岛地图有时真的过不去。** 现在 50/50 局都有浅滩带，所以"海军"在这张图上永远是
   可选项。建议给 `buildIsles` 一个概率：约 1/3 的局**不铺**浅滩带（或只铺一半），
   让船从"奢侈品"变成"唯一的路"。这是让海军真正进入博弈的最便宜的一刀。
2. **现代组在这个时代没有意义。** `naval-modern`（E6）与两个现代包在城市最多升到 E4/E5
   的局里一个兵都不会造（数据里只有 1 条导弹快艇是 E6 城主线的偶然产物）。要么把
   时代的升级速度调快，要么这类"未来包"在 E3 开局里就别默认开——它会稀释兵种池。
3. **AI 侧的可选改进**（本轮没做，怕一次改太多难归因）：
   - 舰队"护航编队"：运输船 + 1 条战舰同行，别让运输船单独过海；
   - 沿岸炮击：让战舰优先打"贴着岸的敌方攻城单位"，而不是谁近打谁。

## 七、局限

- 只有 50 局/轮，逐单位的样本仍偏小（护卫舰 1、铁甲舰 1、察打无人机 29），
  这些行只当方向参考，不当结论。
- 统计口径是"野战交换"：攻城打的是城市耐久，不计入单位输出（见 `balance-report.ts` 头注释）。
- 运输船在这两轮里都是 0 条，所以"装卸"这套逻辑只在用例里验证过，
  还没被真实对局的数据覆盖——要它产出数据，得先做上面第 1 条（让海真的挡路）。
