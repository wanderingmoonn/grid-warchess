## 队列

### 第 1 步：把 X-1-01 的红修掉——**守队也要有 focusId**

- **为什么**：`pickFocus` 的判据本来就是对的（能斩杀优先），只是只发给了 `press` 队。
  X-1-01 证明守队各自"打血最少的"会各打各的。
- **做法**：约束层给 `hold-c1` / `recall` 也算 `pickFocus`（不新增判据，不写新比较器）。
- **验收**：① X-1-01 转绿（城血 ≥77，四颗种子）；② D-1-01/02/03 不退；
  ③ S-009（守城 + 造兵）读数不变；④ 全量 22 道除 X-1-01 外红绿不变。
- **可能弄坏**：S-013（两城分兵，守军行为会变）、S-004（该不该收手）。
  这两道本来就红，但要对比读数不能更差。
- **风险**：低。这是"把一个已经写好的判据发给第二个读者"，不是新机制。

### 第 2 步：X-1-02（同一格一换）

- **为什么**：X-1-01 只有一道，按规矩不算"立住"；一换能证明考的是机制不是这张地图。
- **换什么**：换**覆盖形状**——让"能合打的目标"是那个残血的，而不是血多的那个
  （把 20/36 对调，再造一次不对称覆盖）。如果 v4 修完第 1 步在这里仍绿，
  说明它真的按"能不能收掉"选，而不是按"血少"。
- **验收**：v1/v3/v4 全绿 + 空壳红（护栏），或 v4 红（继续当探路题，但要能指出红在哪一层）。

### 第 3 步：X-2-01（两件事：集火 + 靠拢）

- **为什么**：X-1-01 测的是"不用动就能合打"（远程）。真正缺的是**近战要走到同一个敌人身边**，
  而 v4 的走位是"照计划走一格"，没有"这一步能多打到谁"这个概念（v1 有，附在走位分数里）。
- **局面**：进攻面（`press` / `stage=clear`），我方 2 个近战 + 1 个远程 vs 2 个守军，
  两个近战**都能走到同一个敌人的相邻格**，但要走不同的两格。
- **判据**：第 N 手前把这两个守军清掉（用 `cityHp` 或 `unitCount` 这类按手采样的量；
  **别用 `foeLost`**，它是全程累加量，`in` 无效——X-1-01 踩过）。
- **预期**：红（v4 没有前瞻）。红了就进第 4 步。

### 第 4 步：加"一步前瞻"（只在打分层，二值判断）

- **做法**：`focusId` 在射程外时，问"这一手能不能走到一个打得到它的格子"；
  能就去，不能就走原来的路。**不加分数项**（加项会让落点跑偏，项目里已证伪一串）。
- **验收**：① X-2-01 转绿；② S-000 / S-005 / S-016 / S-017 不退（这四道都吃走位）；
  ③ S-011 的"一次送够 6 个"不许变差。
- **风险**：中。它会动 press 的走位，是全量回归里最容易翻车的一改。**改一处跑一批**。

### 第 5 步：9.14（`rest` 摘人 → 一个单位一个任务）

- **为什么**：站在关键格上的兵会被摘出所有队伍，**静默失去任务**；队里人数还少算一个，
  会让 `press` 的"人够了没有"判断失真。
- **做法**：不摘人，改成"这一手只干让开"的 order（或 `yieldFirst` 标记）。
- **验收**：S-001（过桥 + 接管）、S-009（守城造兵）不退；keepClear 那条链的行为指纹不变。

## 判据规矩（这次新加的两条，写进 `exams/README.md` 第六节）

1. **想按"第几手"判，只能用按手采样的量**（`cityHp` / `cityOwner` / `unitCount` / `unitsNear`）。
   `foeLost` / `recruited` / `lostUnits` 是**全程累加量**，`in` 对它们无效。
2. **摆局面要分清"为战斗摆的"和"为决定层摆的"**：决定层要"对面身价 > 我 0.9 倍"才选守，
   凑不够就放一个**6 手里走不过来**的敌人——它只影响决定，不影响战斗。
