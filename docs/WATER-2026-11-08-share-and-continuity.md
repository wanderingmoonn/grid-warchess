# 水域：占比提到 20%，并把"连通"还给水（2026-11-08）

一句话：**水从 13.8% 提到 20%，并且不再被"必须打通"填断。** 代价是陆地不再保证
走得通——桥、船、飞行兵接住了这件事，这是这一版明确接受的取舍。

---

## 一、起因

两条反馈叠在一起：

1. "水域过于零散"——一堆 1~4 格的水坑，既不像湖，水军下水也没地方开。
2. "你不连通海军太难发挥了。现在最缺的就是河流的连通性，大湖也缺。"

第 2 条指向的不是"水太少"，而是**水被切断**：`mapgen.carve()` 会沿着"陆军最省事的
那条路"把水凿成浅滩或平原。一条横贯全图的河，被 2~4 处渡口 + 若干次开凿切成几段，
水军只能在每一段里转圈。

## 二、几何上的死路（先说清楚，免得再走一遍）

"渡口留一条 1 格宽的水道，陆军从岸边过、船从中间穿"——**做不到**。

- 陆军过河是**垂直**穿过河宽方向：河宽里只要剩一格水，那一列就过不去；
- 船要求每一列至少一格水，且**正交相连**。

同一格不可能既挡陆军又放船——除非它同时"能走又能开船"。游戏里这个东西就是
**浅滩 `shallow`**（`config.navigable()` 含它，陆军移动力 2）。

所以这一版把**浅滩升为本体地形**：渡口一律画浅滩，河从头到尾都是水面，
船能开到底，陆军照样徒涉。

## 三、改了什么

| 位置 | 改动 |
|---|---|
| `mapgen.carve()` | **水一格不动**，只给山开隘口 |
| 双人 / 三人局连通性 | 不再"为水开路"（四人局早就是这个口径，这次统一） |
| `paintRiver` 渡口 | 无条件画 `shallow`，不再看有没有开「地形高差」 |
| `height-mapgen.carveGreatRiver` | 渡口改成**整条横截面**都是浅滩（以前只画河岸两格，河心永远是深水，等于没有渡口）；抽不到时中段强制开两格 |
| `enrichTerrain` 的湖 | 面积按"目标 20% − 已有水"反推；块数按缺口给；改圆盘生长（新增 `blobRegion`） |
| `blobRegion` | 圆盘 + 边缘噪声 + 填洞 + 从种子泛洪，"走不到的碎块"一律退回平地 |
| 湖的落点 | 每对都优先**贴着已有水**生长：湖是河的"湾"，湖与湖串成一片 |
| 城边水 `lakeNearCity` | 从"2~4 格水坑"改成 5~8 格**港湾**；优先朝已有水的方向铺；吃水预算；撞到别的城就停 |
| 城郊规则 | 从"最多留 2 格水"改成"保证城外有 ≥3 格陆地"，其余水保留（填也只填浅滩） |
| 支流门槛 | `size >= 28` → `>= 22` |
| 河宽上限 | `span * 0.42` → `span * 0.26`（12×12 上原来的上限能到 5 格，光河就占两成） |
| 新增 `topUpWater` | 收尾量一次真实占比，不足才补，**只补不削**；只对本体地貌做 |

## 四、实测（4 尺寸 × 4 地貌 × 40 seed = 800 张）

| 指标 | 改前 | 改后 |
|---|---|---|
| 平均水占比 | 13.8% | **19.95%** |
| 单张区间 | 6%~22% | **13.2%~25.2%** |
| 水域块数 | 6.64 | **3.97** |
| ≤2 格碎水 | 3.46 / 图 | **0.83 / 图** |
| 最大水块占全部水 | 67% | **70.9%**（河图 90.6%） |

按地貌：横河 21.0% / 纵河 21.1% / 山岭 18.5% / 开阔 19.1%。
按尺寸：12 → 20.2%、16 → 19.9%、20 → 19.5%、24 → 20.4%、32 → 19.8%。

**没到 100% 的连通度是结构性的**：公平图把水按点镜像分给两边，A 的水和 B 的水
永远不可能是一块水体，所以"最大块/总水"天然封顶在 50% 左右。河图能到 90%，
因为那条河本身横贯全图。

## 五、代价与兜底

- **陆地不再保证走得通。** 被水隔开的图要靠桥（`bridgeChainOk` 支持接龙，任意宽度
  都能架）、船或飞行兵。AI 批测 12 局全部正常打完（均 56.3 回合），没有出现
  "两军互相看着"。
- **仍保留两条硬底线**（它们不是"连通性"）：
  1. 山必须开隘口——桥架不过山，飞行不是每族都有；
  2. 城外必须留 ≥3 格能站人的陆地，否则开局一个兵都摆不下。
- **`fordless`（无渡口的天堑图）原样保留**：它本来就一处不断，只靠桥过，这次没动。

## 六、测试契约的变更

| 用例 | 旧契约 | 新契约 |
|---|---|---|
| 任何种子下四座城都连得通 | 陆军必须走得到 | **被水隔开可以（但架得起桥），被山隔开不行** |
| 河道能长成成片的大水域 | 只数 `~` | 浅滩也算水（渡口是浅滩，不然会把河统计成几段） |
| 水军只能在水上走 | 落点必须 `water` | 落点是 `navigable()`（含浅滩） |
| 地形高差默认不开 | 不勾就一格新地形都没有 | 浅滩除外（它已是本体地形） |
| 选卡：旱地图 | 靠 seed 抽到一张旱图 | 显式把水抽干（现在没有天然旱图了） |
| AI 弃城 ×2 | 城门口直接摆兵 | 先 `dryWater()` 再摆（水多了会摆不下） |

## 七、上线后的补丁（22:40，用户报"新开一把只有 7%"）

第一版只在**双人 + 本体地貌**上做对了。追下去是三个洞：

| 洞 | 症状 | 修法 |
|---|---|---|
| 收尾补水只肯长在"干净空地"上 | 12×12 **山岭**图最低 **6.9%**——小图上空地早被散布的丘陵/林地占完，补水找不到落点直接返回 | 放宽到"丘陵、林地也行，**山不行**"（`blobRegion` 新增 `ground` 参数；`topUpWater` 不再认 `blocked`，只认"别动城"） |
| **多人图一格都没调** | 3 人图均值 **7.9%**、4 人图 **6.7%**，最干的种子 **0%** | `generateMultiLayout` 补一段水域校平，用同一个 `WATER_TARGET` |
| 等高线地貌（「地形高差」）跳过了补水 | 同一套阈值能出 **2.5%**，也能出 **43%** | 等高线图也补水，但只淹 `plain/valley/marsh/forest/hill`——台地、山不碰 |

多人图的补水要保住公平，两条口径分开写：

- **四家**：只长一处，再把**画上去的那几格**按 90° 镜像复制三份。
  第一版是"四个镜像点上各长一次"，可 `blobRegion` 每次都要摇随机数——
  四次形状不一样，逐格镜像对称当场就破（实测差 28 格，被那条用例逮住）。
- **三家**：方格棋盘没有 120° 旋转对称，只能做数量公平。每轮挑**水最少的那个区**
  补一块，补到三家齐平（第一版"每区各长一块同样大小的"会差成 26/29/20，同样被逮住）。

补丁后实测（每档 40~200 个种子）：

| 配置 | 均值 | 最低 | 最高 |
|---|---|---|---|
| 2 人 10×10 | 21.7% | 12.0% | 30.0% |
| 2 人 12×12 | 19.9% | 14.6% | 25.0% |
| 2 人 16×16 | 19.6% | 16.8% | 24.2% |
| 2 人 20×20 | 19.7% | 18.0% | 21.5% |
| 2 人 32 / 48 / 64 | 19.7%~19.8% | 18.8% | 22.3% |
| 3 人 16 / 20 / 24 | 18.9%~19.2% | 16.4% | 26.2% |
| 4 人 16 / 20 / 24 | 17.3%~19.4% | 15.6% | 22.0% |

**已知未处理**：勾了「地形高差」时，那种等高线图本身的水量波动很大
（同一套参数能到 50%），这一版只保证"不低于目标"，没给上限做收敛。
要压上限得改 `height-mapgen` 的阈值分层，是另一件事。
