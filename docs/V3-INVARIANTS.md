# v3 的硬前提（不变量）

> 动 v3 之前先读这一页。下面这些"帽子"已经摘掉，代码里不该再出现它们的逻辑或注释。

## 1. 没有单位编制上限

- `CONFIG.maxUnits = 24` 是**v1 给自己戴的帽子**，不是游戏规则；规则层招募不拦玩家。
- v3 的 `unitCapOf` 默认 `Infinity`（2026-11-21 用户决定）。
- **2026-11-22 已彻底删除**：`unitCapOf`、`swapOutCandidate`（换血整套）、采购里的
  `编制已满` 拒绝、`SWAP_GAIN`、以及所有"24 个兵/编制满"的注释。
- 以后看到"编制满"三个字，一律当作过时残留处理，不要照着它加条件。

## 2. 没有"每城 2 个经济单位"

- 经济投入由 `solvePower` 的 `econUntil` 决定（`aiEconPlan`）；**地块容量**是唯一上限。
- `econRoom = 城数 × 2` 只在 `aiEconPlan` 关时作为旧口径保留，不是 v3 的默认行为。

## 3. 没有编队数量上限

- `maxSquads` 只在 `aiSquadUnlimited === false` 时生效（默认不限）。
- 约束换成两个独立的下限：每支 `want` 5~9、建队要 3 个散兵；不再用"限制支数"防散兵。

## 4. 单位级指令是过渡形态

- `fields.scout` / `fields.peek` 是临时字段，**最终都要进编队**（用户 2026-11-22 明确）。
- 新机制不要再照着这个形状加字段；优先扩编队（`AiSquad`）与计划指令（`PlanOrders`）。

## 5. 计划层是唯一的目标来源

- 编队不自己挑目标（39.1 的教训：让编队自选 = 全量 8-9-7，配对 4↑8↓）。
- 编队只执行；"打哪座城、去哪个渡口、修哪座桥"都由计划层的 `orders` 给。

## 6. 难度不靠数值

- 难度来自"有没有安全位 / 有没有必须回应的威胁 / 玩家能不能看见发生了什么"，
  不是给 AI 加编制、加钱、加战力。
