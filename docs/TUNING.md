# 可调参数台账（2026-11-22 建）

## 为什么要有它

用户的原话："以后调的参数越来越多，我怕我以后记不住了。"

问题不在"参数多"，而在**没有唯一的查询入口**：值写在代码里、理由写在注释里、
改过几次写在提交信息里，三个月后没人分得清哪个数标定过、哪个是拍的。
所以定两条：**拍的值必须打标记，清单必须能自动生成。**

## 约定

1. 拍脑袋定的、以后要调的值，在注释里写 `@tune`，后面跟一句"为什么是这个数"。
2. 有推导、有实测支撑的常量**不标**——它们是结论，不是旋钮。
3. 改值的时候顺手改那句理由，并写清是哪次跑批定的（或"未标定"）。

## 怎么查

```bash
npm run tune:list          # 按文件列出来
npm run tune:list -- --md  # 输出 markdown 表格，可以贴进文档或发给人看
```

脚本在 `scripts/list-tuning.ts`，扫的是 `src/**/*.ts` 里的 `@tune` 标记。

## 为什么不把所有参数搬进一个对象

集中成一个大对象确实更好查，但 `ai-v3.ts` 里这些常量紧贴各自的使用处，
搬走之后"为什么是 8"离代码就太远了。用标记 + 脚本扫描，兼顾"就近可读"和"全局可查"。

`ai-plan.ts` 的 `PLAN_TUNING` 已经是集中对象（计划层的值都在里面），
它不需要 `@tune` 标记——它本身就是清单。
