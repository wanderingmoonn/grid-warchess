# 2026-10-29 · 攻城记账、房间聊天与英雄调整

六件事，一句话一件：

1. 攻城伤害不再是一套单独写的算式，而是走野战那几个函数——**法师攻城不再等于零**；
2. 大型单位挨溅射只结算一次，不按它占的格子数翻倍；
3. 投降终于会同步到对面（以前发起方结束了，对手还在等下家）；
4. 房间里能说话，观战者也能；
5. 刺客大师的隐匿从"冷却 2"改成"一池 3 发、每 2 回合回一发"，界面上写清还剩几发；
6. 至尊法师按新数值重排，单位卡多一行「当前属性」；顺带把参谋部的检索从搜索框换成
   **DLC + 时代**两维筛选。

---

## 一、攻城与野战：同一套账

### 以前

`computeDamage`（野战）和 `damageToCity`（攻城）是两份各自长大的代码。结果不是"略有出入"，
是**两条完全不同的规则**：

- 野战：攻击力（基础 + 光环 + 状态）− 护甲 → 再叠 `magicAtk` 魔法段（只被魔抗挡）
  → 再乘属性克制倍率 → 钩子链；
- 攻城：`atk − city.armor` → 走 `siegeDamage` 钩子 → 结束。

于是所有"在野战里成立、在城墙前失效"的东西，都变成了攻城时的漏洞：

| 东西 | 野战 | 攻城（以前） |
|---|---|---|
| 魔法攻击 `magicAtk` | 算 | **不算** → 至尊法师打城 = 0 |
| 属性倍率（火/水/自然/暗） | 算 | **不算** |
| 威吓 `fear` | 算 | **不算** → 带威吓的兵攻城反而更疼 |
| 状态（中毒/燃烧的减攻） | 算 | **不算** |

最刺眼的是至尊法师：36 点魔攻、攻击力为 0，站在城下就是一块不会动的石头。

### 现在

把野战那几步抽成函数，攻城直接调用同一批：

```ts
attackPowerNow(s, attacker)                 // 基础 + 光环 + 状态修正
magicSegment(s, attacker, magicRes, foe)    // 魔法段（只被魔抗挡）
applyElementMul(damage, el, weak?, resist?) // 属性倍率
```

`damageToCity` 现在是五步：

1. 攻击力 − 威吓 − 城墙护甲（保底 0）；
2. `siegeDamage` 钩子（破城 ×1.5 这类）→ 扩展的 `modifySiegeDamage`；
3. `+= magicSegment(s, attacker, 0, null)`；
4. `applyElementMul(...)`；
5. 取整、保底 0。

第 3 步的 `magicRes` 传 **0**，不是漏了：`City` 上没有魔抗这一列，**也不打算加**——
城市本来就该被法师克制，给城墙一条法抗等于把"带法师攻城"这条战术关掉。
这也正是"法师攻城不再等于零"的来源：至尊法师现在对城墙稳定打出 36 点。

### 什么东西停在城门之外（写清楚，免得以后被当成漏项）

- **地形加成不叠**：`terrainAtkBonus` 说的是"站在这块地上打得更准"，城墙又不站在那块地上。
  更实际的理由是——它已经通过 `attackPowerNow` 的 `auras` 进了一次，再算一遍就是重复计算；
- **驻军与状态钩子跳过**：城里的守军是"另一支部队"，不是这一下的目标。
  状态（中毒、燃烧）在攻城时按 `fearPenalty` 那条路一次性减掉，不再单独跑一遍；
- **射程折扣不适用**：远程拆桥那套"隔一格半伤"是给**桥**的，城墙没有这个概念；
- **不再跑 `modifyDamage`**：`modifySiegeDamage` 和它的差额是同一笔加成（"全军攻击 +X%"
  这种按攻击力算的规则），两条都跑等于给攻城算两遍。这条注释留在代码里。

### 大型目标挨溅射只结算一次

`footprintOf` 让一个大单位占 2×2 或更大，于是"溅射半径罩住了它的三格"这种判定会
让同一个目标挨三份伤害。修法是把去重做成显式的：

```ts
const seen = new Set<string>([defender.id]);   // 被直接打的那个先记上
for (const v of unitsOf(...)) {
  if (distBetweenUnits(s, defender, v) > radius) continue;
  if (seen.has(v.id)) continue;
  seen.add(v.id);
  ...
}
```

距离用 `distBetweenUnits`（按身体最近边算），不用格子中心——不然一个 2×2 的大家伙
明明贴着半径边，也会被判成"够不着"。

## 二、房间里能说话

### 为什么不能塞进 `GameState`

第一反应是"加个 `state.chat` 数组"。三个问题，每一个都是致命的：

1. **整块覆盖**：房间那一行存的是整局快照，`submitTurn` 是"整块写回 + `.eq('turn')` 防覆盖"。
   聊天跟着它走，就只能**等对方结束回合**才能看到你说的话——两个正在对峙的人说不了话；
2. **观战者根本不提交**：观战位不占座、不写云端，聊天对它等于不存在。而"观战者也能发言"
   正是这次要的东西；
3. **"只改 chat 字段"也不行**：那要先读整行再整块写回，中途对方提交的那一回合会被这次写回
   抹掉——正是 `.eq('turn')` 在防的事。

所以单开一张表：`warchess_chat`。一条消息 = 一次 `insert`，天然不互相覆盖；
读是"按 id 增量取"（`.gt('id')`，一次 50 条）。玩家和观战者走的是同一条路，
这一层没有任何区别。

### 形状

```ts
// src/net/chat.ts
CHAT_TABLE = 'warchess_chat'
CHAT_MAX_LEN = 120
type ChatSeat = 'A' | 'B' | 'watch'

trimChatBody(raw): string          // 去控制字符、压空白、截断，返回空串＝别发
chatWhoLabel(seat, mine): string   // 站在"我"的角度写：我 / 对面 / 观战
chatTimeLabel(at): string
chatLinesHtml(lines, mine): string // 整条转义 + 三类归属 + 空态
fetchChat(code, afterId)           // 增量取
sendChat(code, seat, name, raw)    // 一次 insert
```

`chatWhoLabel` 特意不用 A/B：屏幕两边都写着同样的名字，说"B 说"对双方都是错的。

### 界面

右下角一个气泡按钮（未读数写成角标），点开是浮层：消息区可滚、输入框 + 发送。
壳子只建一次（`ensureChatDock`），重绘只换里面的行——不然每 4 秒轮询一次就把
正在打的字和焦点一起清掉了。发失败（断网、表没建）会把打好的字**还回输入框**。

### 建表

`sql/warchess_chat.sql`：表 + `(room, id)` 索引 + RLS + `grant select, insert` +
两条 policy。**只给读和写，不给改和删**——聊天记录发出去就收不回，这是有意的。

没建也能开局，只是点开聊天会说"需要先在云端执行 `sql/warchess_chat.sql`"，
而不是含糊成"网络不通"。错误码翻译在 `classify()` 里（42P01 = 表不存在，
42501 = 权限不够）。

### 边界

房间码就是钥匙：拿到 6 位码的人能读也能发，没有身份校验，也没有私聊。
别在聊天里放真名和联系方式——邀请链接别往公开场合贴。

## 三、投降为什么同步不过去

### 根因

认输这个动作**既不推进回合，也不换行动方**。而联机轮询里"接收对方状态"的分支，
前提条件写的是：

```ts
if (remote.current !== mySeat) return;   // 不是我的回合，不动
if (remote.turn === local.turn) return;  // 回合没变，不动
```

一方投降 → `state.winner` 变了，但 `current` 和 `turn` 一个都没动。于是：

- 投降的人自己看到结算卡；
- 对手那边两条前置条件都不满足，**永远不采纳**，还在等下家行动。

### 两侧都修

**发起方**：`dispatch` 里记下 `const prevWinner = state.winner;`，判完胜负立刻在同一个
函数里提交，不等玩家再点"结束回合"：

```ts
if (room && !prevWinner && state.winner) {
  dirty = false;
  void pushTurn(room, prevTurn, '这一局已结束，结果已经同步给对方');
}
```

**接收方**：把"要不要采纳对面这份状态"抽成纯函数，顺序即优先级：

```ts
export function adoptDecision(remote, local, seat): AdoptDecision {
  if (remote.winner && !local.winner) return { take: true, why: 'finished' };  // 终局压倒一切
  if (seat.spectator) { ...只看 turn/current/winner 有没有变... }
  if (remote.current !== seat.seat) return { take: false, why: 'not-my-turn' };
  if (remote.turn === local.turn) return { take: false, why: 'same' };
  if (seat.draft) return { take: false, why: 'draft' };
  return { take: true, why: 'turn' };
}
```

第一行是这次的关键：**终局不看是不是我的回合**。`why === 'finished'` 时顺便清掉本地
未提交的草稿标记，并 toast「对面已经结束这一局，你赢了」／「这一局已经结束，对面赢了」——
不然屏幕上只有一张结算卡，没人知道是谁先按的。

抽成纯函数的直接好处：这条规则现在能在规则测试里断言，不用起浏览器、不用连云端。

## 四、刺客大师：隐匿从冷却改成充能

### 以前

`cooldown: 2`。冷却的语义是"能放就放，放着就是浪费"——它逼你按节拍用。但刺客要的
恰恰相反：**攒着，等一个值得用的时机**。连开两回合（脱身 + 再进）是它唯一能主动
制造的机会窗口，而冷却 2 让它永远做不到。

### 现在

```ts
{ id: 'vanish', effect: 'vanish', charges: 3, regen: 2 }
```

- 一池 **3 发**，每 **2 个自己的回合**回 1 发（满发时计时器归零）；
- **一回合最多放一次**（`u.skillTurn === s.turn` 就拒）。这条以前是"冷却 ≥ 1"顺带保证的，
  改成充能型之后必须显式写，否则三发能在一回合里全打光；
- 界面写清剩余发数：单位卡和沙盒的「手上这支兵」都显示 `2/3 发`；
  没到点时写「1 回合回一发」。

数据形状：

```ts
interface SkillDef { cooldown?: number; charges?: number; regen?: number }
interface Unit { skillCharge?: Record<string, { n: number; t: number }>; skillTurn?: number }
```

`heroSkillsOf()` 成了唯一口径，返回 `{ def, cd, ready, charge, chargeMax, toNext }`：

- 冷却型：`ready = !skillCd[id]`；
- 充能型：`ready = n > 0`；老存档里没有 `skillCharge` 字段按**满发**处理
  （否则读一次存档，刺客的隐匿就凭空消失了）。

顺手修了一个连带 bug：`ai.ts` 的 `heroSkillCandidate` 原来直接读 `u.skillCd`，
充能型技能永远不会出现在那里——AI 整局都不会隐匿。现在它也走 `heroSkillsOf`。

## 五、至尊法师：新数值 + 当前属性

| 项 | 以前 | 现在 |
|---|---|---|
| 攻击 | 10 | **0** |
| 魔法攻击 | 26 | **36** |
| 护甲 | 6 | **10** |
| 魔抗 | 10 | **14** |
| 射程 | 5 | **6** |
| 视野 | 8 | **9** |
| 造价 | 590 | **640** |
| 首招解锁费 | 300 | **350** |

攻击归零是有意的：它的伤害**全部**来自魔法段（36 点，只被魔抗挡）。以前那 10 点物理
是为了"至少能敲一下"，代价是每一下都要先减对方护甲——打重甲兵时永远是 0，留着只会
让人以为它能肉搏。现在的分工很清楚：物理归零、魔法拉满，护甲再高也躲不掉那 36 点。

护甲/魔抗/射程/视野这一档换的是"站得住、看得远、够得着"。它不是靠血厚活下来的兵，
是靠"对面还没走到就已经挨了两轮"。

### 界面上新增「当前属性」

单位卡多两行：

- `魔法攻击 / 魔抗`（只在 `def.magicAtk` 存在时出现）；
- `当前属性`：写着这一回合的元素（火/水/自然/暗），带一句效果说明
  （`ELEMENT_EFFECT`，例如「火：命中带燃烧」），能切换的再补一句「（可切）」。

以前这个信息只在棋盘上的小图标里，而图标又和"属性克制"的箭头混在一起——玩家知道
"我好像是火"，但不知道"火具体干什么"。

## 六、参谋部：检索换成 DLC + 时代

上一批给参谋部加的是"搜索框 + 职能分类 chip"。五个下拉、每个六七十项，光靠敲字找不到
自己缺哪个包，而职能分类（近战/远程/机动…）回答的是"这兵怎么打"，不是"它从哪来"。

现在换成两个维度，可单独也可叠用：

| 维度 | 取值来源 | 「全部」的表示 |
|---|---|---|
| DLC | `packOf(def)` ——原版兵归到 `core`，标签取 `packRow` | `PACK_ALL` |
| 时代 | `def.era`，标签取 `eraDef(level).name` | `0` |

- 两个维度都是 **空 = 不筛**，条件之间是 **AND**（`cmdPass`）；
- chip 再点一次 = 回到全部；
- 边界一致：只有一个包 / 只有一个时代时，**整条筛选行都不出现**（`packRow` 与
  `eraChipRow` 都按这个规矩返回空串）——留一颗点了没反应的按钮比不显示更糟；
- 没命中时下拉里写「（这个筛选组合下没有兵种）」，计数写 `0 / N`，而不是给一个空下拉；
- 结果的展示与交互一个没变：还是那五个下拉 + 计数。

## 验证

| 闸门 | 结果 |
|---|---|
| `npx tsc --noEmit` | 通过 |
| `npm run test:rules` | 375 项（+6） |
| `npm run test:ui` | 136 项（+4，删 2） |
| `npm run test:ai-optimization` | 26 + 7 项 |
| `npm run build` | 通过（js 405.70kB / gzip 153.86kB） |
| `npm run manual` | 通过，6 册 |
| `npm run perf` | 最快 4.14ms / 最慢 12.6ms（与上一批同档） |

新增用例都是先确认"改之前是红的"：

- 把 `damageToCity` 的魔法段改成 `+= 0` → 「攻城和野战走同一套公式」FAIL；
- 把 `adoptDecision` 的终局优先那行删掉 → 「投降同步」FAIL；
- 把 `cmdPass` 的时代判断短路 → 「按 DLC 筛」FAIL（`4 代应该有兵、且比全部少：13/13`）。

新增的六条规则用例：攻城与野战同账（法师攻城 = 36、威吓削物理段）、大型目标溅射只结算一次、
隐匿充能（一池 3 发 / 每回合一次 / 每 2 回合回一发）、投降同步、聊天文本清洗、
聊天记录渲染（转义 + 三种归属 + 空态）。

界面侧：DLC 筛选（单独、叠时代、空组合、退回全部）、只有一包一代时筛选行不出现、
本机对局没有聊天入口、英雄面板显示剩余发数与当前属性。

## 没做的事

- **城市没有魔抗**：不是漏项（见第一节），但如果以后要给城加抗性，`applyElementMul` 那行
  已经留好了 `weak/resist` 参数位。
- **聊天没有历史加载**：只拉最近 50 条，往上翻不补页。真要补是分页游标的事，
  而不是"再多拉一点"。
- **聊天没有@、没有私聊、没有"正在输入"**：房间码就是钥匙，这三样都需要身份，
  而这一层刻意没有身份。
- **观战者发言不标注"观战中"以外的身份**：观战位没有昵称，统一显示「观战」。
- **参谋部的筛选状态不进存档**：换个开局回到"全部"。
