### 拆供货（关键纠正）

查证结果：**供货逻辑从来没被删过**（不是注释没删）。五处仍在生效：
`doBuild` 落成钉 `era: supplyEraAt`、`doBuild` 的"落成即废"守卫、

两条测试钉着它（`军营产兵的时代取最近的己方城市`、`落成即钉死`）。

改法：产兵建筑按**自己的档位**出兵（`def.era`），`Unit.era` 字段删除，
"没有城市"那条门一起删（孤军营能补兵，绕后骚扰放开）。

**连带必须补的一道闸**：以前"二代工匠修四代造船厂"是被供货守卫顺手挡住的
（早修也造不出东西）。删掉供货后二代能直接修出四代产线 → 在
`buildSiteError` 顶部加 `def.era > builderDef.era` 拒绝。用**建造者的档位**
而不是城市时代，整条链只剩"档位"一个概念。已用探针核对全扩展：没有
"建筑 era 高于所有建造者"的数据。

`supplyEraAt` 保留为 `@deprecated` 导出——`scripts/baselines/ai-*.ts` 是带
sha256 的冻结快照，仍然 import 它，删了 `test:ai-optimization` 直接崩。

### 通用产兵判定（对称建造）

新增 `rules.produceAt(s, source, target)`，source = 城市 | 产兵建筑，一条链：
建筑/召唤物 → `campOnly`（城市不产）→ 白名单 → 时代（营按自己的、城按城的）
→ 选卡名单 → `produceNear` → `ExpansionHooks.produceBlocked`。
规则层 / 面板 / AI 三处共用（此前 AI 一次都不查白名单，会在船坞里点民兵）。

- `UnitTypeDef.campOnly`：只能由产兵建筑造；同时进 `draftAlwaysAllowed`
  （跟着建筑走，不该被 ban），因此自然不进选卡池。
- `UnitTypeDef.produceNear: { terrain?, unit? }`：与建筑选址 `adjacent` 同一套
  几何（占地每格 + 四邻），抽了 `adjacentHit`/`adjacentSatisfied` 给两处共用。
- `ExpansionHooks.produceBlocked`：境界/资源/周围站人这类条件的逃生口。

## 实机反馈后的两处修正

1. **建造列表里出现高代建筑**（点下去弹"要X代的工匠"）。根因：`builds` 白名单
   是"这列工人会的手艺"，不等于"这一档盖得起来"——海军包在开局给所有会架桥
   的工兵补了船坞/造船厂，二代工匠于是挂着四代造船厂。修法：`buildListOf`
   新增 `eraOf`，默认滤掉 `建筑era > 建造者era`；六个消费者（面板/属性卡/
   选卡卡/开局/上帝/规则书）各传一个查表函数，规则只写在 buildListOf 一处。
   探针核对：三代劳工白名单 10 条 → 实际列 8 条（少了造船厂、海军船台）。
2. **普通军营里出现灰着的法器**。根因：`produce.units` 不写 = 不设限，
   军营因此认一整张兵种表，连 campOnly 的法器也伸手；`produceAt` 的 campOnly
   判断只对城市生效。修法：`canProduce` 里补一条——`campOnly` 的兵只有
   **点名写进白名单**的产兵建筑才认，空白名单不再等于全认。

测试：rules 634、cultivation 67、ui 189（+军营不列法器、+建造列表按档位过滤）。

## 后三件法器 + 飞行（2026-11-08 傍晚）

用户拍板：四件法器都加 `fly`；玄石印保留"丘陵或 2 灵矿"（2 代造不出灵矿，
那是"地图没丘陵"的兜底）；护甲/真元百分比都带 **+1 保底**；debuff 波及溅射
但**不动现有兵种**；持续 2 回合不叠加；移动减半下限 1 是硬要求。

**新机制三件**：
1. `AuraSpec` 加 `allyArmorPct` / `allyTrueDamagePct`；`auras.ts` 抽出
   `bestAllyPctOf` 统一"取最强"的比较方向，三个百分比光环共用一个实现。
2. 两个状态 `chill`（移动减半，`Math.max(1, floor(move/2))`）与 `sunder`
   （护甲减半，按当前甲算）。放核心 `STATUS_REGISTRY`：它们不依赖任何修真
   概念，且 cultivation 侧 import rules 会成环。
3. 新钩子 `AbilityHooks.onSplash`：只对**溅射受害者**触发，主目标走 onHit。
   接在 doAttack / 攻城 / 炮塔三处。刻意不自动扩到 onHit——37 个既有溅射
   兵种的毒火一直只打主目标，扩大是平衡改动。

**踩到的坑（重要）**：`stats.ts` / `panel.ts` / `qi-true-damage.ts` 都不能
import `auras.ts`。初始化链是 packs → hooks/abilities → 这些文件，往上拉
`auras.ts` 会把 `ability-registry` 提前执行，而它顶层遍历 `EXPANSIONS`，
当场 `Cannot access 'EXPANSIONS' before initialization`。
解法：`HookCtx.trueDamagePct` 由 rules 注入（和 terrainBonus 同待遇），
`trueDamageWithMods(base, pct)` 做成纯函数。面板因此**看不到**"当前真元"
那一行——已删，避免再次成环。

**数据**：玄石印 12/9/52 溅1；寒水镜 16/3/30 射4 视5 溅2；赤炎珠 30/3/34 射3 溅2。
四件造价 180/190/260 金 + 10/12/16 灵。

**发现**：`fly` 的真实语义是"掠水"——**水面可以停**（`tileStandsOk` 里有注释
说明），但 `fly` 的 summary 写着"不能停在水上"。文案与代码不一致，是既有问题，
本期没改（改一句会动到所有带 fly 的兵种说明）。

验证：rules 651、cultivation 82（+7）、ui 203、ai 7+51、manual 9 册（能力 90 条）。

## 修复：宗门大殿看不到「研发」（提交 2a898af）

**根因**：产兵建筑点开时走 `ui/panel.ts` 的 `renderCamp` 分支，**不经过**单位详情卡
`renderDetail`；而扩展的 `unitActions` 按钮只画在详情卡上。宗门大殿是 producer
（招募弟子），所以它的面板永远是"生产 + 招募"，研发/遗弃按钮根本不存在。

我上一轮的渲染自查也骗了自己：我传的是 `selectedCampId: null`，走的是详情卡那条路。

**修**：`renderCamp` 的 `mine` 分支里补 `${mine && myTurn ? unitActionBlock(s, camp, me) : ''}`。
