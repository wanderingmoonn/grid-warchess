## 风场 + 湿度平流 + 「大风」（commit b329c62）

用户拍板：新标签「大风」、**只逆风步耗 +1**、风暴不上陆、**先做矢量风与平流**，
大风和风场合流（不要临时判据）。

**风场**：气压 ≈ −T，风 = 季节主导风 + k×∇T（温度先 3×3 平滑，否则山脚是锯齿风口）。
存 `Tile.custom.windX/windY`，单位「百分之一格/步」；缺省退回主导风（老存档零迁移）。
阵风表 `gust[8]` 每 2 回合换一档，让"这几天风大"成串出现。

**平流**：`stepHumidity` 变成 蒸发 → 半拉格朗日平流（双线性）→ 小扩散 → 凝结。
任意风速稳定；确定性只靠四则 + round + sqrt。

**大风**：只替换「温和」（13~20°C、不下雨），不抢凉爽/温暖——不亏玩家的增益。
效果 `airUpwindCostAdd: 1`。

**核心改动**：飞行原来在 `stepCostInto` 里硬编码 return 1、跳过所有钩子，
所以新增 `ExpansionHooks.airStepCost({state,unit,fromIdx,toIdx,cost})`——带方向，
逆风 dot<0 才加价。

**实测**：32×32 四季，大风 春 0~24% / 秋 0~19%（随阵风成串）、夏 0~3%、冬 0（无温和档）；
`stepClimateField` 0.87ms/次；`tune:climate` 33.3% 精确（原先 31.7%，平流没伤到拟合）。

**踩点**：
- `classifyClimate` 住在 **field.ts** 不是 climate.ts（改错文件浪费了一轮）。
- 大风阈值不能只看主导风：`galeAt` 26 + `windGrad` 450 是量出来的甜点，
  再高（36）就几乎不出现（0.3%）。
- 判"云有没有漂"要用**重心**，不能用 argmax——一个方块凸包的 argmax 恒在左上角。

## 换季平滑 + 每图气候带 + 对称主导风（commit d5868ff）

**换季跳变**的根因：目标温度是阶跃的，而陆地热容 48%/步，换季那回合直接吃掉
二十多度差额的一半。改成按**季节中点**插值（`seasonBaseOf`）：
仲春 15 → 仲夏 34 → 仲秋 15.5 → 仲冬 −6.5，换季那天正好在两季中间。
实测单回合 ≤1.9°C。**注意**：连续曲线 + "季中平台"在数学上不能共存
（平台两端必有一处要跳），所以只能选三角波。

**纬度**：`latitudeOf(seed)` ±5.5°C，乘散列不要用 `seed % n`（相邻种子会相邻）。
没有 seed 的最小 state 返回 0，否则调参工具会被整体平移。

**夏季 30→34、冬季 −6→−6.5**。冬季不敢再降：内陆 amp=1.15，−7.5 时
`136+(−75−136)×1.15 = −10.7` 就跌破严冬线，整片内陆会半速十回合。

**主导风**改 春西/夏南/秋东/冬北；因为秋季改东风 + 气温变化，`galeAt` 26→31 重标定
（秋季峰 25%、夏 8%、春 ~1%、冬 0）。

**踩点**：`tune-climate` 原来一回合只走一步（实战是两步），量出来比实战冷；
而且整季取众数会把"升温过程"和"季节"混在一起。两处都修了，匹配率 36.7/48.3
（改前 31.7/40）。教训：**改气候参数前先确认调参脚本的步进节奏和实战一致**。
