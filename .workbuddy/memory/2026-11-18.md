## 阶段 2：三道门（完成）

**和计划不同的做法**：没做 dev 关卡，改成在 `probe:unit-ai` 第 5 段**手工搭小局面**
（12×12 全平地、B 方一个探针 boss、A 方贴脸民兵、无城），兵种用探针内注入
（`s.unitTypes['probe-boss']`），不进出厂表。理由：boss 内容没定，先做关卡等于把结构定死；
手工局面能把变量分开控制。

**三个答案**
1. `must` 不会被贴脸普攻抢走（1000 vs 普攻，8 个种子无一失手）。
2. **"被拒后重提"在结构上不可能**——候选在挑选前就被 `applyAction(view,…)` 筛掉，
   走不到的目的地根本不会变成动作。这条是好消息，值得钉住：谁把这个筛子优化掉，
   扩展写错坐标就会变成每回合空转。另补了一条 rejected 契约（已进 rejected 的动作不再提）。
3. 不会被 1.5% 带宽吃掉（1000 对带宽 15）；但**低分的 add 会被吃掉**。
   自主分确实在打折：同一个 add 200 分，autonomy 1 赢、autonomy 0.01（=2 分）输。

**顺手量出的基准**：24 攻打 100 血 2 甲，**贴脸普攻 ≈ 89 分**。原表"打一下 10~40"偏低
（评分里含"会不会打死"和"目标价值"）。已写回 DESIGN 第 5 节，并给了定分口诀：
想抢在普攻前 → 90 以上；想"有条不紊铺场" → 30~60。

**自己踩的坑**：二分找 89 分时用 `Math.round((lo+hi)/2)`，`lo=2/hi=3` 时 `mid=3`，
"赢了"分支 `hi=mid` 减不下去 → 死循环、进程被系统杀掉（exit 137）。改成 `Math.floor`。

## 阶段 3b：技能自带 AI 提示（`registerSkillAi`）

**口径**：曼哈顿菱形；分母只数地图内格子；**严格超过一半**才触发；视野/射程减半向上取整、
不低于 1；多个诡异不叠乘。

**三个决策**
1. **每回合末整份重铺**（`onTurnEnd`），不跟着诡异走——实时刷会撞热路径
   （`visionOf`/`effectiveRange` 每个兵每帧都在问）。当回合它走了黑雾留在原地，是故意的。
2. **存在局面里 `GameState.overlays.shadow`**（格号数组），不是实时算。这样规则/AI/界面
   读同一份，不会"显示能打、点下去说不行"；`playerView` 是 structuredClone，视图天然带着。
3. **界面用现成 `boardViews`**（色层），核心 `onlyVisibleCells` 自动按迷雾过滤，不泄露。

**必须记住的陷阱**：`modifyVision` 里不能调 `visionOf`/`playerView`——playerView 算迷雾时
正在调 visionOf，回头一查就是死循环。只能用 `base`。

**已知限制**：只在地球上算（多图会画错位置）；当回合不跟随移动。

**探针** `npm run probe:shadow`（8 段，已接进 npm test）：145 格 / 视野 9→5、射程 4→2 /

## 词条化 + 数值回调

**所有机制改成 AbilityDef 词条**（暗蚀/暗影侵蚀/化影/化血/侵染/汲取/增生），
挂在谁身上谁就有，不再按兵种 id 写死。`AbilityDef` 新增 `valueLabel(def) -> string|null`：
面板和规则书**同一个来源**，改一处两边一起变（之前血肉/血核的暗蚀只在面板上有，
规则书里查不到——因为能力压根没挂上，面板那行是假的）。

**坑1**：字段名不能叫 `valueOf`（`Object.prototype.valueOf` 冲突，TS 报 "Object 不能赋给 string"）。
**坑2**：能力 `onTurnStart` 跑在回合开始，`unit.acted` 已被重置 → "攻击过"改用 `onStrike` 写 `custom.hit`。
**坑3**：删旧钩子要删干净——旧的 `tickBlood` 和新词条叠在一起，增生一回合跳 2 格。
**坑4**：探针里"只有 B 方单位"的场，交棒即判胜；而且 `startTurnOf` 不能"已是它的回合就返回"，
必须从对面真交一次棒，否则能力不跑（表现为"化血一次都没长"）。

**数值回调**：化血 60→80、化影 5→4。**校准原则：AI 能打赢的局对玩家很简单，
以后只要 AI 输得不太难看就别削弱**（已写进设计文档）。

**血肉聚集 bug**：原来只按"离血核最远"选点，每团血肉都选同一个全局最优 → 全挤到一角。
改成 离核 + 1.2×离最近同伴。

## 骨系三兵 + 新核心钩子 onTurnEnd

**为什么加钩子**：能力原先只有 `onTurnStart`，而"本回合攻击过就腾空""回合末吞相邻血肉"
必须看清这一回合做过什么——`onTurnStart` 时 `acted` 已被重置。
新增 `AbilityHooks.onTurnEnd`，在 `doEndTurn` 里**切人之后、resetUnitsFor 之前**跑，
并按 `StagedKey` 登记。

**三兵**：骸骨（血70/攻20/射1/暗影1，找血肉）/ 尸骸（血150/攻32/射3/溅射1/暗影3，找暗影）/
不详（血140/攻38/射3/2段/溅射1/暗影5，朝仙帝但 4 格停，看不见就沉暗影最深处）。

**六词条**：寻躯（吞血肉变尸骸）/ 复苏（吞暗影变不详）/ 腾空（打过就升空，没打过降落，
落点被占就延后）/ 拼装（死后半血骸骨+2淤血）/ 点化（击杀→骸骨+淤血+暗影）/ 解离（死后2淤血+骸骨+暗影）。

**三个坑**：
1. 死亡钩子里"原地生成"必然失败（尸体还占格）→ 先试原地、不行落相邻。
2. **`flight: true` = 一直在空中层**，不是"会飞"。不详写了它 → 近战打不到（报"超出射程"）。
   它的飞要靠 `unit.layer='air'` 表达。
3. 探针用同方兵当凶手会被拒 → 表现成"死亡能力全没触发"。

探针 `npm run probe:bone`（30 条）。

## 三系平衡第一轮（作者实测后）

**结论：滚雪球其实不快**——格子占满就动不了、顶点倾向聚合、生成点位不多。

1. 血肉 160→130（太肉：又给影系铺暗影、又打不死）。
2. 骨系「寻躯」「复苏」加 1 回合间隔：吞下 → `custom.formTo` → 下个自己回合末才变形。
   **锁移动的办法**：能力 `onTurnStart` 把 `u.moved=true`；`canMove` 只看它，
   而 `grantTurnTo`（重置）跑在 `turnStartSkills` 之前，所以能撑满一回合。
   **变形血量按比例**（35/70 → 75/150），不再 `min(hp,newMax)`。
3. 影系补强：蚀影加「化影」、影主加「暗影侵蚀」、暗影半径各 +1（4/2/8）。
   连带影响：探针"只有暗影杀人才能生蚀影"不再成立，判据改成"有没有这条词条"。
4. 顶点不聚合：`kinCrowd()` 同类 2 格及格、1 格才扣分；影主×血核不扣；不详不加。
   去掉"已在最深处就 return"的早退（否则叠在一起的顶点永不散开）。

**探针坑**：`endTurnOf` 和 `beginTurnOf` 是两回事——结束 B 的回合只开启 A 的回合，
B 的 onTurnStart 要等 A 交棒。第一版混用，表现成"凝结期间没锁住移动"。
