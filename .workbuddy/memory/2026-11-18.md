### 这次做了什么

- `types.ts`：`UnitTypeDef` 加 `aiAutonomy?`（0~1，0 = 全听全局）、`aiProfile?`（行为表名字）。
- `expansions.ts`：新类型 `UnitAiCandidate` / `UnitAiCtx` / `UnitAiResult` / `UnitAiProfile`；
  `Expansion.unitAi?: UnitAiProfile[]`（和 abilities / marks 同构）。

  · `registerUnitAiProfile`（**重复 id 抛错**，不许后来者覆盖）
  · `unitAiOf(s, unit)`（autonomy≤0 时**连表都不查**，直接 null）
  · `unitAiActionProblem`（单兵动作白名单：禁 END_TURN/RECRUIT/UPGRADE/SET_*/DISBAND 等席位级动作，
    并要求 `action.unitId === 这个兵`）
  · `UNIT_AI_MUST_SCORE = 1000`、`unitAiWarn`（同一问题只警告一次）
- `ai.ts`：`unitAiCandidates()` 把 handler 的回答转成候选；per-unit 循环加一步；
  `Candidate.ignoreRisk` + 推演削分跳过它（`must` 恒为 true，所以剧本动作不会被
  "对面下一回合能打多疼"否决）。
- `scripts/probe-unit-ai.ts` 接入 `npm test`。

### 验的东西

- 零变化（硬指标）：自主分 0 → handler 0 次调用、序列一致；自主分 1 但返回空 →
  handler 被调用、序列仍一致（证明路是通的，不是死代码）；未注册 profile → 静默降级；
  提 END_TURN → 被丢弃并告警。
- 白名单四条、悬空 profile 检测一条。
- 全套回归：test:rules 956 / ai 53+7 / probe:level / boot / replay 9 / net 4 全过，tsc 干净。

### 两处设计微调（写进 PLAN 了）

1. `must` 除了固定 1000，还带 `ignoreRisk`——否则作者写的"第三回合变身"会被推演削没。
2. 自主分是在**进候选表时**才乘上去（`c.score * autonomy`），扩展给的是"这个 profile
   认为值多少"，同一个 profile 挂在 0.5 自主分的兵上自动打折。
