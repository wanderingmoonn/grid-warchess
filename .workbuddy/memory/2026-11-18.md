## 阶段 2：三道门（完成）

**和计划不同的做法**：没做 dev 关卡，改成在 `probe:unit-ai` 第 5 段**手工搭小局面**
（12×12 全平地、B 方一个探针 boss、A 方贴脸民兵、无城），兵种用探针内注入
（`s.unitTypes['probe-boss']`），不进出厂表。理由：boss 内容没定，先做关卡等于把结构定死；
手工局面能把变量分开控制。

**三个答案**
1. `must` 不会被贴脸普攻抢走（1000 vs 普攻，8 个种子无一失手）。
2. **"被拒后重提"在结构上不可能**——候选在挑选前就被 `applyAction(view,…)` 筛掉，
   走不到的目的地根本不会变成动作。这条是好消息，值得钉住：谁把这个筛子优化掉，
   扩展写错坐标就会变成每回合空转。另补了一条 rejected 契约（已进 rejected 的动作不再提）。
3. 不会被 1.5% 带宽吃掉（1000 对带宽 15）；但**低分的 add 会被吃掉**。
   自主分确实在打折：同一个 add 200 分，autonomy 1 赢、autonomy 0.01（=2 分）输。

**顺手量出的基准**：24 攻打 100 血 2 甲，**贴脸普攻 ≈ 89 分**。原表"打一下 10~40"偏低
（评分里含"会不会打死"和"目标价值"）。已写回 DESIGN 第 5 节，并给了定分口诀：
想抢在普攻前 → 90 以上；想"有条不紊铺场" → 30~60。

**自己踩的坑**：二分找 89 分时用 `Math.round((lo+hi)/2)`，`lo=2/hi=3` 时 `mid=3`，
"赢了"分支 `hi=mid` 减不下去 → 死循环、进程被系统杀掉（exit 137）。改成 `Math.floor`。

## 阶段 3：用邪龙王验真技能 + 核心污染清理第一批

### 邪龙王行为实验（`npm run probe:dragon-king`）

靶子：奇想包的邪龙王（真英雄/真技能陨卵/真产物链 卵→魔龙）。
场地：16×16 空地、两家各留一城（**不能清空城，否则第一帧判出局**）、
B 方一条王、A 方三个自造「木桩」（600 血 2 攻）——真兵会被一发陨卵打成灰，观察窗口没了。

挂的行为：王「射程外 7~9 格游弋 + 够 2 条魔龙才出击」，魔龙「离王超 3 格就回防、贴身时打威胁王的敌人」。

20 回合、单种子的结果：
- 离最近敌平均距离 8.2 → 9.6；余量 7.2 → 8.6
- 原样压到 3 格、第 16 回合开始普攻；挂行为全程 8~12 格、**一次都没打**
- 下蛋 4 次（两臂相同）、魔龙峰值 3（相同）
- 魔龙离王平均 5.3 → 4.2（护主生效）

**结论：这套机制能承载"剧本行为"**，游弋/等数量/护主三件都做到了。
诚实边界：一个种子、假对手、阈值 2 是拍的、"余量"是曼哈顿近似。

**踩的坑**：`s.cities = []` → 席位立刻出局（第二次踩）；
第一版用真对局两档逐字相同——不是机制没生效（日志里提案确实被采纳），
是规格写错："贴着射程外 1~2 格"和"推进"落在同一个位置。

## 阶段 3b：技能自带 AI 提示（`registerSkillAi`）

**问题**：`ai.ts` 的 `heroSkillCandidate` 是一串 `case '效果名'` —— 引擎认识具体内容。
每加一个技能要回核心改一处；扩展的技能（修真法术）AI 根本不认识。

**口子**（`skill-hooks.ts`）：`registerSkillAi(效果id, 提示函数)`，返回三选一：
`null` 不放 / 数字 值几分（落点交给规则层）/ `{score,x,y}` 值几分并指定落点。
ctx 给了 `state`(雾图) / `unit` / `def` / `skill` / `api` / `foes`(核心筛好的战斗敌人) /
`hpRatio` / `allies`。核心先查表、查不到再走旧 case（搬一个少一个）。

**和 unitAi 的分工**：unitAi = 一整个兵这一回合的剧本（要开自主分，能走位/提动作/必须做）；
技能提示 = 单个技能放不放的常识（所有会技能的兵都生效，只给分数）。写进注释了。

**第一步：只搬 `dragon-egg`**，分数照抄（30 / 射程内有人）。零变化证据：
`probe:dragon-king` 输出 diff 为空；两个种子的全 AI 动作指纹相同（1769d015/588、c048213/385）。

## 暗影领域（最小验证已通）

**口径**：曼哈顿菱形；分母只数地图内格子；**严格超过一半**才触发；视野/射程减半向上取整、
不低于 1；多个诡异不叠乘。

**三个决策**
1. **每回合末整份重铺**（`onTurnEnd`），不跟着诡异走——实时刷会撞热路径
   （`visionOf`/`effectiveRange` 每个兵每帧都在问）。当回合它走了黑雾留在原地，是故意的。
2. **存在局面里 `GameState.overlays.shadow`**（格号数组），不是实时算。这样规则/AI/界面
   读同一份，不会"显示能打、点下去说不行"；`playerView` 是 structuredClone，视图天然带着。
3. **界面用现成 `boardViews`**（色层），核心 `onlyVisibleCells` 自动按迷雾过滤，不泄露。

**必须记住的陷阱**：`modifyVision` 里不能调 `visionOf`/`playerView`——playerView 算迷雾时
正在调 visionOf，回头一查就是死循环。只能用 `base`。

**已知限制**：只在地球上算（多图会画错位置）；当回合不跟随移动。

**探针** `npm run probe:shadow`（8 段，已接进 npm test）：145 格 / 视野 9→5、射程 4→2 /

## 影系第二轮：目标偏好 + 影主藏身 + 跳跃改规则

**目标偏好**：蚀影扑**落单**（两格内没同伴，防围杀）；暗影**补刀**（血最少）；影主打**威胁最大**
（射程内 atk+magicAtk 最高）。顺序也是设计：蚀影"先扑落单→再守边界→最后走位"。
坑：近战射程 1 摆不出"落单 vs 有护卫"（贴脸的两个敌人彼此只差 2 格，按两格判据永远互为护卫），
探针里用一个**射程 2 的变体**测这条。

**影主没事往哪走：选「暗影最深处」（离边界最远那格），不选重心。**
理由：重心可能落在暗影**外**（环形/两块黑雾的重心在中间亮处），还会被细长影子拉偏；
"离边界最远"那格按定义就在暗影里。实现=多源 BFS，按 overlay 数组缓存。

**暗影跳跃改规则**：攻击后不能跳（`acted` 挡），走完能跳、跳完能走（**不再改 moved**），
冷却 1（+ skillTurn 兜一回合一次）。三个兵自己会用：
蚀影"够不着的落单目标旁有暗影就跳过去伏击(165)"、走不到边界时跳边界(130)；
影主"深处太远（>移动+2）就化进去(140)，近了才走"。
