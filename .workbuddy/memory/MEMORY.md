## 引擎事实（别再记错）

- **攻击会同时置 `moved`** → 同一回合不能"先打再走"；"先走再打"合法。
- `RECRUIT` 只拒：非我城 / 废墟 / 本回合刚打下 / 时代白名单 / 钱不够 / **产兵格占满**。
  "被围的城造不出兵"是假的（9.13 已清）。
- `cityRegenOf` 要求**城格里有自己人**才回血（3 / 每多 1 人 +1 / 上限 6），城外一圈有敌人就停；
  `siegeTargets` **不看城外守军** → 站城外挡不住攻城。所以出击 = 留人守城 + 其余野战。
- **产兵格 = 城格**（2×2 = 4 个）；造兵营能加，但只有 5 代的好用，人也造得少。
  → 钱多时**每格战力**才是瓶颈（不是每金）。
- 浅滩 `s` 对陆军可通行；`make-scene.ts` 的 `LEGEND` 已补 `s → shallow`。
- **桥有两种形态，别混**：`BUILD` 造出来的是**单位**（`category:'building'` + `bridges:true`），
  同时把脚下地形改成 `'bridge'`；手摆图里的桥**只有地形**（`P-4-01` 就是这样）。
- **桥不占位**：引擎 `blockedAnchor` 对桥返回 `false`（"桥是双向的，谁都能站"）。
  所以"这一格有没有人"必须用 `rules.occupantAt`，**不许直接数 `s.units`**——
  AI 自己造的桥会被自己当成一个人，队伍就永远走不上桥（`P-2-03` 踩过，40 手 14 人全在河西）。

## 已经定的口径（别重新发明）

- **链路分工**（2026-11-25 定）：**枚举属于服务层，选择属于决定层，价格与可行性属于计划层**；
  入口（`ai-v4.ts`）只剩"排序 + 派动作"，不许再出现资源判断（缓存键里的金币除外）。
  同一问题只准一处回答（守得住吗 / 钱够不够 / 造不造兵）。

- **每金 vs 每格**：钱是瓶颈 → 按每金（民兵 1.80 最优，越往上越低，步枪兵 0.45）；
  格子是瓶颈 → 按每格（民兵 45 → 戟兵 75 → 步枪兵 90）。
  **同一条规则两处用**：2c 守城、P3-B 升级。详见 `docs/DESIGN-UPGRADE-PER-CELL-2026-11-25.md`。
- **发展期 T** = `marchTurns(进攻编队 → 敌城)`，速度取**队里最慢的兵**；没有编队时按
  "双方非废墟城最小步数 ÷ 当代战斗兵移动力众数"。**它不是考试窗口**
  （用户原话："让 v4 理解他在考试吗？实战里没这个概念"）。
- **升级三个闸**：A 应急（城 ≤2 轮塌 → 升）、B 每格（`金 > 产能 × 剩余手数 × 当代最强兵价`
  → 选总战力最大的那一代）、C 发展（投影已跑通，**C3 还缺一道"做过会变绿"的题**）。
- **升级只在"还没有军队"（`myCombat.length === 0`）时规划**——否则升级费是沉没成本，
  每手重算会越升越高（E-2-03 上从 3 代漂到 5 代）。

## 方向（别走回头路）

- 不为 S 题调 AI；不写"永久收入比"（会让它永远造经济兵不出兵）；
  **不把投影摊成逐动作打分**（v3 的死法）。
- 出题：一格一主一换（奇数主 / 偶数换），隔离考点；**别出"发展→开战"那种接近实战的题**
  （红绿无法归因）。
- v4 的风险不在"打分"，在**求解器的输入造假**（v3 就是这么高估的）：经济兵要走路、
  地块产出从认领表来、产兵格有上限、模板兵种不能混水兵。
