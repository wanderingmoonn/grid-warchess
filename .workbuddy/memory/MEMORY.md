## 太空战争：战斗口径（2026-11-12 P2f）

- **材料研究室**改回普通 `modifyArmor`：它的加成本来是给**地球**部队的，
  站内被「恶劣外空环境」÷5 吃掉是对的。`postHazardArmor` 钩子已删，
  别再"为了不被除"把它挪到环境之后。
- **敌方空间站只公开外形**（甲板/破口），舱段靠 `hideUnit` 钩子整块不下发，
  只有核心舱例外。`fog.playerView` 里活单位、ghosts、`memory.known` 三处都要过。

  核心舱那一格连可点格都不给。

## 架构与坑

- **移动是瞬移结算**：`doMove` 直接改坐标，没有路径记录。要按"路过"判定必须
  给 `reachableTiles` 补父指针再回溯。目前相关规则（反应射击）一律按**落点**算。
- **`s.cities = []` 会让引擎把该席位判为出局**，`END_TURN` 转一圈回到同一个人，
  守方永远轮不到回合。做脚本对局时城市要留着，只把战场挪到无城横带。
- **`placeUnit` 是纯函数**：新单位在返回的 state 里，不改入参。
- **跑批**：单次 60 局会被系统杀；20 局一批、串行连跑多批稳定（约 7 分钟/批）。
  两个进程并发约 24s/局，四个并发反而拖到 2 分钟/局。
- **`node_modules` 是符号链接**，`.gitignore` 里必须写 `node_modules`（不能带斜杠，
  带斜杠只匹配目录，符号链接漏网，合并时会把它提交进库）。
- 仓库会自动 push：提交后 `origin/<branch>` 可能已经更新，不用手动推。
