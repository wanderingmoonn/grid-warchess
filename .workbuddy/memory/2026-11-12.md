## 太空战争：计划定稿 + P0 地基落地

### 四个已定决定（用户拍板）
1. **空间站 = 一张小棋盘**（`kind: 'station'`），站内驻军/建造/战斗复用现成规则。
2. **航道只计时，不能打**：在途单位不进战斗；反制仍在地面。
3. **胜利 = 月面基地累计采样**（满 N 赢）。挨打 → 那一回合不 +1（暂停）、进度保留；
   基地被拆才归零。**这反转了 11-11 的"挨打清零"**，已和用户确认。
4. **空间站来自"核心舱"**：发射井送不同的核心舱，型号决定初始化出的棋盘大小。

计划文档：`docs/PLAN-SPACE-WAR-2026-11-12.md`（P0 已完成，P1 星图 UI / P2 空间站 / P3 胜利条件）。

## P1.5 星图视图（已完成，未提交）

用户设计：星图做成"一张特殊的棋盘"，节点占格、连线是航线，点星球看信息（含停泊的空间站）、
点航线看航程与在途，还能直接切图。

### 关键决定：星图**不是** boards 里的图
塞进去会自指（boardIds 多一项、面板又列它）、被当战场扫（视野/AI/待命统计）、
boardStateOf 投影出空图。所以是 UI 层视图：借 CSS grid 与坐标，不借数据管线。

- `ui/star-layout.ts`：布局纯函数。地球居中、其余节点沿外圈均分；坐标**算出来不进存档**
  （否则加图会挪老局面）。5×5 外圈 16 格，不够换 7×7。
- `ui/star-map.ts`：覆盖层渲染（DOM 格子 + SVG 航线 + 角标）。
- `main.ts`：`starOpen` / `starSel`（纯界面状态）、`star-open/close/node/lane/go` 动作、
  `starPanelInfo()` 生成侧栏卡、Esc 先关星图（stopImmediatePropagation 挡住复盘那条）、
  切图时自动收起。
- `ui/panel.ts`：`StarPanelInfo { kind,title,lines,goto[] }`；goto 是列表——
  一个星球可能停好几座站，各有各的「前往」。
- 左上角面板菜单加入口；复盘里也放行（`star-*` 不改这一局）。

### 两个坑
- **细线点不中**：2px 的线没有命中面积，每条线配一根 `stroke-width: 0.34` 的透明线接点击。
- **`hidden` 会被 `.star-map{display:flex}` 压住**（类选择器 > UA 的 `[hidden]`），
  必须写 `.star-map:not([hidden]){display:flex}`。和左上角面板那次同一个教训：**藏东西要藏两遍**。

测试：ui 235（+1 星图布局：地球居中、月球在右、站挂节点、布局确定、单图返回 null）。
全量 839/235/11 全绿，build 通过。

### 修：点「查看星图」没反应
根因：`case 'star-*'` 被插进了 `handleReplayAction` 的 switch（我用 `s.replace("switch (act) {", …, 1)`
只替换了文件里**第一个** `switch (act) {`，那是复盘条那个），而那条路只在 `rp-` 前缀时才走。
修法不是挪回去，而是抽成 `handleStarAction`，在 `handleAction` 开头用 `act.startsWith('star-')` 前置分发
（和 `rp-` 同一个套路），以后再插也不会插错。顺带把 replay 白名单里的 `star-` 删掉（走不到那儿了）。

星图入口挪到菜单最上面（`${starBtn}${rows}`）。

### S2：航线点不到（已修）
根因：点击挂在 SVG `<line>` 上，靠 `.sm-lane-hit { pointer-events: stroke }` 覆盖父级
`.sm-lanes { pointer-events: none }`——这条继承/命中路径实机不生效。

修法：**不再依赖 SVG 命中**。SVG 只画视觉线（pointer-events:none），
每条航线另渲一根普通 DOM 按钮 `.sm-lane-tap`：left/top 是 a 格中心的百分比、
width 是两点距离占比、`transform: rotate(角度)`、`transform-origin: 0 50%`。
节点 z-index 3 压在命中条（2）之上。顺带有了 hover 与键盘焦点。

### 航程的前瞻（用户提出）
"航程不能简单用回合数，推进器越多飞越快" → 时间 = 距离 ÷ 速度。
现在 `StarLane.turns` 就等于距离（都是 1），**暂不拆字段**（等空间站做完）；
文案加了"以后装了推进器，同一段路会更快走完"。
将来改成 `distance` + 速度修正时，面板文案不用再动。

测试：ui 236（+1 星图渲染：航线有命中条、节点可点、签名不变不重建）。
全量 839/236/11 全绿，build 通过。

## P2 空间站：方案定了（未开工）

### 四个决定（用户拍板）
1. **站挂在星球轨道**（`starmap.stations[].at = 'earth'`），一个节点可停多座。
2. **扩建是选点，不是按环**：核心舱挂一门技能（`targeting:'point'` + `multiCast`），
   可点格 = "相邻于已有甲板/核心舱的 void"；一次一格，每格花钱（也算折扣）。
   用户原话："可以套用技能模板"。
3. **折扣：`rate(n) = 0.5 - 0.8^n`**（n = 井的等效数量）。
   0 井 −50%、1 井 −30%、2 井 −14%、3 井 −1.2%、4 井 +9%…
   **边际递减、不封顶、软上限 +50%**（渐近）。未来不同井型给不同权重，代入同一个 n。
4. **P2a 带一个"生产舱"**：站内建筑，每回合产一点资源，验证"在站上花资源造东西"。

### 关键技术点
- **必须先补地基**：`enterLane` 现在要求目的地有棋盘，核心舱要去"轨道"——
  要拆成 `surface` / `orbit` 两种目的地，orbit 到达时生成 station board。
- 两个新地形：`void`（不可通行/不可建造）、`deck`（甲板，1 步）。
  **不能复用 plain**：`buildOn:['plain']` 的建筑（发射井）会在站内被判定可盖。
- 核心舱发射**不加注**：发射井多一组 `silo:core-*` 按钮，直接扣资源 → enterLane(orbit)。
- 技能模板够用：`SkillDef` 没有固定 cost，花费在 effect 里自己扣 → 动态价格没问题。

### 数值草案（待调）
扩建 80 金/格（额定）、生产舱 320、核心舱 600/900/1400，尺寸 5×5 / 7×7 / 9×9。

## 三个"依然没修好"的真根因（第二遍）

上一轮判断错了（以为是 idx/boardOf 的事）。这次用探针把规则层排除掉：
`heroSkillsOf` ready=true、`SKILL_TARGET_CELLS['station-expand']` 返回 4 格、
`applyAction(HERO_SKILL)` 成功。所以问题 **100% 在界面层**。

### ① 技能点不中：上帝模式抢走了点击
`onBoardClick` 里 `pendingSkill` 那一段排在 `if (state.config.godMode)` **之后**。
一开沙盒，点技能按钮进了瞄准模式，再点棋盘却被 godMode 分支接走（落子/选中），
永远到不了选点逻辑。修法：把"技能选点 + 设备选点"整块**提到所有模式判断之前**——
"正在等一个落点"是全局状态，不该被任何模式抢走。
（另外 `skillTargetPicked` 对 point 型根本不看 aimTiles，所以第一次改的 `idx→idxOn`
其实没解决问题，只是把方向型修对了。）

### ② 上帝模式点空地：读地球格子 + 只弹 toast
`state.tiles[idx(state, x, y)]` → 改成 `tileOn(state, activeBoardId, x, y)`；
并且**同时设置 selectedTile + render**（以前只弹一句 toast，侧栏什么都不变，
玩家以为"点了没反应"）。

### ③ 空间站里有天气：格子钩子不知道是哪张图
`ExpansionHooks.getTilePanelHtml / getTilePanelLines` 加可选 `board?: BoardId`（缺省地球）。
`panel` 透传（selectedTile 用 activeBoard，selectedUnit 用 boardIdOf）。
季节包只在地球算天气——气候是按"地形+海陆+纬度"推的，那套只对地球成立。

教训：**界面层的"按格"逻辑有两个开关要同时看——在哪张图、在哪个模式**。
两次都栽在"函数用对了、上下文没传对"。

### 真根因（第三轮才找到，用户没开上帝模式）
`onBoardClick` **函数体第一行**就是 `if (activeBoardId !== EARTH) { ... return; }`——
非地球图的点击全在这里被处理（建造选址 → 走子 → 选中），**skill 选点排在它后面**，
所以空间站/月球上的技能永远点不到落点。前两轮我只看了函数中段，漏了开头。

同时这个分支里：
- `selectedTile = null`（写死），点空地只弹 toast → 侧栏永远不更新 → "虚空看不到地形"
- 修成 `selectedTile = pick || selectedId ? null : at`

另外 `refreshSelection` 的 `if (activeBoardId !== EARTH)` 也提前 return，
导致站内 `aimTiles` 永远是空的（没有高亮）。条件加 `&& !pendingSkill`。

**教训**：改"点击/选中"这类函数，必须从函数第一行读到分支结束。
`grep` 到目标片段就动手，会漏掉更早的 return。上一轮改的 godMode 分支是**真 bug**
（只是用户没开），但不是他报的那个。
