# 2026-11-12

## 太空战争：计划定稿 + P0 地基落地

### 四个已定决定（用户拍板）
1. **空间站 = 一张小棋盘**（`kind: 'station'`），站内驻军/建造/战斗复用现成规则。
2. **航道只计时，不能打**：在途单位不进战斗；反制仍在地面。
3. **胜利 = 月面基地累计采样**（满 N 赢）。挨打 → 那一回合不 +1（暂停）、进度保留；
   基地被拆才归零。**这反转了 11-11 的"挨打清零"**，已和用户确认。
4. **空间站来自"核心舱"**：发射井送不同的核心舱，型号决定初始化出的棋盘大小。

计划文档：`docs/PLAN-SPACE-WAR-2026-11-12.md`（P0 已完成，P1 星图 UI / P2 空间站 / P3 胜利条件）。

### P0 做了什么（已提交）
- `types.ts`：`Starmap`（nodes/lanes/stations/seq）与 `Transit`（owner/lane/from/to/left/cargo）
  作为 `GameState` 的可选字段，存档回放联机天然带上。
- `space/starmap.ts`：`createStarmap` / `starmapOf`（老存档自补）/ `lanesFrom` / `nodeOf` / `nodeById`。
- `space/transit.ts`：`enterLane` / `tickTransit` / `arrive` / `landingSpotOn` / `transitLines`。
  **在途单位移出 `s.units`**（否则会被回合重置、迷雾裁、战斗误伤）。
- 发射井：`launchToMoon` → `launchIntoLane`，代码里不再有 `MOON_BOARD`；
  目的地 = "我在哪个节点 + 这儿有哪些航道"。
- `board.ts::tileOn`：按图取格，**放这里是避开循环依赖**（transit 不能 import rules）。
- 修两个地球假设：`boardViews` 染色（`c.y * state.w` → 当前图宽 + 该图可见集）、
  `LOAD/UNLOAD`（删 offWorld，落点/占地/地形按船所在图）。
- 顶栏加 `<方> 火箭 <n>`（公开），和"登月 n"并列。

### 行为变化（唯一一处）
发射到落地从 3 回合变 4 回合：加注 3 + **航道 1**（`MOON_LANE_TURNS`）。
那一回合就是"能被看见、能被等"的那段路，是多航道/拦截的地基。

### 坑
- **`nodeById`（节点 id）vs `nodeOfBoard`（棋盘 id）**：两个名字太像，发射时传错会得到
  "航道那一头还没有能落脚的地方"。
- `transit.ts` 一开始 import `rules.ts` 的 `tileAtOn` → 循环依赖
  （rules → mark-registry → expansions → space-age → silo → transit），
  `EXPANSIONS` 未初始化直接崩。按图取格要用 `board.ts::tileOn`。
- 护栏 `/\.tiles\b/` 连 `b.tiles` 这种正确写法也算，块注释里的 `s.tiles` 也会命中（只剥 `//`）。
  正确写法用 `tileOn`；注释里别写字面量。
