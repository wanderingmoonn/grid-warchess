# 2026-11-15

## 关卡编辑器：差距评估 + 计划文档

- 新增 `docs/PLAN-LEVEL-EDITOR-2026-11-15.md`：六批（E0 注册表 / E1 校验收口+导入导出 /
  E2 画布 / E3 摆兵 / E4 事件编辑 / E5 试玩+AI自打 / E6 管理+分享），五个里程碑。
- `STATUS-LEVEL-MODE-2026-11-15.md` 的"关卡编辑器没有"一条补了指向计划的指针。

**评估结论（有用的判断）**：编辑器不需要改引擎。`validateLevel(raw)` 本来就是
"收一份来路不明的数据 → 校验 → 拿去开局"，`createMatch` 早就在这么干。缺的是三样：
界面、本机存储（照 `customUnits.ts` / `registerUserMaps` 抄）、试玩闭环。

**识别出的新坑（写进计划 E1/E2）**：
- 地图 `rows` 用 `TERRAIN_CHARS`（含 `=` `#` `_` `%`），事件 `terrain` 只能改成
  `LEVEL_TERRAINS`（不含 city/void/bridge）——编辑器和事件表单要用**两个不同的地形下拉**。
- 兵种在不在本局、spawn 落点能不能站，`validateLevel` 查不了（要等建局拿兵种表），
  必须另写一层 `level-lint`，否则作者写错时代兵种会被静默跳过。
- 城位分散在 `map.citiesA/B` 和 `seats.cities.C/D` 两处，编辑器要合成一个"摆城"操作。
- `validateLevel` 静默忽略未知字段 → 编辑器草稿状态不许写进关卡对象。
- 用户关卡不能进 `LEVELS`（探针 26 段直接读它，会被玩家数据污染）。
