### 3. 战报卡（0.3.47，commit f86ed78）
一局打完出一张 720×560 的卡：破城回合 / MVP 兵种 / 关键三步，出口是
存图片（本地生成）、系统分享（有 `navigator.share` 才出现）、复制文字。

实现口径（下次改这块要守住）：
- **数据全从 `GameState` 算，不依赖录制器**——关掉"详细记录"的局也要能出卡。
- 破城回合读 `city.capturedTurn` 并按 **`owner === 赢家`** 找。
  第一版从"owner !== 我"找，破城那一刻城已归我 → 永远 null。
- 敌方席位必须走 `seatsOf(s)`。`state.players` **恒有 A/B/C/D 四个键**，

- 入口条件**不复用结算卡**：结算卡在上帝模式里是不给的（沙盒），
  而那正是自家玩得最多的地方。战报卡只排"复盘"一种情况。
- 终局一次性提示放在 `render()` 里（`settledNotified`）：分出胜负有八条路
  （攻城/认输/城被打光/联机提交/AI 走完/指挥官收尾…），各处各写一句一定漏。

`msedge --headless=new --screenshot=... file:///...` 能出图，前提是
1) 脚本必须**内联**进 HTML（file:// 外部脚本报 "Script error." 拿不到真消息）；

## 修真扩展：阵法第三期——守御阵（仅转移伤害 + 被动吸守阵修士）

用户拍板：只转伤害不转状态、保留反击、做成被动能力（不做主动技能）；
三个数按设计先上线，强度等实机再调；AI 看不见这个机制先放放。

**三个数**：每回合吸血额度 = 守阵修士境界；阵 80 血 / 6 护甲（4 代、
110 金 + 14 灵石、buildCost 18、大阵师/天阵师可建）；友军建筑受击也转。
兑换 1 点修士血 → 境界 × 1 点阵血；修士至少留 1 血，0 级无额度。
转移半径 2，多阵取最近（同距按 id），一次伤害只问一次。

**核心改动（通用能力，不是给守御阵特制的）**：
- `rules.ts` 新增 `hurtUnit(s,target,amount,opts)` 作为**全引擎唯一扣血出口**：
  问 `ExpansionHooks.redirectDamage` → 扣血 → 跑 `AbilityHooks.onDamaged` → 判死。
  顺序不能换：被打成 −5 但吸回 9 点能活，−100 则照样死。
- 收口的直伤：普攻 / 溅射 / 反击 / 塔自动开火 / 塔溅射 / 地雷 / 陨卵 /
  自爆 / 剑气纵横。**不收口**：中毒灼烧 tick、单位自身损耗、onTurnEnd 的 hurt、
  攻城（City 不是 Unit）——这些都不该被转。
- `AbilityApi` 加 `hurt()` 与 `maxHpOf()`；`ExpansionHooks.redirectDamage`、
  `AbilityHooks.onDamaged` / `DamagedCtx`。
- 转移致死由 hurtUnit 自己 killUnit（调用方只判原目标，会漏掉接替者）。

**两个坑**：
- 能力文件绝不能 `import rules.ts`（rules → 扩展 → rules 成环）；生命上限、
  战报都走注入的 `c.api`。上次中断前的草稿在这里写错了，已纠正。
- `bestAdjacentCultivator` 补了 `u.owner === self.owner`：原来敌方修士路过
  也会算"守阵"，守御阵会去抽敌人的血。三座阵共用这一条判据。
  同境界取血量多、再按 id，保证联机确定性。

验证：test:rules 607、test:cultivation 50（新增 9 条守御阵用例）、
test:ai-optimization 通过、manual 兵种 253 / 能力 81、tsc 仅剩既有 6 条
（@types/node、cloud-sdk 缺声明）。

## 传送阵「挪移」只能点相邻格：UI 按 targeting 分流

实机发现只能往身边挪。根因不在技能，而在 `main.ts` 的 `refreshSelection`：
`pendingSkill` 分支**无条件**把 `aimTiles` 设成施法者四邻（那是给方向型技能
写的"选方向"），点击处理又只认 `aimTiles`。传送阵是第一个真正用
`targeting: 'point'` 的技能，所以被这段卡死；核心 `doHeroSkill` 与
`teleport-swap` 本身对落点没有任何距离限制。

- `pendingSkill` 记下 `targeting`；`refreshSelection` 按 point / direction 分流。
  point **不逐格高亮**：`.tile.aim` 是大红斜纹，全图点亮会盖住战场。
- 全图选点时棋盘加 `.aim-point`（十字光标）；落点范围靠鼠标悬停现算，
  换格才重算（`skillAimKey` 去重），离开棋盘才清空。
- 点自己脚下 = 取消：技能会把"落点=自己"判过载**并照扣灵石**，不能让误点白亏。
- 判定抽到 `src/ui/skill-aim.ts` 的 `skillTargetPicked()`，两种规则各有测试钉住，
  防止以后又被改回"只认四邻"。
- `teleport-swap` 注册 `registerSkillPreview`：返回**单位的目的格**而不是两片
  作用范围——传送阵波及的是人不是地，染两片圆盘反而看不出谁会被挤掉。

验证：test:cultivation 51（+落点预览）、test:rules 612、test:ui 185

## 灵石显示成 spirit-stone：资源名字不该绑死在 createMatch

实机发现 UI 多处显示英文 id。根因：`RESOURCES`（本局流通表）只在
`setup.ts:createMatch` 里按本局启用的扩展 `registerResource`。任何不走开局的
路径——规则书生成脚本、开局设置、兵种编辑器，以及**联机加入 / 读档**（只恢复
state）——都查不到定义，`resourceShort/Name` 只能退回 id。修真册里实测有 2 处
「产出 +1 spirit-stone」。

**修法（没有把扩展资源塞进 `RESOURCES`）**：
- `resources.ts` 新增 `RESOURCE_NAME_FALLBACK` + `registerResourceName()`，
  `resourceById` 查不到时兜底。
- `expansions.ts` 模块加载时把所有 `EXPANSIONS[].resources` 登记进兜底表。
  名字是数据、跟着扩展声明走，不该由"有没有开局"决定。
- 刻意不动 `RESOURCES` 的长度和顺序：RL 特征向量按它开槽（`RESOURCE_SLOTS`），
  全局注册会把没启用的资源算进去，破坏 frozen parity。
- `setup.ts` 的按局注册保留（幂等），注释改成"本局流通表仍由开局决定"。
- `build-manual.ts` 加自检：任一册出现扩展资源 id 就让 `npm run manual` 报错。

验证：修真册改成「产出 +6 金 +1 灵」、全册无残留；test:rules 613（+兜底测试）、
cultivation 51、ui 185、ai parity 通过、tsc 无新增错误。

## 出手闪烁：战况烈度的一次性版本

用户要"我方开火也能看见打了哪"，定的是最轻的方案——不常驻、不加颜色，
复用 `.fx-heat` 那套红块闪一下（0.7s）就散。

**不加记账**：`core/heat.ts` 新增 `newHeatCells(before, after)`，把两份状态的
记账摊平成「格 → 次数」再取差。谁记了账谁浮出来——普攻/溅射/反击/攻城/技能
直伤全都自动覆盖，不用按动作类型特判；移动、建造、招募差值为空自然不闪。

**接入点**：`dispatch` 与 `runAiTurn` 各一处；联机在 `pollRoom` 装快照时补一次
（没有本地动作可挂钩）。`dropHeatFlash()` 在换局/进房/退房/撤回时清掉，
否则上一张棋盘的红块会落到新局上。

**渲染**：board 新增独立 `.heat-flash` 层（排在 `.heat` 之后，压在棋子上）。
没复用 `.heat` 是因为两层更新节奏相反：常驻层多数帧不变、靠 diff 省重写；
闪烁层每次动作都要重播动画。`flashSeq` 写进节点 `data-flash`，同内容不同批次
也会重建节点，动画才会从头播。雾外不画，复盘不闪。

CSS：`.fx-heat.flash` 一次性 keyframes（亮→暗→亮→淡出），
`prefers-reduced-motion` 下降级成单次淡出（常驻层那份刻意不关，这层是新加
的脉冲效果，没必要冒光敏感的险）。规则书第 12 节补一条说明。

验证：test:rules 613（+对账：炮兵溅射 5 格、开火格不闪、结束回合不闪）、
test:ui 186（+闪烁层的档位/批次号/雾外/清空）、cultivation 51、
manual 9 册、ai parity 通过、tsc 无新增错误。

## 攻城溅射：红格与伤害统一到一份格表

用户报：带溅射的单位攻城，城外明明在半径内的敌兵不掉血（红格却亮了）。
根因是 `doSiege` 只扣城耐久、根本没调溅射——溅射只活在 `doAttack`，而
`splashVictims` 要求爆心是个 `Unit`，城市是 `City` 进不去。

**修法不是"攻城单独写一段"**，而是先把几何收成一份：新增
`strikeCellsOf(s, attacker, rect, hit)`（爆心 = `pickHitCell`，半径 = `splashRadiusOf`，
直线 = `splashLine`），烈度、出手闪烁、溅射全读它。
`splashVictims` 改成收「矩形 + excludeIds」，命中判据从"矩形到矩形距离"
换成"身体占到被覆盖的任意一格"——玩家看见红格盖住谁，谁就掉血。

`doSiege` 接上后：城外圈内、以及**城里站着的守军**（距离 0）一起吃；
公式与野战同款（`computeDamage × splashRatioOf`），走 `hurtUnit`（守御阵能接），
死亡走完整善后（删人+战报+沉船+击杀钩子）。战报补「溅射 X、Y」，
被波及方各收一条私有战报（隐匿的袭击者不具名）。

顺带：塔自动开火的烈度改用同一个 `noteStrikeHeat`（多一个记账口子），
`splashTilesOf` 也改成 `strikeCellsOf`，`onStrikeLine` 删除。
规则书溅射词条原写"不分敌我"是错的（代码只打敌人），改成"只打敌人"。

按用户要求：**不写**"带溅射会波及城外"那句（视觉统一后不必解释），AI 先不动。

验证：test:rules 617（+4：红格-掉血逐个对账、点哪炸哪、无溅射回归、波及致死）、
cultivation 51、ui 186、manual 9 册、ai parity 通过、tsc 无新增错误。

## 修真批 2 · 体修（第一个纯数据流派 + 一个新减伤时点）

用户定的设计：时代 2、30 血、特色「金刚不坏」30%→50%（最后 1/4 血满档），
境界加成偏科：攻 ×1.1，真元/移动/射程 ×0.5。做成"站立型近战"。

**引擎新增一个具名伤害时点** `DAMAGE_STAGE.damageTakenMul = 800`
（护甲/魔抗/属性之后、真伤之前）。减伤必须放这里而不是扩展现有的
`modifyDamage`（那个在扣护甲之前，50% 打在高甲单位身上只剩几个点）。
顺带语义成立：真元排在 1000，天然不吃减免；中毒/灼烧不走公式也不吃。

**能力** `abilities/body-ward.ts`：纯函数 `bodyWardPct(hp, maxHp)`，
读 `c.api.maxHpOf`，不写 state（computeDamage 会被 AI 反复调用）。
护甲挡到 0 的那一下直接 return，别把 0 抬成 1。

**流派系数** 全在 `stats.ts`（`BODY_ATK_MUL` 等），`identity.ts` 只加 id 与
`isBodyCultivatorType`（progression 不能 import stats，会成环）。
新增 `realmAtkFor(u)` 给面板用：面板那行「境界加成」有条既有测试钉着
"印纯境界值、不乘系数"，所以体修另起一行写"折算后实际 +N"，
否则玩家会看到"射程 +1"而实际 +0。

刻意**没做**：生命成长系数。要动 `maxHpDeltaBetween`/`totalHpBonusForRank`，
而 `spirit-rebirth` 重算血量也走它（体修可能死了化灵再重生），漏改就是
"重生后血量少一截"。先用 30 基础血表达"更耐打"。

实测（挨同境界炼气士）：rank1 4.2 下 vs 1.9；rank3 4.3 vs 2.6；rank5 9.3 vs 7.4。
到 rank5 只剩 1.26 倍——因为炼气士 18 点真元占了单次伤害的六成，
而体修真元只有一半且减免不作用真伤。"硬抗刀枪、怕真元"这条链是自洽的。

验证：cultivation 56（+5）、test:rules 622、ui 186、manual 9 册

## 修真批 2 · 魔修（血祭：绕过击杀上限的成长路）

## 零散修复：「多动」下线 + multiCast:false 的按钮不回弹

**「多动」是历史遗留的第二套说法**，和「攻击次数」指同一件事（`burst` 字段）。
用户要求全部删掉、统一看攻击次数。改动：
- `traitsOf` 不再挂「多动 N 次」那一格（攻击列已经写成 `20×3`，特性列重复）；
- 规则书小节「溅射与多动」改名「溅射与攻击次数」，正文全部改用新词，
  词条 `burst` 的 name 也从「多动」改成「攻击次数」（键不变，ref 照旧）；
- `info.ts` 的兵种说明「多动：一回合能攻击 N 次」→「攻击次数：…」。
- 现在 public/*.html 里「多动」出现次数为 0（有一次性核对脚本的思路：
  grep 所有册子，改完应为 0）。

**`multiCast: false` 与不写应当等价，但按钮不回弹**：`heroSkillsOf` 只算了
冷却/充能/扩展就绪检查，漏了 `doHeroSkill` 里那句
`!skill.multiCast && u.skillTurn === s.turn`。于是不能连发的技能放过一次后
仍然显示「就绪」，点下去才报「这一回合已经放过技能」。
修法：在 `heroSkillsOf` 里补同一条判据（`ready=false`，原因写「这一回合已经
放过技能」）。`!k.multiCast` 对 false 和 undefined 一视同仁，两者从此等价。
配套加了 test-rules 用例（false / 不写 / true 三种写法各断言一次）。

验证：test:rules 630、cultivation 63、ui 186、manual 9 册、ai parity 通过、
tsc 无新增错误。

## 传送阵：不可撤回 + 「撼动了时空结构」

事实：撤回是**整步快照回滚**（`dispatch` 把施放前的 state 推进栈），所以失败
传送扣的 10 灵石和这一回合的施放机会，撤一下就全回来了——"失败也照扣"实际上
只在玩家不撤的时候算数。

用户定的方案（比之前的甲/乙/丙更干净）：
- `SkillDef.irreversible?: boolean`，传送阵置 true；`doHeroSkill` 真的放出去
  （灵石不足那种拒绝不在此列）时把标记透传进 `ActionResult`，`dispatch` 见到
  就 `undoStack = []`。**不是只封这一步**——撤回栈里存的是每步之前的整份状态，
  想"跳过这一步、保留更早几步"做不到（更早快照里灵石还在）。清空后本回合
  继续走子照旧可撤，只是撤不回传送之前。
- 战报在扣灵石那一刻就留一句「传送阵撼动了时空结构」（`TELEPORT_RIFT_LOG`），
  成败都有；日志按时间倒序显示，所以它落在"过载/挪移"那行下面。
- 文案三处：技能按钮小字（summary 追加"而且撤不回来"）、进入瞄准的 toast、
  规则书阵法一节（`build-manual` 引用常量，不手抄）。

验证：cultivation 64（+灵石不足不封撤回、成功/失败都要 irreversible + 战报）、
rules 631、ui 186、manual 9 册、ai parity 通过、tsc 无新增错误。
