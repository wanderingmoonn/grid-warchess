## 产品线：新手教程收尾 → 上帝模式 UI 瘦身 → 战报卡

用户已放弃继续修 AI（"我不修 AI 了"），转做产品。今天三件事，全部已上线。

### 1. 教程扩到十步（0.3.46，commit 9eff5f3）
`goal → select → move → terrain → attack → endturn → upgrade → recruit → siege → done`。
每步用**状态谓词**（`done?: (c: Ctx, s: Snap) => boolean`）判定"真的做到了"，不是"点了下一步"。
踩过的坑：
- 红框必须在 `renderBoard` 的渲染参数里给（`tutorialTiles / tutorialCityId`），
  不能渲染完再往 DOM 上贴 class——棋盘每帧重建，首帧在 rAF，贴上去就没了。
- 逐格 outline 会在交界处出现细线/中央十字 → 改成整块 `.city-block` 上框。
- 第三步要限位：`allowedDestinations()` 只放行"走完贴脸"的落点 +
  `dispatch` 首部 `tutorialBlocking()` 拦掉讲解页的一切改局动作。

### 2. 上帝模式工具栏瘦身（0.3.46，commit 51b54ef）
删掉「操控」整组、`GodUi.selected`、两段自解释文案、多余的棋子状态；
轮次行合成一行；结束回合按钮统一成同行样式（偏高是 `.chip` 的 line-height 造成的）。

### 3. 战报卡（0.3.47，commit f86ed78）
一局打完出一张 720×560 的卡：破城回合 / MVP 兵种 / 关键三步，出口是
存图片（本地生成）、系统分享（有 `navigator.share` 才出现）、复制文字。

实现口径（下次改这块要守住）：
- **数据全从 `GameState` 算，不依赖录制器**——关掉"详细记录"的局也要能出卡。
- 破城回合读 `city.capturedTurn` 并按 **`owner === 赢家`** 找。
  第一版从"owner !== 我"找，破城那一刻城已归我 → 永远 null。
- 敌方席位必须走 `seatsOf(s)`。`state.players` **恒有 A/B/C/D 四个键**，
  直接 `Object.keys` 会在两人局多出两个 0 兵 0 城的幽灵席位（`4 !== 2` 就是这么来的）。
- 入口条件**不复用结算卡**：结算卡在上帝模式里是不给的（沙盒），
  而那正是自家玩得最多的地方。战报卡只排"复盘"一种情况。
- 终局一次性提示放在 `render()` 里（`settledNotified`）：分出胜负有八条路
  （攻城/认输/城被打光/联机提交/AI 走完/指挥官收尾…），各处各写一句一定漏。

排版验证的办法（**这个可以复用**）：本机没有 puppeteer/playwright，但有 Edge。
`msedge --headless=new --screenshot=... file:///...` 能出图，前提是
1) 脚本必须**内联**进 HTML（file:// 外部脚本报 "Script error." 拿不到真消息）；
2) esbuild 打 CSS 会产出独立 `.css`，得手动内联进 `<style>`，否则整页没样式。
另外加了一条用例：假 ctx（CJK 1em / 半角 0.55em）记录每一笔的边界，
断言没有字块画到卡外——排版错误变成红灯，比肉眼看一遍稳。

## 修真扩展：阵法第三期——守御阵（仅转移伤害 + 被动吸守阵修士）

用户拍板：只转伤害不转状态、保留反击、做成被动能力（不做主动技能）；
三个数按设计先上线，强度等实机再调；AI 看不见这个机制先放放。

**三个数**：每回合吸血额度 = 守阵修士境界；阵 80 血 / 6 护甲（4 代、
110 金 + 14 灵石、buildCost 18、大阵师/天阵师可建）；友军建筑受击也转。
兑换 1 点修士血 → 境界 × 1 点阵血；修士至少留 1 血，0 级无额度。
转移半径 2，多阵取最近（同距按 id），一次伤害只问一次。

**核心改动（通用能力，不是给守御阵特制的）**：
- `rules.ts` 新增 `hurtUnit(s,target,amount,opts)` 作为**全引擎唯一扣血出口**：
  问 `ExpansionHooks.redirectDamage` → 扣血 → 跑 `AbilityHooks.onDamaged` → 判死。
  顺序不能换：被打成 −5 但吸回 9 点能活，−100 则照样死。
- 收口的直伤：普攻 / 溅射 / 反击 / 塔自动开火 / 塔溅射 / 地雷 / 陨卵 /
  自爆 / 剑气纵横。**不收口**：中毒灼烧 tick、单位自身损耗、onTurnEnd 的 hurt、
  攻城（City 不是 Unit）——这些都不该被转。
- `AbilityApi` 加 `hurt()` 与 `maxHpOf()`；`ExpansionHooks.redirectDamage`、
  `AbilityHooks.onDamaged` / `DamagedCtx`。
- 转移致死由 hurtUnit 自己 killUnit（调用方只判原目标，会漏掉接替者）。

**两个坑**：
- 能力文件绝不能 `import rules.ts`（rules → 扩展 → rules 成环）；生命上限、
  战报都走注入的 `c.api`。上次中断前的草稿在这里写错了，已纠正。
- `bestAdjacentCultivator` 补了 `u.owner === self.owner`：原来敌方修士路过
  也会算"守阵"，守御阵会去抽敌人的血。三座阵共用这一条判据。
  同境界取血量多、再按 id，保证联机确定性。

验证：test:rules 607、test:cultivation 50（新增 9 条守御阵用例）、
test:ai-optimization 通过、manual 兵种 253 / 能力 81、tsc 仅剩既有 6 条
（@types/node、cloud-sdk 缺声明）。

## 建造名单：从"可建 N 种"改成悬停就能看到名单

用户否决了"新增建造对照表"（来回翻页负担），要两处 hover：
规则书词条悬浮窗、游戏内造兵之前的提示。方案敲定：乙档（复用选卡浮层风格）、
规则书列全名单。

**规则书**：浮层是按 `a.ref` 的 href 去词条表取文字，不是每颗链接自带文案。
所以不用改浮层 JS/CSS——`traitsOf()` 里给每个工兵用 `dynamicTerm()` 登记
`builds-<兵种id>` 专属词条，brief 写全名单即可。奇想包技能词条就是这个模式。
核心册 5 / 时代册 7 / 修真册 5 / 奇幻册 1 = 18 个。第 10 节保留一个
`ref('builds')`，否则通用「建造」词条（沿桥递两节那条）会从词条表消失。

**游戏内**：把选卡专用的 `#draft-tip` 泛化成 `#hover-tip` +
`[data-hover-tip]` 宿主 + `.hover-tip` 数据节点，产兵按钮和选卡卡片共用。
产兵按钮外面套 `.recruit-wrap` 当宿主，是因为 **disabled 按钮在部分浏览器
不派发鼠标事件**——钱不够时恰恰最需要看名单。开局设置 / 上帝模式的 chip
保持原生 `title` 风格，只补名单，没有硬换浮层。

**口径收口**：新增 `src/core/build-list.ts` 的 `buildListOf(def, {nameOf, exists})`，
规则书 / 属性卡 / 产兵按钮 / 选卡 / 两处 chip 都读它。修掉两个老问题：
`info.ts:345` 只查本局表会漏英文 id；`panel.ts` 静默丢掉本局没有的建筑，
导致"可建 10 种"配 8 个按钮。

**一个刻意的不一致**：规则书用静态全量表（最多 10 项），游戏内用
`s.unitTypes`（含开局补丁，实测全扩展下建筑队能到 18 项）。规则书词条里
注明"以游戏内产兵提示为准"，不用全扩展快照去印一长串船坞。

验证：manual 9 册、test:rules 610、test:cultivation 50、test:ui 183、
test:ai-optimization 通过、tsc 无新增错误。
环境备注：工作区原本没有 node_modules，为跑 test:ui 用
`npm install --no-save esbuild jsdom` 临时装了依赖，没动 package.json / lock。
