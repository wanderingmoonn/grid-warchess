**结论**

1. 用户观察成立：`recruitCandidate` 的 score **没有任何一项**依赖产兵点位置

   用户看到的"跋涉"可能是"站在错的格子上"。

   账上钱在 121~540 之间来回震，**一次都没攒到**（`savingAllowance` 每回合仍放行
   `inc/产兵点数` 的额度；`reach(cost,6)` 不问"6 回合后城还在不在"）。
4. **已证伪的修法**：按兵力比关闸（造价 ×1.2 / 血量加权 ×1.25，含"复活"路径）
   → Q1/Q2 10-2-0 → 9-3-0 → 8-4-0，两局胜变负；**三局负回合数逐局一字不差**
   （闸在病灶上零触发：AI 自己不认为落后）。已回退，登记进 BACKLOG 第六节。
   → 下一步只能改"攒钱目标的评分"（存活折现），不能靠关闸。

**工具坑**：`s.aiIntent` 是旧字段，`focusOf` 只在没有 `aiFocus` 时才读它；
探针要读 `s.aiFocus[me].save`（`setFocus` 已经把 aiIntent 清掉）。

## 桥的更正 + 编制注释清理 + 废墟安全闸（aiRuinSafe）

**更正**：桥是 `category:'building'`、`move:0` 的**建筑**（木 45 / 石 85 / 钢 140 金），
占一格水面、改地形；**被拆掉时**才还原，它不会自己走开。"人一走桥就塌"是我说错了。
5 格河 = 5 座桥建筑（+ 工人动作），不是吃 5 个兵。19 座桥 ≈ 1600 金建材。

**编制注释**：v3 已无编制上限，`ai-v3.ts` 里所有"编制上限 / 帽子 / 编制快满"的说法删掉；
"编制"在这个文件里现在只指**阵容档位**（tank/melee/ranged/siege）。

**废墟安全闸（`aiRuinSafe`，默认关）**：
- 三处都要求"抢下来守得住"，判据 `enemyThreatAt(废墟格).n === 0`
  （敌人移动力+射程，和"城下有人"同一把尺子，不新拍数字）；
- 接管分和坡度乘 `1/(1+接管次数)`；次数用 **`capturedTurn`** 数——
  不能用归属：废墟被打空不改归属，同一方能反复接管自己那座城（22 次里大多数是这种）。

**实测**：Q4|32|A 22 次 / 5924 金 → **4 次 / 1096 金**，261 平 → 87 胜（=基线）。
四组：基线 10-2-0/11-1-0；只开废墟闸 **0↑0↓（对基线 no-op）**；
三件套 11-1-0/4-3-5；三件套+废墟闸 11-1-0/**4-1-7**（叠在三件套上 **2↑0↓**，两局负→平）。

**教训**："修了一个 bug"要分清是"所有局受益"还是"给某个开关配套"——
废墟闸对基线逐局不变，只是等三件套把兵推到城下才显形。别拿它解释基线胜率。

## P1 前置查清：判决只有一条，"行军回合"自己在跳（未改代码）

**结论**：`aiCalls` 里同回合的两条不是两条判决在打架，而是**同一条判决每动作重算一次**
（`aiNextActionCoreInner` 每动作跑一遍 `decisiveOf` + `decideCallOf`），`call` 翻了就记一条。
插桩实测 T35：同一兵同一城，成本 **157 → 12 → 156**，桥单位 **6 → 7 → 6**——
**桥出现/被拆**就是那两次跳变；`marchTurns` 40 ↔ 3，`call` 跟着 develop ↔ attack，最后算的赢。

**三个观测同一个根**（`canReachEnemyByLand`：等步数 BFS + `min(w,h)` 上限）：
1. **宽浅流会被当渡口**：浅流 `passable` 算陆地，但按"1 格 1 步"记，20 格宽就超 24 → 判不通 → 修桥；
2. **池塘造船**：`seaDemandNow` 里 `!canReach → 1`（全额海军），且**从不检查这片水通向哪**；
   即使 seaDemand=0，水军总惩罚也只有 -18；
3. **"平局"里有一部分是 v1 不会收废墟**：`src/core/ai.ts` 全文没有 reclaim，
   对面拿不到最后一座废墟 → 拖到回合上限判平。**看平局要先确认还剩没剩废墟**。

**方案**：P0 把 `canReach` 改成按代价判（用 advance 场）+ 相对绕路上限（≤ 直线×k）；
P2 海军加"死水"洪泛；P1 判决等 P0 之后再评估；P4 报表标注"是否还剩废墟"。
详见 `docs/ANALYSIS-CANREACH-2026-11-23.md`。
