**结论**

1. 用户观察成立：`recruitCandidate` 的 score **没有任何一项**依赖产兵点位置
   （唯一例外是 `royalComboBonus` 的"国王 4 格内"；camp 有 +6，城市没有）。
   同兵种在各城分数逐位相同 → 落进 tied 区间按 `aiNoise` 抽 = 在城之间均匀随机。
   实测 Q3|31|A：45% 战斗采购落在比最靠前城远 ≥2 格的城，平均多跑 1.93 格；
   敌人贴近 5 格内的回合里，只有 55% 的兵出在被威胁城。
2. 经济侧同病：`maxIncome(d)` 用兵种自己的最好地形（牧民 8 / 农民 7）而不是城周边 →
   平原城也造牧民；60% 经济单位-回合站在"别的兵种更值"的格子上，平均少产 6.35 金/回合。
   注意：**它其实不太走**（"开始产出"平均 0.6 格、走 ≥4 格只有 1/11），
   用户看到的"跋涉"可能是"站在错的格子上"。
3. 三局负的真形状：`savingFor='era'`（360~540 金）从 T20~24 挂到输，
   账上钱在 121~540 之间来回震，**一次都没攒到**（`savingAllowance` 每回合仍放行
   `inc/产兵点数` 的额度；`reach(cost,6)` 不问"6 回合后城还在不在"）。
4. **已证伪的修法**：按兵力比关闸（造价 ×1.2 / 血量加权 ×1.25，含"复活"路径）
   → Q1/Q2 10-2-0 → 9-3-0 → 8-4-0，两局胜变负；**三局负回合数逐局一字不差**
   （闸在病灶上零触发：AI 自己不认为落后）。已回退，登记进 BACKLOG 第六节。
   → 下一步只能改"攒钱目标的评分"（存活折现），不能靠关闸。
