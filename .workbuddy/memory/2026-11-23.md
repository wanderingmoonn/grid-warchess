## 城市盲区 + 三局负的真因（分析，未改行为）

**产出**：`docs/ANALYSIS-CITY-PROFILE-2026-11-23.md`；
新探针 `npm run probe:city-role` / `npm run probe:collapse`（已进 package.json）。

**结论**

1. 用户观察成立：`recruitCandidate` 的 score **没有任何一项**依赖产兵点位置
   （唯一例外是 `royalComboBonus` 的"国王 4 格内"；camp 有 +6，城市没有）。
   同兵种在各城分数逐位相同 → 落进 tied 区间按 `aiNoise` 抽 = 在城之间均匀随机。
   实测 Q3|31|A：45% 战斗采购落在比最靠前城远 ≥2 格的城，平均多跑 1.93 格；
   敌人贴近 5 格内的回合里，只有 55% 的兵出在被威胁城。
2. 经济侧同病：`maxIncome(d)` 用兵种自己的最好地形（牧民 8 / 农民 7）而不是城周边 →
   平原城也造牧民；60% 经济单位-回合站在"别的兵种更值"的格子上，平均少产 6.35 金/回合。
   注意：**它其实不太走**（"开始产出"平均 0.6 格、走 ≥4 格只有 1/11），
   用户看到的"跋涉"可能是"站在错的格子上"。
3. 三局负的真形状：`savingFor='era'`（360~540 金）从 T20~24 挂到输，
   账上钱在 121~540 之间来回震，**一次都没攒到**（`savingAllowance` 每回合仍放行
   `inc/产兵点数` 的额度；`reach(cost,6)` 不问"6 回合后城还在不在"）。
4. **已证伪的修法**：按兵力比关闸（造价 ×1.2 / 血量加权 ×1.25，含"复活"路径）
   → Q1/Q2 10-2-0 → 9-3-0 → 8-4-0，两局胜变负；**三局负回合数逐局一字不差**
   （闸在病灶上零触发：AI 自己不认为落后）。已回退，登记进 BACKLOG 第六节。
   → 下一步只能改"攒钱目标的评分"（存活折现），不能靠关闸。

**工具坑**：`s.aiIntent` 是旧字段，`focusOf` 只在没有 `aiFocus` 时才读它；
探针要读 `s.aiFocus[me].save`（`setFocus` 已经把 aiIntent 清掉）。

**没做**：没验真人回放里的"牧民长途跋涉"；没量三局负里 AI 自己的 `myVal`（下一步进探针）。

## P0-4 城画像落地（默认关）+ 攒钱冻结考古

**落地**：`CityPlan` + `buildCityPlans()`（ai-v3）、`Fields.cityPlans/needCityId`、
`recruitCandidate(..., siteBoost)`、开关 `aiCitySite`（types.ts + setup.ts 白名单 +
`bench:ai --city-site`）。默认关，关着时逐局与基线完全一致（Q1|30|A 负78、Q3|31|A 负84 复现）。

**实测**：小图 1↑1↓（Q1|30|A 负78 → 胜51，8 局胜局提前 4~14 回合），
**大图 0↑3↓**（两局胜变 261 回合平）→ 净负，默认关。
升级选城加 slots/heat 的那一版更差（Q3/Q4 0↑5↓），已单独回退。

**量出来的真病根**：前线城常常是 e2、后方 e3 → `eraWindowOk` 让前线城造不出当代兵，
"兵从后方来"其实是时代问题（P1-3），不是选址。选址只把多跑从 1.93 → 1.24 格。

**坑（第二次踩）**：`setup.ts` 的 config 是**逐项白名单抄**的，新开关不加进白名单
= 开了跟没开一样（跑批逐局与基线相同就是这个原因）。

**攒钱考古**（`docs/ANALYSIS-SAVE-FREEZE-2026-11-23.md`）：机制是 v1 的，v3 一行核心没改
（ai.ts 4746/4818/4870/4934/5154/5192/5427 与 ai-v3 逐行对应）。v3 只改两处：
① `quality` 的第三项 `army>=maxUnits-6` → `boom>0.5`（语义从"富了买贵的"翻成"弱了攒"）；
② `stance='turtle'` 搬进 `DEFEND_PLAN`（判据相同，不碰 savingFor）。
三个缺口：刹车只认"贴脸"（且是作者故意摘掉"落后→防守"）、`reach()` 用立目标时的收入外推
不重算、目标抖动把 `since` 清零使 `INTENT_TURNS` 的过期永不生效。
