## 10:05 修订：八级阶梯作废 → **四轨 × 三档**（用户指出"按复杂度排没按内容排"）

用户质疑两件事：① 阶梯只按复杂度排，人类的打仗能力是多方面的（经济/升代/侦查/编成/时机/关口/兵种），

**核心发现一：三项能力在 v4 里没有主人**（逐个 grep 过，记进 V4-CODE-MAP 9.10）
- **升级时代**：`src/core/v4/` 里没有"升级"这个词，三层都不决定升。

→ 结论："升级时代放第几层"没有答案，因为它哪一层都不在。这类进"架构欠账"，不进题库。

**核心发现二：题面"一个兵走到指定格"和架构对不上**
决定层只输出四个意图（发展/打/接管/守），没有"把某单位挪到某格"。走动是意图分解后的执行细节。

① 用第 1 手（没有上次决定）② 守要"对面身价 > 我 0.9 倍"→ 让我强或对面 0 兵

陷阱：**对手必须有城**（否则判出局），所以"无敌人"= 空城；空城 + 我有战斗兵 = 必打。
→ **纯发展局面必须一个战斗单位都没有**（S-015 正是"我 0 兵"）。
→ 另一条：**经济岗与意图无关**（约束层无条件算），所以发展轨的题测不到决定层。

而是**换兵种+数值**：弩兵（19 攻，`previewAttack` 一发 **16**）→ 弓手（11 攻，一发 **6**），
敌人血量 20/30 → **10/12**。能合打收掉的从"30 血"变成"12 血"（6+6=12）。

**实测**：空壳红（第 1 手剩 3 个）/ v1 v3 v4 绿（2 个）；**修前 v4 也是红（3 个）**，四颗种子一致。
→ 两道一起才说明机制认的是"这一手能不能收掉"，不是"哪个数字小"。

**记下的三个伤害数**（省以后再量）：弩兵→长枪 **16**、弓手→长枪 **6**、弓手→民兵 9。

**教训**：拿旧代码做对照不能靠 `git stash`（src 已提交时 stash 是空的，会静默用新代码跑，
得出"改前也是绿"的假结论）。正确做法：`git checkout <旧提交> -- src/core/v4` 再 `git checkout HEAD -- src/core/v4`。
