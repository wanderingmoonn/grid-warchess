## 侧栏过长：钉底 + 长列表收纳（2026-11-20）

**实测的病根**（`createMatch` + 全 28 包）：城市时代 1 有 23 种可造、时代 3 有 111、
时代 5 有 191、**时代 8 有 240**，而时代 8 只新增 5 种——产兵列表**只增不减**。
侧栏 `#side` 是独立滚动区，而 `.side-footer`（结束行动）只在 ≤920px 才 fixed，
桌面上它排在最后 → 每回合要滚十几屏才能交棒。

**做了两件，都不走"少列一些"那条路**（项目老规矩：藏起来＝玩家以为没了）：
1. `@media (min-width:921px) .side-footer { position: sticky; bottom:0 }` + 背景。
   用 sticky 不用 fixed：仍在文档流里，滚到底就在原位，不盖最后一张卡；
   内容短时靠原有 `margin-top:auto` 自然沉底。手机保持原 fixed 方案（单列布局下
   `#side` 不是滚动容器，sticky 没有可吸附对象）。
2. `src/ui/list-fold.ts`（新）：`FOLD_TOTAL=30` 整个列表超过才启动，
   `FOLD_KEEP=12` 每组留 12 行，其余进 `<details class="list-fold">`，
   标题写「还有 N 种」。**用 `shown.length`（筛完的条数）判门槛**，
   搜完只剩三行就不再折。城/营/「还造不出来」各算各的门槛。
   展开状态记在 `main.ts` 的 `openFolds: Set<string>`，键是
   `recruit:<城/营 id>:<组>`——面板每帧整块重建，open 不记外面就丢。

**探针** `npm run probe:fold`（8 条，已进 `npm test`）：验「标题数字＝真正藏起来的
按钮数」（防 slice 与计数对不上）、露出 ≤12、搜索变短不折、早期局不折、
展开跨重绘保持、键跟着城走。

**没做**：技能块按兵分组、产兵"常用置顶"（用户明确说钉底之后不需要了）、
研究法术的选择面板。这三条仍在讨论，别顺手改。

**注意**：`npm test` 里 `test:serve` 在本机 sandbox 会卡住（要 build + 起服务），
其余 15 步都正常。跑全量时要知道最后那步会挂这么久不是新引入的。

## 「待放技能」= SkillDef.mustCast（2026-11-20）

**问题**：没选中单位那一页原来把**所有兵的所有技能**铺出来。修真包上来之后
十个修士×四门法术＝四十行，真正要紧的那条淹掉了。

**做法**：`SkillDef.mustCast?: boolean`（纯界面开关，规则不读）。默认页只列
`mustCast && ready` 的，其余"选中那个兵再看"——一条没少，只是不占待办页。
标题从「技能」改成「待放 · 漏了就补不回来」；超过 5 条走 `foldRows`
（`MUST_CAST_KEEP=5`，比产兵的 12 小，因为"该做什么"过五个就挑不过来）。
开合键 `skill:must-cast`，同样记在 `openFolds`。

**标记口径只有一条：漏掉一回合，代价是不是永久的。**
标了 4 个：招魂（只认本轮遗体）、圣旗（两回合一次的团队光环）、
圣剑觉醒（永久叠加）、陨卵（卵要两回合孵）。
**没标**投斧/再生/降临/隐匿/裂殖/转属性/烈焰俯冲/聚合——它们是"什么时候用"的
战术选择，提醒反而逼人每回合点一遍。裂殖尤其不能提醒：它会毁掉自己。

**修真包没标**（用户说以后再说）——所以现在默认页对修士是空的，这是预期的。

**改了旧用例**：`smoke-dom.ts` 里"默认页也要列出英雄技能"整段重写成新口径
（没标的不出现 / 圣旗出现 / 标题写「待放」）。`probe:fold` 加 5 条到 13 条。

**环境坑（更正）**：`npm test` 挂住的是 **test:boot**，不是 test:serve——
`smoke-boot.ts` 跑完不 `process.exit`，jsdom 里的定时器让进程不退，
`run-tests.ts` 就永远等它 close。断言全绿、只是不退出。单跑时直接看输出即可。

## 法术按钮的两个排版毛病（2026-11-20 傍晚）

**现象**（用户截图）：宗门大殿里"研发「掌心雷」"的描述被压成五行竖排，
右边那格写着"没有藏经阁：一门法术都研发不了（先盖一座贴着宗门的藏经阁）"。

**根因两层**：
1. `.recruit-btn .price` 是 `flex:0 0 auto` + `nowrap`，**没有上限**——
   以前只有产兵的短价签，从没长过。法术的"不能研发的理由"一长就把
   `.meta` 挤没了。`.skill-btn .price` 早就有 8em 上限，`.recruit-btn` 没有。
2. 理由文案本身是一整句话。

**改法**：
- `.recruit-btn .price` 加 `max-width: 9em` + ellipsis + 右对齐；
  `.recruit-btn .meta` 补 `min-width: 0`（flex 项默认 min-width:auto，
  不补的话长内容不缩）。
- 新增 `.action-btn`（`align-items: flex-start`）：说明两行时价格不该居中漂着。
- 按钮加 `title`（label｜detail｜note 全文）——理由被截断后还能看全文。
- 理由压短（`spells.ts`）：缺少藏经阁 / 额度已满 3/6 / 灵石不足 12/60 /
  法术位已满 1/2 / 境界不足（要 5 期）。**"怎么办"不再写进理由**，
  面板本来就有"本方研发 0/0（藏经阁 0 × 2）"。
- 探针加一条：理由 ≤ 12 字，防止以后再写长。

用户澄清：**远端是他手动推的**，不是自动推送。
