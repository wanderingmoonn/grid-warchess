## 灵气视图（提交 b30df8c）

用户要：顶栏季节旁边一个「灵气」chip，悬停看全图浓度（深浅绿格），点一下钉住、再点取消。

**核心开洞（通用，不认灵气）**：
- `ExpansionHooks.boardViews?: (c) => BoardView[]`；
  `BoardView = { id, label, hint, cells?({state,viewer}) => [{x,y,color}] }`。
  核心只拿"格子和 CSS 颜色"，**不知道绿色代表什么**。
- 棋盘加一层 `.board-view`：`tiles → board-view → marks → units → cities → heat → heat-flash`。
  铺在地面之上、棋子之下；`pointer-events:none` 是硬要求。
- 顶栏 `topbarShell()` 在 `weather-chip` 后加 `<div class="topbar-ext" data-ref="board-views">`，
  空时靠 `.topbar-ext:empty { display:none }` 不占位。

**main.ts 的胶水**（这是最容易踩的地方）：
- `boardViewHover` / `boardViewPinned` 两个模块变量，**绝不进 GameState**
  （否则跟存档/回放/联机快照走）。`activeBoardViewId() = hover ?? pinned`。
- chip **只在数量变化时重建**：每帧重建会让 mousedown/mouseup 落在不同节点上，click 直接丢
  （顶栏骨架那条老注释就是这个坑）。
- hover 用**委托**（`mouseover`/`mouseout` 挂在 topbarEl），因为 chip 会随换局重建。
- 点击时顺手清 `hover`：鼠标还停在 chip 上，不清的话"取消"会立刻被 hover 重新点亮。

**修真包**：`qiOverlayCells(s)` 返回全图每格 + 5 档绿（`QI_VIEW_COLORS`，第 0 档也给极淡底色，
否则"稀"和"没数据"看起来一样）。**全图不按视野裁**——灵气是天地之气，
和 `redactUnit` 藏丹药是两回事（这条写进了注释和规则书）。

验证：cultivation 132（+2）、ui 206（+2）、rules 701、ai 7+51、replay 9、net 4、rl 24、
tsc 无错、`npm run build` 通过、manual 9 册。

## 任务 A：温湿度场替代 120 格天气表（提交 331edbc）

**用户要求**：用温度场 + 湿度场模拟天气，正弦波给四季定基准、地形吸放热不同（相位延迟）、
欧拉方程扩散湿度、饱和判据决定降水，再映射回原来的 14 个标签。

**结构（新文件 `src/core/seasons/field.ts`）**：
- `temp`（整数 0.1°C）：`target = 年均 + (季节基准 − 年均) × 海陆振幅 + 地形海拔`，
  每步 `temp += (target − temp) × heat`。**这一个式子就同时给出相位延迟和振幅衰减**——
  水的 heat 只有 40~100‰，夏至时海还是凉的。
- `wet`（0~100）：每步 蒸发 → 扩散（凸组合写法，任意 D 稳定）→ 过饱和凝结 → 截断。
- 判类 `classifyClimate(temp, wet, precip, water, terrain)` 仍输出**原来那 14 个标签**，
  所以 `ClimateEffect`、五条规则钩子、天气视图、`weatherBlock` 全都不用动。
- 存 `tile.custom.temp` / `tile.custom.wet`，缺省现算（老存档零迁移）。
- **全程无 sin/exp/pow**：超越函数跨引擎有 ULP 差异，回放会算出不同天气。

**依赖方向**：`climate.ts`（类型/季节/海陆/效果表）← `field.ts`（场 + climateAt）。
`climateAt` 从 climate.ts **移到** field.ts，否则两个文件互相 import 会成环。
4 个 import 点要跟着改：index.ts / view.ts / scripts/test-rules.ts。

**坑（都实测踩过）**：
1. **湿度损耗忘了接进演化** → 只涨不降，跑一年全图饱和，处处是雾。
2. **固定扣量的降水做不出暴雨**：要么永远差一点到不了大雨，要么一次倒空连旱十回合。
   改成**按过饱和比例凝结**（`over × rainDrain`），过饱和量稳定在 `蒸发/rainDrain`，
   水面能冲到十几点、平地只有几点——大雨自然只落在大片水上。
3. **季节湿度偏移不能作用于水**：水比热大，不会"秋高气爽、冬天干冷"。
4. **水面风暴要温度闸**：2°C 的外海下大雨只是阴天，不是台风。少这道闸冬天整片海在刮风暴。
5. **dampWet 太低（0.75）→ 冬天全图湿冷**（那是产出翻倍的气候），经济会崩。
   提到 0.86 后冬天恢复成"寒冷"。
6. **测试采样不能用"季中那一回合"**：天气会变，拿骰子一次结果当期望值会让测试随参数抖。
   改成统计整季的**众数**。

**参数全部集中在 `TUNING`**，`npm run tune:climate` 跑对照，`--search` 坐标下降扫参。
原 120 格表搬进 `scripts/tune-climate.ts` 当期望值（运行时已删除）。
**当前匹配 26/60 = 43.3%**，且有意不再往上顶——剩余差异是结构性的：
- 「阴雨」在原表里是"这个季节的典型天气"，在连续场模型里是"偶尔下一下"，
  所以 9 个期望 overcast/downpour 的格子跑成了 mild
- 山地夏天只有 15°C，打不了雷（原表写的是 thunder）
- 水面比热大，冬天不封冻（原表 shore 冬 = frozen）

**核心测试改了 3 条**（都在 `scripts/test-rules.ts`）：
- 「气候效果」和「天气伤害」两条改成**手工摆温湿度**：它们验的是效果链，不是模型能不能下雨。
- 「气候矩阵照表走」改名「温度场随季节与海陆走」，断言只留温度能决定的那几条。

## 温度七档 + 砍掉日常减速（提交 03ccb7e）

**用户两点**：① 24°C 报"炎热"、6°C 报"温和"，体感差太多；② 玩家反馈"到处在减移动力，
战斗节奏太折磨"，让温和两侧各加一档（温暖 / 凉爽）并给增益。

**分档**（0.1°C，`TUNING` 里的六个阈值）：
```
严冬 < −100 < 寒冷 < 50 < 凉爽 < 130 < 温和 < 200 < 温暖 < 270 < 炎热 < 320 < 酷暑
```
新增 `cool`（凉爽，5~13°C，移动 **+1**）与 `warm`（温暖，20~27°C，产出 ×1.25）。
`Climate` / `CLIMATE_NAME` / `EFFECTS` / `CLIMATE_ICON` / `CLIMATE_TINT` / `.w-cool` `.w-warm` 六处都要补。

**关键洞察：整数移动力让乘法修正比标称狠一倍。**
`2 × 0.75 = 1.5` → floor 1，**标着 −25% 实际 −50%**，越慢的兵越惨。
所以新增 `ClimateEffect.moveAdd`（加法），`modifyMove` 里**乘完再加**、最后 `Math.max(0, floor)`。
「凉爽」用 `moveAdd: 1` 而不是 `moveMul: 1.25`（后者对 move 2 完全无效）。

**减速只留三种**：严冬 ×0.5、酷暑 ×0.5、暴雨 moveCostAdd 1。
寒冷改成纯经济（incomeMul 0.7，去掉 moveMul 0.75）；炎热改 `incomeMul 1.25 + armorPenalty 1`；
阴雨去掉 moveMul（留 rangeAdd −1 + incomeMul 1.25）；暴雨 moveCostAdd 2 → 1。

**实测 16×16 跑 80 回合**：减速格子 春/夏/秋 **0%**、冬 5%（山地严冬）；加速格子秋 24~29%、春 18~30%。

**连带**：
- `mountain coastal/近岸 冬` 从 cold 变成 hardWinter（hardWinterAt −130 → −100），
  测试期望跟着改并注明"这格是有意偏离原表的"。
- 雷暴测试的 temp 260 → 280（26°C 现在是温暖档，不该打雷）。
- `tune-climate` 加 `NEAR` 映射：mild ↔ cool/warm 算"邻近"，报告分精确/邻近/不符。
  精确 31.7% + 邻近 5 格 = 40%。
- 三条新回归测试：分档体感（24/6/15/30°C）、**减速天气 ≤ 3 种**、凉爽 +1 对慢兵生效。
- **手册不能用 `**`**（不走 markdown），summary 里改用 `<b>`——这个坑踩过第二次了。
