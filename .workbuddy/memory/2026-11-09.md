## 任务 A：温湿度场替代 120 格天气表（提交 331edbc）

**用户要求**：用温度场 + 湿度场模拟天气，正弦波给四季定基准、地形吸放热不同（相位延迟）、
欧拉方程扩散湿度、饱和判据决定降水，再映射回原来的 14 个标签。

**结构（新文件 `src/core/seasons/field.ts`）**：
- `temp`（整数 0.1°C）：`target = 年均 + (季节基准 − 年均) × 海陆振幅 + 地形海拔`，
  每步 `temp += (target − temp) × heat`。**这一个式子就同时给出相位延迟和振幅衰减**——
  水的 heat 只有 40~100‰，夏至时海还是凉的。
- `wet`（0~100）：每步 蒸发 → 扩散（凸组合写法，任意 D 稳定）→ 过饱和凝结 → 截断。
- 判类 `classifyClimate(temp, wet, precip, water, terrain)` 仍输出**原来那 14 个标签**，
  所以 `ClimateEffect`、五条规则钩子、天气视图、`weatherBlock` 全都不用动。
- 存 `tile.custom.temp` / `tile.custom.wet`，缺省现算（老存档零迁移）。
- **全程无 sin/exp/pow**：超越函数跨引擎有 ULP 差异，回放会算出不同天气。

**依赖方向**：`climate.ts`（类型/季节/海陆/效果表）← `field.ts`（场 + climateAt）。
`climateAt` 从 climate.ts **移到** field.ts，否则两个文件互相 import 会成环。
4 个 import 点要跟着改：index.ts / view.ts / scripts/test-rules.ts。

**坑（都实测踩过）**：
1. **湿度损耗忘了接进演化** → 只涨不降，跑一年全图饱和，处处是雾。
2. **固定扣量的降水做不出暴雨**：要么永远差一点到不了大雨，要么一次倒空连旱十回合。
   改成**按过饱和比例凝结**（`over × rainDrain`），过饱和量稳定在 `蒸发/rainDrain`，
   水面能冲到十几点、平地只有几点——大雨自然只落在大片水上。
3. **季节湿度偏移不能作用于水**：水比热大，不会"秋高气爽、冬天干冷"。
4. **水面风暴要温度闸**：2°C 的外海下大雨只是阴天，不是台风。少这道闸冬天整片海在刮风暴。
5. **dampWet 太低（0.75）→ 冬天全图湿冷**（那是产出翻倍的气候），经济会崩。
   提到 0.86 后冬天恢复成"寒冷"。
6. **测试采样不能用"季中那一回合"**：天气会变，拿骰子一次结果当期望值会让测试随参数抖。
   改成统计整季的**众数**。

**参数全部集中在 `TUNING`**，`npm run tune:climate` 跑对照，`--search` 坐标下降扫参。
原 120 格表搬进 `scripts/tune-climate.ts` 当期望值（运行时已删除）。
**当前匹配 26/60 = 43.3%**，且有意不再往上顶——剩余差异是结构性的：
- 「阴雨」在原表里是"这个季节的典型天气"，在连续场模型里是"偶尔下一下"，
  所以 9 个期望 overcast/downpour 的格子跑成了 mild
- 山地夏天只有 15°C，打不了雷（原表写的是 thunder）
- 水面比热大，冬天不封冻（原表 shore 冬 = frozen）

**核心测试改了 3 条**（都在 `scripts/test-rules.ts`）：
- 「气候效果」和「天气伤害」两条改成**手工摆温湿度**：它们验的是效果链，不是模型能不能下雨。
- 「气候矩阵照表走」改名「温度场随季节与海陆走」，断言只留温度能决定的那几条。

## 温度七档 + 砍掉日常减速（提交 03ccb7e）

**分档**（0.1°C，`TUNING` 里的六个阈值）：
```
严冬 < −100 < 寒冷 < 50 < 凉爽 < 130 < 温和 < 200 < 温暖 < 270 < 炎热 < 320 < 酷暑
```

**关键洞察：整数移动力让乘法修正比标称狠一倍。**

**减速只留三种**：严冬 ×0.5、酷暑 ×0.5、暴雨 moveCostAdd 1。

阴雨去掉 moveMul（留 rangeAdd −1 + incomeMul 1.25）；暴雨 moveCostAdd 2 → 1。

## 严冬产出 / 风暴 10×5 / 风暴收到外海（提交 3ba0deb）

**三个实机反馈**：
1. 严冬不减产出、寒冷减产出 → 更冷的天气反而更养人。补 `hardWinter.incomeMul: 0.5`
   （cold 是 0.7）。
2. 风暴分布太广、开局到处都是 → 影响前期发展。
3. 风暴伤害改 10 次 × 5 点。

**风暴分级的关键发现**：**不能用 `coastClassOf` 的 deep 档**。
它要求"方圆 7 格内没有陆地"，而 16~32 格的小地图上**一格都满足不了**
（32×32 图上 202 个水格全是 shore）——分级形同虚设，等于"永远不起风暴"。
改用新写的 `distToLandOf(s,x,y)`（切比雪夫距离，只扫边圈，最多 7 格）。

`TUNING.stormTemp` 按离岸距离分三档（0.1°C）：
- `coast`（贴岸 1 格）= 265 → 夏天 25.4°C 到不了，**贴岸零风暴**
- `near`（2~3 格）= 195 → 夏天刮
- `open`（4 格以上）= 120 → 暖一点就刮

`classifyClimate` 的参数从 `coast?: Coast` 换成 `distToLand?: number`（水格才传）。

**10×5 的副作用**：每次只有 5 点，`max(0, 5 - 护甲)` 让护甲 5 以上**完全免疫**。
在 `onTurnEnd` 里改成 `Math.max(1, ...)` 保底——风刮不动铁罐头不是设计意图。
雷暴（50 点真伤）不受影响（`ed.amount >= 50` 走另一条路）。

**实测 32×32（水格 202，贴岸 172）**：开局 0 风暴、春 0、冬 0、
夏 30 个且全在离岸 2 格以上。

## 风暴保底撤销 / 修士起步加成（提交 44d4e57 + 4c3ce48）

**一、风暴保底撤销**（用户明确）：10×5 的意图就是"5 甲以下重伤、5 甲以上免伤"，
护甲是**硬门槛**不是可磨穿的减伤。`Math.max(1, ...)` 改回 `Math.max(0, ...)`。
护甲 0 → 50 点、护甲 3 → 20 点、护甲 5+ → 0。

**二、修真节奏诊断**（用户："修士赶不上同时代的科技，亏模"）

数据（纯打坐，40 回合 = 一年）：

| 境界 | atk×次数 / 甲 / 血 | 回合 | 对照 |
|---|---|---|---|
| 0 期 | 11×1 / 0 / 20 | 1 | 比 25 金民兵（13/2/28）还差，造价 150 |
| 2 期 | 21×1 / 6 / 38 | 15 | ≈ 3 代戟兵（100 金） |
| 3 期 | 26×2 / 12 / 55 | 34 | > 3 代骠骑兵（150 金） |
| 5 期 | 44×3 / 32 / 222 | 69 | 碾压 5 代坦克（400 金） |

**结论：3 期之后超模，问题全在起步**——0→3 期要 34 回合，本体早换两代了。

**改法**：`LOW_RANK_GROWTH = [5, 4, 2]`（下标 = 境界），只给 0~2 期打坐加成。
`getExpGrowth` 变成 `rank + EXP_GROWTH_FLAT + (LOW_RANK_GROWTH[rank] ?? 0)`。
0→3 期 34→23（-32%），0→2 期 15→10。3 期之后完全不变。

**踩的坑**：一开始直接把 `EXP_GROWTH_FLAT` 2→4，结果
`cultivation.test.ts` 的「纯挂机曲线」立刻变红——纯挂机从 5 级封顶冲到 6 级。
那两条测试（「纯挂机曲线」「设计预算：剑修能摸到 7 级、炼气士不能」）
是**故意钉住设计地基的**：挂机 5 级封顶、再往上必须靠打仗。
所以加成必须做成"只给低境界"，不能动全局常量。

剑修打坐仍减半（靠实战），魔修仍固定 1 点，都不受影响。规则书同步。

验证：rules 788、cultivation 132、ui 219、ai 7+51、replay 9、net 4、rl 24、
tsc 无错、build 通过、manual 11 册。

**留给用户拍板的**：炼气士 150 金 vs 民兵 25 金，0 期战力还低于民兵。
现在靠"10 回合到 2 期"缓解，但如果实机仍觉得起步亏，下一步是**降造价**
（150→110 一档），而不是继续加快成长——成长再快就会碰到 5 级封顶那条线。

## 修士造价改成「升到下一时代花费的一半」

上一轮留的"降造价"落地。口径：`cultivatorCost(era) = nextUpgradeCost(era) / 2`
（`nextUpgradeCost(n)` 取的是 `ERAS[n].upgradeCost`，即 n→n+1 那笔）。

| 修士 | 时代 | 旧 | 新 |
|---|---|---|---|
| 炼气士 | 1 | 150 | 110 |
| 剑修 / 体修 | 2 | 270 / 240 | 180 |
| 魔修 / 魂修 | 3 | 300 | 270 |

1 代不能直接取 `ERAS[0].upgradeCost`（0，会白送），所以借"升到 2 代"那一笔。
只覆盖有境界成长的五支；法器/阵法/建筑不挂钩。宗门招募的灵石价
（`sectRecruitStone = round(gold/10)`）与 AI 估值都从 `cost` 派生，自动跟着走。
回归测试：`cultivation.test.ts`「修士造价：升到下一时代花费的一半」。

## 天气/灵气视图不能再当全图透视（迷雾漏洞）

`BoardView.cells` 返回的是**全图**的场（温湿度、灵气浓度都存在 `Tile.custom` 里），
主渲染层原来全量染色 → 玩家切一下视图就能读出对面城市位置（一座灵田=一团深绿）
和地形分布（尤其浓雾局）。

改法：新增 `fog.ts` 的 `cellsInSight(s, visible, cells)`，在 `main.ts`
`computeBoardView(view.visible)` 里统一裁。三条边界：无雾一格不动；
有雾只留 `visible`；观战/复盘传的是全图所以自动不受影响。裁掉的格**留白不画灰**。

设计原则落成一句：**扩展算场，核心管"该不该让你看"**——遮蔽只能有一个地方能漏。
两处注释 + 规则书那段"全图，不按视野裁"的旧说法一并改掉。
回归测试：`test-rules.ts`「棋盘视图的染色按视野裁，不开全图透视」。

**还没关的同类口子**（已知未修）：浓雾局里点一个雾外格子，侧栏仍会显示
地块面板（地形按活数据、`qiSourceLabel` 还会点出那一格的敌方灵田/灵泉）。
要关得给 `getTilePanelLines` / `getTilePanelHtml` 加 `visible` 入参，
再让浓雾走"记忆里的地形"——没做，等玩家反馈。

验证：rules 790、cultivation 133、ui 219、ai 7+51、replay 9、net 4、
tsc 无错、build 通过、manual 11 册。
