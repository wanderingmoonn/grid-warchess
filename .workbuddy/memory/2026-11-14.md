## 关卡模式：方案文档（只讨论，未写代码）

产出 `docs/DESIGN-LEVEL-MODE-2026-11-14.md`。用户是编程小白（设计者），文档刻意用大白话，
末尾附"术语对照"表给以后写代码的人。

### 查证到的硬事实（这些决定了方案形状）

- `isAiSide()` 写的是 `p === 'B' ? aiOpponent : aiAlly`，而 `setup.ts` 里
  `aiOpponent = twoSeats && ...` → **三人四人局一律没有 AI，纯热座**。
  这是"2玩家+1AI骚扰""中立势力"三种形态共同的卡点。
- **没有同盟/队伍概念**，任意两席都是敌人。真同盟要改所有 "owner !== x" 判断，成本最高。
- `isEliminated()` = 没城即出局 → "没城的中立势力"第 1 回合就死。要"未登场"状态。
- 一局最多四家（PLAYER_ORDER 四个），四种想要的组合都落在上限内，不用抬天花板。
- 改地形没有寻路缓存要清（reachableTiles 每次现算），tiles 直接进存档 → 技术上最省事；
  真问题是城格不能改、格上有兵怎么办、桥断会不会切成死局、改完要让人看见。
- `ai.ts` 里三处调 `applyAction` 做试算 → 事件在试算里也会触发。所以事件记忆必须进局面。

### 建议的落地顺序（和最初设想不同）

1. 放开"第三家能是电脑" + 允许一人管两席 → 形态二、形态一(简化)立刻能跑，不需要事件系统
2. 开局部署 + 事件表第一批（回合数/阵亡/进区域 → 刷兵/播报/改打法）
3. 改地形 + 中立登场 + 真胜负条件；编辑器最后做（占全部工作量约 2/3）

### 待用户拍板

合作先用"一人管两家"还是必须真同盟；中立是否只占一个席位；地形改动能不能动有兵的格。

## v2（用户反馈后重写）

用户拍定：**砍掉"一人管两家"**（只增负担，且会造成"看着是队友实际是敌人"的长期不一致）；
**编辑器不开放，只做官方预制关卡**；中立占一个席位；**改地形给作者自由**，引擎只兜底
合法性，不做界面警告。

关键建议（写进文档第三章）："是不是关卡模式"要分三层，不能堆一个 if——
1. 空字段（首选，零风险，装下绝大部分：开局部署/事件表/胜负/中立/未登场）
2. 只在四个点分叉：怎么算赢、谁算出局、这一回合谁走、何时检查事件（这张表当登记册）
3. 不分叉直接做给所有人：**"第三家能被电脑接管"属于这层**，不是关卡模式特性

不开放自定义的连锁收获：安全模型、审核、编辑器、坏关卡四块全省掉；
新问题变成"关卡怎么更新"→ 建议云端表只读公开+写入锁管理端，且**每局记住自己用哪一版关卡**
（不能只存"第 3 关"）。真正的成本转移到内容：第一批至少 5~8 关。

"AI 打包"的可行形状：不是包里带代码，而是引擎先支持预设打法（守据点/巡逻/伏击/撤退/护送），
关卡只挑一个 + 事件中途换。关卡特有聪明 = 我们按关卡编号挂代码，不进关卡数据格式。

### 踩到的两个白名单

`state.config` 和 `openSetupPanel` 的 config **都是逐个字段抄的**。前者 P0 已补 `level`；
后者还没补，P1 做选关入口时**两处都要补**，否则"选了关卡→开面板→开始"关卡会静默消失。

### 顺手发现的既存问题（不是本次的活）

`state.config` 从来没抄 `fixedMap`，所以固定地图对局的复盘一直走"按种子重建 + board.w 对不上告警"。
关卡地图放在 `level.map` 里，所以不受影响；以后碰选图/复盘那块时再看。

### 用户新增需求：关卡限制扩展包

三档：必须开 / 禁用 / 其余自选。已定排在**批次 2**（和开局部署合并，因为都是"关卡对开局提要求"、
都碰建局流程、只需一次回归）。理由：关卡里的刷兵和地图依赖扩展，玩家关掉对应包不是"少个兵"
而是开局崩。界面上必须显示"本关固定开启 X / 固定关闭 Y"，否则玩家以为自己在改、实际没生效。

## 批次 1 已落地（21:0x）

- `MatchConfig.aiSeats: PlayerId[]` 是"谁被电脑操作"的通用写法；`aiOpponent/aiAlly` 由
  `createMatch` 反算写回，两家局老存档完全不变。`isAiSide` 三层：`aiControl` → `aiSeats` →
  老布尔。空数组＝全真人（判 `!== undefined`，不是长度）。
- **固定地图原来只在两家局生效**（`layoutFromRows` 只认 A/B）。给 `layoutFromRows` 加可选
  `extraCities` 让第三四席有城，**不进公开的 FixedMap 格式**（那要改校验/导出/缩略图/审核）。
- 关卡「三岔口」16×16 三家，`LevelSeats{count, cities, ai}` + 校验（第三席必须有城）。
- 面板：战役页加「关卡」一栏；多人局改成"每一席一个开关"；选关卡时人数/对手变只读。
  `applyLevelToConfig` 是唯一翻译点（面板和脚本共用），改人数会自动脱离关卡。
- probe 第 8 段：三家局 900 步跑到有人出局；回归 tsc / 900 / 248 / 9 全过。

### 踩到 / 学到的三件事

1. **`git stash pop` 失败会静默丢改动**：我 `cp` 覆盖了 stash 要恢复的文件，pop 冲突后没检查，
   一度以为"引擎改动没问题"。以后 stash 前后必须看 `git stash list` 和 status。
2. **老测试的前置条件写漏**：上帝模式拖笔用例找"干净横线"没排除**站着单位**的格，
   而 `paintTerrain` 本来就不刷有人的格。种子一挪就炸。已补单位判断（不是代码 bug）。
3. **三家局会打很久**：900 步 ≈ 119 回合只灭了一家 → 批次 4 的胜负条件（回合上限/任务目标）
   是必须做的，不是可选项。

### 踩到的一个坑（值得记）

断后关卡里我把守方唯一的兵摆在**桥面那一格**。写"攻方能过河"的断言时跑 160 步都没过去——
一度以为 `=` 桥不通。实际是：守方会补兵堵桥头，"能不能过"取决于打法，不是地图属性。
断言改成"攻方能摸到桥头（站到桥相邻那一列 or 把守桥兵打掉）"，这条才既稳定又真的在验桥。
**教训：用"AI 跑出某个结果"当断言时，先确认那个结果真的只由被测的东西决定。**
