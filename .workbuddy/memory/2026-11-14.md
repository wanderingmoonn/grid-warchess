# 2026-11-14

## 关卡模式：方案文档（只讨论，未写代码）

产出 `docs/DESIGN-LEVEL-MODE-2026-11-14.md`。用户是编程小白（设计者），文档刻意用大白话，
末尾附"术语对照"表给以后写代码的人。

### 查证到的硬事实（这些决定了方案形状）

- `isAiSide()` 写的是 `p === 'B' ? aiOpponent : aiAlly`，而 `setup.ts` 里
  `aiOpponent = twoSeats && ...` → **三人四人局一律没有 AI，纯热座**。
  这是"2玩家+1AI骚扰""中立势力"三种形态共同的卡点。
- **没有同盟/队伍概念**，任意两席都是敌人。真同盟要改所有 "owner !== x" 判断，成本最高。
- `isEliminated()` = 没城即出局 → "没城的中立势力"第 1 回合就死。要"未登场"状态。
- 一局最多四家（PLAYER_ORDER 四个），四种想要的组合都落在上限内，不用抬天花板。
- 改地形没有寻路缓存要清（reachableTiles 每次现算），tiles 直接进存档 → 技术上最省事；
  真问题是城格不能改、格上有兵怎么办、桥断会不会切成死局、改完要让人看见。
- `ai.ts` 里三处调 `applyAction` 做试算 → 事件在试算里也会触发。所以事件记忆必须进局面。

### 建议的落地顺序（和最初设想不同）

1. 放开"第三家能是电脑" + 允许一人管两席 → 形态二、形态一(简化)立刻能跑，不需要事件系统
2. 开局部署 + 事件表第一批（回合数/阵亡/进区域 → 刷兵/播报/改打法）
3. 改地形 + 中立登场 + 真胜负条件；编辑器最后做（占全部工作量约 2/3）

### 待用户拍板

合作先用"一人管两家"还是必须真同盟；中立是否只占一个席位；地形改动能不能动有兵的格。

## v2（用户反馈后重写）

用户拍定：**砍掉"一人管两家"**（只增负担，且会造成"看着是队友实际是敌人"的长期不一致）；
**编辑器不开放，只做官方预制关卡**；中立占一个席位；**改地形给作者自由**，引擎只兜底
合法性，不做界面警告。

关键建议（写进文档第三章）："是不是关卡模式"要分三层，不能堆一个 if——
1. 空字段（首选，零风险，装下绝大部分：开局部署/事件表/胜负/中立/未登场）
2. 只在四个点分叉：怎么算赢、谁算出局、这一回合谁走、何时检查事件（这张表当登记册）
3. 不分叉直接做给所有人：**"第三家能被电脑接管"属于这层**，不是关卡模式特性

不开放自定义的连锁收获：安全模型、审核、编辑器、坏关卡四块全省掉；
新问题变成"关卡怎么更新"→ 建议云端表只读公开+写入锁管理端，且**每局记住自己用哪一版关卡**
（不能只存"第 3 关"）。真正的成本转移到内容：第一批至少 5~8 关。

"AI 打包"的可行形状：不是包里带代码，而是引擎先支持预设打法（守据点/巡逻/伏击/撤退/护送），
关卡只挑一个 + 事件中途换。关卡特有聪明 = 我们按关卡编号挂代码，不进关卡数据格式。

## 批次 1 已落地（21:0x）

### 踩到 / 学到的三件事

1. **`git stash pop` 失败会静默丢改动**：我 `cp` 覆盖了 stash 要恢复的文件，pop 冲突后没检查，
   一度以为"引擎改动没问题"。以后 stash 前后必须看 `git stash list` 和 status。
2. **老测试的前置条件写漏**：上帝模式拖笔用例找"干净横线"没排除**站着单位**的格，

### 踩到的一个坑（值得记）

断后关卡里我把守方唯一的兵摆在**桥面那一格**。写"攻方能过河"的断言时跑 160 步都没过去——
一度以为 `=` 桥不通。实际是：守方会补兵堵桥头，"能不能过"取决于打法，不是地图属性。
断言改成"攻方能摸到桥头（站到桥相邻那一列 or 把守桥兵打掉）"，这条才既稳定又真的在验桥。
**教训：用"AI 跑出某个结果"当断言时，先确认那个结果真的只由被测的东西决定。**

## 批次 3 已落地（11-15 上午）

- `LevelDef.events`：`turn`(>=) / `unitDied` / `enter`(矩形) → `spawn` / `say` / `doctrine`。
- 触发点：`applyAction` 唯一出口，**排在结算/战损/胜负之后**（否则刷的兵算进战损、判的胜负被覆盖）。
- 进度 `state.levelState.fired`；差量 O(n)（Map/Set，别用 filter+some，它被 AI 每一步调用）。
- **`orderDirectiveOf` 去掉了 `if (!commanderMode) return auto`**：关卡事件要改 AI 打法。
  安全前提是该字段只有两处写，普通局读出来 undefined → auto，老存档不受影响。
- `LogEntry.system` 标记事件旁白（一定 open）。
- **性能实测**：引擎本身 +9%（5.47→5.96ms/步）；「断后」整体 +45% 是因为真多刷了兵，
  场上兵多 AI 自然慢。别把内容开销算到引擎头上。
- 教训：**一个永远不触发的事件比没有还糟**。断后的 enter 最初写"过到西岸"，守方一直堵桥头，
  几十回合踩不到 → 改成"推到桥东侧那一格"。写事件要问"正常打法下必然会发生吗"。

## 批次 7 首轮：三关落地（11-15 晚）

按讨论收敛成**三类各一关**：孤城（防守）/ 斩首（进攻）/ 黄雀（混战）。

**三个新能力（都不动规则地基）**
- `LevelDef.dev`：夹具关不进菜单、留在注册表（`playableLevels()` vs `allLevels()`）。
- `LevelDef.units`：关卡自带兵种，用 `summonedOnly` 做"只此一个"的守将。
- `LevelSeats.cityEra`：逐席开局时代，晚到的第三方进城就是铁器城。

**两个"配置对了但没生效"的坑**
1. 关卡兵种没并进 `state.unitTypes`（那张表只从 pool 来，summonedOnly 不在池子里）→
   部署被跳过 → `assassinate` 判"对手没有这个兵种" → **开局秒赢**。已修 + 加了保护
   （目标兵种不存在则目标不成立）。
2. `cityEra` 在 `validateLevel` 重新拼对象时丢了 → 第三方进城还是青铜。已修。

**AI 对 AI 实测**
- 孤城：三种子都是守方守满 15，城未破。攻方会打到河边，但没突破。
- 斩首：三种子都是敌方撑满（守将活着）。
- 黄雀：第三方 era2/42hp + 5 铁器兵，把蓝方城打没了，**优势可能过大**。

## 桥宽的定义（用户抓出来的，11-15 深夜）

**"桥宽"= 过河方向的通行格数，不是桥跨了几列河。** 河是竖的、过河走横向，
所以通行口宽不宽只看桥面在 **y 方向**占几格。只画 `(7,7)(8,7)` 是"跨过两列河、
只开一个口子"，还是一个兵堵得死。桥面要 2×2 四格，**炸桥事件的 zone 也得盖住四格**
（少写一行只塌一半，看着像"炸桥没生效"）。

**"改了地图进去没变化"**：`createMatch` 把关卡整包快照进 `config.level`，
事件/城位/部署全读快照；启动时 `loadMatch()` 优先于 `createMatch()`。
所以续旧档看到的是旧图（存档自洽，只是不含新改动）。**改完要开新局。**

两条都写进了 GUIDE 的坑列表（现在 12 条）。

## 关卡专属 AI 参数（11-15 深夜，提交 6f833d3）

**"AI 太胆小"的真实来源**：`tacticalMoveScore` 里推进一格只值 `progress*6` 分，
而 `risk.damage` 的惩罚是 `(25 + cost*0.18)` 量级——**站进对方射程要扣 20 分往上**。
守方摆几个兵它就不走了。战术档（rush/hold）只改倾向，改不动这笔账。

**新增 `LevelDef.ai`（`LevelAiTuning`）**：
- `riskAversion` 0.2~2（默认 1）—— 进攻性主旋钮，直接乘在威胁惩罚上
- `cohesion` 0~2（默认 1）—— 战线收拢强度（`aheadOfLine` 惩罚 0.15 的插值）
- `appetite` 0.2~3 —— 放大推进分

**但只调参数不够**（实测）：孤城上把 riskAversion 压到 0.3、cohesion 归零，
过河 3→4 个，守方城**一滴血不掉**。原因是投送/拥堵：过河的兵停住堵桥头，
后面的被自己人卡在窄桥上。**投送是 AI 的硬伤，参数改不动。**

**所以孤城改成用事件送人**：三支过河突击队（第 12/15/24 次）直接 spawn 到西岸。
四条经验：落点要在对方那侧 / 时间要早（16 次后就晚了）/ 每波都要播报 / 兵种配一个弓手。

实测四种子：seed404 破城、77 打到 12、3 打到 23、21 没影响。

**斩首关可以反过来用**：`riskAversion: 1.5` 让守将惜命（还没试）。

**修正（用户指出）**：直接送到西岸不行——玩家觉得"AI 在耍赖"，不是"远处来了援军"。
改成**从地图南北边缘进场**的骑兵（`a7c26ee`）：关卡自带兵种 `游骑`
（铁器数值但 move 4，`summonedOnly`），三波 14/19/25 次，从 (2,0)(3,0) / (2,13)(3,13) 跑进来。
**兵种移动力是包抄感的关键**：move 3 的骑兵会被一步步点掉，逼不出分兵。
实测四种子：三个城掉到 18，一个没挨打。
探针钉住"骑兵必须落在 y=0 或 y=h-1"。

## 合并 liuks-branch 后的三个修复（11-15 晚，提交 0b4a020）

## 修 bug：地图上的桥会自己塌（11-15 晚，用户实机发现）

- 现象：地图里的 `=` 桥**第一次结算就塌**（有人站上去就落水）。
- 原因：`syncBridges` 判据是"桥面 + 没有桥单位撑着 → 塌"，只对工兵桥成立，地图桥没单位。
- 修法：建局把桥面格号记进 `state.mapBridges`，`syncBridges` 跳过；老存档读档时补扫。
- 连带：`断后` 因此变成永远打不完（一个兵卡桥面），已补 `survive 24`。
  **那关以前"能打完"是建立在 bug 上的。**
- 探针 +9 项（走三步桥还在/兵还活着；工兵桥照旧塌）。
