## F1 无城对战：方案定稿（还没写代码）

文档 `docs/DESIGN-CITYLESS-2026-11-16.md`。

**两处比直觉麻烦的地方**：
1. 只改 `isEliminated` 会让这局**永远收不了场**——`checkWinner` 的存活条件是
   "有兵 **或** 买得起一个兵"，无城方永远买得起。所以要同时改三处：
   `isEliminated`（无城→没兵才出局）、`checkWinner` 的 alive（无城只看兵）、
   `retireLostSeat`（无城直接跳过）。
2. AI 的推进分来自"到敌城的距离场"，没敌城 = Infinity → 全军不动。
   **这是结构问题不是权重问题**（和"AI 不渡河"同类），决定把"目标"从城抽象成一个点。

**定下的四件事**：
- AI 走完整方案（目标点抽象，没敌城用敌军重心）。
- **底薪（baseIncome 20）全部删除**，有城模式也删；各时代 cityIncome 各自 +20
  （30/35/41/48/56/62/68/78 → 50/55/61/68/76/82/88/98）。
  单城局一分不变；**双城局每回合 +20（青铜 +25%）**；无城方 0 收入。
  连带要改：`scripts/test-rules.ts` 的收入断言、`scripts/build-manual.ts` 规则书两处、
  `ANALYSIS-ECON` 一类经济结论全部作废。
- 视野不补偿（城给 1 格，无城方少一圈，写进简报）。
- 无城方兵打光即输（带后续波次的关卡有隐藏失败点，写进简报/GUIDE）。

**还有一个口子**：`validateFixedMap` 要求 A/B 各≥1 城，所以它要能接受
"这一方允许没城"（由 validateLevel 传 cityless 下来；地图上传那条路不传）。

## 新玩家关「护送」（第四关，补齐能力展示）

基于用户灵感：escort + cityless + 长条地图 + 经过刷追兵 + 到达即胜。
18×8 横长走廊，玩家 A 无城（5 个铁器兵 + 信使），B 有城（铁器城 cityEra 2），
escort 目标 = 信使到东端；cityless 的"兵打光即输"自动兜失败。

**关键设计结论（实测踩出来的）**：
1. **城防高 = 开局在城前摆一堆箭塔**（用户纠正）。不是改城时代、不是改数值。
   塔是静态建筑，只压路线、不滚雪球；cityEra 拉高反而会让 AI 刷高级兵碾压。
   最终 3 座塔（北通道/南通道/城前），射程 3 覆盖两条绕城通道。
2. 兵种领先靠 `cityEra: { B: 1 }` 把敌城压回青铜。`startEra` 是双方共用的，
   写 2 的话 B 也是铁器城、一样造长枪兵，领先就不存在。
3. 信使 move 4、血 36：塔阵从 x=10 覆盖，move 2 会被磨死；
   move 4 连挨两轮（14+21=35）剩 1 血进终点，慢一步就死。
2. 护送目标开局别被自己人围死——deploy 要给信使留向东的通道。
3. AI 对打里护送方（A）必输（AI 不会保护关键单位），只能用来"验能跑完"，
   平衡手感必须真人实机试玩，脚本测不出。

**探针更新**：菜单"三关"→"四关"（probe-level + smoke-dom 各一处）；

## 关卡「禁用兵种」`banUnits`（2026-11-16）

起因：邪龙关里玩家也能造邪龙王，两人各一条就破了。现在关卡数据有 `banUnits: string[]`。

**挂点选得很关键**：`canUseType`（draft.ts）是所有"能不能造"的共同出口——
城市产线、军营、AI 采购、建造单位盖房子都问它。所以规则层和界面自动同口径。
**别**在 unitTypes 里删兵种：事件 `spawn` 读的是 unitTypes，删了敌人就刷不出来。

- 不删场上已有的（读档 / 后加禁用都安全）。
- produceAt 里单独给文案"这一关禁用「X」"，不要落到选卡那句"不在本局选用的名单里"。

## 邪龙关 AI 三旋钮拉满（用户要求）

`doctrine: 'rush'` 只改倾向，改不动"每格那笔账"（挨打扣分 > 推进得分），所以
AI 会停在山脊上排队。加上 `ai: { riskAversion: 0.2, cohesion: 0, appetite: 3 }`
（三个都取攻击端极值）之后才会真压过来。

**范围**：riskAversion 0.2~2（小=敢换命）、cohesion 0~2（0=不等队友）、
appetite 0.2~3（大=更想推进）。`level.ai` 是**整关一份**，不分席位

## 邪龙不推进的真因：riskAversion 下限卡在 0.2

实机"大军堆在城前、只靠邪龙王下蛋"。查评分公式：`score += progress*6*appetite*tuning.appetite`，
`progress` 一格才 ~0.32（air 距离场 ×0.32 权重）→ 每格约 5~6 分；而
`score -= loss*(25+min(60,cost*0.18))*riskMul`，即使 riskMul=0.2 也有十几分。
所以 0.2 档仍然停在火力圈外。

修法（引擎层）：
1. `riskAversion` 下限 0.2 → **0**（完全不计伤亡）。默认 1 不变。
2. `soonRisk`（下下回合威胁）以前**不乘 riskMul**，0 档仍被它劝退；改成一起乘。
3. 编辑器滑杆 min = 0。

效果（seed 5，260 步）：最近城距离 5 → 1，城血 96/96 → 96/58，分布 y=5~9 → y=4~15。

**注意**：`level.ai` 是整关一份（不分席位）；改夹具 probe-flat 时要当心全局 replace 波及
（我这次误把它的 0.2 改成了 0，已还原）。

**胜利条件**：用户要求去掉 survive(45)，改回默认全歼。代价是恶魔召唤 + 残兵散角落
可能拖成"追着最后几只跑"，实机再看要不要加清剿手段。

**探针**：boss 下场那条改用 `godMode` 另开一局——AI 变凶后电脑代打的玩家第 24 次就被打崩，
正常局根本跑不到第 26 次。

## 护送关"到了终点没赢"的真因 + 护航队换代

**根因**：`escort` 判定没问题（把信使放进 zone 立刻判胜）。问题是**点亮区域比终点大一圈**——
`reveal` 写的是 14..17×1..6，`goals.zone` 是 15..17×2..5。玩家拿亮区当终点，
走到 x=14 那列就以为到了。修法：两者必须**完全一致**。

**教训**：凡是"玩家看不见的判定框 + 能看见的提示"（点亮、高亮、标记），
两个区域的边界必须逐格相同。差一格就是"我明明到了"。

配套：
- `goalText` 的 escort 以前直接显示 id（"把「messenger」送到…"），改成查兵种名；
  关卡独有兵种查不到 → `LevelGoal.escort` 加了 `label`（"信使"）。
- lint 新增：reveal 区域与 escort 终点重叠但不相等 → warn。

**护卫队换火器**：骑士×2/长弓/弩兵 → 火枪×2/戟兵/骠骑兵；`startEra` 2→3。
实测 B 城第 10 次行动升到 2（铁器）后停住，火枪仍压得住。
**但 AI 还在花钱升级**——真要锁优势得加"席位时代上限"，不是继续抬护卫队。

## 邪龙"整军不动"：两个校验 bug + 新参数 pressure

**最重要的发现**：`normalizeAiTuning` 的 `riskAversion` 区间一直卡在 0.2~2，
而注释/编辑器都写"0 = 完全不计伤亡"。关卡写 0 会被**静默夹回 0.2**——
上一轮"拉满攻击性"实际只拉到 0.2。同一函数还不认识新字段（`pressure` 被整段丢掉）。
**教训：加字段/改区间时，`normalizeXxx` 是第四个地方（类型、UI、文档之外），漏了就静默失效。**

**评分层的结构问题**：`best.v <= 0` 就返回 null。一批单位在离城十几格的开阔地上时，
推进分抵不过地形分和拥挤分 → 每回合都 null。实测 22 个单位里只有 3 个在动。

**新增 `pressure`（0~3，默认 0）**，两道：
1. 推进分随回合加码 `1 + pressure*turn/25`（封顶 4 倍）；
2. **督战 `pressureAdvance`**：core 返回 null 时，挑一个"还能动且更接近敌城"的单位走一步。
**只对没有城的席位生效**（有城的是防守方，加码会让它丢城出击）。

邪龙关：`riskAversion 0.3`（0 会站着送）、`cohesion 0`、`appetite 3`、`pressure 1`。
实测一回合 8~12 个单位移动、出现 SIEGE，AI 对打 33 回合推平。

**判断口径**：AI 对打只能证明"机制通了"，不能当难度依据（用户明确说过）。

## 战报栏：事件触发时自动展开（2026-11-17）

战报 `<details data-fold="log">` 默认收起，事件往往只在里面一句话 → 玩家看不见。
现在按 `levelState.fired` 的**长度**判断：变大就 `logOpen = true`。

**口径（用户 2026-11-17 定）**：只展开**带 `say`** 的事件。不带 `say` 的（spawn/terrain/reveal）
很可能是作者有意不让玩家知道的暗手，抖出来等于剧透。判断函数 `logEventSays`。

三条边界：
- 基线是 **id 集合**不是计数（`fired` 是 Set，repeat 事件重复触发不改变长度）；
  首次进局时集合为空，已触发的事件全算"新"，于是开局播报会展开；
- `repeat` 事件只在第一次展开（之后每回合弹一次比不提示还烦）；
- 复盘不展开；
- 复盘期间**连基线都不动**（回放的 state 是另一份快照，否则退出复盘会凭空多出一批事件）。

`logOpen` / `opsOpen` 是 main.ts 的模块状态（`<details>` 每帧重建会丢 open），
toggle 事件不冒泡，监听挂在 `#side` 的捕获阶段。
