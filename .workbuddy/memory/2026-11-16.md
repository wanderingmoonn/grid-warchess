## F1 无城对战：方案定稿（还没写代码）

文档 `docs/DESIGN-CITYLESS-2026-11-16.md`。

**两处比直觉麻烦的地方**：
1. 只改 `isEliminated` 会让这局**永远收不了场**——`checkWinner` 的存活条件是
   "有兵 **或** 买得起一个兵"，无城方永远买得起。所以要同时改三处：
   `isEliminated`（无城→没兵才出局）、`checkWinner` 的 alive（无城只看兵）、
   `retireLostSeat`（无城直接跳过）。
2. AI 的推进分来自"到敌城的距离场"，没敌城 = Infinity → 全军不动。
   **这是结构问题不是权重问题**（和"AI 不渡河"同类），决定把"目标"从城抽象成一个点。

**定下的四件事**：
- AI 走完整方案（目标点抽象，没敌城用敌军重心）。
- **底薪（baseIncome 20）全部删除**，有城模式也删；各时代 cityIncome 各自 +20
  （30/35/41/48/56/62/68/78 → 50/55/61/68/76/82/88/98）。
  单城局一分不变；**双城局每回合 +20（青铜 +25%）**；无城方 0 收入。
  连带要改：`scripts/test-rules.ts` 的收入断言、`scripts/build-manual.ts` 规则书两处、
  `ANALYSIS-ECON` 一类经济结论全部作废。
- 视野不补偿（城给 1 格，无城方少一圈，写进简报）。
- 无城方兵打光即输（带后续波次的关卡有隐藏失败点，写进简报/GUIDE）。

**还有一个口子**：`validateFixedMap` 要求 A/B 各≥1 城，所以它要能接受
"这一方允许没城"（由 validateLevel 传 cityless 下来；地图上传那条路不传）。

## 新玩家关「护送」（第四关，补齐能力展示）

基于用户灵感：escort + cityless + 长条地图 + 经过刷追兵 + 到达即胜。
18×8 横长走廊，玩家 A 无城（5 个铁器兵 + 信使），B 有城（铁器城 cityEra 2），
escort 目标 = 信使到东端；cityless 的"兵打光即输"自动兜失败。

**关键设计结论（实测踩出来的）**：
1. **城防高 = 开局在城前摆一堆箭塔**（用户纠正）。不是改城时代、不是改数值。
   塔是静态建筑，只压路线、不滚雪球；cityEra 拉高反而会让 AI 刷高级兵碾压。
   最终 3 座塔（北通道/南通道/城前），射程 3 覆盖两条绕城通道。
2. 兵种领先靠 `cityEra: { B: 1 }` 把敌城压回青铜。`startEra` 是双方共用的，
   写 2 的话 B 也是铁器城、一样造长枪兵，领先就不存在。
3. 信使 move 4、血 36：塔阵从 x=10 覆盖，move 2 会被磨死；
   move 4 连挨两轮（14+21=35）剩 1 血进终点，慢一步就死。
2. 护送目标开局别被自己人围死——deploy 要给信使留向东的通道。
3. AI 对打里护送方（A）必输（AI 不会保护关键单位），只能用来"验能跑完"，
   平衡手感必须真人实机试玩，脚本测不出。

**探针更新**：菜单"三关"→"四关"（probe-level + smoke-dom 各一处）；

## 新事件动作「点亮」+ 缩略图透明底（用户需求）

**点亮** `{ kind: 'reveal', zone }`：
- 永久可见（地形+单位），不随视野收回；不改地形/不刷兵/不影响规则。
- 状态 `GameState.revealed: number[]`（地球格号），playerView 并进可见集。
- **开关 = 加不加这条动作**（隐秘事件不加）。
- 幂等（repeat 里重复点亮不堆）。
- 编辑器：动作下拉「点亮一片区域」、卡片「点亮 [区域]」、拖框共用 pick-do-zone、时间轴「点亮 N 格」。
- 护送关：开局点亮终点 4×6；两处伏兵点亮刷兵位。

**缩略图**：`.map-card-thumb` 底色 `--plain` → 斜条纹（透明格不再和平原同色）。

坑：`turn: 1` 的事件在 `createMatch` 末尾就跑了（runLevelEvents），

## 点亮改限时 + 双人合作方案（讨论稿）

**点亮限时**（用户反馈"一直可见不太好"）：
- `{ kind: 'reveal', zone, turns? }`，默认 1；`until = turn + turns`，fog 按 `until >= turn` 过滤。
- 默认 1 覆盖"当下 + 下一手"（事件常在对方回合触发，只亮当下一手等于没看见）。
- `GameState.revealed: RevealMark[]`（格号 + 过期点）；doEndTurn 清过期。
- 编辑器：「持续 [N] 次行动」输入；1 是默认不写进 JSON。

**双人合作打强敌：引擎不支持**（方案 `docs/DESIGN-COOP-2026-11-16.md`）。
三处地基都是"各家独立"：
1. `ai.ts enemySeats` = 除我之外所有人（无队友概念）
2. 攻击判定 `defender.owner === attacker.owner`（A 能打 B）
3. `checkWinner` 剩一家才结束（打光 C 后 A、B 还要互打）
连带：视野不共享、`retireLostSeat` 队友丢城会撤兵、认输按人算。
改法 P0（队数据+sameTeam+攻击3处+胜负按队+AI）/P1（视野共享/丢城/认输）/P2（友军穿行/文案/面板），
约 2~2.5 天。最大风险：AI 不会配合队友、2打1 平衡只能实机调。

## 点亮永久选项 + 同盟引擎（用户决定后落地）

**点亮**：`turns` 写负数 = 一直亮（state 里用 999999 而不是 Infinity，JSON 存不了）。
编辑器加了「一直亮」勾选框。默认仍是 1 次。

**同盟**（`seats.teams`）：
- 用户划掉三项，**一个字没动**：视野不共享、一人认输只退自己、丢城队友照撤。
- 做了两项：攻击判定（打兵/攻城/溅射三处 `sameTeam`）、友军穿行。
- **穿行的正确改法**：只改寻路的 `enemyBlocks`（同队不挡），**不动** `blockedAnchor`
  → 能穿过去、不能停在队友身上。也没碰 `sameLayerAt`（它同时管"能不能站"）。
- **胜负必须同时按队**：不能打友军 + 只剩一家才结束 = 打光敌人后死锁。
  按队判：只剩一队活着就结束，赢家 = 队内第一个活着的席位。
- AI `enemySeats` 排除队友，否则它会一直"想打又打不了"。
- 未做：席位面板的同盟开关（目前只能改 JSON）、结算文案、第一张合作关。
