# 方格战棋

一个回合制战棋：古典到现代五个时代，基于地形的走位、跨河的桥、迷雾、联机对局（带观战位）。
没有 UI 框架，没有后端，一套纯函数规则内核 + 一层手写 DOM。

线上地址：<https://grid-warchess-76858.app.workbuddy.host/?sharecode=JXRGIZAHUH>

## 跑起来

```bash
npm install
npm run dev      # 本地开发，http://127.0.0.1:5178
```

需要 Node 18+（`node --experimental-strip-types` 直接跑 TypeScript，不需要编译）。

## 常用命令

| 命令 | 做什么 |
|---|---|
| `npm run dev` | 本地开发服务器 |
| `npm test` | 全量测试：规则内核 280 项 + DOM 冒烟 93 项 |
| `npm run test:rules` | 只跑规则内核（无浏览器、无 mock，直接 import） |
| `npm run build` | `tsc --noEmit` + `vite build`，产出 `dist/` |
| `npm run manual` | 从代码里的兵种/能力/扩展数据重新生成规则书（13 册：核心册 + 小型扩展合订本 + 每个大型扩展一册） |
| `npm run bench` | 双 AI 对打基准：每个组合 N 个种子，统计回合数与最高时代 |
| `npm run ablate` | 消融实验：逐个"撤销"某轮平衡改动，看它到底影响多少 |
| `npm run balance` | 生成平衡报告（JSON + markdown） |
| `npm run map` | 打印一张地图，排查地图生成问题 |
| `npm run sim` | 单局 AI 对打，逐步打印决策 |

环境变量对基准工具很好用，例如只跑古典 12×12 的 100 局：

```bash
BENCH_ERA=1 BENCH_SIZE=12 BENCH_SEEDS=100 npm run bench
AB_ERA=1 AB_SEEDS=60 npm run ablate
```

## 目录结构

```
src/core/      纯函数规则内核（不含 DOM、不含网络、不含 Math.random）
  types.ts       数据模型，GameState 可 JSON 序列化
  config.ts      ⭐ 所有可调数值都在这里：兵种、时代、地形、城市
  rules.ts       applyAction(state, action) → ActionResult，规则的唯一入口
  ai.ts          AI 决策，只吃玩家视图，不作弊
  mapgen.ts      地图生成：城市布点、河、山脊、出生点
  fog.ts         战争迷雾与视野
  expansions.ts  扩展规则（血战、老兵、堑壕战……）与钩子
  era-packs.ts   ⭐ 五个时代兵种包（69 个新单位），数值推导写在文件头
  abilities.ts   能力的接口与时机（各能力自己的实现在它主人的文件里）
                 · ability-hooks.ts  只定义钩子与 stage，不实现任何能力
                 · abilities.ts      本体兵种用的公共能力（11 条）
                 · ability-registry.ts 核心表 + 各扩展贡献的能力，合并查询
  setup.ts       开局装配、起始金币

src/ui/        手写 DOM，没有框架
src/net/       联机房间（云数据库存整局状态，6 位房间码）
src/storage/   本机存档（自动落盘，刷新不丢）
scripts/       测试、基准、报告、规则书生成
```

## 三条硬约束

改代码前值得先知道这三条，它们是这套东西能撑住的原因：

1. **`applyAction` 是纯函数。** 吃一个 `GameState` 和一个 `Action`，返回新的 state，不碰 DOM、不发网络、不用 `Math.random`。所以整套规则能在 Node 里直接测，也能拿去做 AI 对打基准。
2. **一切都是确定性的。** 随机数走 `state.seed`，AI 的"手感"走 `aiNoise(seed, turn, log.length)`。同样的种子和操作序列，结果一定相同——测试和复现靠这个。
3. **AI 不作弊。** 它只拿到 `playerView(state, player)` 同一份迷雾视图，没有上帝视角。

## 改数值改哪里

绝大多数平衡工作只需要动 `src/core/config.ts` 里的 `UNIT_TYPES`（兵种）和 `ERAS`（时代）。改完跑：

```bash
npm test           # 有回归测试兜底，比如"射程必须大于移速"
npm run manual     # 规则书会跟着数据重新生成
npm run bench      # 看对局长度和时代推进有没有跑偏
```

如果某次改动让对局长度变了，先别猜原因，`npm run ablate` 会把每个改动的影响单独量出来。

## 时代兵种包（大型模组）

五个时代各一套兵种扩展，取材自真实历史的兵种、攻城器械与防御工事，**每套都比原版同期更多**：

| 时代 | 扩展 id | 新增 | 原版同期 | 代表单位 |
|---|---|---:|---:|---|
| 古典 | `pack-antiquity` | 15 | 12 | 重装步兵、军团兵、战车、战象、攻城槌、弩炮、瞭望塔 |
| 中世 | `pack-medieval` | 12 | 8 | 重装军士、弩手、骑射手、瑞士长矛兵、投石机、攻城塔 |
| 火药 | `pack-gunpowder` | 14 | 11 | 线列步兵、胸甲骑兵、猎兵、攻城加农炮、棱堡、风帆战列舰 |
| 工业 | `pack-industry` | 14 | 7 | 堑壕突击队、火焰喷射器、毒气兵、榴弹炮、列车炮、马克 I 坦克 |
| 现代 | `pack-modern` | 14 | 11 | 伞兵、突击队、反坦克炮、喀秋莎、重型坦克、机枪地堡 |

它们在开局面板的扩展列表里单独勾选，不勾选时对原版零影响。
数值怎么定的、每金耐久带、为什么古典包的价格要压在 60 金以内，都写在
`src/core/era-packs.ts` 的文件头注释里。

平衡数据在 `results/packs/report.md`（含每兵种的交换比、每百金杀伤/抗伤、采用率）。
重跑：

```bash
# 五个模组 + 五个基线，各 30 局（约 1 分钟一组）
node --experimental-strip-types scripts/balance-report.ts --era 1 --games 30 --seed 900 \
  --expansions bloodbath,turn-order-comp,pack-antiquity \
  --md results/packs/era1.md --out results/packs/era1.json
# ……其余四个时代同理（基线去掉 pack- 那一项）
npm run pack-report    # 汇总成 results/packs/report.md
```

**一条改数值时容易踩的坑**：开局部队是从 `era === 1 && category === 'combat' && domain !== 'water'`
的池子里**轮流白送且不看价钱**的。所以古典包（唯一 era 1 的包）的陆军战斗单位价格必须压在
60 金以内，否则开局就白送战象，整局基准会直接漂掉——`npm test` 里有一条专门守这个。

## 指挥官模式

开局选「你的角色 → 指挥官模式」后，玩家不再亲自走子，只排**接下来 5 回合各造什么兵**，
建造、升级、走位、攻击全部交给 AI。

- 顶栏下面一条「参谋部」横带，5 格生产序列，第一格标着「本回合」
- 每格可以是**一个兵种**、**「升级时代」**，或者**留空**（这回合故意不产兵也不升级）
- 每格下面标着「≈ N 金」：那一回合大概有多少钱可花（现有金币 + 中间几次收入 − 前面几格的花费），不够就变红
- **点一次「执行 5 回合」，5 个回合一起打完**，中途可中断；打完序列原样留着，排一次能用很多批
- 每回合最多产 1 个兵；**造不出来也照样消耗那一格**（钱不够、时代不够、编制满了都算）
- 点名的兵不会被顶替：排了坦克造不起就空过，不会自动换个民兵顶上
- **升级权也归你**：没排「升级时代」，AI 不会自作主张升；排了，这一回合就专注升级、不产兵
- 棋盘只看不碰，这一方的走位归 AI

这条限制**对 AI 同样生效**：在指挥官模式下选「双 AI 观战」，两边都只剩一回合一个兵，
用来量这套限制下 AI 还能打成什么样（人类能一次排 5 格、AI 只知道当下造什么，
所以测的是下界）。

实现上是 `MatchConfig.commanderMode` 加 `GameState.orders`（序列存在状态里，跟着存档走），
执行时把 `AiBudget.order` 交给 AI，产兵候选被限定到点名的那个兵种。

## 联机

房间码就是通行证：把 6 位代码发给对方，谁拿到谁就能进这局。
只在**结束回合（提交）**时把整局状态写到云端，所以对方看不到你这一回合正在怎么摆兵。

**观战位**：输代码点「只看」，或者把邀请链接发给第三个朋友——两个座位都满了，链接会自动以观战身份打开。
观战不占座（数据库里没有为它加列，观战本来也不需要互斥）、不写云端、给的是**全图视角**，
走路/产兵/提交全部锁住。所以别在两个人还在打的时候开着麦念棋盘。

一个必须说清的边界：`GameState` 是整块存进去的，服务端不参与规则计算。
**迷雾是界面约定，不是安全边界**——真要防作弊得把 `playerView` 挪到服务端算。
观战位把这条边界放大了：看得见对方每一支部队和每一笔金币。

## 对局数据（可选上传）

一局打完，结算卡上会多一块「这局的数据要不要捐出来」。**默认是关的**，
勾选框只代表"允许"，点按钮才真的发；发之前会把要交的内容一条条列出来。

**开局时还能选「记录详细数据」**（新对局面板里的「数据收集」，默认关）：
勾上之后这局每回合留一行压缩数字（双方兵力 / 城防 / 金币 / 军队身价 / 累计战损）
+ 双方的出兵与行动次数，结算时一起交。只交终局快照看不出"这局是怎么崩的"，
而调 AI 和兵种要的恰恰是曲线和中途的选择。

战损这一列是**靠单位集合差分**数出来的（每走完一步比对"上一刻在场、这一刻不在了"），
不去数 `u.kills`——那个字段只在「老兵不死」扩展下增长，别的组合里永远是 0。
口径只算兵、不算建筑，主动拆除（`DISBAND`）也不算：那是回收，不是被打掉。

- 交上去的：地图种子、棋盘尺寸、行动次数、胜负、扩展包组合、AI 难度、
  双方终局阵容与资源、地形分布；勾了详细记录再加逐回合摘要与行动/出兵计数；
- **不交的**：玩家名、房间码、每一步的操作记录、自定义兵种的说明文字。
- 传不上去（没开通 / 凭据过期 / 断网）不影响任何事：报告随时能「复制」或
  「下载 .json」，自己发出来一样有用。

**收集端已经开通**（2026-10-28）：云端数据库里有 `warchess_reports` 表，
外加两个分析用的视图。表只给 anon 发写权限、不给读权限——谁都能交一份，
但没人能顺着这张表把别人交的东西整锅端走；做分析请用管理员连接查
（云服务面板的 SQL 窗口，或 `cloud-service` 的管理通道）。

- 建表 / 重建：`sql/warchess_reports.sql`（表 + RLS + 限流触发器 + 两个视图，逐句执行）
- 分析查询：`sql/warchess_reports_queries.sql`（先手胜率、按难度分组、
  扩展是否一边倒、兵种采用率、终局经济、来源分布、重复上传排查）
- 一键汇总：把 `select * from warchess_reports;` 导出成 JSON，然后
  `node --experimental-strip-types scripts/reports-digest.ts that.json --md digest.md`，
  得到一份带样本量提醒的 markdown 报告（含双方的战损身价、赢家交换比，
  以及"单格最大掉血"这个崩点指标）

另外两列和采集渠道有关：`campaign`（邀请链接上的 `?campaign=`，用来按批次隔离数据，
不是身份）、`verdict`（`plausible` 过了结构校验 / `unverified` 老数据 / `quarantined` 人工隔离）。

两层防滥用，别混：
- **限流**（`client_id`）：每个浏览器一个随机代号，同一小时内超过 30 条由触发器拒掉。
  它只用来分组计数，不是身份，也不进报告正文；
- **去重**（`fingerprint`）：种子+回合+胜负+终局（+摘要规模）算一个键，服务端唯一索引兜底。
  换设备、清缓存后重传会被认出来，客户端显示"这局云端已经有了"而不是报错。
- 视图：`warchess_reports_by_side`（一场两行，带 won / ai_level / 阵容）、
  `warchess_reports_units`（一个兵种一行）。**不要**把视图 grant 给 anon，
  否则等于绕开"只写不读"的设计。

代码上分两层：`src/core/report.ts` 只负责从 `GameState` 里**算**出一份报告
（纯函数，规则测试直接断言"里面不许出现某个名字"）；
`src/net/reports.ts` 只负责把它塞进 `warchess_reports`，并按错误码说清楚
是没开通、凭据不对，还是网络不通。

## 已知的待办

- 联机防作弊（服务端算视野）
