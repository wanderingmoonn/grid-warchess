## 它和 P-1-03 是一对

| | P-1-03（该升） | P-1-04（不该升） |
|---|---|---|
| 城 | 2 代 **30/63** | 3 代 **81/81** |
| 城能撑几轮 | **2**（闸 A 的门槛） | **7** |
| 池子 | 2 代全废（三发 42 < 46） | 3 代够用（戟兵 48 / 火枪 54） |
| 金 | 520（升完只剩 160） | 900（升完还剩 360） |
| 正解 | **升，然后造打得穿的** | **不升，造兵打死它** |
| v1 / v3 | 绿 / 红（升了但买废物） | 红 / 红（**升了 4 代**） |

**一换只动两个数**（城的代与血、金币），敌人/地形/窗口全不动——这是"换变量不换考法"的标准形状。

## v1 为什么红：它见本就升

v1 金 900 → 花 540 升到 4 代（城血 88、金 60），造了 2 个兵、打死了戟兵。
**行为本身没错**，但它付了一笔这题不需要的钱：城本来能撑 7 轮、兵本来就打得穿。
判据用 `cityEra max 3` 拦的就是这件事——"能升"不等于"该升"。

v3 更糟：升了 4 代、造了 3 个兵、**一个没打死**（钱都花在便宜兵上）。

## 判分器的一个小改动（顺手做的）

`cityEra` 原来只支持 `min`，`mustNot` 里没法表达"不许升到 4 代"（`ok: era >= min` 在 mustNot
里语义是反的）。这一轮给它加了 `max`，和 `gold` / `foeCities` 的写法统一：
`ok = (min 满足) && (max 满足)`。现在 `mustNot { kind:'cityEra', max:3 }` = "整局别超过 3 代"。

## 它没量什么

- **不量升级的收入收益**（+7/回合）——8 手窗口里看不出来，那是 `E-2-01`。
- **不量"升 4 代换步枪兵"**——1~2 个步枪兵 vs 4 个戟兵的账在这题里算不清（P5 的编成）。
- **不量多城**：只有一座城。
