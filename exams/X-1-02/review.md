# X-1-02 评审（战术动作 · 1 一件事 · 集火的一换）

## 结论

**护栏题：空壳红，v1 / v3 / v4 全绿**（四颗种子 51/1/2/3 同结论）。
和 X-1-01 同一结论形状，但兵种与数值都换掉了。

| 答题者 | 第 1 手结束时敌人还剩 | 结论 |
|---|---|---|
| 空壳 | 3 | 红 |
| v1 | **2** | 绿 |
| v3 | **2** | 绿 |
| **v4（现在）** | **2** | **绿** |
| v4（战术模式之前） | **3** | 红 |

判据：`unitCount(side=foe) ≤ 2`（第 1 手）+ `neverLostCity`；`lostUnits ≤ 1`。

## 一换换掉了什么

| | X-1-01 | X-1-02 |
|---|---|---|
| 我方兵种 | 弩兵（19 攻，一发 **16**） | **弓手**（11 攻，一发 **6**） |
| 敌人血量 | 20 / 30 | **10 / 12** |
| 能合打收掉的 | 30 血那个 | **12 血那个** |
| 只有 u1 够得着的 | 20 血那个 | **10 血那个** |
| 考的东西 | 合打 vs 各打各的 | **完全一样** |

局面、坐标、覆盖形状、判据形态全不变——只把"伤害是 16"换成"伤害是 6"，
把敌人的两个血量按同一比例重算。这是"一换"该有的样子：换掉一个条件，不改考的东西。

## 它证明了什么

X-1-01 有个隐患：结论可能只是"那一组的数字凑巧"（20 血那个正好是血最少的）。
一换之后：

- 如果 v4 只按"血最少"选，它还是会去啃 10 血那个（一发 6，剩 4），**第 1 手一个都不死**；
- 而按"能不能收掉"选，它会和 u2 一起去收 12 血那个（6+6=12），**第 1 手少一个**。

实测：修之前的 v4 是"3 个敌人"，修之后是"2 个"。**两道题一起**才说明机制认的是
"这一手能不能收掉"，不是"哪个数字小"。

## 它没量什么

- 不量"三发以上才收得掉"的多回合集火（那需要更长的窗口，会掺进补兵/撤退）。
- 不量"该打谁"的价值判断：两个敌人威胁一样（都是贴脸长枪）。
- 不量"进攻时的近战靠拢"——`converge` 现在是关着的，等第 4 步（`X-2-01`）。
