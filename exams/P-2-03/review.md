# P-2-03 评审（2026-11-26）· 自己架桥

> **它现在是一道 v4 的回归题**：架桥这件事要全链走通——**把桥铺出来、从桥上过去、站到城下开打**。
> 2026-11-26 定版时它复现的是"桥能铺出来、但部队不过桥"；当天就定位到原因并修掉了
> （AI 把自己造的桥当成一个人挡在路上），现在 v4 **绿**。

## 一、题是什么

- 18×18，一条 **3 格宽**的河横断全图，**一格桥都没有**（就是 `P-4-01` 把桥拆掉）；
- 我方：6 戟兵 + 6 火枪 + **2 个劳工**（能修木桥，45 金/格）、**900 金**；无收入；
- 敌方：一座 3 代城 + 两座箭塔，**摆在角落 (17,0) / (17,17)**——打不到桥、不压上岸点，
  只用来避免对手"无兵出局"；
- 判据：40 手内把敌城打掉 ≥60 血 + 老家不丢。

和 `P-4-01` 的唯一差别：**那道题有现成的一格桥，这道要自己修**。

## 二、编号

`字母-数字-数字` = **类型-复杂度-序号**。架桥只有两件事（铺出来 + 过去），复杂度 **2**；
序号顺延取奇数（`P-2-01` 是主，`P-2-02` 留给它的"一换"），所以是 **`P-2-03`**。

## 三、四版读数（窗口 40 手，修完之后）

| 答题者 | 城伤 | 到城下 | `SIEGE` | 结论 |
|---|---|---|---|---|
| 空壳 | 0 | 0 | 0 | 红 |
| v1 | 0 | 0 | 0 | 红 |
| v3 | 0 | 0 | 0 | 红 |
| **v4** | **≥60** | **7 人** | **7** | **绿** |

v1 / v3 不会为过河造桥（会造建筑，但不会为过河修桥），所以它们过不去。
**修前 v4 也是红**（城伤 0、城下 0 人），"修前 vs 修后"的对照在第六节。

## 四、卡点找到了：AI 把自己造的桥当成"一个人"

用户 2026-11-26 的怀疑是对的：**v4 造的桥，v4 认为这里有自己的单位，所以不往前走。**

查证（三处都要对上，才算坐实）：

| 事实 | 证据 |
|---|---|
| 桥在局面里是**一条建筑单位** | `BUILD bridge` 之后 `s.units` 里多一个 `category: 'building'` + `bridges: true` 的单位，同时把它脚下那格 `terrain` 改成 `'bridge'` |
| 引擎**允许**桥和兵同格 | `rules.ts` 的 `blockedAnchor`：`if (d.bridges) return false; // 桥是双向的，谁都能站` |
| v4 的打分层**不允许** | `tactics.ts` 里 5 处落点过滤写的是 `s.units.some((v) => 格的 x/y 相同)` —— 桥自己也算"有人"，于是**桥面永远不是候选落点** |

**为什么 `P-4-01` 能过、这道过不去**：`P-4-01` 的桥是**纯地形**
（`snap.json` 里 `tiles[8,9].terrain === 'bridge'`，`s.units` 里**没有** bridge 单位，是手摆图生成的）；
`P-2-03` 的桥是 `BUILD` **造出来的单位**。同一段代码，一个能走、一个不能走，差别只有这个。

## 五、修法

- **一处定义**：`rules.occupantAt(s, x, y, excludeId?)` —— "这一格真正挡路的单位（桥不算）"；
- `tactics.ts` 的 5 处落点过滤改成 `takenByOther`（内部调 `occupantAt`）：
  `approachStep` / `stepToward` / `stepAside` / `cityPostCell` / `stepOffSpawn`；
- `constrain.ts` 的让路（`yieldMoves`）两处：桥不再被当成"要挪开的人"。
