# v4 题库（exams/）

> 这里面装的是 v4 的"考卷"。规矩看 `docs/GUIDE-V4-EXAM-2026-11-23.md`，
> 为什么要考卷看 `docs/PLAN-V4-2026-11-23.md` 第五节。
> **一道题不经手三个文件就不算存在。**

---

## 一、一道题 = 四个文件

| 文件 | 给谁 | 里面有什么 | 能不能外发 |
|---|---|---|---|
| `snap.json` | 游戏 | 那一格的完整局面（首页「导入对局」粘贴） | ✅ 发给测试员 |
| `card.md` | 测试员 | 局面摘要（有多少什么）+ 问题 + 请他回的三件事 | ✅ 发给测试员 |
| `answer.md` | 出题人 + 机器 | 标准答案、判据、红线 | ❌ 含答案 |
| `author.md` | 出题人 | 带坐标的完整面板 + 被雾挡住的敌人 + **v3 这一回合实际做了什么** | ❌ 含隐藏信息 |

`card.md` 和 `author.md` 都从同一个局面生成，所以"给人看的"和"给机器判的"永远是同一盘棋。
`card.md` 里**只有测试员在游戏里看得见的东西**——被雾挡住的敌人一个字都不许出现，
否则这题就成了"人开了全图，AI 没有"。

导出的回放在 `results/replays/v4src-*.json`，都能重放到和记录一致的终局：

## 四、两条必须记住的发现（会影响后面怎么出题）

### ① 24×24 的真实局面很快就不适合当单机制题

`Q3|49|A` 到第 31 手就已经 28 个单位、第 61 手 38 个、第 151 手 64 个。
手册第八节把"局面太复杂（十个兵、三个战场）"列为坏题——因为答错了也归因不明。
**单机制题请优先从 12×12 挖**（`Q1` 那一档，19~23 个单位已经是上限）。
大图只留给整局过程指标，以及下面第二条说的手工小局。

### ② 从失败局直接切出来的局面，多半是"综合判断"题

原因很实在：v3 的失败不是"少做了一个明确动作"，而是"整体判断错了"。
所以真实局面的答案一定有分歧（守还是弃、打还是等），判据也就写不硬。

**真实回放的价值是"证据"，不是"题目本体"。** 题目本体要靠手工摆小局面——
把某一个病单独隔离出来，像 v3 的探针那样（`probe:bridge-block` 就是手工摆的"桥头被自己人堵住"）。
那条路在 v3 里是有效的：探针把病钉死了，虽然当时没能治好。

所以第一批 15 题的构成改成：

| 类型 | 数量 | 来源 | 判据 |
|---|---|---|---|
| 真实局面（综合判断） | 3~5 道 | 这三局 + 后面导的失败局 | 松一点，先验流程 |
| 手工小局（单机制） | 10+ 道 | 照病灶自己摆 | **硬**，也最容易先红后绿 |

## 五、下一步（阶段 0 还差的两件工具）

1. **造局面工具**（`scene` → 局面）：手工小局题要用。输入是一张图 + 双方单位列表 + 回合上限，
   输出和 `snap.json` 同一种格式，所以题卡、判分器都不用改。
   v3 的探针已经证明了这条路能走（它们就是手工造局面），只是没有统一的文件格式。
2. **判分器 + 三个答题桩**：给定 `snap.json` + 一方的动作列表，判红绿；
   三个桩分别是"人写的标准答案"（必须绿）、"v3 现状"（必须红）、"空壳"（必须红）。

在这两件东西做出来之前，`answer.md` 里的判据都只是文字，**没有人会去执行它**——
所以现阶段不要急着写满十五道题，先各做一道，把工具跑通。

## 六、命令

```bash
# 从跑批队列复现某一局（种子不在 30/31/32 时要加 --allow-any-seed）
node --experimental-strip-types scripts/export-bench-replay.ts \
  --queue Q3 --seed 49 --new-side A --allow-any-seed \
  --out results/replays/v4src-Q3-49-A.json

# 看一局的时间线（每 30 手一行：城/兵/经济/金）
node --experimental-strip-types scripts/analyze-replay.ts results/replays/v4src-Q3-49-A.json --every 30

# 从某局切一格出来出题（--dry 只看不出文件）
node --experimental-strip-types scripts/make-exam.ts \
  --replay results/replays/v4src-Q1-30-A.json \
  --turn 12 --me A --id Y-001 [--ask "自定义问句"] [--dry]
```

`--turn` 是**半回合**（引擎每次结束回合把 `turn` 加一，A 打完是 B）。
脚本会切到"该方还没动手"的第一格，实际落在第几手会打在面板标题上。

## 七、种子卫生（别忘）

- `30 / 31 / 32`：被 v3 调参用过太多次，**只配当出题原料**，不能当验收集。
- `40~49`：v3 的诚实验收样本，同上——出题可以，验收不行。
- `60~69`：**留给 v4 自己的体检，出题时不许用，写完锁起来。**

题库是 v4 的开发集（拿它调，天经地义）；验收集必须是没进过题库的种子。
v3 就是在"练习卷即考卷"上刷出了 88% 的假成绩。
