# X-1-01 评审（战术动作 · 1 一件事 · 集火）

## 结论

**护栏题：空壳红，v1 / v3 / v4 全绿**（四颗种子 51/1/2/3 同结论）。

| 答题者 | 第 1 手结束时敌人还剩 | 结论 |
|---|---|---|
| 空壳 | 3 | 红 |
| v1 | **2** | 绿 |
| v3 | **2** | 绿 |
| **v4（修战术模式之后）** | **2** | **绿** |
| v4（修之前） | **3** | 红 |

判据：`unitCount(side=foe) ≤ 2`（第 1 手）+ `neverLostCity`；`lostUnits ≤ 1`。

## 这道题的作用：它是"战术模式"这个开关的回归探针

2026-11-25 之前的 v4：**守队（`hold-c1` / `recall`）没有 `focusId`**，每个兵各自
"打射程内血最少的"。这题第 1 手：

```
u1(2,10) → 打 (4,9) 那个 20 血的     ← 射程内血最少
u2(1,11) → 打 (3,11) 那个 30 血的    ← 它只够得着这个
```

20−16=4、30−16=14，**一个都没死**。而合打 30 那个是 16+16=32 ≥ 30，**第 1 手就能收**。

修法不是给守队单独打补丁，而是**约束层新增"战术模式"开关**（`Squad.tactics`）：
只有当局势说"这一手有一个值得全队一起办的目标"时，才把 `focusId` / `converge` 挂上去；
没挂 = 行为与原来一字不差。守队也挂，但它 `converge = false`（不许离开城）。

所以这题以后的作用是：**谁把守队的战术模式拿掉，它立刻红。**

## 出题时踩的三件事（都是这游戏/这套判分器的硬约束）

1. **伤害必须用 `previewAttack` 量**。第一版按"19 攻"算，得出"38 ≥ 36 能收掉"，
   于是把 36 血的敌人放在那儿——实际一发只有 16，32 < 36，根本收不掉。
   那道题修前修后都是 81 血（都收不掉），看起来"改了没效果"，其实是算错了。
2. **城血不能当时间窗**。城会自己回血，单个敌人砸城一手只掉 7 血；6 手里能回满。
   第一版用"第 6 手城血 ≥75"判，v4 修前修后都是 81——**判据完全失效**。
3. **`foeLost` 是全程累加量，`in` 对它无效**（判分器读全局计数器）。想按手判"打死几个"，
   只能用 `unitCount(side=foe)`——这个 `side` 是本次新加的（`scripts/exam-grade.ts`），
   因为它以前只能按兵种/兵种类别数人头。

## 它没量什么

- **不量"进攻时近战能否包围"**：这题是守城局面，守军不许离开城，近战集火在这种局面里
  本来就退化成 1v1。近战靠拢要另出一道（`X-2-01`，见 `docs/PLAN-V4-NEXT-2026-11-25.md`）。
- 不量"该打谁"的价值判断：两个敌人威胁一样（都是贴脸长枪），差别只在"能不能这一手收掉"。
- 不量"造兵/补兵"，金是 0。
